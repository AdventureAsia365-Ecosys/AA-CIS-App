# AA-1017 — migration 324: acc2 candidate chat models ("add a model = one PR" proof)

Lane w4a of the S262 gateway plan (wave 4). A migration-only PR (MIG-4: contract class) that catalogues five chat
models acc2 can call today, with one enabled acc2 deployment each and no route. No app code.

## Decisions

- **Which models.** The ones that answered a real call on acc2 on 31/10/2026 (root audit
  `docs/audits/2026-10-31-S261-aws-bedrock-org-access/model-access-matrix-2026-10-31.md`, acc2 column): Amazon Nova Lite,
  Amazon Nova 2 Lite, Meta Llama 4 Maverick, Meta Llama 4 Scout, Moonshot Kimi K3. The brief also named Nova Micro: left
  out because the AWS price list has no us-west-1 entry for it and the matrix did not test it (a catalog row needs a
  price, CHECK `llm_model_catalog_enabled_needs_price`). Nova 2 Lite (tested, priced) took its place.
- **Wire ids** are the `us.` inference profiles from the matrix, the same form as the existing acc2 rows
  (`cohere-embed-v4`, `haiku`): no ARN, no account ID.
- **Prices** come from the AWS Price List API (offer AmazonBedrock, version 20261030160456, region us-west-1), the data
  behind `aws.amazon.com/bedrock/pricing`, which renders its tables in the browser only. The `us.` profile bills at the
  source-region price (Kimi K3: the "US CRIS" column of the page, 3.30 / 16.50). Nova 2 Lite cache read 0.10725 is
  stored as 0.1073 (numeric(10,4)).
- **Capabilities `{}`, max_output_tokens NULL.** Unknown = today's code rules (no cachePoint for a non-Anthropic
  profile; a forced tool choice that a model rejects is remembered for the process). They get stated after a trial.
  Kimi K3 is a reasoning model: `supports_temperature = false`.
- **Enabled deployments, priority 20** (the acc2 rank of 304), `origin bedrock_profile`.
- **Guard in the file:** five enabled catalog + acc2 deployment pairs, and no role config / alias row names a new key.

## Tradeoffs

- Enabled rows are visible to everything that lists the catalog (admin pages, `POST /admin/llm-connections/acc2/test`
  without a model now picks `nova-lite`, the failure-domain report, the probe when it is switched on). That is the
  point of a candidate row; no stage can reach it without a separate route change.
- Contract, not expand: ADR 0017 classes any INSERT into routing tables as contract, so this is a migration-only PR
  followed by a manual DB Migrate apply.

## Should know

- **Q0 route hash.** The live hash is computed under the RDS database collation (glibc `en_US.UTF-8`); a local
  Postgres in `C` or ICU collation orders the lines differently and gives another md5. Reproduced from the step-0 dump
  with glibc en_US: before 320-322 `d13dd30e60453c4fa11a870e6b1fdc83` (79 lines, = step 0); after 322 (four seeded
  `cn|` lines) `16509de97a93379d6820f659d8465f43` (83); after 324 `a9bf3ce845a50fe459a54921c5ec3bb6` (93), if no
  other route row changed in between. The robust check: Q0 with the five keys filtered out of the `dp|` / `ct|` lines
  equals the hash before the apply.
- **Live test (paid, tiny):** one `POST /admin/llm-connections/acc2/test` per model with `model_key`. The test sends at
  most 32 output tokens today; Kimi K3 spends those on thinking (reply empty, still `ok`). The code PR of lane w4a adds
  an optional `max_tokens` (up to 512) to the test body.
- Order: after 320-323 are on `main`; preflight wants `main max + 1`.
