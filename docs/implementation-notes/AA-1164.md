# AA-1164 — Node base image pinned by digest, Alpine fixes at build

Lane l8-aa1164-image-scan, S287. The nightly scan of the running images is the AA-CIS-Infra part of the same issue
(`image-scan.yml`, `tools/security/image_scan.py`).

## Decisions

- **Pin the base by tag AND digest** in both stages of `frontend/Dockerfile`:
  `node:22.23.5-alpine3.24@sha256:1314fb30…` (the `node:22-alpine` index of 2026-11-12, read 21/11/2026 from Docker
  Hub). The floating `node:22-alpine` tag made every build pick whatever base was current and left the running image
  on the base of its last build, with no record of which.
- **`apk upgrade --no-cache` in the runtime stage**, in the same layer as the npm removal: Alpine publishes OS fixes
  faster than the Node image is rebuilt. On 21/11 the running `aa-cis-dev-admin` image carried a fixable zlib finding
  that the triage rule classes P0 (CVSS 9.4) and fixable OpenSSL findings; the newest Node base still had both, and
  the Alpine repository has the fixed packages.
- **Dependabot docker entry** for the Dockerfile's directory: weekly, one PR, grouped, Node majors ignored (a major is a
  deliberate change). Dependabot moves the tag and the digest together.
- Node stays on 22 (maintenance LTS); no runtime change.

## Changed

- `frontend/Dockerfile`: both `FROM` lines, runtime `RUN` (apk upgrade before the npm removal).
- `.github/dependabot.yml`: `docker` ecosystem entry.

## Tradeoffs

- `apk upgrade` makes the OS layer depend on the build day, not only on the pinned digest; the gain is that a rebuild
  always takes the published Alpine fixes. The digest pin still fixes the Node version and the base layers.
- Measured with the pinned Trivy v0.70.0 on the new base (21/11): every fixable HIGH was in npm's own bundled packages,
  which this image already deletes; the remaining fixable OS findings are the ones `apk upgrade` installs.

## Should know

- Merging rebuilds and redeploys `aa-cis-dev-admin` (the deploy workflow runs on this path). The Infra nightly Image Scan then
  reads the new digest; dispatch it once after the deploy to see the counts at once.
