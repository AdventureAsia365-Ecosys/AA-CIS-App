# AA-1146 — Tour edits are versioned, locked and published through one review gate (part 1)

Lane l14 of session S285. Part 1 of the slice: quick fixes (option A of the content-editing advisory), tour versions
with draft / diff / publish, the hand-edit lock, D1 (content.publish + the two-person switch), T1 (Excel re-import
merge) and D5 (price edits). Part 2 (later lane): the full editor pages, T3 (automatic agency-copy refresh with the
cap), TripPlanner notice on every publish.

Two PRs: the migration-only PR (CIS 457 expand + 458 contract, `batch: cis 457-458`) and this code PR (chain: both
applied first).

## Decisions

- **A draft is a `generated_content` row**, not a new table: status `draft` (the enum already had it, no writer used
  it), `origin` human, `parent_version_num`, `edit_reason`, `author_id` (CIS 457 columns). Reuses the re-validation,
  the final contract, `process_export` and the Review Queue machinery as they are. One open draft per tour (advisory
  lock per tour in the save).
- **The live version is never edited in place** once 457 is applied: `PATCH /generated/{id}` on the live version is
  409 `edit_live_version`. Non-live versions (Review Queue rows) keep the edit-then-revalidate flow.
- **Editors, not only the author**: everyone who saved the draft is in `edit_diff.editors`; the two-person rule
  refuses any of them (`same_person`). For a Review Queue approve or a promote the editors are the draft editors and
  the last hand editor (`reviewed_by`).
- **D1 capability**: `content.publish` for admin and content_lead. The publish routes take
  `content.publish | review.act`, and the route itself adds the two-person rule when the switch is on, so `content`
  self-publishes on Dev (switch off) and is refused 403 `two_person_required` when it is on. The switch is read in the
  route's own transaction (fails closed: unreadable = on), never from the 30 s cache.
- **Switch changes need a second person while it is on** (`settings_registry._decide`), on top of the existing
  maker-checker (which needs a second person only while `cis.settings.two_person_approval` is on). Turning it on alone
  stays possible on Dev.
- **Lock** = `published_tours.human_lock_*`. Set by a person's publish of a hand-edited version (approve / promote /
  human_publish of an `origin` human or `human_edited` version); lifted by a person's publish of a writer's version or
  by `POST /unlock` (master.admin, reason, audited). Automatic exits (auto_publish, recompose, lambda) are refused in
  `process_export` (version → hitl, `HumanLockedError`); the `s1_rewrite` job skips before any paid call; `run-tour`
  is 409; the S1 batch submit leaves locked tours out.
- **T1 merge keeps the tour id** (no new source version) and is a `raw_tour_revision` row `excel_merge` with the
  resolutions. "Hand-edited" = fields of `staff_edit` rows, minus fields a later merge took from the sheet, plus fields
  a merge kept. An empty sheet cell never erases a value; an unknown country never overwrites a valid one.
- **D5**: `price_raw` on the raw tour needs `reference_price.write` (admin, customer_success); content_lead lost
  `reference_price.write`. Every raw edit (price and provider included) keeps its old value in `raw_tour_revision`
  and in the audit row.

## Changed (against the issue and the lane brief)

- **Review Queue itinerary editing** (option A item 4) already worked: `ReviewEditor.tsx` has the itinerary textarea
  and `aa_itineraries` is in `_ALLOWED_GC_FIELDS`. Pinned by a test (the draft fields equal the editable fields,
  itinerary included); nothing else changed there.
- **"The result is a draft" (T1)**: the merge applies the facts to the source tour (with history) and does not touch
  the published text; the published wording changes only when a version is published. The fact fields that
  `catalog.v_tour` serves straight from the source (duration, inclusions, ...) do change at once. Staged fact drafts
  belong to part 2 (the facts lane of the editor).
- **Wave report**: a skipped tour shows as a succeeded `s1_rewrite` job with `result.skipped = human_locked` and a
  log line; the report still classifies it `unclassified` (follow-up: a `locked` state).
- **TripPlanner**: no immediate purge on a text publish (the purge job is keyed on lifecycle events); TripPlanner
  shows the new text within its 30-minute cache. Follow-up for part 2.
- **Supply content and AA content publish** routes do not run the two-person gate yet (follow-up).

## Tradeoffs

- Rows instead of a new versions table: no data copy, every existing reader of `generated_content` keeps working; a
  draft is the newest `version_num` while open, so readers of "the newest version" may show it (the drawer's Rewrite
  tab does on purpose).
- `reviewed_by` stays NULL on a draft (it is an `admin_users` FK; the actor id from a Cognito session is not always a
  row there); the author is `author_id`.
- The T2 refresh cap and alert are seeded now, not enforced (no reader until part 2), and badged "not enforced".
