# AA-648 — Batch search-demand research (real bulk DFS tasks)

Branch `feat/aa-648-batch-research`, stacked on `feat/aa-649-cost-guard` (PR #452).

## Decisions
- **New module `services/acp_contract/segment_research_batch.py`**, which runs research in phases over the whole selection:
  1. **propose** — Haiku, 15 places per call → up to 4 keywords per place. The plain place name is always included, even if the LLM output is unusable.
  2. **volumes** — per market: one cache query; the rest is bought in tasks of ≤1,000 keywords; cache hits are logged as one aggregated `dfs_call_log` row per market.
  3. **serp** — each place's best keyword with volume, only in the markets where it has volume.
  4. **suggestions** — zero-volume places, 20 seeds per `keywords_for_keywords` task (primary market); ideas that have volume are cached.
  5. **log** — `segment_research_log` is written only for places whose purchases all succeeded, and only if the run was not aborted.
- `run_segment_research(strategy="batch")` is the default. `strategy="loop"` keeps the per-place ReAct loop, for comparison until batch is proven on real runs; then it is removed.
- **SERP: 1 keyword per place (was up to 2).** It is the largest remaining line in a full pass, and PAA for the best keyword covers the place.
- **The dry run returns `estimate`** (an upper bound): LLM calls, volume tasks, SERP calls, idea tasks, and DFS/LLM dollars. Example: all 2,222 places × 3 markets → 27 volume tasks, 112 idea tasks, ≤ 6,666 SERP calls ≈ **$25 upper bound**. The real cost is lower, because SERP runs only for keywords with volume (~400 per market on 25/09 → ≈ $2.4).

## Changed vs issue
- **DFS Standard (`task_post` / `task_get`) mode is NOT in this PR.**
  - With real bulk, a full pass needs ~27 volume tasks (≈ $2), so the Standard discount on volumes saves cents.
  - Where Standard would really help is SERP (roughly 3× cheaper per task), but it needs async polling and could not be verified without paid calls.
  - Proposed as a follow-up issue, pending approval.
- **The Jev relevance gate before buying is not in this PR.** It depends on AA-660 (Jev `decide()` seam); shadow mode first.

## Tradeoffs
- The batch replaces the ReAct loop's adaptive "look at volumes, then decide" with a fixed propose → buy → SERP → suggestions pipeline. There are fewer LLM calls (1 per 15 places, versus ~3.5 per place on 25/09) and far fewer paid tasks. The price is less per-place adaptivity (for example, no second volume round driven by the first results). Suggestions partially cover that for zero-volume places.
- Suggestion ideas are cached as keywords but not tied to a place. Ranking's `_demand()` matches keywords to segments by tokens, as before.

## Should know
- Every paid call still goes through the AA-649 cost guard and the AA-647 circuit breaker.
- No migration.

## Follow-up (S203, 29/09/2026) — suggestions pass stored 0 ideas

### Root cause
- The two real batch runs on 28/09 logged `ideas_returned=4, ideas_with_volume=0` (4 seeds) and `ideas_returned=2, ideas_with_volume=0` (2 seeds). The returned "ideas" were the seeds themselves (`membar tsho`, `mongar farmhouse`, `nyili la pass`, ...), all with null volume.
- The pass only takes places with **no volume anywhere**, and it used each place's own best keyword as the seed, which by definition had no volume. Google Ads answers a task made only of unknown seeds by echoing the seeds back with no ideas. Parsing was correct.

### Decisions
- Seed = `"<place> <country>"`, where country is the most common `raw_tours.country` of the platform tours whose atoms are in the place's segments (`_PLACE_COUNTRY_SQL`, one query per run). If no country is found, the tidy place name is used. The country is not appended twice. Seeds are capped at 10 words (DFS limit) and deduped.
- Probe before coding: 1 paid task (~$0.09, logged in `dfs_call_log`) with 8 broadened Bhutan seeds → 26 ideas, 22 with volume (`mongar bhutan` 40, `ura valley bhutan` 70, `phobjikha valley` 260, plus hotel/"things to do" ideas). Truly obscure places (`membar tsho`, `orgen choling`, `nyili la pass`) stay at 0 even with the country.
- The country query was run read-only on Dev: 2,189 of 2,222 segment places resolve to a country; the other 33 have no platform tour and keep the name-only seed.

### Tradeoffs
- No "anchor" seeds (for example `"bhutan tours"`) were added to force ideas out of an all-obscure batch. They would fill `search_demand` with generic country keywords that do not match any place.
- A batch with no known seeds can still cost one task and return nothing. That is accepted for now: the pass runs at most once per 20 zero-volume places.

### Should know
- The log line `segment_research_ideas_task` now carries `seed_sample` (seeds sent) and `sample` (stored ideas with volume), instead of the raw first 5 returned keywords.
- No migration. Tests: `test_idea_seed_adds_country_once_and_caps_words`, `test_suggestion_seeds_use_place_country_not_the_zero_volume_keyword`.
