# AA-1113 — Free-text PII scrub in the shared LLM gateway, fail closed (lane l6, CIS)

Scope of this lane: the first bullet of the issue only (the F3 scrub moves into the shared CIS gateway for free-text
stages, failing closed). The CRM ledger routing, the over-cap flag column and the acc3 budget are other slices.

## ADR status (root ADR 0009 decision 10)

Accepted S283 (17/11/2026, tech lead, session decision page): root ADR 0009 decision 10 ("Data scopes: maker,
geography and tenant rules per provider") is accepted together with its data-class bullet "scrubbed traveller text":
a stage that carries tenant free text sends only a scrubbed copy of its prompt, and a scrub that cannot run refuses
the call. This repo does not hold the ADR (it lives in the root repo, `docs/adr/0009-ai-platform-and-provider-gateway.md`),
so the status line there (and the "Not covered by the three answers, still Proposed: decision 10" sentence of its
decision record) is edited by the orchestrator in a root PR; this note is the CIS record. The rest of decision 10
(makers and geography per stage, the per-provider tenant rule, "a scope change happens only by migration") is not
built here: the stage list below is a code allow-list for this slice.

## Decisions

- **Which stages.** `FREE_TEXT_STAGES = {t9_write, t2_generate, t8_angle_gen}` in
  `shared/llm_client/free_text_scrub.py`, a code allow-list. Measured first (root
  `docs/audits/2026-11-17-S283-session/aa1113-provider-stage-30d.psv`): these three carry tenant text for 7 tenants;
  the catalogue stages (`s1_*`, `a3_*`, `tp_compose`) carry none (tenants = 0), so `tp_compose` is not scrubbed.
  No existing column fits: `shared.llm_role_config.pii_class` (CIS 373) is `content | pii`, and `pii` means the
  opposite rule (the stage needs the personal data, so it runs only on US AWS deployments, unscrubbed). Reusing it
  would block the vendor APIs these writers use first. A `free_text` flag in the stage row is a migration (decision
  10: "a scope change happens only by migration") and the lane brief said no migration unless unavoidable.
- **Where it runs.** `LLMClient._generate_with`, after the app switch, stage switch, tenant budget and central budget
  gates and before the first provider attempt; `request` is rebound to the scrubbed copy, so the single-model call,
  the route (every rung), the legacy `haiku` / `sonnet` keys, the gateway truncation retry, the A/B shadow and the
  cassette only ever see the scrubbed request. The admin `probe` runs it too. Lesson S260 (a gate placed in
  `deployment_plan` missed the legacy chain): the gate sits above the chain split, and a test covers a legacy key.
- **Fail closed.** Any exception inside the scrub, or a scrubbed text that still holds an e-mail or a `+` phone (a
  self-check), raises `FreeTextScrubFailed`: the gateway writes one 0 USD row (status `refused`, `error_class`
  `other`, `quality_signal.pii_scrub = {version, status: failed, error_type}`) and raises. `other` because the CHECK
  on `shared.llm_call_log.error_class` has no scrub class; a dedicated class is a contract migration (follow-up).
  Not account-level: a job retries with its normal backoff, each retry 0 USD.
- **What is redacted.** The CRM log scrub (`AA-Partner api/app/observability/scrub.py` `scrub_text`) with its F3
  detectors (`api/app/privacy/patterns.py` + the folding of `api/app/privacy/text.py`), copied, never imported: JWTs,
  Bearer / Basic credentials, key-like `name=value`, Postgres key details, e-mails, `+` phones, then signed links,
  cards (Luhn), CCCD numbers, passports, phones without `+` (VN mobiles / landlines, NANP, after a cue) and OTPs after
  a code cue. Dates are left alone (prompts are full of trip dates), as in the CRM log scrub. Bracket labels, no
  restore step (the CRM's own LLM gateway uses `<KIND_n>` placeholders and restores them; that pass and the
  known-value pass are not ported, root ADR 0008a section 5 keeps the CRM gateway separate).
- **Receipt.** Counts per label on the request's attempt scope (`quality_signal.pii_scrub` of the gateway's own rows)
  and the log line `llm_free_text_scrubbed`; never a value. The call site's success row (written with
  `**billed_fields(resp)`) is unchanged: its `prompt_hash` is still the hash of the system prompt the call site built
  (the scope is made before the scrub), so prompt versions keep one hash.

## Changed

- `shared/llm_client/free_text_scrub.py` (new): the scrub, the stage allow-list, `FreeTextScrubFailed`.
- `shared/llm_client/pii_patterns.py` (new): the F3 detectors. One structural change from the CRM: `_classify` is
  split in three functions in the same rule order (the CIS complexity ratchet, AA-1097: the CRM function scores 12,
  the limit is 10). Behaviour is unchanged; nothing to port back to the CRM.
- `shared/llm_client/client.py`: the gate, `attempt_outcome` maps the refusal to `refused / other`, and a few long
  comments shortened so the file stays at its code-health baseline (2964 lines, the file-size ratchet).
- `tests/unit/test_aa1002_no_behaviour_change.py`: the two new modules are listed in the call path.
- `CONTEXT.md`: the "Free-text PII scrub" bullet next to "Data class per stage".

## Tradeoffs

- Code allow-list now vs a stage-row flag: the allow-list ships without a migration and covers the three measured
  stages; the cost is that a new tenant writer stage must be added in code (and a reviewer must remember it). The
  follow-up migration moves it into `shared.llm_role_config`.
- The repair / judge stages that read tenant-written text (`t9_repair`, `t10_judge`, `t9_faq_*`, tenants > 0 in the
  same measure) are not in the list: their input is the scrubbed writer's output plus the same seed. Listed as a
  follow-up to measure and decide.
- Brackets instead of placeholders with restore: the content a tenant gets never contains a traveller's contact
  value anyway (no CIS prompt carries brand contact details; the CTA rules are text); a restore step would put the
  value back into model output.

## Should know

- The scrub runs on every free-text call; it is pure regex (linear, CPU only, no I/O). The platform's own static
  prompts of the three stages scrub to themselves (a test guards it), so a prompt edit that trips a detector fails CI
  instead of silently losing words.
- Live check without a paid call: a one-off script in the API container that builds an `LLMRequest` for `t9_write`
  with a planted e-mail and phone and prints `free_text_scrub.scrub_for_stage(...)` (no model call).
