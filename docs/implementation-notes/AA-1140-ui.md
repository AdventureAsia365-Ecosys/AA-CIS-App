# AA-1140 — Ecosystem status page (frontend)

`/admin/overview` becomes the "Ecosystem status" page the tech lead approved on 19/11 (S285 advisory, mockup v2). The
backend (`GET /admin/overview/status`, the 5-minute sampler, CIS 475) has its own note, `AA-1140.md`, in the backend
PR. This PR is the page, and the move of the old Overview content to the pages it belongs on.

## Decisions

- **One call.** The page reads only `GET /api/admin/overview/status` (the generic admin BFF, `ops.read` = admin).
  Every card shows its section's own `as of` time; a section that did not answer shows its reason, a section or
  signal with no source shows a grey "Not measured yet" chip with the reason as its title, never a green value.
- **View state in the URL** (`lib/opsStatus.ts parseView / viewParams`): `range` (1h, 6h, 24h default, 7d, custom
  with `from` / `to` in ISO UTC), `compare=1`, `apps`, `sev`, `st`, `svc`, `ev`, `hide` (legend boxes per chart as
  `chart:id`) and `sort` (one `table:col:dir` per list). A default value leaves the URL, so "Copy link to this view"
  copies a short link and "Reset view" clears only the page's own keys.
- **Verdict headline (review fix).** Green "All systems normal" only when the API says `ok` and its `unknown` list
  is empty (`verdictHeadline`). A `partial` answer (nothing open, a core source did not answer) shows a neutral
  "No problems found in the sources that answered" with the "Not counted" names beside it; `unknown` stays neutral.
- **Refresh.** A preset range refetches every 60 s (the server reads CloudWatch on a 5-minute grid and caches it, so
  a refetch inside the same 5 minutes is DB reads only); a custom range does not move. The header shows the time of the answer and the countdown.
- **Limits from the API, never literals.** Every warn / critical line, every headroom and every colour reads
  `thresholds` (the `cis.ops.status_*` settings and the two CIS 469 in-app check keys) or the level the API computed.
  The history setting (`cis.ops.status_history_days`) bounds the custom picker; before the first answer the picker
  leaves the check to the server (422 `bad_range`). The stale factor note appears only once the setting is known.
- **Charts** (Recharts, as on Platform › Delivery): one line per app on one time axis, the previous period dashed and
  faint, warn dashed, critical solid with the area above shaded, deploy ticks and alarm bands from the sampler's
  events, a headroom line under each chart (latest, peak, room to the warn limit or the critical one when there is no
  warn), legend tick boxes with "only" and "Show all", and a table view of every value per step (kit DataTable).
- **Lists are kit DataTables** with controlled sorting kept in the URL (services, queues, AI connections, events,
  sources); the attention list is a card list with a sort picker. The app filter scopes every section; rows of the
  shared platform always show.
- **Timezone:** the viewer's own clock (kit `formatDateTime`), not a fixed ICT as the mockup shows; the custom picker
  is a `datetime-local` on the same clock and sends UTC.

## Changed (against the issue / mockup)

- The nav entry keeps its label "Overview" (Home group; e2e and IA tests name it); the page title is "Ecosystem
  status".

- Requests per minute has no capacity line: there is no load-test capacity value to read yet. Its subtitle says
  "Load-test capacity: not measured yet" and its headroom line says "no value".
- Cost card: month to date, AWS + AI split, forecast against the summed budgets with headroom. The daily columns and
  the share by app of the mockup are on Spend (By app tab, the same cost module); not repeated here.
- AI gateway: today's spend per app against its daily cap (the near-cap marker is `cis.ops.app_spend_near_pct`'s
  value) and the range's spend by connection; no per-hour chart yet (the table carries cost, requests, errors).
- Event timeline: lanes (deploy, alarm, service, check, job) drawn on the range's axis as plain blocks, plus the
  sortable, searchable list; no zoom (the mockup's "Undo zoom").

## Moved off the page (nothing deleted)

- Pipeline funnel per country and the content counts (atoms, segments, routes, hubs, score rows, researched places)
  → Data coverage, `data-coverage/ContentPipeline.tsx`, still from `GET /api/admin/overview` (60 s cache).
- Tenant activity of 7 days and the quota outliers → Tenants, `tenants/TenantActivity.tsx`, the same query; shown
  only to a role with `ops.read` (the read is admin-only), so other Tenants viewers fire no refused call.
- Cost per app and the paid sources (today, month, providers near their cap, DataForSEO balance) → already on Spend
  (By app tab and the AI & data spend tab, the same cost module): not copied.
- The AA-858 business cards (`_components/AppHealthStrip`, `CostByAppCard`, the B2C cards, `AlertList`) stay in the
  repo, rendered nowhere: App health, Spend and the attention list replace them. Their guard tests were adjusted.

## Tradeoffs

- One 60 s poll of an endpoint that runs about 15 small DB reads, against a page that looks live. The CloudWatch part
  is cached per range, so polling adds no AWS cost.
- API texts (verdict titles, reasons, event texts, source descriptions) are shown in English in both languages, like
  Data coverage; the page's own words are in `status.messages.ts` (EN + VI).
