# Dependency vulnerability sweep (S245): npm side of AA-CIS-App

Scope extension of the pip-audit issue: close the open Dependabot npm alerts on `frontend/` and `portal/`.

Open alerts at start (20/10/2026):

| Package | Lockfile | Severity | Advisory | Patched on npm |
|---|---|---|---|---|
| xlsx 0.18.5 | frontend, portal | high ×2 each | GHSA-4r6h-8v6p-xvw6 (prototype pollution, < 0.19.3), GHSA-5pgg-2g8v-p4x9 (ReDoS, < 0.20.2) | none: SheetJS publishes fixed builds only on its CDN |
| sprintf-js 1.0.3 | frontend | medium | GHSA-hp3w-g68c-fv3c (unbounded precision DoS, <= 1.1.3) | none: no fixed version exists |

## Decisions

- **Admin app (`frontend/`): remove `xlsx` instead of moving it to the CDN.** Nothing in `frontend/` imports
  it; both admin XLSX exports (Master Content tour list and version comparison) download a file the API builds
  (`/api/admin/tours/.../export?format=xlsx`). Removing it drops 9 packages from the lockfile
  (xlsx, adler-32, cfb, codepage, crc-32, frac, ssf, wmf, word).
- **Tenant portal (`portal/`): `xlsx` from `https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz`, exact URL
  (`npm install --save-exact <url>`).** 0.20.3 is the current SheetJS release and is outside both vulnerable
  ranges. The lockfile records `resolved` = that URL and `integrity` sha512; the sha512 of a fresh download
  from the CDN matches the lockfile value. 0.20.3 has no runtime dependencies, so 8 transitive packages leave
  the portal lockfile.
- **sprintf-js: no override, dismiss the alert as "vulnerable code not actually used".** The chain is
  `mammoth` (runtime, used client-side in `BrandIdentityEditor.tsx` for .docx import) → `argparse@1.0.10` →
  `sprintf-js@1.0.3`. `argparse` is required only by `mammoth/bin/mammoth` (the CLI); nothing under
  `mammoth/lib` or `mammoth/browser` requires it, and the production build's mammoth chunks contain no
  `sprintf`/`argparse`/`ArgumentParser` code. There is no fixed sprintf-js to override to, and overriding
  `argparse` to 2.x would break the mammoth CLI (it uses the 1.x `addArgument`/`parseArgs` API). Newest
  mammoth (1.13.0) still asks `argparse ~1.0.3`, so a bump does not help either.

## Changed

- `frontend/package.json` + lockfile: `xlsx` removed (`npm uninstall xlsx`).
- `portal/package.json` + lockfile: `xlsx` `^0.18.5` → the 0.20.3 CDN tarball URL.
- `CONTEXT.md`: one bullet under the tenant portal app on where `xlsx` comes from and that the admin app has none.

## Tradeoffs

- A tarball dependency is invisible to Dependabot version updates: future SheetJS releases must be bumped by
  hand (noted in CONTEXT.md). Accepted: it is the only distribution SheetJS maintains, and the alternative
  (another XLSX writer such as exceljs) is a bigger code change for one export button.
- `npm ci` now fetches one file from cdn.sheetjs.com (CI runners, Vercel build). If that host is down, the
  portal install fails; the lockfile integrity hash makes a tampered tarball fail too, not install silently.

    `main` before the change.
