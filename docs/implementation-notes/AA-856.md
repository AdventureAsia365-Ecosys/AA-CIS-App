# AA-856 — Cohere Embed v4 on the global cross-region profile (migration 238, S239)

CIS half of AA-856. TripPlanner branch `fix/aa856-search-embed-cache` (query-embedding cache +
keyword fallback) carries the main notes; Infra: `chore/aa856-copy` (byte copy of 238) and
`fix/aa856-tp-embed-global-iam` (TripPlanner Lambda role may invoke the global profile).

## Decisions

- **A migration, not an admin edit**: the catalog PATCH edits only price / enabled, and the profile
  is a decision that must replay on a fresh DB (as 222 / 224 / 227). Gateways pick it up within
  their 60 s catalog cache, no deploy.
- **Only `bedrock_profile_ids->'acc2'` changes** (`jsonb_set`), price and every other key untouched.
  Same model `cohere.embed-v4:0`, so stored 1536-d vectors stay comparable: nothing re-embedded.
- **Guard**: raise when the row is missing or the acc2 profile is neither `us.` nor `global.`
  (a hand edit needs a human decision). Idempotent: the UPDATE skips a row already on `global.`.
- **In-code fallbacks keep `us.`** (`shared/llm_client/embed._CATALOG_FALLBACK`, TripPlanner
  `BUILTIN_ROUTES`): used only when the catalog is unreadable, and both roles keep the `us.` grant.

## Changed

- Not asked by the issue as such: the issue requested a quota increase; S239 found the `us.` quota
  (L-EB8C1F30) is not adjustable and requested the global one (L-7089DC7D, case 179212369200770,
  20 -> 2,500 rpm). The switch is what makes that increase reach the callers.

## Tradeoffs

- Considered a second catalog row (`cohere-embed-v4-global`) with the `us.` row as route fallback:
  it would add the two 20 rpm quotas together and survive a missing IAM grant, but it duplicates
  the model in the admin dropdowns and changes four stage routes. Not done; the cleaner switch was
  asked for. Revisit if the quota case is refused.
- A global profile may serve a request from any commercial region, not only the US. The texts are
  tour content and anonymous traveller search queries.

## Should know

- **Order**: Infra IAM (`fix/aa856-tp-embed-global-iam`) applied first, then this migration
  (owner PR merged -> Infra copy PR -> DB Migrate check -> apply). Applied before the IAM grant,
  every TripPlanner search embed gets AccessDenied. CIS callers (ECS role: InvokeModel on `*`) are
  fine either way.
- Until the quota rises, CIS embed bursts (a3_place_embed backfills) and TripPlanner search share
  20 rpm, as they share the `us.` 20 rpm today.
- Rollback SQL is in the migration header.
- Verified locally (PostgreSQL 16, minimal tables): run from `us.`, re-run (no change), guard on an
  unexpected profile and on a missing row. The integration test replays it in CI.
