# AA-788 — T10: promote F12_scope, F14 under-length and F9_brand_style

S260 (30/10/2026). Report 12 #4 (S234 panel): F12_scope is precise but warn-only, F14 under-length posts were heavy,
brand-style misses pass. Scope from the issue: flip F12 to blocking; under-length → regenerate with unused seed facts;
F9_brand_style → one repair, never a hold. The F14 floor block itself shipped in AA-780 (S247).

## Decisions

- **Each promotion is a per-check mode, default = today's behaviour.** Worker task-def env, read per call (the
  `T10_SA_MODE` pattern of AA-789):
  - `T10_F12_SCOPE_MODE` = `warn` (default) | `block`;
  - `T10_F9_BRAND_STYLE_MODE` = `warn` (default) | `repair`;
  - `T10_F14_FLOOR_MODE` = `repair` (default, AA-780 behaviour) | `warn` (kill switch).
  An unset or unknown value is the default. Reason for the default: the S246 standing rule — no new blocking gate for
  4 weeks (freeze until ~19/11). Switching F12 / F9_brand_style on is an env change (Terraform task def), no deploy of
  code, and can be undone the same way. The hold rate is measured first with the $0 replay below.
- **F12 block mode: only a body finding blocks.** A title / meta-only finding stays a warning, like F17 / F18
  (`body_blocking`): `service._fit_seo_meta` already refuses a title or meta naming an out-of-scope place and asks
  for a new one each attempt, so what is left is the writer's own value. A body finding goes to the existing sentence
  repair (F12 was already in `_QUOTED_GATES`); if it is still there after the repair the piece is held (F12 is not
  style-only). Held stays an admin-only label (AA-770): the tenant still receives the piece; the reason shows in the
  admin atom-curation / content-quality views only.
- **F9_brand_style repair mode: attempt 1 only, never a hold.** Applied in `run_quality_gates` after the F9 results
  are collected (`promote_brand_style`), so a $0 replay of stored verdicts gets the same decision. It blocks only when
  at least one flagged phrase sits in a body sentence of ≥ 4 words (`brand_style_sentences`) — otherwise
  `sentence_repair.plan` would return None and send a style note to a full rewrite. Added to `STYLE_ONLY_GATES`
  (never holds; waived on an approved piece like F15) and `CHEAP_REPAIR_GATES` (t9_repair stage).
- **One reading of the violation for both sides.** `brand_style_sentences` is used by the gate (does it block?) and by
  `sentence_repair.plan` (what to repair) — lesson "a value computed in two code paths must share one function".
  The stored violation text is unchanged, so the admin highlight (`_F9_PHRASE_RE`) and Writing Memory readers are not
  touched.
- **F14 under-length: unused seed facts in the rewrite feedback.** `_repair_feedback(..., source=, content_text=)`
  appends one `F14_social_shape: source facts this post does not tell yet …` line (at most 5, from
  `quality_gates.unused_source_facts`, the deterministic helper the FAQ step already uses) when the attempt has the
  AA-780 under-floor block. This is the "regenerate with unused seed facts" item; it changes only the rewrite
  instruction of a block that is already live, not a severity.
- **Decision log.** `t10_promoted_check` (structlog: gate, mode, blocking, findings, why) when a promoted check fails
  while its mode is not the default. Nothing is logged in the default modes (no noise, ledger byte-identical).
- **No migration.** Config lives in task-def env like every other T10 mode; no table needed.

## Changed

- `services/acp_content_writing/quality_gates.py` — the three mode readers and env names, `gate_scope` block mode,
  `brand_style_sentences`, `promote_brand_style` (wired in `run_quality_gates`), F14 floor via `f14_floor_mode()`,
  `STYLE_ONLY_GATES` / `CHEAP_REPAIR_GATES` + `qr.F9_BRAND_STYLE`.
- `services/acp_content_writing/sentence_repair.py` — F9_brand_style is eligible; `plan()` turns each located phrase
  into a sentence item; an unlocated one is skipped like an F9 judge quote.
- `services/acp_content_writing/service.py` — `_repair_feedback` unused-facts line, called with the writer's grounding
  text.
- `tests/unit/fixtures/aa926_gate_snapshot.json` — regenerated on this behaviour commit. The only change: the routing-
  set members (`STYLE_ONLY_GATES`, `CHEAP_REPAIR_GATES`, `sentence_repair._ELIGIBLE_GATES` gain `F9_brand_style`).
  Every gate outcome of the 40 fault cases and every A1/T2 decision is byte-identical (default modes).
- `scripts/aa788/promotion_replay.py` — the $0 hold-rate replay (read-only, ECS exec after the deploy).
- Tests: `tests/unit/test_aa788_t10_promotions.py` (held / unaffected / logged per check, the T9 loop doing one style
  repair and never holding, the F14 kill switch and feedback), `tests/unit/test_aa788_promotion_replay.py`.
- `CONTEXT.md` — F12 / F14 / F9_brand_style lines.

## Tradeoffs

- **Default off vs. on.** On by default would be the literal issue text, but it breaks the S246 freeze and F12 has
  known false positives in its lexicon ('Mongol' on a Mongolia trip, noted in `check_replacement`). Off by default
  plus a measured replay keeps the ledger unchanged on deploy and makes the flip a one-line env change with numbers.
- **F12 hold vs. "repair once, never hold" for F12 too.** The issue says "flip to blocking" for F12 only; holding is
  what blocking means for a scope breach (selling a place no day visits is product truth, `scope.framing` is a hard
  class). The replay reports the new-hold upper bound per gate, so a too-high F12 rate can be answered by keeping the
  mode at `warn`.
- **Extra cost of F9_brand_style repair mode**: every attempt-1 brand-style failure with a locatable phrase adds one
  t9_repair call and one F9 judge call (attempt 2). The replay counts them (`attempt1_extra_repairs_by_gate`).
- A regression-guard revert to attempt 1 keeps attempt 1's blocking F9_brand_style and can give it a second repair on
  attempt 3 — the same as F15 stock phrases today. Not special-cased.

## Should know

- The replay must run AFTER the deploy (it imports the promoted modes from the image; it refuses to run on an older
  image). It forces the modes inside its own process only; the service env is untouched.
- The replay's "new holds" are an upper bound: a live run first gives the F12 finding its sentence repair.
- The registry (`taxonomy.yaml`) still lists F12_scope / F9_brand_style detectors as `mode: warn` — that matches the
  code default. When a mode is switched on for good, change the detector mode to `enforce` in the same PR that flips
  the default.
- Done-when (20-piece pilot, Trail Pulse false passes down, no new holds on panel-light pieces) needs LLM paths and a
  paid run; not done here.

# S287 (21/11/2026) — the measured flip: setting only, evidence = the pilot record, the 20-piece pilot runner

S279 review added to the Done-when: the F12_scope flip to blocking needs a measurement record from a 20-piece pilot
(precision lower bound on labelled fires, root ADR 0020); the flip is an admin setting (AA-1096 L2) whose evidence is
that record, never a code constant; F9_brand_style stays repair-once, never a hold; F14 under-length uses the AA-1077
floor and the `length_short` code, no floor of its own.

## Decisions

- **`F12_SCOPE_BLOCKING` is deleted.** `f12_scope_mode()` reads only the setting `cis.quality_modes.t10_f12_scope`
  (maker-checker, evidence required since CIS 412) at gate time; an unknown value is `warn`. No migration: the
  definition, its approval rule and the reader already exist.
- **`block` needs the pilot record as its evidence** (`quality_settings.evidence_problem`, called by
  `settings_registry.propose`, 422 `evidence_mismatch`). The rule is a table `HOLD_EVIDENCE` {(key, value): (reference
  prefix, what)} so the next measured check adds a row, not code. The reference is `aa788-pilot:<run id(s)>:<12 hex of
  the measurement's sha256>`, printed by `pilot.py score` only for a passing measurement. `warn` (the way back) takes
  any evidence. A format check, not a lookup: the record itself lives with the session audit (counts only) and the
  private `.tmp-session` (the fires quote tenant text); the sha ties the reference to one labelled measurement.
- **The bar is sample_size.BARS "deterministic"** (precision >= 0.90, Wilson-95 lower bound >= 0.75, n_pos >= 15,
  labeller agreement >= 0.7): F12_scope is a code check, not an LLM instrument. Precision counts the tech lead's labels
  only (`panel.release_evidence`: panel-only labels are not release evidence); a fire labelled by both gives the
  agreement. n_pos = labelled true fires (nothing outside the fires is labelled, so recall is not measured; the
  record says so). Records pool only under the same detector sha (gate_scope + the hygiene scope finder), never twice.
- **F14 under-length = `length_short` for blog and social alike.** `length_contract.violation_side` also reads the
  F14 word-count wording ("N words, under the … band" / "(far) over the"), and `ledger_length_codes(ledger)` returns
  the codes of F4 and F14 entries. The floors stay where they are (blog: `floor_chars()`, AA-1077; social: the brand's
  channel spec band, AA-780). The regeneration itself was already live: the AA-780 attempt-1 rewrite with unused seed
  facts (S260 PR) and the AA-1077 blog extend. Hold codes are unchanged (the F14 floor block never holds).
- **F9_brand_style** needed no code change (STYLE_ONLY_GATES since the S260 PR); the pilot counts `f9_brand_style_holds`
  and the Done-when requires 0.
- **The pilot drives the real T9 loop, in-process, writing nothing.** Per input: `service.start_write` (the Write
  button's context build from the live request, no model call) then `service.run_write_background`, with in-process
  patches only (`isolated`): the promoted modes over quality_gates' readers, the placeholder INSERT and final UPDATE
  captured in memory, no FactSheet / claim-shadow / A/B-shadow write. `call_log.bind_eval_stage("adhoc_aa788", run)`
  relabels every ledger row (real stage in quality_signal.real_stage, tenant / piece NULL: no tenant usage); the writer
  code already records each call with `**billed_fields(resp)`. Pattern: scripts/aa729/evalpatch (AA-729 / AA-780), but
  self-contained so the root ECS exec wrapper can ship it alone (the image has no `scripts/`).
- **Cost cap = the setting `cis.spend.run_cap_adhoc_usd`** (default 5 USD, Platform › Settings); `CAP_USD` can only
  lower it. Checked before every model call (spent + the largest call seen must fit, `Budget.check_call`) and before
  every piece (spent + the larger of the stored piece's own ledger cost and the largest pilot piece). The gateway's own
  run cap (same setting, adhoc class) is a second stop. No new setting, no migration.
- **Inputs**: the newest piece of each approved T8 request on the four AA-741 audit tenants, labelled pieces first,
  round-robin by tenant, or explicit `PIECES`; `SKIP` leaves out an earlier trial's inputs, so a 3-piece trial plus a
  17-piece run make the 20 and `score` pools both records.

## Changed

- `services/acp_content_writing/quality_gates.py` — `F12_SCOPE_BLOCKING` removed; `SEO_FINDING_PREFIXES` (gate_scope,
  the F17 / F18 body rule and the pilot's body / title reading use it; the file stays at its code-health baseline).
- `services/acp_content_writing/length_contract.py` — F14 wording in `violation_side`; `ledger_length_codes`.
- `services/quality/quality_settings.py` — `F12_PILOT_EVIDENCE_PREFIX`, `HOLD_EVIDENCE`, `evidence_problem`.
- `api/services/settings_registry.py` — `propose`'s evidence checks moved to `_check_evidence`, which also calls
  `evidence_problem` (422 `evidence_mismatch`; the split keeps `propose` under the complexity limit).
- `scripts/aa788/pilot.py` — MODE=plan ($0) / MODE=run (paid, CONFIRM=PAID) / `score` (local, $0).
- Tests: `tests/unit/test_aa788_pilot.py`, `tests/integration/test_aa788_f12_flip_evidence_db.py`; the constant's old
  asserts in test_aa768 / test_aa788_t10_promotions / test_aa789 now read the mode.
- `CONTEXT.md` — F12 and F14 lines.

## Tradeoffs

- In-process loop vs a new job kind: a job kind would need registry / capacity / snapshot changes and would write the
  piece rows; the exec script reuses the production loop with its two writes captured, like the AA-729 harness. Cost:
  it runs in one exec process (its heartbeat blocks CIS deploys while it runs, ~1–3 min a piece).
- A reference-format rule vs storing records in the DB: a table for measurement records would be a migration and a
  new retention row for one flip; the sha in the reference is enough to find and re-check the record.
- The "false pass" Done-when is a proxy: the panel label belongs to the stored text, the pilot writes a new one. The
  pilot pieces can be labelled by the panel afterwards if the proxy is not enough.

## Should know

- Paid: the run needs the tech lead's own yes, then a trial (`N=3`), then the rest (`SKIP=<trial ids>`,
  `CAP_USD=<cap minus the trial's spend>`). Labels: one JSON per labeller pass, `{"labels": {fire_id: {"tech_lead":
  "tp|fp", "panel": "tp|fp"}}}`; the template is the run's `LABELS` line.
- 20 pieces will probably not give 15 true fires (the S261 replay: 5 F12 holds on 300 pieces): the measurement then
  says how many more labelled fires the bar needs and prints no evidence_ref, so the mode stays `warn`. That is the
  honest outcome per ADR 0020; more pilot records pool into the same measurement.
- Follow-up: the definition text of `cis.quality_modes.t10_f12_scope` (CIS 412 / 424) still says "a $0 replay" is
  enough evidence; the server now refuses that for `block` with a message naming the record. Reword it in the next
  settings-text migration (contract, compiled defaults regenerated).
- `service.F14_UNUSED_FACTS_MAX = 5` (S260) is a code literal, not a setting: listed for the thresholds follow-up.
