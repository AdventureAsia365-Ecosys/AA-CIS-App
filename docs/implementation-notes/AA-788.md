# AA-788 — T10: promote F12_scope, F14 under-length and F9_brand_style

S260 (30/10/2026). Report 12 #4 (S234 panel): F12_scope is precise but warn-only, F14 under-length posts were heavy,
brand-style misses pass. Scope from the issue: flip F12 to blocking; under-length → regenerate with unused seed facts;
F9_brand_style → one repair, never a hold. The F14 floor block itself shipped in AA-780 (S247).

## Decisions

- **Each promotion is a per-check mode, default = today's behaviour.** Worker task-def env, read per call (the
  `T10_SA_MODE` pattern of AA-789):
  - `T10_F12_SCOPE_MODE` = `warn` (default) | `block`;
  - `T10_F9_BRAND_STYLE_MODE` = `warn` (default) | `repair`;
  - `T10_F14_FLOOR_MODE` = `repair` (default, AA-780 behaviour) | `warn` (kill switch).
  An unset or unknown value is the default. Reason for the default: the S246 standing rule — no new blocking gate for
  4 weeks (freeze until ~19/11). Switching F12 / F9_brand_style on is an env change (Terraform task def), no deploy of
  code, and can be undone the same way. The hold rate is measured first with the $0 replay below.
- **F12 block mode: only a body finding blocks.** A title / meta-only finding stays a warning, like F17 / F18
  (`body_blocking`): `service._fit_seo_meta` already refuses a title or meta naming an out-of-scope place and asks
  for a new one each attempt, so what is left is the writer's own value. A body finding goes to the existing sentence
  repair (F12 was already in `_QUOTED_GATES`); if it is still there after the repair the piece is held (F12 is not
  style-only). Held stays an admin-only label (AA-770): the tenant still receives the piece; the reason shows in the
  admin atom-curation / content-quality views only.
- **F9_brand_style repair mode: attempt 1 only, never a hold.** Applied in `run_quality_gates` after the F9 results
  are collected (`promote_brand_style`), so a $0 replay of stored verdicts gets the same decision. It blocks only when
  at least one flagged phrase sits in a body sentence of ≥ 4 words (`brand_style_sentences`) — otherwise
  `sentence_repair.plan` would return None and send a style note to a full rewrite. Added to `STYLE_ONLY_GATES`
  (never holds; waived on an approved piece like F15) and `CHEAP_REPAIR_GATES` (t9_repair stage).
- **One reading of the violation for both sides.** `brand_style_sentences` is used by the gate (does it block?) and by
  `sentence_repair.plan` (what to repair) — lesson "a value computed in two code paths must share one function".
  The stored violation text is unchanged, so the admin highlight (`_F9_PHRASE_RE`) and Writing Memory readers are not
  touched.
- **F14 under-length: unused seed facts in the rewrite feedback.** `_repair_feedback(..., source=, content_text=)`
  appends one `F14_social_shape: source facts this post does not tell yet …` line (at most 5, from
  `quality_gates.unused_source_facts`, the deterministic helper the FAQ step already uses) when the attempt has the
  AA-780 under-floor block. This is the "regenerate with unused seed facts" item; it changes only the rewrite
  instruction of a block that is already live, not a severity.
- **Decision log.** `t10_promoted_check` (structlog: gate, mode, blocking, findings, why) when a promoted check fails
  while its mode is not the default. Nothing is logged in the default modes (no noise, ledger byte-identical).
- **No migration.** Config lives in task-def env like every other T10 mode; no table needed.

## Tradeoffs

- **Default off vs. on.** On by default would be the literal issue text, but it breaks the S246 freeze and F12 has
  known false positives in its lexicon ('Mongol' on a Mongolia trip, noted in `check_replacement`). Off by default
  plus a measured replay keeps the ledger unchanged on deploy and makes the flip a one-line env change with numbers.
- **F12 hold vs. "repair once, never hold" for F12 too.** The issue says "flip to blocking" for F12 only; holding is
  what blocking means for a scope breach (selling a place no day visits is product truth, `scope.framing` is a hard
  class). The replay reports the new-hold upper bound per gate, so a too-high F12 rate can be answered by keeping the
  mode at `warn`.
- **Extra cost of F9_brand_style repair mode**: every attempt-1 brand-style failure with a locatable phrase adds one
  t9_repair call and one F9 judge call (attempt 2). The replay counts them (`attempt1_extra_repairs_by_gate`).
- A regression-guard revert to attempt 1 keeps attempt 1's blocking F9_brand_style and can give it a second repair on
  attempt 3 — the same as F15 stock phrases today. Not special-cased.

## Should know

- The replay must run AFTER the deploy (it imports the promoted modes from the image; it refuses to run on an older
  image). It forces the modes inside its own process only; the service env is untouched.
- The replay's "new holds" are an upper bound: a live run first gives the F12 finding its sentence repair.
- The registry (`taxonomy.yaml`) still lists F12_scope / F9_brand_style detectors as `mode: warn` — that matches the
  code default. When a mode is switched on for good, change the detector mode to `enforce` in the same PR that flips
  the default.
- Done-when (20-piece pilot, Trail Pulse false passes down, no new holds on panel-light pieces) needs LLM paths and a
  paid run; not done here.
