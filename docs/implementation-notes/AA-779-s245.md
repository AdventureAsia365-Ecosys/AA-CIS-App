# AA-779 (S245) — FAQ from People Also Ask + every answer names its question's subject

Stacked on the tenant signature vocabulary branch (`feat/tenant-signature-vocabulary`), because
both touch `prompts.py` and `quality_gates.py`. Agent: Claude Code (coding lane `paafaq`).

## Decisions

- **PAA goes to the main blog writer too, not only to `write_faq`.** `write_faq` runs only when
  fewer than 3 FAQ pairs survive the droppers, and F16 holds were 0 in r3/r4, so it almost never
  fires. Sending the questions only there could not meet "≥1 PAA question used in ≥4/8 blogs".
  `build_user_prompt(search_questions=…)` adds a `SEARCH QUESTIONS` block (blog only); the FAQ
  bullet of both blog format variants says to prefer one only when a seed/FACTS fact answers it.
- **Where the PAA filter runs.** `start_write` keeps the raw `people_also_ask` list of the request's
  `dfs_paa_snapshot` in `context["people_also_ask"]` (at most 12, strings only). The `t9_write`
  job filters it (`quality_gates.paa_for_scope`) once the Facts are known, with the same
  out-of-scope gazetteer the hygiene context and `choose_keyword` use, and stores the result in
  `context["paa_questions"]` for the writer, the rewrite and `_enforce_faq_contract`. Older job
  payloads without the key give `[]` — no PAA block, same as before.
- **PAA filter rule** (deterministic, $0): normalise (whitespace, first letter upper case, ends in
  "?", 10–160 chars), drop a question that names an out-of-scope place (`hygiene.names_place`
  against the gazetteer — lower-case DFS text counts, like `choose_keyword`), drop a question the
  source cannot answer (`unanswerable_faq_topics`: age, fitness, price, booking, accommodation,
  best time — unless a seed/FACTS line supports it), keep it only when it names one of the
  moment's own places (a capitalised seed name, not the country) or shares ≥2 non-generic content
  words with the seed. Duplicates removed, capped at 6.
- **Subject check = two deterministic reasons** in `quality_gates.faq_answer_problem`:
  - `no_subject`: the question's subject tokens are its capitalised names (all their words,
    "Lake Khövsgöl" → lake, khovsgol), the nouns after "the/a/an" (up to 4 words, stopping at a
    preposition, verb or punctuation; abstract words like role/significance/kind are skipped) and
    the noun after "What/Which" ("What animals…", "What weather…"). The answer's first sentence
    (plus the next one when the first is a bare "Yes."/"No.") must contain one of them, after
    accent and case folding and a plural/possessive strip. A definite description ("The volcano
    last erupted…" for "Uran Togoo") also passes when the post or the seed has a sentence with both
    the name and that noun ("Uran Togoo is a dormant volcano"); trip words (route, trip, journey,
    day…) never count as such a description. A question with no subject tokens is skipped.
  - `negative_only`: a wh-question (what/which/who/where/when/why/how) answered only by negated
    sentences ("…meat production is not the primary purpose.") — r4 #19 Q5 names the Tsaatan but
    still does not say what the reindeer are used for. Yes/no questions are never checked for this.
    "not just / not only" and a negation followed by "instead / rather / but" do not count as
    negated (r4 #15 Q1 and r5 #14 Q2 are fine answers; the first replay flagged them).
  - Refinements from the replay and the existing tests: the noun after "What/Which" takes its "of"
    phrase ("What kind of dwellings" → dwellings, "What share of fresh water" → fresh, water); a
    "Who <verb>…" question ("Who lives near the lake?") asks for the people, so it is not given a
    subject test; plurals are cut with -ies/-oes/-es rules so "volcanoes" matches "volcano".
- **Drop, never hold.** `drop_subjectless_faq` drops failing pairs in reading order only while
  more than `FAQ_MIN_PAIRS` (3) remain, and returns how many failing pairs it had to keep. F16
  stays the only FAQ hold; no new gate. Drops and kept failures are logged in the
  `F7_faq_autofix` flag (non-blocking), like the other droppers.
- **Regeneration budget unchanged.** When failing pairs had to be kept on a fresh writer text,
  the existing one `_enforce_faq_contract` call runs with `fix_subjects=True` (one `write_faq`
  call, ~$0.004–0.008). There is still at most one FAQ regeneration per writer text (plus the
  existing one after a repair cut the FAQ below 3). In that call the failing pairs leave the base
  before the merge, and the regenerated FAQ goes through the same subject dropper.

## Replay ($0, local)

All 62 blog FAQ pairs of S234 r4 and S235 r5 (the `pieces_r4.json` / `pieces_r5.json` exports),
context = body before the FAQ + the moment's own seed: **5 flagged, exactly the 5 pairs the panels

## Tradeoffs

- **Lenient subject tokens.** Every word of a name and every "the <noun>" in the question counts,
  and a seed/post sentence can make a class noun an alias. That keeps false drops on panel-clean
  pairs low, at the cost of missing an answer that names the subject but still dodges the question
  (only the negation case is caught). The panel stays the judge of "non-answer"; this check catches
  the two shapes r4/r5 showed (no subject / pronoun or demonstrative opening, and negation only).
- **A pronoun opening fails** ("It freezes solidly…" to "What happens to the lake in winter?"). It is
  readable under its question, but the issue's rule is that every answer names the subject; the
  writer and `write_faq` prompts now ask for that, and the dropper never takes the FAQ under 3 pairs.
- **No LLM judge** for answer-addresses-question: deterministic only, as the issue asks.
