# AA-702 — Admin UI audit fixes before the platform rerun

Source: S207 Playwright audit of every admin page + tab on Dev `:407` (evidence in root
`.tmp-session/s207_audit/`). Scope agreed with Nghiệp: items 1–9 of the issue; Settings copy,
distinctiveness, upload file names and mobile admin go to UI v2 (AA-662).

## Decisions
- **Notifications**: decode the jsonb payload per row (`json.loads` when it is a string) rather than
  registering a jsonb codec on the pool — a pool-wide codec would change the type every other
  handler receives (many already `json.loads` themselves).
- **Active sources only**: S0 "Ready for Rewrite" and the S1 list now filter
  `source_status = 'active'` (column is NOT NULL, default `active`). Superseded rows stay reachable
  through Dup Review, which is the only place meant to act on them.
- **Internal tenant key**: internal LLM/DFS work is logged both with `tenant_id IS NULL` and with the
  aa_internal UUID. Folded in the read queries (`NULLIF(tenant_id, aa_internal)`), not by
  backfilling the logs — the writers stay as they are, and the UI key is `null` + label
  `aa_internal` on both the LLM and DFS tabs (DFS used to say `platform` / raw UUID).
- **Dashboard model usage**: source switched to `shared.llm_call_log`, last 30 days, real calls and
  cost per model. Dropped "Avg Score" there — it came from generated_content and has no per-call
  meaning. Pass Rate shows "—" when there were no runs.
- **SEO Intelligence**: countries = distinct published masters with SEO data; Top keywords = DFS
  keyword ideas with a measured search volume, ordered by volume.
- **S1 model selector**: defaults to "Settings default — <model>" and sends `model_tier: null`, so
  the `s1_generate` route/fallback/shadow in Settings applies. Explicit options come from the same
  catalog list as Settings (`/admin/llm-config`, available options only) and apply to that run only.

## Changed
- Found while fixing item 8: the S1 page always sent `model_tier: "haiku"`, and an explicit
  `model_tier` wins over the stage config in `LLMClient._generate()`. So every admin S1 run ignored
  whatever `s1_generate` said in Settings. Fixed by the null default above.
- `jobs_repo.find_active_duplicate()` compared `model_tier` with `=`, which never matches NULL; now
  `IS NOT DISTINCT FROM`, otherwise the new null default would disable double-submit dedup.
- Tenant detail + Master Content "LLM Cost" read `shared.llm_call_log` (all time; internal tenant
  includes NULL rows). Labels: "LLM Cost (all time)", "API Quota" (detail) vs "tour quota" (list).

## Tradeoffs
- Folding keys at read time leaves two spellings in the logs. A backfill + writer change would be
  cleaner but touches every call site; the read fold is one place per query and reversible.
- Master Content's LLM cost now includes all internal platform work (A-series, Jev, research), not
  only S1 — it is the internal tenant's real spend; the per-stage split lives in External Spend.

## Part 2 (Nghiệp: fix both open items too)
- **Migration 195** — `v_trip_registry` filters `rt.source_status = 'active'` (was: not trashed).
  Dev before: 761 rows, 25 superseded (3 with an active master duplicating the active version:
  Classic Exploration, Classic Journey — both versions published; Southwest & Highland Odyssey —
  only the superseded one published). Columns unchanged from 087. The S1 run endpoint and the S1
  batch loader now also reject/skip superseded tour_ids (they only checked trashed).
- **S1 keyword ideas** — the AA-251 tour-name seed stays the primary seed (SERP/PAA, search
  volume). Keyword ideas now send up to 4 seeds in ONE `keywords_for_keywords` task (same price:
  DFS bills per task): the specific seed, the title's place words + country, country + activity,
  "{country} tours". `rank_keyword_ideas()` orders: real volume first, ideas naming a place from the
  title before generic ones (weak geo nouns like "valley"/"trek" don't count as specific), then
  volume. `_parse_keywords` no longer returns volume-less rows (it echoed the seed back, which
  blocked the ideas promotion); the seed is kept only as a last-resort lead keyword. Redis key gets
  `:ideas_v2` so 7-day-old single-seed entries are not reused.
- Tradeoff: generic phrases ("India tours") can now appear among ideas — they rank below anything
  tour-specific, which is the AA-251 concern (DFS_INTENT_UNDERUSED false positives on generic
  keywords). Cost per tour unchanged (search_volume + SERP + one ideas task).

## Part 3 — relevance filter (after a real Dev trial)
- Trial on Kang Yatse (Ladakh mountaineering), DFS $0.18: with the "{country} tours" seed every idea
  with volume was generic and wrong for the tour ("golden triangle india", "kerala trip package",
  "delhi to agra"). Removed that seed; `rank_keyword_ideas()` now KEEPS ONLY ideas naming a title
  place (weak geo nouns excluded) or the tour's activity; generic country ideas are dropped even with
  high volume. Redis key bumped to `:ideas_v3`.
- Found in the same trial: `first_activity()` only accepted a list, but S1 passes
  `raw_tours.activities` as JSON text (no jsonb codec) — so the AA-197 "activity in country" seed
  never reached DataForSEO in the real S1 path; every seed fell back to the tour name. It now parses
  JSON text.
- Trial runs: the ECS exec session dropped (EOF) right after the first colored structlog line, which
  killed paid runs halfway; silencing structlog in the script fixed it. Trial DFS spend ≈ $0.8.
