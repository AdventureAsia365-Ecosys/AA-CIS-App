# AA-793 — T2 best draft wins + targeted repair + background-fact allowance in T3 grounding

Source: S235 report 12 §2.3 F-c / F-d (S237 lane cis-backend item 5). Built in S237 by Claude Code;
the first build agent was interrupted (WSL OOM restart), its uncommitted work was recovered as a WIP
commit and reviewed/finished by the relaunched agent.

## Decisions
- Two layers lose drafts today, so both get "best draft wins":
  1. the content graph (T2 retry loop, `MAX_RETRIES`): the `hitl` exit kept the LAST draft. The
     tenant graph variant (`build_graph(t2_drafts=True)`) adds `track_best` after the judge and
     `restore_best` on the `hitl` exit (`services/content_generation/t2_repair.py`);
  2. the T3 QA gate (`tenant_pipeline.run_t3_qa_gate`): returned the latest repair round. Now every
     checked draft is a candidate; a clean draft returns at once, otherwise the best candidate is
     returned (`_draft_key`: clean first, then score, then fewer issues, then the later attempt) and
     each round repairs the best candidate so far, not the last one.
- "Score" = `quality_score` (the judge-adjusted score `should_retry` gates on, brand_fit under the
  S236 AA-801 setup: anchors on, gate `brand_fit`, mission diagnostic only). The judge/gate config is
  untouched; AA-793 only chooses among drafts that were already judged.
- Ties keep the earlier draft in the graph (strictly higher wins). In T3 a tie goes to the later
  attempt, because a later T3 candidate with an equal score is a repaired copy of the same draft.
- Targeted repair:
  - graph retry: the writer gets the best draft so far (`YOUR PREVIOUS DRAFT (revise it, do not start
    over)`, writer-facing fields only) plus that draft's own feedback (validate issues + judge
    feedback) instead of a blind re-roll. Prompt block lives in `t2_repair.revise_block`, appended
    in `generate_node` only when `is_tenant_rewrite` and the switch is on; the A1 prompt is unchanged
    (`test_aa792_a1_prompt_golden.py` still pins it).
  - T3 grounding-only failure: one sentence repair (A1's `grounding.repair`, stage `t2_flag_fix`,
    tenant id logged, brand-neutral fact-editor system prompt `T3_REPAIR_SYSTEM`) instead of a
    whole-tour rewrite. The draft's judge score is carried (removing a figure does not change brand
    fit). One sentence repair per draft; if it changes nothing, or the repaired draft still fails, the
    next round is a revision rewrite.
  - T3 structural failure (hard codes): a revision rewrite of the best candidate with the T3 findings
    plus, for a draft below 7.0, the judge's feedback (`_revision_feedback`).
- Background-fact allowance (`services/acp_produce/t3_background.py`), applied in T3's numeric
  grounding (`_t3_grounding_check`): a novel number is accepted only when it is place background of
  three narrow kinds — a past year (also ranges/decades via AA-785 `year_forms`), a century /
  millennium ordinal, or an elevation >= 1,000 m/ft stated as the height of a place. Never: this year
  or later, prices, counts, durations, clock times, distances, lengths. Review hardening (S237):
  also never in a first-person sentence (operator claim), a sentence about accommodation / dining /
  service (lodge, hotel, camp, stay, overnight, restaurant, guide…: fidelity rule B), or an elevation
  next to a gain word (climbs / ascent / descent / gain / up / by). Second review (S237 adversarial
  reviewer) found counts, prices and distances still passing ("1,500 monks", "1500 statues",
  "1200 ngultrum", "a short walk (1,500 m)", "the trail runs 1,200 m", "raft 1,500 m of rapids") and
  tightened it: a bare 4-digit year needs a year cue right before it (in / since / the / of / "(" …)
  or must open the sentence, never carries a thousands comma, a plural noun or a currency after it;
  a metre figure next to a walking / route word or followed by "of" is a distance; the elevation cue
  must sit within 40 chars of the number. Accepted numbers are logged
  (`t3_background_cleared`) and counted in `job.result.t3.background_cleared`.
- Flags (env on the worker task def, read per call — same pattern as `T2_JUDGE_ANCHORS`):
  - `T2_BEST_DRAFT` default **ON** — pure selection among drafts already written and judged; no new
    text, no new call, no gate relaxed. Safe.
  - `T2_TARGETED_REPAIR` default **ON** — changes how retries are prompted and adds a cheap Haiku
    sentence repair, but every output still goes through the same validate / judge / T3 checks and
    best-draft keeps a worse revision from being saved. Judged safe to default on.
  - `T3_BACKGROUND_FACTS` default **OFF** — it relaxes a deterministic truth gate: an accepted figure
    is not verified by anything (a wrong elevation or year would pass). The policy (memory rule
    "writer source fidelity", Nghiệp S223) allows type-A background, but flipping it on is
    Nghiệp's call; recommended ON for the AA-793 rerun (Infra worker env).
  - Both T2 switches off = the pre-AA-793 graph and T3 loop exactly (tests pin it).

## Tradeoffs
- A "targeted" graph revision still outputs the whole tour JSON (the writer's output format is the
  full tour). Savings come from fewer rounds (a revision of a 6.x draft should pass more often than
  a re-roll) and from the Haiku sentence repair replacing a Sonnet rewrite; input tokens grow by one
  draft (~3-5k tokens, about $0.01-0.015 per revision on Sonnet).
- A revision may anchor on the previous draft's weaknesses. Mitigated by best-draft: a worse revision
  is never saved. Measured by the rerun (per-attempt judge rows, `revision` flag).
- The sentence-repaired draft is not re-judged (no extra judge call); its score is the base draft's.
- The allowance is lexical, not semantic: deliberately narrow, with false negatives preferred
  (e.g. "the pass rises to 3,120 m" passes; "climbs 1,200 m to the pass" stays flagged).

- `apply_replacements` replaces a highlight only when the flagged sentence is the whole item; a
  multi-sentence highlight is left alone and the round falls back to a revision rewrite.
- `qa_repair_count` now counts sentence repairs as rounds too.
- T3 is "truth first": a clean draft returns at once even when an earlier draft that failed T3
  scored higher (e.g. an 8.0 draft with an unsupported number vs a clean 6.0 revision; the 6.0 is
  saved `needs_review`). With targeted repair on, the higher draft gets its sentence repair first,
  so this only happens when that repair cannot clear it. The rerun report counts "below an earlier
  pass" against clean passes only, consistent with this rule.
- `restore_best` also restores the draft's own call metadata (`judge_tiebreak`, `fallback_used`,
  `satellite_account`) so the saved draft's metadata matches its text (review fix).
