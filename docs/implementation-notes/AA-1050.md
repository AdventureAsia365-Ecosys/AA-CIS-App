# AA-1050 — Quality W4: the calibrated claim instrument in shadow (lane l20, S273)

Source plan: root ADR 0020 (D6, D7, D16), the S271 writing-quality audit
(`docs/audits/2026-11-06-S271-writing-quality-audit/`, `data/design-review.json` `arch.roadmap[4]`), W2 tooling
(`services/ground_truth/`, AA-1048) and the W3 T9 / T2 route tables (`services/acp_content_writing/route_table.*`).
This lane is the **shadow part only**: the instrument runs beside F9 and the T2 claim check and is recorded; nothing
changes a piece or version status. The enforce flip is a later PR, once W2 has a passing record per class.

## Decisions

- **Where the shadow runs: after the save, inside the job, never before.** T9: right after `_finalize_piece` (and its
  log line) in `run_write_background`; T2: in `t2_rewrite_job.run` after the final row read (covers both the graph and
  the linear orchestrator paths, the policy hold is skipped). The status is already written, the shadow writes only
  its own table and the ledger, and every error is swallowed (the T9 helper sits inside the write's `try`, so it has
  its own `try` too: an import error there must never turn a stored piece into `failed`). A separate job kind was
  rejected: a new kind touches the job registry, capacity lines and kind lists for a shadow that is off by default.
- **Extraction mode only.** Live objects have no labelled claims, so the instrument reads each field with the full
  source (one call per field per vote) and code maps confirmed quotes onto sentences (`claims.sentence_spans`,
  `r1._overlaps`). The user prompt is built by `r1.extraction_prompt` (byte-identical to the calibrated instrument);
  system prompt and schema are R1's. `CLAIM_SHADOW_INSTRUMENT` must name an `:extraction` instrument with a price.
- **Votes and verdict as calibrated (D7).** `VOTES = r1.VOTES` (3). A sentence is unsupported / supported only with
  2 agreeing real votes (`r1.majority`); a vote is lost on a non-JSON reply (miss), a refusal stop reason, an answer
  from another model or connection (identity, `r1._identity_ok`), a caller error or the guard. Object verdict:
  unsupported if any non-tenant sentence is unsupported; else unverified if any sentence is undecided; else supported.
  Typed reasons: `unsupported:<policy class>` (unknown class -> `unclassified`), `unverified:budget|error|identity|
  refused|miss|split`, `supported:clear`.
- **Enforce map keyed `<writer>:<class>`** (R1 lists passing classes the same way). `mode_for` returns `enforce` only
  when the key is in `ENFORCE_OVERRIDES` AND in `CALIBRATED[instrument id]`; both ship empty, a unit test pins the
  literals. `shadow_action`: hold (enforce class flagged by pinned votes), review (unverified while the writer has an
  enforce class: D7 "a miss is never a pass"), warn, none. Recorded only.
- **Tenant-authored spans (D6):** the T9 CTA, the T2 brand `default_cta` and `brand_name`. A flagged sentence that
  carries one is kept in `details` with `tenant_span: true` and never counts; `cut_eligible` is always false in W4.
- **Baselines.** T9: the final `F9_cta_fact` ledger entry (pass / flag = blocking / warn / unavailable = outage marker
  / none). T2: there is no live LLM claim judge on T2 (the brand judge is report-only and source-blind); the closest
  claim-level decision is the deterministic brand-claim check (`judge_breakdown.brand_claims`, AA-795): flag when it
  left an unsupported claim. Agreement: unverified verdict -> `unverified`; no baseline -> `no_baseline`;
  flag <-> unsupported, pass / warn <-> supported -> `agree`; else `disagree`.
- **A new table (CIS 391), not llm_call_log / llm_shadow_log / the piece row.** A cache hit bills nothing but must be
  counted next to its baseline (a fake ledger row would break the "one row per billed attempt" contract);
  `llm_shadow_log` compares two models' raw outputs with no object or tenant; the piece / version row is tenant
  content the shadow must never write. No text in the table (spans, claim hashes, classes, votes).
- **Migration class: contract (MIG-4), like CIS 388.** First written as expand (a new table only, like CIS 360), but
  the CIS migration preflight's expand lint refuses `REVOKE` and `DROP POLICY IF EXISTS`, and both are wanted: the
  REVOKE keeps UPDATE away from cis_app (cis_owner's default privileges in shared would grant it; a verdict is never
  rewritten) and the DROP keeps a re-apply a no-op. So: a migration-only PR (391 + its integration test + the X1 lists
  in conftest + the erasure inventory node, which the inventory-completeness test needs once the table exists), the
  Infra copy, Migration Apply (class contract, every job table idle), then the code PR. The code PR is stacked on the
  migration commit (identical content): after the squash merge a rebase on main drops it. No readiness raise: the
  shadow is off by default and fails open without the table (503 on the admin read).
- **Cache first.** Key = sha256 of the instrument id, votes, the system prompt + schema sha and each field's user
  prompt sha. The newest definitive (non-unverified, non-cached) verdict of the key is reused: a `cached` row, 0
  calls, cost 0 (a CHECK enforces it). Unverified verdicts are never served from the cache.
- **Spend guard.** `SpendGuard(cap)` over the `claim_shadow` stage's ledger sum in the window: spent = max(first
  reading + this run's charges, newest reading); a call starts only when spent + the call's worst case
  (`r1.worst_call_cost`, reserved attempts = `r1.route_attempts`) fits. No reading or a non-finite one closes it.
  Charges use `r1.billed_cost` (worst case for a missing cost); a caller error is charged its worst case and stops the
  object / run. Default cap 0.30 USD (Done-when), env max 0.50 (the issue's total). The replay adds a run cap.
- **Replay corpus as a module CLI** (`python -m services.quality.claim_shadow_replay`): `scripts/` is not in the
  image; services/ is. DRY RUN default (plan: cache hits, calls, expected / worst cost); `--live --confirm-spend`.
- **Ledger.** Stage `claim_shadow`, role judge, `{"shadow": true}` (so `is_shadow`), `**billed_fields(resp)`; billed
  unusable replies via `record_unusable`. A platform stage (not `t<digit>` / `adhoc_`): no tenant budget stops it; the
  tenant bill already excludes shadow rows. Registered in the AA-927 call-site registry and the AA-642 model-tier
  allowlist (pinned on purpose, like R1).
- **Admin read**: `GET /admin/writing-memory/claim-shadow/summary` (Writing Lab read). Counts, cells, reasons, cached
  and pinned shares, would-hold / non-pinned-hold counts, spend vs cap, a seeded `md5(id || seed)` sample of
  disagreement ids (piece / version ids only, no tenant id). The tech lead labels about 30 of them (W4 item 1).

## Tradeoffs

- **3 votes per field cost 3x one vote**, but a 1-vote shadow would not be the calibrated instrument (test-retest and
  the 2-of-3 rule are part of what W2 measures). The cache and the 0.30 cap bound it; at GPT-6 Luna prices one T9
  blog is about 0.01 USD (3 fields x 3 votes, mostly reasoning tokens), a T2 version about 0.05 (5 fields).
- **Object-level agreement, not claim-level.** F9's flags are free-text quotes; matching them claim by claim is the
  disagreement labelling's job (the details keep claim hashes + spans so the lab can join with `eval_claim_label`).
- **Inline in the job** adds the shadow's latency to a T9 / T2 job when the switch is on (a few seconds per call,
  sequential). Acceptable for a cents-scale shadow on Dev; a job kind is the path if it ever runs at volume.
- **No prompt registration** (`shared.prompt_version`) for `claim_shadow`: the prompts are R1's, frozen in code, and
  each row carries `prompt_sha` in its details. Registering it would need a contract migration; left as a follow-up
  for the enforce PR.

## Should know

- **Off by default.** Nothing runs until `CLAIM_SHADOW=on` is set on the api + worker task definitions (Infra TF var or
  task def env). The replay CLI runs regardless of the switch (DRY RUN unless `--live --confirm-spend`).
- **No paid call was made in this lane.** The orchestrator's live steps run the DRY RUN, then a small live replay under
  the cap, then optionally switch the live shadow on for a short window.
- **The enforce flip** (holds for measured classes, the F9 judge prompt and route row retired, LinkedIn
  unsupported_trip_promise -> cut) needs: a passing R1 record (`r1.report` passing_classes on held-out), the classes
  copied into `CALIBRATED`, the overrides set, and ~30 labelled disagreements with the instrument right in >= 80%.
- `run_id` of a live row is the job id (else the object id); a job retry with the same text writes nothing new
  (`ON CONFLICT (run_kind, run_id, cache_key) DO NOTHING`) and is served from the cache anyway.
