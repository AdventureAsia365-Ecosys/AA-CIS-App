# AA-1118 — Split CONTEXT.md into a short core and detail pages

Part of the root issue "docs back to reality" (S282 audit R19: CONTEXT.md had 5,809 lines). Lane c-docs-drift, S291.

## Decisions

- **Verbatim move.** Every line below "Run it locally" moved unchanged, in order, to thirteen pages under
  `docs/context/`, cut at existing section or bullet boundaries (the long "Architecture at a glance" section into five
  pages by topic: stack, AI gateway, cost and jobs, runtime features, data and settings). A script check proved that
  each page body is a verbatim slice of the old file and that no non-empty line was lost.
- **What stays in CONTEXT.md** (131 lines): front matter, the intro, "What it is" (unchanged: the root AA Academy
  allowlist pins that section's hash), "Run it locally", a table of the detail pages, the boundaries, a pointer for the
  content pipeline domain, open questions and related documents.
- Each page starts with one note line that names CONTEXT.md and the move; no front matter (the root docs reader does not
  publish app pages; CONTEXT.md keeps catalog id ARCH-06-cis).

## Changed

- Two links that pointed inside the old file now point at their page (`Deploy & CI`, `Pipeline stages`).
- `tests/unit/test_aa998_no_acc1_runtime.py` also scans `docs/context/*.md`, so moving text out of CONTEXT.md does not
  take it out of the acc1 guard.

## Tradeoffs

- Pages follow the old order instead of a fresh outline: a reviewer can diff them against the old file; regrouping can
  follow once each page has an owner.
