# AA-638 — Tenant portal product polish

## Decisions
- **Notifications panel** shipped in AA-636 (#439) as the fix for the dead bell — not repeated here.
- **Getting started** is derived from real state (brand identity has a system prompt or core idea,
  catalog count > 0, ≥1 written piece in /content-writing/reviews, WordPress connected). No new
  "onboarding" table. Dismiss = localStorage only. It takes the Dashboard slot the fake
  "Re-rewrite balance" card had (removed in AA-636).
- **Usage chart**: a per-day source exists (`shared.tenant_api_usage.called_at`,
  `tenant_tour_versions.created_at`), so `/v1/billing` gains `daily` (current month, zero-filled
  via generate_series). Sparkline = API calls (the metric that moves daily); scale 0..max, labels
  only name values the series reaches (first day, today, peak).
- **⌘K** now opens a command palette (pages + "search tours for …" which reuses the shell's
  globalSearch → Browse Tours). The top-bar search box stays for mouse users.
- **Skeletons** for Dashboard, Browse Tours list and My Catalog list (the pages that load the most).

## AA-637 follow-ups bundled here (found in the live prod check of #441)
- T9 marks the "Saving" step before `_finalize_piece` (it was skipped).
- Highlights section joined with single newlines (bullets were double-spaced).
- LiveWriter auto-scrolls to the newest line while writing, unless the reader scrolled up.
- Tour writing hint: "a few minutes — longer when the checks ask for a revision" (a real rewrite
  took ~4 min with 3 revisions; "1–2 minutes" was wrong).

## Should know
- A real tour rewrite in the live check went through 4 writer calls (1 write + 3 revisions) in
  ~4 minutes — existing retry/QA-repair behaviour, now visible to tenants as "Revising…". Worth a
  separate look at why the first draft fails the checks so often (cost + latency).
