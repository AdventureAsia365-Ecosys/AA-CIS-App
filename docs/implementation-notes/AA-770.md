# AA-770 — Tenant always receives the content (T2 + T9)

## Decisions (Nghiệp, S233: "held = admin-only label")
- **Publish**: `held` publishes like `approved` (only processing/failed → 422). `/v1/publish-log/pending` lists held.
- **Tenant projections**: `flags` removed from every tenant piece/review response; ReviewDrawer flag banner and
  ReviewList flag icon removed; copy "our team is reviewing" / "passed quality review" reworded.
- **T2**: `quality_score`, `qa_status`, `qa_repair_count`, `qa_checked_at`, `qa_auto_passed`, `aa_quality(_score)`
  removed from `/v1/tours/my-versions`, `/versions/{id}` (+ history), `/v1/marketplace`; marketplace status is
  `ready | writing | failed | approved | rejected` (ai_generated and needs_review are both "ready"); "auto-passed"
  badge removed.
- **Gates**: F5 (citation density), F3 (rhythm), F7 (FAQ restates) → warn only; F7 auto-fix drops FAQ pairs that
  restate the body before gating (logged as a `F7_faq_autofix` flag for admin). F9 judge outage → non-blocking
  "not checked" flag (was a hold).
- **Attempt 3 = sentence repair only**, same row; it replaces the AA-485 buffer retry (second content_piece row),
  which is deleted with its tests. Attempt 3 runs only when attempt 2's failures are all sentence-repairable; a
  failed repair at attempt 3 keeps attempt 2 as final (held), never a full rewrite.
- **Held pieces are indexed** (`content_embedding` persisted) so F10 cross-tenant and within-tenant reuse see them.

## Tradeoffs
- `discarded_attempts` still keeps one prior attempt (the one directly before the final).
- Admin still sees `status='held'`, `held_reason`, `gate_ledger`, `flags` (Content Quality page, AA-769).

## Should know
- Rows written before this change may still have a second (buffer-retry) piece per request; the tenant list shows
  the latest (DISTINCT ON request), unchanged.
