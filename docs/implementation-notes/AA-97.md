## AA-97: Pre-UAT Migration — Inspect DB schema và apply migrations

### Decisions
- `acp_shared.acp_runs` là S1 runs table (PK=run_id, acpcore v0.4.0) — KHÔNG phải `acp_silver_s2.s1_runs`
- Migration tracking dùng `shared.schema_versions` (không phải Alembic)
- MIG-025 và MIG-026 đã được apply và recorded (versions 025, 026)
- MIG-028 (idempotency_keys) đã được apply via ECS exec — schema live có thêm tenant_id, stage columns so với migration 029 file
- `pipeline_checkpoints` là table mới, UNIQUE(run_id, stage, node_name) để support LangGraph resume
- Số migration: 028 (không có file 028 trong repo, 029 đã có)

### Changed
- Tạo `028_pipeline_checkpoints.sql` — chỉ tạo `pipeline_checkpoints`, KHÔNG tạo lại idempotency_keys (đã có)
- Apply migration qua psql tunnel (localhost:15432), không dùng S3-mediated ECS exec
- Record migration 028 vào shared.schema_versions

### Tradeoffs
- `input_hash VARCHAR(64)` cho SHA256 cache key — consistent với acp_silver_s4.blog_drafts.evaluator_input_hash
- UNIQUE(run_id, stage, node_name) cho phép upsert idempotent per LangGraph node
- `output_data JSONB DEFAULT '{}'` thay vì nullable — consistent với ACP JSONB conventions

### Should know
- `gold_aa_internal.published_tours` là BASE TABLE (không phải VIEW) — PRD spec về VIEW không áp dụng cho sprint này
- Migrations 027–034 đã được apply vào live DB nhưng KHÔNG được recorded trong schema_versions (gap cần fix sau)
- `acp_shared.idempotency_keys` live schema: (key, run_id, tenant_id, stage, created_at, expires_at) — richer hơn file 029
