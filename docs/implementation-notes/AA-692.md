# AA-692 — A1/A2 Jev points: judge tie-break (A1-4) and source-aware meal/time code (A1-3)

Design: `docs/architecture/at-series-v2-design.md` §4.1. Scope agreed with Nghiệp (S205, 30/09): **A1-4 + A1-3**; **A1-2 dropped**, **A1-5 deferred**, A2-1 goes with UI v2.

## Decisions
- **A1-2 (brand-audit prefilter) dropped.** Measured: 36 `s1_brand_audit` GPT calls / $0.18 in 30 days. Since AA-206 the audit reuses the judge result whenever the judge ran, so there is almost nothing to save.
- **A1-5 (generic soft codes) deferred.** The codes are soft; a second signal changes no outcome.
- **A1-4 judge tie-break.** In `judge_node`, only for A1 (not tenant rewrites) and only when validate already passed and the judge score is within ±0.5 of 7.0 — the judge alone decides retry/HITL there. New Noul `a1_brand_fit` (migration 191, shadow). Enforced: accept → score lifted to 7.0; reject → 6.9; grey/shadow/error → unchanged. The judge still writes the feedback. The verdict is kept in state as `judge_tiebreak`.
- **A1-3 meal/time code, no new question.** Measured on 125 master tours: the regex fired on 41; 14/17 clock times are verbatim in the source; 26/34 tours' sources state meals too. So:
  - clock time: deterministic — no code when the same time is in the source;
  - meal claim: the sentence goes to `a1_claim_supported` (already calibrated and enforced, accept 0.90) with the same source text and subject key grounding uses, so it is normally a cache hit; cleared only on an enforced accept (fail-closed otherwise).

## Changed
- `pre_audit_checks(generated, tour=None)` — without a tour it behaves exactly as before.

## Tradeoffs
- The tie-break band is ±0.5 (the design's value). Wider would let Jev overrule clear judge scores.
- A1-3 reuses an existing calibrated question rather than adding "logistics claim vs narrative": a meal claim the source supports is exactly "a supported claim".
