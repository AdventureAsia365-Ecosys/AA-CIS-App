## Decisions

- **History keyed (keyword, market, month), written once** (`ON CONFLICT DO NOTHING`): Google revises the last month a
  little; keeping the first answer means a reader never sees a month move. `source` keeps the endpoint label.
- **Capture point = the DataForSEO client / queue parse, write point = the research cache `put_volumes`.** The client
  keeps the parsed months in a `MonthlyBuffer` per (location, keyword); every caller that stores volumes pops the
  months of the keywords it stores and hands them to `put_volumes(history=...)`. A history write never fails a paid
  purchase (logged `search_history_write_failed`). Test doubles without the buffer keep working (`with_history`).
  Paths: live volume task (`_purchase_volumes`), Standard queue (`volumes`, recovered tasks), keyword ideas
  (`_buy_suggestions`, S1 prefetch ideas task), S1 per-tour fetch (`process_seo`).
- **Season = MAX over the place's keywords per month**, never the sum: close variants carry the same number.
  Peak month over the latest 12 months; YoY = latest 12 vs the 12 before, else latest month vs the same month a year
  earlier, else None (the first purchase has 12 months only; YoY appears after the next refresh).
- **Variant groups (item 2)**: keywords of one place whose volume is identical in every measured market (and > 0
  somewhere) are one demand group (`demand_groups`). The SERP keyword is the top group by volume; inside the group it
  is chosen by SERP presence (a fresh SERP in the store = nothing to buy), then map order (the plain name first, the
  LLM's natural phrasing order), then fewer words. Never by volume. The deduped estimate uses the same rule.
- **Freshness windows (item 3)**: default 180 days, maker-checker (CIS 452 edit); bounds unchanged.

## Changed

- `s1_prefetch.py` comment: a Google Ads volume is an average that hides the season; the months are kept now.
- `s1_prefetch.cached_ideas`: the PAA caps 5 per keyword / 10 per tour are settings (`cis.seo.tour_paa_per_keyword`,
  `cis.seo.tour_paa_max`), shared with the tour PAA backfill (`paa_from_rows`).

## Tradeoffs

- History is not back-filled for the volumes bought before this change (the answers were not kept); it fills as the
  rolling refresh re-buys places.
- Requesting 24 or 48 months (`date_from`) at the same price would give YoY at once; not done here: it changes the
  request payload of every volume task (follow-up).
