# AA-926 — Q-1: error taxonomy, gate registry, single thresholds file and lint

Quality System v1 (root `docs/audits/2026-10-20-S245-quality-system/design.md` §3, §4.6, §5.3, Appendix A).
Constraint from the issue: **gate outcomes must not change**. The proof is a byte-identical snapshot of gate
outcomes taken before the refactor (commit A) and recomputed after it (`tests/unit/test_aa926_equivalence.py`).

## Decisions

- **D1 — YAML location.** `services/quality/{taxonomy,thresholds,paths}.yaml`, next to `registry.py`, not a
  top-level `quality/` folder (design §3.1). The Dockerfile copies `services/`, so the files ship in the api and
  worker images, and the deploy-dev path filter already covers `services/**`. No Dockerfile or workflow path change.
- **D2 — constants, not moved logic.** `services/quality/registry.py` holds the only gate-name literals, as plain
  `str` constants. Routing sets (`STYLE_ONLY_GATES`, `CHEAP_REPAIR_GATES`, `OWNED_BY_FIX_STEP`, `TRUTH_CUT_GATES`,
  `_ELIGIBLE_GATES`, `_QUOTED_GATES`, `TRUTH_GATES`) stay in their owner modules, built from the constants; their
  membership is pinned by the snapshot. The YAML carries per-gate metadata (classes, label, kind, channels,
  retired, show_in_filter). Persisted names (ledger gates, `F9_brand_voice` in `llm_call_log.quality_signal`,
  flags) are never renamed; retired names stay registered so old ledgers still resolve.
- **D3 — literal-lint scope.** AST scan of string constants (incl. f-string parts) in `api/`, `services/`,
  `shared/`, `worker/`, `scripts/aa729/`. Gate pattern `F\d+_[a-z][a-z0-9_]*` plus the exact registry names
  flagged `lint_exact` (`promises_an_option`, `within_tenant_reuse`, `T3_grounding`). Exempt: `__all__` lists,
  docstrings, comments, tests, docs, migrations, the YAML, the registry and the generated TS file. Structlog
  event names that match the pattern (`F9_sticky_*`) are registered `kind: telemetry` and use constants — no
  call-site exemption. Inline escape `# qlint: allow <reason>`, counted in `--report`.
  **A1 validate / brand-audit codes are mapped (lint error if unmapped), not de-literalised** — flagged in the PR.
  `FORBIDDEN_WORD` is both an A1 code and a T2-version gate name, so it is not `lint_exact`.
- **D4 — thresholds.** One canonical `pass_line: 7.0`; every consumer has its own key that `ref`s it. Other
  cut-offs moved only where the snapshot pins them at the boundary. `decision_question.accept_floor` /
  `reject_ceiling` (Jev, calibrated per question in the DB) are out of scope — a second, deliberate threshold
  source. `scripts/setup_run_health_alarms.py` (ACP evaluator alarm, different metric) is outside the lint scope.
  Every entry carries `calibration: {run_id, precision, recall, n}` all null and `calibrated: false` (design
  §5.3); the format check allows a null `calibration.run_id` only when `calibrated: false`.
- **D5 — issue fields vs design v2.** `owner_gate`, `metric` and `tolerance` (issue scope 1) are derived by the
  loader (design §3.2 dropped them as stored fields: owner = detector with `mode: enforce`; metric/tolerance =
  default per severity, §4.2). `synthetic_examples` are the golden examples: ≥ 1 positive + ≥ 1 negative per
  hard/block class.
- **D6 — frontend.** `frontend/lib/quality-registry.generated.ts` is generated by
  `python -m services.quality.gen_frontend` ("GENERATED, do not edit"). `GATE_LABELS` keeps the 33 existing keys
  in their current order with the same labels, then adds labels for the four active gates that showed as raw
  codes (`F2_platform_truth`, `F2_superlatives`, `F2_style_warn`, `F19_authenticity`). `shared.ts` re-exports it.
  The review page reads `PASS_LINE` for "7.0+" and `canApprove`; score colours read `SCORE_BANDS`.
- **D7 — diff-hash job.** New **non-required** CI job `quality-paths` (job-level `permissions: contents: read`),
  script `.github/scripts/quality_paths.py` (stdlib + PyYAML, no `services` import). Deviation from design §4.6
  (step inside a required job): AA-919 moves it / makes it enforcing when it adds `quality/q2`.
- **D8 — taxonomy content.** 17 classes per design §3.3, `other.<alias>` at warn for F6, F7, S3, S4, S5, S7,
  C1, C3, C5, V1, plus `judge.excerpt_artifact` / `judge.missed` as `kind: meta`. Two extra warn classes
  `other.lexicon` (brand/word-layer rules) and `other.length_shape` (length / SEO title-meta / LinkedIn shape codes and gates) so every existing
  detector maps somewhere (design §7.6 allows new warn classes; reported in the PR). Examples are synthetic only.
- **D9 — registry safety.** `yaml.safe_load`; schema validated by unit tests; lookups used in request paths are
  total (unknown name → `None`, never `KeyError`). `services/__init__.py` and `services/quality/__init__.py` stay
  import-free so the Lint job runs the lint with only PyYAML installed.
- **D10 — F15_stock_cut (S250).** The #916 stock-line cut writes a non-blocking `F15_stock_cut` flag. Registered as
  `kind: flag, class: none` with a fixer-log reason, like `F7_faq_autofix` / `F13_autofix` (the S250 plan suggested
  class `other.lexicon`; the flag records sentences a fixer removed, not a detected error, and the stock phrase
  itself is already classed through `F15_voice` → `other.v1`). Its label "Stock lines cut" is appended after the
  four D6 labels, so the frontend superset stays order-stable (33 old + 5 new).
- **D11 — codes since the first base (S250).** `a1_codes` maps the day-oracle codes (`DAY_*` → `struct.day_structure`,
  `SOURCE_DAY_CONTRADICTION` → `source.contradiction`, `DAY_CHECK_SKIPPED` → `other.degraded_detector`), the
  S1-first `s1_checks` codes (`META_CUT`/`TEXT_TRUNCATED` → `struct.truncated`, `META_LENGTH` → `other.length_shape`,
  `NUMBER_NOT_IN_SOURCE` → `fact.number`, `NUMBER_NOUN_MISMATCH` → `fact.misbinding`, `NAME_NOT_IN_SOURCE` →
  `fact.name`, `DAY_PLACE_MISMATCH` → `struct.day_structure`, `INCLUSION_CONTRADICTED` → `fact.inclusion`),
  `DEGRADED_DETECTOR`, `META_CUT_SIGNATURE`, `BRAND_AUDIT_FLAGGED` (→ `other.v1`) and `BRAND_AUDIT_UNAVAILABLE`.
  `ITINERARY_MEAL_TIME_INVENTED` was already mapped. The same codes are listed as class detectors in mode `shadow`
  (the day oracle ships every code in shadow; `s1_checks` is a measurement), so they never count as enforcement.
  Lint (d) now also reads (read only — `services/quality/` stays exempt from (a)/(b)) the module-level code
  constants of `day_oracle.py`, `s1_checks.py` and `degraded.py`, every `{"code": "X"}` literal in
  `services/content_generation/` (it was `grounding.py` only), and `X = "X"` / `*_CODE = "…"` constants there
  (env-var-name constants such as `T2_JUDGE_GATE_ENV = "T2_JUDGE_GATE"` are not codes and are skipped).
- **D12 — one taxonomy for the Q0 corpus (S250).** The Q-2 corpus uses 12 class ids and 10 detectors the registry
  did not have. The cases are NOT relabelled (`class_id` / `detector` are q0_red_on_base LABEL_FIELDS). Instead:
  `aliases:` maps each Q0 id to canonical class(es) (`other.length`/`other.first_line` → `other.length_shape`,
  `other.brand_forbidden`/`other.forbidden_word` → `other.lexicon`, `other.banned_pattern` → `other.v1`,
  `other.brand_name`/`other.cannibalization` → `safety.tenant_isolation` (what F11/F10 already map to),
  `other.cta`/`other.faq_contract` → `other.c5`, `other.missing_field` → `struct.truncated`,
  `source.unsupported_specific` → `[fact.number, fact.inclusion]` — its cases are an added figure and an invented
  meal, so an alias may name a list). `other.degraded_detector` is a new class (kind `meta`: a detector outage is
  not a writing error, so no parity / enforce-gap warning), not an alias. `code_checks:` names the detector modules
  the corpus uses (`repair_contract`, `degraded`; plus `day_oracle`). New lint rule **(j)**: every Q0 case's
  `class_id` resolves (class or alias) and its `detector` is a gate, Jev key, A1 code or code check. An alias may
  not shadow a class id.
- **D13 — class detectors complete (S250).** `F2_banned_patterns` (other.v1), `F14_first_line`
  (other.length_shape) and `F2_style_warn` (other.lexicon, warn) were gates with classes but were not listed as
  class detectors; now every active gate is (unit test). `ITINERARY_DAY_COUNT_MISMATCH` is recorded as `enforce`
  (hard on an A1 writer-v2 draft since AA-645, `graph.V2_HARD_BLOCK_CODES`); the `struct.day_structure`
  enforce-gap warning goes away (16 → 15 warnings). Metadata only; no gate outcome changes.

## Tradeoffs

- The snapshot pins backend outcomes byte for byte; the frontend is covered by a superset test (labels are a
  deliberate superset, so a byte pin would be wrong).
- Q-2 (AA-925) had no commits when this branch was built, so the snapshot was taken on `origin/main` 7546b123.
  After Q-2 merges the branch must be rebased and the snapshot regenerated at commit A' (harness only on the new
  base), then the equivalence test re-run at HEAD.
- `scripts/setup_run_health_alarms.py` (7.0 for the ACP evaluator alarm, a different metric) stays outside the lint
  scope (only `scripts/aa729/` is scanned), so it needs no `qlint: allow`. The lint reports 0 escapes today.
- Review-page option texts "Critical (<5.0)" and "Low (5.0–6.9)" stay literal; only "7.0+" reads `PASS_LINE`.
- S250 snapshot coverage: main added post-gate steps that this refactor touches (`_cut_stock_lines`,
  `_apply_faq_answer_fit`, `_repair_feedback`'s F4 target). `_repair_feedback` is pure, so it joined the harness at
  A' (`t10.repair_feedback`, 40 cases × blog/facebook). The stock cut and the answer-fit flag need a spec text or an
  LLM step; their literal → constant swap is covered by their own tests (`test_aa780_s246_stock_cut_hashtags`,
  `test_aa779_faq_answer_fit`), which still assert the literal names.
- Q0 severity vs taxonomy severity: Q0 `severity` is per detector (`block`/`hard`) while the `other.*` classes
  the aliases point at are `warn`, and `other.degraded_detector` cases are held at `hard`. Left as is; input for
  AA-924 (per-violation severity), recorded here, not enforced.

## S4 — redundant-detector census (S250, read only, $0)

`python -m scripts.quality.redundancy_census` on the registry. The overlap is per class, so it is an upper bound;
each candidate was read against what it matches:

| Candidate (class cover from) | Reading |
|---|---|
| `F15_voice` ↔ `F2_banned_patterns` (other.v1, T9) | Real overlap: both are stock/cliché word lists. = AA-924's lexicon fold. |
| `F14_first_line` ↔ `F14_social_shape` / `F4_extreme_length` (other.length_shape, LinkedIn) | Partly real: `F14_first_line` (first line ≤ N chars) could fold into `F14_social_shape` as one shape gate with per-violation severity (AA-924 mechanism). Candidate. |
| `F2_superlatives` ↔ `F18_rarity` / `F19_authenticity` (fact.embellish) | Different matchers (stock superlatives vs rarity quantifiers vs testimonial voice); `F2_superlatives` + `F18_rarity` are both word-level overclaim lists → possible fold. Weak candidate. |
| `F10` ↔ `F11` (safety.tenant_isolation) | Not redundant: similarity vs another brand's name. Mutual class cover only. |
| `META_INCOMPLETE_SENTENCE` ↔ `MISSING_FIELD` (struct.truncated, A1) | Not redundant: cut sentence vs empty field. |
| `UNSUPPORTED_CLAIM`, `a1_promise_unsupported` (fact.inclusion via `ITINERARY_MEAL_TIME_INVENTED`) | Not redundant: the meal-time rule covers one sub-case of inclusion. |

Covered only by a model detector (not removal candidates: removing them trades a code check for a model call):
`F1_grounding` (F9 also judges numbers), `F2_platform_truth` (F9), `a3_question_*` (Jev pair).
The S1 code checks (`s1_checks`, `day_oracle`) are all shadow today, so none of them yet makes an A1 code
redundant. Result: **no removal beyond AA-924's 2 folds (F15_voice_warn → F15_voice; F2_banned_patterns +
F2_brand_forbidden + stock list → one lexicon gate), plus 1–2 candidates for the same mechanism
(`F14_first_line` into `F14_social_shape`; maybe `F2_superlatives` + `F18_rarity`)**. Reaching "remove at least 5"
needs the day oracle / s1_checks promoted to enforce first (then `ITINERARY_DAY_COUNT_MISMATCH`,
`ITINERARY_STILL_COMPRESSED`, `UNSUPPORTED_NUMBER`-style A1 codes become candidates).

**Go/no-go option 1b (information only).** `ITINERARY_DAY_COUNT_MISMATCH` is already hard on writer-v2 drafts
(option 1a shipped with AA-645). `DAY_COUNT_VS_DURATION` covers the same "days dropped" fault (Q0
`a1-day-count-vs-duration`) and also the duplicate-day case the canonical parser misses (Q0 `a1-day-duplicate`
is `DAY_OUTPUT_DUPLICATE`), so 1b (enforce `DAY_COUNT_VS_DURATION`, retire `ITINERARY_DAY_COUNT_MISMATCH`) is
net-zero on gate count and is the cleaner end state, but needs its precision read on stored tours first (D5:
≤ 3 hits in S248). Not changed here.
