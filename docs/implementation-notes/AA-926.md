# AA-926 — Q-1: error taxonomy, gate registry, single thresholds file and lint

Quality System v1 (root `docs/audits/2026-10-20-S245-quality-system/design.md` §3, §4.6, §5.3, Appendix A).
Constraint from the issue: **gate outcomes must not change**. The proof is a byte-identical snapshot of gate
outcomes taken before the refactor (commit A) and recomputed after it (`tests/unit/test_aa926_equivalence.py`).

## Decisions

- **D1 — YAML location.** `services/quality/{taxonomy,thresholds,paths}.yaml`, next to `registry.py`, not a
  top-level `quality/` folder (design §3.1). The Dockerfile copies `services/`, so the files ship in the api and
  worker images, and the deploy-dev path filter already covers `services/**`. No Dockerfile or workflow path change.
- **D2 — constants, not moved logic.** `services/quality/registry.py` holds the only gate-name literals, as plain
  `str` constants. Routing sets (`STYLE_ONLY_GATES`, `CHEAP_REPAIR_GATES`, `OWNED_BY_FIX_STEP`, `TRUTH_CUT_GATES`,
  `_ELIGIBLE_GATES`, `_QUOTED_GATES`, `TRUTH_GATES`) stay in their owner modules, built from the constants; their
  membership is pinned by the snapshot. The YAML carries per-gate metadata (classes, label, kind, channels,
  retired, show_in_filter). Persisted names (ledger gates, `F9_brand_voice` in `llm_call_log.quality_signal`,
  flags) are never renamed; retired names stay registered so old ledgers still resolve.
- **D3 — literal-lint scope.** AST scan of string constants (incl. f-string parts) in `api/`, `services/`,
  `shared/`, `worker/`, `scripts/aa729/`. Gate pattern `F\d+_[a-z][a-z0-9_]*` plus the exact registry names
  flagged `lint_exact` (`promises_an_option`, `within_tenant_reuse`, `T3_grounding`). Exempt: `__all__` lists,
  docstrings, comments, tests, docs, migrations, the YAML, the registry and the generated TS file. Structlog
  event names that match the pattern (`F9_sticky_*`) are registered `kind: telemetry` and use constants — no
  call-site exemption. Inline escape `# qlint: allow <reason>`, counted in `--report`.
  **A1 validate / brand-audit codes are mapped (lint error if unmapped), not de-literalised** — flagged in the PR.
  `FORBIDDEN_WORD` is both an A1 code and a T2-version gate name, so it is not `lint_exact`.
- **D4 — thresholds.** One canonical `pass_line: 7.0`; every consumer has its own key that `ref`s it. Other
  cut-offs moved only where the snapshot pins them at the boundary. `decision_question.accept_floor` /
  `reject_ceiling` (Jev, calibrated per question in the DB) are out of scope — a second, deliberate threshold
  source. `scripts/setup_run_health_alarms.py` (ACP evaluator alarm, different metric) is outside the lint scope.
  Every entry carries `calibration_run_id/precision/recall/n: null` and `calibrated: false` (design §5.3); the
  format check allows null `calibration_run_id` only when `calibrated: false`.
- **D5 — issue fields vs design v2.** `owner_gate`, `metric` and `tolerance` (issue scope 1) are derived by the
  loader (design §3.2 dropped them as stored fields: owner = detector with `mode: enforce`; metric/tolerance =
  default per severity, §4.2). `synthetic_examples` are the golden examples: ≥ 1 positive + ≥ 1 negative per
  hard/block class.
- **D6 — frontend.** `frontend/lib/quality-registry.generated.ts` is generated by
  `python -m services.quality.gen_frontend` ("GENERATED, do not edit"). `GATE_LABELS` keeps the 33 existing keys
  in their current order with the same labels, then adds labels for the four active gates that showed as raw
  codes (`F2_platform_truth`, `F2_superlatives`, `F2_style_warn`, `F19_authenticity`). `shared.ts` re-exports it.
  The review page reads `PASS_LINE` for "7.0+" and `canApprove`; score colours read `SCORE_BANDS`.
- **D7 — diff-hash job.** New **non-required** CI job `quality-paths` (job-level `permissions: contents: read`),
  script `.github/scripts/quality_paths.py` (stdlib + PyYAML, no `services` import). Deviation from design §4.6
  (step inside a required job): AA-919 moves it / makes it enforcing when it adds `quality/q2`.
- **D8 — taxonomy content.** 17 classes per design §3.3, `other.<alias>` at warn for F6, F7, S3, S4, S5, S7,
  C1, C3, C5, V1, plus `judge.excerpt_artifact` / `judge.missed` as `kind: meta`. Two extra warn classes
  `other.lexicon` (brand/word-layer rules) and `other.seo_length` (SEO length/shape codes) so every existing
  detector maps somewhere (design §7.6 allows new warn classes; reported in the PR). Examples are synthetic only.
- **D9 — registry safety.** `yaml.safe_load`; schema validated by unit tests; lookups used in request paths are
  total (unknown name → `None`, never `KeyError`). `services/__init__.py` and `services/quality/__init__.py` stay
  import-free so the Lint job runs the lint with only PyYAML installed.

## Changed

- Commit A adds the snapshot harness and a few **pure seams** (no value change) so inline 7.0 sites can be pinned:
  `t2_rewrite_job._t2_status`, `validation.handler._validation_route`, `admin_pipeline._tour_passed`,
  `admin_pipeline._score_band_where`, `admin_pipeline._SCORE_HISTOGRAM_CASE`.

## Tradeoffs

- The snapshot pins backend outcomes byte for byte; the frontend is covered by a superset test (labels are a
  deliberate superset, so a byte pin would be wrong).
- Q-2 (AA-925) had no commits when this branch was built, so the snapshot was taken on `origin/main` 7546b123.
  After Q-2 merges the branch must be rebased and the snapshot regenerated at commit A' (harness only on the new
  base), then the equivalence test re-run at HEAD.
