# AA-989 — The place layer, card links and embeddings follow a Master publish (S252)

Design input: root `.tmp-session/s252/aa988/design.md` §3 B/C/D, §4 C1/B1/B2/D1/D2. The orchestrator accepted the
§7 decisions as proposed: (1) automatic `place_extract` only for tours that already have a place build; (3) the
embeddings Done-when becomes "consumer (PAA landing) named and covered", no backfill; (4) register
`published_tours.content_embedding` as a dead column. Segments are in `AA-988.md` (same branch).

## Decisions

- **C1, $0 card relink inside atomize.** `_run_a3_atomize_background` calls
  `place_cards.relink_tour_place_cards(pool, tour_id)` after the segment stage and BEFORE `after_atomize`
  (place_extract). It reads the tour's active place atoms and runs `ensure_place_cards(ids, pool, max_places=0)`:
  rule skip, existing card by alias / core name / locality, stored miss — never a draft (`max_places=0` stops before
  `build_card_for_group`; the unit test pins 0 LLM client calls). Order matters: the card fields are in
  `components_hash`, so a relink after the extract would extract the tour twice. Best-effort; result key
  `place_cards_relink` (counters, or `failed: …`).
- **Cached misses now leave an atom row.** A group skipped on an active `place_card_miss` row used to leave its atoms
  with no `atom_place_card` row at all, so a re-created atom looked "never tried" (probe
  `place_card_links_missing`). `ensure_place_cards` now writes the atom-level miss row (`miss_reason` = the stored
  reason) for those atoms; new counter `miss_recorded`. The miss SQL never overwrites a link.
- **B1, "maintain what exists".** `enqueue.auto_allowed(db, tour_id)`: allowed when `PLACE_PIPELINE_AUTO` is on, or
  when the tour's source (`COALESCE(raw_tours.source_group_id, tour_id)`) has a `geo.tour_build` row that is not
  `retired` (read with `app.tenant_id` pinned, raw_tours is FORCE-RLS). Used by `after_atomize` (same idempotency key
  as before) and by the place-card build's relink (`place_cards_job._relink_places`). A source never built stays
  gated (coverage expansion = AA-905 / AA-784, S236). Result key `place_extract_trigger` = `auto` | `maintain_built`.
- **B2, atom ids in `components_hash`.** A re-upload (new tour_id → new atom ids, same text) or an action-only
  re-atomize no longer takes the rebase / `skipped_unchanged` path with `atom_ids` of replaced atoms. One-time
  effect: the next `place_extract` of every built tour rebuilds once; days are reused (same `days_hash`), vectors
  are reused by `text_hash`, names are already resolved, so it costs $0 unless a name is new.
  The admin backfill's `only_stale` now also compares `components_hash` (reads the atoms only for a tour the cheap
  checks call fresh).
- **TripPlanner saved pins (S252 AA-990 audit).** TripPlanner stores a pin as a `trip_events` row
  (`add_component` / `remove_component` / `reorder`, payload `component_id`) and resolves it against
  `catalog.v_tour_component.component_id` (after its own `tripplanner.component_id_map`, tp-017, for pre-flip ids).
  Nothing in TripPlanner re-derives an id. The CIS id is uuid5(source, day, itinerary spelling, country, activity),
  so a rewrite that respells a place, retypes its activity or moves it a day minted a new id and the rebuild's
  DELETE+INSERT dropped the pin. Chosen fix: **keep ids stable in CIS** (no id map, no TripPlanner change, no
  migration): `components.carry_over_ids` maps each new component that has no row of its own to the previous row of
  the same source for the same place — passes: same day + spelling (retyped), same day + destination, same day +
  place card, same day + link name, then any day + destination / card / link name — one-to-one and only on an
  unambiguous pair. The uuid5 is therefore the id of a place's first build. A place the rewrite removed loses its id
  (`ids_dropped` in the build counts) — the same outcome tp-017 accepted for an old id with no match.
- **D1, embeddings.** No new writer. Consumer = PAA landing (`atom_matching.py`, k=1 nearest), covered by the
  recompute's landing pre-pass on every run; nothing else reads `atom_embedding`.
- **D2, `gold_aa_internal.published_tours.content_embedding`.** No writer and no reader in any app (grep of CIS,
  Booking, TripPlanner, Partner, S252); only a passthrough column of `acp_contract.v_trip_registry` (migrations
  078 → 195), which no code selects. Registry row text for the root `docs/architecture/dead-table-registry.md` is in
  the S252 runbook (root repo, not this branch). Drop later by a CIS migration that recreates `v_trip_registry`.

## Tradeoffs

- **Id carry-over vs an id map.** A map table (CIS `geo.component_redirect` or a TripPlanner tp- table) would also
  survive a removed place being "re-pointed", but needs a migration in one or two repos plus a reader change in
  TripPlanner. Carry-over needs neither and keeps `catalog.v_tour_component` the only contract. Cost: a component id
  is no longer re-derivable from its fields (nothing derives it today; noted in CONTEXT.md).
- **Unambiguous pairs only.** Two new components on one destination and one old row → no carry-over (the pin drops)
  rather than a guess that could move a pin to the wrong activity.
- **Automatic place_extract on built tours is paid but small.** Days call only when the day text changed and the rules
  miss an overnight; embeds only for new texts; new names go to the debounced `place_geocode` under its own budget.
  Budget row `bedrock/job:place_extract`.
