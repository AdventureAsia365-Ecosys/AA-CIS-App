# AA-1125 — Platform › Delivery: Merge queue and Git map tabs (AA-CIS-App part)

Lane l11-delivery-tabs, S283. Builds on the AA-1108 Delivery page and pipeline. The collector change (merge-queue
timelines, commits and their files, the new `queue` and `git` sections of `summary.json`) lives in the root repo
(`tools/delivery/delivery_metrics.py`, its `docs/implementation-notes/AA-1125.md`).

Two PRs here (MIG-4, the AA-1108 pattern): the migration-only PR (CIS 445 + the compiled defaults +
`services/reports/delivery_settings.py` + `tests/integration/test_aa1125_migration_445.py`), then the code PR (this
note, the API section switch, the two tabs).

## Decisions

- **Same route, a `section` query parameter** (`dora` default, `queue`, `git`) instead of two new routes: no new staff
  policy entry, role-matrix or route-policy snapshot line, and the AA-1108 page keeps its URL. The default `dora` view
  now leaves `queue` and `git` out of each app, so the first load of the page stays the size it had (the git section is
  the largest part of the summary: the commit calendar, two churn windows and the 50-commit graph per repo).
- **Read-only, same cache.** The sections come from the same published `summary.json`, through the same in-process cache
  and `?refresh=1` floor (`docs_reader.CACHE_TTL_S`, `MIN_REFRESH_S`) and the same account-ID mask. Commit and pull
  request links sit under `url` / `*_url` keys (github.com only), commit SHAs under `sha`, so they pass the mask; commit
  titles are text and are masked like any other text.
- **Colours from settings (tech lead S279).** Six new settings (CIS 445, area `delivery`): green / amber pairs for the
  queue wait p95 (1 h / 4 h), the ejection rate (10 % / 25 %) and the flaky rate (5 % / 15 %); `cis.delivery.min_sample`
  (CIS 433) greys a value with too few entries, as on the DORA tab. The API grades them
  (`delivery_metrics.grade_queue`); the summary carries raw numbers with `n`.
- **Queue wait = enqueue to merge of each merged entry** (p50 shown, p95 graded); "to merge" counts from the first time a
  pull request entered the queue (ejections included). Ejection and flaky rates are over the entries that merged or
  were ejected; an entry a person or the agent took out is listed under "removed", not counted as an ejection.
- **Git map without a treemap**: the hotspot table with a drill-down (top-level directory, then its sub-directories or
  files) carries the same information, reads at 390 px and needs no new chart library. Author kinds per directory
  ("who changes what") are a column of that table. The commit graph is a list (squash merges keep main linear); a
  commit with two parents would show a square dot.
- **Tabs**: Merge queue and Git map sit after Overview in the existing tab list (`?app=merge-queue`, `?app=git-map`);
  inside them the repo (`?repo=`), period (`?period=d30|d90`) and directory (`?dir=`) live in the URL. A tab change clears
  them. Each tab loads its own section on first open; Refresh re-reads the summary and refetches both.

## Changed (against the issue)

- The issue named GraphQL `mergeQueue`; it lists only the entries in the queue now, with no history, so the root
  collector reads each pull request's REST timeline (added to / removed from the merge queue, merged) plus the
  merge_group runs it already stores. See the root note.
- Commits per week: the Git map shows the commit calendar plus a weekly bar chart under it, computed in the browser
  from the daily series (no extra summary field).

## Tradeoffs

- One request per tab against one bigger first load: the overview and app tabs load as before; the activity tabs
  cost one cached read each.
- Settings are read on every `section=queue` request (six `aget`, cached by the reader) so a changed threshold shows
  at once.

## Should know

- The tabs show "no repo ... yet" until the root collector has run with the AA-1125 code (the summary of an older run
  has no `queue` / `git` keys). The commit files of a cold store fill over a few hourly runs; the Git map shows the
  share read ("Files read").
- Only AA-CIS-App, AA-Booking and AA-Partner use a merge queue (`merge_queue: true` in root `tools/delivery/apps.json`);
  the other three repos are absent from the Merge queue tab by design.
- Visual run: `tests/e2e/visual/pages.ts` lists both tabs (`platform-delivery-queue`, `platform-delivery-git`).
- Tests: `tests/unit/test_aa1125_delivery_tabs.py` (sections, colours, 422, policy, mask),
  `frontend/lib/deliveryActivity.test.mjs` (calendar, weekly series, author shares, drill-down helpers),
  `tests/integration/test_aa1125_migration_445.py` (migration PR).
