# AA-1187 — Supplier pack and tour pack importers (CIS part)

Step 1 only (S296): the CIS data-entry bug fix that must ship before the content staff re-uploads tours (T01
enrichment). The Booking part (meal plan on the price setup Components sheet) is a separate PR of the same lane.

## Decisions

- **The bug.** The Upload preview called a row "already exists" when any raw tour had the same Name; Commit
  (`services/ingestion/handler.py`) matched Name + Provider. A re-upload with a different Provider was announced as a
  duplicate in the preview and then inserted as a second tour with a new key.
- **One function for both paths** (`services/ingestion/tour_match.py`, `match_existing`): preview and Commit cannot
  drift again. The rule, in order of preference:
  1. same Name + same Provider (the old key; the newest ingest wins, as before);
  2. same Name + same country, or the country unknown on one side;
  3. otherwise no match: a new tour.
- **Why Name + country, not Name + Provider, decides "the same tour".** The S295 data audit: Provider is optional
  (43 live tours have none) and the staff copy it by hand, so a typo, another spelling or a Provider filled in where
  the tour had none must not make a second tour. Country is required and normalized by the parser
  (`shared/country_resolver.py`), so the same Name in another country is a real other tour. The issue suggested
  "preview matches Name + Provider like Commit"; that would only make the preview agree with the bug (the different
  Provider would read "new" and still mint a tour). The lane brief asked that a Provider change never mint a tour,
  and this rule does that while keeping the preview and Commit equal.
- **Two operators really can sell a tour of the same name** (`near_duplicate.py`, S206). Such a row now goes to
  Duplicate Review instead of being inserted silently; the person picks Create a new tour there (decision
  `create_new`, Q6), so nothing is lost, it just needs one click. The preview says which Provider the existing tour has.
- **Review fix 1: Duplicate Review really offers Create a new tour for another Provider.** Before, the UI showed
  Create a new tour only for a deleted or hand-made match, so a live supplier match got Bypass / Merge / Replace /
  Keep both and another operator's tour could only be dropped or folded into the wrong tour. The staging list
  (`GET /admin/upload-staging/{batch_id}`) now returns `matched_other_provider` (computed in Python with
  `tour_match.same_provider`, the same normalization as the match, so the UI never re-implements it), and
  `stagingDecisions.ts` adds `create_new` to the choices when it is true. A note above the row names both Providers.
  The API already accepted `create_new` for a live match (`services/tour_lifecycle` `supersede`).
- **Review fix 2: a Merge never changes the Provider by itself.** `excel_merge.plan` treated `provider` like any
  field, so an untouched Provider was an `auto` change: a T01 enrichment re-upload (Inclusions added) with another
  spelling would have rewritten the operator once the draft was published. `plan` takes a new `ask` set (fields that
  are a conflict whenever they change, hand-edited or not); `_merge_inputs` passes `{"provider"}` when the sheet's
  Provider differs from the tour's (`same_provider`). The Merge panel's default for a conflict is "current", so the
  Provider stays unless the person takes the sheet's value; that choice's label reads "Keep the current value"
  (not "Keep the hand edit") when the field was not edited by hand. A case-only spelling (same after lower/trim) is
  planned as before (an `auto` change).
- **No source row id rule.** The Excel has no stable row id column that survives a hand-made T01 file (`sku` and
  `tour_id_external` are 67–100 % empty, gap report §2), so Name + country is the best key available.
- **The in-file check keeps Name + Provider** (two rows of one file, neither in the database): out of scope, unchanged.
- **Empty Itineraries.** Commit skips a row without Itineraries before matching (AA-604). The preview now checks in
  Commit's order, so a re-upload of an existing tour that left Itineraries empty is told "matches an existing tour but
  will be skipped on Commit; copy the tour's Itineraries" instead of "already exists" (the issue's "warn when
  Itineraries is empty").
- **DB-01.** The Provider stays internal: it appears in the staff preview (`matched_provider`) and Duplicate Review
  only, never in a tenant response. No route, setting, migration or threshold is added.

## Changed

- New `services/ingestion/tour_match.py` (`MATCH_SQL`, `match_key`, `match_existing`, `preview_message`).
- `services/ingestion/handler.py`: Commit's existing-tour query is `match_existing`.
- `api/routers/admin_pipeline/uploads.py` (preview): the name-only batch query is gone; each row asks `match_existing`;
  the empty-Itineraries check runs before the match; a `duplicate_tour` entry also returns `matched_tour_id` and
  `matched_provider`.
- `docs/context/pipeline-stages.md`: an "A0 match" bullet.
- Review fixes: `tour_match.same_provider`; `excel_merge.plan(..., ask=())`; `uploads.py` `_merge_inputs` (Provider is
  asked) and `list_upload_staging` (`matched_other_provider`); frontend `stagingDecisions.ts`
  (`OTHER_PROVIDER_DECISION_LABELS`), `page.tsx` (`MatchNote` other-provider line), `messages.ts`
  (`otherProviderMatch` EN + VI), `MergePanel.tsx` + `tourDraft.messages.ts` (`keepCurrentValue`, conflict count copy).

## Tradeoffs

- The preview now runs one small query per row (up to `max_tours`) instead of one batch query; `raw_tours` holds about
  a thousand rows and Commit already queried per row, so the cost is small and the two paths stay one rule.
- Routing a same-Name, same-country, other-Provider row to Duplicate Review costs the person a click when it really is
  another operator's tour; the alternative (a silent second tour) is the bug.
