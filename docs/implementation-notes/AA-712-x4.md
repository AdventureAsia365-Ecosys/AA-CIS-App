# AA-712 X4 — CIS 270: TripPlanner keeps only the catalog views and the Model Gateway (lane aa712-zero, S248)

Branch `feat/aa712-revoke-tp-cis-grants`. The CIS half of the AA-847 leftovers: revoke the `tripplanner` grants on
CIS objects that its first pilot read directly. Companion PRs: AA-TripPlanner-Web `feat/aa712-tp-cis-only` (the
legacy readers removed, with a guard test) and `feat/aa712-tp018-drop-frozen` (tp-018, needs approval after the DRY
RUN); AA-CIS-Infra byte copy. Written while implementing.

## Decisions

- **One migration, five relations, two schemas.** `REVOKE ALL` on `gold_aa_internal.published_tours`,
  `shared.destinations`, `shared.v_destination_photos`, `shared.v_tour_photos`, `acp_contract.v_active_tour_atoms`
  (a table-level REVOKE also removes the CIS 216 column grants). USAGE on `gold_aa_internal` / `acp_contract` goes
  only when nothing else of the schema is granted (the 254 pattern; otherwise a NOTICE and USAGE stays).
- **Kept: the Model Gateway (CIS 173) and the catalog.** TripPlanner's own model calls read `llm_role_config` /
  `llm_model_catalog` and write `llm_call_log`; that is a standing contract, not a content read. Schema USAGE on
  `shared` stays for those three. `geo.name_norm` EXECUTE (228) is untouched.
- **Guards check the outcome, not the statements.** After the revokes: no table or column privilege of
  `tripplanner` on any relation of `gold_aa_internal`, `silver_aa_internal`, `acp_contract`, `acp_shared`, `shared`
  except the three gateway tables; `catalog.v_tour` SELECT and `llm_call_log` INSERT still there. A grant made by
  another grantor (the cis_owner REVOKE would not remove it) fails the apply instead of passing silently.
- **`validity_fix.CROSS_APP_TABLES` drops `tripplanner.itinerary_components`.** The table goes with tp-018, and the
  CIS runtime could not read it anyway (the report said "not readable").

## Tradeoffs

- Number 270 assumes 269 is taken by the CRM owner registry grant (AA-932 lane, same session). If the order changes,
  renumber the file, its registry row, the test name and the Infra copy together.
- The Dev grant on `published_tours` (and USAGE on `gold_aa_internal`) has no CIS migration of its own (out of band
  in the pilot), so the test seeds it explicitly to reproduce Dev.
