# AA-1157 — migration 470 (view-as log takes staff-role sessions)

Migration-only PR (MIG-4) for the owner's read-only "view as a lower staff role". The code PR follows once 470 is
applied on Dev; its notes are `AA-1157.md`.

## Decisions

- One table, two kinds: `shared.staff_view_as_session.tenant_id` becomes nullable and `view_role` is added; a CHECK keeps
  exactly one of the two. The role code is checked for format only (the API checks it against the built-in and custom
  roles), so a new role needs no migration.
- The guard trigger gets an explicit branch for a row without a tenant: `shared.tenant_account_closed(NULL)` is true
  (NOT EXISTS over a NULL key), so the 364 body would have let any role row be deleted. A role row may be deleted only
  once it has ended and started more than 24 months ago (the DM-7.1 window; no purge job yet).
- `view_role` joins the UPDATE immutability tuple (an UPDATE still only ends an open session).

## Changed

- Nothing in the grants (cis_app keeps the 364 rights; the guard limits UPDATE and DELETE).

## Tradeoffs

- Contract class (DROP NOT NULL, a CHECK, CREATE OR REPLACE FUNCTION): applied by Migration Apply once every job table
  is idle. Behaviour on apply is none for running code (every existing row is a tenant row and passes both CHECKs).

## Should know

- Guard 1 probes the trigger with a throwaway role row inside a subtransaction that is always rolled back; it needs at
  least one `shared.admin_users` row (Dev has them; an empty test database skips the probe).
- Rollback is destructive: put back the 364 guard body first, then delete the role rows (DRY RUN procedure).
