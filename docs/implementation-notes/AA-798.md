# AA-798 — Real LLM cost in tenant usage/billing

Status: migration half written (S235, lane B, branch `feat/aa-798-real-llm-cost`). The app half
(admin billing defaults, tenant `/v1/billing` projection, `/admin/tenants/{id}/usage`) comes later
on this same branch.

## Decisions

- **Migration 223 is a baseline capture, not a patch.** The live `shared.v_tenant_monthly_usage`,
  `shared.membership_plans` and `shared.tenants.plan_id` were created by hand on Dev and exist in no
  migration (synthesis R4). The repo's only view definition is `007_tenant_usage.sql`, which has
  other columns (`month`, `total_calls`, ...). 223 was written from a read-only live dump taken
  14/10/2026 (`.tmp-session/s235/view_dump.json`: viewdef, owner, grants, dependents, plans DDL +
  rows, `plan_id` + FK).
  - `membership_plans`: `CREATE TABLE IF NOT EXISTS` with the live columns, defaults, PK and
    `UNIQUE (plan_name)`. The five live plans are seeded with their live ids, `ON CONFLICT
    (plan_name) DO NOTHING`. This is a no-op on Dev.
  - `tenants.plan_id`: `ADD COLUMN IF NOT EXISTS plan_id UUID REFERENCES shared.membership_plans(id)`.
    The FK gets the live name `tenants_plan_id_fkey` and is created only together with a new
    column, so Dev gets no duplicate FK (checked: two runs leave one FK). This is a no-op on Dev,
    and there is no backfill: Dev was backfilled in S234, and a fresh DB has no tenants.
  - View: `DROP VIEW IF EXISTS` + `CREATE VIEW`. `CREATE OR REPLACE` cannot turn the 007 shape
    (CI) into the live shape. The 16 columns keep the live names, types and order, and every
    expression except `llm_cost_usd` is the live one unchanged. A `DO` block fails the migration
    if the column list differs from the live list.
- **`llm_cost_usd` definition.** It is `SUM(shared.llm_call_log.cost_usd)` where `tenant_id` = the
  tenant, `created_at` falls in the current calendar month (the same `date_trunc('month', now())`
  boundary as the other columns, written as a range so `idx_llm_call_log_tenant_created` is used),
  and `quality_signal` does not contain `{"shadow": true}`. It is rounded to 4 dp and COALESCEd to
  0, as the live column was.
  - Jev is included: `decide()` logs every TypeSafe call to `llm_call_log` (role `validate`,
    model `jev-latest`). The issue scope says "incl. Jev".
  - Shadow rows are excluded. `llm_call_log` has no shadow column, but `shared/llm_client/shadow.py`
    always writes `quality_signal = {"shadow": true, "shadow_of": ...}`. Shadow runs are AA's own
    model experiments (ADR 0006), not the cost of serving the tenant.
  - Rows with `tenant_id IS NULL` (A-series/platform) are not attributed to any tenant, including
    aa_internal. Platform spend already has its own place (`/admin/overview` `_MTD_LLM_SQL`).
- **No GRANT statements.** The live ACL is owner-only: `information_schema` lists only
  `aa_cis_admin`'s implicit owner privileges. DB Migrate runs as the CIS api `DATABASE_URL`, which is
  the master user `aa_cis_admin`, so DROP + CREATE reproduces the same owner and ACL. An explicit
  `GRANT ... TO aa_cis_admin` would also fail on CI, where that role does not exist. `aa_app_user`
  never had access to this view, and none is added because billing data stays on the admin path.
- **Plain `DROP VIEW` (no CASCADE).** The live dump found no dependents. If one appears before
  apply, the migration fails loudly instead of silently dropping it.

## Tradeoffs

- **NUMERIC precision of `membership_plans`.** The dump recorded `data_type = numeric` only, not
  precision/scale. The live values (`299.00`, `4.0000`) imply scale 2 and 4. The file uses
  `NUMERIC(10,2)` / `NUMERIC(10,4)`, so precision 10 is inferred. This only matters on a fresh DB
  (`IF NOT EXISTS` skips it on Dev). A read-only check before merge would confirm it (see "Should
  know").
- **Shadow exclusion and the AA-766 "±$0.01" check.** A raw `SUM(cost_usd)` over a tenant's rows
  includes shadow rows. The verify query must use the same shadow filter as the view.
- Per-month history is not kept: the view stays "current month only", as live. A history view is
  out of scope.

## Should know

- **The CI test DB cannot create this view through conftest.** No repo migration creates
  `gold_aa_internal.tenant_tour_versions` (107/108/109 already warn "does not exist" in CI), and the
  live view joins it. conftest's own run of 223 therefore logs a warning and rolls back, and the CI
  DB keeps the 007 view. This follows lesson S231 (conftest swallows migration errors).
  `tests/integration/test_aa798_usage_view.py` handles it as follows:
  - It runs the 223 body itself, twice, to prove idempotency.
  - It creates a minimal stand-in for `tenant_tour_versions` only when the table is missing.
  - It asserts the view column exists before reading any value, then checks the column order, the
    llm_call_log sum and the plan quotas.
  - It rolls everything back, so the shared test DB is unchanged.

  Ran locally against Postgres 16: 4 passed, and the conftest output showed the expected
  `Warning 223 ... tenant_tour_versions does not exist`.
- Infra copy: `infra/AA-CIS-Infra/db/migrations/cis/223_tenant_usage_real_llm_cost.sql` must be a
  byte copy (DB Migrate checks sha256). Apply order: Infra PR merged → DB Migrate `check` → `apply`
  → verify → then merge the app PR.
- Read-only pre-apply checks on Dev:
  - `SELECT column_name, numeric_precision, numeric_scale FROM information_schema.columns WHERE table_schema='shared' AND table_name='membership_plans' AND data_type='numeric';`
    This confirms the inferred precision (informational; `IF NOT EXISTS` makes it a no-op either way).
  - Re-run the dependents query from `view_dump.py`. It must still be empty.
- Post-apply verify:
  - `SELECT tenant_name, llm_cost_usd FROM shared.v_tenant_monthly_usage ORDER BY 2 DESC;`
  - Compare with `SELECT tenant_id, round(sum(cost_usd),4) FROM shared.llm_call_log WHERE created_at >= date_trunc('month', now()) AND NOT (quality_signal @> '{"shadow": true}') GROUP BY 1;`
  - Atlas and Terra should show dollars, not cents.
