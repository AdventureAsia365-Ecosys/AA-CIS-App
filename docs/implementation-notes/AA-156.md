# AA-156 — Master active/inactive + Notification Layer Phase 1

## Decisions

- **`tenant_id` in notification**: hardcoded to `AA_INTERNAL_TENANT` (`00000000-0000-0000-0000-000000000001`) for master toggle — master content is aa_internal-only. If B2B tenants ever have their own masters, caller must pass correct `tenant_id` to `NotificationService.emit()`.
- **No `updated_at` in PATCH UPDATE**: `published_tours` has no `updated_at` column in schema (not added in 052). UPDATE only sets `master_status`.
- **`request.json()` instead of Pydantic body**: admin.py pattern uses `request: Request` everywhere, not Depends. The PATCH endpoint follows the same pattern — body parsed inline.
- **NotificationService never owns a connection**: always injected by caller inside their `conn.transaction()` block — pure INSERT, no own transaction.
- **Route order**: `/notifications/count` and `/notifications/read-all` registered before `/notifications/{notif_id}/read` to avoid FastAPI greedy matching on `{notif_id}`.
- **Frontend badge**: added to `AdminSidebar` (not a separate layout file — the admin layout is a passthrough). 30s polling via `setInterval`. Dropdown shows last 10 notifications inline.

## Changed

- `api/routers/admin.py`: added import `Query` from fastapi, import `NotificationService, EventType` from services.notifications, plus 5 new endpoints appended at end.
- `services/notifications.py`: new file. `EventType` enum uses unaligned `=` (no multi-space alignment) to pass CI flake8.
- `api/migrations/053_notifications.sql`: uses `VARCHAR(100)` for `tenant_id` (FK to `shared.tenants.tenant_id` which is VARCHAR(100) — confirmed from schema).
- `frontend/app/admin/_components/AdminSidebar.tsx`: added `useCallback`, `Bell` icon, `Notif` interface, unread count state, dropdown panel.

## Tradeoffs

- **Notification dropdown in sidebar vs dedicated page**: sidebar inline dropdown is lower friction for ops use. A full page can be added later if notification volume grows.
- **30s polling vs WebSocket**: polling is simpler, no infra change. WebSocket would require FastAPI SSE or Redis pub/sub — deferred.
- **No pagination in dropdown**: shows last 10. Full list available via GET /admin/notifications with offset.

## Should know

- Migration 053 must be applied before deploying — `shared.notifications` table must exist or the notification INSERT will fail at runtime.
- The `master_status` enum cast `$1::gold_aa_internal.master_status_enum` is explicit to avoid asyncpg type inference issues with custom PG enums.
- Migration 052 must also be applied (it creates `master_status` column). Handoff says it was NOT yet applied to dev DB as of session 40.
