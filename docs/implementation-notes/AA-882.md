# AA-882 — server-side staff authz, phase GĐ1 (money / model / Jev / job-control writes)

Design: AA-Ecosys `docs/audits/2026-10-17-S241-admin-console/README.md` §5.1–5.3, §7 GĐ1, §11 R2/R3.
Builds on GĐ −1 (#791: every /admin route needs the secret, constant-time compare).

## Decisions

- **One module, `api/core/staff_authz.py`**: `ROLE_PERMS`, `OWNER_PERMS`, `POLICY`, `MACHINE_ROUTES`,
  dependency `staff_policy`. Policy is keyed by `(method, route template)` (R3: six routers share the
  `/admin` prefix and `admin_llm_ops` mixes `GET llm-config`, needed by S1 for reviewer/content, with
  admin-only PATCHes).
- **`staff_policy` is attached router-level** on the five GĐ1 routers (`admin_llm_ops`,
  `admin_budgets`, `admin_job_runner`, `admin_decisions`, `admin_settings`). Routes without a POLICY
  entry pass through unchanged after the secret check, so every GET stays open to every staff role.
- **`staff_policy` depends on `verify_admin_secret` itself** (FastAPI caches it per request, so it runs
  once next to the router-level copy). That makes it self-contained on `admin_decisions` and
  `admin_settings`, which had no router-level secret check, and the S241 route-auth guard sees it as
  a staff dependency without any change.
- **Machine principal (R2)**: secret + no `x-admin-role` -> machine, allowed only on `MACHINE_ROUTES`
  (CI deploy preflight/smoke GETs, the five ops-probe Lambda POSTs). A role header that is present but
  not a staff role (empty, `tenant`, typo) is a staff principal with no permissions -> 403, never a
  machine fallback.
- **Capabilities for the GĐ1 routes**:
  - `ai.admin`: PATCH llm-config/{stage}, llm-config/{stage}/route, llm-catalog/{model_key}; PUT
    decisions/questions/{key} (Jev mode/floors).
  - `spend.write`: PUT budgets, POST cost-explorer/check (paid CE API call, button on External Spend),
    POST/DELETE Jev credit top-ups (a money ledger, so spend rather than ai).
  - `ops.write`: job cancel/retry, retention run/schedule, dfs-balance/check, jev-canary/check,
    jev/402-sweep (the scheduled probes; machine-allowed except cost-explorer).
  - `content.settings.write`: PATCH settings/seo.
- **`staff.write` is an owner flag, not a role permission** (`OWNER_PERMS`, S241 Q2: Nghiệp + one
  break-glass account). No column for it yet (`admin_users.is_owner`, GĐ5) and no route uses it.
- **Role sync with the frontend is a test, not a shared JSON**: the backend image does not ship
  `frontend/`, and Vercel builds `frontend/` alone, so neither side can import a file from the other
  at runtime. `tests/unit/test_aa882_staff_authz.py` parses `frontend/lib/rbac.ts` (`StaffRole`,
  `STAFF_ROLES`, `ROLE_LABEL`) and fails when the role sets differ. A FE capability map comes with GĐ4b
  (deny-by-default BFF), generated from the route snapshot.

## Changed

- `api/core/staff_authz.py` (new).
- Router-level `dependencies=[Depends(staff_policy)]` added on the five routers above (next to the
  existing `verify_admin_secret` where present). Inline secret checks in the endpoints are untouched.

## Tradeoffs

- Route template from `request.scope["route"].path`: on FastAPI >= 0.143 it does not carry an
  `include_router(prefix=...)`. All POLICY routers are included in `api/main.py` without a prefix;
  the route-policy test checks that the walked full path equals `route.path` for every POLICY route,
  so a future include prefix fails CI instead of silently skipping the policy. If the route can not be
  read at all, `staff_policy` fails closed (403).
- Header trust stays until GĐ4 (Bearer staff JWT): anyone with the secret can still send
  `x-admin-role: admin`. GĐ1 narrows what the BFF's reviewer/content sessions can do, it does not
  make the secret less powerful.

## Should know

- **Tenant proxy staff branch now forwards the role** (`frontend/app/api/tenant/[...path]/route.ts`,
  review fix in this PR). It sends the secret to any backend path; before the fix it sent no
  `x-admin-role`, so the backend saw every staff session there as the machine principal and any staff
  role (`API_RULES.tenantProxy` = all staff) could call the four machine-allowed POLICY POSTs through
  `/api/tenant/admin/...`: dfs-balance/check, jev-canary/check, jev/402-sweep, retention/schedule
  (`waves/check` is a machine route with no POLICY entry, so it is not narrowed in GĐ1 at all). These
  are not all harmless probes: jev-canary/check makes one real, billed Jev decide call and resets the
  Jev breaker on success; only retention/schedule is idempotent per day
  (`idempotency_key retention:<kind>:<day>`). The proxy now sets `x-admin-role = auth.role` (verified
  JWT role), like `/api/admin/[...path]`: admin keeps every route, reviewer/content get 403 on POLICY
  routes, GETs are unchanged. Side effect: tenant writes behind `_require_tenant_admin`
  (`api/routers/admin.py`) now work for an admin through this proxy (they 403'd for every role before).
  No FE page calls a POLICY route through `/api/tenant` (LLM, budgets, decisions, jobs, settings all go
  through `/api/admin`), so nothing that worked breaks.
- `POST /admin/cost-explorer/check` has no machine caller (grep of AA-CIS-Infra main 11c542f, Infra PR
  #105, the workflows, AA-Booking, TripPlanner and scripts, per review), so it stays off
  `MACHINE_ROUTES`.
- The Lambda paths in `MACHINE_ROUTES` mirror AA-CIS-Infra
  `accounts/aa365/lambda_src/dfs_balance_check/handler.py` `_ALLOWED_PATHS` (not in this repo, so not
  test-checked); the CI GETs are checked against `.github/workflows/deploy-dev.yml` by a test.
- Post-deploy verification (design §7 GĐ1): deploy smoke green, the next deploy's preflight green,
  one manual Lambda invoke (log shows 200s), reviewer gets 403 on `PATCH /admin/llm-config/{stage}`.

## Tests

- `tests/unit/test_aa882_staff_authz.py`: decision table (16 POLICY routes x admin/reviewer/content/
  unknown/machine), real-app checks (non-admin roles and off-list machine refused before the DB; admin
  reaches PATCH llm-config / PUT budgets / retention run; machine reaches retention/schedule; GET
  llm-config and the CI smoke GETs open to every role and the machine), POLICY/MACHINE_ROUTES name real
  routes, every `/admin` path in `deploy-dev.yml` is a machine GET, staff roles equal `lib/rbac.ts`.
- `tests/unit/test_aa882_route_policy.py`: snapshot `tests/unit/snapshots/aa882_admin_write_policy.json`
  (81 non-GET /admin routes, 16 under POLICY at commit time). Fails only for a GĐ1-router write without
  policy, a POLICY route not running `staff_policy`, or a POLICY route behind an include prefix; drift is
  a warning. Regenerate: `python -m tests.unit.test_aa882_route_policy`.
- Tenant proxy (review fix): reviewer/content with the proxy's headers get 403 on the four
  machine-allowed POLICY POSTs (detail names `ops.write`), admin reaches retention/schedule, and a
  source check that both secret-carrying catch-all BFFs (`/api/admin`, `/api/tenant`) forward
  `x-admin-role` from `auth.role` (removing the line from the tenant proxy fails it). The repo has no
  FE test runner, so the BFF side is a source check; `tsc --noEmit` and eslint pass on the route.
- Both files also pass on FastAPI 0.143.3 (`_IncludedRouter`), with the S241 route-auth guard.
- Mutation check: removing `staff_policy` from `admin_budgets` fails 6 tests (route-policy + app deny).
- Importing `api.main` locally tries to read the Sentry DSN from Secrets Manager with the default AWS
  profile (MFA prompt -> GetPassWarning). Run the unit suite with the AWS config/credentials files
  pointed at /dev/null to keep it offline; CI has no AWS credentials so it is unaffected.

# AA-882 — phase GĐ3 (policy on every /admin router, the staff /v1 routers, enforcing test)

Design: same README §5.2–5.3, §7 GĐ3, §11 R17. Builds on GĐ1 (#793). Branch `feat/aa-882-g3`.

## Decisions

- **Mapping rule.** The capability of a route follows the S241 §5.1 table first, then the page that
  calls it (`frontend/lib/rbac.ts` PAGE_RULES): a write called only from an admin-only page gets an
  admin capability; a write of an every-staff content page (Upload, S1, Review) keeps an every-staff
  capability (`content.write` / `review.act`). Where §5.1 and today's page rule disagree (Master
  Content lifecycle, Settings brand), §5.1 wins, like GĐ1 already did for `PATCH settings/seo`.
- **Circular import.** `admin.py` defines `verify_admin_secret` and now also needs `staff_policy`, while
  `staff_authz` used `Depends(verify_admin_secret)` imported from `admin.py`. `staff_policy` now reads
  the `X-Admin-Secret` header itself and calls `admin.verify_admin_secret` lazily (same function, same
  503/403, `admin.ADMIN_SECRET` still the monkeypatch point), so `admin.py` can import it at the top.
- **Two dependencies.** `staff_policy` (secret, then POLICY) on every router whose only staff guard is
  the secret. `staff_policy_if_staff` (POLICY only when the request carries the *valid* secret; a
  no-op otherwise) on the routers whose own guard also admits someone else or answers differently:
  `admin_pipeline` (brand-identity takes a tenant JWT, AA-424), `admin_atoms` (logs a refused tenant
  Bearer, AA-859), `/v1/pipeline`, `/v1/rules`, `/v1/social` (401 without credentials, 403 for any JWT,
  secret read from the env per call). A missing/wrong secret is left to that guard so status, detail
  and the AA-859 log line are unchanged. "Valid" = `admin.ADMIN_SECRET` or env `ADMIN_SECRET` (the same
  ECS secret; the /v1 guards read the env, admin.py reads it at import). `staff_policy_if_staff` is
  deliberately NOT in the S241 route-auth guard's STAFF_DEPENDENCIES (it is no auth check alone);
  `staff_policy` is (it now calls the secret check directly instead of `Depends(verify_admin_secret)`).
- **Capabilities, GĐ3 routes** (full table in `api/core/staff_authz.py` POLICY):
  - every staff role: Upload (`upload-url`, `ingest-s3`, `upload-staging/{id}/decide`, raw-tours
    set-active/delete, source tours trash/restore), S1 (`run-tour`, `run-tour-async`, `s1-batch/submit`,
    `s1/seo-prefetch`), tour edits (country, raw, generated, revalidate, versions promote), `/v1/pipeline/run`
    -> `content.write`; Review Queue approve/reject/dismiss/supersede (admin + /v1/pipeline) -> `review.act`;
    notification bell PUTs -> `content.read`.
  - admin: master lifecycle + trip-page publish -> `master.admin`; atomize/atom patch + `/v1/social/batch-review`
    -> `atoms.write`; photos sync/assign -> `photos.write`; A4 force-unpublish -> `a4.unpublish`;
    content-quality writes (10) -> new `quality.write`; brands + brand-identity (staff branch) +
    `/v1/rules/{id}` -> `content.settings.write`; tenant writes -> `tenant.write`; places backfill,
    segment-research run, waves create/close/check, trip-pages recheck -> `ops.write`.
  - admin-only GETs: tenants list/usage/audit/config/rewrite-activity, Tenant 360 cost/quality/markets,
    `/admin/billing` -> `tenant.read`; budgets, cost-explorer, dfs-balance, dfs-usage(+by-country),
    llm-usage calls/tree, spend/daily -> `spend.read`; `/admin/overview`, `/admin/infra/status`,
    POST segment-research/preview (dry run) -> `ops.read`; AA-883 `/admin/platform/staff` (+ detail)
    -> `staff.read`.
- **New capability `quality.write`** (admin): the T2/T9 quality writes (sentence suggest/apply, labels,
  regenerate angles, place cards) are tenant-output corrections, not atoms or A4; folding them into an
  existing capability would have widened that one. One line in ROLE_PERMS.
- **AA-883 staff routes not on main yet.** POLICY has `GET /admin/platform/staff` and
  `GET /admin/platform/staff/{staff_id}` (`staff.read`), listed in `AWAITING_ROUTE` so the "policy entry
  without route" check skips them. The enforcing test also requires a POLICY entry for EVERY
  `/admin/platform/*` route, so if AA-883 names the detail parameter differently (`{id}`,
  `{admin_user_id}`) CI fails there instead of leaving the detail readable by every staff role.
- **Machine allowlist unchanged** (9 routes: 4 CI GETs, 5 Lambda POSTs). Newly under POLICY and
  machine-allowed: `POST /admin/waves/check` (ops.write), `GET /admin/overview` (ops.read).

## Changed

  `STAFF_PATH_PREFIXES`, `staff_policy_if_staff`, `_is_valid_secret`; `staff_policy` no longer
  `Depends(verify_admin_secret)` (lazy call, see circular import above).
- Router-level dependency added on `admin`, `admin_a4`, `admin_api_docs`, `admin_content_quality`,

  machine principal: every /v1/pipeline write and the staff brand-identity POST would be refused).
- Tests: `test_aa882_route_policy.py` is enforcing (see its docstring); snapshot renamed
  `aa882_admin_write_policy.json` -> `aa882_staff_route_policy.json` and widened to every staff route
  and method (195 routes, 105 with a capability) because GETs now carry policy too.
  `test_aa882_staff_authz.py` generalised from "every POLICY route is admin-only" to per-capability;
  new `test_aa882_gd3_router_samples.py` (a sample per router x admin/reviewer/content/machine through
  the real app). Callers in existing tests that wrote with the secret and no role now send
  `x-admin-role: admin` as the BFF does (`test_aa799_pipeline_auth`, `test_aa859_admin_atoms_staff_only`,
  `tests/test_social_batch_review.py` — the last is outside the CI test paths, fixed anyway).
- `CONTEXT.md` "Staff roles and permissions": capability list, both dependencies, every secret BFF,
  the behaviour change.

## Tradeoffs

- **Design §5.1 over today's page rules** for Master Content lifecycle and Settings brand writes:
  reviewer/content can open both pages but now get 403 on those buttons (the UI shows the backend
  detail). The alternative (content.write) keeps today's behaviour but leaves `master.admin` unused and
  contradicts GĐ1's `PATCH settings/seo`. One POLICY line each to flip if Nghiệp disagrees; GĐ0 (nav
  split) should hide those buttons for non-admin.
- **GETs kept open** even on admin-only pages when every-staff pages share them or the data is content
  QA rather than money/accounts: job-runner reads (S1 polls `jobs/{id}`), `llm-config`, `llm-catalog`,
  `llm-shadow/report`, `decisions/*` reads, `decisions/jev-credit` (Settings tab every role can open
  until GĐ0 moves it), A4/content-quality/dashboard/SEO/photos reads, `tenants/{id}/details` (Master
  Content reads the aa_internal catalog through it), `/admin/search` (palette), `unmapped-market-requests`.
- **Anonymous calls to `admin_pipeline` writes still answer 422** before the inline secret check when
  the body is invalid (pre-existing: inline checks run after FastAPI's body validation). The endpoint
  never runs; the policy is not involved without the secret. Not changed here.
