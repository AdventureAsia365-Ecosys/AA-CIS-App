# AA-553 — Cross-Tenant Oversight vs Tenants/Tenant Activity overlap review + sidebar move

## Decisions

- **Part 1 stayed comment-only, no code** — per the issue's explicit requirement. Findings posted
  as a Linear comment, decision on merge direction left to Nghiệp/Claude Chat.
- **Part 2 — kept "Atom Curation" admin-only (`isAdmin && ...`) even though its new home,
  "AA Internal Content", is otherwise NOT role-gated** (Upload/S1 Rewrite/Review/Brand/Master
  Content all render for `reviewer`/`content` roles too). `middleware.ts`'s `PROTECTED_ROUTES`
  still restricts `/admin/atom-curation` to `roles: ["admin"]` — left untouched, out of this
  issue's scope. Without the `isAdmin` guard, the move would have put a dead link (redirects to
  `/login`) in front of every non-admin user landing in that group. Live-verified this session
  only as `e2e-test-admin` (role `admin`) — did not spin up a separate `content`/`reviewer` test
  login to independently confirm the link stays hidden for those roles; the `isAdmin &&` guard is
  the same conditional-render pattern this file already uses for the Dashboard fallback a few
  lines above, so it's trusted by precedent rather than independently re-tested end-to-end here.
- **Accent color kept `A.red`** (not `A.gold` like its new AA Internal Content neighbors) —
  `accent` in this file is a per-item visual signal, not itself an access gate (the real gate is
  `middleware.ts`, a separate file) — keeping it red preserves the "this one is still admin-only"
  visual cue even though it now sits in an all-roles group.
- **Did not touch the in-page `<h1>Master Content Pipeline (01-05)</h1>` heading** on
  `/admin/atom-curation` itself, even though it's visibly the same "Pipeline" naming AA-552
  already flagged as wrong (see Live Verify screenshot below) — out of scope for this issue,
  which only asked to move + propose new names for the SIDEBAR label. Worth folding into whichever
  follow-up issue implements the chosen rename, so the sidebar label and the page's own heading
  don't end up saying two different things.

## Changed

- `frontend/app/admin/_components/AdminSidebar.tsx`: removed the "Atom Curation" `NavItem` from
  the "ACP v2 — Setup & Approval" group, added it to "AA Internal Content" right after
  "Master Content", wrapped in `{isAdmin && ...}`. No backend change, no migration, no
  `middleware.ts` change — the route's own access control is unchanged.

## Tradeoffs

- Considered changing `middleware.ts` to also allow `reviewer`/`content` for `/admin/atom-curation`
  now that it visually sits in an all-roles group — rejected: that's a real access-control
  decision (who should see platform-wide Master Content Atom/Segment/Score/Route/Hub/Slate data),
  not implied by "fix the sidebar grouping," and the issue didn't ask for it. Flagging it as a
  question worth asking Nghiệp separately if the intent behind moving it into "AA Internal
  Content" was also to eventually open it to content/reviewer roles.

## Should know

- Part 1's full comparison (file:line evidence for every one of the issue's 5 numbered questions)
  is posted as a Linear comment on AA-553, not duplicated here — see that comment for the
  reasoning. One-line summary: Content Log/Publish Log (Cross-Tenant Oversight) and
  Write-Gate+Review/Publish (Tenant Activity) genuinely read the exact same 2 backend endpoints
  (`GET /admin/a4/content-log`, `GET /admin/a4/publish-log`) and the exact same 2 tables
  (`acp_shared.content_piece`, `acp_shared.publish_log`) — confirmed by reading
  `api/routers/admin_a4.py` and `frontend/app/admin/_components/auditPanels.tsx` directly, not
  inferred from naming. This is a documented, deliberate "2 lenses, 1 dataset" split
  (cross-tenant-wide vs single-tour) already called out in `auditPanels.tsx`'s own header comment
  — not an accidental UI duplicate. Review Log (T3/T5) and Trust Ramp are genuinely exclusive to
  Cross-Tenant Oversight (`review_queue`, `acp_deliver.packets` — no Tenant Activity counterpart).
  `/admin/tenants` was also read in full (908 lines) — confirmed zero table overlap with any of
  Cross-Tenant Oversight's 4 sections (grepped for `publish`/`review`/`gate_ledger`/
  `content_piece`/`escalat` — the only hits were `isPublished` referring to the unrelated T1/T2
  tour-rewrite catalog, and `needs_review` for a different status enum on that same catalog).
