# AA-984 — T9 blog holds: F9 heading claims, heading-safe truth cut, F4 over-length trim

Lane `aa984-held-blogs`, session S248. Diagnosis: the S248 held-blogs lane (3 S247 round-9 holds +
census since 2026-10-01: 34 blog holds on F9_cta_fact, 2 on F4_extreme_length).

## Decisions

- **Heading items come from plan() only for F9 quotes.** When `locate_sentence` fails on an F9 quote,
  `locate_heading` matches it to exactly one body heading (never the FAQ heading): same word sequence, a
  contiguous run of ≥ 3 words inside the heading, or the heading inside the quote. The item carries
  `"heading": True`, spans the heading text AFTER its `## ` marker (so every splice keeps the marker), and
  its problem adds a heading instruction (short, no end mark, no claim beyond the SOURCE). Other gates
  keep the old behaviour (an unlocated non-F9 quote still returns None → full rewrite).
- **A heading is never deleted.** In `splice`, a heading item's replacement is cleaned (`clean_heading`:
  no `#`, no end mark, one line, ≤ 90 chars). An empty or unusable replacement falls back to the
  item's `fallback` (the section's place name) or keeps the heading as it was (`guard: heading_kept`).
  The repeat guard never turns a heading repair into a cut.
- **Place-name fallback** (`heading_fallback`): the moment (trip_facts.parse_moments of the seed) named
  most often in the heading's section body (ties → first named), its itinerary label as the heading
  (`a local Buddhist monastery` → `A local Buddhist monastery`). None when the section names no moment or
  another heading already reads the same — then the heading stays and the piece is held as before.
- **Blog attempt-3 truth cut** (`delete_flagged`, used by `_cut_blog_truth_items` and the failed-repair
  fallback): a heading item is replaced by its place-name fallback, never cut; other headings are still
  never touched. The truth-cut entry reports `headings_replaced` beside `sentences_cut`.
- **F4 over-length: deterministic trim before the gates, every blog attempt** (`length_trim.trim_to_band`),
  not only "after a rewrite": the trim runs right before `run_quality_gates`, after every LLM step and
  deterministic fix of the attempt, so attempt 1's over-long text never takes a full Sonnet rewrite for
  length alone, and attempt 2's rewrite is trimmed before it can be held for length.
  - Target `BLOG_TRIM_TARGET_CHARS = 12_500` (500 under the 13,000 gate max, so the after-loop steps that
    only shorten never matter and the gate's tag-stripped measure has room).
  - Droppable paragraph: a prose paragraph of a body section that is not the section's first paragraph,
    not in the FAQ, holds no CTA sentence, no list item, and is not a list lead-in (ends with ':').
  - Lowest value first: an untagged paragraph (no citation tag → no cited source fact) before a tagged one,
    then the longest section, then the latest paragraph in that section.
  - Each drop must pass `sentence_repair._integrity` on its seam window (section heading + the paragraphs
    before and after): no new dangling-pronoun opener, duplicate, echo or orphan line. The window, not the
    whole text: `integrity_problems` is quadratic (≈ 3 s per call on a 14k text, 27 s for 9 drops in the
    first test run), and a paragraph drop cannot create a repeat between distant sentences. A paragraph
    followed by an 'It…/This is…' opener, or the only paragraph naming a moment, is never dropped.
  - All-or-nothing: if the text cannot reach ≤ 13,000 (gate max) with safe drops, nothing is dropped and
    the old path runs (full rewrite at attempt 1, hold at attempt 2). Never below the 4,700 minimum.
- **No new LLM call.** The scope allowed "a deterministic trim … or one length-only repair call". The
  trim reaches the band on the observed shape (14,135–14,615 chars, 8 sections, 2–4 paragraphs each); the
  fallback when it cannot is the existing full rewrite, whose feedback now carries the target size.
- **`_repair_feedback`**: an F4 over-max violation now tells the rewrite the target ("cut to under 12,000
  characters …; keep every heading, the CTA and the FAQ").

## Changed

- `sentence_repair.py`: `locate_heading`, `clean_heading`, `heading_fallback`, `HEADING_PROBLEM`; `plan()`
  heading fallback for F9; `_merge_item` never merges into/with a heading item; `splice` heading branch;
  `splice_checked` fills heading fallbacks (with `moments`); `delete_flagged` replaces heading items.
- `service.py`: `_cut_blog_truth_items` relocates a heading item left to repair with `locate_heading` and
  counts `headings_replaced`; the loop runs `length_trim.trim_to_band` before the gates (blog) and logs it
  in the F13_autofix flag; `_repair_feedback` F4 target.
- New `length_trim.py`.
- Not changed: the F9 judge (prompt, `in_body` rule, F9_PROMPT_VERSION) — per scope. The blog writer
  prompt has no length line yet (diagnosis C1) — left out: it changes every blog; the trim makes it
  unnecessary for the holds.

## Tradeoffs

- Trim vs. LLM shortening: the trim can drop a good paragraph; the rule protects each section's first
  paragraph (the moment stays named and introduced), cited paragraphs go last, and the integrity check
  blocks orphaned pronouns (lesson S234 r3: no sentence-level prose trims — this drops whole paragraphs).
- Trimming on every attempt (not only after a rewrite) means a long attempt 1 is trimmed instead of
  rewritten: cheaper ($0.09–0.10 per avoided Sonnet rewrite) and the rewrite was the source of new F9/F17
  claims (S233: full rewrite fixes F9 0/6).
- The place-name heading is plain ("A local Buddhist monastery"), but it is grounded and the piece stops
  being held on an invented heading; the LLM heading repair (attempt 2, or attempt 3 without an earlier
  F9 sentence repair) still gets the first chance when it applies.

## Review round (S248, independent review)

- **Family access caveat kept by the trim.** `trim_to_band` takes `trip_ctx` (the job's
  `TripFactContext`) and skips any drop after which `trip_facts.missing_family_caveat` reports a moment it
  did not report before. Decision: compare against the text before the trim (not "no finding at all"), so a
  caveat that was already missing does not block an unrelated drop; the check reads the whole text, which is
  cheap next to the integrity window. Only the caveat rule is checked, not the whole
  `find_trip_fact_issues`: the caveat is the F17 rule where missing text is the finding; the others flag
  sentences that are there, which a drop removes rather than adds. Not proven for every rule (e.g. the
  thin-moment coda) — a residual risk, caught by the gates after the trim like any other F17 finding.
- **`locate_heading` is stricter.** A partial run must be ≥ 3 words AND cover ≥ 60 % of the heading's words
  (`HEADING_RUN_MIN_SHARE`); the heading-inside-quote branch accepts a quote at most 2 words longer than the
  heading (`HEADING_QUOTE_SLACK_WORDS`: a '##' or a tag). A paraphrased prose quote that repeats a heading, or
  a short fragment such as 'for curious children', is skipped by `plan()` as before AA-984. Tradeoff: a judge
  quote of half a heading ('Ruined Monastery Tells Families', 4 of 8 words) is no longer a heading claim; the
  live 781b5de7 quote was the whole heading.
- **F4 rewrite target is blog-only.** `_repair_feedback(gate_ledger, channel)` adds the 12,000-char target only
  when `channel == "blog"`; other channels (max 6,000) get the plain violation.
