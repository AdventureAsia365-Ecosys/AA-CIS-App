# AA-779 — follow-up after the S245 r7 checkpoint (real questions: filter, use, top-up)

Earlier AA-779 notes: `AA-779-s245.md` (#870, PAA into the FAQ + subject check) and
`AA-779-real-questions.md` (#877, the real-question chain, part A). This file covers the fix after
the r7 8-blog checkpoint (20/10, current main): every piece got 4 "given" real questions
(place_paa 3, segment_match 1), two of them off-meaning junk that passed the filter
('Is moron a British word?', 'What is moron in German?' — Mörön is a town), and the writer used a
real question for 3 of 30 FAQ questions (0/8 blogs with ≥ 2 real). Agent: Claude Code.

## Decisions

- **Off-meaning, word-sense cues (any question)**: added 'a/an/the <1–2 words> word(s)' ('Is moron a
  British word?'), 'word(s) for', 'words', translate/translation, dictionary, vocabulary, 'rhymes with',
  'how do you say', slur, derogatory.
- **Off-meaning, name-specific (the piece's own place names)**: '<name> in <language>' ('What is moron
  in German?'), 'say/spell/write/translate <name>', '<name> come from', 'a total/complete/real … <name>',
  and the **lowercase test**: the name occurs only as a lowercase word after the first one *and* the
  question has no travel-context word (visit, town, airport, weather, far, located, lake, worth, …).
  Google PAA capitalises a place ('Does Mörön have an airport?') but not the common word.
- **Lowercase test reads real names only**: `paa_for_scope`'s `seed_names` come from
  `proper_nouns(keep_initial=True)`, which also holds line openers ('Fly to Mörön' → 'fly'). The
  lowercase test gets only names capitalised mid-sentence (`lowercase_names`), so 'Can you fly to
  Mörön?' stays. The chain merge passes place words (already clean), so the default (= `names`) is used.
- **Real questions first (FAQ)**, deterministic selection + the existing one regeneration:
  - `missing_real_questions(faq, search_questions)`: given real questions no FAQ question asks yet.
  - When a fresh writer text skips any, the blog's ONE FAQ regeneration per writer text
    (`_enforce_faq_contract`, `write_faq` on t9_repair / Haiku, ~$0.005) runs with
    `required_questions=` them: answer each FIRST, keep its words (grammar / place name only), skip one no
    SOURCE fact answers. The required ones are not listed again under SEARCH QUESTIONS.
  - `real_first_pairs`: real-question pairs first (they win a duplicate in `merge_faq_pairs`), writer pairs
    only to fill: up to the 3-pair minimum and never more writer pairs than real ones; 5 max. With no real
    pair the FAQ is untouched. `real_first_faq` applies it on every blog attempt after the FAQ contract (an
    F7_faq_autofix line records it).
  - The regeneration is kept also when it asks more real questions than before and the FAQ does not drop
    under min(before, 3) (before: only "more pairs" or "fewer failing subject checks").
- **Honest source match**: unchanged rule (same folded text, or ≥ 80% shared content words) but filler words
  ('any', 'really', 'actually', 'ever', …) are left out — one r7 blog wrote 'Does Mongolia have volcanoes?'
  for 'Does Mongolia have any volcanoes?' and it was recorded as `writer`.
- **Part B (SERP top-up)** = `services/acp_shared/question_topup.py` + `scripts/aa779_serp_topup.py`:
  - Places = Segment `canonical_place` of blog work (Subjects proposed/picked + blog `angle_gate_request`s,
    merged ids through the alias), × the countries of their atoms on that tour.
  - A place gets ONE SERP when the chain's DB tiers give it < 3 real questions after the filters and no
    top-up row with questions exists. Order: places named by more blog work first, then fewer questions.
  - Query '<place> <country>' (US, en) — the country makes Google read the town ('Mörön Mongolia'), not the
    word. `people_also_ask_click_depth=2` (new optional `_serp_advanced` argument; every other payload is
    unchanged). Parse: every `people_also_ask_element` title at any nesting, ≤ 20.
  - Store: `acp_contract.search_demand`, keyword `topup_keyword(place, country)` (folded words, e.g.
    'moron mongolia'), market US, `search_volume` NULL, `serp_domains` = organic domains. Upsert; an empty
    answer never wipes stored questions; `retrieved_on` is not bumped on conflict.
  - Read back by a new chain tier `SerpTopupSource` (`serp_topup`, after `place_paa`, English-only tier);
    `PlacePaaSource` leaves those keywords to it so the label is honest.
  - Money: dry run by default (SELECTs only). `--run` uses `load_run_budget(pool, 'dfs', 'aa779_serp_topup')`
    with per-run = min(cap, row) and hard stop; a cap > $3 is refused (script and function). Before every
    call `budget.check(0.01)` (deliberately high estimate), after it the real DFS cost is charged (client).
    A fatal DFS error stops the run. Logged in `shared.dfs_call_log` by the client.
  - AA-646: no router / job / tenant path imports it (unit test walks api/, worker/, services/, shared/).
- **Coverage script (4)**: line 1 now drops off-meaning questions again with the scope's place words
  (reported as `off_meaning_not_counted`) and counts `serp_topup` as a DB source; new `--pieces` mode
  measures Done-when line 2 on stored blogs (`piece_question_stats`: a FAQ question counts only with a real
  recorded source, not off-meaning itself, and not matching only an off-meaning given question).

## Tradeoffs

- ~~**Writer pairs trimmed.**~~ Superseded by the review round below: the FAQ is only reordered now.
- **Real-first needs real questions to exist.** Replaying r7 with the new filter: each blog has 2 real given
  questions (volcanoes, Mongolia's average altitude), and the altitude one is likely not answerable from the
  seed — so the code alone gives ~1 real per blog. Done-when line 2 needs the top-up (B) run first.
- **Lowercase test** relies on Google capitalising places; a PAA that writes a place lowercase with no travel
  word is lost. Narrowed in the review round below (single-word places only, no other place / country, no
  common English word, never the autocomplete tier).
- **Top-up rows have no volume**: atom ranking (`search_volume IS NOT NULL`) ignores them, so the top-up never
  moves Segment ranking. The Segment `questions_count` cache is NOT invalidated (that would make the next
  recompute land the new PAA by embedding — a separate, paid step); the chain reads the rows directly.
- **Estimate $0.01/SERP** is above DFS's live advanced price plus PAA clicks, so the planned list is shorter
  than what $3 could really buy; the real cost is charged, and the cap stops the run either way.

## Review round (S245, after the AA-779 r7 code review)

### Decisions

- **Lowercase test narrowed** (review: it dropped 'How long should I spend in Hanoi?' — 'long' of Ha Long Bay —
  and 11 more real questions). It now fires only when ALL hold: the name is a whole single-word place
  (`single_word_places`: the place folds to one token, e.g. 'Mörön'; never a token of 'Ha Long Bay', 'Great
  Wall', 'Lake Khövsgöl'); the question names no other place word and no country of the scope; the token is
  not a common English word (`_COMMON_ENGLISH` stoplist; 'moron' deliberately absent); no travel word (list
  extended: volcano, climb, steps, pack, expensive, cost, spend, festival, people, language, cruise, …); and the
  tier is not `autocomplete`. `is_off_meaning(lowercase_names=)` now defaults to NONE (opt-in); callers pass
  `chain_filter_names(scope)` (chain, top-up count, coverage script) or `seed_place_names(own_seed)`
  (`paa_for_scope`, FAQ regeneration). Common English words are also left out of the name-bound cues.
- **Word cues bound to a name**: the global regex is back to the pre-r7 cues; the r7 cues ('a British word',
  'word for', translation, dictionary, rhymes with, slur, derogatory) fire only next to a place name
  (`_name_word_cue`), like '<name> in <language>'. 'How do you say hello in Mongolian?' etc. stay.
- **FAQ is reordered, never trimmed** (review: trimming cut good Khövsgöl / Mörön answers and could meet
  Done-when line 2 by deleting writer questions). `real_first_pairs` = real pairs first, then writer pairs;
  a pair goes only above `FAQ_MAX_PAIRS` (5). `writer_input` records `faq_pairs_before` (the writer's own FAQ,
  before any FAQ step) and `faq_pairs_after` (final), each `{pairs, real}`; the coverage script sums them
  (`pair_counts`) so a share gain can be told apart from writer pairs removed.
- **Matching pool = in-scope questions only**: ordering, the regeneration's real before/after counts and the
  pair stats use `search_questions` (what `paa_for_scope` kept); the full chain pool stays only in the admin
  `faq_questions` provenance record.
- **Top-up rows in their own market `US-PAA2`** (`real_questions.TOPUP_MARKET`) instead of `US`: Segment
  research reads only its markets (US/UK/AU/DE/FR/NL), so it never takes a top-up row as "measured, no volume"
  and a top-up never overwrites a research row's PAA; a research row with the same '<place> <country>' key is
  `place_paa` as it should be (`PlacePaaSource` now excludes by market, not by keyword). S1 prefetch / atom
  ranking read volume rows only; admin SEO views list the new market. No migration (no CHECK on market).
  `retrieved_on` is refreshed on conflict. `invalidate_questions_cache_for_keyword` is NOT called: question
  landing reads rows with a volume only, so it would reset caches for nothing (the chain reads the rows itself).
- **$3 cap across runs**: deep-PAA calls are logged as endpoint `serp_advanced_paa_deep` (new
  `_serp_advanced(log_endpoint=)`; estimate $0.01 in `DFS_CALL_ESTIMATE_USD`). `run_topup` sums earlier spend
  (`prior_spend`: NULL cost counts at the estimate) and caps this run at min(cap, $3 − prior); nothing left →
  `refused`, no call. Dry run shows `prior_spent_usd` / `left_usd`. A place whose SERP returned no question
  gets an empty-PAA marker row, so `_count_real` marks it bought (`_BOUGHT_SQL`) and a rerun skips it.
- **Hardening**: required questions are re-checked with `is_off_meaning` before the regeneration; the AA-646
  guard also fails on any `fetch_people_also_ask_deep` call or `people_also_ask_click_depth` argument/string
  outside `question_topup.py` / `dataforseo_client.py`; the REAL QUESTIONS prompt says never to write that
  readers search for the question.

### Changed

- `real_questions.py`: `_WORD_SENSE_RE` (old cues), `_name_word_cue`, `_COMMON_ENGLISH`, `_TRAVEL_CONTEXT`,
  `single_word_places`, `is_off_meaning(names, lowercase_names, countries)`, `merge(lowercase_names, countries)`,

- `quality_gates.py`: `seed_place_names`; `paa_for_scope` uses it. `service.py`: pool, reorder, pair stats,
  required re-check. `generate.py`: one prompt sentence. `question_topup.py`, `dataforseo_client.py`,
  `shared/cost_guard.py`, both scripts. Tests: unit (+ review must-keep cases, cap across runs, marker row,
  research-row clash, guard) and the integration SQL test (own market, research row untouched, marker,

### Tradeoffs

- A lowercase-only junk question about a multi-word place name is now kept (rare; the name-bound cues still
  catch 'X a … word', 'X in German', etc.).
- The FAQ keeps writer pairs, so the real share rises only by adding real questions (slower, but honest).
- The cross-run cap relies on `shared.dfs_call_log` rows (fire-and-forget logging); a lost log row would
  under-count by one call. The per-run budget still bounds each run.
