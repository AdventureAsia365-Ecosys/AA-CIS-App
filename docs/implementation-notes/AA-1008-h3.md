# AA-1008 H3 — Visual and Kit consumers ready to be required checks (CIS)

Lane `aa1008-h3-visual-merge-group` (S270). Companion PRs: AA-Partner and AA-Booking (`visual.yml`, same pattern).
The branch-protection step itself is the tech lead's (ADR 0011); this PR only makes the checks safe to require.

## Decisions

- **Step-level skip, not a scope job.** `visual.yml` job `pr` gets a `Scope` step right after the checkout. It diffs
  the PR (`origin/<base_ref>...HEAD`) or the queue group (`merge_group.base_sha...HEAD`) and matches the old
  pull_request `paths:` list. No match: `run=false`, "no frontend change" in the step summary, every later step is
  skipped by `if: steps.scope.outputs.run == 'true'` and the job is green. A separate scope job with a job-level
  `if`/`needs` would report "skipped", which GitHub counts as passed even when the scope job failed.
- **The required names stay as they are**: `Visual (next start, public pages + kit gallery)` and `Kit consumers`
  (the TL script and verify-h3.sh pin them). A test pins them too.
- **Scope fails open toward running**: no base (empty `base_ref` / `merge_group.base_sha`) or a failing `git diff`
  runs the full check with a warning, never a silent skip. `--no-renames` so a file moved out of `frontend/` still
  counts by its old name (like GitHub's path filter).
- **merge_group**: `Changed pages` diffs `$MERGE_BASE_SHA...HEAD` (`github.base_ref` is empty there); the PR
  comment stays pull_request-only; the `deployed` job says `github.event_name != 'merge_group'` explicitly.
- **Concurrency**: visual.yml already fell back to `github.run_id` for every non-PR event (checked); kit-consumers.yml
  now uses `github.event.pull_request.number || github.run_id` (an empty number on merge_group made one shared,
  cancelling group).
- **kit-consumers.yml**: no `paths:`, `merge_group` added, `BASE_SHA = merge_group.base_sha || pull_request.base.sha`.
  The "Check out this PR" step keeps the default ref, which is the queue commit on merge_group. The aggregator also
  fails when the plan says "unchanged" but the legs did not skip (defensive; cannot happen today).

## Changed

- `.github/workflows/visual.yml`, `.github/workflows/kit-consumers.yml` (header comments: now required checks).
- `tests/unit/test_aa1008_h3_required_checks.py` (new): triggers, names, step guards, concurrency; the Scope step run

## Tradeoffs

- Every PR now starts the visual job (checkout with full history + one diff, ~30 s) even with no frontend change;
  that is the price of a check that always reports.
- A frontend PR's queue group runs the full visual again (~3–6 min); accepted, it is what makes the check
  meaningful on the combined commit.
