# AA-1096 l23 — Settings explained (operator guides, plain labels, decimal comma, readable approver)

Tech lead feedback (S279): "the thresholds on the Settings page are hard to understand; each needs an explanation or
definition so I know when to change it". Two defects seen the same day: the change dialog refused `3,364` ("Enter a
number"), and the Last change column showed the approver's UUID.

Two CIS PRs, in order, and one Booking PR:

1. **CIS migration-only** (CIS 416, contract; was 415, then 417 while it carried another lane's 416):
   `shared.setting_definition.guide` (jsonb) with `setting_definition_guide_chk` (`shared.setting_guide_complete`),
   the guide and a plain label of all 196 keys on main (CIS 407 + 411: 28; CIS 412 quality registry: 151; CIS 414
   TripPlanner: 17), the generator reading the `settings-guide` block, `compiled_defaults.json` regenerated, the guide
   lint (`tests/unit/test_aa1096_settings_guides.py` + its empty shrink-only baseline), the 416 integration test, the
   CONTEXT.md rule and these notes. Second resume: main merged in (CIS 412-415 applied on Dev); the claim checker
   test limits (five keys of the instrument evaluation lane) left this branch and follow as CIS 417 in their own
   lane, which carries their guides on its seed rows (the text was written in this lane's first fix pass and
   handed to that lane).
2. **CIS code**: the API returns `guide` and the readable actor names; Platform › Settings shows the short "what" (two
   lines at most, the full text in the tooltip; hidden while the guide is open) under each label, an Explain toggle per row (what / if you raise it / if you lower it / when to change it / example,
   plus the collapsed Engineering note) and the same guide at the top of the change dialog; the number input accepts a
   decimal comma; the Last change and History columns show the staff member's name or e-mail with the id in a tooltip;
   the Booking tab says each Booking value is explained on Booking's own page.
3. **Booking code**: `app/pricing/policy_guides.py` (EN + VI guide of all 39 pricing policy parameters, bk-050 and
   bk-056), served by `GET /booking/pricing/policy` (`guide`), shown on Pricing › Policy the same way, with a unit
   guard; decimal comma accepted there too.

## Decisions

- **Guide shape.** `{"en": {what, raise, lower, when, example}, "vi": {...}}`, one shape for CIS, CRM, TripPlanner and
  Booking. `raise` / `lower` keep their names for every value type; the page names them by type: number "If you
  raise it / lower it", on/off "If you turn it on / off", choice / list / table "Stricter choice / Looser choice"
  (the text itself says which choice, and agrees with the heading). `example` is the **default** in plain terms,
  worded "With the default of ..." (the page labels it "Example (at the default)"), because the value in force can
  change and the guide is migration data; the guard checks the English example names the default and that no example
  says "Today". Where the value in force changes the meaning (blog source words, the repeat cleanup, the blog length
  aim) the page computes an "In force now" line from the values in force (code PR).
- **Where the guide lives (CIS).** A column on `shared.setting_definition`, written only by migrations (the 407 guard
  trigger covers it), like the rest of the definition. The API keeps serving definitions from the compiled defaults
  (no DB read for the page's metadata); the generator merges the `settings-guide` block into them. A seed row may carry
  `guide` directly once 416 is applied (the generator accepts it; a re-seed without it keeps the earlier guide).
- **NULL allowed in the table, completeness in CI.** A NOT NULL / complete-only CHECK would fail this file's own ALTER on Dev
  if another lane's keys (CIS 412-414) are applied first without guides. The CHECK refuses only an incomplete guide;
  `test_aa1096_settings_guides.py` fails on a compiled key without a complete guide (both languages, five parts of
  10-800 characters, Vietnamese not a copy of English, no issue id, no stage code like T7 / A1 / F13 in operator text,
  the example names the default). Its baseline (keys allowed without a guide) is empty and shrink-only.
- **Labels.** Rewritten without stage codes (`T7 Blog characters per seed word` → `Blog length per source word`); the
  key stays on the page in small monospace, so an engineer still finds the code.
- **Booking keeps its definitions in code.** Booking's parameter definitions are `app/pricing/policy_params.PARAMS`
  (code, not a table: bk-050 / bk-056 hold only the versions), so the guides are code too
  (`app/pricing/policy_guides.py`) — no bk- migration (the lane brief allowed "or equivalent columns"). The CIS
  Booking tab stays a link to Booking's own maker-checker page; it does not read Booking's definitions.
- **Readable approver.** `proposed_by` / `decided_by` stay `admin:<uuid>` in the table (407: never an e-mail); the API
  adds `proposed_by_name` / `decided_by_name` from `shared.admin_users` (display name, else e-mail, else username) in
  the same read; the page shows the name with the actor id in the tooltip.
- **Decimal comma.** On a decimal key (numeric, USD, percent) the form accepts `3,364` and `3.364` as 3.364 (one
  comma or one point as the decimal mark). On a whole-number key (int, seconds) a comma or point is refused with
  "Enter a whole number, without separators": `2,000` on the rerun wave size must never become 2. No thousands
  separator anywhere.

- **Fix pass (review of the first pass).** Rebased on main with CIS 412-413 (151 new keys with coded labels and no
  guide): rather than baseline them, every key got a plain label and a guide (option (a) of the review; the tech
  lead's ask covers the whole page). The 81 quality-check modes share one template filled per (error type, check):
  the code (l17 `registry.classes()`) reads the mode only to derive which checks own an error type for the quality
  reports, evaluations and the lint, so the guide says the mode does not change what happens to a piece. The tour
  rewrite attempts guide says the current writer (S1 contract mode, the Dev setup) ignores the number; the agency
  voice check guide says a second allowance is only used when a job retry resumes. The label / stage-code and the
  example rules skip baseline keys, so the baseline is a real escape hatch. The post-check now reads the keys from the
  block (a temp table, no hand list) and refuses a definition left without a guide; no DROP TABLE (the runner lint
  wants the destructive header for one).
- **Guide content source.** Written from the seed descriptions and the readers (taxonomy.yaml class definitions,
  `f9_policy.py`, `blog_seed.py`, `length_contract.py`, the 414 descriptions, the TripPlanner call sites); no number is invented: every
  example uses the seeded default.

## Changed

- Labels of all 196 keys (operator wording; the key stays shown small). No value, bound, approval rule or
  enforcement flag changes.
- `compiled_defaults.json` rows gain `guide` (null before a guide exists).

## Tradeoffs

- Guide text in migrations is reviewed like code and versioned with the key, but a wording fix needs a migration. A
  separate editable "help" store was rejected: the guide must change with the definition it explains, and the page
  should not let an operator rewrite what a bound means.
- The first pass left the CIS 412 keys to their lane; that lane merged without guides, so the fix pass writes them
  here (one PR owns every guide of the wave). A template for the 81 check modes keeps them consistent; the cost is a
  524 KB migration file (delivered to the runner through S3, the copy bot posts it as a JSON body since the CIS 412
  copy fix).
