# AA-1046 R4b part 1: CIS readers of the Booking B2C tables (S271)

Root plan: AA-Ecosys `docs/audits/2026-11-05-S270-aa1037-b2c-drop-dryrun/README.md` section 4. Booking bk-045
(destructive) drops `booking.customers`, the customer OTP / session / identity tables, `media_files`, the customer
invoice / payment tables and the views `v_invoice_balance`, `v_payment_schedule_status`, `v_customer_summary`,
`v_ops_inquiry_inbox`; `v_ops_data_totals` loses its `customers` metric. This PR removes what CIS still names.

## Decisions

- **Data coverage**: row `bk.customers` removed (its metric disappears from `booking.v_ops_data_totals`). No other
  row reads a dropped metric.
- **KPIs moved, not deleted** (`services/reports/registry/kpis.yaml`, byte copy of root `docs/reports/kpis.yaml`):
  K-AR-AGING, K-AR-OVERDUE, K-AR-UNVERIFIED, K-BK-CASH, K-BK-INVOICED, K-BK-UNVERIFIED now read agency billing
  (`booking.agency_invoice`, `agency_payment`, `v_tenant_billing_status`), version 2. K-MKT-CUSTSRC has no source
  left (no traveller customers): `sources: []`, definition says it is retired. K-PRIV-CONSENT names the three
  sources of root `docs/legal/consent-capture-query.md` after the drop: `tripplanner.customers`, its hand-off rows in
  `booking.inbox_events` and `crm.consent` (review fix: the query page and the Infra script no longer read
  `booking.customers`). No code computes these KPIs yet (definitions only), so nothing else changes. The root lint
  `tools/docs/report_registry.py check` checks KPI sources against the schema reference: this must merge before the
  `bot/db-schema-reference` PR that follows the drop.
- **catalog.yaml** synced byte for byte with root (it lagged two root edits: #492, #503) plus the MKT-01 section 3
  text that named `booking.customers.source`.
- **Erasure checklist** (`services/erasure/inventory.py`): the Booking line lists what remains after the drop
  (inbox payloads, b2c trip cases kept as history, notifications, the archive `booking.retired_b2c_record`).
- `tests/unit/test_aa1003_r4_reports.py` no longer expects `booking.v_ops_inquiry_inbox` in the schema reference
  (it would fail once the dump drops the view).

## Changed

- Nothing in the X1 probes (`244_x1_cis_app_runtime.sql`, `245_x1_cis_owner.sql`): both already skip with a NOTICE
  when `booking.customers` is absent. Integration tests `test_aa860_migration_24{4,5}.py` and
  `test_x1_cis_app_privileges.py` also guard on the table's existence.
- `tests/integration/rls_catalogue_rules.py` keeps the allowlist key `booking.v_ops_inquiry_inbox:cis_app`: it is
  byte-copied in AA-CIS-Infra (`db/rls_catalogue_rules.py`, Copy Guard) and a stale entry is reported, not fatal.
  Remove it in both repos after the drop.

## Tradeoffs

- Moving the six money KPIs to agency billing keeps the reports (BK-01, BK-03, FI-07) meaningful in the B2B-only
  model instead of leaving holes; their wording is definition-level, the report engine does not compute them today.

## Should know

- Merge before Booking bk-045 is applied. Tests: data coverage, reports and registry unit tests (318 passed locally);
  root lint `report_registry.py check --copy <this repo>/services/reports/registry` ok.
