# AA-739 — Review Queue: block reason as the headline + server-side paging/filters (Review Queue, Master Content)

## Decisions

- **Option A of the issue (presentation only).** The gate (`_is_publishable`) is unchanged. The API
  now returns `block = {kind, label}` per row (`_review_block`): `needs_human` (fact check / claim
  not in the source — e.g. elephant riding, which chị Thư decided on 08/10 stays for a person),
  `hard` (a hard-block code survived, with the field), `low_quality` (score < 7), `other`. The UI
  shows it as the first chip in Reasons. When the block is hard or needs_human, the score renders
  small and grey, so a "8.0" no longer reads as "why is this held?".
- **Scope added on 08/10 (S218, Nghiep):** list pages paginated/filtered client-side over one
  20-row server page. Review Queue showed 20 of 54, "Page 1/1", 100/page did nothing, and the
  country list only had the countries on screen. Master Content had a fixed 20/page, country options
  from the page, and "Status"/"Version" filtering only the current page.
- **DataTable kit:** new optional `serverPagination` prop (pageIndex, pageSize, total, onChange).
  When it is set, the pager and the page-size select drive the server. Client mode is unchanged for
  every other page.
- **Review Queue API:** `country`, `score` (critical / low / ok), `tour_id` filters in SQL; the
  total uses the same filters; `facets.countries` (with counts) ignores the country/score filters
  so the dropdown always lists every country in that status. page_size is clamped to 200.
  `quality_scores` is joined as the latest evaluation (LATERAL); a plain LEFT JOIN repeated a row
  for each evaluation.
- **Brand words in field markers:** `_derive_field_failures` on the Review Queue now gets the
  brand's forbidden words (AA-738 had done it on the run path only).
- **Master Content:** page size 20/50/100/200; country options from `facets.countries`; "Version"
  moved server-side (`version=v1|v2+|v3+` on the latest content version); the "Status" select was
  removed (on the internal catalog every row is "published", so it filtered nothing).

## Tradeoffs

- The DataTable search box and column sort still act on the current page in server mode. A full
  server search is out of scope; country/score/tour filters cover the reviewer's real cases.

## Should know

- No migration. Frontend + 2 endpoints (`/admin/review-queue`, `/tenants/{id}/details`).
