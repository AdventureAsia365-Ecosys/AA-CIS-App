## Decisions
- Split into two PRs as the issue asks ("each nac is its own PR"): nac 5 first (small, low risk),
  then the nac 3 stage registry.
- Nac 3 "fold the a3_atomize inline recompute into the recompute gate" is already done by PR #598
  (AA-743): A3 now runs only atomize + segment matching and enqueues one debounced `recompute`
  job. What remains of nac 3 is the declared stage registry.
- Nac 5 flip of `JOB_WORKER_IN_API` default to false needs no Infra change: the api task-def
  already sets it to `false` explicitly (`AA-CIS-Infra/modules/ecs/main.tf:280`).
- Legacy `shared.pipeline_jobs` writers retired; the read path (`get_job` fallback for old job
  ids, admin history) stays, since 523 historical rows remain and the table is read-only history
  (db-schema steering: "chỉ còn dữ liệu lịch sử, KHÔNG ghi mới").

## Changed
- Nac 5 (PR 1): `in_api_enabled()` now opt-in (`1/true/yes`), default False. Startup
  `sweep_interrupted()` removed; every `jobs_repo` writer deleted (`create_job`, `mark_*`,
  `update_stage`, `sweep_interrupted`); `get_job` / `find_active_duplicate` (reads) kept. Dead
  `elif job_id` stage branch in `_execute_run_tour` and the `_background_tasks` set + shutdown drain
  removed. Unit suite 2474 -> 2471 (4 writer-only tests removed, 1 parametrize case added).
- Nac 3 (PR 2): new `services/recompute/stages.py` — 4 declared stages (segment, landing, score,
  route+hub), each with reads / writes / per-table write strategy (matched to the real SQL), plus
  `run_stages()` and `TOUR_STAGES` / `PLATFORM_STAGES`. `recompute_segment_score_route` and
  `recompute_rankings_and_routes` are thin wrappers over `run_stages` (same names, signatures,
  docstrings, result keys, progress events and logs as before); the A3 path runs its segment
  matching through `run_stages(["segment"])`. `recompute_job.py` unchanged (calls the wrappers).
  Unit suite 2471 -> 2488 on top of nac 5.

## Tradeoffs
- Nac 3: `recompute_job` keeps calling the handler wrappers instead of `run_stages` directly, so the
  stage-result -> legacy result-key mapping lives in one place (the Jobs page + scripts read those keys).
- Nac 3: write strategy declared per table, not per stage — segment mixes upsert (`atom_segment`)
  with repoint delete+insert (`atom_segment_member`); route+hub mixes versioned_swap (`route`) with
  upsert (`hub`).
- Startup `sweep_interrupted()` removed: checked live 09/10 — `shared.pipeline_jobs` has 0 rows
  in `running`/`queued` (506 succeeded, 16 interrupted, 1 failed; last row created 05/10, before
  AA-723 shipped). Nothing left for it to sweep, and nothing writes new rows.
