# AA-994 — one design system: S1a, the canonical UI kit core in CIS (S253)

Slice S1a of the AA-994 plan (root `docs/audits/2026-10-27-S252-aa994-design-system/plan.md`, root ADR 0016
"one design system, guarded kit copies"). Creates `frontend/app/_kit/core/`, the canonical copy that AA-Partner
(portal, CRM web), AA-Booking and AA-TripPlanner-Web will vendor through the root `tools/kit/kit-sync.sh`. No token
value, no style and no page changes: pixel and behaviour stay as they were (token values are S1b).

## Decisions
- **What moved into `core/` (ADR 0016 decision 1):** `tokens.ts`, `brand.ts` (was `app/_brand/tokens.ts`),
  `primitives.tsx`, `DataTable.tsx`, `csv.ts`, `savedViews.ts`, `Drawer.tsx`, `Modal.tsx`, `Toast.tsx`,
  `Providers.tsx`, `useHydrated.ts`, `useMediaQuery.ts`, `sidebarStore.ts`, `useSidebar.ts`, `PageFrame.tsx` (was
  `AdminMain.tsx`), `GuidePanel.tsx`, `theme.ts`, `useTheme.ts`, plus new `guide.ts`, `check-kit-copy.mjs`,
  `MANIFEST.json`. Moved with `git mv` so history follows. Not in S1a: `tokens.css` (S1b), `eslint-kit.mjs` (S1c),
  `KitGallery.tsx` (S1d).
- **Stays CIS-local** (ADR list): `api.ts`, `guideContent.ts`, `SessionKeepAlive.tsx`, `adminNav.tsx`,
  `useNavSections.ts`, `useAdminIdentity.ts`, `useReviewPendingCount.ts`, the shell (`AdminShell`, `Sidebar`,
  `Topbar`, `BottomNav`, `CommandPalette`), and new thin bindings `theme.ts` / `useTheme.ts`.
- **Header line**: line 1 of every code file is `// UI kit core (root ADR 0016). Canonical: …` exactly as ADR
  decision 3 words it, before any `"use client"` (comments may precede a directive). `MANIFEST.json` carries it as
  `_header`. The self-check enforces both.
- **GuidePanel content as a prop**: GuidePanel already took `content`; what made it non-portable was its import of
  `guideContent.ts`, which the ADR keeps CIS-local. The renderer's contract (types, captions, `guideAnchor`,
  `guideOutline`) moved to `core/guide.ts` (no imports); `guideContent.ts` keeps the CIS guide checks
  (`guideProblems`, `guideUiLabels`, `guideControlLabels`) and re-exports the shape, so the writing-memory guide, the
  barrel and `lib/guides.test.mjs` import exactly what they did.
- **`.ts` import in guideContent.ts**: `node --test --experimental-strip-types` loads `guideContent.ts` directly and
  Node ESM needs the extension, so it imports `./core/guide.ts`; `tsconfig.json` gains `allowImportingTsExtensions`
  (allowed with `noEmit`). Core files themselves keep extensionless imports, so no consumer tsconfig needs the flag.
- **Theme store**: `core/theme.ts` exports `createThemeStore({ storageKey })` (returns readChoice / resolveTheme /
  applyResolvedTheme / subscribe / getSnapshot / getServerSnapshot / setChoice / restoreScript) and
  `themeRestoreScript(key)`; `core/useTheme.ts` exports `createThemeHooks(store)` → `useThemeChoice`,
  `useResolvedTheme`, `useChartColors`. CIS binds them once in `app/_kit/theme.ts` (`cis_theme`) and
  `app/_kit/useTheme.ts`, so the 5 importers of `_kit/useTheme` and the Topbar import of `./theme` are unchanged.
  `core/theme.ts` dropped `"use client"` (no React in it) so the server root layout can read `restoreScript`.
  The key is validated (`[A-Za-z0-9_:.-]{1,64}`) and JSON-quoted because it is written into an inline script.
- **Root layout** renders `themeStore.restoreScript` instead of its hand-written copy; the script body is the same
  text except the key literal (`"cis_theme"` instead of `'cis_theme'`). A unit test runs it against a fake browser.
- **PageFrame**: `PageFrame`, `PageFrameHeader`, `PageFrameBody`; `AdminMain`, `AdminPaneHeader`, `AdminPaneBody` are
  `const` aliases in core (Booking can use either name after the sync). CSS classes (`aa-admin-main`, …) unchanged.
  Booking's `width` prop is S4a, not here.
- **Visual-job hooks added now** (plan section 4.2 says S1a): `data-kit-frame="page|split"` on PageFrame and
  `data-kit-scroll` on the ScrollX and DataTable scrollers. Attributes only; nothing styles them.
- **Manifest format** (read by `kit-sync.sh`): `{ _header, adr, canonical, generator, profiles: { tokens: [...] },
  files: { "<path>": "<sha256>" } }`, files sorted, `MANIFEST.json` not hashed. `profiles.tokens` is ADR 0016's
  tokens list filtered to the files that exist (today `tokens.ts`, `brand.ts`, `theme.ts`, `check-kit-copy.mjs`,
  `MANIFEST.json`; `tokens.css` and `eslint-kit.mjs` join when S1b/S1c add them).
- **`check-kit-copy.mjs`**, dependency-free, one file: `--self` (CIS) = manifest current + header lines + import
  closure of core + closure of the tokens profile among itself; default (consumer) = every profile file present with
  the manifest's sha256, no extra file, and `kit.lock.json`'s `manifest_sha256` equals the copied manifest (so a copy
  edited and re-manifested locally still fails). Profile comes from `--profile`, else the nearest `kit.lock.json`
  (up to 4 folders up: `portal/app/_kit/core` → `portal/kit.lock.json`, `frontend/ui/core` →
  `frontend/kit.lock.json`), else `full`. Provenance (lock ref on CIS main) is the separate S2a/S3 job.
- **Import closure rule**: `./` paths resolving to a core file; packages `react`, `react-dom`, `next/*`,
  `lucide-react`, `@tanstack/react-table`, `@tanstack/react-query`; `node:*` only in `.mjs` scripts. Imports are read
  with a small comment/string-aware scanner (no TypeScript dependency, so consumers can run it before `npm ci`).
- **Generator** `frontend/scripts/kit-manifest.mjs` (`npm run kit:manifest`) imports `manifestText` from
  `check-kit-copy.mjs`, so generator and checker cannot disagree. `.gitignore` ignores every `scripts/` folder;
  `!/frontend/scripts/` un-ignores this one (like `!/.github/scripts/`).
- **CI**: Frontend Build (required) gains "Kit core self-check" before `npm ci`: the self-check and
  `lib/kitCore.test.mjs`. The other `lib/*.test.mjs` are still not in CI (unchanged; not this slice).
- **Direct core imports outside pages**: `app/layout.tsx` (server layout: importing the barrel would evaluate
  CIS-local modules on the server), `app/login/LoginForm.tsx` (it already avoided the barrel; brand constants only),
  `app/admin/_components/adminUi.tsx` (barrel → `Sidebar` → `adminUi` would be an import cycle), and the CIS-local
  kit files (`Sidebar`, `Topbar`, …). Pages keep importing the barrel.

## Changed
- `app/_brand/tokens.ts` is gone (moved to `core/brand.ts`); its 4 importers point at `core/brand`. The barrel also
  re-exports the brand constants (`BRAND`, `FONT_*`, `LOGO_SRC`, `SUPPORT_EMAIL`, `SITE_URL`) for new pages.
- Barrel `app/_kit/index.ts` re-exports core first, then CIS-local parts; it adds `PageFrame*` names. Its 89
  importers (`grep -rlE "from '…_kit'"` over `app/` and `lib/`: 89 before, 89 after) and their imports are unchanged;
  the brief's "~93" counted a little wider (tests, comments).
- Comment-only path updates: `globals.css`, `eslint.config.mjs` message, `lib/adminFrame.test.mjs`,
  `tests/e2e/smoke/smoke-helpers.ts`; `tests/unit/test_aa858_overview_sources.py` reads `core/primitives.tsx`,
  `tests/unit/test_aa760_muted_contrast.py` reads `core/brand.ts` (missed in the first pass, caught in review: the
  required "Unit Tests" job runs `pytest tests/unit/` with no path filter; a scan of every frontend path string in
  `tests/**/*.py` now finds none missing).
- `package.json`: `kit:manifest`, `kit:check` scripts. `frontend/README.md` is the create-next-app boilerplate and
  does not document the kit, so it was left alone; CONTEXT.md carries the rules.

## Tradeoffs
- Byte-identical headers cost a 144-char first line in every core file (over the usual 120): the ADR fixes the text
  so copies and grep results name the canonical place.
- A shim at each old path (`_kit/tokens.ts` → `./core/tokens`) would have kept the 5 deep imports outside `_kit/`
  untouched, but would leave two files per module and still break AA-Partner's live-compare check; repointing them
  (and the CIS-local kit files) was smaller.
- The regex/scanner closure check can be fooled by exotic syntax (a quote inside a regex literal before an import);
  core keeps imports at the top, and the unit test pins detection on representative syntax. A TypeScript-AST check
  would need `typescript` installed in every consumer before the check runs.
- `sidebarStore.ts` still hard-codes `cis_sidebar`; moved as is (ADR lists it as core, keys are per origin). A
  `createSidebarStore({ storageKey })` like the theme store can follow when a consumer needs another key.

- `kit-sync.sh <consumer> --from-local --cis <this worktree> --dry-run` was run for `tripplanner` (5 files, tokens

- `api/services/staff_invite.py` has a comment naming `frontend/app/_brand/tokens.ts`; left as is so this PR touches

## Decisions
- **Stricter value per token** = higher contrast on every surface it is used on. Only four light tokens differ between
  CIS and the stricter copies (diffed per token against AA-Partner `portal/` + `web/` `globals.css`, AA-Booking
  `frontend/ui/tokens.css` and AA-TripPlanner-Web `frontend/ui/tokens.css` on their `origin/main`). For
  `accent-deep` TripPlanner's `#875D12` beats AA-760's `#8A5F12` (it also clears accent-soft, 4.58 vs 4.43).
- **AA-995 scales promoted as they are.** TripPlanner's `tokens.css` says its new non-colour `--aa-*` scales are
  "proposed for AA-994 slice 1" and should be deleted there once `ui/core/tokens.css` exists. Since ADR 0016 forbids
  `--aa-*` definitions outside core, keeping them out would force S5a to rename them; promoting them is inert for CIS
  (no CIS file reads them: grep over `app/` and `lib/`). The `--tp-*` B2C surfaces (sand / navy band, scrims
  `--tp-scrim-*`, script face, ribbon, layout) stay in TripPlanner.
- **`--aa-font-display` keeps Fahkwang** (brand.ts `FONT_DISPLAY`, loaded by CIS / Partner / Booking). TripPlanner
  AA-995 pointed display at the sans because "the live brand does not use Fahkwang" and asked AA-994 to decide; this
  slice does not change CIS headings, so the open question goes to S5a (see Should know).
- **Fonts as `var(--font-*, "<family>")`.** CIS loads fonts with a Google Fonts `<link>` and never sets
  `--font-poppins`, so the fallback family is used; next/font apps (TripPlanner) get their hashed family. `body` in
  `globals.css` keeps its literal Poppins stack (no change needed).
- **`globals.css` imports the file** right after `@import "tailwindcss"` (CSS `@import` must come first; Tailwind 4's
  PostCSS plugin inlines it). The tokens stay unlayered, as before, so their cascade is unchanged. `color-scheme`
  rules, the legacy `--brand-*` / `--bg-*` / `--text-*` variables and every layout rule stay CIS-local.
- **CSS guard (plan G10) lives in `check-kit-copy.mjs --css <app-root>`**, so every consumer gets it with the core
  (tokens profile included): walks `**/*.css` (skips `node_modules`, `.next`, build and report folders), strips
  comments, flags `--aa-name:`; `var(--aa-name)` never matches. The core's own `tokens.css` (next to the script) is
  the one allowed file. Exit 2 on a missing folder.
- **Contrast test (plan G15)** is `frontend/lib/tokensContrast.test.mjs` + helpers `lib/contrast.mjs`, a JS port of
  TripPlanner `lib/contrast.ts` / `contrast.test.ts` (node --test, no dependency, runs before `npm ci`). Pairs: the
  TripPlanner planner pairs, the CIS AA-760 / S248 muted pairs, every kit Badge tone (`primitives.tsx TONE`), admin
  status / link colours, the dark sidebar / toast, white over `--aa-scrim` (on a white pixel), white on
  `--aa-hero-bg`; all in light and dark. Also: both theme blocks define the same names, muted2 stays quieter than
  muted, the font tokens keep the `var(--font-*, "<family>")` form. TripPlanner-only `--tp-*` pairs stay with
  TripPlanner until S5a decides where they are tested.
- The Python `tests/unit/test_aa760_muted_contrast.py` (required "Unit Tests" job) now reads `core/tokens.css`;
  kept, since it also pins `brand.ts` muted values to the light tokens.

# S1c — kit lint rules in the core: `core/eslint-kit.mjs`, errors with a shrinking baseline (S254)

Slice S1c of the plan (row S1c; ADR 0016 decision 7, guards G1–G9, G11, G19): the conformance rules ship with the
core, CIS lints page code with the `inline` preset at `error`, existing violations are frozen in
`frontend/eslint-suppressions.json`, and Frontend Lint becomes a real gate (Nghiệp adds it to required checks: H2).

## Decisions
- **One file, no plugin package**: `core/eslint-kit.mjs` exports `plugin` (rules under the `aa-kit/` prefix),
  `PRESETS`, `kitRules(preset)` and `kitConfig({ preset, files, ignores, rules })` (one flat-config object). It imports
  only `node:path` (allowed in core `.mjs` scripts), so the import-closure self-check passes and TripPlanner can take
  it in the tokens profile (it already was in `TOKENS_PROFILE`; `kit-sync.sh tripplanner --dry-run` lists it).
- **Rules** (ADR numbering): 1 `no-raw-main`, 2 `no-raw-table`, 3 `no-raw-dialog` (`<dialog>`, `role="dialog"` /
  `"alertdialog"` as a literal), 4 `no-hex-colour`, 5 `no-hand-styled-button` (`<button>` with `style`, `className` or
  `class`), 6 `no-raw-aa-var` (a string or template with `var(--aa-`), 7 `no-aa-var-definition` (JS side: an object
  key `"--aa-x"`, `setProperty("--aa-x", …)`, or CSS text `--aa-x:` in a string; CSS files stay with
  `check-kit-copy.mjs --css`), 9 `no-legacy-kit`. Plus `no-class-name` in the `inline` preset only: today's AA-732
  className rule kept (plan G7). Rule 8 (`no-raw-form-control`) is S6a, when the form controls exist.
- **`no-hex-colour` precision** (it must not flag `href="#add"` or "Order #1234"): flagged are rgb()/rgba()/hsl()/
  hsla() with a literal first value; a string that is only a hex colour (except in `href`, `to`, `id`, `htmlFor`,
  `key`, `name`, `src`, `target`, `rel`, `type`, `placeholder`, `title`, `alt`, `label`, `aria-*`, `data-*`; and,
  outside a style attribute or colour-ish key, except a 3–4 digit all-number value such as `"#123"` / `"#1024"`,
  which reads as an issue or order number — `"#000"`, `"#3333"`, 6/8-digit and lettered values stay colours);
  a Tailwind arbitrary value `[#…]` / `[rgb(…)]`
  in `className`; a hex inside longer text only when the text is a style attribute value, the value of a colour-ish
  object key (`color`, `background`, `border`, `boxShadow`, `fill`, …) or contains CSS words (`solid`, `px`,
  `linear-gradient`, …). All 28 hits on CIS were real colours (checked by hand); no false positive.
- **`no-legacy-kit`** matches by resolved path, not by name: `@/` resolves against ESLint's cwd (the app root, same
  alias in all five apps), `./` / `../` against the file; a resolved path that *ends with* the legacy module path also
  matches, so an editor started at the repo root still sees it. Default modules: `app/admin/_components/adminUi`
  (CIS) and `app/portal/_components/ui` (portal); option `modules` overrides. The whole module is legacy (it is
  deleted at the end of S6b), so every import counts, not only the replaced names.
- **Scope in CIS**: `app/**/*.{ts,tsx,js,jsx,mjs}` minus `app/_kit/**` (the kit and the CIS shell own the raw
  elements). Not `lib/` (helpers, the contrast test's colours). Wider than before (was `app/admin/**/*.tsx`): the
  login page and the public `/trip/[tourId]` page are page code too (the trip page is the only raw `<main>` left).
- **Baseline** made with `eslint --suppress-all` (ESLint 9.39.4): 486 suppressed errors in 68 files, by rule:
  `no-raw-aa-var` 158, `no-hand-styled-button` 137, `no-legacy-kit` 53, `no-raw-table` 48, `no-hex-colour` 28,
  `react-hooks/set-state-in-effect` 25, `no-class-name` 16, `react/no-unescaped-entities` 10,
  `react-hooks/static-components` 6, `@typescript-eslint/no-explicit-any` 3, `react-hooks/purity` 1, `no-raw-main` 1.
  The old "74 legacy errors" (Next/React rules) are in it too, so the job is green at once and can be required.
  Warnings are not suppressed by ESLint and do not fail the job (no `--max-warnings`), as before.
- **"Only shrinks" (G11)** = `check-kit-copy.mjs --suppressions <base> <head>`: fails when an existing entry
  (file + rule) grows, when a rule's total grows, or when an entry names a file that no longer exists (ESLint's own
  prune only sees files it linted, so a deleted file's entry would stay forever). A *new* entry (file + rule the base
  did not list) is only a move: per rule, the new entries may carry at most what the files that are gone carried
  (rename / split of a file with suppressed violations), and with `--base-files` (CI: `git ls-tree` of the base
  commit) a new entry must be in a file the base did not have. So fixing one old violation never buys a new one in
  another file, and deleting a file never buys one in an old file (review fix, see below). In the growth check
  because the script is dependency-free and already vendored in every profile (like `--css` in S1b).
- **No inline disables of kit rules** (review fix): `check-kit-copy.mjs --no-kit-disable app --ignore _kit` fails on

## Tradeoffs
- Suppressing the Next/React rule errors too (not only the kit rules) makes the job requirable now; the cost is that
  those 45 legacy errors are hidden from the summary. They stay listed in the file, which only shrinks.
- The rename allowance is limited to entries that come from a file that is gone. The cost: extracting part of a page
  (with its suppressed violations) into a new component while the page stays blocks, because no file is gone; the
  extracted code must be fixed then (it is migration work anyway). A rename that also adds one new violation of the
  same rule into the renamed file (`a.tsx` 3 → `a2.tsx` 3, one of them new, one old fixed) still passes: counts
  cannot tell those apart, and the reviewer sees the moved file whole.
- A PR that adds a new kit rule (S6a `no-raw-form-control`) grows that rule's total from 0, so the growth check fails
  it by design: that slice either fixes every hit first, or adds the rule's baseline in a PR whose base already has
  the rule off (needs an explicit, documented override at that time).
- `no-hex-colour` heuristics (attribute names, colour-ish keys, CSS words) can miss a colour in free text that is
  later used as a style (e.g. `const shade = "#0003 inset"` without a CSS word). The goal is no false positives;
  the visual job and review catch the rest.
- `--prune-suppressions` in CI rewrites the file in the runner; the job never commits it back (no bot write), the
  author does.
