# AA-727 — Rerun wave as an object

## Decisions
- **Derive, don't instrument.** A wave row (`shared.rerun_wave`, mig 217) stores only the expected
  tour set and its window (`created_at` → `closed_at`/now). Tour states come from rows the pipeline
  already writes: `shared.job` (kinds `s1_rewrite`/`a3_atomize`/`revalidate`, matched on
  `payload->>'tour_id'` inside the window), `published_tours` (active + published inside the window),
  latest `review_queue` row inside the window, `raw_tours.source_status`. No job carries a wave id,
  so nothing in the pipeline changed and a wave can be opened before any run is started.
- **Terminal states** (issue §2): `master`, `review_pending`, `trashed`, `failed`
  (`failed`/`stopped_budget`), `interrupted` (`cancelled`). Non-terminal: `running`, `unclassified`
  (S1 succeeded but neither Master nor a pending review), `not_started`.
- **Jev coverage** = tours with at least one `decision_log` row *without error* written by one of
  the tour's wave jobs (`decision_log.job_id`) — not call counts, since Jev fails open.
- **Cost** = `llm_call_log` by `job_id` of the wave's jobs (includes Jev rows, provider `typesafe`)
  + `dfs_call_log` by `tour_id` inside the window.
- **Failure class** of review rows reuses the Review Queue classifier (`_review_failure_class`,
  AA-728) with the facts available (score, summary, raw itinerary length; no gate codes).
- **Alert** (§4): `POST /admin/waves/check` → a wave whose jobs all finished with a non-terminal tour
  becomes `incomplete` and inserts ONE `shared.notifications` bell (`platform.rerun_wave.incomplete`)
  + logs `rerun_wave_incomplete`. All tours terminal → `complete` (no job needed — batch-path tours
  resolve from Master/review). Called daily by the ops-probe Lambda (AA-CIS-Infra).

## Changed vs. the issue
- No dedicated UI page yet — the report is an admin API (`GET /admin/waves/{id}/report`); the
  runbook (`skill/aa-wave-rerun`) points to it. A page can come later if useful.
- `s1_batch_ingest` (Bedrock Batch, one job for many tours) has no per-tour job; those tours still
  resolve from Master/review, but `s1_ok` and Jev coverage do not see them.
