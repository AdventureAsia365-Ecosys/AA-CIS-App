# AA-876 — API edge hardening (CIS App part)

Scope here: login throttle on `/auth/admin-login` + `/auth/tenant-login`, no CORS on deployed tasks, the BFF 429
mapping (admin + portal), and security headers on the admin app. The API Gateway stage throttle is in
AA-CIS-Infra, the Booking docs gate in AA-Booking, TripPlanner headers in AA-TripPlanner-Web. The WAF is deferred
(S241: on when customer sign-up opens).

## Decisions

- **Count failures per IP, not attempts.** Every BFF login reaches the API from a shared Vercel egress IP, so an
  "all attempts" bucket of 20 would be filled by staff + parallel CI smoke logins. Failures per IP: 20 per 15 min
  (TTL set on the first failure, not refreshed). A separate all-attempt ceiling of 100 per 5 min only protects
  bcrypt CPU.
- **Backoff keyed on (username, IP)**, not the username alone: real usernames appear in public repo comments, so a
  username-only key would let anyone keep a staff account in backoff from anywhere. A second, much higher
  cross-IP limit (50 failures in 15 min → 5 min wait) stops distributed guessing; it is the one remote lever on a
  real account and expires by itself. No hard lockout anywhere.
- **Tenant login: per-IP only.** API keys have far too much entropy to guess, and a per-key wait would let anyone
  lock a tenant out.
- **Client IP = rightmost globally routable X-Forwarded-For entry** (`ipaddress.is_global`, so RFC 1918, CGNAT
  100.64/10, loopback and garbage are skipped; IPv6 bucketed by /64). API Gateway appends the real source; a caller
  can only prepend. Non-IP peers (TestClient's `testclient`) are used as an opaque key, never raised.
- **One Redis pipeline per phase** (`check`: one round trip; `record_failure`: one, plus one more only when a wait
  must be set). `SET key 0 EX ttl NX` + `INCR` gives "TTL on first increment" in one round trip on every Redis
  version (EXPIRE NX needs 7.0).
- **Fail open** on any Redis problem; the first error marks `request.state` so the later `record_*` calls skip
  Redis (a dead Redis costs at most one bounded call, ~1 s with the client's 0.5 s timeout + 1 retry, inside the
  admin BFF's 5 s timeout).
- **Limits are module constants**, not env vars (no deployed-config change; tune by PR).
- **CORS:** `cors_allow_origins()` returns `[]` when `AWS_EXECUTION_ENV` is set (same signal as
  `_is_publicly_deployed()`), and the middleware is not installed at all then. No browser calls the API
  cross-origin (every caller is a BFF / server component / Lambda; TripPlanner's `<img>` covers need no CORS).
- **bcrypt moved to the threadpool** (`run_in_threadpool`): a login burst no longer blocks the event loop for every
  other request on the task. Same function, same result.

## Changed

- New `api/core/login_throttle.py`; `api/main.py` login routes take `request: Request` first and call
  `check` / `record_failure` / `record_success`.
- `api/main.py` CORS block replaced (localhost only off ECS; the two `lumiguides` origins removed — the API never
  needed to grant its own host or the admin host).
- `frontend/app/api/auth/login/route.ts`, `portal/app/api/auth/tenant-login/route.ts`: a 429 from the API is passed
  on as a 429 with `detail` "Too many sign-in attempts. Try again in a few minutes." and `Retry-After` when sent.
  The login pages already show `detail`, so no page change.

- Tests: `tests/unit/test_aa876_login_throttle.py`, `test_aa876_cors.py`, `test_aa876_frontend_edge.py`;
  `test_aa559_tenant_activity_audit_log.py` passes a request to the direct `tenant_login` calls; smoke

## Tradeoffs

- Shared Vercel egress IP: an attacker failing through a public BFF can fill that IP's failure bucket for up to
  15 min, delaying legacy logins for everyone behind it. Accepted for now (legacy login is on its way out; Cognito
  is unaffected). Follow-up: a signed forwarded client IP from the BFF (needs a new secret + env var), or retiring
  legacy login (AA-680 PR-4).
- The cross-IP username wait is a deliberate, rare DoS lever (50 failures in 15 min); TTL 5 min.
- CSP is minimal (framing, base-uri, form-action, object-src). No script-src yet — XSS mitigation via nonces is a
  follow-up.
- `frame-ancestors 'none'` also covers the public `/trip/[tourId]` pages; nothing frames them today (grep: no
  iframe/embed). A partner embed would need an allow-list.

## Should know

- No DB change, no migration, no new env var or secret.
- 429s are visible only as `login_throttled` log lines (scope, reason `ip_fail|ip_rate|user|user_global`, IP).
- Live probes must use throwaway usernames (`aa876-probe-*`), never a real account. A per-IP probe needs a distinct
  username per request (one username trips the (user, IP) backoff after 5).
- The XFF rule depends on the API GW → NLB → ALB edge; revisit if that changes.
- Ship this PR (BFF 429 mapping) before the Infra stage throttle, so API Gateway 429s never meet a BFF that maps
  them to 502.
