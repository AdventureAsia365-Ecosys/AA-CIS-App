# AA-1040 — AI notice variants and machine-readable AI-content marking (CIS)

Lane l6-ai-marking, S266. Root ADR 0019 d19 (EU AI Act Art. 50, deadline 02/12/2026). Builds on AA-1033 (the kit
`AiNotice`, S263/S264). Sibling notes: AA-Partner `docs/implementation-notes/AA-1040.md`, AA-TripPlanner-Web
`docs/implementation-notes/AA-1040.md`.

## Decisions

### Kit (PR 1)

- **Variants stay per audience; the badge is a form, not a variant.** The issue asks for "AiNotice variants per
  audience (traveller chat/narration, staff draft, tenant content label)". `staff` (staff draft) and `publisher`
  (tenant content) already exist; this adds `narration`: a traveller reading text the AI wrote *when they asked for
  it* (TripPlanner trip narration, the only interactive AI surface left after the R0 B2B-only switch-off; there is no
  chat). Art. 50(1) is about telling a person they deal with an AI system, so the sentence says "written by AI when you
  asked for it". The Content studio label is `form="badge"`: a short "AI-assisted" pill whose accessible name and
  tooltip are the variant's full sentence, so the badge never says less than the line. One component, one wording file.
- **Badge text in `aiNotice.messages.ts`** (`AI_BADGE_MESSAGES`, `aiBadgeText`), so TripPlanner (tokens profile only)
  could render it too; same language rule as `aiNoticeText`.
- Badge markup: `<span role="note" aria-label="AI-assisted. <sentence>" title="<sentence>">`, visible text
  `aria-hidden` (the name already carries it), Sparkles icon `aria-hidden`, neutral pill tokens (both themes),
  `whiteSpace: nowrap`, `flexShrink: 0` (sits in a card header without wrapping). `data-ai-notice=<variant>` and
  `data-ai-notice-form="badge"` for tests and smoke.

## Changed

- `core/aiNotice.messages.ts`: `narration` variant (EN + VI), `AI_BADGE_MESSAGES`, `aiBadgeText`.
- `core/AiNotice.tsx`: `form?: "line" | "badge"` (default `line`, unchanged markup).
- `core/KitGallery.tsx`: the narration line and two badges in the `ai-notice` entry.
- `_kit/index.ts`: exports `AiNoticeForm`, `AI_BADGE_MESSAGES`, `aiBadgeText`.
- `lib/kitAiNotice.test.mjs`: narration wording, badge text, badge markup; barrel regex loosened for the new type
  export.

## Tradeoffs

- A separate `AiBadge` component would be one more core file for every consumer to sync and test; a `form` prop keeps
  the "one component" rule of ADR 0016 / AA-1033 and the same variant → sentence mapping.

## Should know

- After merge, the Kit Sync bot opens sync PRs in AA-Partner (portal + web), AA-Booking and AA-TripPlanner-Web. The
  Partner and TripPlanner feature PRs of this lane use `form="badge"` / `narration` and must be rebased after those
  sync PRs merge (lesson S263, AA-1033).
