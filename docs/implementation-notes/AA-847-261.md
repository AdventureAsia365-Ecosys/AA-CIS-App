# AA-847 — migration 261: place locate back on Sonnet; backfill by tour ids; live-route prices

## Decisions
- **Only `a3_place_locate` moves.** This was the second option in the notes for 260. The S247 build of one country
  (Mongolia, both stages on Haiku 4.5) left 84% of its names `llm`. Laos, located on Sonnet, left 49%.
  `a3_place_days` stays on Haiku (S246 plan): the day skeleton is what the trip map draws, and on days Haiku
  matched Sonnet.
- **Model key `sonnet`.** This is the row locate had before 260 (seeded by 226), with the shadow off.
- **Fallback `{haiku}`.** Before 260 the fallback list was empty. Haiku as the outage fallback follows the same
  pattern as 222 and 260: during a Sonnet outage names still get placed, with coarser points. They are not left
  pending.
- **Migration, not the admin PATCH.** Same reason as 260: it is a record that can be replayed, and it needs no
  staff `ai.admin` session.
- **`tour_ids` on `POST /admin/places/backfill`:**
  - Takes at most 100 ids (the country mode stays at 50 tours).
  - Each id is either a live tour id or a source id. The probe's `coverage_missing` lines print source ids, so
    they can be pasted in as they are.
  - Ids are normalised to uuids and de-duplicated, and each source runs once.
  - `country` and `tour_ids` together is a 422.
  - Ids that are not live come back in `skipped.not_live`. Fresh tours (when `only_stale` is set) come back in
    `skipped.fresh`. Neither kind is enqueued.
- **Prices in the estimate:**
  - Tokens per call: design §8 (days ≈ 3.2k in and ≤ 1.2k out; locate ≈ 1k in and ≤ 0.8k out).
  - Rate: the stage's live route (`shared.llm_role_config`) joined to `shared.llm_model_catalog`, read on the same
    connection. The shadow is priced at its own model × its sample %.
  - Fallbacks: SAFE_DEFAULTS, then `pricing.COST_TABLE`. A model with no known price is priced at Sonnet rates,
    so the estimate never comes out low.
  - The response now has `estimate.prices`: the model and $ per call for each stage.

- `shared/llm_client/role_config.py`: `SAFE_DEFAULTS["a3_place_locate"]` changes to sonnet with fallback (haiku).
- `services/places/backfill.py`:

  `skipped` when ids were given.
- `CONTEXT.md`: the place stage line and the backfill line.
- Tests: `tests/unit/test_aa847_backfill_ids_prices.py`.

## Tradeoffs
- **Cost of locate on Sonnet:**
  - About $0.015 per call of 40 names, against about $0.005 on Haiku.
  - That is about $0.005 per tour, against the geocoder confirmations it buys back.
- **The estimate is still an envelope, not the bill.** The real cost is written per call to `llm_call_log`. The
  envelope is now right for whatever model the route names, so a Haiku days route is no longer quoted ~3x high
  ($0.028 → $0.0092 per call).
- **Read on the caller's connection, not through `pricing.calc_cost`.** `calc_cost` reads the catalog through its
  own sync connection. Using the caller's connection avoids a second DB connection inside the request and is
  simple to test.

## Should know
- **Names already placed are not located again:**
  - `place_geocode` only locates keys that have no resolved `geo.place_name` and no located `shared.destinations`
    row. This holds even after a forced rebuild.
  - So Mongolia's `llm` names stay as they are. 261 improves the tours still to be built, which are the coverage
    gate's list.
  - Re-locating `llm` names would be a separate, deliberate step: reset them to pending and pay for the locate
    and geocoder calls again. It is not part of this change.
- **Order (flow D8):**
  1. Merge the migration-file-only CIS PR (`feat/aa-847-cis-261`). It changes nothing live, because the deploy does
     not apply migrations.
  2. Merge the Infra byte copy (`feat/aa-847-cis-261-copy`). Its Copy Guard compares the file against CIS `main`.
  3. Run DB Migrate `check`, then `apply`. The job tables must be idle.
  4. Merge the `bot/db-schema-reference` PR, if one opens. A row update changes no structure, so usually none does.
  5. Merge this PR (`feat/aa-847-locate-sonnet`, stacked on step 1: rebase it onto `main` after the squash). Its
     unit tests read the migration file, not the DB.
  6. Deploy, so that the backfill takes `tour_ids`.
- **No deploy is needed for the model change.** The gateway reads the row on each call (20 s cache). The deploy
  only matters for `tour_ids` and the prices.
- `REQUIRED_CIS_SCHEMA` is unchanged (257): the code reads the row, not a new column.
- **Rollback of 261:** set `a3_place_locate` back to `model_id 'haiku'` with fallback `'{sonnet}'` (the 260 row).
  There is no shadow either way.
