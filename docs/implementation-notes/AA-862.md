# AA-862 — Cohere Embed v4 falls through acc2 -> acc3 (-> acc1)

CIS part of the S239 design (`AA-Ecosys/.tmp-session/s239/aa862_design.md`). Branch
`feat/aa862-embed-satellite-fallback`.

## Decisions
- **One catalog row per account, chained with `fallback_model_ids`** (migration 240):
  `cohere-embed-v4` (acc2, primary, unchanged), `cohere-embed-v4-acc3` (enabled, first fallback),
  `cohere-embed-v4-acc1` (disabled with `blocked_reason`, in no route). A single row with three
  accounts cannot put acc2 first: CIS `CatalogModel.account_for` picks one account per row (acc3 before
  acc1 before acc2), TripPlanner tries `account_route`, acc3, acc1, acc2, and
  `llm_role_config_account_route_check` allows only acc1 / acc3 / NULL.
- **No routing code change in CIS** (only the acc2 retry fix below). `shared/llm_client/embed.py` already moves to the next route
  entry on any exception (throttling included) and calls the satellite client for acc3 / acc1.
  `content_embedding` / `places.llm` already log `account`, `fallback_used` and
  `provider = bedrock-satellite` from the response.
- **New rows copy the base row** (`INSERT ... SELECT` from `cohere-embed-v4`): vendor, api_style,
  callable_via, prices, price_source. Same price, nothing to keep in sync by hand.
- **acc1 is not in any route.** The admin route PATCH rejects a fallback that is not selectable
  (disabled), so a disabled row in a route would make every later edit of the stage fail with a 422.
  Turning acc1 on = enable the catalog row, then append it to each route (two audited admin actions).
- **Probe:** `--account acc3|acc1` on `scripts/aa856_global_profile_probe.py preflight --invoke`.
  One satellite call + one acc2 call of the same text, through `embed._call` (the gateway's own path),
  checks 1536 floats and cosine >= 0.999. Gate `apply_240`. Jobs in flight are reported, not gating:
  240 only adds a fallback.

## Changed
- `api/migrations/240_cohere_embed_satellite_fallback.sql` (new).
- `shared/llm_client/embed.py` `_acc2_client`: `retries={"total_max_attempts": 1}` instead of
  `{"max_attempts": 1}`. botocore reads `max_attempts` as retries, so each acc2 throttle cost 2 calls
  against the 20 rpm quota before falling through (review finding; same fix as TripPlanner).
- `scripts/aa856_global_profile_probe.py`: `--account`; catalog / routes read all three model keys;
  `post-apply` counts ok rows per stage and account (`stages_served_by_acc3`). acc2 behaviour unchanged.
- Tests: `tests/unit/test_aa862_embed_satellite_fallback.py`, `tests/unit/test_aa862_satellite_probe.py`,
  `tests/integration/test_aa862_migration_240.py`.

## Tradeoffs
- Guards refuse a hand-edited route (any route not `cohere-embed-v4` / NULL / `{}` or
  `{cohere-embed-v4-acc3}`), so an admin who already added a fallback must decide by hand.
- `_CATALOG_FALLBACK` / `SAFE_DEFAULTS` (used only when the DB is unreachable) stay acc2-only: with the
  DB down, embeddings have nowhere to be stored anyway.
- The CIS satellite client uses boto3 default retries (acc2 client has one attempt). At 2,000 rpm
  on acc3 a throttle is unlikely; not changed to keep this PR data-only.
- CIS background jobs keep their 3.5 s pacing (`content_embedding._pace_calls`), sized for acc2's
  20 rpm. Routing jobs acc3-first would leave acc2 to customer search, but differs from the agreed chain.

## Should know
- **Order:** the acc3 invoker role (`AA3-Bedrock-Invoker`) needs the Cohere Embed v4 permission
  (AA-CIS-Infra `feat/aa862-cohere-embed-satellite-iam`, applied by hand) BEFORE 240. Without it every
  acc3 attempt is AccessDenied (no harm beyond one wasted attempt per throttled call).
- The probe for acc3 must report `gate.apply_240 = true` before DB Migrate applies 240. An acc2 throttle
  during the probe leaves the cosine unproven: run again a minute later.
- 240 needs an identical copy in `AA-CIS-Infra/db/migrations/cis/`. Never auto-merged.
- Caches pick up 240 without a deploy (CIS routes 20 s, catalog 300 s, TripPlanner 60 s). In the gap a CIS
  process sees the new route entry before the catalog row and skips it as "not in catalog" (harmless).
- Local integration run: 240 + 238 tests pass on local Postgres; `test_aa712_migration_226.py` errors
  locally only because the local `cistest` role is not SUPERUSER (CI's is).
