# AA-1049 — Quality W3, T2 PR train (lane l15, S272)

Scope: the T2 tenant tour rewrite only (S1 is out of scope). Plan: root
`docs/audits/2026-11-06-S271-writing-quality-audit/data/design-review.json` (arch.roadmap[3] item "T2: the linear
orchestrator behind the T2 profile row ...", the eval item "then the S1 and T2 dry stores", workflows[t2].pick), root
ADR 0020, decisions D8 / D9. Reuses the T9 train's patterns (route table, PieceStore seam + DryStore, declared-diff
replay) instead of forking them.

Hard limits kept (S272 lessons): with every flag at its default T2 equals main byte for byte; no gate or judge becomes
more permissive on any path; no paid LLM call and no live replay; every LLM call keeps `**billed_fields(resp)` (the
orchestrator makes no call of its own: it calls main's `generate_node`, `grounding.repair`, `_rerepair_meta` and
`judge_node`, which record their rows); no prompt text change (`scripts/prompt_registry_check.py`: 68 entries, 0
problems; policy_sha unchanged; the linear first writer request has main's exact prompt sha).

## Decisions

- **One switch, opt-in.** `T2_ORCHESTRATOR` (in `config_fp.MODE_FLAGS["t2"]`). Unset, `graph` or ANY other value =
  main's path (LangGraph + T3 + main's save). Only the exact value `linear` (case and spaces ignored) runs the new
  path, and only while the T2 interim profile is on (`T2_INTERIM=off` is the break glass back to the judge-gated v1
  path; the linear path does not reproduce a judge-gated status, so the flag is ignored then).
- **The orchestrator reuses main's steps, so no prompt changes.** write = `graph.generate_node` on
  `v1_pipeline.initial_state_for` (same prompt bytes, gateway call, forbidden strip, meta fit, call-log row);
  normalize = T3's per-candidate fits + em-dash fix; verify = `validate_node` (score), T3 hard codes
  (`_t3_structural_issues`), T3 grounding + Jev clear (Jev only clears hits, as on main), Master day slots; local
  repair = `_t3_sentence_repair` / `_t3_meta_regenerate` (repair contract); field regen = one more `generate_node`
  call with T3's deterministic feedback (`t3_repair_feedback`); voice report = `judge_node` once on the selected draft
  (report-only under the interim profile).
- **Route via the shared route table.** `route_table.yaml` gets a `t2:` section (version `t2-route-table-v1`, one row
  per enforce code: the T3 hard codes, `T3_grounding`, `T2_DAY_COUNT_VS_MASTER`; default `rewrite` = fail closed).
  The T9 rows, their lint and `MECHANICS_VERSION` are untouched. The status rule does not read the table, so no row can
  pass a version. The file is in neither policy_sha nor config_fp (as for T9).
- **Status (L1) is a strict subset of main's rule.** `linear_status` = main's `_t2_status(score, codes)` with every
  enforce code counted as a hard code, plus a held fallback writer -> `needs_review`. A candidate's score is never
  above main's for the same text lineage: min(validate on the writer's raw draft (what main's graph scores), validate
  after the code fixes, the parent draft's score for a local repair).
- **VersionBudget**: writer <= 2, repair <= 3, voice <= 1, usd <= 0.25, checked before every model call. Persisted in
  `generation_meta.t2_orchestrator.checkpoint` on the still-pending version (no migration: existing admin-only jsonb
  column, CIS 297), pessimistically: each billed call is counted and persisted BEFORE it is sent, and its cost is
  persisted right after it returns (before verify, Jev, validate), so a crash or a failed save never lets a retry pay
  a call twice. A checkpoint without a candidate (budget only: e.g. two unusable writes) is loaded too. A job retry
  resumes from the best candidate when one exists: no new writer call. (Review fix, S272: the first version saved the
  checkpoint only once a candidate existed, so two empty writes + a retry could make 4 writer calls.)
- **The meta regenerate counts its real attempts and cost.** `_t3_meta_regenerate` runs flag_fix's `_rerepair_meta`
  loop (up to 3 billed t2_flag_fix calls, `t2_orchestrator.META_ATTEMPTS`) and reports neither count nor cost. The
  linear path runs it only when all 3 fit the repair budget, counts all 3 before it runs, then sets the count to the
  calls really billed and adds their cost, read from an observation-only meter in the call log
  (`call_log.meter_calls`: a ContextVar that `record_call_sync` / `record_unusable_sync` append (stage, cost) to;
  unset everywhere else, the written row is unchanged; `asyncio.to_thread` copies it into the worker thread).
- **The voice judge runs in a thread** (`asyncio.to_thread(judge_node, ...)`), like every other model step, so the
  sync judge call does not block the job worker's event loop.
- **Dry store = no DB write at all.** Under `t2_store.use_store(DryStore())` the checkpoints go to
  `DryStore.checkpoints` (read and write), the review row to `DryStore.reviews`, the row to `DryStore.rows`; only the
  input lookups (SEO, writing memory) still read the pool the caller passes. A dry run can never leave a checkpoint a
  real job would resume from.
- **Final contract on the linear path.** `final_contract.EXITS` T2 lists `t2_orchestrator.py::run_and_save` (it runs
  `check_t2` through the job's `final_contract_record`); `save_version` is the one write, listed in the topology
  test's NOT_EXITS (the T9 `_finalize_piece` pattern). `gated` = the selected draft exactly as `verify()` checked it
  (a deep copy taken in `_check`), so a code edit after verify is the contract's POST_GATE_EDIT finding; `save_version`
  stamps the contract with the sha of the text it writes (`stamp_stored`), so `sha_match` compares the checked text
  with the stored text, not a text with itself.
- **config_fp records `T2_ORCHESTRATOR` only when it changes the path** (`linear` with the interim profile on);
  `graph`, a typo, or `linear` with `T2_INTERIM=off` are omitted like unset, so they trigger no reverify.
- **compose_slots** = the Master's day numbers only (no prompt change allowed, so code cannot write the day skeleton
  into the prompt; it asserts it on every candidate instead).
- **D8 (elephant riding) was already on main** (S271 W0: `policy_hold_hits` + `_save_policy_hold`, 0 LLM calls,
  review row). The policy route runs before either path in `_rewrite_and_save`, so it is the same in both modes. Added
  only the missing tests.
- **T2 dry store** (`services/content_generation/t2_store.py`): `production_input(row)` (the job's builders + the raw
  FactSheet + the policy scan, with shas) and `DryStore` behind a ContextVar, used by the linear store step
  `t2_orchestrator.save_version` (registered in `final_contract.EXITS` T2). Main's save is NOT routed through the seam
  (it would move the parity trace).
- **Replay** (`scripts/quality/replay_aa1049_t2.py`): drives the checkout's production `_rewrite_and_save` over
  stored versions with the stored text as the writer cassette and the stored judge verdict as the judge cassette; any
  other model call is a counted miss. Two runs (main checkout -> base, branch -> diff). Declared ids only with
  `--opt-in` AND `T2_ORCHESTRATOR=linear` in the run. Never declared, and never hidden in the MISS bucket: a looser
  status, a stored score above main's or where main stored none, a QA pass main did not give, a review row with fewer
  findings. A difference on a version that met an outcome-moving cassette miss on EITHER side (any stage but the
  interim's report-only judge) is MISS: counted apart from declared and equal, exit 3 (re-record). The report gives
  base and branch misses and cassette hits. The unit test diffs the branch against a replay RECORDED ON MAIN
  (`tests/unit/fixtures/aa1049_t2_replay_main_base.json`), not against itself.

## Parity proof

The harness drives the real `_rewrite_and_save` (real LangGraph, T3, save SQL) with scripted model answers over 8
scenarios (clean, sentence repair, unrepaired number, writer JSON retry, dropped day, forbidden word + long meta,
missing summary, elephant). The trace = every model request (stage + sha16 of system+user prompt), every SQL
statement with its args, the job diag. With `T2_ORCHESTRATOR` unset / `graph` the trace equals the main golden for
all 8 scenarios; 8 unknown values (`""`, `GRAPH `, `on`, `true`, `1`, `v2`, `linear2`, `lin ear`) equal it on 3
scenarios each; `linear` + `T2_INTERIM=off` equals plain `T2_INTERIM=off`. A mutation (empty value -> linear) fails
the parity test (checked by hand).

## Tradeoffs

- **No compiled writer/repair prompts, no narrative-slot writer, no 3 meta candidates, no LLM claim verifier.** Each is
  a prompt change or a new paid instrument; the S272 rules forbid both here. The orchestrator is the topology; the
  prompt work is W4/W5 with a paid A/B.
- **Brand-audit flag_fix and the itinerary nudge are not run on the linear path (L4).** Neither gates the T2 status on
  main; the deterministic brand pre-audit codes are recorded as a report. Declared, opt-in.
- **The voice judge sees the normalized selected draft**, not the raw draft main's graph judges; its prompt sha differs
  for that reason only (report-only either way).
- **Checkpoint writes on a pending version**: one extra UPDATE of `generation_meta` per candidate (linear only),
  guarded by `status = 'pending'`.

## Should know

- Review fixes (S272, 4 reviews): the replay script is tracked (`git add -f`); budget persisted before each call and
  after it (two empty writes + retry = 2 writer calls total, tested); dry store touches no DB; replay MISS bucket and
  main-recorded base; meta regenerate attempts and cost counted; judge off the event loop; contract gated = verify's
  copy and stored sha stamped at the write; EXITS row `run_and_save`; config_fp normaliser; the never-more-permissive
  test covers the stored score and qa_status. The replay's cassette method is `answer` (not `generate`): the AA-927
  call-site registry treats a `.generate` attribute in a file that imports LLMClient as a model call. Not done (minor,
  not in the fix list): an elephant `FACT_CHECK_MANUAL_CHECK` code from the brand pre-audit is recorded on the linear
  path but does not hold the version (main does the same; the policy route already holds Master / source hits).

- Review fix (S272, round 5): the sentence repair's cost is metered like the meta regenerate's. Before, the cost was
  added only when `_t3_sentence_repair` returned a result, in memory only, as `repaired.cost_usd - draft cost`, and
  reached the checkpoint only at the next loop turn (after verify / Jev / validate). `grounding.repair` bills its
  t2_flag_fix call and can still return no field (or a fully contract-reverted one): the repair returns None and the
  call's cost was dropped (stored usd 0.002 for 3 billed calls), and a crash in verify of the repaired candidate left
  the checkpoint without the repair's cost. Now `_sentence_repair` runs the call inside `call_log.meter_calls()` and,
  in a `finally`, settles the sum of the metered t2_flag_fix costs and persists it before `_check`. Tests: a repair
  that changes nothing (usd = every billed call) and a verify crash on the repaired candidate (checkpoint repair=1,
  usd=0.002). Default path untouched (parity golden and replay defaults vs main unchanged).

- **Main's REPORT-mode final contract misreads T2 days.** `final_contract.check_t2` reads days with
  `day_parse.output_days` (dash form "Day N — Title" only). T2 text is dash-fixed to "Day N: Title" (AA-778), so every
  T2 version, D8 policy holds included, records `T2_DAY_COUNT_VS_MASTER` and verdict `needs_review` (a D8 hold should
  record `policy_hold`). Report only (no status reads it), but the W2 measurement of that code is wrong. Fixing it
  changes stored `judge_breakdown.final_contract` on the default path, so it is NOT done in this lane (parity); the
  xfail test `test_d8_contract_verdict_is_policy_hold` flips when it is fixed. The linear path uses its own slot reader
  (`t2_orchestrator.day_slots`, `source_day_markers`: both forms).
- On main a version whose T3 grounding finding survives is still `ai_generated` (status = score + hard codes only),
  and a dropped day is `ai_generated` too (the harness `day_dropped` / `grounding_unrepaired` scenarios). The linear
  path makes both `needs_review`.
- The golden pins prompt shas and SQL text of the T2 path: a later PR that changes T2 on purpose re-records it on its
  own commit (instructions in the test header), never to make the test pass.
