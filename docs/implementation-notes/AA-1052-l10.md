# AA-1052 (lane l10-w6-lineage, S273) — Quality W6: lineage, dormant-code cleanup, permanent change control

Root ADR 0020 (roadmap W6), the S271 audit `data/design-review.json` `arch.roadmap[6]`. This lane builds the $0
parts that do not wait for the W4 instrument promotion or the W5 paid proofs: (a) lineage of every writer output,
(b) a proven-dead-code cleanup, (c) the CI change-control guard. Live behaviour is unchanged: no prompt, route,
gate or status changes; the only new write is one jsonb key next to a record the store steps already write.

## Decisions

- **No migration.** Every lineage field already had a home except `policy_sha` and the route version at the exit.
  Both now ride in the final contract record (`lineage: {v, policy_sha, route_config_version}`), written by
  `final_contract.stamp_stored`, which is the one store step of every S1 / T2 / T9 exit (the AA-1047 topology test
  pins that). FactSheet ids (`generated_content.fs_id`, `tenant_tour_versions.fs_id`, `writer_input.fs_id`) and the
  writer prompt stamps (`metadata.prompt_version`, `generation_meta.writer_prompt_version`,
  `writer_input.writer_prompt_version`) were already stored.
- **The route version at the exit is the process cache** (`route_settings.cached_version()`, new, no read): the
  gateway's `watch_version` refreshes it at every route resolution, so after the writer's calls it is the version
  they used. The authoritative per-call versions stay on the ledger (`llm_call_log.route_config_version`, the CIS 370
  trigger); the lineage read shows both (`stamped`, `ledger`).
- **Eval lineage is read, not stamped.** An eval result's run already stores `fingerprint.config_fp` with
  `parts.policy` and `route_config_version`, and the row has `judge_version`; r2.py is untouched. An eval item has no
  FactSheet (the golden item is its input): `fs_id` is not an expected field there.
- **Ledger joins**: T2 by `job_id`; T9 by `content_piece_id` (plus the job's own rows without a piece, e.g. the
  angle writer); eval by `quality_signal.run_id` + `item_id` inside the run's time window; S1 by the run's job
  (`metadata.s1_job_id`, AA-993 G2) and, for older versions without it, by `tour_id` + S1 stages in the 3 hours
  before the version (`ledger_join: tour_window`, approximate by design).
- **Change control is a lock file, not a diff check.** A diff-based guard needs the PR base in every unit shard; a
  lock (`services/quality/change_control.lock.json`) is deterministic, works the same locally, in a PR and in the
  merge queue, and its git history is the change log. Components hash files (policy source, taxonomy + thresholds,
  prompt manifest versions, route table, final contract version + mode) plus `SAFE_DEFAULTS` of the gated stages.
- **Evidence kinds** `eval:<uuid>` (a Writing Lab run), `parity:<tests/...py>` (an existing replay / parity test:
  mechanics-only change) and `break-glass:<reason>` (>= 12 chars, reviewed in the PR). The initial lock is recorded
  as a break-glass "initial lock at adoption".
- **Route-migration lint** (ADR 0020 d12, roadmap "'-- eval:' or '-- break-glass:' per tier"): files above 390 only
  (383 already carries a break-glass header; 366 and the other older files are grandfathered). Stage-scoped tables
  (`llm_role_config`, `stage_model_params`) need the header only when a gated stage literal appears; global route
  tables and `writing_memory_release` always. `shared.prompt_version` inserts are the bump itself.
- **Endpoints** in a new router (`api/routers/admin_quality_lineage.py`) under `/admin/quality/lineage/*`, policy
  `ops.read | lab.read` as the funnel (ids and shas only).

## Tradeoffs

- The lock fails every PR that moves a component, including the W3/W4 lanes' own planned prompt bumps: one extra
  `--accept` line per such PR, by design (that is the change control). A wave with several such PRs: each one adds
  its own entry; two PRs moving the same component conflict on the lock file, as they would on the manifest.
- The S1 tour-window join can pick up a second run on the same tour within 3 hours; only versions without the job
  marker use it, and the response says which join it used.
- Lineage of objects written before this deploy shows `policy_sha` (and often `fs_id`) missing; coverage reports
  that honestly instead of backfilling a guess.
- No runtime gate on admin route edits yet: the issue's "UI edits on gated stages require an eval run id or a
  break-glass reason, frozen during waves" changes live admin behaviour, so it is left to a follow-up.
