# AA-112 — S2 AsyncPostgresSaver + Migration + Cache Tables

## Decisions

**Cache tables: SKIPPED**
S2 tools (dataforseo, apify, google_trends, reddit) already cache via `acp_silver_s2.visibility_reports`
(checking `fetched_at` TTL) + S3 keys. Creating `raw_keyword_cache` / `raw_html_cache` would duplicate
this logic. Migration 059 only adds `metadata JSONB` to `acp_stage_runs`.

**Single psycopg3 connection (not pool)**
`AsyncPostgresSaver` holds one psycopg3 `AsyncConnection` for the app lifetime. Sufficient because
S2 runs are semaphore-guarded (max 2 concurrent per tenant) and the checkpointer is only invoked
during graph invocations. `app.state.s2_pg_conn` stores the reference; lifespan closes it on shutdown.

**Return type change: `(graph, conn)` tuple**
`get_compiled_s2_graph` now returns a 2-tuple. main.py updated to unpack it and store
`app.state.s2_pg_conn` for cleanup. The function signature (args) is unchanged.

**DATABASE_URL format**
No format conversion (`postgresql://` → `postgresql+psycopg://`). The `postgresql+psycopg://` scheme
is for SQLAlchemy, not native psycopg3. Native `psycopg.AsyncConnection.connect` accepts
standard `postgresql://` URI directly.

**LangGraph checkpoint tables vs pipeline_checkpoints**
`AsyncPostgresSaver.setup()` creates its own tables (`checkpoints`, `checkpoint_writes`,
`checkpoint_blobs`) in the public schema — separate from `acp_shared.pipeline_checkpoints`
which tracks stage-level metadata. No conflict.

## Changed

- `services/acp/s2/graph.py`: replaced `MemorySaver` with `AsyncPostgresSaver(psycopg3 conn)`;
  return type changed from `compiled_graph` to `(compiled_graph, conn)`
- `api/main.py`: lifespan unpacks tuple, stores `app.state.s2_pg_conn`, closes it on shutdown
- `services/acp/s2/router.py`: added metadata logging in `_background()` (fresh run, iteration=0)
  and `_resume()` (reads iteration from graph checkpoint state via `aget_state`)
- `api/migrations/059_s2_checkpoint_metadata.sql`: adds `metadata JSONB NOT NULL DEFAULT '{}'`
  to `acp_shared.acp_stage_runs`
- `tests/acp_s2/test_checkpointer.py`: 4 unit tests (all mocked, no real DB)

## Tradeoffs

**Single connection vs connection pool**: A `psycopg_pool.AsyncConnectionPool` would be more
robust (auto-reconnect on disconnect). Chosen single connection for simplicity — the checkpointer
is not on the hot path, and if the app restarts the connection is re-established. Upgrade to pool
if we see `InterfaceError: connection already closed` in prod.

**try/except on metadata logging (FIXED in chaos test AA-166)**: original `except Exception: pass`
silently swallowed ALL upsert errors, including the ambiguous column bug (Bug 2). Now re-raises
after `logger.error` so failures surface in ECS logs.

## Should know

- **Migration chain**: 059 depends on 055 (creates `acp_stage_runs`). Migrations 052-058 are
  still unapplied in dev. Apply in order: 052 → 053 → 054 → 055 → 056 → 057 → 058 → 059.
- **`COALESCE(acp_stage_runs.metadata, '{}') || EXCLUDED.metadata`** (FIXED): bare `metadata`
  is ambiguous — PostgreSQL raises "column reference 'metadata' is ambiguous" because EXCLUDED
  also has a metadata column. Must qualify with the target table name. This was the Bug 2 root
  cause, hidden for the entire original AA-112 impl by the silent `except Exception: pass`.
- **`autocommit=True` on psycopg3 connect** (FIXED): psycopg3 defaults to autocommit=False.
  Without it, every `AsyncPostgresSaver` write goes into an uncommitted transaction; connection
  close (SIGKILL, shutdown) discards all checkpoints. This was Bug 1.
- **LangGraph version**: pinned to `1.1.8` + `langgraph-checkpoint-postgres>=2.0.0`. Both
  already in requirements.txt before this PR.
