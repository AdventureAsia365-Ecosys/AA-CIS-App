## Decisions

- **Bronze bucket prefix `docs-reader/`, no new bucket.** Same pattern as the data-model ERD (AA-894): the bronze bucket
  is already `App=cis`, SSE-S3 and Block Public Access, and the CIS task role reads through a named statement. Saves a
  bucket, its policy and its tags. Cost under $0.10/month (mostly PUT requests of each sync).
- **Publication rule v1 is stricter than the S243 wording (N-3).** The handbook said security and audit pages are
  synced but owner-only; the lane brief said never publish security reports. v1 never syncs `docs/security/` or
  `docs/audits/` (or any journal, template, archive, Linear export). The N-3 owner tier still exists, for `SEC-*`
  pages outside `docs/security/` (privacy / legal, secret rotation) and the generated infrastructure maps `ARCH-02`
  network, `ARCH-03` inventory, `ARCH-04` IAM roles.
- **The rule is by path + catalog id, not a new front-matter field.** `frontmatter.schema.json` is vendored
  byte-identical in four repos and has `additionalProperties: false`; a `visibility` field would mean four PRs. `audience`
  stays a navigation filter (its schema says so).
- **Redaction at build time plus a guard.** Every 12-digit run (also inside bucket names and ARNs), VPC resource IDs,
  user-pool IDs, API Gateway host IDs and AWS access keys become `[redacted-…]`; then the bundle is re-scanned with those
  patterns and the docs-lint resource-ID patterns, and any hit fails the build before an upload.
- **Serve-time mask as a second line (CIS).** `docs_reader._read_page` masks any 12-digit run again when it serves a
  page and logs `docs_reader_page_redacted_on_serve`: a hit means the builder guard was bypassed or something other
  than CI wrote the prefix. The test builds its fake IDs at run time (the public-repo resource-ID check refuses
  literals).
- **ADRs are published** (no front-matter; title from the H1, status from the Status line, id `ADR-NNNN`).
- **Admin only (`ops.read`), like the other Developer pages.** Ms. Thư is an admin, so she sees every staff page.
  Owner pages need `auth = cognito` and `is_owner`; for anyone else they are a 404, not a 403 (no existence leak).
- **The API reads by manifest key only.** The caller sends `repo` + `path`; the server finds the entry in its cached
  manifest and reads the `key` written there, after checking it equals `pages/<repo>/<path>` and has no `..`.
- **Rendering in the browser with react-markdown 10.1.0 + remark-gfm 4.0.1** (exact pins), as the S243 proposal (I13)
  named. `skipHtml` drops raw HTML; images are not loaded (alt text shown); links: published page → reader, `#x` →
  in-page heading, https / mailto → new tab with noopener, anything else (http:, javascript:, data:, unpublished
  path) → plain text. Heading ids come from one outline pass keyed by the heading's source line, so the table of
  contents and the ids always agree.
- **`MarkdownView` is a CIS-local kit file (`app/_kit/MarkdownView.tsx`)**, not core and not a page file: the kit lint
  forbids raw `<table>` and `className` in page code, and a Markdown renderer has to emit both. Not exported from the
  barrel, so react-markdown is only in the bundle of the page that imports it.
- **Sync order:** pages (no delete) → manifest → pages with `--delete`, so the manifest never lists a page that is not
  uploaded yet; a removed page disappears after the new manifest is up.

## Changed (vs. the issue / proposal)

- No "audience toggle" that hides by role: audience is a filter, access is the backend tier.
- ~~No Mermaid rendering yet~~ — superseded by the follow-up below (branch `feat/aa-898-reader-lang-mermaid`).

- No live widgets (alarms, drift, overdue docs) on the page yet.

## Tradeoffs

- Browser rendering vs. server-rendered HTML: browser rendering keeps the API returning data (Markdown) and avoids
  `dangerouslySetInnerHTML`; the cost is ~100 small npm packages (unified / micromark) in that page's chunk.
- A sync from a fresh checkout re-uploads every page (new mtimes); with bronze versioning on, noncurrent copies are
  expired after 7 days by a lifecycle rule rather than diffing hashes in the workflow.
- The page cache is keyed by (key, sha256 from the manifest), so a new manifest invalidates a changed page at once; a
  sha mismatch (body newer than the manifest during a sync) is served and logged, not refused.

## Follow-up: languages, Mermaid, callouts, owner proof (S255, branch `feat/aa-898-reader-lang-mermaid`)

### Decisions

- **Translations follow the root builder exactly** (`tools/docs/build_docs_reader.py` rule 8): every entry carries
  `lang`, `translation_of`, `translations` ([{lang, path, key, title}]). `_ENTRY_FIELDS` names them; the reader then
  re-checks each link instead of trusting it: an item survives only when its path and key pass the entry shape
  checks, an entry with that path exists, names this page in `translation_of` with the same `lang`, and the language is
  not English (one per language, at most 8). A copy whose original is owner-only is owner-only too, even when the
  manifest says otherwise or the original does not list it (fail closed). Keys are never sent to the browser
  (`translations` items go out as {lang, path, title}). No path-based guessing (`*.vi.md`): an older manifest
  without the fields reads as English pages without translations, which is what it was.
- **The list shows English pages only** (`lang == "en"`; a translation is reached through its page's EN / VI switch).
  `counts.hidden_owner_only` counts English pages, so a hidden page and its copy count once.
- **EN / VI switch** on the reader, English by default, remembered per browser in `localStorage["aa_docs_lang"]`
  (try/catch; an in-memory value when storage is blocked; read through `useSyncExternalStore`, so no hydration
  mismatch). A link straight to `x.vi.md` is rewritten to the English page with VI chosen. A page without the chosen
  language shows English with a one-line note.
- **Mermaid: `mermaid` 12.2.0 + `dompurify` 3.4.17, exact pins (new dependencies; no other repo pins Mermaid).**
  Published 13/10 and 12/10/2026 (over two weeks old). DOMPurify is already Mermaid's own dependency (`^3.4.12`), so
  pinning the version Mermaid resolves adds no package, only makes it a direct import. Why render at all: 17 published
  pages carry 30 diagrams (the ERDs, the ecosystem architecture), which were unreadable as source. Both are dynamic
  imports inside `app/_kit/MermaidDiagram.tsx`, so the chunks load only on a page with a diagram.
- **Mermaid safety:** `securityLevel: "strict"` (labels encoded, `click` / links off), `htmlLabels: false` (no
  foreignObject), `maxTextSize` 20 000, `suppressErrorRendering`, and `secure` extended so a page's `%%{init}%%` can not
  change the security, label, theme or CSS keys (`lib/mermaidSafety.ts`). The SVG is sanitised again with DOMPurify's
  SVG profile with `foreignObject`, `image` and `use` forbidden, and refused (source shown) if it still refers to
  anything outside itself (CSS `url()` not to `#…`, `@import`, an `href` / `src` attribute): the reader never loads a
  remote resource, as for images. Any error shows the labelled source.
- **Callouts:** a small remark plugin (`lib/markdownCallouts.ts`), not a new dependency: a blockquote starting with
  `[!NOTE]` / `[!TIP]` / `[!IMPORTANT]` / `[!WARNING]` / `[!CAUTION]` (upper case, as GitHub writes them) loses the
  marker and gets `data-callout`; MarkdownView labels and colours it with kit tokens. Content stays Markdown children,
  so `skipHtml` and the link rules still apply.
- **`docs.owner_read` (owner proof on Dev).** Not a role capability and not a POLICY entry (kept out of
  `CAPABILITIES`, so no route can be keyed on it by mistake): the docs routes need `ops.read`, then filter entries with
  `staff_authz.can_read_owner_docs`. Holders: a verified Cognito owner (as before), or — TEMPORARY, A10b — the Dev-only
  E2E CIS admin: verified Cognito session + `e2e_read_only` identity + role `admin` with `ops.read` + `ENVIRONMENT`
  exactly `dev` (re-read per call). `is_owner` stays False (the manifest echoes the real flag and adds `owner_read`),
  so `staff.write` and every owner-only write stay refused (a test walks every `staff.write` POLICY route). Every use
  is logged `docs_owner_read_e2e_dev`.

### Changed (vs. the brief)

- The brief gates the E2E branch on `E2E_DEV_ONLY_STAFF_ENABLED`. That flag is a Lambda env of the WORKFORCE triggers
  only (AA-CIS-Infra `identity.tf`); the API task does not have it. The API-side twin of that switch, used by every
  other A10b check, is `e2e_staff.dev_only_e2e_environment()` (`ENVIRONMENT` exactly `dev`), and the identity is only
  flagged `e2e_read_only` on a token the trigger issued while the flag was `"true"`. So "flag off" means either layer
  off: trigger flag off → no token at all; API `ENVIRONMENT` not `dev` → `resolve_staff` refuses the token, and even a
  principal carrying the flag gets no owner pages (tested for `prod`, `staging`, `Dev`, empty, unset).
- Route summaries of `/admin/docs/*` lose the issue ID (same text as the AA-998 branch, so the two merge cleanly);
  `docs/api/openapi.json` updated by hand for those two strings (the only change to the schema).

### Tradeoffs

- Mermaid is ~1 MB of lazily loaded JS. The alternative (pre-rendered SVG in the root bundle) would need a headless
  browser in the Docs sync workflow; browser rendering keeps the bundle Markdown-only.
- Large ERDs are drawn fit-to-width, so on a phone they are small (no zoom / full-size view yet).
- The "outside reference" check can refuse a harmless diagram whose label literally contains `url(`; it then shows
  the source, which is the safe direction.
