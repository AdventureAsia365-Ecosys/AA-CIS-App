# AA-1127 C4 — Tenant content QA layout (S285)

Source: S283 UI audit (root `docs/audits/2026-11-17-S283-fe-audit/`, CIS rows 9, 10, 11 and the Trace / Quality /
Assignments / Place cards notes in `rows.json`). The C3 batch (read-only hint and copy) is its own PR with its notes in
`AA-1127.md`; this file is separate so the two PRs never touch the same file.

## Decisions

- **The Tenant content QA sub-nav is a row above the content at every width.** It repeats the sidebar's five QA links
  exactly and took a 200 px column (plus a 16 px gap) on all five QA pages. As a row (the phone layout it already had)
  it keeps the in-page way between the QA pages and gives the content the full pane. `SocialContentSplit` takes
  `stack`; the Atoms & routes catalogue sub-nav keeps its column (in-page tab state, not in the sidebar).
- **Content quality pieces table fits at 1440.** Measured in the audit: 1306 px of columns in a 914 px pane. Freed:
  216 px (sub-nav), up to 80 px (title capped at 240 px instead of 320), about 139 px (blocking fails and warnings in
  one column, `GateResults`: danger chips, then warning chips, max 260 px). `tableMinWidth` 1100 → 1040.
- **Filters at 390.** The shared `TenantSelect` inline select was `width: auto` (as wide as the longest tenant name,
  482 px); now `maxWidth: min(100%, 280px)`, the search box 200 px (was cut to "Search by name, slu" on the sibling
  pages) and never wider than its row; the Quality filter rows wrap with `minWidth: 0`.
- **Dates on Quality** use the kit `useFormat().formatDateTime` (UI language) instead of the page-local `fmtTime`
  (browser locale).
- **Content Trace** uses the kit `FilterField` (a `<label>`, so Channel / Status / Published have names) and the kit
  `DateField` (From / To with `aria-label`, `min`/`max` tied together); the filter bar and the stat tiles moved from
  the page header into the content column, under the sub-nav, like the sibling pages. `?tenant=<id>` opens the page
  filtered (the C3 Tenant 360 Social tab links there).
- **One search box**: `searchable={false}` on the kit tables whose page has its own search (Quality pieces and tour
  versions, Place cards: server-paged, where the kit box searched only the 50 rows on screen; Tenant assignments,
  where two boxes filtered the same rows).

## Changed

- The audit asked for the Trace filters "inside the content column"; they now scroll with the body (the header no
  longer holds them). The audit's own counter-argument (fixed header controls) was weighed: consistency with the four
  sibling pages won.

## Tradeoffs

- No local measurement harness for the pieces table (no fixture server for this page); the widths above are from the
  audit's live measurement. The live step after deploy measures it again at 1440 (every column's right edge inside
  the pane) and at 390 (no wrapper wider than its client width).
- The merged gate column has no CSV value, as before (the two gate columns had no accessor either).
- No threshold is touched.

## Should know

- No backend change; no migration.
- The kit DataTable page-size select still has no accessible name (kit core, the Kit accessibility batch).
