# AA-870 — CIS backend error tracking (Sentry)

## Decisions
- Sentry project `aa-cis-api` (org dk-0ql) already existed (created by Nghiệp); only the DSN secret
  `aa-cis/dev/sentry-dsn-api` was missing. Created by CLI on 17/10/2026 (tag ManagedBy=manual-AA-870,
  ~0.40 USD/month). The ECS task role already reads `*` secrets.
- Implementation moved to `shared/sentry_init.py`: `python -m worker` cannot import `api.core.sentry`
  because `api/__init__` builds the FastAPI app. `api/core/sentry.py` re-exports it.
- Worker now calls `init_sentry(service="worker")`; job errors logged at ERROR reach Sentry through the
  default logging integration. Tag `service` = api | worker.
- Release = `APP_GIT_SHA`, baked by `docker build --build-arg GIT_SHA=<sha>` in Deploy Dev (was
  `VERCEL_GIT_COMMIT_SHA`, never set on ECS → "unknown").
- Privacy: `send_default_pii=False`, `max_request_body_size="never"`, `before_send` drops request data and
  cookies, keeps only allowlisted headers (custom secret headers like x-admin-secret never leave), and
  redacts key-like query parameters.

## Changed
- `tests/test_sentry.py` moved to `tests/unit/` (CI only runs tests/unit, so it never ran) + AA-870 tests.

## Uptime
- Sentry free plan allows 1 uptime monitor: CIS `/health`. Booking's external check stays out of Sentry;
  Booking already has CloudWatch alarms (no healthy task, unhealthy hosts, 5XX).
