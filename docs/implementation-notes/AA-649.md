# AA-649 — Cost guard (spend budgets for DFS / LLM / Jev)

Branch `feat/aa-649-cost-guard`.

## Decisions
- **Table `shared.spend_budget` (migration 168).**
  - Key: `(provider, scope)`, where scope is `global` or `job:<kind>`.
  - Columns: `per_run_usd`, `per_day_usd`, `hard_stop`, `alert_pct`.
  - NULL means unlimited on that axis.
- **Seed values** (conservative, editable):
  - DFS global: $10/day;
  - research run: $5 DFS + $2 Bedrock.
- **Effective budget for a run:**
  - per-run = the job row's value (else the global row's);
  - daily = the smaller of the job and global daily caps;
  - day spend = today's UTC sum from `dfs_call_log` / `llm_call_log` at load time, plus what the run charges.
- **The check happens before each paid call, using a worst-case estimate:**

  | Call | Estimate |
  |---|---|
  | DFS `search_volume` (single or bulk) | $0.075 |
  | DFS `keywords_for_keywords` | $0.09 |
  | DFS `serp_advanced` | $0.002 |
  | One Haiku research turn | $0.005 |

  The charge after the call uses the real `cost` from the DFS response or the LLM response.
- **A breach raises `BudgetExceeded`.**
  - The research run guard treats it like a fatal DFS error: the run stops, remaining places are skipped, and no place is marked researched unless its purchases finished.
  - `BudgetExceeded` is raised outside the swallow-on-error `try` blocks in the DFS client, so it is never converted into "no data".
- **Balance precheck.** `/admin/segment-research/run` refuses with 409 when the DFS balance, a free read, is below the run's DFS budget remaining, or when the balance cannot be read.
- **Alerts** go to `shared.notifications` (event `spend_budget_alert`, target role `admin`), at most one unread per provider per 24h. They fire when day spend reaches `alert_pct`, or when a run is stopped by a budget.
- **Missing table.** If the table does not exist yet (deploy before the manual migration apply), the guard uses `SAFE_DEFAULTS`, the same values as the seed. It never fails open.

## Changed vs issue
- The Bedrock / OpenAI budgets are only enforced in the research loop for now. Enforcing them on every LLM call belongs in the Model Gateway (AA-659), which will call the same `RunBudget.check()` / `charge()`.
- Jev has no call log yet (AA-660), so its day spend reads as 0.
- The UI (Settings → Budgets) is AA-665. This PR ships the API only:
  - `GET /admin/budgets`;
  - `PUT /admin/budgets/{provider}/{scope}`.
- A pre-run estimate per phase depends on AA-648's deterministic batch phases. Until then, preview shows the **spend ceiling** (`max_spend_usd`), which the run is guaranteed not to cross.

## Tradeoffs
- Day spend is a snapshot at run start plus the run's own charges. Two concurrent runs could each spend up to the daily cap, but research allows one run at a time, and AA-650 will serialise per provider.
- The estimates are rounded up, so the guard may stop a run slightly before the exact limit. We prefer that to overshooting.
