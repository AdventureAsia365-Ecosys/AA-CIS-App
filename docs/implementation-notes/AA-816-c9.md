# AA-816 — C9 principal-aware admin secret + Preview credential, and D1 (retire the staff script)

Cutover plan (Stage S) checklist E1 (C9) and D1, root ADR 0006 / 0006a A6, A9. Nghiệp's S244 decisions: N-C (C9
right after S1, not waiting for AA-680), N-E (API legacy flag stays on until a Preview sign-in exists).

## Decisions
- **One module decides "who is calling" for the secret guards:** `api/core/staff_credential.py`.
  `principal_verified()` is true when the staff bearer middleware verified a Cognito Bearer (`current_staff`) or
  recognised the Preview credential (`current_credential`). Every admin-secret guard on a staff path checks it
  first and keeps its own main-secret compare unchanged after it: `admin.verify_admin_secret` (and so every router
  that uses it, `staff_policy`, `admin_atoms`, the brand-identity resolver), `admin_settings.verify_admin`,
  `v1_pipeline._require_admin`, `core/staff_secret.require_staff_secret` (`/v1/rules`, `/v1/social`),
  `staff_authz.staff_policy_if_staff`, the staff audit middleware and the rate limiter's admin tracking.
- **`staff_policy_if_staff` had to change too**, not only the guards: it applied POLICY only to requests with the
  valid secret. Without the change a Cognito or Preview request without the secret would pass the router's own
  guard and skip POLICY entirely. `has_staff_credential()` closes it; tests mutate it back and fail.
- **Preview credential lives in the middleware**, not in each guard: the middleware is the one place that already
  rewrites `x-admin-role`. It replaces the header with `viewer` (adds it when absent), so every later reader — POLICY,
  `READ_ONLY_ROLES`, role-filtered reads, the audit row — sees the viewer, and the guards need only the boolean.
- **Name by code constant** `PREVIEW_SECRET_NAME = "aa-cis/dev/admin-secret-preview"` (the name the plan and the
  register propose). No env var. Read only when `AWS_EXECUTION_ENV` is set (the AA-577 "deployed API" signal), so
  local runs and CI never call AWS.
- **Cache:** 5 min for a value, 1 min for missing / unreadable; one log line per state change
  (`staff_preview_credential_state`, never the value). The fetch runs in a worker thread
  (`asyncio.to_thread`) and only for a staff-path request whose `X-Admin-Secret` is present and is not the main
  secret, so normal traffic never reads Secrets Manager. Boto timeouts as in `booking_jwt.py` (2 s / 3 s, 2 tries).
- **Preview equal to the main secret** = misconfiguration: the main meaning wins (never capped), so the Production
  BFF and the machine callers keep working.
- **Cognito Bearer + Preview secret on one request:** the Cognito path wins (it already rewrites the role).
- **BFF:** one helper, `lib/auth-server.ts staffCredentialHeaders(auth, ADMIN_SECRET, backendPath)`: Cognito session
  on a staff API path → `Authorization: Bearer` only; legacy session or a non-staff path → `X-Admin-Secret`; null
  (→ 503) only when the secret is needed and missing. `STAFF_API_PREFIXES` moved there from the tenant proxy; a
  test keeps it equal to `STAFF_PATH_PREFIXES`. All five proxies use it: `/api/admin`, `/api/pipeline`,
  `/api/tenant/[...path]`, `/api/tenant/pipeline/brand-identity`, `/api/tour-full/[id]`.
- **Legacy sessions keep the secret "while the legacy flag is on"** without reading the flag in the proxy: the BFF
  can only verify an HS256 session while the API flag is on (`/auth/verify-admin`), and N-D lets live production
  HS256 sessions expire on their own after S1, which needs the secret until then.
- **D1:** `scripts/create_staff_user.py` deleted with its two unit tests (replaced by one test that the file stays
  gone). CONTEXT.md, an `auth.py` comment and two old implementation notes updated (the notes keep their history
  plus a "retired" line).

## Tradeoffs
- **Viewer cap on Preview** means admin writes and admin-only reads can no longer be checked on a Preview once the
  Preview BFF holds the Preview value (plan Tradeoffs). Accepted: the Preview key was the larger risk (register
  item 1).
- **The open job-runner GETs** (`/admin/job-runner/deploy-gate`, `summary`, `workers`) are MACHINE_ROUTES with no
  POLICY entry, so they are open to every staff role — the Preview viewer included (read-only job counts). The
  MACHINE_ROUTES that carry a POLICY entry (`/admin/overview` and every scheduler POST) refuse the Preview
  credential; a test covers each. Giving those three GETs a POLICY entry would break the reviewer/content Jobs
  views, so not done here.
- **`/api/tour-full` keeps sending the secret for Cognito sessions**: `/v1/tours/{id}/full` is not a staff path
  (it reads a Bearer as a tenant token). No page calls the route today; moving it under `/admin` (or deleting it)
  is the clean fix, left out of this PR.
- **Header trust remains for the legacy (main-secret) path** until S2: whoever holds the main secret can still claim
  any role. The Preview credential, by contrast, is capped whatever it claims.
- **D1:** with the script gone, changing a legacy test row's password (the e2e accounts kept until S2) needs a
  reviewed DB Migrate `run-script`. Accepted: those rows are frozen until S2 anyway.
