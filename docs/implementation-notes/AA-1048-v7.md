### TP side (shape only)

- 21 stored violations, step 1 sent 21 on (all 3-0), step 2 flagged 21 (all 3-0).
- The single-specific violations add a quality, a mood, a light, a group, a suitability or a measure that NO source

## Decisions

- **v7c (step 1): look up facts, not words.** v6c's order stays (set aside, then trip specifics, then the lookup) and
  so does the recall guard. The lookup gets a close-paraphrase list: the same thing under another name (synonym,
  near-synonym, a looser or more general name, singular or plural, a verb for the source's noun), the same number or
  measure written another way (units, digits or words, a range or a rounded figure that holds the source's figure,
  nights and days), the same quality in other words (a walk the source calls meditative is unhurried; optional
  activities let each traveller choose; an evening at the hotel with nothing planned is free), a feature the place
  background gives for a place the trip visits, and landscape the source puts around a stop crossed on the way to it.
  The guard right next to it: a source fact plus a NEW quality, mood, light, measure, group or suitability is not the
  same fact, and a fact stretched to other days, nights or the whole trip is not either.
- **v7c's reply schema adds `checked` before `new_specifics` and `kind`**: one entry per trip specific with the
  closest source wording and `same_fact` (true/false). The model must write the source line down before it decides; a
  specific with `same_fact: true` does not go into `new_specifics`. The schema is part of the v7c tag.
- **v7j (step 2): clear what the source supports.** Framed as a source lookup that can come out either way: step 1
  lists every specific whose words it did not find, so many listed specifics are in the source in other words. For
  each listed specific v7j writes a `checks` row (the specific, the closest source wording, and a `finding`: `same_fact`,
  `one_step`, `not_trip`, `not_given`, `against`) before the verdict. `supported` when every row is `same_fact`,
  `one_step` or `not_trip`; `unsupported` when at least one row is `not_given` or `against`. v5j's promise list stays
  as the definition of what `not_given` means for a quality (mood, light, view, crowd, guide, meal character, pace,
  effort, comfort, safety, suitability). Same user prompt as v5j / v6j. The vote is still the reply's `verdict`
  (`judge_vote` unchanged); the rows are reasons, not a second vote.
- **Shaping runs and pools.** v7 was written from run `c5983e03` on the S281 fresh pool, so `c5983e03` joins
  `shaped_on` and the pool `716df551d458fee1` joins `shaped_on_pools` (with the S279 pool). No claim-level hold-out:
  the v7 run uses the NEW fresh pool (481 never-read claims on 20 pieces), whose manifest excludes runs `2977dd78`,
  `3018008d`, `33835b87`, `9b0d46f8`, `c5983e03` and pools `487bf484...`, `716df551...`. The pool is given at run time
  (`--fresh`); the registration names no digest, and the out-of-sample gate refuses a manifest that does not exclude
  every shaping run and pool.
- **Same bars (60 / 90 / 95 / 95 / 40)**, a new id `aa1048-two-step-v7`, the same candidate, votes, stage and role.
- **v6 is closed in code** (like v5): every live run of it is refused; its DRY RUN and the $0 `score` replay still
  work. v7 is the default step set (`--steps v7`). The ledger stop rule is unchanged: v7 gets exactly one gated run.
- **fresh_pool `--exclude-run` takes a two-step report as it is.** `instrument_eval.prefixes_from` now reads a report
  whose `votes` are nested per step (`{"classify": {...}, "judge": {...}}`) as the union of the step claim keys
  (step 2 votes only on claims step 1 sent on, so the union is the step-1 set). Today the orchestrator had to derive a
  flat file. `run_of` already reads `run_id` from any report.
- **No new settings, no migration.** The bars, caps and claim limits are the CIS 417 / 423 keys.
- **Prompt text checks.** Every example is invented (Vessa, Pellow, Brannock, Mirre, Saint Avel, Cobbe, Corran, plus
  v6's names). A scratch leak check compared every three-word sequence with a content word of both texts with every
  claim of the S281 fresh pool and the S281 claim exports (see Should know for the result).

## Tradeoffs

- **The close-paraphrase list could clear a violation of the same shape.** Seven violations of the last run rest on one
  specific, each a quality or measure attached to a source place or time. The guard sentence and the guard examples
  (a mood added to a plain visit, a light added to a visit time, a fact stretched to more nights) are written for
  that shape; the bars (route TP >= 95 %, judge TP >= 95 %) are the check, and H1 / H4 are falsifiable on the run.
- **Per-specific rows cost output tokens.** Both steps now write one short row per specific (step-1 false positives
  listed 1-4, violations 1-7). At the S282 measured price (0.072 USD for 234 calls) the gated run stays far under the
  cap; the trial's `--measured` prices it.
- **The verdict is still the model's.** Deriving the vote from the `checks` rows in code would make step 2 mechanical,
  but it changes the verdict rule the registration states and puts a new rule in code after the data. The rows make
  the model commit to a finding per specific; the verdict field stays the vote.
- **A whole pool becomes a shaping pool.** Reading the 11 routed false positives and the TP shape of run `c5983e03`
  makes all of `716df551` in-sample; the new pool excludes it at piece level, so nothing of it is measured again.
