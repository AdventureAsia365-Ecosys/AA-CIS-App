# AA-912 — CodeQL backlog (ReDoS + stack-trace exposure)

Branch `fix/aa912-codeql-backlog`. Tests: `tests/unit/test_aa912_codeql.py`.

## Decisions

- **Rule for every regex alert:** time the pattern on adversarial input built from the alert's own
  message, each size in its own subprocess with a 20 s guard. Linear growth (1M chars in tens of ms,
  2x input ≈ 2x time) → dismiss as false positive with the numbers. Superlinear → rewrite, fuzz the
  rewrite against the old pattern, add a runtime-bound test.
- **Tag-body classes exclude `[`** (`[^\]\[]`) instead of using possessive quantifiers: the cost was
  the re-scan from every `[R:` / `[F:` start to the end of the text, not backtracking, so `[^\]]++`
  stays quadratic (measured). Real tag ids (`[R:atom_83c7…]`, `[F:fact_9]`) never contain `[`.
- **text_integrity (#24) keeps its pattern** and applies it only up to the last `]` (`_drop_tags`):
  exact semantics on all inputs, nested tags included (0 diffs on 300k fuzz strings).
- **photos/match (#27):** reversed pattern + `re.match` on the reversed name (one start, one parse),
  no possessive quantifiers so CodeQL's parser can read it.
- **hygiene hashtag tail (#26):** the exponential regex is replaced by a line-by-line backward scan
  (`_hashtag_tail_start`) with possessive per-line patterns; same `start()` on 100k fuzz strings.
- **hygiene word-before-dot (#10):** a backward character scan (`_word_before_dot`), not a regex
  `search(text, 0, i)` that restarted at offset 0 for every period.
- **Stack-trace exposure:** new helper `api/core/error_ref.py` — `log_exception_ref()` logs the
  exception with traceback under a 12-hex ref (`logger.exception`), `public_error()` returns
  `"<what> failed (ref <ref>); details in server logs"`. Same status codes and response keys.

Measurements (old → new, adversarial input from each alert message):

- #26 `'\n#A0'*k + '!'`: k=24 3.4 s (×4 per +2 repeats) → 1M chars 0.01 s.
- #10 every period of 100k one-line prose 2.4 s; `'.'*100k + ',.'` > 20 s → 1M 0.009 s.
- #16 `'\t'*100k + 'x'` 16.8 s → 1M 0.026 s.
- #9 `sentence_tail_end('.[F:'*k)` 1M > 20 s → 1M 0.11 s.
- #17/#20/#8/#24 `'[R:' + '[F:'*k` (no `]`): 100k ≈ 0.8–9 s, 1M > 20 s → 1M 5–16 ms.
- #21 `'x' + '*'*100k + 'x'` 16 s → 1M 20 ms. #22 `'[Fact id='*k` 100k 0.37 s → 1M 19 ms.
- #7 `'[\\](http://' + '[!](http://'*n` 220k 18 s → 1M 62 ms.
- #25 long tag of spaces 1M 19.6 s → 1M 5 ms. #27 `'0'*26 + 'x'` 5.8 s (exponential) → 1M 0.4 ms.

## Tradeoffs

- Excluding `[` from tag bodies changes output only for malformed nested input (`'[R:abc [F:def]'`
  becomes `'[R:abc'` instead of `''`). Fuzz diffs were all of this kind; well-formed tags are identical
  (fixture tag bodies and the 573 tag-related tests unchanged). #24 kept exact semantics instead
  because the cheap wrapper was available there.
- Possessive quantifiers (Python 3.11+) are used in the hashtag and dash patterns; CodeQL may not
  parse them. The runtime-bound tests are the real guard either way.
- Error bodies lose the raw exception text: an admin now needs the ref and the server log
  (`/ecs/aa-cis-dev`, field `error_ref`) to see what failed.

## Should know

- Every rewritten regex has an equivalence test against the OLD pattern (copied verbatim into the
  test) on representative inputs plus a runtime bound (< 1 s at ≥ 100k chars; new code runs in ms).
- Not changed (same `[^\]]+` shape, not flagged, follow-up candidates): `hygiene._TAG` (shared by
  `_SENT_END_RE`, `_SENTENCE_TRAILER_RE`, `strip_tags`), `quality_gates.TAG_RE`,
  `text_integrity._TAG_RE` itself (wrapped), and `sentence_repair._TRAILING_TAGS_RE`
  (`(?:\s?TAG)+\s*$`, still quadratic on `'[R:a]'*k + 'x'`: 100k chars ≈ 11 s).
- `get_infra_status` still hard-codes a default NAT instance id in code and a comment; not an
  account id/ARN, but it could move to the env var only.
- Local unit runs import `api.main`, whose `init_sentry()` reads Secrets Manager with the local
  default profile (MFA prompt). Run tests with `AWS_CONFIG_FILE=/dev/null
  AWS_SHARED_CREDENTIALS_FILE=/dev/null` to match CI.
- Analysis scripts (timings, fuzz) live outside the repo in the root workspace scratch area.
