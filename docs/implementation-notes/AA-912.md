# AA-912 — CodeQL backlog (ReDoS + stack-trace exposure)

Branch `fix/aa912-codeql-backlog`. Tests: `tests/unit/test_aa912_codeql.py`.

## Decisions

- **Rule for every regex alert:** time the pattern on adversarial input built from the alert's own
  message, each size in its own subprocess with a 20 s guard. Linear growth (1M chars in tens of ms,
  2x input ≈ 2x time) → dismiss as false positive with the numbers. Superlinear → rewrite, fuzz the
  rewrite against the old pattern, add a runtime-bound test.
- **Tag-body classes exclude `[`** (`[^\]\[]`) instead of using possessive quantifiers: the cost was
  the re-scan from every `[R:` / `[F:` start to the end of the text, not backtracking, so `[^\]]++`
  stays quadratic (measured). Real tag ids (`[R:atom_83c7…]`, `[F:fact_9]`) never contain `[`.
- **text_integrity (#24) keeps its pattern** and applies it only up to the last `]` (`_drop_tags`):
  exact semantics on all inputs, nested tags included (0 diffs on 300k fuzz strings).
- **photos/match (#27):** reversed pattern + `re.match` on the reversed name (one start, one parse),
  no possessive quantifiers so CodeQL's parser can read it.
- **hygiene hashtag tail (#26):** the exponential regex is replaced by a line-by-line backward scan
  (`_hashtag_tail_start`) with possessive per-line patterns; same `start()` on 100k fuzz strings.
- **hygiene word-before-dot (#10):** a backward character scan (`_word_before_dot`), not a regex
  `search(text, 0, i)` that restarted at offset 0 for every period.
- **One citation-tag definition (review round, commit 2):** `services/acp_shared/citation_tags.py` holds
  `TAG` / `TAG_RE` / `strip_citation_tags()` / `trailing_tags()`. quality_gates, hygiene (`_TAG`,
  `strip_tags`, `_TAG_AT_RE`), sentence_repair, text_integrity, trip_facts and grounding all use it; a
  guard test fails if one of those files defines its own `(?:R|F):` regex again. Tag body: `[^\[\]\n]+`
  (no bracket, no newline — real ids are `atom_83c773a60a`, `fact_9`, `f-12`).
- **Malformed (unclosed) tags — chosen behaviour:** strip the opener and the id right after it
  (`\s?\[(?:R|F):(?:[^\[\]\n]*\]|[\w-]*)`: a whole tag, the empty `[R:]` included, or else `[R:` + `[\w-]*`).
  Why: tenant text must lose no prose AND show no raw `[R:` / `[F:`. Pre-AA-912 deleted everything up to
  the next `]` (real prose); the first AA-912 cut left `[R:abc` visible. Checked first whether something
  already handled it: `text_integrity._unbalanced` flagged a dangling `[R:` only as an F13_hygiene
  **warning** (no removal), and it runs on the tagged text before the final strip — so nothing removed
  it. The cleanup now lives in the shared strip, which is the final tenant-facing step
  (`service.write_and_check` → `strip_citation_tags`). `[Moment id=…` / `[Fact id=…` source labels
  (`sentence_repair._SOURCE_LABEL_RE`) follow the same rule.
- **Readers see the tenant text:** `text_integrity._drop_tags` and `grounding` use the same strip, so a
  dangling opener is not an "unbalanced bracket" (it will be gone) and F1 reads the number after an
  unclosed tag (`"The trek is [R:a1 12 km long"` → `['12']`; old strip hid it) but never an id like `[R:12`.
- **Trailing tag run** (`sentence_repair.splice`, `trip_facts` thin coda): `trailing_tags()` is one backward
  pass (`rfind('[')` + `fullmatch` per tag) instead of `re.search(r"(?:\s?TAG)+\s*$")`, which retried from
  every tag start (O(n²)). `trip_facts` caveat anchor matches the tag run in place (`_TAG_RUN_RE.match(text,
  end)`) instead of on a `text[end:]` copy.
- **Stack-trace exposure:** new helper `api/core/error_ref.py` — `log_exception_ref()` logs the
  exception with traceback under a 12-hex ref (`logger.exception`), `public_error()` returns
  `"<what> failed (ref <ref>); details in server logs"`. Same status codes and response keys.

## Tradeoffs

- Malformed tags: output differs from pre-AA-912 only on malformed input, by design. Fuzz (300k realistic
  token mixes, prose separated from the opener by a space): 0 diffs vs the old strip on well-formed tags,
  0 `[R:`/`[F:` left, 0 prose words lost. Two residual cases, accepted: (1) prose glued to the opener with
  no space (`[R:Paro is…`) loses that one word, since it cannot be told from an id; (2) an unclosed opener
  followed on the same line by a prose `]` (`[R:a1 all day] more`) still loses the span, exactly as before
  — it cannot be told from a multi-id tag `[R:a1, a2]`. A `[` + removed tag + `R:` can also re-form `[R:`
  (`[[F:x]R:`); not realistic writer output, and a fixpoint loop would be quadratic again.
- A newline ends a tag body (was allowed by the old `[^\]]+`): a tag never spans lines, and this stops
  an unclosed `[R:` from deleting the next paragraph up to a stray `]`.
- `_MD_LINK_RE`: a URL holding a non-empty `[...]` (`?a[0]=1`) stays raw markdown on plain-text channels;
  allowing it would bring the O(n²) scan back. `[]` query arrays convert. An unclosed `[` before a link now
  stays as the stray bracket and the link converts (old: the link text swallowed it). Pinned in tests.
- Possessive quantifiers (Python 3.11+) are used in the hashtag and dash patterns; CodeQL may not
  parse them. The runtime-bound tests are the real guard either way.
- Error bodies lose the raw exception text: an admin now needs the ref and the server log
  (`/ecs/aa-cis-dev`, field `error_ref`) to see what failed.
