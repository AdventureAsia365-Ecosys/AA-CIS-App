# AA-1096 lane L2 — the quality registry on the platform settings registry (CIS)

Tech lead S279: quality thresholds are admin-editable WITH a required evidence link (an eval / golden-set run id or a
$0 replay). Lane L1 (CIS 407, `shared/settings`, Platform › Settings) built the mechanism; this lane moves the quality
registry onto it (root audit `docs/audits/2026-11-13-S279-session/thresholds-audit/`, sections 3.1, 5.4, 5.5, lane L2).

Two PRs, MIG-4 order:

1. **Migration-only** (batch cis 409-410, contract): CIS 409 seeds 151 setting definitions (no value rows) from today's
   effective values; CIS 410 registers prompt version `t9_write` v8. `shared/settings/compiled_defaults.json` and
   `services/quality/settings_keys.py` ride with it (byte-identical in both PRs; an identical add merges cleanly).
2. **Code**: the readers switched, YAML reduced to structure, the frontend reads the values at runtime, the prompt
   renders the blog length values at call time, the settings fingerprint joins the prompt version and the release
   fingerprint, the change-control `gates` lock checks the governance of the gate settings.

## Decisions

- **One key per value, named in `services/quality/settings_keys.py`.** Readers never copy a value into a module
  constant: every former import-time constant (`MIN_QUALITY`, `_TIE_BAND`, `WARN_LINE`, `HOLD_CLASSES`,
  `CONTESTED_CUT_THRESHOLD`, `MAX_CUT_FRACTION`, `BLOG_FLOOR_CHARS`, `TARGET_MARGIN`, ...) is now a function reading the
  settings reader's 30 s snapshot at call time (no DB on the request path).
- **thresholds.yaml keeps the structure.** Each consumer key keeps its entry (`used_by`, calibration record) and names
  the `setting` (a band: `settings`) that holds its value; `ref: pass_line` entries are unchanged, so one approved pass
  line reaches A1 retry, the publish floor, Review approve, T2 status, T3, the T7 cut, legacy validation and the golden
  set. `report.score_histogram_edges` left the file: chart bucket edges, not a gate (a `technical-constant`).
- **taxonomy.yaml detectors lose `mode`.** `registry.classes()` lays each detector's mode in force in per call
  (`owner_gates` derived from it); the quality lint requires a seeded mode setting for every detector and no YAML mode.
- **writing_policy.yaml keeps the structure; `effective()` lays the values in.** The compiled file, `policy_sha` and the
  prompt-register hashes use the SEEDED defaults, so they are byte for byte what they were; the run-time accessors
  (`band`, `rules_config`, `f9_hold_classes`, `fill`, `policy_sha_in_force`) read the values in force.
- **Modes that were worker env vars keep the env var as the definition's emergency override for one release**
  (T10_*, T10_SA_MODE*, T10_ADJ_MODE*, T9_BRIEF_GROUNDING_MODE, T7_DEBATE_MODE; none is set in Terraform). The settings
  reader matches an enum env value exactly (spaces stripped): `" CUT "` is ignored where the old code lower-cased it.
- **T2_JUDGE_GATE / T3_BACKGROUND_FACTS are seeded with the worker's Terraform values** (`brand_fit` / on; the code
  defaults were `brand_fit_mission` / off) and have no env override (they were set on the worker only, so the page
  could not have shown them); the env vars are inert now and lane L6 removes them from Terraform.
- **Evidence and maker-checker on every quality key.** The API refuses a proposal without an `evidence_ref` (L1's
  `evidence_required`). Rules a single definition cannot say are `quality_settings.cross_problem`, called by the
  settings API before a proposal is stored (422 `cross_check`): caps and the low review band under the pass line, the
  pass line under the top colour band, band minimum under maximum, the writers' meta aims inside the meta band, Channel
  bar fields (`needs_demand`, `needs_questions`, `needs_said`, `most_per_hub` only for a weekly-rhythm Channel).
- **The SEO bands and meta aims are listed but not editable yet.** They are stated in the A1 / T2 writer prompts,
  `content_generation.seo_meta_utils`, the flag-fix / brand-audit prompts and the T9 SEO fit lines, all built when the
  module is imported, before the settings reader has its first snapshot; a stored value would reach the T9 gates at
  once and those prompts never. `cross_problem` refuses any value but the seed (`START_TIME_REASON`), the definition
  descriptions say so, and the follow-up is to render them at call time on the A1 / T2 path.
- **Blog length values render at call time (t9_write v8).** `prompts._blog_words()` / `_blog_length_instructions()`
  replace the hashed literals `_BLOG_WORDS` / `_BLOG_LENGTH_INSTRUCTIONS` / `_PLAN`; at the seeded values the block is
  byte for byte v7's (sha recorded in the parity test). CIS 410 registers v8.
- **Settings version on the ledger.** `prompt_registry.version_for` appends `.s<8 hex>` (`quality_settings.prompt_fp`,
  the keys a writer prompt renders) for a writer stage while a value differs from its seed (`v8.s1a2b3c4` fits the
  `llm_call_log.prompt_version` CHECK); `config_fp` component `policy` becomes `policy_sha_in_force()+<settings_fp>` in
  the same case. At the seeded values both are exactly as before, so no release fingerprint moves on deploy.
- **Change control.** The `gates` component hashes the gate structure (taxonomy.yaml + thresholds.yaml) plus each gate
  setting's governance and seed (`value_type`, bounds, allowed values, default, approval, evidence_required,
  env_override) from the compiled defaults, so a migration that widens a bound or re-seeds a value needs evidence;
  `check()` also reports any gate setting that is not evidence_required + maker_checker (audit 5.4 check 5). Lock
  accepted with `parity:tests/unit/test_aa926_equivalence.py` (gates) and
  `parity:tests/unit/test_s279_quality_settings_parity.py` (prompt registry).
- **Frontend reads the values at runtime.** `GET /admin/quality/thresholds` (pass line, score bands, SEO bands; POLICY
  any of content.read / tenant_content.read / tenant_content.book.read / tenant.book.read) and
  `useQualityThresholds()`; `quality-registry.generated.ts` no longer exports `PASS_LINE` / `SCORE_BANDS` /
  `SEO_BANDS` / `WRITING_POLICY_SHA`. Until the values load, score colours are neutral, the meta band hint is hidden
  and the Review "Approve" readiness is false (no fallback literal: that would be a mirror).
- **Advanced group.** The low-impact detector sensitivities (hygiene Jaccards, geomatch distances) are not in this
  lane (audit Q10: later phase).

## Changed (vs. the issue text)

- SEO bands: moved onto the registry as asked but refused on change until the A1 / T2 call-time follow-up (above).
- `T7 CHANNEL_BARS` keeps its structure dict (grain, on_demand, takes_route, ...); the numbers come from
  `slate.bar(channel)` / `slate.bars()`.
- The AUTO_UPGRADE_THRESHOLD setting is read through a thresholds.yaml entry (`a1.auto_upgrade`) like every score.

## Tradeoffs

- Call-time reads cost a dict lookup per gate decision; the snapshot is per process (30 s to reach another process).
- Keeping the compiled policy at the seed means the policy_sha only moves with a structural policy edit; the values in
  force are named by the settings fingerprint instead (a second identifier, but no churn at deploy).
- Tests written for main's code defaults of T2_JUDGE_GATE / T3_BACKGROUND_FACTS serve those defaults
  (`tests/unit/settings_serve.py`), so the T2 golden (`aa1049_t2_parity_golden.json`) stays the record of main.

## Should know

- **Order.** Migration PR (cis 409-410) → Infra copy → Migration Apply (contract) → code PR. Without 409 the reader
  serves the same values from the compiled defaults; the page lists the keys only once 409 is applied. Without 410,
  t9_write calls carry `prompt_version` NULL until it is applied.
- **Parity evidence.** `tests/unit/test_aa926_equivalence.py` (the AA-926 gate-outcome snapshot, unchanged fixture) and
  `tests/unit/test_s279_quality_settings_parity.py` (defaults = before, v7 block sha, follow, evidence, bounds).
- `shared/settings/compiled_defaults.json` and `services/quality/change_control.lock.json` are shared with other
  lanes that seed settings or bump prompts: a concurrent change there conflicts textually; regenerate
  (`scripts/settings/gen_compiled_defaults.py`, `--accept`) rather than hand-merge.
- `config_fp.MODE_FLAGS` still lists T2_JUDGE_GATE / T3_BACKGROUND_FACTS as worker env flags (removing them would move
  every fingerprint); they disappear with lane L6.
- Follow-ups: render the SEO bands / meta aims at call time on the A1 / T2 writer path (then drop `START_TIME_REASON`);
  the audit's "Advanced" detector sensitivities; a dry eval from the page (audit Q3).
