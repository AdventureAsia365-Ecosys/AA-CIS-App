# AA-808 — Drafter must not append traveller clauses to background facts

## Decisions
- Two layers: a prompt rule in `_CARD_SYSTEM` (no clause on reaching/views/what visitors do/
  combinations/"making it a stop"; such content is omitted) and a deterministic post-check in
  `_clean_facts` that re-kinds a writer-kind fact (what_it_is/history/setting/naming) matching a
  traveller-clause pattern to `practical` or `visiting`. The fact is kept on the card (admin view),
  only hidden from the writer seed (`atom_seed.WRITER_FACT_KINDS`).
- Practical patterns are checked before visiting ones (getting-there beats seeing), so a fact that
  is both (e.g. "gateway for travellers ... views") lands in practical.
- Pattern table `_TRAVELLER_CLAUSES` (kind, name, regex) + public `traveller_clause(text)`; the log
  event `place_card_fact_rekinded` carries card name, pattern name, from/to kind and the first
  120 chars of the text.
- `_WRITER_KINDS` is a local copy of `atom_seed.WRITER_FACT_KINDS` (atom_seed imports place_cards,
  so importing back would be circular); a unit test pins them equal.
- PROMPT_SHA is a hash of the prompts, so it changes with the prompt text (681e1e20ff92d7f3 ->
  b0bf2195e0f1896e). Effect is the same as AA-774: stored misses are retried; existing cards are not
  re-drafted.

## Changed
- Spec mapping "combined with / inclusion -> visiting" was followed; the audit reviewers had put
  Kyichu Lhakhang #6 and Zorig Chusum #5 in practical. Both still leave the writer kinds (29/31
  match the reviewers' target kind exactly, 31/31 leave writer kinds).
- Existing cards are NOT re-classified by this change (only new drafts pass `_clean_facts`); the
  31 audited leaks are fixed separately by the S235 apply plan.

## Tradeoffs
- Bare "gateway", "visitors", "tourists", "visited", "overland route", "travel between" and
  "making it ... destination" were tried and dropped: they hit 13 untouched background facts
  (airport "gateway to Mongolia", "visited by pilgrims", "trade and travel between Tibet and
  Nepal", ger-camp "accommodation for visitors"). Narrow forms kept instead.
- "with ... views" stays: it catches Gyatso La (agreed leak) and also Zhongba County ("... and
  mountain views", not flagged by reviewers, near-identical wording). "km ... by road" stays per
  spec and hits Darkhan. These are the 2 background hits.

## Measured (audit data embedded in tests/unit/test_aa808_card_traveller_clauses.py)
- agreed_leak: 31/31 re-kinded out of writer kinds.
- agreed_unleak: 0/22 false positives (limit 3).
- Untouched writer-kind background (facts_flat minus apply_plan): 2/437 = 0.46% (limit 3%).

## Should know
- Fixture texts are copied into the test file (no docs/ read at test time); long fixture lines
  carry `# noqa: E501`.
- New regexes are case-insensitive and search the whole fact text; no LLM call involved.
