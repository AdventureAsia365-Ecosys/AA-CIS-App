## Part 2 — country scope (S204)
- **Two Jev Questions** (migration 185, shadow), with wording ported from Ms. Thư's ticket 04:
  - `a3_question_foreign` (loose rule);
  - `a3_question_about_here` (strict rule; generic questions are out, Q3).

  Both are asked in one call about the state `{question, countries}`.
- **Scope = the Segment's own tour countries** (Q4), joined from `raw_tours.country`. The countries are in the state and the subject key, not in the wording, so the wording hash stays fixed. A Segment that gains a country is asked again. A Segment with no known country is not filtered.
- **Where:** `filter_candidates_by_country_scope()` runs in `precompute_question_landings()` after the candidate shortlist and before embedding and landing, so a dropped question is never embedded or counted. One Verdict per distinct (country set, question), 4 at a time; the cache makes repeats free.
- **Drop rule:** `foreign` is a confident yes, or `about_here` is a confident no, and only in enforce mode (ADR 0007). In shadow the Verdicts are logged as calibration data.

## Part 3 — A3-6 demand + A3-1 atom gates enforced; atomize prompt scoped to the day (S205)
### Decisions
- Nghiệp reviewed both calibration Sheets with 0 overturned (70/70, 47/47) → `a3_demand_belongs` reject ≤ 0.40 and `a3_atom_in_text` reject ≤ 0.30 go to enforce (DB row update, no migration).
- Root cause of A3-1 was the prompt, not the model: `build_day_user_prompt()` sent the whole-tour summary/highlights on every day with no marker. Now fenced as `TOUR CONTEXT (background only …)` and the day as `DAY N (extract atoms only from this section)`; SYSTEM_PROMPT gets the same rule, plus "evidence must be quoted from the DAY section".
### Changed
- INCLUSIONS/EXCLUSIONS are no longer sent in the per-day prompt (trip-wide; an atom from them cannot belong to one day). `run_t5_atomize()` never put them on `row`, so this is a no-op today; it closes the path for future callers.
### Tradeoffs
- The preamble is kept (not removed) so the model can still resolve "the village" / "the dzong" to a name the tour uses.
- Changing SYSTEM_PROMPT changes every day fingerprint → the next atomize of every version re-reads all days (paid). Intended: the clean rerun (AA-653) needs it anyway.
### Should know
- The Jev gate stays on after the prompt fix: the fix should cut what the gate has to drop; the gate catches what the prompt still lets through.
- Tests: `test_aa694_atomize_day_scope.py`.
