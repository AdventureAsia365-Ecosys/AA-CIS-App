# AA-1029 R4: tour price chain, CIS part (S267, lane r4-price-chain)

## Decisions

- **One contract view, Booking only**: `catalog.v_tour_price_reference_v1` (CIS 365) gives AA-Booking the free-text
  source price (`raw_tours.price_raw`) of each live published tour, keyed by the catalog key of `catalog.v_tour`.
  Booking keeps it on its trip plan as a reviewed reference (root ADR 0005 d7); it is never a selling price.
- **Catalog recipe** (as 323 / 341 / 347 / 357): view owned by `catalog_owner`, `security_barrier`, SELECT to
  `booking` only; `catalog_owner` already reads `raw_tours` (AA master rows only), so no new base-table grant.
- **Live set = `catalog._live_tour`**, the same set `catalog.v_tour` serves; a blank or missing text gives no row.

## Changed

- `tests/integration/rls_catalogue_rules.py`: two allowlist keys for the Booking side of the chain
  (`booking:tripplanner` schema USAGE and `booking.v_from_prices:tripplanner`, Booking bk-039). The AA-CIS-Infra
  byte copy changes in the same wave (its Migration Copy Guard compares it with CIS main: merge this PR first).

## Tradeoffs

- A view over the raw text rather than a parsed column in CIS: parsing is Booking's (it owns prices), and the text
  stays the audit source.
