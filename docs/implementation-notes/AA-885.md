# AA-885 — Tenant portal as its own Next.js app and Vercel project (S243, PR-B)

Plan: S243 lane AA-885 steps S4a–S4e (`.tmp-session/s243/plans.json`), cross-lane corrections in

## Decisions

- **Same repo, second app root** `portal/` next to `frontend/`, deployed as Vercel project `aa-cis-portal`
  (Root Directory `portal`) on `https://portal.lumiguides.it.com`. Session decisions (Nghiệp, S243): this
  domain, keep the `/portal/*` path prefix, staff lose direct access to the tenant portal.
- **Vendored kit, not a shared package.** The portal needs 14 files from `frontend/` (list in CONTEXT.md and
  `tests/unit/test_aa885_portal_split.py`). They are byte copies; the pytest guard fails when a copy drifts.
  The plan listed 11 (8 kit files + 3). The portal's own imports reach `DataTable` (ReviewList, CatalogTab,
  PoolTab …), which pulls `csv.ts` and `savedViews.ts`, so 3 more kit files are vendored, and
  `@tanstack/react-table` is a portal dependency.
- **The portal has its own `app/_kit/index.ts`** (not a copy): it re-exports only the vendored files, so no
  admin shell code (AdminShell, Sidebar, adminNav, SessionKeepAlive …) can be imported by accident.
- **No Sentry in the portal yet** (deferred, plan item (c)). Instead of shipping inert Sentry code and the
  `@sentry/nextjs` dependency, the portal has none; adding it later is one PR (`withSentryConfig` +
  `instrumentation*.ts`) plus the Vercel env vars Nghiệp sets by hand.
- **`/privacy` and `/terms`.** `https://adventure.asia/privacy-policy` answers 200 (checked with `curl -sI`,
  19/10/2026), so `/privacy` is a temporary (307) redirect to it. adventure.asia has **no** terms page: the
  site's route table (Nuxt bundle) lists only `/privacy-policy`, and `/terms`, `/terms-and-conditions`,
  `/terms-of-use`, `/terms-of-service` and 9 other guesses all answer 404. So `/terms` is a small portal page
  that says the partner terms are being finalised and gives `info@adventure.asia` (the address the
  adventure.asia site itself shows). No legal text is written. Flagged to Nghiệp (AA-820 / Ms. Thư).
- **Staff login link** on the portal's tenant-login page is the absolute admin URL from `portal/lib/hosts.ts`
  (code constant, no env var). The admin `/login` "B2B Tenant login" link uses `PORTAL_BASE_URL` from
  `frontend/lib/apps.ts` (code constant, no env var).

- **Portal gate on a backend outage** (`portal/proxy.ts`): fail closed outside development, but the cookies
  are kept on a 5xx / unreachable backend (only a 401/403 clears them), the same rule the admin gate got in
  AA-816. The plan said "clear the 5 cookies on fail"; clearing on an outage would log every tenant out for a
  blip.
- **`requireTenant()` returns the verified token**, so the portal proxies forward exactly the token they
  checked (the old playground route re-read the cookie after verifying).
- **Tenant logout also drops the token's verify-cache entry** on the instance that served it (same idea as
  the AA-816 staff logout).
- **`runPageCheck` moved from `ui-smoke.spec.ts` to `smoke-helpers.ts`** (plan: "use the shared
  runPageCheck"), with two optional hooks (`afterChecks`, `screenshots`). Admin behaviour unchanged.
- **Portal "not blank" signal** = kit row / kit empty state, else the page title `main :is(h1, h2)`: every
  portal page has one, but several (Brand Identity, Social Content, Marketplace, Settings …) have no table.
  Data errors still fail through the /api/ + console checks. Measured on Dev (below).
- **Vercel project id** is the repo variable `VERCEL_PORTAL_PROJECT_ID` (task text: the main session creates
  the project). The workflow fails red while it is empty, like a missing `VERCEL_TOKEN`.

## Tradeoffs

- **Vendored copies vs a shared package**: 14 files (plan said revisit above ~12). A workspace package
  would need npm workspaces or a published package; the Vercel root-dir build of `portal/` cannot see
  `frontend/node_modules`. The guard makes drift loud instead. If the list keeps growing, move to a package.
- **`/portal/*` prefix kept** on the new host (no href rewrite of ~100 links). Flattening is optional later.
- **Admin previews 308 to the PRODUCTION portal host** (a code constant), so a portal preview is never
  reached through an admin preview. Intended.
- **`globals.css` copied whole** (admin dark-theme vars included, unused because the portal pins light):
  smaller diff than trimming it now.
- **Moved files keep their 9 pre-existing lint errors** (set-state-in-effect ×5, no-explicit-any ×3,
  unescaped quote ×1). Fixing them would change behaviour in a move PR; `portal-lint` is non-required with
  the same step-level `continue-on-error` as `frontend-lint`. Admin lint went 163 → 139 problems.
- **xlsx 0.18.5** is carried over as-is (npm advisories, no fixed npm release); same exposure as the admin.
