# AA-785 — T9/T10 F1 year-format tolerance ("1637–38", "the late 1630s")

Branch `fix/aa-785-f1-year-forms` (from main @ 20a2387). Lane A-T9, S235 (Claude Code).

## Decisions
- **Opt-in keyword, one implementation.** `find_novel_numeric_claims(..., *, year_forms=False)` in
  `services/acp_shared/grounding.py`; only `quality_gates.gate_grounding` (T9/T10 F1) passes
  `year_forms=True`. T3 (`acp_produce/tenant_pipeline.py`), A1 (`content_generation/grounding.py`)
  and `source_facts.py` call it without the keyword and get byte-identical results
  (`tests/unit/test_aa298_aa325_grounding.py` untouched and green). A sibling function was rejected:
  two readings in two functions would drift (lesson: a value computed in two code paths must share
  one function). The AA-769 admin sentence check (`sentence_repair.check_replacement`) calls
  `gate_grounding`, so it gets the same reading for free.
- **No interim "F1 warn" step.** The issue scope says "F1 warn-only for these until merged"; the
  tolerance ships in the same PR, so F1 stays blocking (report 12 §1.4 "then back to blocking"
  expects this). Deviation from the issue text, agreed in the S235 synthesis.
- **Range rule.** `YYYY–YY` / `YYYY-YY` / `YYYY—YY` / `YYYY/YY` (2-digit tail, not followed by a
  digit or a decimal/thousands part). The start year is checked like any number. The tail is
  expanded to the full year in the same century (rolls over: `1998–02` → 2002), and is supported
  when the source has that full year (a source range `1637–52` counts as 1652) or when it is
  start + 1 and the source has the start (a founding that spans two calendar years — the S234
  case: seed "1637–1638", text "1637–38"). Otherwise the FULL end year is reported (`'1652'`, not
  `'52'`), so the repair prompt names a real year.
- **Decade rule.** `YYY0s` / `YYY0's` is supported by any 4-digit source number inside the decade
  (`1637` → "the 1630s", `1992` → "the early 1990s"); `YY00s` ("the 1600s") is read as the
  century (the looser reading, fewer false holds). Otherwise reported as `'1880s'`.
- **4-digit ranges ("1637–1638") are not touched** — both years are full numbers already and the
  plain reading checks each; not in the S234 evidence.
- **Message format unchanged** (`sentence states [...] not present in the content seed: '...'`),
  so `sentence_repair._F1_QUOTE_RE` still parses it (asserted in the new test).

## Tradeoffs
- Lenient by design on vague time phrases: "the 1630s" passes on any 163x seed year, even if the
  seed year belongs to another event in the same sentence family. A decade is a weaker claim than a
  year; the S234 panel never raised one. A different, unsupported decade still flags.
- start + 1 acceptance means "1637–38" passes on a seed that says only "1637". The panel never
  raised it, and the seed's founding year is the claim the reader takes away.
- A non-year number that looks like a range ("1500–20 m") is read as a range: the end becomes
  1520 and is still flagged (reported as 1520, not 20) unless the source has it — never a new pass.
