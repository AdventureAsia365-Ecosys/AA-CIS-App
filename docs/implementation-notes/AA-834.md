# AA-834 — flaky UI smoke "(b) collapse toggles the rail and survives reload"

Failure (gh run 38684738547): first try and retry both failed at `aa752-shell.spec.ts:67`,
`Expected < 186, Received 236` — the rail never collapsed. The test navigated with
`waitUntil: 'domcontentloaded'`, waited only for the rail to be visible (it is in the SSR HTML),
then clicked the collapse button. A click that lands before React hydrates the button has no
`onClick` attached yet, so it is a no-op.

## Decisions

- **Hydration marker on the admin sidebar**: `<aside data-testid="admin-sidebar">` gets
  `data-hydrated="true"` once the client has hydrated. Server HTML and the hydrating render omit
  the attribute; it appears only in the post-hydration commit, when the button's handler is live.
- **`useSyncExternalStore`, not `useEffect` + `useState`**: the brief suggested an effect + state,
  but the repo's ESLint (Next 16 React Compiler rules) rejects `set-state-in-effect` (lessons.md,
  Frontend). `useSyncExternalStore(noop, () => true, () => false)` is the pattern already used in
  `admin/content-quality/page.tsx` and the kit hooks (`useMediaQuery`, `useSidebarCollapsed`):
  React renders with the server snapshot (`false`) while hydrating, then re-renders with the
  client snapshot (`true`). Wrapped in a tiny kit hook `app/_kit/useHydrated.ts` so the Sidebar
  diff is 3 lines.
- **Shared test helper** `waitForShellHydrated(page)` in `smoke-helpers.ts` — bounded
  (15 s) wait for `[data-testid="admin-sidebar"][data-hydrated="true"]`.
- **Assertion order in (b)**: `data-collapsed="true"` first (deterministic, flips in the same
  commit as the click), the width poll second (CSS transition `.18s`).

## Changed

- `frontend/app/_kit/useHydrated.ts` (new) — `useHydrated()` hook.
- `frontend/app/_kit/Sidebar.tsx` — one import, one hook call, one attribute on `<aside>`.
- `tests/e2e/smoke/smoke-helpers.ts` — `waitForShellHydrated()`.
- `tests/e2e/smoke/aa752-shell.spec.ts`:
  - (b) waits for hydration after `goto` and after `reload`, asserts `data-collapsed` before width.
  - (a) waits for hydration before the logo click (keeps its bounded retry-click poll as a backstop).
  - (c) waits for hydration before pressing ⌘K (the palette keydown listener is client-only).
- Playwright `retries` unchanged (still 1).

## Tradeoffs

- A test-only attribute ships in production HTML (`data-hydrated` on one element). Cost is nil and
  it mirrors the existing `data-collapsed` / `data-testid` attributes on the same element.
- The marker proves the Sidebar subtree hydrated. The whole admin shell is one client tree with no
  Suspense boundary between Sidebar and the palette/logo, so it hydrates in the same pass; if a
  Suspense boundary is added later around part of the shell, that part would need its own marker.
