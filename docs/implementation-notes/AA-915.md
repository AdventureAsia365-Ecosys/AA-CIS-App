# AA-915 — Freeze the pipeline_lessons loop; ADR 0010 governed writing memory

Covers WM-01 (freeze `shared.pipeline_lessons` behind a flag) and WM-02 (app ADR for governed
writing memory). Design: AA-Ecosys root `docs/audits/2026-10-20-S245-writing-learning-loop/`
(decisions D1–D16, E1–E4, approved S245).

## Decisions

- **Env flag `PIPELINE_LESSONS_ENABLED`, default OFF, read on every call.** Only `1/true/yes/on`
  (case-insensitive, stripped) turns it on. ON exists only as a byte-identical rollback of the old
  S1 prompt.
- **No `tenant_flags` override, on purpose.** `S1_STRUCTURED_FACTS` and `S1_PER_DAY_TARGETS` let a
  tenant config win; this flag must not. A per-tenant switch would reopen the path the freeze
  closes (T2 runs the shared S1 graph, the table has no `tenant_id`).
- **One reader module.** `services/content_generation/pipeline_lessons.py` owns the query, the
  legacy block format and the flag. All three readers call `load_s1_lessons_block(conn)`:
  `s1_batch._load_prompt_state` (batch S1), `admin_pipeline._execute_run_tour` (sync S1, also the
  batch persist path) and `scripts/aa729/select_samples.py` (AA-729 golden-set sampler).
- **With the flag OFF no SQL is sent** (reader returns before `conn.fetch`; the writer returns before
  `asyncpg.connect`, which also skips its dedup SELECT). That keeps `pg_stat_user_tables`
  idx_scan / seq_scan / n_tup_ins flat for the WM-01 live check.
- **`_write_lessons_safe` keeps its name**; the guard is its first statement. It covers both call
  sites in `flag_fix_node` (the itinerary-only early return and the main fix path).
  `scripts/aa729/evalpatch.py` patches the name and refuses to install if it is missing;
  `tests/unit/test_aa729_golden_set.py` and `tests/unit/test_aa792_t2_tenant_voice.py` patch it too.
- **`write_lessons_log` also returns 0 when the flag is off** (second line of defence).
- **`stage = "audit"` left as is**, with a comment. Aligning writer and reader stages would revive
  the ungated loop.
- **The new ADR is app ADR 0010, not 0009.** App ADR 0009 is already taken on `origin/main`
  (`0009-f17-owns-offered-moments-promises-gate-dropped.md`, AA-787). D13 approved "app ADR 0009";
  the renumber is mechanical, but it deviates from an approved decision and is reported to Nghiệp.
  The ADR still cites ecosystem ADR 0009 (AI platform, AA-804), which is a different series.
- **`_LESSONS_SQL` and `_lessons_text` deleted from `select_samples.py`.** No test imports them.

## Tradeoffs

- **Freeze now vs. drop the table now.** Freezing keeps a one-env-var rollback and leaves the data
  for WM-34, which drops the table under the DRY-RUN procedure. No migration in this issue.
- **Env flag vs. DB/tenant config.** An env flag needs a task-definition change to flip, which is
  the point: nobody turns the loop on per tenant from the admin UI.
- **Keeping the dead writer code** rather than deleting it: evalpatch and two tests patch the
  function by name, and WM-34 removes it together with the table.

## Should know

- **The write path was probably already dead.** `flag_fix_node` is a sync LangGraph node run in an
  executor thread; `_write_lessons_safe` calls `asyncio.get_event_loop().run_until_complete(...)`,
  which raises in a thread with no event loop and is swallowed as `lessons_writeback_failed`. That
  matches n_tup_ins = 0 in the live dump. The freeze is still needed: a future "fix" of the loop
  handling or of the stage mismatch would revive an ungated, tenant-blind loop. Do not repair it.
- **The S1 prompt most likely does not change.** Root `docs/eval/aa729/fixture-1.1.0.json`
  (built 20/10 by `select_samples`) has an `s1:default` `system_prompt` with no "LESSONS FROM
  PREVIOUS BATCHES" block. The old lessons query ran in the same `try` that produced those brand
  rules, and the rules are present, so the query succeeded and returned 0 active `S1_rewrite` /
  `S1_editor` rows. The 1 956 idx scans in the 20/10 dump are empty scans. The live count (WM-01
  Done-when 1) confirms this; `test_no_active_rows_means_no_prompt_change` shows that 0 active rows
  means a byte-identical prompt and the same `prompt_version`. Only if active S1 rows exist does the
  PR fall in risk class "LLM prompt change" (independent review + batch-path prompt hash).
- **The live "no insert" check is weak evidence.** Because the old writer was already dead (see
  above), `n_tup_ins` stays 0 with or without this change; the live snapshot cannot tell old code
  from new. The proof for the write path is the unit tests (`test_write_safe_flag_off_*`,
  `test_write_log_flag_off_*`). The live check is meaningful for the read half (idx_scan /
  seq_scan).
- **AA-729 golden items**: if active S1 rows exist, S1 items frozen by `select_samples` before this
  change carry a lessons block the live prompt no longer has. Re-baselining is out of scope.
- **Batch S1 reads the helper twice** (materialize in `s1_batch`, then persist through
  `_execute_run_tour(batch_text=...)`). Both use the same helper, so they agree — unless api and
  worker run different SHAs, or a Bedrock batch materialized before the deploy is persisted after
  it. The merge gate (job tables idle, api and worker on the same SHA) covers this.
- **ADR 0010 invariant 12** defines Release 0's byte-identical baseline as the post-AA-915 prompt
  with the flag OFF, so WM-20 cannot take a lessons-bearing prompt as its baseline.
- **Live evidence (orchestrator):** row counts per stage, pg_stat snapshots A/B around one S1 and one
  T2 rewrite (fresh connections, ≥ 75 s wait — PG15 backends flush stats on an idle timer with
  retries up to 60 s), and — only if active S1 rows exist — the batch-path S1 prompt hash with the
  flag on and off, taken before snapshot A (it reads the table) and labelled "batch-path
  prompt_version" (not comparable with the sync path's stored `metadata.prompt_version`). A `lessons_writeback_frozen` log line is supporting evidence only (it needs flag_fix to
  apply with non-empty `lessons_extracted`); its absence is not a failure.
- Prompt-hash evidence: _only if the live count finds active S1 rows; to be added by the orchestrator._
