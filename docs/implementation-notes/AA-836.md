# AA-836 — tenant portal defects (T11 Publish, My Catalog drawer, markdown, 390 px)

## Decisions

- **D4 "See original content" (My Catalog drawer):** no new backend route. The drawer already
  loads `GET /v1/tours/versions/{id}` (`fetchVersionDetail`), and that response carries the Master
  source content it needs: `_VERSION_SQL` joins `gold_aa_internal.published_tours` and returns
  `pt.aa_summary`, `pt.aa_highlights`, `pt.aa_itineraries`, `pt.seo_title AS aa_seo_title`,
  `pt.seo_meta AS aa_seo_meta`. The route runs on the tenant pool (`aa859:t2_version_reads_pool`,
  RLS on `tenant_tour_versions` + 239 master-read on `published_tours`), so it is already
  tenant-scoped. The removed `fetchPoolTour()` called `GET /v1/tours/pool/{id}`, which never
  existed (only `GET /pool` and `POST /pool/{id}/rewrite`), so every drawer open logged a 404 and
  then fell back to exactly these version-detail fields anyway. What the tenant sees is unchanged;
  the 404 + console error are gone.
- **Markdown (D6):** the repo has no markdown renderer or stripper on the frontend (no
  dependency, no helper; the backend has `services/acp_content_writing/generate.py::strip_markdown`
  but that is Python, applied only to plain-text channels at write time). Added one small portal
  module, `frontend/app/(tenant)/portal/_components/markdownText.tsx`:
  `stripMarkdown()` for the T11 card previews (one plain line, clamped) and `<MarkdownBody>` for the
  T10 drawer body (headings, paragraphs, bullet / numbered lists, quotes, bold / italic, links as
  their text). It builds React elements, never `dangerouslySetInnerHTML`, so piece text cannot inject
  HTML. No new npm dependency (bundle + memory budget).
- **D3 StickyBar:** fixed in the shared portal `StickyBar` (`ui.tsx`), not per page. The 28 px
  `bleedTop` band is only needed while the bar is stuck (it covers `<main>`'s top padding band);
  at rest it painted 28 px of card colour over whatever sat above the card (T11: the bottom border
  of the connection card; also the card's own top border). The bar now detects "stuck" (a zero-
  height sentinel before it; stuck when the bar has moved down relative to the sentinel) and only
  then paints the band; at rest the band is transparent and lets clicks through. Geometry (margin
  / padding) is identical in both states, so nothing moves when it sticks.
- **ROUTE pill:** the portal `Badge` is now `nowrap` with `maxWidth: 100%` and an ellipsis on its
  text, so a long label (`Route: <hub> · N Segments`) stays a one-line pill instead of wrapping into
  a tall oval. Applies to every portal `Badge` (short labels are unaffected).

  `FinishedPiece`): review fix — the finished piece body is `<MarkdownBody>` too (was raw `pre-wrap`

- `frontend/app/(tenant)/portal/_components/ReviewList.tsx` (T10 My Content): the three filter

## Tradeoffs

- A new `GET /v1/tours/pool/{id}` was the other option. Rejected: it would duplicate data the drawer
  already has from an RLS-scoped route, add a tenant-pool route + flag + test + CONTEXT.md row, and
  the "original" the drawer shows is the Master text of `published_tours`, which `/versions/{id}`
  already returns.
- Render vs strip: the T10 drawer renders (a blog piece is long; plain text without headings or
  list bullets is hard to read). T11 previews strip (a 2-line clamp has no room for structure).
- `MarkdownBody` is deliberately small (no tables, no nested lists, no code highlighting). Writer
  output uses headings, paragraphs, lists and bold; anything else falls back to readable text.
- Stuck detection uses one passive capture-phase `scroll` listener per StickyBar (2 on the portal
  today), throttled to one `requestAnimationFrame`. A CSS-only `scroll-state()` container query
  would avoid JS but is Chromium-only.

## Should know

  converts to HTML for WordPress); only the read view is rendered. If tenants must never see `##`
  even while editing, that needs a rich-text editor — out of scope.
- Backend is unchanged (`content_preview` is still the first 280 raw characters; stripping is
  client-side). Review fix: because the slice can end inside a span, `stripMarkdown` now also drops
  markers the cut left unpaired (`visit **Punakha` → `visit Punakha`, `[Paro](https://ex` →
  `Paro`, a trailing bare `##`, an unclosed `*` / `_` / backtick opener). Stripping in the backend
  before the slice was the alternative; kept client-side so the API shape and other consumers of
  `content_preview` do not change. The frontend has no unit-test runner, so the cases (cut mid-bold,
  mid-link, mid-link-text, mid-code, bare `##`, plus snake_case / `2 * 3` / `#Bhutan` untouched)
  were run ad hoc through jiti, not committed as a test.
- Not converted (out of the review scope): `LiveWriter.tsx` still shows the in-progress text with
  `pre-wrap` while the piece is being written, so a blog piece's markers are visible during the
  live view; the finished view (Writer panel + T10) is rendered.
- Not verified live: layout at 390 / 1440, light / dark, and the stuck StickyBar band need the
  Playwright pass in the main session (T11 Publish, T10 My Content list + drawer, Dashboard, My
  Catalog Tours drawer network tab: no `GET /v1/tours/pool/{id}`).

## S241 UI-verify follow-up (Dev Playwright pass on 748c12c / PR #787)

Evidence: AA-Ecosys `docs/audits/2026-10-17-S241-ui-verify/` (README + PNGs). Branch
`fix/s241-ui-verify-defects`. The old and new styles were checked in a static DOM repro in
headless Chromium (same inline styles, Tailwind preflight `svg { display: block }`). It was not
checked on a deployed build.

### Decisions

- **ROUTE pill (A7 FAIL).** The portal `Badge` gets an `icon` prop. The icon is its own
  non-shrinking flex item (`inline-flex`, `align-items: center`, `flex-shrink: 0`,
  `line-height: 0`) between the dot and the text. The text span is `display: block`, `min-width: 0`
  and `overflow: hidden` with an ellipsis. Before, the lucide `<svg>` sat inside the text span, and
  preflight makes `svg` a block, so the icon took its own line. Repro height: 29 → 18 px at both
  widths (Dev measured 33.5 vs 22.5 with real fonts). The ellipsis still applies at 390.
  `PublishPendingList` now passes `icon={<Milestone size={11} />}`. No other portal Badge has an
  icon child.
- **Stuck StickyBar strip (D3).** Root cause: Chrome resolves the sticky `top` against `<main>`'s
  scrollport inset by its padding-top (28 px desktop, 20 px phone). With `top: 0` the stuck bar's
  border box started at y 84 (or y 76 on a phone), so the whole `bleedTop` band was inside the bar
  and the strip from y 56 down to the bar was left uncovered. Fix: `top: -bleedTop` (when
  `bleedTop > 0`). Repro, stuck: the bar top moves from 84 to 56 at 1440 and from 76 to 48 at 390
  (the 8 px above 56 is clipped by `<main>`'s overflow). `elementFromPoint` from y 57 to 89 hits
  the band only, where before it hit scrolled rows at 390. At rest nothing changes: the
  sentinel/band logic is the same, the band is still transparent and starts `bleedTop` lower, and
  sticky offsets only apply once the bar reaches the line. The bar's content lands where a
  `top: 0` bar without a bleed would put it. SlateTab's StickyBar uses the same component and gets
  the same fix.
- **Heading duplicated into T11 previews (D6 side effect).** `stripMarkdown(text, opts?)` takes
  two options: `dropLeadingHeading` (drop the first block when it is a heading) and
  `blockSeparator`. Blocks are headings and blank-line-separated text. Between two blocks the
  separator is used unless the first block already ends in sentence punctuation (`.!?…:;)"'`), in
  which case a plain space joins them. With no options the output is exactly the same as before:
  every line is joined with a space. T11 passes `{ dropLeadingHeading: true, blockSeparator: " · " }`.
  Ad hoc cases:
  `## Where Two Worlds Meet…\n\nThere is a line…` → `There is a line…`.
  `Intro\n\n## H2\nBody **cut` → `Intro · H2 · Body cut`.
  `- a\n- b\n\nline #Bhutan` without options → `a b line #Bhutan` (unchanged).
- **Dashboard Recent Activity at 390.** On a phone the grid is `36px minmax(0, 1fr)`. The status
  badge moves to the meta line under the name, next to the date, and that line wraps if needed. The
  name gets the whole text column, about 268 px against 99 px before, and stays one line with an
  ellipsis. Desktop is unchanged.
- **T4 My Catalog drawer title (optional item 8).** The kit Drawer title is now the tour name
  (`openGroup.aa_name`). CatalogDrawer's in-body header no longer repeats it and keeps only the
  language, the Save button and its own close button. Both close buttons were already there before
  this change, so that duplicate is pre-existing and was left alone.

### Changed

- `portal/_components/ui.tsx`: Badge `icon` prop; StickyBar `top: -bleedTop` and comment.
- `portal/_components/PublishPendingList.tsx`: ROUTE pill passes `icon`; the preview uses the new
  `stripMarkdown` options.
- `portal/_components/markdownText.tsx`: `StripMarkdownOptions` and block-aware joining.
- `portal/_components/DashboardTab.tsx`: badge goes under the name on a phone.
- `portal/_components/CatalogTab.tsx` and `CatalogDrawer.tsx`: tour name in the Drawer title.
- `_kit/Drawer.tsx` (shared with admin): the title box is `flex: 1 1 auto; min-width: 0;
  overflow: hidden`, and a string title ends in an ellipsis with a tooltip. The close button has
  `flex-shrink: 0`. See AA-863 notes for the admin side.

### Tradeoffs

- The `top: -bleedTop` fix assumes `bleedTop >= <main>` padding-top. The default 28 covers both
  breakpoints (28 / 20). Measuring the padding at runtime would need state from an effect, so
  instead the assumption is written in the StickyBar comment.
- With `dropLeadingHeading`, any leading heading is dropped, even a section heading that differs
  from the title (the third T11 card starts with `## The Weight of 1937`). A 2-line teaser gains
  more from body text than from a section heading, and the rule stays simple.
