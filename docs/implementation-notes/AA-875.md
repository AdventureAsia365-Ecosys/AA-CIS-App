# AA-875 — SSRF-safe outbound HTTP client (`shared/safe_http.py`)

## Decisions

- **Built on aiohttp**, the library every tenant-URL call site already used, so the response
  handling at the call sites (status, content-type, body checks from AA-460) stays the same.
- **Connect to the checked address**: the client gives aiohttp a custom resolver
  (`_PublicOnlyResolver`) and turns the DNS cache off. aiohttp connects only to the addresses
  that resolver returns, and the resolver refuses the whole host when *any* record is not public.
  The check and the connect use the same lookup, so a DNS answer that changes between a
  "validate" step and the connect (DNS rebinding) cannot reach an internal address.
- **IP literals skip aiohttp's resolver**, so `validate_url()` checks them before every hop
  (first request and each redirect).
- **Non-canonical numeric hosts are refused** (review fix): aiohttp treats any all-digits-and-dots
  host as an IP literal (`aiohttp.helpers.is_ip_address`) and hands it straight to getaddrinfo,
  whose `inet_aton` reads `2130706433`, `127.1`, `0177.0.0.1`, `012.0.0.1`, `0` as 127.0.0.1 /
  10.0.0.1 / 0.0.0.0 — past the resolver. `validate_url()` now refuses (`reason=noncanonical_ip`)
  any host aiohttp would treat as a literal that `ipaddress` cannot parse. Refusing beats
  normalising with `inet_aton`: no real WordPress site is typed as a decimal integer. Hex forms
  (`0x7f.0.0.1`) are not digits-only, so aiohttp sends them through the resolver, which checks the
  answer. Because redirect hops run `validate_url()` too, a 30x to `https://167772161/` and a
  `wp_url` saved before AA-875 are both covered.
- **Redirects are followed by hand** (`allow_redirects=False` + a loop, at most 3 hops). Each hop
  is validated again (scheme, IP literal, then the resolver at connect). 301/302/303 turn a POST
  into a GET (what aiohttp did before); 307/308 keep method and body. `Authorization` / `Cookie`
  headers and Basic auth are dropped when a hop changes origin (aiohttp's own rule before).
- **What counts as public**: `ipaddress.is_global`, minus multicast, plus an explicit deny list
  (RFC 1918, loopback, link-local incl. 169.254.169.254, CGNAT, 0/8, 240/4, benchmark, ULA
  fc00::/7 incl. fd00:ec2::254, fe80::/10, site-local, multicast). IPv4 embedded in IPv6
  (`::ffff:a.b.c.d`, 6to4, NAT64 `64:ff9b::/96`) is judged by the embedded IPv4; Teredo is refused.
  IPv4-compatible `::/96` (`::7f00:1`) and SIIT `::ffff:0:0:0/96` are refused outright (review
  fix): `is_global` calls them public and some stacks map them to the embedded IPv4.
- **Name deny list** (`localhost`, `*.localhost`, `*.local`, `*.internal`) is only defence in
  depth; the address check is the real control.
- **Scheme allowlist**: `https` only by default (WordPress always required https). URLs with
  user-info (`https://a@b`) are refused (parser-confusion trick).
- **Limits**: one total deadline per `request()` across all redirect hops and the body read
  (`asyncio.timeout(timeout)`; callers keep their 8 s / 30 s even when the site redirects — aiohttp's
  own `total` is per hop, which allowed 4 × 8 s = 32 s, past the 29 s API Gateway limit), connect timeout ≤ 10 s, body
  cap 5 MiB by default (counted on the decompressed stream, so a gzip bomb stops at the cap).
  `trust_env=False`, so no proxy from the environment can bypass the resolver.
- **Save-time check (WordPress connect)**: `save_wordpress` now resolves the host; an address that
  resolves to a private/reserved range → 422 and a `safe_http_blocked` log line. A name that does
  not resolve yet is still accepted (the old design: typos / new DNS are classified by the test
  connection). The real protection is at connect time.
- **Blocked at connect in test-connection** → 422 with the same tenant-safe message (like the old
  pre-check), nothing written to `last_verify_error`.
- **Facebook**: the host is fixed (`graph.facebook.com`), so it is not a tenant URL; the adapter and
  the Facebook test-connection still go through `safe_http` (one outbound path, redirect re-check,
  size cap), and the tenant-entered `page_id` / post id are percent-encoded as one path segment.

- New `shared/safe_http.py` (`request()`, `validate_url()`, `check_destination()`,
  `is_public_ip()`, `UnsafeURLError`, `ResponseTooLarge`, `TooManyRedirects`, `SafeResponse`).
- `api/routers/v1_integrations.py`: `_validate_wp_url` removed → `_normalize_wp_url` +
  `safe_http.validate_url` / `check_destination`; WordPress + Facebook test-connection use
  `safe_http.request`.
- `services/acp_s4_blog/cms/wordpress.py` (`create_post`, `find_post_by_slug`, `delete_post`) and
  `services/acp_publish/facebook.py` (`create_post`, `find_recent_post`, `delete_post`) use

  public DNS answer, so no unit test does a real lookup.

## Tradeoffs

- One `ClientSession` per `request()` call (no pooling). Tenant URL calls are rare clicks or one
  publish, so the extra TLS handshake does not matter; it keeps the guarded connector isolated.
- Redirect cap 3 (aiohttp default was 10): a WordPress site needs at most http→https→www.
- Refusing the whole host when one DNS record is private (instead of dropping that record) is
  stricter; a real public WordPress host never publishes a private record.

## Should know

- To add a new tenant-URL fetch, call `safe_http.request()`; never open an `aiohttp.ClientSession`
  / `httpx.AsyncClient` on a tenant-supplied URL.
- Rejections log `safe_http_blocked` (fields `host`, `reason`, `stage` = `url|dns|redirect`) —
  the CloudWatch evidence for the Done-when live check. The URL path/query is never logged.
- Live check (orchestrator, after the paid round): connect WordPress with a host that resolves to
  a private address (e.g. a `nip.io`-style name for 10.0.0.1) → 422 + `safe_http_blocked`; the
  WordPress test site still connects and publishes.
- Tests: `tests/unit/test_aa875_safe_http.py` runs real local aiohttp servers (127.0.0.1 plays the
  public site, 127.0.0.2 the internal one and counts hits), so "blocked" is proven by zero hits.
  Two mutations were checked by hand: disabling the resolver's address check fails 7 tests,
  skipping the per-hop redirect validation fails 2.
  Review round: the new tests (numeric hosts as start URL and as redirect target against a raw TCP
  listener counting accepted connections, the slow redirect chain deadline, `::7f00:1`-style
  addresses) were run against the pre-fix module — all 26 fail there, all pass after.
- `tests/integration/test_aa859_integration_connect_pool.py` was updated to the new seam but could
  not run locally (local Postgres has no `aa_app_user` role; the unchanged file fails the same way) —
  CI "Integration Tests" is the check.
