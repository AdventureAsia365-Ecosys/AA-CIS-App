## Decisions

- **Floor flag = attempt 1 only, reusing `stock_blocking`.** `gate_social_shape(..., floor_blocking=False)` gets a
  keyword; `run_quality_gates` passes `F14_FLOOR_BLOCKING and stock_blocking` (service.py already sets
  `stock_blocking=attempt == 1`). The default is `False`, so the post-loop re-runs in `_cut_truth_items` and
  `_enforce_authenticity` keep their old warn-only behaviour (a cut that drops the post under the band is still
  held through F9's `cut_reason`, unchanged).
- **The floor block goes to a full rewrite**, not a sentence repair: F14 is not a sentence-repair gate, so
  `sentence_repair.plan` returns None and `rewrite_with_feedback` runs once with
  `F14_social_shape: post is N words, under the 120–250-word band … — rewrite it to 150–220 words with more of the
  source's own detail, keeping the same angle and adding nothing the source does not state` (panel r4 fix 3:
  "regenerate with more seed facts"). `" under the "` stays in the text because `_cut_truth_items` reads it.
- **Never holds.** New `quality_gates.never_holds(g)`: a STYLE_ONLY gate, or an F14 result with no "far over the"
  violation. `hold_failure`, `service._hold_or_ship` and `service._waive_style_only` use it. Reason: the AA-528
  revert can put attempt 1's ledger (F14 blocking) back as the final one; without this the piece would be held on
  word count. AA-788 (related) also says "F14 under-length: repair once, never hold". The far-over-the-band block
  (> 1.3 × top) still holds, as before. `never_holds` reads the violation text, so a `ledger_snapshot` or a DB row
  answers the same as the live dict (no new key that a trim could drop).
- **Broetry warn (F15_voice_warn)**: ≥ 2 consecutive prose/bullet sentences of ≤ 5 words, one warning per run,
  quoted with the same `_quote` helper (admin highlights work). Hashtag lines are never in the spans. A sentence the
  configured CTA contains (word-boundary match on folded words) ends a run — `run_quality_gates` now passes `cta`
  to `gate_voice_warn`. Warn only, never repaired (same contract as the other warn checks).
- **New stock lines**: the six phrases from the issue are in `STOCK_PHRASES` (writer avoid list) and as
  regexes in `STOCK_PATTERNS` (F15_voice, LinkedIn only). Patterns are written from the real r1–r4 sentences:
  `not / isn't … filler` (one optional word: "not downtime filler"), `worth pausing on|over|in|for`,
  `not (simply) (a) (dramatic) backdrop` (never "forms a dramatic backdrop"), intransitive `does not perform`
  only (an object after it — "do not perform the cham dance" — is a trip fact), `tolerates them|you|visitors…`,
  `isn't/aren't/not (a) (word) inconvenience(s)`. Curly apostrophes accepted.
- **§3.7 channel spec**: `_LINKEDIN_AVOID` gains the three items verbatim (no comma inside any item:
  `ranking.split_avoid_phrases`); the `CONSUMER_SOCIAL` structure is the plan's text verbatim — no Kuang Si
  example, no "contractions welcome". Other registers are untouched.

## Tradeoffs

- **Reusing `stock_blocking`** couples "attempt 1" for two gates. A separate `attempt` argument would be cleaner
  but would touch every caller and test; the flag already means "attempt 1" in service.py, and
  `F14_FLOOR_BLOCKING` is its own kill switch.
- **A full rewrite vs. a sentence repair** for an under-floor post: a repair cannot add a paragraph; the full
  rewrite (t9_write) costs ≈ $0.004 per short LinkedIn post (plan estimate). Risk: the AA-528 guard reverts the
  rewrite when it breaks another blocking gate without fixing more — the short attempt-1 text then ships with F14
  waived (never held), the same as a reverted F15 repair.
- **When F15_voice and the F14 floor both fail on attempt 1** the attempt takes the full rewrite (feedback lists
  both) instead of the cheap sentence repair; the rewrite is told about the stock line too.
- **Broetry ≤ 5 words** as the plan says. A tighter ≤ 4 would also catch all 4 real hits; kept 5 and excluded the
  CTA instead, which was the one realistic false-positive path (a short line before "Ask us for the dates.").
- **New stock lines are LinkedIn-only** (STOCK_PATTERNS is read only with a channel spec). The same lines appear
  in 6 blog pieces (r2–r4) and are not gated there; extending to blogs (via `hygiene.template_lines`, which runs on
  every channel) is a separate decision.
