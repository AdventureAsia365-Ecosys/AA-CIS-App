## Decisions

- **Scope of this PR:** the four drops plus the F7→F16 merge. The memo's "agent does next" step 1 lists
  the drops and the merges. The drops and F7 only remove warn results, so no hold or repair changes; the
  replay below shows it. Three merges are left out (see Changed).
- **promises_an_option dropped** (Nghiệp S234, reconfirmed S245, option a). An amendment ADR in this repo:
  `docs/adr/0009-f17-owns-offered-moments-promises-gate-dropped.md` (the origin ADRs 0023/0026 are not
  tracked in this repo). The guard from the decision is written in the ADR: if the AA-729 golden replay
  finds a real failure that the removed check catches and F17 misses, fold it into F17 as a non-blocking
  sub-check (option c) and report to Nghiệp. The removed function is pure; the replay reads it from git
  at the parent of this commit.
- **F8_framework dropped with its LLM call** (one `t10_judge` call per attempt, about 3.1% of T9 cost
  in S234). `framework_rubrics.py` had no other reader, so it is deleted. The `t10_judge` stage stays
  (F9 uses it). `run_quality_gates` loses its `goal_key` parameter (only F8 read it) and its
  `route_segments` parameter (only promises_an_option and F3 read it). The service call site is updated.
- **F3_structural_variance and F5_atom_density dropped.** The writer prompt still asks blogs for H2
  sections and `[R:id]` tags: F1 and F16 read them, and the prompt text is unchanged (byte-identical; only
  the T9 `prompts.py` module docstring changed).
- **F7_faq_dedup folded into F16_faq, keeping the fixer.** `service.run_write_background` runs
  `drop_restated_faq` on every attempt, and again after an FAQ regeneration, before the gates read the
  text. So F7 at gate time only fired when that fixer had not run. F16 counts the pairs left after the
  fixer (its message already says so), and the fixer's log stays in the `F7_faq_autofix` flag. The check
  itself is kept as `restated_faq_answers()`, used by tests to prove the fixer leaves nothing.
- **Dead helpers removed:** `offered.is_offered_seed`, `offered.has_status_lines`,
  `offered.has_offered_phrase` and `trip_facts.mentions_activity` (the public wrapper; `_mentions_activity`
  stays for F17). Each was read only by promises_an_option.
- **Admin UI:** `GATE_LABELS` keeps the five old names, because ledgers from before this change still
  carry them. A new `RETIRED_GATES` set adds "(retired)" to their label, and the Pieces filter lists them
  under a "Retired (older pieces only)" group. The Gate stats endpoint groups by the ledger's gate names,
  so it needs no change. Retired rows drop out of its 30-day window on their own.

## Changed (vs the issue text)

- **Not done in this PR (left on AA-787 or moved, for the orchestrator to decide):**
  - *F15_voice_warn → F15_voice.* A ledger result has one `blocking` flag. F15_voice blocks on attempt 1,
    and `sentence_repair.plan` rewrites every violation of a blocking result. Merging the two would make
    the repair rewrite the warn-only checks (trade register, audience leak, opener). The S234 code split
    them on purpose to prevent exactly that. The merge needs severity per violation, which is a design
    change (ledger shape, `sentence_repair`, admin highlights). Report 12 also folds F15 into the new
    voice-rubric gate, so it fits better with that AA-741 child.
  - *F2 variants + F15 stock list → one lexicon gate "with severity per source".* Same blocker: severity
    per violation. Also, AA-800 (S245, live) has since added three more F2 results (`F2_platform_truth`,
    `F2_superlatives`, `F2_style_warn`), and the AA-800 lane is editing the same word layers right now.
    Merging here would collide with that lane and change repair routing (`CHEAP_REPAIR_GATES`,
    `STYLE_ONLY_GATES`).
  - *F13_hygiene repeat → F13_repeat.* Already done by AA-768 S234 round 4: `hygiene.find_issues` puts a
    strict repeat in the blocking `repeat` list (F13_repeat). Only the loose two-trigram match stays an
    F13_hygiene warning, which round 4 chose on purpose (false positive r1 #17). No change.
- **Done-when "27 → ~18":** today's stack had grown to 31 distinct results (AA-800 and AA-819 added five).
  After this PR there are 26: blog 30 → 25, LinkedIn 26 → 24, other channels 25 → 23. Report 12's "~18"
  also needed the three deferred merges plus new gates.

## Tradeoffs

- With promises_an_option gone, F17 is the only check for "optional stated as planned". F17 blocks and
  repairs, which the warn gate never did. Its known limit (AA-773 notes, r5 README:92): a hedge in the
  same clause can slip past it offline. In the other direction, F17's hedge list has no "there is time
  to", so F17 flags that hedged sentence where the old gate did not. That makes F17 stricter, not weaker
  on recall; the test pins it, and F17 tuning owns the fix.
- Dropping F8 removes a structure signal. In S234 it fired on 20 of 24 *light* LinkedIn posts and showed
  no lift on blogs, so the signal was noise. Report 12 suggests folding one or two of its criteria into
  the F9 prompt; that is not done here.
