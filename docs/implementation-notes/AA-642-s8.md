# AA-642 S8 — shared core `aa_llm` for TripPlanner and the CRM (root ADR 0009 decision 13)

Scope: slice B4 of the S262 gateway plan. Canonical pure core `shared/aa_llm/` in AA-CIS-App, its sync tooling,
CIS migration 323 (the two contract views for TripPlanner), the TripPlanner and AA-Partner copies, and the root
wrapper. No route change, no paid call, every provider mocked.

## Decisions

- **Pure core, copied logic.** `errors.py`, `pricing.py` and the v2 row of `ledger.py` copy the logic of
  `shared/llm_client/errors.py`, `pricing.py` and `call_log._v2_values` / `_INSERT_V2_SQL`. The registry v2 lane
  (A3) edits `errors.py`, `pricing.py`, `client.py` and `catalog.py` in parallel, so this slice does **not** touch
  them: the CIS modules keep their own code and `tests/unit/test_aa642_s8_aa_llm_parity.py` pins both sides to each
  other on a table of cases (error classes, quotes for the same catalog prices with and without deployment
  overrides / batch / geo / the Haiku 5.5 long-prompt tier / an unreadable catalog, the ledger column list, casts and
  v2 normalisation). The re-export switch (CIS modules importing from `shared.aa_llm`) is a follow-up after both
  lanes merge; the parity test then becomes trivially true and can be deleted with it.
- **Pricing takes the catalog as an argument.** The CIS `quote` reads `shared.llm_model_catalog` itself; the core
  `quote(model, usage, deployment, catalog=catalog_rates(...))` receives the rates the app read through its own
  config source. `on_estimate` replaces the structlog warning (the core has no logger).
- **Ledger row.** `LedgerRow` carries every column of the CIS v2 INSERT (35); `insert_sql()` emits one placeholder
  per column with the CIS casts. Values outside the 319 CHECKs are written NULL (as CIS does). `app` is required
  (no CIS default), and `is_experiment` reads only the signal (the CIS eval-label ContextVar is CIS-only).
- **Budget.** `BudgetDecision` + `decide()` reproduce TripPlanner's `budget_status` rules (fail closed when spend is
  unreadable, total and stage caps, 80 % near-cap) and its dict shape (`as_dict`).
- **Ports** are Protocols only (ConfigSource, LedgerSink, BudgetStore, ClientFactory); each method receives the
  connection or pool, so the caller keeps transaction control (the CRM's lock-until-logged guarantee).
- **Contract module.** `contract.py` names the two 323 views, their columns and the SELECTs a consumer runs (named
  columns, never `*`), so a consumer's SQL is tied to the core version it vendors.
- **Integrity inside the package.** `check_copy.py` (stdlib) checks a copy against its `MANIFEST.json` (sha256 per
  file, nothing added, nothing missing) and optionally the consumer lock's `manifest_sha256`. The manifest keeps each
  hash on its own line as `{"sha256": ...}` (gitleaks lesson S253).

## Changed (vs. the plan)

- The plan lists one CIS PR "core + sync tooling + 323 if expand". 323 is **contract** (see Tradeoffs), so it ships
  as its own migration-only CIS PR. The core PR does not need the views (only TripPlanner reads them), so the order
  is: CIS core PR → CIS 323 migration PR (after A3's 320–322) → Infra copy → DB Migrate apply → TripPlanner PR →
  Partner PR → root wrapper PR. The 323 tests that read `shared/aa_llm/contract.py` live in the migration PR, which
  merges after the core PR, so no PR imports code of a later one (lesson S258).

## Tradeoffs

- **323 is contract, not expand.** The catalog-view recipe (X1 S22) makes `catalog_owner` own every `catalog.*`
  view. `catalog_owner` has no SELECT on `shared.llm_*` today, so 323 grants it column-level SELECT on four existing
  tables: a `relacl` change on pre-existing objects, which ADR 0017 classifies as contract. The alternative (views
  owned by `cis_owner`, no grants, expand) would have broken the "views owned by NOLOGIN catalog_owner" rule of
  `schema-ownership.md`, so the extra manual apply step was preferred.
- **Spend view reads the ledger, not `tripplanner.llm_spend_daily`.** ADR 0009 d13 says TripPlanner reads its spend
  through `catalog.v_llm_app_spend_today_v1`. The view sums today's `shared.llm_call_log` rows with
  `coalesce(app, quality_signal->>'app') = 'tripplanner'` (today's rows only, through the `created_at` index).

## Should know

- Never edit a copy in a consumer: change `shared/aa_llm/` here, run `python3 shared/aa_llm/check_copy.py --write`
  (the unit test fails on a stale manifest), merge, then sync (the Llm Core Sync bot opens the consumer PRs).
- The core must stay standard-library only with relative imports (`test_core_imports_only_the_standard_library…`);
  it is imported as `shared.aa_llm` (CIS), `backend.aa_llm` (TripPlanner) and `app.aa_llm` (Partner).
- The code is ruff-formatted with the AA-Partner config (line length 120, py312) so the byte copy passes Partner's
  `ruff check` and `ruff format --check` without an exclude.
