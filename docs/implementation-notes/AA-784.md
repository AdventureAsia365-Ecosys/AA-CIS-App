### Decisions

- **Migration 286** (`api/migrations/286_place_card_draft_gpt6_luna.sql`, byte copy in AA-CIS-Infra
  `db/migrations/cis/`): `a3_place_card` → role `validate`, provider `openai`, model `gpt-6-luna`, `acc3`. Same shape
  as 222 (unconditional `UPDATE ... WHERE stage = 'a3_place_card'`): the eval decision applies whatever the row holds.
  `a3_place_card_check` is not touched (Haiku, fallback `{sonnet}`).
- **Fallback `{gpt-5.6-luna}`, not 222's `{sonnet}`.** The checker is Claude Haiku. With a Claude draft fallback, every
  card drafted while the primary fails is drafted and checked by the same vendor (222 accepted that). GPT-5.6 Luna is
  another vendor than the check and is the previous live drafter, measured in the same eval (FK 2.4–4.0%), so a
  fallback card is no worse than today's. The check's own Sonnet fallback stays Anthropic against an OpenAI draft, so
  every combination of the two chains is cross-vendor (unit test pins it). No OpenAI-platform key, no shadow.
- **Catalog guard + enable.** 170 seeded `gpt-6-luna` disabled ("Bedrock agreement not accepted on acc3 yet"). Dev
  already routes four stages on it and the eval called it, so a still-disabled row (a fresh DB) is enabled by 286 with
  a NOTICE. A missing row, a non-`converse` row, no `acc3` profile or no price refuses the file. A disabled / missing
  fallback `gpt-5.6-luna` is only a NOTICE (the route skips it).
- **`DRAFT_MAX_TOKENS` 1500 → 4000.** GPT-6 Luna reasons inside `max_tokens`: at 1500 it returned an empty reply in
  the S246 trial. The eval ran it at 4000: 30 drafts, max 1,384 / p90 1,201 output tokens, all `end_turn`; the
  orchestrator's read of `llm_call_log` history gives p90 1,956. Billing is per token used.
- **Check stays at 1024**, now named `CHECK_MAX_TOKENS`: Haiku 4.5 ran at 1024 in the eval (177 checks, max 490,
  all `end_turn`).
- `SAFE_DEFAULTS["a3_place_card"]` mirrors 286 (`gpt-6-luna`, fallback `gpt-5.6-luna`).

### Tradeoffs

- **Catalog-unreadable behaviour.** Both draft keys are catalog keys, so with the catalog unreadable the draft call
  raises (no card, no miss stored; the next build tries again) where 222's legacy Sonnet would still have drafted.
  Accepted: card builds are jobs, a missing card only means fewer background facts, and the alternative breaks the
  vendor rule exactly when things go wrong.
- **Coverage.** 88% of identifiable groups by the rule's wording; 79% if the 4 ambiguous groups counted (then the
  winner would be GPT-5.6 Luna × Opus 5.5 at ≈ $72). GPT-6 Luna declines vague names instead of guessing.
- **Slightly fewer facts** (U 3.44 vs 3.73), still above the 2.5 floor.
- **Checker recall is weak** (Haiku 4.5: 8/34 natural wrong facts, 22/23 planted), so quality rests on the drafter;
  that is why the drafter changes and the checker does not.
