# AA-535 — S1 SYSTEM_PROMPT hardcodes "Adventure Asia" voice; neutralize Master Content base

## STEP0 — updated approach (05/09/2026 issue update)

The issue's original description asked to edit the hardcoded Python `SYSTEM_PROMPT` constant in
`services/content_generation/prompts.py` / `graph.py` directly. A same-day update to the Linear
issue retracted that plan: Nghiep confirmed a real `/admin/brand` (CIS Admin > Brand Identity)
page already exists, backed by a real DB table, and asked to investigate whether S1 rewrite reads
from it before touching any Python code.

### Where `/admin/brand` reads/writes

- **Table**: `shared.tenant_brand_rules` (created `api/migrations/003_schema_v3.sql`, evolved by
  migrations 008/018/043/044/045/046/047/104).
- **API**: `api/routers/admin_pipeline.py` — `GET /admin/brands` (list), `GET /admin/brands/
  {brand_name}` (detail + version history), `POST /admin/brands` (create), `PUT /admin/brands/
  {brand_name}` (update — inserts a NEW version row, deactivates the old one), `POST /admin/
  brands/{brand_name}/activate` (`admin_pipeline.py:3896-4064`). All hardcode `tenant_id =
  '00000000-0000-0000-0000-000000000001'` (aa_internal).
- **The "default" row's identifier**: `tenant_id = aa_internal` **and** `brand_name = 'default'`.
  This is the exact row Master Content (S1) resolves to when no explicit brand is chosen
  (`admin_pipeline.py::_resolve_brand_rule()`, `admin_pipeline.py:311-335`).
- **Columns**: `system_prompt` ("Should Write"), `style_guide` ("Writing Style"), `core_idea`,
  `customer_segment`, `customer_mindset`, `voice_examples` ("Tone of Voice", jsonb list),
  `good_examples`, `forbidden_words` (jsonb list), `brand_type`, `target_markets`,
  `rewrite_language`, `version`, `is_active`.

### Does S1 read from this table? — YES, but only as an append, never a replacement

File:line evidence:
- `services/content_generation/prompts.py:68-113` — hardcoded `SYSTEM_PROMPT` constant, opens
  with `"You are a travel content editor for Adventure Asia, a private-travel brand for senior
  professionals (40-60)..."`.
- `services/content_generation/graph.py:296-331` (`generate_node`) — line 315: `system =
  SYSTEM_PROMPT` (the hardcoded constant is ALWAYS the starting point, for every call, S1 or
  T2/T5+ alike). Lines 310-324:
  ```python
  brand_sp = state.get("brand_system_prompt", "") or ""
  ...
  system = SYSTEM_PROMPT
  ...
  if brand_sp:
      system += f"\n\nCLIENT BRAND CONTEXT (append only — do not override AA rules):\n{brand_sp}"
  ```
  The comment is explicit and load-bearing: **append only — do not override AA rules**.
- The DB fetch happens upstream in the caller, not in `graph.py`: `admin_pipeline.py::
  _resolve_brand_rule()` (`admin_pipeline.py:311-335`), called from `_execute_run_tour()`
  (`admin_pipeline.py:338-431`, itself called by `POST /admin/run-tour` / `/admin/run-tour-async`,
  `admin_pipeline.py:982-989`). Resolution priority: explicit `brand_identity_id` → named active
  `brand_name` → the `'default'` sentinel, all scoped to `tenant_id = aa_internal`. The resolved
  row's `system_prompt`/`style_guide`/`forbidden_words`/`core_idea`/`customer_segment`/
  `customer_mindset`/`voice_examples`/`good_examples` are packed into a `brand_rules` dict
  (`admin_pipeline.py:411-429`), passed through `_rewrite_tour()` (`api/routers/v1_pipeline.py:
  82`, `v1_pipeline.py:112-121` maps them into `initial_state`), and consumed exactly as shown
  above in `generate_node`.
- **T2/T5+ (tenant rewrite) uses the SAME `generate_node`/append mechanism**, just with a
  simpler, tenant-scoped fetch in `api/routers/v1_tours.py:516-549` (no `brand_identity_id`/
  `brand_name` disambiguation — always that tenant's own highest-version active row). Confirmed
  unrelated to this issue's scope and left untouched.

**The real gap (why "S1 reads the table" is not the same as "editing the table makes S1
neutral")**: because the append is explicitly non-overriding, the hardcoded, AA-specific opening
of `SYSTEM_PROMPT` ("Adventure Asia," "senior professionals," "$250k+ audience") runs on EVERY
S1 call regardless of what the `default` row's own `system_prompt` says. Simply rewriting the DB
row's content (this task's actual deliverable, see below) genuinely shifts tone via the appended
block — it does NOT and cannot fully eliminate the underlying Adventure-Asia-specific framing,
because the graph.py mechanism guarantees the hardcoded text is never removed or overridden.
Also worth flagging: `build_rewrite_prompt()`'s returned user-role prompt itself contains the
unconditional literal `"Rewrite the following tour content for Adventure Asia brand."`
(`prompts.py:157`) — untouched by any DB row, for S1 or T2/T5+ alike.

**This is exactly the fork the issue update called out.** Per the issue's explicit branching
(step 3 applies since S1 DOES read the row — even if only as an append) and the explicit
instruction to preserve the append-only architecture (step 5) and not touch `prompts.py`/
`graph.py`'s Python text as originally planned, the decision made here is: **do the content-only
fix (rewrite the `default` row via the real admin API), and report the append-only/hardcoded-
floor limitation to Nghiep as a residual, NOT-fixed gap requiring his explicit sign-off before any
further Python-level change** (see "Decisions" below).

## Decisions

1. **No Python code touched.** `prompts.py`'s `SYSTEM_PROMPT` text and `build_rewrite_prompt()`'s
   `"for Adventure Asia brand"` literal are unchanged — per the issue update's explicit
   instruction. This means the fix's reach is real but partial: the `default` row's own content
   (appended after the hardcoded floor) is now neutral, but the hardcoded floor itself still
   frames the LLM's very first instruction around Adventure Asia. Flagged clearly to Nghiep in the
   Linear comment — a full fix would require a deliberate, separately-approved edit that splits
   `prompts.py`'s universal structural/output-format rules (JSON schema, itinerary structure,
   SEO length gates, fabrication bans — all real, load-bearing, needed regardless of brand) from
   its Adventure-Asia-specific voice text, which this task does not attempt given the explicit
   "don't touch Python" instruction and the regression risk of doing that surgery casually.
2. **Content fix went slightly beyond the issue's literally-named 5 fields.** The issue named
   Core Idea / Customer Segment / Tone of Voice / Should Write / Forbidden Words. `writing_style`
   (style_guide) is ALSO appended by the same mechanism (`graph.py:327-328`) and its prior content
   was deeply Adventure-Asia-branded ("Adventure Asia writes to ONE reader," etc.) — left
   unchanged, it would have silently reintroduced the same problem even after `should_write` was
   fixed. Neutralized it too (kept its genuinely universal craft rules — CALM/ASSURED/SPECIFIC/
   etc — stripped the AA-specific framing). `forbidden_words` and `good_examples` were reviewed
   and found to already be brand-neutral (generic anti-AI-cliché words; illustrative South Korea
   sentences with no age/income signal) — left unchanged to minimize scope.
3. **Version history preserved, not overwritten.** Used the real `PUT /admin/brands/default`
   endpoint (creates version 2, deactivates version 1) rather than a raw SQL `UPDATE` — matches
   the established convention (migration 104 did a raw UPDATE because that was a one-time
   backfill of empty columns; this repo's own admin UI mutates via versioned INSERT). Old
   Adventure-Asia content is fully recoverable at version 1 if ever needed.
4. **Live-verify used version toggling, not two different tours.** To get a genuine before/after
   on identical inputs, the script (real ECS-internal call to `POST /admin/run-tour`) temporarily
   reactivated version 1 (old AA content), ran all 3 tours, then reactivated version 2 (new
   neutral content, the permanent end state) and re-ran the same 3 tours. This isolates the
   content change as the only variable.

## Changed

- `shared.tenant_brand_rules` row (`tenant_id=aa_internal`, `brand_name='default'`): new version 2
  — `core_idea`, `customer_segment`, `customer_mindset`, `tone_of_voice`, `should_write` (system
  prompt), `writing_style` rewritten to be niche-agnostic (family/adventure/luxury/budget), via a
  real `PUT /admin/brands/default` call. Version 1 (old, Adventure-Asia-specific) preserved,
  deactivated, in the same table's version history.
- No application code changed.
- `docs/implementation-notes/AA-535.md` (this file).

## Tradeoffs

- Leaving `prompts.py`/`graph.py` untouched means the fix cannot be "complete" by the issue's own
  stated goal (fully neutral S1 output) — traded off explicitly against the issue's own updated
  instruction to not touch that code and the real regression risk of doing that surgery without
  separate review (the hardcoded constant mixes brand voice with load-bearing structural rules —
  JSON output shape, itinerary day-count fidelity, meal/time fabrication bans, SEO length gates —
  that the rest of the pipeline depends on; naively swapping the whole constant for DB content
  risks breaking those, not just the voice).
- Neutralizing `writing_style` beyond the issue's literal field list was chosen over leaving it
  AA-branded, because leaving it would have visibly undermined the fix's own stated goal for zero
  extra effort to avoid.
