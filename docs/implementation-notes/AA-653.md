# AA-653 — clean rerun prep

## S1 DataForSEO spend (S207, 01/10/2026)

### Decisions
- Measured on Dev (`dfs_call_log`): S1 bought 3 live tasks per tour — `search_volume` for ONE
  keyword ($0.09; DFS bills per task, up to 1,000 keywords), `keywords_for_keywords` ($0.09), SERP
  ($0.002). ≈ $0.18/tour → ≈ $130 for the 736-tour rerun vs a $48 balance.
- **Reuse a tour's own `seo_context` for 365 days** (`S1_SEO_REUSE_DAYS`). One row per tour
  (`ON CONFLICT (tour_id)`), so the row itself is the long-term cache; rows in the current format are
  marked by `cache_key` ending `:ideas_v3`. Redis (7 days) stays as is — the DB row is what lasts.
- **Research cache first:** `acp_contract.search_demand` rows (bought by Segment research) whose
  keyword names a strong title place are used free; ≥5 with volume → no purchase, PAA taken too.
- **Batch:** `s1_seo_prefetch` job (S1 page runs it before the per-tour rewrites) packs ≤20 seeds per
  `keywords_for_keywords` task, same country together; ideas are assigned back per tour with the
  AA-702 relevance rule, and an idea naming another batch tour's place (and none of this tour's) is
  not taken.
- **No `search_volume` task** in the multi-seed path — the ideas task returns the seeds' volume.
- SERP stays per tour ($0.002) for PAA unless the research cache already gave PAA.

### Changed
- `process_seo()` (S1 callers only — they pass `extra_seeds`) returns the reusable row before any
  purchase (`status: "reused"`).
- Reset script keeps `:ideas_v3` seo_context rows, so future resets don't throw the cache away.

### Tradeoffs
- Prefetch is a separate job the S1 page waits for (≤15 min); if it fails or times out, rewrites
  fall back to per-tour fetching (now 2 tasks instead of 3). The Bedrock-batch S1 path
  (`s1_batch.py`) does not prefetch yet — it still benefits from reuse and the dropped task.
- Activity-only ideas can be shared between tours of the same batch (e.g. "trekking in nepal"); they
  rank below place-named ideas.

### Should know
- T2 (tenant rewrite) buys nothing since KAN-90 — it only reads the tour's `seo_context`; the long
  reuse above therefore also serves T2.
- Estimate after the change: ≈ $0.01–0.02 DFS per tour; to be measured on the Bhutan wave.
