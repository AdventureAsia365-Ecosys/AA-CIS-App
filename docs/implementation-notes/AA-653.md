# AA-653 — clean rerun prep

## S1 DataForSEO spend (S207, 01/10/2026)

### Decisions
- Measured on Dev (`dfs_call_log`): S1 bought 3 live tasks per tour — `search_volume` for ONE
  keyword ($0.09; DFS bills per task, up to 1,000 keywords), `keywords_for_keywords` ($0.09), SERP
  ($0.002). ≈ $0.18/tour → ≈ $130 for the 736-tour rerun vs a $48 balance.
- **Reuse a tour's own `seo_context` for 365 days** (`S1_SEO_REUSE_DAYS`). One row per tour
  (`ON CONFLICT (tour_id)`), so the row itself is the long-term cache; rows in the current format are
  marked by `cache_key` ending `:ideas_v3`. Redis (7 days) stays as is — the DB row is what lasts.
- **Research cache first:** `acp_contract.search_demand` rows (bought by Segment research) whose
  keyword names a strong title place are used free; ≥5 with volume → no purchase, PAA taken too.
- **Batch:** `s1_seo_prefetch` job (S1 page runs it before the per-tour rewrites) packs ≤20 seeds per
  `keywords_for_keywords` task, same country together; ideas are assigned back per tour with the
  AA-702 relevance rule, and an idea naming another batch tour's place (and none of this tour's) is
  not taken.
- **No `search_volume` task** in the multi-seed path — the ideas task returns the seeds' volume.
- SERP stays per tour ($0.002) for PAA unless the research cache already gave PAA.

### Changed
- `process_seo()` (S1 callers only — they pass `extra_seeds`) returns the reusable row before any
  purchase (`status: "reused"`).
- Reset script keeps `:ideas_v3` seo_context rows, so future resets don't throw the cache away.

### Tradeoffs
- Prefetch is a separate job the S1 page waits for (≤15 min); if it fails or times out, rewrites
  fall back to per-tour fetching (now 2 tasks instead of 3). The Bedrock-batch S1 path
  (`s1_batch.py`) does not prefetch yet — it still benefits from reuse and the dropped task.
- Activity-only ideas can be shared between tours of the same batch (e.g. "trekking in nepal"); they
  rank below place-named ideas.

### Should know
- T2 (tenant rewrite) buys nothing since KAN-90 — it only reads the tour's `seo_context`; the long
  reuse above therefore also serves T2.
- Estimate after the change: ≈ $0.01–0.02 DFS per tour; to be measured on the Bhutan wave.

## S207 part 2 — before the Bhutan wave

### Decisions
- **Reuse window 180 days, not 365.** Google Ads volumes are 12-month averages (seasonality is
  already inside), but keyword ideas and PAA drift with trends/new routes; a year is too long for
  ideas. Refresh happens only when a tour is rewritten after the window.
- **DFS Standard (queue) mode — not built.** Correction of what S207 told Nghiệp: research never used
  Standard either (AA-648 notes). After batching, the catalog needs ~75–120 ideas tasks (≈ $7–11)
  + SERP ≈ $1.5; Standard would save a few dollars at the cost of async polling that can only be
  verified with paid calls. Revisit only if the measured Bhutan cost says otherwise.
- **Budget:** `dfs / job:s1_seo_prefetch` per run $3, hard stop (set via /admin/budgets).
- **Forbidden words — whole-word match** (`forbidden_words.has_word`, plural s allowed) in validate,
  flag_fix, seo_meta and the review-queue failure derivation. On the 58 HITL versions of the 17/09
  run FORBIDDEN_WORD fired on 50; substring false hits included "depicts" (epic), "fundamental"/
  "fund" (fun), "ideal" (deal), "epicenter". Real hits remain (e.g. "explore" 43).
- **Writer prompt lists the full forbidden list** (AA core + brand). It used to list only the
  brand's words while validate checked both, so core words were written and then repaired.

## S207 part 6 — Korea trial (3 tours) and keyword relevance
- Trial on :416: 1 ideas task $0.09; approved 7.0 / 8.0, one HITL 6.0 (meta too long + optional
  language in highlights). Keywords were wrong: "village life bhutan" / "wildlife rescue center" /
  "Jeju island nightlife" for "12 Day Life & Culture Of South Korea"; "jeju island from seoul" /
  "seoul airport transfer" for "Gangwon … Tour from Seoul". Jev a1_seo: 90 verdicts, all grey (shadow).
- Causes: `acp_contract.search_demand` holds every country's research keywords (keyed by market
  only); substring matching ("life" in "wildlife"); departure city after "from" taken as a place;
  transfers not excluded.
- Fix (`seed_builder`, used by S1 prefetch, the per-tour S1 path and T2's market keywords):
  whole-word matching (`has_word`, plural/-ing/-er allowed); `foreign_country()` drops a keyword
  naming another country unless the tour title names it; `title_place_terms` ignores what follows
  "from" when the part before has place words; airport/transfer keywords dropped; "life",
  "departure" and weekdays are generic title words. `country` passed through `process_seo` /
  `fetch_all` / every `rank_keyword_ideas` call.
- A tour whose title has no place word ("Life & Culture Of South Korea") now keeps no idea rather
  than wrong ones; the writer gets the title seed.
- The 3 Korea trial tours are rewritten again in the full Korea wave (their `seo_context` rows are
  deleted first so the new rule applies).
