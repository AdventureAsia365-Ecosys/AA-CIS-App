# AA-900 — S271 lane l16: W0 S1 + T2 safety interim (root ADR 0020)

Scope: the W0 items of root ADR 0020 for S1 (A1 Master) and T2 (tenant rewrite): the elephant-riding policy, the
closed hitl exit, the server-side approve gate, the T2 interim profile, the S1 judge off the live path, and the S1
Bedrock Batch gate. No migration, no paid call. Design and evidence: root
`docs/audits/2026-11-06-S271-writing-quality-audit/` (README W0, decisions D8 / D9, `data/tour-pipeline-audit.json`,
`data/design-review.json` workflows s1 / t2).

## Decisions

- **One elephant detector** (`services/quality/elephant_policy.py`), used by the S1 brand pre-audit, the T2 policy
  hold and the AA-645 shadow-wave selection script. It matches the policy wording ("elephant riding", "riding an
  elephant", "ride an elephant", "elephant ride / trek / back", plurals and inflections, "elephant safari", "back of
  an elephant", "mount an elephant") and skips a mention negated in its clause ("no elephant riding", "without riding
  the elephants", "elephant riding is not offered", "riding-free"). It reads every customer-facing field of the page
  (name, subtitle, summary, description, highlights, itinerary, SEO title / meta, trip type) and the raw source
  (name, subtitle, summary, description, highlights, itinerary, inclusions, activities, price), never `exclusions`
  (a ride listed there is not offered) and never `seo_keywords_used` (metadata, lesson AA-738).
- **Fix pass (independent review, S271)**: the detector is now **fail safe** and **context aware**.
  - Negation only RIGHT next to the mention ("no elephant riding", "without (an) elephant ride", "we do not offer
    elephant rides", "instead of an elephant ride", "elephant riding is not offered", "-free"); marketing idioms stay
    hits ("Don't miss the elephant ride", "never forget riding an elephant", "no trip is complete without an
    elephant ride", "cannot leave without riding", "non-stop fun with elephant rides", "not to be missed"). The
    old "any no/not/never in the 25 characters before" rule dropped those offers (a miss breaks the policy; a
    false hit costs one review).
  - Bare "back" is gone: "elephant-back" / "elephantback", "elephant back" only before ride / safari / trek, "on /
    by elephant back". "bring the elephants back to the river" is not a ride.
  - "elephant safari" needs context: never when its clause puts it in a vehicle (after it: jeep / 4x4 / vehicle /
    game drive; right before it: "jeep elephant safari"); a ride when the clause has a riding cue (on / atop an
    elephant, on the back, riding); otherwise a ride unless the tour's country is in `JEEP_SAFARI_COUNTRIES`
    (Sri Lanka: Minneriya / Kaudulla / Udawalawe are jeep safaris). `scan` takes the country from the source row
    (`raw_source_from_row` now carries `country`; S1 `tour`, T2 `_PT_SQL`, the approve gate and the revalidation
    tour all have it).
  - **policy_keep is tied to the detector, not the shared code** (`elephant_policy.is_policy_only_hold`):
    manual_check, `FACT_CHECK_MANUAL_CHECK` the only brand code, AND a detector hit on the version text or the raw
    source. The LLM brand audit also emits that code (brand_standards "rare wildlife + location mismatch",
    quality_gates uncertain claims), so the code alone approved non-elephant manual_checks unedited. The approve
    gate query now joins `raw_tours` and reads the version's aa_* / seo_* text. flag_fix's policy skip uses the
    same rule.
  - **The elephant deadlock is closed** (was deferred to W3): `human_edit_gate_node` lets a manual_check held only
    by the policy pass (the human edit is the policy's review), so Edit → Re-validate → Approve works for an
    elephant tour. Every other manual_check, the score floor and the hard codes still fail it.
- **S1 keeps "as-is + human review"**: a hit adds `FACT_CHECK_MANUAL_CHECK` (manual_check → Review Queue, never
  auto-published), and `flag_fix_node` makes no LLM edit on such a tour (a source-blind whole-field rewrite could take
  the ride out). The grounding sentence repair still runs (it only drops figures the source lacks).
- **T2 `policy_hold` v0 (D8)** in `services/jobs/t2_rewrite_job.py`: a hit on the Master text the writer would read or
  on the raw row → the version is the Master prose verbatim + SEO title / meta composed by the deterministic fitters
  (the T2 "brand fields": the only fields T2 tailors for an agency's page beyond the prose; no brand claim added), the
  AA-778 em-dash rule, status `needs_review` (the agency still receives it as ready), `quality_score` NULL,
  `qa_status` escalated + `qa_auto_passed` true, `judge_breakdown.policy_hold` (admin-only) and a review row with
  `check_id = policy:elephant_riding`. No writer, judge, T3 or Jev call. `_PT_SQL` now also selects the raw src_*
  columns, inclusions, activities and price (read by the detector only; `source_tour_dict` and the writer prompt are
  unchanged).
- **hitl exit closed** (`graph.py`): every graph (A1, T2 drafts, resumed, batch seed) sends `hitl` through
  `hitl_exit` → brand_audit → grounding → revalidate (flag_fix skipped on a hitl draft: it is a source-blind LLM
  rewrite of a draft a human will see anyway). revalidate's last step is the existing chain (grounding recheck,
  final_day_guard, route guard, degraded hold). The version records `metadata.exit_path = "hitl"`.
- **Approve gate** (`services/quality/approve_gate.py`, called by `v1_pipeline.approve_review`, so the admin alias and
  the legacy `/v1/pipeline` route both have it): an unedited version must pass the auto-publish checks: score floor,
  no surviving hard code (incl. `DEGRADED_DETECTOR`), grounding ran (metadata.grounding present) and left no
  unsupported sentence, brand audit not flagged-unfixed and not manual_check. Else **409** with
  `X-Error-Code: approve_blocked` and the reasons in `detail` (the admin toast prints it). A tour held only by the
  elephant code is approvable (`policy_keep: true` in the answer): that approve is the human review the policy asks
  for. An optional body `{"override_reason": "..."}` (≥ 10 characters) approves over the blockers and appends the
  reason + blocker codes to `review_queue.reviewer_notes`. Human-edited versions keep the AA-234 re-validation gate.
- **T2 interim profile, one switch** `T2_INTERIM` (default on; `services/content_generation/t2_interim.py` documents
  every item): judge report-only (score = validate's; no feedback into the retry or the T3 revision), no Jev
  tie-break, no median-of-3 (`score_brand_fit(near_band_repeat=False)`, `T2_JUDGE_REPEAT` ignored), no revalidate
  judge, no T3 full-graph rewrite rounds (meta regenerate and sentence repair stay), status from validate + T3 hard
  codes, no master `quality_score` fallback (NULL), dashes fixed inside T3 before every check.
- **S1 judge off the live path (D9)**: `S1_JUDGE_LIVE` (default off): `judge_node` makes no call on an A1 writer-v2
  draft and the brand audit takes its deterministic pre-audit codes (what it did when the judge ran:
  `_audit_from_judge`), so no `s1_brand_audit` LLM call replaces it. A v1 draft (legacy writer) is still judged. The
  `s1_judge` stage and route stay for the Writing Lab sampler.
- **S1 Bedrock Batch gated**: `POST /admin/s1-batch/submit` answers 409 (and `submit_s1_batch` raises
  `BatchUnavailable`) while the S1 writer v2 is on, whatever the batch kill switch says: the batch seeds a v1 draft
  and the graph keeps it on v1. The legacy `/v1/pipeline/review-queue/{id}/approve` route is kept: it runs the same
  gate now, so it no longer bypasses checks.

## Changed (vs the lane brief)

- No migration: every new state fits existing columns (`metadata.exit_path`, `judge_breakdown.policy_hold`,
  `review_queue.reviewer_notes`, `quality_score` NULL).
- The T2 itinerary nudge is left as it is (the audit's W0 list names it, the lane brief does not).
- T2 status uses T3's *structural* (hard) codes; a T3 grounding-only failure stays `qa_status = escalated` + review
  row, as before (the brief says "validate + T3 hard codes").

## Tradeoffs

- The approve gate blocks most unedited Review Queue rows by design (they were queued because they failed the same
  checks). The admin page already hid Approve for most of them (`canApprove`); the override reason is API-only in
  this slice (no UI field yet).
- Older hitl versions have no `metadata.grounding`, so they need Edit → Re-validate, a Regenerate or an override.
- The elephant detector now also reads the source, so a tour whose source offers a ride goes to review even when the
  writer left the ride out. That is the policy ("mark source tours so any rewrite goes to human review").
- "elephant safari" counts as riding in context (see the fix pass above); a bare one in Sri Lanka does not. The
  country rule is one entry, not a park list: a Sri Lankan source that sells a real ride says "elephant ride" or
  "riding", which still hits. Residual: a bare "elephant safari" in a Sri Lankan tour that IS a ride is missed;
  outside Sri Lanka a bare one that is a jeep safari with no vehicle named in its clause is a false hit (one review).
- Residual of tying policy_keep to the detector: an elephant tour on which the LLM audit ALSO raised
  `FACT_CHECK_MANUAL_CHECK` for another reason reads as policy-only (one code, a hit). The reviewer of that approve
  sees the whole tour, which is the policy's review; a distinct code would remove it but touches the taxonomy,
  the review UI labels and every reader of the code (left for W3).
