# AA-789 tier 0 (S258): prevention in the writer input

Plan: root `docs/audits/2026-10-29-S257-aa789-design/PLAN.md` §2 rows 7 and 8, slice S5, decision D6 (approved by the
tech lead in S257). The two leak classes (brief recipe, naming note) are text the writer was given and copied. A leak
that is never written needs no gate, so this slice changes what the writer reads. It adds no check and changes no
gate.

## Decisions
- **Naming line.** `atom_seed.naming_line(note, display_name)` renders the card's naming note as
  `Naming: use the name 'Mörön', not 'Moron'; also written 'Murun', 'Muren'.` Only names survive. The note's prose
  ("phonetic approximation", "for an international audience", "unintended connotations", "no significant spelling
  variants", "acceptable") never reaches the seed.
  - A name is a quoted string, or a capitalised run after a naming word (`spelled`, `written`, `known as`,
    `romanised as`, `referred to as`, `seen as`, `nickname`, `name is`). A place the note only mentions ("near Luang
    Prabang", "in Bulgan Province") is not a name of this place.
  - A clause with an avoid cue (`approximation`, `avoid`, `connotation`, `incorrect`, `unfortunate` …) puts its
    names in the "not" list. A clause that explains a meaning ("'Taktsang' means 'Tiger's Lair'") adds nothing.
  - Names are compared case-folded but **not** accent-folded. `fold('Moron') == fold('Mörön')`, so an accent-folded
    comparison dropped the name to avoid.
  - Every name is in single quotes, so `trip_facts._moment_tokens` and `hygiene.build_scope_lexicon` still read the
    other spellings as names of the place (test: the moment still has `murun`, `muren` tokens).
- **Thin moment wording.** The seed note (`atom_seed.thin_note`), the T8 route digest line, the T8 system prompt
  sentence and the route-blog writer rule no longer give a count or a "one sentence" shape. A thin moment is
  "named in passing … with only what its source line states". The bans stay: never its own heading, never the hook,
  title or climax. The `Thin moment:` prefix is a parsing contract (trip_facts, claim_rules) and is kept.
- **Audience range ("seven-to-sixteen").** No change. The writer's AGES rule (AA-790 round 3) already forbids an age
  band the seed does not state; the brand pack's audience is tenant data, and the tier 1 detector is the measuring
  stick for whether this class still occurs.

## Changed

  Location block uses `naming_line`; `thin_note` keeps its signature (callers pass the fact count) and no longer
  prints it.

  (`SYSTEM_PROMPT`), `services/acp_angle_gate/route_digest.py` (`render_digest`).
- Pinned prompt hashes updated with a dated note: `test_aa771_s234_voice_contract` (`route` only; `SYSTEM_PROMPT` and
  `single` unchanged), `test_aa790_t8_round8` (`ROUND6_SYSTEM_SHA`), `test_aa790_round9_brief_grounding`

- New `tests/unit/test_aa789_tier0_writer_input.py` (synthetic notes in the shape of real cards).

## Tradeoffs
- The naming note's free text sometimes carried useful context ("a widely used region name"). The writer now gets
  names only. The admin place-card view still shows the full note; the seed is the only thing that changed.
- The extractor is regex over one short sentence the card builder writes. A note in an unusual shape can yield a
  shorter list of names (never prose). Worst case: `Naming: use the name 'X'.`
- "Named in passing" is softer than "one sentence at most". The gates that police thin moments (`trip_facts`
  thin heading / coda findings) are unchanged, so a long thin-moment passage is still caught.
- The prompt register says a prompt change needs an eval run ID. All LLM routes are blocked on acc3 today, so there
  is none. D6 accepted measuring this on the next paid T-round we run anyway, counting tier 1 `sa:` fires for
  classes 7 and 8 before and after.

## Should know
- The writer prompt version (`WRITER_PROMPT_VERSION`, sha8 of `SYSTEM_PROMPT`) does not change: the edited rule is
  in the route-blog user prompt. The T8 angle system prompt does change.
- Stored seeds are rebuilt per piece, so the new lines apply from the first piece written after deploy. No
  migration, no backfill.
