# AA-117 — acp_run_context Pydantic guard + atomic jsonb_set

## Decisions
- `RunContext` schema lives in `api/schemas/run_context.py` — importable by both FastAPI routers
  and Lambda handlers (no circular deps; pure Pydantic, no DB logic inside schema).
- `RunContextDB` helper (read/write) in `api/services/run_context_db.py` uses asyncpg for FastAPI
  paths and a separate psycopg2 variant for the Lambda (services/acp_s3) — the Lambda cannot import
  asyncpg; the two adapters share the same Pydantic schema.
- Lambda (services/acp_s3) gets its own thin psycopg2-based write helper rather than importing
  from api/ — keeps Lambda dependency surface minimal.
- `RunContextValidationError` is a typed exception that carries `missing_path` so callers can
  surface it to HITL without re-parsing the message.
- Atomic write uses `jsonb_set(context_col, ARRAY['stage_key'], payload::jsonb, true)` where
  the entire column is a JSONB object keyed by stage name. This maps cleanly to the existing
  per-column schema (one column = one stage key). We use individual column updates for now
  (matching existing schema) and per-column `jsonb_set` is the atomic primitive.
- Actually: the existing schema has DISCRETE columns (s1_keywords_used, brand_brief, s2_*, s3_*),
  NOT a single `context` JSONB column. The atomic write helper therefore targets individual columns
  via `jsonb_set` where applicable, or plain column assignment for scalar fields (like s2_confidence_score).
  The "stage" concept maps to a named set of columns — we use per-stage UPDATE statements that only
  touch that stage's columns.

## Changed
- `services/acp/s2/tools/synthesize.py`: replaced full INSERT/ON CONFLICT upsert with typed
  `write_run_context_stage_async(pool, run_id, "s2", payload)`.
- `services/acp_s3/handler.py`: replaced full `UPDATE SET s3_* = %s` with typed
  `write_run_context_stage_sync(conn, run_id, "s3", payload)`.
- `api/routers/v1_acp.py`: `get_run_context` now calls `get_run_context_validated` which validates
  on load and raises `RunContextValidationError` instead of returning silent None.
- `services/acp/s2/router.py`: `_handle_gate1` now calls `get_run_context_validated` to assert
  `s2_confidence_score` is present before evaluating Gate 1.

## Tradeoffs
- Kept psycopg2 in Lambda vs asyncpg in ECS — adding asyncpg to Lambda would bloat the layer.
  Duplication is justified by deployment boundary.
- Pydantic schema validates stage payloads on write too — minor overhead but prevents silent
  schema drift between writers.
- Did NOT migrate to a single `context` JSONB column (would require migration + all callers rewrite).
  AA-117 targets NULL-propagation and race condition, not schema redesign.

## Should know
- `write_run_context_stage_async` uses asyncpg `fetch` (not `execute`) to return the updated row,
  letting callers verify the write in tests.
- The concurrent-write test exercises two asyncio tasks writing different stages simultaneously;
  the atomicity guarantee comes from each UPDATE targeting disjoint columns (no WHERE clause
  race on unrelated columns).
- `get_run_context_validated` accepts a `require_stages` list — callers assert which upstream
  stages they need before proceeding.
