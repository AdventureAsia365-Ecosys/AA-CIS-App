# AA-1000 — T10 tier 2: LLM adjudicator for the forms seed alignment cannot reach

Plan: root `docs/audits/2026-10-29-S257-aa789-design/PLAN.md` (tier 2, §0, §2 "Tier 2 residual" column, §3, §4 P3/P4).
Tier 1 (AA-789, CIS #1152): `services/acp_content_writing/seed_align/` (`checks`, `seed_graph`, `modes`, `nlp`).

## Decisions

- **Module place:** `services/acp_content_writing/seed_align/adjudicate.py`, next to tier 1, because it reads tier 1's
  run record and reuses `modes.apply` / the `sa:` routing. Like tier 1's candidate layer it imports nothing from
  `quality_gates` (invariant I1; a test pins it).
- **Classes (four, the issue's list):** `naming_note_leak` (paraphrased naming notes, under F13_leak),
  `paraphrased_repeat` (subjectless / implicit-subject repeats, under F13_repeat), `faq_non_answer` (open
  WHAT / WHY / HOW answers, under F13_repeat), `scopeless_superlative` (hype such as "hard to overstate", under
  F18_rarity). No new gate (S246 freeze).
- **"Triggered but skipped" made concrete.** Tier 1 records only what it found, not what it abstained on, so tier 2
  re-reads the piece with a deterministic, spaCy-free trigger per class (regex + `SeedGraph`), then drops every
  sentence tier 1 already has a candidate on. A trigger needs tier 1's run to be `status == "ok"` this attempt; for
  the two classes tier 1 has a check for (naming note, superlative) it also needs tier 1 to have run that class
  (mode not off). No tier-1 run → no trigger → no call.
- **Finding text:** `sa:t2.<class>: <reason>: '<sentence>'`. The `sa:` prefix routes it through tier 1's existing
  never-hold path (`quality_gates.never_holds` → `seed_align.finding_may_hold`): the class `t2.<class>` is never in
  `HOLD_CAPABLE`, so a tier-2 finding can never hold, whatever the env says. The quoted-sentence shape is what
  `sentence_repair.plan` already parses for these gates, so the repair is the gate's normal one-sentence repair.
- **Reason text is ours, not the model's:** the live finding carries a fixed per-class reason (with "or cut it"),
  never model text, so a model reply cannot steer the repair prompt.
- **Mode env:** `T10_ADJ_MODE` (global) and `T10_ADJ_MODE_<CLASS>`; values `off | shadow | repair`, default off.
  Anything else (including `hold`) reads as off.
- **Stage:** `t10_adjudicate`, role `judge` (it scores the writer's output, ADR 0008; a judge stage must be
  non-Anthropic). Route: `gpt-6-luna` (acc3 Bedrock, cheapest catalog model, $0.1 / $0.5 per Mtok) →
  `gpt-5.6-luna` (acc3) → `gpt-6-luna-openai` (last resort, S235 rule). No shadow. SAFE_DEFAULTS mirrors the row.
- **Migration 309** seeds the row (307 and 308 are taken by other lanes). It inserts one row into an existing table,
  so it is additive but NOT lint-expand (the expand lint allows INSERT only into a table the file creates): no
  `-- migrate: expand` header, a person applies it through DB Migrate. It is optional: SAFE_DEFAULTS carries the same
  route, so the code works before it lands.

- **One sentence per attempt, and never the only sentence of an FAQ answer.** Repair mode puts at most one verified
  finding live per attempt (the first in text order). A finding on the only sentence of an FAQ answer is adjudicated
  and recorded (`live_blocked: only_sentence_of_faq_answer`) but never goes live: a repair that fails is cut in code on
  the last attempt, and an emptied answer could drop the FAQ under `FAQ_MIN_PAIRS`, which F16_faq holds on. That keeps
  "tier 2 never holds" true end to end, not only for its own finding.
- **A $0 replay calls nothing.** `run_quality_gates(f9_results=…)` (the writing-memory replay) records
  `status: "replay"` and makes no call, whatever the env.
- **Review (S259): the cheaper judge route stays, as a documented exception.** The AA-714 guard pins every judge
  stage to GPT-5.6 Luna → GPT-6 Luna → GPT-6 Luna on the OpenAI API. `t10_adjudicate` keeps GPT-6 Luna first (about
  half the price: $0.10 / $0.50 vs $0.20 / $1.20 per Mtok) because it is a short span check that never holds a
  piece. `test_aa714_judge_safe_defaults.CHEAP_JUDGES` lists it with its reason; its own tests pin the same rules as
  every judge (Bedrock acc3 first, the OpenAI API only last, no legacy key, no shadow, non-Anthropic) and that a
  migration seeds the same route as SAFE_DEFAULTS.
- **Review (S259): a tier-2-only failure is left out of the AA-528 regression guard.** Tier 2 is re-asked every
  attempt and defers triggers past MAX_ITEMS, so its finding can first appear on attempt 2. Counted as a regression,
  it would revert a rewrite that fixed F1 / F9 back to the attempt with that product-truth failure (which can then
  hold). `adjudicate.tier2_only_failure(g)` is true when a result fails only on `sa:t2.` findings (no tier-1 `sa:`
  finding, own findings did not block before `apply`); `service._regression_failures` drops such results, and only
  the guard uses it. `_blocking_failures` is unchanged (the writing-memory repair hints still see the gate). Tier 1
  keeps its rule (an `sa:` finding new on a repaired attempt is a regression, `test_aa789_seed_align`): it is
  deterministic, so a new tier-1 finding means the rewrite introduced it. Deferring past MAX_ITEMS is kept: with the
  guard fix a deferred finding just gets its sentence repair on the next attempt.
- **Fail open everywhere:** trigger error → `error`; model raise, unusable or partial reply → `error` (a billed
  unusable reply writes one `billed_unusable` row, AA-927); no reply in 60 s → `timeout` (the call runs on in a worker
  thread with a copy of the contextvars, so its row still lands with the job's tenant). The ledger is unchanged in all.

## Tradeoffs

- **Re-deriving triggers vs. changing tier 1.** Making tier 1 record its abstentions would touch every check; a
  separate spaCy-free trigger pass is cheaper to own and cannot change tier 1's output. The cost: tier 2's notion of
  "triggered" is its own lexicon, not tier 1's parse.
- **Trigger breadth** ($0 dry run on the AA-789 eval set, 405 items, local, counts only): 42 items trigger
  (by class: hype 19, FAQ 16, repeat 4, naming 4; 1 of 181 general clean items). Of the residual defects tier 1 misses:
  hype 12/13, naming 1/1, repeat 3/13, FAQ 3/14 (the other FAQ misses are yes-no / how-long / who / when questions,
  out of scope). Many clean hard negatives trigger too (FAQ 8, hype 6, naming 3, repeat 3): precision is the model's
  and the quote check's job, measured by the calibration run. Worst-case cost of one full eval pass: $0.09.
- **Repeat trigger** needs an implicit subject or a definite opener whose noun the earlier sentence has, ≥ 3 shared
  content words (≥ 40% of the shorter), the same section, and a seed line both sentences draw on (the seed anchor the
  quote check needs). Repeats with a named subject far apart stay tier 1 S6's job (embeddings).
- **No sticky verdicts / ClaimMemory yet** (plan B): each attempt re-asks. Bounded: ≤ 3 calls a piece.
- **Cheap judge route vs. the standard one:** the standard judge route would roughly double the per-call price for
  a check that never holds; the exception costs one entry in the AA-714 guard.
- **Guard exclusion is tier-2 only:** widening it to every `sa:` finding would change tier 1's reviewed behaviour.
- **Role judge** (not validate): it scores the writer's text, so ADR 0008 makes it a non-Anthropic judge stage.
- **Reasons are fixed text**, so the repair gets a generic instruction per class, not the model's diagnosis.

## Should know

- Cost: default off = $0. On, it bills the
  existing acc3 Bedrock account (GPT-6 Luna, $0.10 / $0.50 per Mtok; acc3 is now paid from its AWS Lift credit, then

  it (SAFE_DEFAULTS). `REQUIRED_CIS_SCHEMA` is not raised.
- Turning it on: worker env `T10_ADJ_MODE=shadow` (plus tier 1 at least `shadow`: tier 2 reads tier 1's record and
  makes no call when tier 1 is off or has no spaCy). `repair` only after the calibration run and the `t9_repair`
  route work (the repair itself is a `t9_repair` call).

  under its raw key, like `t9_faq_answer_fit`.
