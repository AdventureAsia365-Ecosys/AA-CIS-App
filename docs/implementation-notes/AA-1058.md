# AA-1058 — Cost attribution on every ledger row

Lane l8-cost-attribution, session S274 (Claude Code). Source: S273 system picture §4 and §5 item 7.

## Decisions

- **No migration.** Every column already exists (db-schema-reference.md): `shared.llm_call_log.tour_id`,
  `content_piece_id`, `job_id`, `prompt_version`, `app`; `shared.dfs_call_log.stage`, `app`;
  `silver_aa_internal.generated_content.prompt_version`. The gaps were in the writers.
- **One context, bound at the entry point.** `call_log.bind_attribution(tour_id=, content_piece_id=)` (a ContextVar,
  same propagation as `bind_job`: tasks, `asyncio.to_thread`, LangGraph executors, the AA-927 background write
  thread) plus the decorator `@attributed(...)` for an entry point whose arguments name the object. `record_call`,
  `record_call_with_pool` and `record_calls` fill a missing `tour_id` / `content_piece_id` from it; an explicit id
  always wins. Binders:
  - the job worker, from the payload (`tour_id`; `piece_id` / `content_piece_id`), next to `bind_job` — covers
    `s1_rewrite`, `a3_atomize`, tour-scope `recompute`, `t9_write`;
  - `_execute_run_tour` (S1: job, sync `/admin/run-tour`, Bedrock batch ingest), `_revalidate_tour`,
    `run_a3_atomize`, `run_write_background` (T9 writer + T10 gates of one piece), and the `a1_seo` Jev of the SEO
    prefetch (one prefetch job covers many tours, so it binds per idea task).
- **Rules live in `shared/llm_client/attribution.py`** (`RULES`, `BINDERS`, `BOUND_MODULES`): s1_ / a1_ / t5_ /
  a3_atomize → tour_id; t9_ / t10_ → content_piece_id; the A3 recompute Jev stages (a3_demand, a3_question_scope,
  a3_question_landing, a3_segment_type, a3_segment_match) → job_id.
- **Guard** `tests/unit/test_aa1058_cost_attribution.py`: an AST scan of every ledger write (`record_call*`,
  `record_unusable*`, `record_billed_failure*`, `decide` / `decide_sync`) in api/, services/, shared/ resolves the stage
  (literal, module constant, local assignment, parameter default) and fails when a ruled stage's call neither passes
  its key nor sits in a module registered in `BOUND_MODULES`; each `BINDERS` entry must still bind its key (AST); a
  `BOUND_MODULES` entry with no ruled write any more is stale and fails too.
- **Runtime check logs, never refuses.** A ruled tour / piece row written without its key logs
  `llm_call_log_attribution_missing` (the call was billed; the row is kept). job_id is guard-only: the same stages run
  outside a job (sync admin endpoints) where NULL is right.
- **Mandatory stage and app.** LLM: an empty stage is written `unattributed` and logged (`stage` is NOT NULL; the row
  of a billed call must survive a caller bug); app was already defaulted to `cis` by ledger v2 (the 187,773 no-app rows
  of the S273 picture predate migration 319: the 30-day cis-app cost equals the November total). DFS: the caller's
  stage, else the bound job kind (`capacity.current_kind()`, bound by the worker), else `dfs_balance` for the free
  balance read, else `unattributed` (logged); app defaults to `cis` also for an empty string.
- **DFS stage at the sites this lane owns**: `s1_seo` (S1 SEO fetch, live + cache hit), `s1_seo_prefetch`,
  `a3_question_topup`. `segment_research` sites are left to the job-kind fallback: lane AA-1055 buy side rewrites
  those files and already passes `a3_search_demand`.
- **S1 prompt_version.** The 1,219 "none" were `generated_content.prompt_version`, a column the S1 INSERT never wrote
  (only `metadata.prompt_version`). Now written: the writer stage's registered version (`prompt_registry.version_for`,
  the value the gateway puts on the writer's ledger row), else the writer's AA-289 prompt hash. The writer's ledger row
  gets the same hash as a fallback when the register has none (`billed_fields(resp, prompt_version=...)`), so a version
  and its writer row always share one value. The ledger's full `prompt_hash` still joins on `left(prompt_hash, 8)`.
- **Eval rows stay off production attribution**: nothing is filled while `bind_eval_stage` is bound (the AA-729 / WM-19
  relabel already nulls tenant / piece / request).

## Tradeoffs

- Binding at entry points instead of threading ids through ~40 call sites: far smaller diff, and new call sites under
  a binder are covered automatically. The cost is indirection, which the guard and the runtime log make visible.
- `BOUND_MODULES` is a registry a developer must update for a new module; the alternative (proving statically that a
  module only runs below a binder) is not tractable. The stale-entry test keeps the list honest.
- Worker binds from the payload generically: a kind whose payload `tour_id` is not the tour it produces would
  misattribute. Today every payload `tour_id` is the tour the job works on.
- `shared.job.cost_usd` stays the handler-reported (non-LLM) cost by design (AA-687): the Jobs page sums the ledger by
  job_id on read (`queue.LLM_COST_SQL`). The S273 "0 USD for writing kinds" read that column, not the ledger.
