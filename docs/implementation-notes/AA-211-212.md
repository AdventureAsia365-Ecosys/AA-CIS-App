# AA-211 + AA-212 — Export gate hardening + HITL review_queue re-wire

Branch: `feature/aa-211-212-export-gate-hitl-rewire` (from develop)

## Decisions
- **No migration.** S69 diagnostic confirmed `review_queue` schema is complete and the
  Step Functions columns (`step_fn_task_token`, `step_fn_execution_arn`) are already nullable.
- **Atomic-claim over gc.status guard.** `process_export` never advances
  `generated_content.status` past `'approved'` (verified READ 7c), so a "guard on
  gc.status='published'" is impossible without adding that write. Instead `approve_review`
  atomic-claims the `review_queue` row (`WHERE review_status='pending' ... RETURNING`) so a
  double-click claims nothing on the second call → no double export. This matters because
  `process_export` re-fires `acp.s1.completed` EventBridge + re-writes the S3 manifest on the
  batch-completing version with NO downstream dedup key (verified READ 6/7).

## Changed
- **CHANGE 1 (AA-211), admin_pipeline.py:** replaced the bare `quality_score >= 7.0`
  publishable decision with an audit-aware gate. Did NOT touch the 7.0 floor. Export block left
  unchanged — auto-approve path stays one-call-per-version.
- **CHANGE 2 (AA-212), admin_pipeline.py:** in the not-publishable (`pending`) branch, enqueue a
  `review_queue` row. Used `INSERT ... SELECT ... WHERE NOT EXISTS` (idempotent) rather than
  `ON CONFLICT` — no unique constraint on `generated_content_id` was verified, so `ON CONFLICT`
  would raise at runtime. SF columns left NULL (marks the admin/direct-export path). Wrapped in
  try/except → logger.warning so enqueue failure never breaks the run.
- **CHANGE 3 (AA-212), v1_pipeline.py:** `approve_review` + `reject_review` re-wired to a single
  atomic-claim `UPDATE ... WHERE review_status='pending' RETURNING`. No claim → 409. approve
  branches on the *claimed* token: NULL → `process_export(generated_content_id)`, non-NULL →
  legacy `send_task_success`. Token branch uses `is not None` (not falsy) so an empty-string
  token stays on the SF path. reject never exports.
- **Refactor for testability (CHANGE 4):** extracted the gate and enqueue into module-level
  helpers `_is_publishable(result)`, `_build_failure_summary(result)`, `_enqueue_review(conn,...)`
  in admin_pipeline.py. Tests call these same helpers + the real v1_pipeline endpoints — no
  re-implemented copies (S67 lesson). Single source of truth for both prod and tests.

## Tests
- `tests/unit/test_aa211_212_gate_hitl.py` — 14 tests. Gate truth table (8 cases incl. Terra
  flagged+fixed→publish and score 6.99→block); enqueue one-row + columns + NULL SF cols +
  re-run idempotency (in-memory fake conn emulating NOT EXISTS); approve double-fire guard
  (process_export call_count==1 across double-click, 409 on second); token→SFN path; reject
  claim/409/no-export and token→send_task_failure.
- Full `tests/unit/` suite: 346 passed.

## Tradeoffs
- Gate mirrors catalog-readiness semantics (manual_check blocks; flagged blocks only if the
  fix pass did not repair). A flagged tour that `fix_pass_applied=True` (Terra case) is allowed
  to publish — trusting the repair pass rather than forcing manual review.

## Should know
- `process_export` is NOT idempotent against EventBridge re-fire; the safety comes entirely
  from the approve atomic-claim, not from the export function.
