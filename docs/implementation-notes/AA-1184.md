# AA-1184 — Calendar tab on Platform › Compliance readiness (CIS part)

Session S297, lane l6-calendar. The calendar itself, its guard, the `.ics` feed and the collector check live in the
root repo (AA-Ecosys `docs/ops/calendar.yaml`, `tools/ops/ops_calendar.py`, root `docs/implementation-notes/AA-1184.md`).

## What this PR adds

- `api/services/compliance_calendar.py`: shapes the newest evidence row of the check `ops_calendar_overdue` (the same
  read as the Overview tab: a sealed row first) into the tab's answer; adds the current state of each compliance check
  a calendar line is watched by.
- `GET /admin/platform/compliance/calendar` (compliance.read, administrator only; the GET ingests the published file
  like the other tabs, never the live sources; no write under "view as").
- `frontend/app/admin/platform/compliance/CalendarTab.tsx` + `calendar.messages.ts` (EN + VI): check state, KPI tiles,
  a filter (needs attention / every dated line / all, `?cal=`), the table. Helpers in `lib/compliance.ts`.
- Snapshots refreshed: `docs/api/openapi.json`, the staff route policy, the role × route matrix.

## Decisions

- **No table, no migration, no setting.** The collector computes pass/fail from the calendar's own due dates (overdue =
  past the due date; per-line `warn_days` live in the calendar file). CIS only displays; the check turns red through the
  existing evidence path (Overview › attention lists a failing check whether or not a control maps it).
- **Row format** is the root tool's compact `"id|kind|state|due|last|owner|title|check|extra|note"` string (the 8 KiB
  detail CHECK of compliance.evidence). `parse_row` drops a malformed row instead of failing the page.
- **Line states are the collector's for its run day**; when the evidence goes stale the check itself shows stale, and
  the tab prints "as of <day>".
- **Titles stay English** (they come from the calendar file); UI labels are translated.
