# AA-843 — Legacy writer chain starts at the satellite (acc2-native tier off by default)

## Decisions
- **Switch = env var `LLM_LEGACY_ACC2_NATIVE`, default off.** Values `1`/`true`/`on`/`yes`
  (case-insensitive) turn the acc2-native tiers (T1 Sonnet, T2 Haiku via `_call_bedrock`) back on, in
  their old place at the head of each tier. Chosen over a catalog/settings column because it needs no
  migration, no admin UI and no DB read on the hot path; acc2 gaining Anthropic model access is a rare,
  deliberate infra event, so a task-definition env change (one deploy) is the right weight for it.
- The flag is read on every call (`legacy_acc2_native_enabled()`), not frozen at import, so tests can
  set it with `monkeypatch.setenv` and nothing caches a stale value.
- Log event names are unchanged (`t1_5a_satellite_used`, `t2_5a_satellite_used`, `*_5b_*`, and
  `t1_failed_trying_t2` / `t2_failed_trying_t2_5a` when the flag is on). Only the `reason=` field on the
  satellite events changes when the flag is off ("acc2 native off (AA-843)" instead of "acc2 T1 failed"),
  so a log reader is not told acc2 failed when it was never called.
- Admin "via" label for `haiku`/`sonnet` (Settings › LLM Models) follows the flag:
  `Bedrock acc3 → acc1` by default, `Bedrock acc2 → acc3 → acc1` when it is on.

## Changed
- `shared/llm_client/client.py`: `_legacy_chain` skips both `_call_bedrock` attempts unless the flag is
  on. Order with the flag off: Sonnet: primary satellite → other satellite → (Haiku) primary satellite →
  other satellite → T3 gate. Haiku: primary satellite → other satellite → T3 gate.
  `_call_route`, `_call_catalog_model`, the T3 GPT-4.1 gate and shadow code are untouched.
- `api/routers/admin_llm_ops.py`: legacy via label computed from the flag.
- `CONTEXT.md`: the "acc2 → acc3 → acc1" sentence now says the legacy chain starts at the satellite.

## Tradeoffs
- Keeping `_call_bedrock` (instead of deleting it) keeps ~80 lines of code that never run by default. It
  is the only way back if acc2 ever gains model access (issue scope item 1 allows either), and its
  streaming tests (AA-224) still cover it.
- Env var vs catalog switch: an env var cannot be flipped from admin. Accepted (see Decisions).

## Should know
- `llm_call_log` semantics: unchanged. Satellite responses already carried `satellite_account` and
  `fallback_used = (tier == "sonnet")` for the Haiku tiers; the acc2-native path never set
  `satellite_account`. No caller depends on the acc2 attempt (no metric filter or alarm matches
  `t1_failed_trying_t2` / `t2_failed_trying_t2_5a`; the only log metric filters on `/ecs/aa-cis-dev`
  are the `*_write_failed` ones in AA-CIS-Infra `accounts/aa365/observability.tf`). The
  `bedrock_satellite.py` TODO (CloudWatch metric `t3_fallback_used`) is independent of the acc2 tier.
- Live streaming: one `stream_sink.emit_restart` fewer per call (the acc2 attempt used to emit a restart
  before failing); the satellite path still streams through `on_delta`.

## Expected latency effect (evidence, read-only, 15/10/2026)
Source: `aws logs filter-log-events` on `/ecs/aa-cis-dev`, stream prefix `worker/`, last 3 days
(28,311 events, 79 streams). For each acc2 failure line, the gap from the previous log line in the
same stream to the failure line is an upper bound of the wasted acc2 attempt (it also includes the
local prompt build between the previous line and the call).

| Legacy tier | acc2 failures | gap p50 | gap p90 | gap p99 | satellite `latency_ms` p50 / p90 |
| -- | -- | -- | -- | -- | -- |
| Haiku (`t2_failed_trying_t2_5a`) | 408 | 113 ms | 435 ms | 1.6 s | 1.19 s / 3.13 s |
| Sonnet (`t1_failed_trying_t2`) | 739 | 125 ms | 429 ms | (noisy, parallel calls) | 5.37 s / 31.3 s |

One worked trace (worker stream f71c3559…, 14:25:54 UTC, a `t2_rewrite` job): previous line
`seo_meta_fit_unresolved` at .105 → `t2_failed_trying_t2_5a` at .228 (123 ms) → `t2_5a_satellite_used`
at 55.076 (848 ms, matching the satellite's own `latency_ms=845.8`). So the gap between the failure
and `*_satellite_used` is the satellite call itself, not waste; the waste is the ~0.1–0.2 s before
the failure line.

Expected: each legacy writer call is ~0.1 s faster at the median (up to ~0.4 s at p90): about 9% of
a median Haiku call (flag fix, itinerary nudge, short repairs) and about 2% of a median Sonnet call.
Log volume drops by ~2,400 warning lines a week. Cost is unchanged (a ValidationException is not
billed).
