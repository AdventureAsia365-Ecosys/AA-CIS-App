# AA-1006 — CIS admin pages on the kit (S6b rest): suppressions → 0, `adminUi.tsx` deleted (S263)

The rest of slice S6b of AA-994 (root ADR 0016; S6b PR1 / PR2 in `AA-994.md`). Moves every remaining CIS admin page
off the legacy `adminUi.tsx` and off hand-made markup onto kit components, so the kit lint rules pass with an empty
`frontend/eslint-suppressions.json`, then deletes `adminUi.tsx`. No data flow, route or API change; English copy.

## Decisions

- **Form controls by codemod** (221 uses, 47 files): `<input>` → `Input`, `<select>` → `Select`, `<textarea>` →
  `Textarea`, `<input type="checkbox|radio">` → `Checkbox` / `Radio` (the `type` attribute dropped), hidden and file
  inputs left alone (the rule allows them). Every native prop passes through the kit controls, so state and handlers
  are untouched. The page's own `style` still merges last, so a control keeps its width and padding; the kit adds the
  40px height, the radius-8 box and the focus / invalid / disabled states. Filter-row controls that were 32–34px
  take `size="sm"` (36px, the FilterBar height) where the page was edited by hand.
- **`KX` (CIS-local, `app/_kit/adminTokens.ts`, barrel export)** names the few `--aa-*` colours the admin draws and
  `K` does not: `onSolid`, `onAccent`, `onDark`, `sideBg`, `sidePanel`, `link`, `neutralBorder`, `amberDeep`,
  `amberBorder`, `successBorder`. ADR 0016 decision 3 (a): an app extends the kit through its barrel; the values stay
  in `core/tokens.css`. Not a core change, so no kit sync PR in Booking / Partner / TripPlanner. Promotion rule: when
  a second app needs one, it moves into core `K`.
- **Pagination** (`_components/Pagination.tsx`): previous / next are kit `IconButton`s (32px outline); page numbers
  are kit `Button size="sm"` (`primary` for the current page with `aria-current="page"`, `ghost` for the others).
- **Writing reason chips**: the hand-made radio group becomes the kit `SegmentedControl appearance="chips" size="sm"`
  (same role="radiogroup" / "radio" + aria-checked the UI smoke asserts; arrow keys from the kit).
- **AuditTable** (`_components/auditPanels.tsx`, atom-curation 01-05) is drawn by the kit `DataTable`: a sortable
  column sorts by its `sortValue` (header click, `aria-sort`; empty values last both ways as before), the per-column
  filters are kit `Input`s in the table toolbar (they were a second header row), no global search, no pager (the rows
  are the page already loaded). The local `EmptyState` / `ErrorState` cards render in a kit `Section`.
- **Social Content sub-nav**: the `<style>` media query on `.a527-*` classes (no `className` in the inline preset)
  becomes `useMediaQuery("(max-width: 980px)")`; `SocialContentSplit` is the content split the four Social Content
  pages share (row on desktop, a stretched column below 980px — the S241 AA-863 fix kept). The sub-nav is a
  `<nav data-testid="social-content-subnav">`; the 01-05 tab buttons are kit `ListButton`s with `aria-current`.
  The `aa568-content-trace` E2E spec selects the test id instead of the old class.
- **CompareModal**: the tab row is kit `Tabs variant="underline"`, the close button a kit `IconButton`; the loading
  flag is derived from which id list the loaded details belong to (no setState in the effect body).

- **Tables → kit `DataTable`** everywhere (overview pipeline / cost per app / Booking weeks / quota outliers, job kinds
  and queue, photos countries, SEO tabs, CRM jobs, Content Trace, platform stats, S1 rewrite tour list, Cost
  Operations tables, tour detail history and SEO keywords). Rules used throughout: `searchable={false}`,
  `paginate={false}` (every row shows, as before; a page that paged keeps its own pager), `compact`, columns sort by
  the same value the page sorted by (`accessorFn`), numbers `meta.align: "right"`. A table that only shows the rows
  the page already holds keeps the page's order until a header is clicked.
- **Overview heads with a source hint** (`opsUi.hintColumn`): the head renders label + `SourceHint`; the column `id`
  is the label text, because the kit table labels each value with the column id on a phone card (a function head
  cannot be shown there). The `ops-cost-table` / `ops-booking-weeks` / `overview-pipeline-table` test ids sit on a
  wrapper `<div>`; `ops-cost-total` and `ops-cost-row-<key>` sit on the first cell's content.
- **Row accordions → kit `Drawer`** (Content Trace detail, platform-stats escalation detail): DataTable has no
  expandable rows; a click on the row opens the same detail in the kit slide-over. Cost per app keeps its expand
  (the services are extra lines in the table, with a `LinkButton` toggle in the app cell).
- **Selected-row highlight dropped** where DataTable cannot draw it (photos countries, S1 rewrite list, tour history):
  the state is still visible (the Tours tab names the country; checkboxes; the version pill).
- **Loads without setState in an effect body**: react-query (`useQuery`) for Content Trace and platform stats; a
  promise chain (state set only in `.then`) where the page keeps its own loader (S1 rewrite, brand editor); a
  derived `loading` from "the key the data belongs to" (CompareModal, SEO keywords); remount by key (tour detail);
  "adjust state during render" for a prop sync (EditableField).
- **Overlays**: hand-made confirm / list overlays become kit `Modal` (S1 run confirm, Cost Ops fallback calls), the
  live writer panel a kit `Drawer`. The tour detail slide-over (70vw, tabs in its header) stays its own panel with
  `KX.scrim` / `KX.shadowLg`: the kit Drawer takes a pixel width and a plain title.
- **Master Content** (`admin/master-content/page.tsx`, the last page): the tour list is one kit `DataTable` with
  server sorting (`sorting` + `onSortingChange` + `manualSorting` drive the page's own `sortKey` / `sortDir`, header
  click = the old `toggleSort`, page reset to 1) and the page's own pager; it replaces both the desktop table and the
  AA-752 hand-made phone card list (the kit card per row on a phone). Row actions are one `ButtonGroup` of kit
  Buttons (View, Versions, Set inactive / active, Retire, Trash, Restore — same handlers and RBAC checks). The
  inline version expansion under a row becomes a kit `Drawer` (1040px, full width on a phone) with the versions
  `DataTable`, the pick-two compare, DOCX, Promote and the Jobs link. The master-status tab row is kit `Tabs
  variant="underline"` (the Trashed count as the tab count). DataForSEO ideas in the version compare: a `DataTable`
  on the panel's own sort. `StatCard` → `KpiTile` (`valueTone` from the score band). The four compare panel
  backgrounds are the panel colour at 6% (`alpha`), not four fixed panel tokens. `KX.toastBg` added for the page toast.
- **adminUi codemod** (kept outside the repo, like S6b PR2): `A.*` → `K.*` (PR1 key map), `SLabel` → `Eyebrow`,
  `Badge color` → `tone` (also the `Record<string, "green"|…>` maps → `Record<string, Tone>`), `LoadingScreen msg` →
  `message`, `Card` → `Section` (style split: box keys to `style`, padding / layout to `bodyStyle`, `padding: 0` →
  `padded={false}`), `StatCard` → `KpiTile` (`sub` → `hint`, `accent` → `hintTone`). Tables, `Card dark` and dynamic
  accents by hand (`Card dark` → a Section on `KX.sideBg` with on-dark text).

## Changed (visible)

- Form controls: kit height (40px, 36px in filter rows), radius 8, accent focus border.
- Pager: pill page numbers (current page gold), outline icon buttons for previous / next.
- Reason chips: the selected chip is the kit chip look (gold border and tint) instead of a solid gold fill.
- Atom-curation tables: kit table chrome (bordered box, Columns menu, phone cards); column filters sit above the
  table, each with its column name as the label.
- Every converted table: kit chrome; on a phone a card per row instead of a sideways-scrolling table (the overview
  cards included: S243 kept every column on a phone by scrolling; the kit card shows every column as a label/value).
- Content Trace and platform-stats details open in a slide-over instead of under the row.
- Status chips (jobs), channel pills (platform stats), day chips (Tenant 360), country chips (AA content): kit chips.
- Master Content: a tour's versions open in a slide-over instead of under the row; the trashed-row red tint is gone
  (the name fades and the Trashed badge stays); amber notes in the version compare use one amber tint (were three
  near-identical amber backgrounds).

## Tradeoffs

- `KX` keeps a handful of raw token names in one CIS-local file instead of growing core `K`: a core change needs three
  sync PRs for names only CIS uses today.

## Should know

- Suppressions: 627 on `main` at branch time (the issue's 659 was the count when AA-1006 was filed; S6b PR1/PR2 and
  later merges took some off) → **0**. `frontend/eslint-suppressions.json` is `{}`; `npx eslint
  --prune-suppressions` reports 0 errors (11 warnings, all pre-existing non-kit rules). The growth check
  (`check-kit-copy.mjs --suppressions`) passes: 627 → 0.
- `adminUi.tsx` is deleted. The `no-legacy-kit` rule keeps its entry for the path (core `eslint-kit.mjs`), so a
  re-created file is refused; core comments that name the old file are left (a core edit needs a kit sync PR in
  three apps for a comment).
- `admin/ai-gateway/**` had no suppressions on `main`, so nothing is left over for the lane that edits
  `ProvidersTab.tsx`; that lane must keep the file at zero kit violations (CI now fails on any).
- Locally `tsc --noEmit` only reports the missing `react-markdown` / `remark-gfm` / `mermaid` / `dompurify` modules in
  `MarkdownView.tsx` / `MermaidDiagram.tsx` (the shared `node_modules` predates those deps); no error in a changed
  file. `next build` was left to CI (Frontend Build) for the same reason.
