# AA-902 — scrub AWS account IDs and ARNs from AA-CIS-App (public repo)

Branch `chore/aa-902-scrub-account-ids`. Scope here: AA-CIS-App only (Booking and TripPlanner are
separate lanes). Real account IDs are never written in this note; `<acc1>`, `<acc2>`, `<acc3>` stand for them.

## Decisions

- **Bronze bucket at run time, no new env var.** `shared/aws_client/bronze.py`: `bronze_bucket()` returns
  `BRONZE_BUCKET` (already set on the api and worker task definitions in AA-CIS-Infra `modules/ecs`), else
  `aa-cis-bronze-<caller account>` with the account from STS `GetCallerIdentity` (no IAM permission needed).
  Used by `admin_pipeline.py` (3 sites), `services/photos/sync.py`, `services/retention/*`,
  `services/jobs/retention_job.py`, `services/eval/regression.py`, `shared/llm_client/bedrock_batch.py`.
- **acc2's own ID from STS.** `cost_explorer.acc2_account_id()` and the Batch `s3BucketOwner` use
  `bronze.caller_account_id()` (cached once per process): the ECS task runs in acc2, the same account as the
  bronze bucket, so the native identity names it. `platform_cost.py` wraps it so an STS failure leaves the
  report's `aws.account_id` null instead of failing the endpoint.
- **acc1/acc3 IDs kept once, not removed.** AssumeRole into the satellite accounts needs their IDs and no
  existing env var, secret or table holds them. Inventing an env var is out of this lane, so the two IDs now
  live on two lines of `shared/llm_client/bedrock_satellite.py` (`ACC1_ACCOUNT_ID`, `ACC3_ACCOUNT_ID`), and
  every ARN is built from them: invoker roles, inference profiles (`_inference_profile_arn`), Batch
  service roles (`bedrock_batch.py`) and Cost Explorer reader roles (`cost_explorer.py`). Built values were
  compared with the old literals: identical for all 6 satellite constants, the 2 Batch roles and the 2 CE
  roles.
- **The admin page gets a key, not an ID.** `read_cost_range()` adds `account_key` (`acc1|acc2|acc3`, null
  for another account) to each account and service row; `frontend/app/admin/llm-usage/page.tsx` labels by
  that key and shows the account ID only from the API data. No ID map in the frontend.
- **E2E mailbox bucket from the runner's credentials.** `tests/e2e/helpers/mailbox.ts` builds
  `aa-cis-dev-e2e-mail-<account>` from `aws sts get-caller-identity` (the read-only mailbox role is in that
  account); a failed lookup is retried on the next poll.
- **Scripts run by ECS exec** (`aa856_global_profile_probe.py`, `link_staff_identity.py`) inline the same rule
  (they are fetched to /tmp and may not import the app); their run instructions set
  `BRONZE=aa-cis-bronze-$(aws sts get-caller-identity … --query Account --output text)` on one line.
- **Nothing moved to the root repo.** Every hit was code, a code comment, a migration comment, a test or a
  short doc line; none was an investigation, inventory or report file.
- **Check:** `.github/scripts/check_resource_ids.py`, a new step in the required **Lint** job (blocking). The
  repo had no docs-lint/resource-ID check yet (AA-888 did not add one here). Patterns: ARN with account,
  `<name>-<12 digits>` (bucket names), VPC resource IDs, API Gateway host, and any standalone 12-digit number
  after blanking UUIDs. AWS documentation example accounts (123456789012, 111122223333, 444455556666,
  777788889999) are allowed for test fakes. Exceptions only in `.github/resource-id-allowlist.txt` with a
  max count and an expiry date (same shape as `.github/pip-audit-ignore.txt`); no inline ignore marker.
- **Cognito user-pool ID not in the blocking set.** The pool ID appears in 20 tracked lines (frontend
  `lib/cognito.ts`, `api/core/identity_config.py` defaults, tests, notes). It is published in every token's
  `iss` claim and in the JWKS URL, so it is not secret, and removing it needs config changes in the auth path.
  Left for a decision (see Should know).

## Changed

- Removed every real account ID / account ARN from 23 tracked files, except the 2 allowlisted lines.
- `services/retention/policy.py`: `ARCHIVE_BUCKET` constant removed; `S3Archiver(bucket=None)` resolves the
  bronze bucket at construction.
- `services/eval/regression.py`: `GOLDEN_TOURS_S3_BUCKET` removed (bucket from the helper).
- `shared/llm_client/bedrock_batch.py`: `BRONZE_BUCKET` constant removed.
- `shared/aws_client/cost_explorer.py`: `ACC2_ACCOUNT_ID` replaced by `acc2_account_id()`; `ACC1_ACCOUNT_ID` /
  `ACC3_ACCOUNT_ID` are now re-exported from `bedrock_satellite.py`; new `account_key()`.
- `admin_pipeline.py`: the old fallback bucket name pointed at an acc1 bucket (dead since the acc1 infra was
  destroyed); it now uses the helper, same as everything else. On ECS `BRONZE_BUCKET` is always set, so
  behaviour there is unchanged.
- Migration comments 153, 167, 208, 240 lose the IDs (comments and `COMMENT ON` text only; no schema change).
- `.claude/CLAUDE.md`: dropped the API Gateway ID.
- Tests: fakes use 111122223333; `tests/unit/conftest.py` sets `BRONZE_BUCKET=aa-cis-bronze-test` and fakes
  `bronze.caller_account_id` (autouse); `tests/integration/conftest.py` does the same, so no test calls STS. New `tests/unit/test_aa902_resource_id_check.py` (19 cases; fake IDs built at run time).

## Tradeoffs

- One STS call per process for acc2's ID and the derived bucket name outside ECS, against a new env var. STS
  `GetCallerIdentity` needs no permission and is cached; on ECS the bucket comes from `BRONZE_BUCKET` anyway.
- Two literal lines stay until Infra carries the satellite IDs. The alternative (invent an env var name in
  this lane) was ruled out by the lane brief; the allowlist entry expires 2026-11-30 so it cannot be forgotten.
- The 12-digit rule is strict (any standalone 12-digit number). On this tree it has no false positive once
  UUIDs are blanked; if one appears, the fix is a rename or an allowlist line with a date, not a marker.
- No git history rewrite (lane brief; account IDs are low-risk identifiers, not credentials).
