# AA-1181 — Content workspace follow-ups

Slices of the AA-1148 follow-ups, in order. This note covers slice (a); the later slices add their own sections.

## Slice (a): an Excel fact draft never publishes over a hand-made tour (S294, lane l20)

### Decisions

- **Refuse at both ends of the sheet path.** A supplier sheet reaches a tour's facts in two steps: the merge of a
  staged re-import becomes a fact draft (`POST /admin/upload-staging/{id}/decide` with `merge`, preview at
  `GET …/merge-preview`), and a person publishes the draft (`POST /admin/tours/{id}/fact-draft/publish`). Both refuse a
  hand-made tour (`raw_tours.entry_origin = 'manual'`, CIS 478) with 409 `fact_draft_hand_made` (header
  `X-Error-Code`). The merge refusal sits in `uploads.py::_merge_inputs`, so the preview and the decide share it; the
  staging row stays pending for another decision. The publish refusal is the first of the publish checks
  (`fact_drafts.py::_fd_publish_checks`), before the two-person gate, so every publisher gets the same clear answer
  and nothing is written (no raw_tours UPDATE, no `excel_merge` history row, no fan-out). The draft stays open and can
  still be discarded.
- **Why the publish check is needed although the merge refuses.** A draft opened before the check shipped (or before
  the tour became hand-made) would otherwise publish. The publish check is the one that guarantees the rule.
- **One probe, owned by the workspace.** `services/content_workspace/store.py::is_hand_made` reads the origin through
  `to_jsonb` (the same `_ORIGIN_SQL` the publish gate of AA-1148 uses: False before CIS 478, for a sheet tour and for
  an unknown id). `_manual_row` now uses it too, so there is one definition of "hand-made".
- **The drawer says it before the click.** `GET /admin/tours/{id}/fact-draft` returns `hand_made`; the drawer's sheet
  draft (`TourFactDraft.tsx`) shows a red note and turns Publish off; Discard stays. The merge panel
  (`upload/MergePanel.tsx`) shows its own text for the 409 and the merge is never ready, so Confirm stays off until the
  person picks Bypass.
- **Known refusal codes are translated in the page.** The API messages are English; a new pure helper
  `frontend/lib/factDraftErrors.ts::refusalText` maps a known code (`fact_draft_hand_made`) to the page's EN / VI text
  and falls back to the API's message, then to the generic text. Messages in `tourDraft.messages.ts` (EN + VI, the
  Vietnamese name of the workspace is the nav's "Khu làm nội dung"; no issue ids).
- **Service layer only, no database guard.** The only writer that publishes a fact draft onto `raw_tours` is
  `publish_fact_draft` (`git grep raw_tour_fact_draft`: the router, the merge decide that creates drafts, the CIS 457
  migration and tests). A trigger on `raw_tours` could not tell a sheet write from a workspace write (both are
  `cis_app` UPDATEs of the same columns), and a trigger on `raw_tour_fact_draft` would only repeat this check for the
  same single writer. No migration in this slice.

### Changed (against the issue)

- The merge is refused too, not only the publish: a draft that can never be published should not be created.
- Replace / update / keep both and set-active are refused too (review fix pass): the issue names the fact-draft
  publish, but those decisions put the same sheet row on the live catalog in the tour's place.
- No setting: the refusal is a rule, not a threshold, so nothing new goes to Platform › Settings.

### Tradeoffs

- The refusals advise Bypass, or Create a new tour: for a hand-made match the Duplicate Review offers exactly those two
  (for a live sheet match it still offers Bypass / Merge / Replace / Keep both, for a deleted one Bypass / Restore /
  Create a new tour).
- The publish refusal runs before the two-person gate, so a person who could not publish anyway also sees the
  hand-made message first. That is the more useful answer: no second person can publish it either.

### Should know

- Tests: `tests/unit/test_aa1181_fact_draft_hand_made.py` (probe, refusal, order before the gate, a sheet tour still
  passes the publish checks and the merge plan; supersede replace / update / keep_both and set-active refused on a
  hand-made key), `tests/integration/test_aa1181_fact_draft_hand_made_pg.py` (merge
  refused with the staging row pending and no draft; an older draft refused at publish with the tour, the draft and the
  history untouched, then discarded; a sheet tour still merges and publishes; replace / update / keep_both refused with
  the tour live and hand-made, Create a new tour still works; set-active of an older sheet version refused), `frontend/lib/factDraftErrors.test.mjs`.
- **A sheet row can match a hand-made tour.** The upload matches a staged row to an existing tour on tenant + lower(trim
  name) + lower(trim provider), newest first, and ignores the batch (`services/ingestion/handler.py`). A hand-made tour
  lives in the same master tenant, with the form's name and the Booking supplier's company name as provider, so a
  supplier sheet with the same tour name and supplier is staged against it. (An earlier draft of this note said the
  opposite; review of this slice corrected it.)
- **So every Duplicate Review decision that would put the sheet on the tour is refused** (fix pass of the review):
  - `merge`: 409 `fact_draft_hand_made` (above);
  - `replace` / `update` / `keep_both`: 409 `source_hand_made` from `services/tour_lifecycle/service.py::supersede`
    (the one writer every caller goes through), when any version of the matched key is hand-made. The rule lives in
    `services/tour_lifecycle/hand_made.py` (`hand_made_versions`, `refuse_sheet`; origin read through `to_jsonb` like
    the workspace probe); service.py calls it in one line per action (service.py is at its code-health line baseline,
    so two signature / call lines were joined to stay at 850). `keep_both` is refused too: it would add
    the sheet row as a superseded version of the hand-made key, and set-active could then make it live;
  - `set_active` refuses an older sheet version of a key with a hand-made version (same code), as a second guard for
    keys that already hold one;
  - `bypass` and `create_new` stay allowed: Create a new tour keeps the sheet's tour as a separate tour (new key, the
    hand-made one untouched).
  - The Duplicate Review list returns `matched_hand_made`; the page shows a red note and offers only Bypass and Create
    a new tour for such a row (`upload/stagingDecisions.ts`); a deleted hand-made match keeps the deleted choices
    (Restore brings the hand-made tour back).
- Not changed: the ingestion match still stages such a row (rather than skipping hand-made tours in the lookup). Staging
  it shows the person the clash and lets them choose; skipping it would add a second tour with the same name and
  supplier without a word.
- Live check: on Dev no staged row matches a hand-made tour, so the live check is the API shape: `GET
  /admin/tours/{id}/fact-draft` of a hand-made tour answers `hand_made: true` (and `draft: null`), of a sheet tour
  `hand_made: false`; `GET /admin/upload-staging/{batch}` items carry `matched_hand_made`.

## Second review pass (S295)

### Decisions

- **The fact-draft refusal is per key, like the rest.** The first pass refused merge and publish when the matched row
  was hand-made, while the Duplicate Review list (`matched_hand_made`) and supersede / set-active look at the whole key.
  A key whose live version came from a sheet but which holds a hand-made version (left by a Replace on a hand-made
  match before this rule) was listed as hand-made, yet a direct `decide merge` or an older page could still draft and
  publish the sheet into it. Now `services/tour_lifecycle/hand_made.py::key_is_hand_made` (`key_of` +
  `hand_made_versions`) is the one rule: `fact_drafts.py::refuse_hand_made` calls it, so merge, merge-preview (through
  `uploads.py::_merge_inputs`) and publish share it, and the drawer's `GET …/fact-draft` `hand_made` uses it too (no
  Publish button for a mixed key). `content_workspace.store.is_hand_made` stays as the workspace's own probe of one row.
- **Tests build the real shape.** The pg `_tour` helper inserts a source version 1 of its own key
  (`source_group_id` = own id, active), `_staged` sets `matched_source_group_id`, and `_join_as_superseded` builds the
  mixed key (hand-made v1 superseded, sheet v2 live). Before, the replace test passed through supersede's "no matched
  group" branch, which never supersedes the hand-made row, so it proved the 409 but not that the real data loss is
  stopped. Unit tests use a `_KeyConn` fake (the key read, then the hand-made versions read).

### Changed

- Two new pg tests: a mixed key refuses merge-preview and merge (row pending, no draft, `hand_made` true, statuses
  unchanged) and a draft opened before a hand-made version joined the key is refused at publish with nothing written.
  With the old row-level probe swapped back in, both fail (DID NOT RAISE).
- `.github/workflows/ci.yml`: `lib/factDraftErrors.test.mjs` joins the node --test lists of "Kit core self-check and
  kit render tests" (Frontend Lint, pull request) and "Kit button render tests" (Frontend Build, merge queue). Before,
  no CI job ran it.
- `docs/context/pipeline-stages.md` states the rule in the Excel re-import T1 paragraph (both 409 codes, per key) and
  the Content workspace paragraph points to it.
- `upload/page.tsx` Confirm all shows the hand-made text for a merge refused with `{code, message}` (it showed the bare
  HTTP status), through `refusalText`.

### Tradeoffs

- The CI lists get one file added rather than switching to `npm run test:unit`: the other `lib/*.test.mjs` files have
  never run on the CI runner, so that switch is its own change with its own trial.
- `key_is_hand_made` costs one more read than the row probe (the key, then its versions); both are indexed
  (`raw_tours_pkey`, `raw_tours_key_expr_idx`) and run once per merge / publish / drawer read.
