# AA-831 — Facebook Page connect: tenant guide + connect-card help text

## Decisions
- The guide is a portal route, `/portal/help/facebook` (`frontend/app/(tenant)/portal/help/facebook/page.tsx`),
  not an external doc. It inherits the portal shell (sidebar, top bar, light theme) from
  `portal/layout.tsx` and the auth guard from the existing `/portal` prefix rule in `lib/rbac.ts`,
  so no middleware change was needed. A breadcrumb entry was added in `layout.tsx`.
- The page uses the portal primitives (`_components/ui`: `PageHeader`, `Card`, `CardHead`, `T`),
  the same layer as the T11 Publish / Connections pages that link to it. It is static content: no
  kit data component (DataTable, Drawer, etc.) applies. It is a client page, like every other portal page,
  because it imports `PermissionList` from the `"use client"` `FacebookConnect.tsx` module.
- The 3 permission names live once in `FACEBOOK_PERMISSIONS` (FacebookConnect.tsx) and render through
  `PermissionList` ("a, b and c", one `<code>` chip each, explicit separators). The card and guide
  share them, so they cannot drift apart.
- Long-lived token path for a non-developer: Graph API Explorer (User token with the 3 permissions)
  → Access Token Debugger "Extend Access Token" (about 60-day User token) → Explorer `me/accounts`
  (Page token with no expiry date). This avoids the `oauth/access_token?grant_type=fb_exchange_token`
  call, which needs the app secret and which Meta says to make only from a server.
- No screenshot placeholders. Meta's dashboard changes often, so each step names the menu items and
  says to look for the closest match.

## Changed
- `FacebookConnect.tsx` help text now names `pages_show_list`, `pages_read_engagement` and
  `pages_manage_posts`. It also states the Live-mode rule, says where the Page ID is, asks for a
  long-lived Page token, and links to the guide.
- Spacing (S237 UI verify D5, "pages_manage_postspermission"): a server render of the new card gives
  "...with the permissions pages_show_list, pages_read_engagement and pages_manage_posts." The JSX
  uses explicit `{" "}`/`{", "}` and not line-boundary whitespace.
- Scope item 3 of the issue (a planner-made facebook piece through T11) was an investigation only in
  this lane. There was no DB or LLM run. The finding is under "Should know".

## Tradeoffs
- Kept the Live-mode text factual and short. It does not cover App Review: the issue's Live run
  (S238) worked without App Review, and Meta's app-modes page does not say clearly what Business
  apps need for role users. If a tenant reports that Meta blocks the switch to Live, add a short
  App Review note.
- The "Common problems" section quotes the two messages that `_classify_facebook_test_failure`
  returns. It also covers two cases the connection test cannot catch, because the test only reads
  `GET /{page_id}?fields=id,name`:
  - a User token pasted in place of the Page token;
  - a token without `pages_manage_posts`.
  In both cases the test passes and publishing fails.

## Should know
- **The planner (T7 Slate → T8 → T9) essentially never produces `channel='facebook'` pieces.**
  - `propose_slate()` loops over every channel in `CHANNEL_BARS` (`services/acp_shared/slate.py:447`).
    It never reads `acp_shared.tenant_config.channels`: the tenant's channel config only feeds the dead
    N6 `compute_slot_grid()` path (no production caller, `allocator.py:8-14`).
  - The loop shares one `seen_places` set across all channels (`slate.py:446`, AA-632).
  - `linkedin` comes before `facebook` in dict order. It has the identical bar (`needs_said=150`,
    `slate.py:80-86`). `atom_segment.canonical_place` is NOT NULL.
  - So every place that clears facebook's bar has already been taken by linkedin
    (`_choose()` place dedup, `slate.py:387-399`).
  - Facebook can only get the overflow past linkedin's `most_per_hub=99` cap.
  - Pure `_choose()` run with 5 clearing segments: linkedin got all 5, facebook 0 (instagram,
    tiktok and the on-demand channels also 0).
  - A follow-up issue is needed to decide the cross-channel dedup rule (per-channel quota or
    round-robin), and whether the tenant's configured channels should filter the Slate.
- The connect card's Page ID hint says "About → Page transparency" (new Pages experience). The guide
  also gives the `id` from `me/accounts` as the primary source.
- No `next build` or dev server was run (RAM limit). `tsc --noEmit` passed. ESLint passed on the
  touched files, apart from the existing `useState<any>` in `portal/layout.tsx:55`, which is
  unchanged from main. Visual check at 1440/390 is still to do on the Vercel preview.
