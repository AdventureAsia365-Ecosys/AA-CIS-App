# AA-894 scope 2: live interactive ERD in the CIS admin (`/admin/data-model`) — Refs AA-894

Part 1 (AA-CIS-Infra) made the nightly DB Schema Dump produce `erd.json`. This branch adds the reader and the page.
The Infra half of scope 2 (S3 key, IAM read grant, upload on by default) is AA-CIS-Infra `feat/erd-cis-read-grant`.

## Decisions

- **Route `GET /admin/data-model`**, own router `api/routers/admin_data_model.py`, `dependencies=[Depends(staff_policy)]`
  (secret or verified staff Bearer, then POLICY). POLICY `("GET", "/admin/data-model")` = `ops.read`: admin role only
  (viewer, reviewer, content, tenant and the machine principal get 403). `ops.read` because the model is system
  internals (every schema of the shared RDS, owners, RLS, PII tags), like `/admin/infra/status`.
- **Page `/admin/data-model`**, nav Platform › Developer next to API Docs; not under `/admin/platform/*` because
  the Developer pages already live outside it (`/admin/api-docs`). PAGE_RULES admin, BFF `API_READ_RULES` `data-model`
  admin (refused before the backend for any other role).
- **Storage**: bronze bucket (`shared/aws_client/bronze.py`), key `data-model/erd/latest.json` and `previous.json`
  (env `DATA_MODEL_S3_PREFIX`, default `data-model/erd`, no Terraform env needed). The Infra branch moves the upload
  there from part 1's `db-schema-dump/erd/` and grants the task role `s3:GetObject` on exactly those two keys.
- **Errors**: `latest.json` missing (`NoSuchKey`) → 404 "No data model has been published yet"; any other read
  failure, non-JSON, or not format 1 → 503 (the raw error is only logged, by class name). `previous.json` missing or
  unreadable → 200 with `diff: null` (a diff is not worth failing the page). Errors are not cached.
- **Cache**: module-level, per process, 5 min TTL, one `asyncio.Lock` so a burst reads S3 once; `?refresh=1` (the
  page's Reload) re-reads only when the copy is older than 30 s, so it cannot drive an S3 loop. boto3 runs in
  `asyncio.to_thread`. Object size capped at 20 MB (today ~650 KB).
- **Diff** (server side, `diff_models`): tables added / removed / changed; per table columns added / removed /
  changed (type, NOT NULL, DM-6.1 tag, PK / FK / UK flags), PK, FKs added / removed, RLS; FK edges added / removed keyed
  `schema.table:constraint` (constraint names are unique per table only). Same fingerprint → no diff.
- **Response**: `{model, previous: {fingerprint, generated_at, migrations_latest_per_owner} | null, diff, loaded_at,
  cache_ttl_s}`, `Cache-Control: private, no-store` (the browser keeps nothing; react-query holds it per tab).
- **UI** (kit only, in `KIT_CLEAN_FILES`): search over table and column names (every word must match; column hits
  shown on the row), schema filter (`<select>` with `maxWidth: 100%` / `minWidth: 0`, lesson S221), "Show changed
  only", "Table +1" (list narrowed to the selected table and its one-FK neighbours), a diff summary card (removed
  tables / FKs listed by name since they cannot be clicked), the table list with new / changed / PII / RLS markers,
  and the detail: owner app + role, kind, RLS, PK / UK, the change box, a neighbour map (referenced by → table →
  references, each neighbour clickable, cross-app / cross-schema / NOT VALID badges, NOT VALID drawn dashed) and the
  column rows. Desktop: two columns; phone (< 768 px): list, detail in the kit Drawer.
- **Public repo**: tests use an invented model (schemas `alpha` / `beta`); no real table or schema name in code,
  tests or this note.

## Tradeoffs

- **No graph library** (no React Flow / d3 / Mermaid in the bundle): the useful question on a 300-table model is
  "what is this table and what touches it", which the +1 neighbour map answers; a full force-directed graph of every
  schema is unreadable (part 1 already saw that with Mermaid on GitHub). The per-schema Mermaid pages stay the
  whole-schema picture.
- **Diff on the server**, not in the browser: the browser gets one model plus a small summary instead of two
  ~650 KB models.
- **In-process cache, not Redis**: the object is small, reads are rare (admin only) and stale for at most 5 min; two
  api tasks read S3 at most twice per 5 min.
- **Selection is not in the URL** (no `?table=`): `useSearchParams` would need a Suspense boundary on a static page;
  can be added when someone needs to share a link to a table.
- **List capped at 400 rendered rows** (more than the whole model today); the search narrows the rest.
