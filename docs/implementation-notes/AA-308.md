# AA-308 — Bake-off Palmyra X5 (T1) vs Claude (T2)

## Decisions
- STEP 0 + rate-limit probe run synchronously first, per explicit instruction, before any
  real Phần A/B work. Findings below gate the go/no-go for both parts.
- Palmyra X5 pings sent via `aws bedrock-runtime converse` CLI (not a fresh boto3.Session)
  — a fresh `boto3.Session(profile_name="aa365-admin")` re-triggered an interactive MFA
  prompt and hung; the CLI reused the already-cached 8h assumed-role session
  (`nghiep-admin-8h-session`) without prompting. Use the CLI (or reuse an existing boto3
  session/credentials object) for any further ad-hoc Palmyra pings in this account.
- Phần A rescoped mid-session, twice, both times by explicit user instruction:
  1. Original "Writer N7 bake-off" was dropped entirely on discovering Writer N7 has zero
     code/design in the repo (see Findings) — building one from scratch would mean
     unilaterally inventing atom-grounding scheme/output schema/brand-rule wiring, which is
     a product decision, not an infra test.
  2. Replaced with a scoped infra-only question: same minimal copywriter prompt sent to both
     models from raw `itinerary_source` (no atoms, no brand rules), Nova Pro blind-judges.
     Explicitly NOT a Writer N7 quality verdict — see Should-know.
- Ran Phần B (25 tours, not the original 22 from AA-299 — 3 more tours had been decomposed
  since) using the exact `_SYSTEM_PROMPT`/`_build_user_prompt()` from
  `api/routers/v1_atoms.py`, copy-pasted verbatim into a standalone script — no DB writes,
  read-only comparison per the task's own instruction.
- Grounding classification (SẠCH/NHẸ/NẶNG) has no reusable script from the original AA-299
  run (no implementation-notes file for AA-299 ever existed) — built an LLM-judge (Claude
  Haiku via the satellite) with an explicit rubric mirroring the anti-hallucination prompt's
  own definition of a violation, rather than re-deriving AA-299's original method blind.
- Both `invoke_claude()`-dependent scripts (grounding judge, Phần A Claude-side writer) had
  to run **inside the ECS container**, not locally — `AA-Bedrock-Invoker`'s trust policy
  (acc1) only allows AssumeRole from `aa-cis-dev-ecs-task-role`, not personal admin
  credentials. Used the S3-mediated exec pattern + self-daemonize (double-fork +
  `os.setsid()`) since plain `nohup ... &` inside an `execute-command` session is killed
  when the SSM session tears down (confirmed live, matches prior memory
  `ecs-exec-long-sync-daemonize`).

## Findings (STEP 0)
- Native model IDs confirmed ACTIVE on acc2 ([acc2 id], us-west-1), via
  `aws bedrock list-foundation-models` / `list-inference-profiles`:
  - Palmyra X5: on-demand `writer.palmyra-x5-v1:0`, inference profile `us.writer.palmyra-x5-v1:0`
  - Nova Pro: on-demand `amazon.nova-pro-v1:0`, inference profile `us.amazon.nova-pro-v1:0`
- `invoke_claude()` (shared/llm_client/bedrock_satellite.py) builds its bedrock-runtime
  client via `session.client("bedrock-runtime", region_name=ACC1_REGION)` with no
  `botocore.config.Config` override — no explicit timeout/retry tuning, matches the existing
  code comment in api/routers/v1_atoms.py ("invoke_claude() has no built-in timeout/retry").
  Response parsing is Anthropic-shaped (`content[0].text`); a Palmyra equivalent needs
  Converse-API or Writer-OpenAI-compatible parsing instead (`choices[].message.content`),
  per the warning already in the bedrock_satellite.py docstring.
- Official quota (`aws service-quotas list-service-quotas --service-code bedrock`, acc2,
  us-west-1): **Cross-region model inference requests per minute for Writer AI Palmyra X5
  V1 = 1.0** (applied). AWS's own *default* for this quota is 10/min — this account is
  running below the AWS default, same shape as the TrueIDC/channel-program restriction
  already documented for Anthropic access on acc2. Nova Pro, for comparison, is 25 req/min
  / 2,000,000 tokens/min — no comparable constraint.
- Empirical 5-ping test (1s apart, `converse` API, minimal prompt): call 1 succeeded
  (Bedrock-reported latency 302ms), calls 2–5 **all** hit `ThrottlingException` even after
  the CLI's own retry budget (max_attempts=2) was exhausted on each. This confirms the 1
  req/min ceiling is a real, hard wall — not just a paper quota.

## Should know
- **Palmyra X5 = 1 request/minute, hard-enforced.** Phần B (22 tours) and the Palmyra side
  of Phần A (20 tours) cannot run in parallel with each other or internally — every single
  Palmyra call must be spaced ≥60–65s apart, sharing one bucket. Sequential-only. Rough
  floor: ~22–24 min for Phần B alone (1 call/tour, no retries), another ~20–22 min for Phần
  A's Palmyra leg — assuming decompose/writer needs exactly 1 call per tour. Claude-side
  calls (satellite, acc1) are a separate quota/account and can proceed concurrently with the
  Palmyra leg without contention.
- **Writer N7 does not exist anywhere** — no code, no draft branch, no implementation-notes
  file, nothing beyond one comment in migration 079 flagging it as unbuilt future work. The
  existing S1 rewrite pipeline (`services/content_generation/prompts.py` + `graph.py`) has
  zero atom awareness — raw tour fields only. Do not treat anything below as a Writer N7
  quality verdict; that requires its own design (atom-grounding tags, output schema, brand
  rules) once AA-300 (Curation UI) exists.
- **`acp_contract.tour_atoms` (migration 079) has no review/curation/approval column** —
  only `starred` (bool) and `deleted` (bool). No AA-300 implementation-notes file exists.
  There is no way to point to "atoms a human has reviewed" today.

## Findings — Phần B (N2 decompose, 25 tours, verbatim PR #80 prompt, no DB writes)

| | Palmyra X5 | Claude (AA-299 baseline, 22 tours) |
|---|---|---|
| SẠCH | 81.2% (147/181 graded atoms) | 96.5% |
| NHẸ | 14.4% (26/181) | 3.5% |
| NẶNG | **4.4%** (8/181) | **0%** |
| Never-pad respected | yes — 6/25 tours correctly returned 0 atoms on thin source | — |
| Hard failure | 1/25 tours — JSON truncated mid-string (`Unterminated string`) | — |

The 4.4% NẶNG is a real, cited violation, not classifier noise: one atom for the "Sacred Bo
Tree" added *"believed to be the oldest historically documented tree in the world"* —
verified absent from the source `itinerary_source` text, and exactly the class of violation
the PR #80 prompt explicitly forbids ("even if you know them to be true from general
knowledge"). Grounding was classified by a Claude Haiku judge (rubric in
`classify_grounding_ecs.py`), not by re-deriving AA-299's original (undocumented) method.

**→ Palmyra is not ready to replace Claude for N2 decompose as-is.**

## Findings — Phần A rút gọn (infra-only writing test, 20 tours, minimal copywriter prompt,
Nova Pro blind judge, 1–10 score)

- Paired per-tour comparison (position-independent): **Palmyra wins 14/20, Claude wins 6/20**,
  mean score 8.50 vs 8.10.
- Nova Pro showed a real position bias (scored whichever text was placed in "Bài B" higher in
  15/20 tours, 75%, regardless of model) — checked and it does not explain the result away:
  Palmyra sat in the lower-scoring "Bài A" slot slightly *more* often (11/20 vs Claude's 9/20),
  so the bias worked against Palmyra if anything.

**→ Palmyra is competitive-to-slightly-better for this minimal writing task** — but this is an
infra signal only (same trivial prompt to both models, no atoms, no brand rules), not a Writer
N7 conclusion.

## Recommendation
- Do not move N2 decompose to Palmyra yet — the 4.4% NẶNG rate is a real quality regression
  versus Claude on the identical prompt. Would need mitigation (lower temperature, tighter
  instructions, or a post-hoc grounding filter) before revisiting.
- Palmyra is viable for basic non-grounded writing tasks if reducing acc1 dependency is a
  goal — but Writer N7 itself needs its own build (atom input, schema, brand wiring) once
  AA-300 lands; this bake-off doesn't decide that.
- Acc1 billing: no reliable number obtained. Cost Explorer returned $0 for the last 30 days
  on acc1, but this is almost certainly reporting lag (24–48h) — dozens of real Sonnet calls
  went through acc1 in this same session — not evidence of genuinely free usage.
- Raw data (25-tour Phần B atoms + grounding classifications, 20-tour Phần A write-ups both
  models, full Nova Pro judge output per tour) is in the session scratchpad
  (`/tmp/claude-*/.../scratchpad/*.json`), not committed to the repo — regenerate via the
  scripts described above if this needs to be re-run or re-audited later.
