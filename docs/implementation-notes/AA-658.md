# AA-658 — Model catalog + Bedrock Converse provider (Gateway P0)

Design settled in S200 (28/09/2026) through a manual `/grill-with-docs` pass (3 rounds). Decisions
are recorded in `docs/adr/0005-model-catalog-and-converse-adapter.md`.

## Decisions
- Keep the existing Model Keys `haiku` / `sonnet` / `gpt-4.1`, so no `llm_role_config` data moves.
- Per-account inference profiles go in one JSONB column, `bedrock_profile_ids`.
- Converse models get no silent fallback in P0; a failure raises (chains belong to AA-659).
- A `callable_via` column limits the dropdown per stage: writer stages via `LLMClient`
  (`llm_client`), judges stay on GPT-4.1 until AA-659.
- Prices are read from the catalog (5-min in-process cache); `pricing.py` is the fallback.
- Opus 5.5 and GPT-6 Astra are seeded `enabled=false`: the public Bedrock pricing page (WebFetch,
  28/09) lists the models but no rates. Sonnet 5 ($2/$10) and GPT-5.6 Luna ($0.10/$0.50) per 1M
  come from S198 research, not re-verified on the AWS page.
- Converse calls log as `provider='bedrock-satellite'`, `account='acc3'`.

## Changed (vs. the Linear issue)
- The issue said "rename the policy" (AA-657). The IAM policy *name* was kept and only the Sid was
  renamed: a name change forces destroy+create and leaves the role without invoke permission
  between the two steps (local plan showed 1 add / 1 destroy).

## Tradeoffs
- No fallback for Converse writer stages: a failed call fails the job, instead of silently
  switching vendor. Accepted because switching a stage to a new model is an explicit admin action.

## Should know
- `api/migrations/169_llm_model_catalog.sql` must be applied by hand via ECS exec (no CI runner).
- The acc3 IAM change (Infra PR #74) must be applied before any Converse call can succeed.
