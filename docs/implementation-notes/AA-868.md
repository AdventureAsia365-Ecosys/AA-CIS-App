# AA-868 — CIS CI/deploy hardening

## Decisions
- pip-audit ignores live in `.github/pip-audit-ignore.txt` (`<id> <expiry> <reason>`), read by
  `scripts/ci/pip_audit_gate.sh`. pip-audit has no expiry of its own; an expired or malformed entry fails
  the check before pip-audit runs. Booking has no ignore list, so the "Booking pattern" here is only
  "failing"; the expiry is new.
- Bumped the two low-risk fixes instead of ignoring them: python-dotenv 1.0.1 → 1.2.2, markdown 3.7 → 3.8.1
  (only `services/acp_content_writing/export.py` imports markdown).
- Ignored with expiry: chromadb (no fix; only `shared/rag/client.py` imports it and nothing imports that
  module), pytest 9 (major bump, test-only), langgraph-sdk / langchain (pipeline deps, bump with a regression run).
  Dropped the old `PYSEC-2024-56` ignore: no longer reported.
- Deploy guard moved to `scripts/ci/deploy_job_guard.sh` so it can be tested. It fails closed on: missing
  secret, gate non-2xx / unreachable (curl --fail, 2 retries), non-JSON, missing `safe_to_deploy`, active jobs.
- The override reason releases every blocked case, not only "jobs active": when the API is down, a deploy is
  the fix, and a fail-closed guard with no way out would lock it.

## Changed
- `concurrency: deploy-dev-cis`, `cancel-in-progress: false` (queue, never kill a running roll).
- `--desired-count 1` kept, with a comment (wakes a service scaled to 0).

## Tradeoffs
- The committed ignore list is also checked by a unit test, so an expiry turns both Security Audit and
  Unit Tests red. Accepted: the expiry is meant to be loud.

## Should know
- A preflight run now checks out the repo (the guard is a file); `preflight` keeps `environment: dev`.
