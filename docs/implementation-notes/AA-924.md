# AA-924 — Per-violation severity in the T10 ledger; one lexicon gate; F15_voice absorbs F15_voice_warn

Plan: root `.tmp-session/s250/plans/AA-924.json` (S250), PR1 = slices a (ledger severity, no behaviour change),
b (merge the gates 26 → 24) and c (offline replay). PR2 (Content Quality UI badges) is a separate, Vercel-only PR.
Stacked on `feat/aa-926-quality-registry-s250` (AA-926 merges first).

## Decisions

- **D1 — the merged entry carries its legacy parts.** A merged ledger entry (`F2_lexicon`, and the new `F15_voice`)
  is `{gate, passed, violations, repairable, blocking, severity, findings: [{text, severity, source}], parts}`.
  `parts` is one legacy-shaped record per folded source (`{gate: <source>, passed, repairable, blocking, …}`
  without `violations`), so `expand_ledger` rebuilds the exact legacy entries — including flags a source carries
  only when it fails (`repairable` of a passed F15_voice depends on the channel spec, `waived` set by
  `_waive_style_only`). Without `parts` the invariant `expand(merge(L)) == L` could only hold up to a
  normalisation, and the routing equivalence would have to be argued instead of tested.
- **D2 — one legacy F15_voice source, split by kind.** F15_voice's stock findings (`stock phrase '…'` from
  `STOCK_PATTERNS`, `stock line '…'` from `hygiene.template_lines`) go into `F2_lexicon`; contrast frames, sibling
  templates and pasted brief phrases stay in `F15_voice`. Both merged entries carry the same F15_voice part, and
  `expand_ledger` puts the F15_voice findings back in the legacy order by kind (stock phrase, contrast, sibling
  template, stock line, brief), which is exactly the order `gate_voice` builds them in.
- **D3 — positions.** `merge_ledger` places a merged entry where its home source sat (F2_lexicon at
  F2_banned_patterns, F15_voice at F15_voice); `expand_ledger` puts each source back at its home entry, in group
  order. Entries that are not merged never move: `_final_integrity` appends F13_repeat at the end of the ledger, and
  a global sort to a canonical order would change which gate `hold_failure` picks.
- **D4 — merge is idempotent; legacy ledgers pass through.** `merge_ledger` expands first, so a mixed list merges
  cleanly. A ledger with no merged entry (every piece stored before AA-924) is returned by `expand_ledger`
  unchanged. Known limit (review round): two entries with the SAME source in one list (two `F15_voice` dicts in a
  flags list, say) come back as one on expand, so `expand(merge(L)) == L` holds only for lists with one entry per
  source — which every list the stack builds is (`run_quality_gates` emits each gate once; flags are a subset of
  the ledger). Keeping per-occurrence parts would add bookkeeping for a shape no caller produces.
- **D5 — flags.** Persisted `flags` are merged the same way (`merge_flags`), keeping only failed merged entries: a
  stock-only F15 flag becomes an `F2_lexicon` flag with warn findings and no empty `F15_voice` flag.
- **D6 — severity stays block / warn** (as the issue says). "Never holds" stays a property of the source
  (`STYLE_ONLY_GATES`), not a third severity. A finding's severity is its source's blocking state at that moment
  (`block` when the source part fails and blocks, else `warn`), so a waived F15 part reads as warn.
- **D7 — regression guard keys.** The AA-528 guard compares blocking failures of the expanded ledgers, keyed by
  the legacy source name. A source name is unique, so this is the `(gate, source)` key of the plan: a new
  banned-pattern failure inside `F2_lexicon` that already failed on a stock phrase still counts as a regression.
  The persisted guard message keeps the source names (no text change).

- **D8 — the source checks stay.** `gate_banned_patterns`, `gate_brand_forbidden_words`, `gate_voice` and
  `gate_voice_warn` stay as the per-source detectors (unit-tested, used by the replay and by `lexicon_sources`);
  the plan's "gate_voice absorbs gate_voice_warn" is done in the stored ledger (`merge_ledger`), not by fusing the
  two functions. Fusing them would have rewritten ~120 test references for no routing gain.
- **D9 — one F15 check feeds two entries.** `run_quality_gates` runs `gate_voice` once and hands it to
  `lexicon_sources`, because the template-line findings are de-duplicated against the contrast / sibling ones
  (`not any(sentence in v for v in stock)`); computing the stock part alone would drift from the legacy list.
- **D10 — "no word judged twice".** `lexicon_sources` drops a tenant-forbidden word already found as a banned
  pattern in the same sentence, and a stock finding a banned / forbidden hit already covers (both of those block,
  so the highest severity is the one kept). Review round: the drop is one-way (`_same_hit(hit, kept)`): a hit is
  dropped only when the KEPT phrase contains it. A stock phrase around a shorter forbidden word ('worth sitting
  with' beside a forbidden 'sitting') is a second problem and stays, so the sentence repair is told both, as the
  legacy stack did. `gate_platform_truth` skips a word on the tenant's own forbidden list,
  as `gate_signature_words` already did. In the 40-case fault set this changes one case: f2b-2 ('Cheap', a tenant
  word and a platform-truth word) is now judged once, by F2_lexicon; its plan route stays "repair".
- **D11 — stored names.** `held_reason` and `repair_log[].gate_targeted` name the stored entry
  (`quality_gates.ledger_gate`: `F2_lexicon: …`); the rewrite feedback and the AA-528 guard message keep the source
  names (the writer prompt text is unchanged). Review round: the `t9_attempt_failed_quality_check` log event uses
  the same stored name (`gate`), plus `source` when the source differs, so logs and the DB agree.
- **D13 — admin highlights, one per finding (review round).** `highlights()` de-duplicated on (span, gate). With
  merged entries two findings of one entry on one sentence (a forbidden word and a stock phrase, or a contrast frame
  and a warn opener) collapsed into one. The key is now (span, gate, source, problem): the ledger + flags copy of a
  warn finding is still removed, two problems both show.
- **D14 — declined review nits.** (b) A passed merged entry keeps `blocking` from its parts (true for F15_voice),
  not false: every legacy passed gate also reads `blocking: true` (blocking is the gate's property, not the
  outcome), and every SQL reader (list/stats, admin_a4, tenant360) pairs `blocking` with `passed = false`, so a
  passed entry is never counted. (c) `gate_platform_truth`'s own-word skip stays exact (lowercased, stripped): the
  forbidden matcher is a literal regex on the entry, so a forbidden 'Book now!' does not match "book now." — a
  looser skip would let that sentence go unjudged by both gates. Judged twice in a rare punctuation case beats
  judged by neither.
- **D12 — the Q0 corpus keeps its source detectors.** The AA-791 Q0 cases still name `F2_banned_patterns` /
  `F2_brand_forbidden` (registered, retired): the fault-set runner and the t9 chain read the expanded view, so a
  source detector still "fires". No Q0 case is changed.

## Tradeoffs

- `parts` duplicates a few booleans per merged entry in the JSONB (two entries per piece). Cheap, and it keeps the
  routing proof a plain equality.

- The replay evidence covers the golden set only until the S234 export is run (needs MFA, orchestrator step).

- The replay compares base and head on the same rebuilt inputs, not against the stored status: sibling texts,
  taken titles and the similarity lookup are not stored, and older stored texts still carry em-dashes the current
  fixer would remove. The "stored status" table in the report is context only.

## Should know

- Readers that only use `gate` / `passed` / `violations` / `blocking` (list_pieces / stats SQL, admin_a4,
  tenant360) keep working on both shapes: a merged entry still has every finding's text in `violations` and
  `blocking` = worst severity is block.
