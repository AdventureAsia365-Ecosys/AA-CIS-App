# AA-154 — Migration 052: CIS tour lifecycle (ADR-018 foundation)

## Decisions

- **Migration format**: followed 051 style — `BEGIN/COMMIT` block with `shared.schema_versions` insert, DOWN block as comments (not a separate file).
- **Backfill order**: `source_group_id` first (step 5), then `source_version`/`source_status` (step 6), then `CREATE UNIQUE INDEX` (step 7). Index comes last so the partial unique constraint is created on an already-consistent dataset, avoiding spurious conflicts during backfill.
- **Active tiebreak**: rows with a non-null `sku` are preferred as the active record within a group; among equal-sku-nullness, latest `ingest_at` wins. This matches the most likely business intent (purchased/confirmed tours are canonical).
- **No NOT NULL on `source_group_id`**: left nullable — the backfill covers all existing rows, but a NOT NULL constraint at DDL time would require a DEFAULT that generates one UUID for all rows before splitting, which is incorrect. The partial unique index on `WHERE source_status = 'active'` will catch future rows that somehow skip the group assignment.

## Changed vs. original requirement

- DOWN block is embedded as SQL comments at the bottom of the file (rather than a separate `052_down.sql`), matching the convention in migrations 049–051 which have no separate down files.
- Added whitespace alignment for readability in the CTE column lists; semantics are identical to the spec.

## Tradeoffs

- **Backfill inside the migration transaction**: keeps the apply atomic (all or nothing), but on large datasets this could be slow. The dev DB has ~few hundred raw_tours so this is not a concern for the current phase.
- **Partial unique index (not a full unique constraint)**: allows `superseded`/`trashed` rows to share a `source_group_id` freely, which is the intended behaviour. A full unique index on `(source_group_id)` would prevent versioning entirely.

## Should know

- `sku` column must exist on `silver_aa_internal.raw_tours` before applying this migration. It was introduced earlier in the project — verify with `\d silver_aa_internal.raw_tours` before running.
- After apply, run all three verify queries from the AA-154 ticket to confirm backfill correctness before merging to main.
- The `upload_staging` table has no indexes yet beyond the PK; indexing `batch_id` and `tenant_id` is deferred to a follow-up migration once query patterns are confirmed.
