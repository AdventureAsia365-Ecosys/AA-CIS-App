# AA-1080 — Brief import fills the brand pack; unsupported markets reported; T2 keywords follow the agency's markets

Source: AA-741 phase 3 audit (root `docs/audits/2026-11-10-S276-aa741-phase3/`, sections 4.1, 5, 6, 9.1).

## Decisions

- **Three fields from the brief.** `services/brand_intake/brief.py` reads new sections / labels: "Brand context"
  (also "System prompt", "Instructions for the writer") → `system_prompt`; "Call to action" / "CTA" / "Closing line"
  → `default_cta`; "Signature words" / "Words we use" → `signature_words`.
- **When the brief has no such section** (the AA brief template the 4 audit briefs use has none):
  - `system_prompt` is a short brand summary built only from the brief's own fields (brand name and type, core
    idea, readers, what readers want, voice). Nothing invented.
  - `default_cta` is the brief's own call-to-action sentence (enquire / talk to / plan your …, never a negated
    one), else a neutral line naming the brand: "Get in touch with <brand> to plan this trip." It makes no promise
    or service-level claim (F17 / F19 safe) and still goes through the saved-CTA review check.
  - `signature_words`: short quoted phrases (1–3 words, no sentence) under Should Write / Good Example, plus the
    AA-800 positioning words the brief itself declares (`signature_vocabulary.signature_words`). A forbidden word
    never becomes a signature word. **None found = an empty list**, reported on the review screen; signature words
    are never invented (they relax gates, AA-800 / writing memory L0).
  - Every drafted value is listed in `drafted`, so the review screen says "drafted from your brief, check it".
- **Unknown sections are reported, not merged.** A Word heading style (or a short paragraph ending in ":") the
  parser does not know opens an unmapped section; its text stays out of the form and is listed in
  `unmapped_fields` (heading + chars) plus a warning. Before, its lines fell into the previous section (e.g. under
  Avoid, then into forbidden words). A known label typed as its own heading ("Customer segment:") now keeps its
  following paragraphs.
- **Signature words storage**: `tenant_brand_rules.custom_validators.signature_words`, the shape the pipeline
  already reads (brand_pack / T2 / L0). The save keeps the previous version's object (other keys such as an admin
  `voice_rubric` included) and replaces only `signature_words` when the client sends the list; not sent = carried
  over (`services/brand_intake/save.py::CUSTOM_VALIDATORS_VALUE_SQL`). Before, a new version dropped the column.
- **Migration 397 (contract, MIG-4)**: `GRANT INSERT (custom_validators)` to `aa_app_user` (the tenant pool had
  INSERT on 16 named columns only, CIS 262). Readiness requires 397 (`REQUIRED_CIS_ABOVE_GAP`), so the code PR goes
  after the migration is applied. 396–399 may be held by other lanes of the wave.
- **Unsupported markets**: `seed_builder.unsupported_countries()` lists every declared country without search data,
  also when another one is supported. The Slate (`_tenant_market_codes`) now records one row per such country and
  returns them as `unmatched_markets`, so the AA-629 banner shows for a partly unsupported agency (Atlas: AE SA SG
  HK). The Brand Identity save (tenant POST and staff PUT) records them too, on the main pool after the tenant
  transaction (AA-859 MAIN exception, like the CTA notice), best effort. `unmatched_countries()` (none supported)
  is kept for its callers.
- **Market note with the reason**: `markets.market_summary()` → `supported`, `unsupported`, `seo_market`,
  `defaulted`, `notes: [{country, reason: "no_search_data", uses: <seo_market>}]`. Returned by GET
  /admin/brand-identity (`markets`, shown on load), by the save and by the brief parse. The portal turns the reason
  code into copy (Partner web).
- **T2 keyword market** = `first_supported_market()` (declared order; "Europe" expands in place to UK DE FR NL), via
  `resolve_buyer_market()`. Every singular caller follows (T2 `tenant_market_seo`, S1 prefetch for a tenant, SEO
  handler, admin pipeline tools). `resolve_buyer_markets()` (plural, Slate) keeps its rank order on purpose: the
  Slate reads every market, and AA-1055 ties use that order.
- **$0 replay**: `scripts/aa1080/t2_keyword_market_replay.py` runs T2's cache-only keyword pick
  (`s1_prefetch.market_keyword_seo`, split out of `tenant_market_seo`) for the old rule and the new one, per tenant.
- **Re-import of stored briefs**: `scripts/aa1080/brief_reimport.py` (dry run by default) parses each tenant's newest
  uploaded .docx and fills ONLY the three fields where the active version is empty, as a new version
  (`services/brand_intake/reimport.py`), and records the unmapped markets.

## Changed

- Scope item "lists the brief fields it could not map": implemented as `unmapped_fields` (sections the parser does
  not know) plus "not found" warnings for the fields it looked for (existing behaviour, now also for signature words).
- "Re-importing the 4 audit briefs fills the three fields for all 4": Brand context and CTA are filled 4/4 (drafted
  when the brief has no section). Signature words are filled only when the brief has them (quoted short phrases,
  a section, or a declared positioning word); otherwise the review screen says none were found. Inventing them
  would contradict AA-800.

## Tradeoffs

- A drafted Brand context repeats fields the brand pack already carries. It is still worth having: the F9 judge and
  T2 use `system_prompt` as the rubric head when present, and the agency can now see and edit what the writer is
  told.
- Re-running migration 262 alone revokes the 397 column grant (262 rebuilds its exact set); 397 must follow it. The
  integration test pins this.
- Recording unmapped markets at save time adds one main-pool write per save for agencies with unsupported markets;
  it is best effort and never fails the save.
