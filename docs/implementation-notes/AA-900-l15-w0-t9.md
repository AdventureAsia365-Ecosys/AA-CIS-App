# AA-900 / AA-741 — S271 lane l15: W0 for T9 (stop and label, every failing gate, interim F9)

Scope: W0 of root ADR 0020 for the T9 write loop (blog and the social / LinkedIn channels that share it). Design
inputs: the S271 writing-quality audit (README W0, decisions D1/D3/D4/D6/D15, design-review blog pick, critic fixes F5
and F15). One CIS code PR, no migration.

## Decisions

- **Attempt 3 = stop and label at $0** (`service.run_write_background`, D6 / critic F5). The paid attempts are 1 and
  2; when attempt 2 still fails, the loop stops there instead of paying for a second sentence repair and a third F9
  judge call. The piece keeps the better of attempts 1 and 2: the AA-528 regression guard already reverts a worse
  attempt 2; its floor exception ("keep a regressed floor rewrite for the attempt-3 repair") now applies only while a
  paid attempt is left (`attempt < paid_attempts`), so in W0 the guard reverts there too.
- **No code truth cut in W0.** The blog attempt-3 truth cut (AA-777), the LinkedIn last-attempt F9 cut (AA-786) and
  the attempt-3 fallback cut (S234 r3) are not reached: they live in the attempt-3 branch or are skipped
  (`if last_try and not stop_label`). D6: a cut needs a passing measurement record for its class, and none exists.
  Kept, because they are not truth cuts: the F15 stock-line cut (style), the F19 authenticity cut (AUP, a legal rule
  that outranks the rest) and the final text-integrity pass. Nothing in the loop edits tenant-authored text (the CTA
  is protected by `delete_flagged` and restored by `ensure_cta`; tenant edits come after the job).
- **Typed label** (`service._stop_label`, `gate_eval.hold_reason_codes`). Every held piece, and every piece that
  stopped instead of paying for attempt 3, ends its `repair_log` with one entry: `repair_mode` `stop_and_label` (a
  paid attempt 3 was skipped; `attempt` 3) or `label` (held, nothing skipped), `reason_codes` (one typed code per
  hold-capable failing gate, `HOLD_REASON_CODES`, plus `detector_degraded` for a hard degraded hold), `kept_attempt`,
  `cost_usd` 0, `needs_review`, `failing`. `held_reason` keeps its old string form (its readers parse the prefix).
  `gate_targeted` is `stop_and_label`, not a registered gate, so the writing-memory backfill does not count the label
  as a rewritten failure, and there is no `gate_ledger` key, so the admin drawer does not list it as an attempt.
- **Every failing gate per attempt** (critic F15, `gate_eval.failing_gates`, schema `failing/1`). Each attempt's
  `repair_log` entry gets `failing`: one row per legacy source (merged F2_lexicon / F15_voice entries counted per
  source) with gate, source, blocking, may_hold, n and, for F9_cta_fact, `classes`. `ledger_snapshot` also keeps the
  F9 `classes` and the `degraded` marker.
- **F9 classes** (`f9_policy.violation_items` / `entry_classes`): trip_promise, unsupported_other,
  fact_check_unquoted, seo_field_claim (fidelity), cta_not_reflected, text_integrity, judge_unavailable
  (infrastructure, also the pre-AA-925 "… treated as fail" text), reasonless, other. Counts keep judge_unavailable and
  text_integrity out of the fidelity baseline.
- **Interim F9 policy** (`f9_policy.apply_policy`, called in `run_quality_gates` on the F9 results, live and replay).
  F9_cta_fact stays blocking only for a quoted body claim with a non-empty why_not_in_source whose sentence names a
  concrete trip activity / service / time / view (`trip_promise_kinds`). Its violations are rebuilt with those claims
  only, in the stored format, so the sentence repair targets them alone (a combined CTA + claim violation took the
  full rewrite before; now it is sentence-repairable). Every other class warns: the entry is stored
  `blocking: false` and lands in the flags with its violations unchanged. Record: `f9_policy` {version, classes,
  warned, blocking_before}. Idempotent; the legacy mode puts a decided entry back.
- **Classifier** (`trip_promise_kinds`, deterministic, on the quoted sentence the tenant reads, never the judge's
  paraphrase). service = a service / inclusion noun with a trip subject or an inclusion verb, or a trip subject with an
  inclusion verb; time / view = a time or view phrase with a trip subject (you, we, our, travellers, guests, the group,
  this trip / tour / route, day N); activity = a reader / operator / group subject followed within three words by a
  trip activity verb ("Imagine yourself paddling …" fires: D4). A question never promises; scope-lexicon place names
  are masked first ("Sunset Point"). Built to favour precision: misses warn (still visible), they do not hold.
- **Rollback switches** (env, read per job): `T9_LAST_ATTEMPT_MODE=legacy` (paid attempt 3 + truth cuts),
  `T10_F9_POLICY_MODE=legacy` (pre-W0 F9 verdicts). Defaults are the W0 behaviour. Tests that pin the legacy loop use
  the `t9_legacy_last_attempt` fixture (tests/unit/conftest.py).

## Changed (vs the lane brief)

- The brief said "attempt 3 becomes stop and label"; the stored `attempt_number` is 2 for such a piece (the attempt
  whose text is stored), and the label entry carries `attempt: 3`.
- No migration was needed: everything is in the existing `repair_log` / `gate_ledger` / `flags` JSONB columns.
- Replay: a new `scripts/quality/replay_aa900_w0.py` instead of extending `replay_aa924.py` (that one diffs two
  trees; this one routes the stored F9 verdicts under both policy modes on one tree).

## Tradeoffs

- Kept the legacy code paths behind switches instead of deleting them (W6 is the cleanup wave). Cost: dead code in
  the default mode; benefit: a one-env rollback and the old tests keep guarding that path.
- TEXT_INTEGRITY and CTA_NOT_REFLECTED no longer trigger a repair. The final text-integrity pass still fails closed
  on duplicates / fragments, and the CTA is inserted word for word in code, so the risk is a garbled sentence that
  ships flagged instead of repaired.
- Fewer F9 holds means fewer attempt-2 repairs and fewer held labels (declared diff). The classifier's precision and
  recall are not measured yet (W2 labels); it is deliberately narrow.
