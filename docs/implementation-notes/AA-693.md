# AA-693 — A3 research: Jev keyword-belongs gate + idea filter

Design: `docs/architecture/at-series-v2-design.md` §4.2 A3-3 / A3-4.

## Decisions
- **A3-3 `_gate_keywords()`** runs right after `_propose`, before any DataForSEO purchase.
  - One `decide()` per proposed keyword, 8 at a time, with state `{place, keyword}` and question `a3_keyword_belongs`.
  - The plain place name is never asked: it is the place by definition, and it is always researched (same rule as `_propose`).
- **A3-4 `_gate_ideas()`** runs in `_buy_suggestions` before the `search_demand` upsert.
  - One `decide()` per idea that has volume, with state `{keyword, seed_places}` and question `a3_idea_traveller`.
  - Ideas are not tied to one place, so the seeds give the context.
- **Enforce-only.** A keyword/idea is dropped only when `decision.rejected()`, i.e. an enforce-mode question with a calibrated, confident reject. The questions are seeded in **shadow** (migration 182), so behaviour is unchanged until calibration (AA-661) sets floors and an admin flips the mode on /admin/decisions. Until then, every research run produces calibration data in `decision_log`.
- The job result carries `jev_keywords_checked`, `jev_keywords_rejected` and `jev_ideas_rejected`.

## Tradeoffs
- One Jev call per keyword (TypeSafe takes one state per call): about 150 ms each, 8 in parallel. A 200-place run with ~3 non-plain keywords each is ~600 calls, about 12 s and a few cents. That is small next to the DFS tasks it can avoid.
