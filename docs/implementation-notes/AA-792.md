## Decisions
- **Separate T2 builders, chosen only when `state["is_tenant_rewrite"]`.** `build_s1_system_prompt`
  returns `build_t2_system_prompt(state)` for T2; `build_s1_user_prompt` passes `voice="tenant"`.
  The A1 branch and SYSTEM_PROMPT are byte-identical (golden test: sync + Bedrock Batch, with and
  without a brand, plus the A1 nudge prompt). The Bedrock Batch path is A1-only and unchanged.
- **One rule set, two heads.** SYSTEM_PROMPT was split into pieces (`_RULE_1_CORE_FORBIDDEN`,
  `_RULE_2_BODY`, `_RULES_3_TO_6`, `_RULE_8_AND_OUTPUT`…) and re-assembled byte-for-byte, so
  `T2_SYSTEM_PROMPT` reuses the exact truth/structure rules (rule 1 core forbidden words, rules 2-5
  structure, rule 6 SOURCE FIDELITY, rule 8 meta band) and cannot drift from A1. T2 replaces the
  EDITORIAL VOICE + NEUTRALIZE PROMOTIONAL SOURCE COPY blocks with BRAND VOICE ("write as this
  brand; re-voice the source; the rules below win over the style guide"), rule 2's head says
  "this brand's voice", and rule 7 drops "base catalog" wording but keeps the budget-word ban
  (validate enforces it).
- **T2 system prompt** = T2 base + language + `render_brand_block(pack, heading="CLIENT BRAND")`
  (AA-771, read-only use) + the brand's own `system_prompt` as a "CLIENT BRAND BRIEF" (no "append
  only") + the AA-202 contrast/generic-phrasing rules (factored out of `build_brand_diff_block`
  byte-identically, so the profile is not printed twice) + the AA core + brand forbidden-words
  hard constraint. The brand pack is rebuilt from the graph state (`brand_pack_from_state`).
- **T2 user prompt** (`_USER_VOICE["tenant"]`): opening "as this client brand's own tour page",
  name/summary/day-body ask for the brand voice in EVERY day with the same facts and no neutral
  register, the seo_meta instruction loses the editorial GOOD example. The style guide is NOT
  appended to the T2 user prompt (it is in CLIENT BRAND). Per-day length and SOURCE FACTS blocks are
  unchanged.
- **Itinerary nudge** (`nudge_itinerary_day(..., voice_hint=)`): T2 passes the tenant voice words
  (`nudge_voice_hint`) at both call sites (graph `_process_itineraries` from generate + seed, and
  flag_fix's ITINERARY_STILL_COMPRESSED repair). The T2 nudge says "keep the CURRENT DRAFT's brand
  voice (…)" with no Adventure Asia / "calm, factual, editorial". A1 nudge unchanged (golden).
  Implementation note: the template is filled with `str.replace`, not `.format()` — the shared rules
  end with a literal JSON `{"title": …}` example (caught by the unit test).
- **Brand load** (`t2_rewrite_job._prepare`): `brand_pack.fetch_brand_pack_conn` (AA-771, 'default'
  row first, else newest active) replaces the hand-written SELECT. brand_rules keeps every old key
  and adds `brand_name`, `brand_type`, `default_cta`; `_rewrite_tour` maps them to `brand_name`,
  `brand_type`, `brand_default_cta` in the graph state (declared in ContentState — AA-209 strip
  gotcha). AA-741 kept: a DB error raises; the no-row path keeps `rewrite_language` and
  `_brand_loaded=False`. The T3 repair rounds reuse the same brand_rules, so they inherit it.
- **Judge — Nghiệp chose option B (Gate 1, 14/10/2026): keep the mission as a gate, but the mission
  is the TENANT's own (`tenant_brand_rules.core_idea`), never Adventure Asia's.** The first commit
  shipped a brand_fit-only default while Gate 1 was open; this is the decided rule:
  - Default `T2_JUDGE_GATE` = `brand_fit_mission`: judge_score = brand_fit, capped at 6.0 (just
    under MIN_QUALITY 7.0, so one retry fires) when `mission_present` is false. `brand_fit` (A1 rule)
    and `combined` (S234 rule, min(brand_fit, distinct), mission-capped) stay selectable by env var
    on the worker task def, no code change.
  - **Mission source:** `judge_node.t2_mission(state)` = `brand_pack_from_state(state)["core_idea"]`
    — the AA-771 brand pack field that `t2_rewrite_job._prepare` loads via
    `brand_pack.fetch_brand_pack_conn`. Before, the judge prompt only listed "Core idea" in the
    profile and asked whether "this brand's mission-hook" surfaced, leaving the judge to guess
    (S234: absent on 72/104 T2 calls, 0 of those passed). Now, for T2 with a core idea, the
    mission_present axis names it verbatim — `does THIS brand's own mission — its core idea: "<core_idea>"
    — actually surface in the ITINERARIES … never Adventure Asia's or a generic travel mission.`
  - **No core idea → no mission gate.** The cap never applies under any gate (`combined` becomes
    min(brand_fit, distinct) without the cap), the prompt keeps the old generic axis, and the judge's
    mission_present is still logged. `quality_signal` gets `mission_source` (`tenant_core_idea` |
    `none`) and `mission_gated` (bool) on T2 rows; a structlog `judge_mission_not_gated` event fires
    when a mission gate was configured but the tenant has no core idea. A1 rows keep the old key set.
  - **How the prompt changed without touching shared scoring:** `brand_fit._build_judge_prompt` and
    `score_brand_fit` gained an optional `mission=None` kwarg that only swaps the mission_present axis
    text. With `mission=None` (A1, every other caller) the prompt is byte-identical — pinned by SHA in
    `test_judge_prompt_without_a_mission_is_byte_identical_to_pre_aa792` (captured before the edit).
    The scoring, the `mission_absent_cap` inside brand_fit.py, the repeat-median and
    `score_candidate_fit` (T7 Debate) are untouched; Debate never passes a mission. A1's
    `score_brand_fit` call does not pass the kwarg at all.
  - The judge system prompt still says "Adventure Asia's B2B content pipeline" — that names the
    platform running the judge, not the mission; left as-is (shared with A1/Debate).
- **flag_fix repairs speak as the tenant on T2** (reviewer finding before the paid rerun).
  `FIX_SYSTEM` ("You are Adventure Asia's editorial fixer") and the user head "Fix these fields for
  Adventure Asia brand standards." are kept verbatim for A1. On `is_tenant_rewrite`,
  `fix_system_prompt(state)` = "You are the editorial fixer for <brand_name>, repairing a tour page
  written in that brand's own voice … Keep the brand voice the current draft already has" +
  `render_brand_block(pack, heading="CLIENT BRAND")` (read-only use of brand_pack.py), and
  `fix_user_prompt_head(state)` = "Fix these fields for <brand_name>'s brand standards (the CLIENT
  BRAND above), keeping the draft in that brand's voice." No brand name → "this client brand". The
  seo_meta re-repair loop (`_rerepair_meta`, new `system_prompt` kwarg defaulting to FIX_SYSTEM) gets
  the same system prompt.
- **AA core forbidden words still bind the tenant voice (Gate-1 default).** Rule 1 ("luxury",
  "curated", "refined"…) stays in the T2 prompt and validate's `VALIDATE_FORBIDDEN` still fires
  FORBIDDEN_WORD on T2. Flipping this is NOT a one-liner: the prompt piece (`_RULE_1_CORE_FORBIDDEN`
  in `T2_SYSTEM_PROMPT`), `forbidden_words.all_forbidden` (writer hard constraint), validate_node's
  FORBIDDEN_WORD and `forbidden_strip` all read the core list. Note: "luxury" is in the prompt's rule
  1 but not in `VALIDATE_FORBIDDEN` — prompt-banned, never validated (pre-existing).
- **Brand-audit fallback** (plan correction 7): when the judge did not run, a T2 tour is no longer
  audited against `AA_BRAND_IDENTITY_PROMPT` ("calm, assured, selective, private, no hype"). It is
  audited against the tenant's `system_prompt` or the compiled rubric (`brand_pack.compile_rubric`)
  + style guide, with a tenant-neutral user prompt; with no brand at all the LLM audit is skipped and
  only the deterministic pre-audit codes apply. A1 audit unchanged.
- **CTA is not used in the T2 tour**: a tour has no CTA field and `default_cta` is empty for 4/4
  pilot tenants. It is carried in state only for the audit rubric.
- **`is_branded` for T2** = a written system_prompt OR a T0 pack with data (`brand_pack.has_brand`),
  so the `unbranded_generation` warning stops firing for form/.docx tenants. Logging-only field.

## Tradeoffs
- Option B keeps a gate the S234 data said rejected most T2 drafts (72/104 mission-absent). The bet
  is that naming the tenant's core idea removes the guesswork; if the rerun still shows mission
  absent on most calls, the mission text (core_idea quality per tenant) is the next suspect, and
  `T2_JUDGE_GATE=brand_fit` is the no-code fallback. The rerun score script's
  `gate_not_brand_fit` check (`.tmp-session/s235/t2_rerun/score.py`) assumed the old default and
  must accept `brand_fit_mission` (judge_score = brand_fit, or 6.0 when mission is absent).
- Gating on brand_fit alone may let generic-but-on-voice copy through where distinctness was low.
  Accepted: the distinct axis cannot be answered (the judge never sees another brand's version) and
  S204 showed the reasoning judge scoring it 2-6 vs 8-9; it stays logged for AA-795.
- The brand block repeats the tenant forbidden words (CLIENT BRAND line + HARD CONSTRAINT list).
  Kept: the hard constraint is the one validate mirrors; the brand block is the T8/T9 shared text.
- AA-775 will later change `render_brand_block`'s text (style guide "never a source"), which also
  changes the T2 prompt — intended. The S235 rerun measures the pre-AA-775 text: a known confound.
- Writer + judge change in one release: the rerun cannot attribute a brand_fit gain to one of them.
  Mitigation: the metric is the judge's raw brand_fit (unchanged prompt), not the gated score.

## Pilot fix — writer and judge share one definition of "mission" (S235, branch fix/aa-792-mission-lens)

**Evidence (paid pilot after PR #704 deployed):** 4 Bhutan T2 rewrites, 27 judge calls.
`mission_present=false` on 27/27 calls. brand_fit on the last judge row per job: 7 / 7 / 7 / 5 — so
three on-brand rewrites were capped to 6.0 by the mission cap (gate `brand_fit_mission`, option B).

**Root cause:** the two sides used different definitions.
- Judge (`brand_fit._tenant_mission_axis`): does the core idea surface "in the ITINERARIES (each
  day's framing), not only in the summary".
- Writer: neither `T2_SYSTEM_PROMPT` nor `build_rewrite_prompt(voice="tenant")` asked the core idea
  to shape the days, and the CLIENT BRAND block (`render_brand_block`) says "Brand self-reference: at
  most one sentence about the brand itself" — read by the writer as "keep the brand out of the days".

**Decisions**
- Option B kept: mission stays a gate (cap 6.0 when absent); only the definition is aligned.
- Writer: new `batch_prompt._core_idea_lens_block(core_idea)` appended in `build_t2_system_prompt`
  after the CLIENT BRAND block (and brief), only when the tenant has a non-blank core_idea — the same
  source `judge_node.t2_mission` reads (`brand_pack_from_state(state)["core_idea"]`). It says the
  core idea is the lens for the overview and each day's framing, in brand voice, source facts only,
  and explicitly "not brand self-reference" (no slogans, no brand name in every day, no verbatim
  quoting, no invented claims). Placed in the system prompt (not the user prompt) because
  `build_rewrite_prompt` has no brand data and the A1 user prompt must stay byte-identical.
- `render_brand_block` text NOT edited — shared with T8/T9, owned by AA-775. The lens rule clarifies
  the self-reference line instead of changing it.
- Judge: T2 mission axis now "true when the overview AND most itinerary days reflect it in what they
  emphasise; it does not have to be quoted or named, and not every single day must carry it; false
  when only in the summary or absent". "Never Adventure Asia's or a generic travel mission" kept.
  A1 `_MISSION_AXIS` and the no-mission judge-prompt SHA pins unchanged.

**Tradeoffs**
- "Most days" rather than "every day": a transfer/arrival day rarely carries a brand idea honestly;
  demanding every day pushes the writer to invent framing (source-fidelity risk).
- Bumps T2 `prompt_version` (system prompt changes) — expected; A1 prompt_version unchanged.
