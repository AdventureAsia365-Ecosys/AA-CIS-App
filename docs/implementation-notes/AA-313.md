# AA-313 — COUNTRY_MASTER missing Pakistan + Sri Lanka typo alias

## Decisions

- **Added `PAK` as a Pakistan alias.** 16 of the 19 pre-existing entries follow an
  ISO 3166-1 alpha-3 convention (`IND`, `KHM`, `LAO`, `MMR`, `IDN`, `MYS`, `SGP`, `PHL`, `MNG`,
  `CHN`, `TWN`, `MDV`, `BTN`, `NPL`, `VNM`, `LKA`, `KOR`) — only Japan and Thailand lack one.
  Majority pattern → added the real ISO3 code, not fabricated.
- **Sri Lanka typo fix covers both match paths, not just one.** `resolve_country()` normalizes
  dashes/underscores to spaces only in the *filename* fallback branch — the direct cell-value
  branch only does `.strip().upper()`. So both `"SRI-LANDKA"` (dash, matches the raw cell value
  as-is) and `"SRI LANDKA"` (space, matches after filename normalization) had to be added as
  separate alias entries for the fix to cover both the Excel cell value and the filename.
- **Did not touch the source Excel files.** Per the ticket, `SRI-LANDKA.xlsx` keeps its
  company-wide typo; the resolver absorbs it as a known-typo alias instead.
- **Did not add Kyrgyzstan or Uzbekistan.** The audit (Step 3) found both missing from
  `COUNTRY_MASTER`, same failure mode as pre-fix Pakistan — but per Nghiep's explicit
  instruction, undetected-but-possibly-still-missing countries are reported, not silently
  added. Needs a separate confirmed decision (no `.xlsx` has ever exercised them, so the gap
  was invisible until this audit).

## Changed

- `shared/country_resolver.py`: `COUNTRY_MASTER["Sri Lanka"]` gains `"SRI-LANDKA"` and
  `"SRI LANDKA"`; new entry `"Pakistan": ["PAKISTAN", "PAK"]`.

## Tradeoffs

- Audit checklist (20 countries from Strategic Analysis v4.0 + legacy `backup.sql` 2021) is
  explicitly a starting point, not a verified-complete list — per the ticket, some countries on
  it may no longer be served. Flagging findings, not treating the checklist as ground truth for
  auto-adding entries.
- No repo-wide second source of truth exists for country lists (grepped `frontend/`, `api/`,
  `services/`) — dropdowns derive country options dynamically from DB data
  (`[...new Set(items.map(i => i.country))]`), not a static list. Confirms
  `shared/country_resolver.py::COUNTRY_MASTER` is the single place this audit needed to check.

## Should know

- **Audit result** (`resolve_country()` tried against full/upper/lower/dash/underscore variants
  of each of the 20 checklist countries):
  - Present in `COUNTRY_MASTER` (17): Thailand, Bhutan, Myanmar, Cambodia, China, India,
    Indonesia, Japan, Laos, Malaysia, Mongolia, Nepal, Sri Lanka, Philippines, Taiwan,
    South Korea, Vietnam.
  - **Missing (3): Kyrgyzstan, Uzbekistan, Pakistan** (Pakistan now fixed by this issue;
    Kyrgyzstan/Uzbekistan still missing, undecided — see Decisions above).
- Direct cell-value matching (`resolve_country(raw_value, ...)`) does **not** normalize
  dashes/underscores to spaces — only the filename-fallback branch does. Any future typo-alias
  fix needs both forms if the typo could appear in either a cell value or a filename.
- New tests: `tests/unit/test_aa313_country_resolver_pakistan_srilanka.py` — Pakistan resolution
  (cell value, filename, ISO code), Sri Lanka typo resolution (cell value, filename, both
  together, lowercase), and a regression guard that pre-existing aliases/entries are unaffected.
