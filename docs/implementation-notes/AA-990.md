# AA-990 — T9 write on a replaced atom: typed 409 `atom_replaced` (S251 slice)

Seen live on 25/10/2026: `POST /v1/content-writing/requests/{id}/write` answered HTTP 500 "atom_id='…' not found
(deleted, or not a live platform/tenant atom)" for two angle-gate requests whose atom a later atomize run had replaced.
This slice only names the condition. Carrying old requests over to the new atoms (the data side) is AA-990 proper and
is not in this branch.

## Decisions

- **One shared definition**: `services/acp_shared/atom_replaced.py` holds the code (`atom_replaced`), the tenant and
  admin sentences, a mixin `AtomReplaced` (status 409, `detail` = "atom_replaced: <sentence>", header
  `X-Error-Code: atom_replaced`) and `atom_is_live()` (the same live-atom filter T8 and T9 use when they read the atom).
  The shape copies `shared.tour_liveness.TourNotServedError` (AA-986 L3), so the portal can treat both the same way.
- **`AtomReplacedError(ContentWritingError, AtomReplaced)`** in the content-writing service: it stays a
  ContentWritingError, so every existing `except ContentWritingError` (and the existing service tests) keeps working;
  the router catches it first and answers 409.
- **Two raise sites**: the single-atom read (`_fetch_atom_text`) and the Route read when every Segment was rebuilt away
  (`_fetch_route_segments`, which was the same 500 with a "refresh the Slate" text). A Route request with no trip id
  stays a plain ContentWritingError (500): that one is a data bug, not a replaced atom.
- **Admin path** = `POST /admin/content-quality/requests/{id}/regenerate-angles`. It cloned the request with the same
  atom and enqueued `t8_angles`, which could only fail on a replaced atom. A single-atom request whose atom is not
  live now answers 409 `atom_replaced` before anything is written or enqueued. Route requests already answered 409
  when no Segment is left (AA-914), unchanged.
- **App-level handler**: `api/main.py` registers the AA-986 handler for `AtomReplaced` too, so a future raise outside a
  router `try` is still a 409 and not the generic 500 handler.

## Changed

- Tenant message: "atom_replaced: Adventure Asia has updated the part of the tour this post was planned from, so it
  can't be written from the angle you picked. Pick the angle again to write this post." The ids stay in the internal
  exception message (logs), not in the response.
- No data change, no migration.

## Tradeoffs

- The t8_angles job itself (`set_goal_and_generate`) still raises `AtomNotFoundError` for a replaced atom; it runs on
  the worker, not in a request, and the tenant already sees `generation_failed`. Left for AA-990 proper.

## Should know

- The tenant UI lives in AA-Partner now (portal moved, AA-979). It shows `detail` as-is today; reading
  `X-Error-Code: atom_replaced` to offer a "pick the angle again" action is a Partner follow-up.
- `tests/unit/test_aa899_openapi_export.py::test_committed_document_is_current` fails on the local venv only
  (fastapi 0.110.1 there vs 0.161.1 in requirements); no route or schema changed here.
