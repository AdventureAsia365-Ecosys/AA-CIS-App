# AA-1033 — AI-output notice (CIS: canonical kit component + admin reviewer screens)

Lane ai-notice, S263. Sibling notes: AA-Partner `docs/implementation-notes/AA-1033.md` (CRM web + portal),
AA-TripPlanner-Web `docs/implementation-notes/AA-1033.md` (traveller notice + terms).

## Decisions

- **One component, three variants.** `core/AiNotice.tsx` with `staff` (default), `publisher` and `traveller`. The
  issue named two variants; the portal's existing sentence ("This content was generated with AI. Review it before
  publishing; you are responsible for what you publish.") is kept word for word as `publisher`, so the portal swaps its
  local component for the kit one without a wording change, and all AI wording of the ecosystem lives in one file.
- **Wording in its own dictionary file** (`core/aiNotice.messages.ts`, `defineMessages(en, vi)`), not in
  `kit.messages.ts`: TripPlanner takes only the `tokens` profile and keeps its own B2C components (ADR 0016 decision 2),
  so the text file (plus `i18n.ts`, the one file it imports; no React) joins the tokens profile and TripPlanner renders
  the same sentence from its byte copy. The React component stays out of the tokens profile.
- **Language:** the nearest kit I18nProvider (CIS admin, portal), English outside one; a `lang` prop for apps with
  their own i18n (CRM web passes its UI language). Vietnamese written for every variant because the kit has an i18n
  table.
- **Markup:** `<p role="note">`, muted 12px + info icon (aria-hidden), `data-testid` (default `ai-notice`) and
  `data-ai-notice=<variant>`; no fixed height, no client-only content (server HTML is English, as every kit text).
- **CIS admin placements:** where a reviewer edits AI-written fields — the Review Queue drawer editor
  (`admin/review/ReviewEditor.tsx`, above the claim checks) and the S1 rewrite "Rewrite" tab of the tour detail panel
  (`admin/_components/TourDetailPanelV2.tsx`, above the editable generated fields; also used by Master Content).
  The compare modal and the live writer are views, not review actions: no notice there.
- Kit gallery shows the three variants (entry `ai-notice`).

## Changed

- `TOKENS_PROFILE` (check-kit-copy.mjs) gains `i18n.ts` and `aiNotice.messages.ts`; MANIFEST regenerated. The fallback
  lists in `.github/scripts/kit-sync.sh` / `kit_sync_bot.py` are only used for a manifest without `profiles`, so they
  are unchanged. Root ADR 0016 decision 2 is amended in the root repo PR of this lane.

## Tradeoffs

- Adding two files to TripPlanner's tokens copy vs a TripPlanner-local copy of the sentence: chose the copy so the
  legal sentence cannot drift between apps; cost is two more byte-checked files in TripPlanner (`i18n.ts` has no
  React and no issue IDs in strings, so its noIssueIds guard passes).
