# AA-845 — `a1_claim_supported` ground truth (option c) + keyword floor write-up

Owner decision (S245, 20/10/2026, root `docs/audits/2026-10-20-S245-m2a-decisions/` §3):
**(c)** — a one-off agent-panel label set of ~100 grey sentences now (~60 with p ≤ 0.20, ~40 in
0.20–0.85, Nghiệp approves the set), then the reviewer per-sentence "unsupported" action as the
long-term truth loop. **Scope item 2 changed:** a Review reject scores the whole version, so it never
writes truth=False for every sentence; truth=False is written only for a sentence a reviewer marks.
**Keyword retune approved** (`a1_keyword_about_tour` accept 0.65 / reject 0.40), applied in the
measurement wave after the "zone → system action → quality change" write-up.

This PR is the code half of (c) plus the write-up. Nothing paid ran; nothing live was changed.

## Decisions

- **Per-sentence label = one subject key.** The reviewer labels a grounding unit; the API maps it to
  the same `subject_key(unit_source(tour, unit), sentence)` the S1 run asked Jev with (the key the
  approve path already uses). One helper (`grounding.review_units`) builds units + keys for the
  approve path, the label path and the sample, so the three cannot drift.
- **Label endpoint takes the subject key, not free text.** `POST /admin/review-queue/{id}/claims/label`
  `{subject_key, unsupported}`: the key must be one of the review's current units (else 404), and it
  must have a logged `a1_claim_supported` verdict (else 409 — nothing to label: the sentence was
  edited after the check, or the row aged out). The server never trusts a sentence string from the
  browser.
- **Undo clears only the reviewer's own label** (`unsupported: false` → `outcome = NULL` where the
  stored source is `review_sentence_unsupported`). An approve label (`review_approve`, truth=True) on
  the same subject is never cleared by an undo.
- **Approve no longer overwrites a reviewer's "unsupported".** `record_outcome(keep_sources=…)` skips
  rows whose stored outcome came from `review_sentence_unsupported`, so "mark this sentence, then
  approve the rest of the version" keeps the sentence's truth=False. The reverse (mark after an
  approve) overwrites truth=True with truth=False: the explicit per-sentence act wins.
- **Reject still writes nothing** (scope change). No `record_rejected_outcome` for the whole version.
  The name in the issue is kept for the per-sentence writer: `grounding.record_rejected_outcome`.
- **`by` in the outcome JSON.** The label writes `{"truth", "source", "ref", "at", "by"}` with `by`
  = the reviewer's admin user id (header), so a label can be traced to a person. Additive key; the
  summary query reads only `truth`/`source`.
- **The panel sample is an endpoint, not a script.** `GET /admin/decisions/claim-sample` rebuilds
  sentences + per-unit sources from the latest master version of a seeded random set of active
  tours, joins each unit's latest `a1_claim_supported` (+ `a1_promise_unsupported`, for AA-803)
  verdict and returns a stratified, reproducible sample (seed). $0 (no Jev, no LLM). Reason:
  `decision_log` stores only the subject key (no sentence, no source), so the sample must be rebuilt
  from content; a read endpoint makes it repeatable and avoids an ECS-exec script (`scripts/` is
  gitignored, lessons).
- **Strata default to the memo:** `low_max=0.20`, `high_max=0.85` (current accept floor), 60/40,
  at most 3 sentences per tour, numeric hits flagged (`numeric_hit`) but kept — the calibration
  record says the reject side only matters for non-numeric sentences, so the panel report must
  split by it.
- **No new migration.** `decision_log.outcome` (TEXT JSON) already exists; no new column.

## Tradeoffs

- **Undo sets NULL, not the previous outcome.** If a sentence carried an approve label before the
  reviewer marked it, undo leaves it unlabelled rather than restoring truth=True. Rare (approve then
  mark then undo) and the safe direction (no label beats a stale one).
- **Labels live on `decision_log` rows**, so a sentence with no logged verdict cannot be labelled
  (409). The UI disables the button for those rows and says why. A separate label table would keep
  them, but such labels could not be compared with a Jev verdict anyway.
- **Sample is per latest version**, not per review row. Older versions' sentences are not sampled;
  the grey population of the current master content is what a reject ceiling acts on.
