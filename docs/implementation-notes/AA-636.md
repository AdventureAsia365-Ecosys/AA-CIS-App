# AA-636 — Tenant portal trust fixes

## Decisions
- **Removed the "Re-rewrite balance 2/3" Dashboard card entirely.** No per-tour re-rewrite limit
  exists anywhere in the backend (grep: no `re_rewrite`/`free_rewrites`); the numbers were literals.
  Its slot is taken by the AA-638 getting-started card.
- **Tenant money view = plan fee + overage ("Amount due")**, not LLM cost. `llm_cost_usd` stays in the
  `/v1/billing` response (no API break) but is no longer rendered.
- **Usage alert threshold 80%** (was 30% on API calls only, with "Growth plan = 300 RPM" hardcoded).
  Now fires on either tours or API calls; links to Billing.
- **Quota reset** = first of next month UTC — the rule the backend already enforces
  (`_current_year_month_and_reset`); read from `/v1/quota.resets_at`, client fallback computes the same.
- **Settings made honest instead of wiring fake controls to nothing:** there is no tenant email
  column (`shared.tenants` has none), no tenant self-service rename / key rotation endpoint, and the
  notification toggles / default language / SEO mode were local state only (the rewrite config tab
  was deliberately removed in AA-566 Phần D). Settings now shows real company + plan, a contact
  path for changes, API docs link, and a plain "Sign out" (the old "Sign out of all sessions" only
  ended the current session).
- **Contact email → `info@adventure.asia`, site → `https://adventure.asia/`.** The portal used
  `admin@adventureasia.com` + `adventureasia.com/contact` (404; not AA's domain). Centralised as
  `SUPPORT_EMAIL` / `SITE_URL` in `app/_brand/tokens.ts` — flagged to Nghiep to confirm the address.
- **Bell = notifications panel over existing activity** (no new backend); unread dot from a
  per-browser last-seen timestamp in localStorage (wrapped in try/catch).

## Changed
- Backend `GET /v1/billing`: + `rate_limit_rpm` (tenant's own, `shared.tenants`), + `plans`
  (`shared.membership_plans`, active, excluding `internal`; rpm from `PLAN_LIMITS`, `None` when absent).
- Frontend: `PageHeader`/`TextLink` in `ui.tsx`; Dashboard, Billing, Settings, Activity, ApiTab,
  Browse Tours + My Catalog headers; `NotificationsBell.tsx`.

## Tradeoffs
- Did not add tenant self-service account editing — needs product decisions (who may rename, email
  verification). Contact path is honest now; real self-service can be its own issue.

## Should know
- **Plan-limit mismatch (not fixed, needs Nghiep):** display reads `membership_plans`
  (starter 50 / growth 200 / business 500 tours), but the 429 enforcement in
  `_check_and_consume_rewrite_quota` reads `PLAN_LIMITS` in `admin.py`
  (starter 100 / growth 500 / business 2000). A Growth tenant sees "0 / 200" but is only blocked at 500.
