# AA-641 — flag_fix must not create new hard failures

## Decisions
- **Shared forbidden list.** `VALIDATE_FORBIDDEN` and its matching rule move to a neutral module `services/content_generation/forbidden_words.py` (graph.py imports flag_fix_node, so flag_fix cannot import graph.py; same reason `seo_meta_utils.py` exists). `graph._VALIDATE_FORBIDDEN` stays as a re-export, so `admin_pipeline.py` and the review-queue code keep working. The matching rule is identical to validate_node: substring of the lowercased `json.dumps`.
- **Part A — `fit_seo_meta()`** in `seo_meta_utils.py` reuses `_salvage_to_band` (AA-239). There is no second trimmer. T3 calls it next to `fit_seo_title` before deciding to rewrite.
  - Forbidden set: `SEO_META_FORBIDDEN` ∪ the tenant's words.
  - With no valid candidate (e.g. a meta that is too short), the meta is returned unchanged.
  - A1 already has the same guard inside flag_fix (`best_meta_candidate` + `_rerepair_meta`), so it needed no change.
- **Part B — per-field revert.** flag_fix now lists the forbidden words in its prompt ("NEVER USE…"). After the repair, `_revert_introduced_forbidden()` restores the pre-repair value of every field whose repair **added** a forbidden word, logged as `flag_fix_introduced_forbidden`. The guard applies to the generic pass and to the per-day itinerary repair (`ITINERARY_STILL_COMPRESSED`).
  - A reverted field is not reported in `fix_pass_fields`.
  - A field that already contained the word keeps its repair.

## Changed vs issue
- Also guarded: the per-day itinerary repair path (not named in the issue; it is the same kind of LLM rewrite).
- Small fix found on the way: a blank tenant forbidden word (`" "`) used to become `""`, which matches every text, so `FORBIDDEN_WORD` always fired. `all_forbidden()` now drops blank words.

## Tradeoffs
- A revert can bring back the soft/length problem the repair was fixing. That is accepted, per the issue's risk section: a soft problem costs nothing, a new hard code costs a full rewrite. If the original field had a hard failure, T3 decides as before.
