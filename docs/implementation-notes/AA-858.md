# AA-858 — Ops overview backend (`GET /admin/overview/ops`)

Branch `feat/aa858-ops-overview-api`, built on `feat/aa884-platform-apps-api` and rebased onto `origin/main` once
CIS #835/#836 merged (347e66b1). The UI is a separate PR
(`feat/aa858-ops-overview-ui`, notes in `AA-858-ui.md`).

## Decisions
- **The cost card is built on AA-884's module** (S243 critic finding 5). `api/services/ops_overview/cost.py` only
  calls `api.services.platform_cost.cost_by_app()` (this month and last month) and reshapes the rows into plain
  labels. It has no Cost Explorer code and no SQL on the cost snapshot, so `/admin/overview` and
  `/admin/platform/cost` always show the same numbers. The lazy CE refresh (24 h, Redis SET NX lock, per-window attempt
  marker) is AA-884's; this lane does not add another one. `shared/aws_client/cost_explorer.py` is not edited (the
  plan's `get_ce_client` wrapper is not needed any more).
- **AI spend by app** comes from that module too (`quality_signal->>'app'`, `llm_call_log` + `llm_call_daily`), not
  from the `tp_` stage prefix the original plan proposed (critic finding 5: the two pages would disagree).
- **Health = CloudWatch only**, one `GetMetricData` call (16 metric queries) + paginated `DescribeAlarms` (all alarms,
  filtered by name prefix in code; `TargetTracking-*` autoscaling alarms skipped). API Gateway metrics use the
  `ApiName` + `Stage` dimensions, the same pair the Infra alarms use (observability_ecosys.tf), stage = `ENVIRONMENT`.
  TripPlanner = the two Lambdas (browse + assembly) summed; its p95 is the slower function's.
- **Daily p95** uses a 24 h period query; CloudWatch may split a non-aligned window into 2 buckets, so the worst bucket
  is reported (conservative).
- **Booking / TripPlanner numbers** come only from the producer contract views `booking.v_ops_funnel_daily`,
  `booking.v_ops_case_status` (bk-017, Booking #37) and `tripplanner.v_ops_traffic_daily` (tp-015, TP #98). No
  `booking.*` / `tripplanner.*` table is read. A missing view or grant (`UndefinedTable`, `InvalidSchemaName`,
  `InsufficientPrivilege`) turns that card into `status: unavailable, reason: contract_view_missing`.
- **AI searches** = `shared.llm_call_log` rows with `stage = 'tp_search_embed'` (a CIS table; index
  `idx_llm_call_log_stage_created`). Raw rows are kept 180 days (AA-825 retention), so the 14-day window never needs
  `llm_call_daily`. Cache hits are not logged, so the number under-counts; the response says so.

## Changed (vs the plan)
- No `get_ce_client` wrapper, no own CE calls, no `fetch_untagged_top_services` (AA-884's snapshot already has the
  untagged row's services), no stacked **daily** cost chart: `cost_by_app` has no per-day breakdown, and computing one
  from the snapshot table would be a second way to compute spend. The card shows this month vs last month per app.
- Cache: per section (`admin:overview:ops:<section>:v1`), health 300 s, TripPlanner 300 s, Booking 300 s, cost 900 s
  (the cost module's own markers limit CE calls; the 15-min cache only saves DB reads). The plan's 12 h cost cache is
  moot because the CE call is not ours.

## Tradeoffs
- **No AWS call without Redis.** Health needs the cache (and its SET NX lock): Redis down → `unavailable:
  cache_offline`, never a CloudWatch call per page view. Cost without Redis still renders from stored data
  (`cost_by_app(redis=None)` never calls CE). DB-only sections compute directly when Redis is down.
- **Stampede:** the health section takes a SET NX lock while computing. A request that loses the race gets the
  last good value (kept 24 h under `:last`), or `unavailable: refreshing` when there is none yet.
- Failures are cached 60 s (not 300 s), so an IAM fix shows within a minute without hammering AWS.
