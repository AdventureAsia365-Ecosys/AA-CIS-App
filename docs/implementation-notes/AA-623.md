# AA-623 follow-up — Cost Explorer panel: Bedrock vs infra split + page-wide date range

Follow-up to AA-623 (PR #426/#427/#428), opened 23/09/2026 after Nghiệp cross-checked the live panel
against the Cost Explorer CSV exports for acc1/acc2/acc3 (Sept 2026).

## Decisions
- **Split Bedrock vs infra per account** instead of one account total. A CE SERVICE counts as
  Bedrock when its name contains "Bedrock" (`Amazon Bedrock`, `Claude … (Amazon Bedrock Edition)`,
  `Cohere Embed 4 Model (Amazon Bedrock Edition)`, `Palmyra X5 (Amazon Bedrock Edition)`); the
  same 4-line-item split `infra/.../observability.tf` already recorded.
- **Compare like with like:** "Bedrock actual" (CE) vs "Bedrock estimated" = `llm_call_log`
  rows on acc1/acc2/acc3 only (OpenAI/legacy excluded; never on an AWS bill), same window.
- **One time window for the whole page:** presets (7/30/90) or a custom from/to (UTC calendar days,
  "to" inclusive, "to" empty = today). Every endpoint (`llm-usage/tree`, `llm-usage/calls`,
  `dfs-usage`, `dfs-usage/by-country`, `spend/daily`, `cost-explorer`, `cost-explorer/check`)
  takes the same `days` | `start`/`end`. Max 366 days, start > end → 422.
- **GET /admin/cost-explorer reads a date range across all stored fetches**, newest fetch per
  (account, service, day) wins — no longer "only the latest batch". So older Refreshes stay usable
  and CE's upward revisions of the last ~48h replace older values.
- No migration: `shared.cost_explorer_snapshot` already stores one row per day (DAILY granularity).

## Changed
- `shared/aws_client/cost_explorer.py`: `_fetch_one_account_cost` follows `NextPageToken`
  (DAILY × GroupBy SERVICE paginates on longer windows — the old code kept page 1 only, so a
  30/90-day fetch would have silently dropped days). `read_latest_snapshot` → `read_cost_range`.
  New `is_bedrock_service`.
- `api/routers/admin_llm_ops.py`: `_resolve_window` / `_ce_days` helpers; SQL filters switched from
  `now() - N days` string interval to explicit `[$1, $2)` timestamptz params.
- FE `app/admin/llm-usage/page.tsx`: date-range picker; CE panel = 3 stat cards (Bedrock actual,
  Bedrock estimated, AWS infra) + per-account table (Bedrock actual / estimated / infra / total) +
  top-10 services + gap warning when stored CE days don't cover the window. Account labels in the
  CE table no longer say "(Bedrock)" — acc2 is "hạ tầng chính".

## Tradeoffs
- Rolling presets are `now() - N days` for LLM/DFS but whole UTC days for CE (CE is day-granular),
  so a 7-day preset can include up to ~1 extra partial day on the CE side. Custom dates align both
  exactly — use them for reconciliation.
- Refresh still only fetches the current window (3 CE requests ≈ $0.03 per click regardless of
  window length). No scheduler added: `/admin/cost-explorer/check` is still manual-only (the
  original comments claimed a daily EventBridge job — there is none; comment corrected).
