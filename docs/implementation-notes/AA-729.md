# AA-729 — golden set + scoring harness for audit rounds

Spec: Linear AA-729 (Done-when line 3 reworded S245) and the decision memo in the private root repo
(`docs/audits/2026-10-20-S245-m2a-decisions/README.md` §1, option a: 100 samples, two modes, cap $15, trial 3).
Code: `scripts/aa729/` (not part of the image; shipped to the api container as a tarball through S3).

## Decisions

- **Mix** (memo option a): 50 S1/Master tours, 10 T2 tenant versions, 15 T9 blogs, 15 T9 LinkedIn posts,
  10 prompt-injection samples (5 S1-shaped, 5 T9-shaped: 3 blog, 2 LinkedIn). Seeded selection (`--seed`,
  default 729): candidates are sorted by id, shuffled with `random.Random(seed)`, then stably re-sorted so
  samples that already carry a human label come first inside every stratum.
- **Hard cases are quotas, filled first** (round-robin across countries / tenants so one country cannot fill a
  quota): S1 cycle/bike 6, poor raw 6 (raw itinerary + description chars at or below the 15th percentile of
  the active tours), 18+ days 6, known failure 10; T2 known failure 4; T9 held 5 per channel. The rest of
  each stratum is allocated by largest remainder over countries (S1) or tenants (T2/T9), at least one per
  group while the budget allows.
- **What counts as a label (not circular).** A label must come from a decision the pipeline did not make
  itself: S1 review-queue outcome (`approved`/`rejected`), admin edit (`generated_content.human_edited`),
  a Jev outcome a reviewer stamped (`decision_log.outcome` truth=false on the tour's `s1_rewrite` jobs);
  T2 tenant approve/reject, tenant edit (a `tenant_edit` child version), admin sentence edit, review-queue
  outcome; T9 human label (`acp_shared.content_piece_label`), admin sentence edit, tenant hand edit;
  audit-round verdicts passed in with `--audit-labels`. The pipeline's own verdict (Master active, version
  status/QA, piece approved/held) is kept as `pipeline_verdict`, never as the label — using it would make
  judge-vs-label disagreement measure the judge against itself. Everything else is
  `label_source = "needs_panel"`, labelled by an agent panel (`labels.py`) and approved by Nghiệp.
- **Injection samples are synthetic** (`injection.py`): a fictional tour / seed carrying an injected
  instruction with a canary token. Regenerate mode feeds the poisoned input to the real writer and checks the
  canary, the injected link, markup and prompt-leak phrases are absent (`label_source = "synthetic"`, expected
  verdict pass = defended). Score-only mode judges a frozen *compromised* output (the injection obeyed;
  expected verdict fail). T9 injection samples borrow a selected piece's tenant context (brand pack, CTA,
  goal, angle) and replace only its seed, so the writer sees a real brief.
- **Every model call is logged under `adhoc_aa729` without touching the gateway code.** `evalpatch.install()`
  rewrites the process's `shared.llm_client.call_log._INSERT_SQL` so every row this process writes gets
  `stage = 'adhoc_aa729'` and `quality_signal.aa729_stage` (the real stage) + `quality_signal.aa729_run`.
  The real stage still picks the route and model; Jev rows (provider `typesafe`) and embeddings are caught too,
  because they share the same INSERT. Each sample runs under `call_log.bind_job(<uuid5(run, sample)>)`, so
  `llm_call_log.job_id` and `decision_log.job_id` carry a per-sample id (neither column has a foreign key).
- **No write to app data.** The harness patches, in its own process only: `service._finalize_piece` and
  `service._insert_placeholder_piece` (T9 output is captured, never stored), `flag_fix_node._write_lessons_safe`
  (no eval lesson reaches `shared.pipeline_lessons`), `LLMClient._start_shadow` (no shadow A/B call, no
  `llm_shadow_log` row). S1/T2 run `_rewrite_tour` / the revalidation graph / `run_t3_qa_gate`, which are pure
  (the persist steps live in `_execute_run_tour` and the T2 job, which are not called). What still lands:
  `llm_call_log` rows (wanted) and Jev `decision_log` rows tagged with the per-sample job id.
- **Frozen inputs, no DataForSEO.** S1 SEO is the tour's `seo_context` row in the `load_fresh` shape (no
  freshness filter), so regeneration never buys DFS. T2 SEO is the job's own lookup (tenant-market cache,
  else `seo_context`). T9 input is the piece's `writer_input` (seed, route moments, Facts, brand pack, CTA,
  keyword, scope) over the `t9_write` job payload context when the job row still exists, else over the
  angle request (goal, chosen angle) — `facts_pending = False`, so the writer gets exactly the stored source.
- **Cost guard.** `--max-cost-usd` (default 15) is checked before every sample against
  `SUM(cost_usd) FROM shared.llm_call_log WHERE stage = 'adhoc_aa729' AND quality_signal->>'aa729_run' = run`
  (and against the in-process sum of `LLMResponse.cost_usd`, whichever is higher), plus the estimate of every
  sample in flight and of the next one. It stops launching samples; running ones finish. A resumed run keeps
  its run id, so the cap covers both parts.

## Changed

- Nothing in the app code. The harness depends on private names it patches (`call_log._INSERT_SQL`,
  `service._finalize_piece`, `service._insert_placeholder_piece`, `flag_fix_node._write_lessons_safe`,
  `LLMClient._start_shadow`); `tests/unit/test_aa729_golden_set.py` fails if one disappears or the INSERT's
  column list changes, and `evalpatch.install()` refuses to run in that case.
- The committed fixture lives in the private root repo (`docs/eval/aa729/`), not here: this repo is public and
  the fixture carries tenant pieces and Master tour text. This repo carries the code and synthetic test data.

## Tradeoffs

- Judge-vs-label disagreement is computed in **score-only** mode only: a label describes the frozen output, not
  a freshly written one. Regenerate mode reports pass-rate, writer calls and cost, plus pass-rate split by the
  frozen label ("inputs whose old output was labelled fail that now pass").
- A frozen output that a human edited in place (S1 `human_edited`, T9/T2 admin sentence edits) is the edited
  text, while its label describes the AI original. Those samples are marked `output_post_edit` and left out of
  score-only disagreement; they stay in the set because they are known failures for regenerate mode.
- T9 score-only replays the T10 gate stack (`run_quality_gates`, F9 judge included) on the stored final text,
  without sibling texts, cannibalization or the post-gate integrity/cut steps of `run_write_background`. It is a
  gate verdict, not a full re-run.
- S1 regenerate copies the AA-736 Sonnet retry rule of `_execute_run_tour` (rewrite-class hard code on Haiku →
  one Sonnet rewrite, keep it if fewer hard codes survive) instead of calling `_execute_run_tour`, which writes
  versions, scores, review rows and exports. The AA-237 opt-in upgrade is off by default there and here.
- Sequential by default would take ~5 h for the regenerate baseline; `--concurrency` (default 3) runs samples
  in parallel inside one process. The cost guard reserves each in-flight sample's estimate.

## Should know

- Scripts run in the api image as `cis_app` (container `DATABASE_URL`), from `/app`, with the package unpacked
  under `/tmp/aa729`: `cd /app && PYTHONPATH=/tmp/aa729 python3 -m scripts.aa729.<module>`. Long runs go in a
  one-off ECS task (lessons: an exec session or a deploy kills a long adhoc run); outputs and a per-sample
  checkpoint go to the bronze bucket under `scripts/out/aa729/`, and `--resume RUN_ID` continues a stopped run.
- `score.py` refuses a paid mode while `shared.job` has queued/running rows (lessons: no paid run during a wave)
  unless `--allow-busy-queue`.
- Report numbers come from `llm_call_log` (stage `adhoc_aa729`); lessons require checking them against the
  provider dashboards before quoting them.
- The task role is only known to write the bronze bucket under `scripts/`; the fixture, the code tarball and a
  resume checkpoint reach the container through presigned URLs (`curl`), never `get_object`.
- The PII scrubber also masks an e-mail address or phone number inside a frozen *input* (a brand CTA, a source
  tour). The writer then sees `[email removed]`; that is the price of a fixture with no personal data.
- `scripts/` is git-ignored in this repo; the harness is tracked with `git add -f`, like the other adhoc scripts.
- `tests/unit/test_aa729_golden_set.py` also fails if a second `INSERT INTO shared.llm_call_log` appears in app
  code (eval rows could then escape the relabel).
