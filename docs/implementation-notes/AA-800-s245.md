# AA-800 (S245) — tenant signature vocabulary: three-layer word list

Branch `feat/tenant-signature-vocabulary`, stacked on `fix/f9-sticky-carry-over-repaired-sentences`
(both touch `services/acp_content_writing/quality_gates.py`).

## Decisions

- **One home for the layers**: `services/acp_shared/signature_vocabulary.py`. T2 (content_generation)
  and T9 (acp_content_writing) both import it; `acp_shared` already holds the brand pack.
  - Layer 1 `PLATFORM_TRUTH`: cheap, deal, book now, instant booking, discount. Blocked for every tenant.
  - Layer 2a `STOCK_SUPERLATIVES`: pristine, stunning, breathtaking, magical, paradise. A1 blocked
    (unchanged); T2/T9 at most 1 per piece (`SUPERLATIVE_CAP`), the 2nd one makes them all blocking.
  - Layer 2b `POSITIONING`: curated, refined, tailored, bespoke, luxury. A1 blocked (unchanged); T2/T9
    allowed when the tenant declares it as signature vocabulary.
  - Layer 3: the tenant's own `forbidden_words`. Always blocked, and always wins over a declaration.
- **`VALIDATE_FORBIDDEN` stays the same literal list in the same order** (A1 validate, flag_fix, the
  strip, a3_atomize and the A1 review-queue scan are untouched). A test pins it to the union of the
  layers minus `luxury`.
- **"luxury" is prompt-only, as before.** It is in A1 prompt rule 1 but was never in the validate
  list. For T2 it stays a prompt word (listed under NEVER unless declared), not a validate word: making
  it a new FORBIDDEN_WORD for undeclared tenants would add holds that never existed. An unsupported
  luxury *claim* is caught by the evidence rule instead, for every tenant.
- **How a tenant declares signature words (no migration)**:
  1. derived from its own T0 text: brand_type, core_idea, voice words, style guide, on-brand example;
     a word counts only in a clause with no negation before it ("Do not use bespoke", "avoid luxury
     clichés", "depth over luxury" do not declare it);
  2. or an explicit list in `tenant_brand_rules.custom_validators` (jsonb, already present, not read by
     anything before): `{"signature_words": [...]}` or a list holding such an object.
  Only the five positioning words can be declared; a word the tenant forbids is never declared.
  Atlas & Hearth's live brand_type is "Luxury cultural travel brand", so `luxury` is declared with no
  data change.
- **Evidence rule** (`service_level_claims`): a positioning word right before a service noun ("luxury
  lodge", "tailored itinerary", "bespoke service", up to 2 words between) needs a supporting root in the
  source (luxury: luxur/deluxe/five-star/5-star/premium; tailored/bespoke: tailor/bespoke/customi/
  personali/private; curated: curat; refined: refine). Brand-level words ("a luxury journey") are not
  service claims and are not checked. Applies to every tenant, declared or not.
  - T2: added to the T3 grounding check (T3 is T2's fidelity gate), as a grounding item with
    `unsupported_claims` and no numbers; the T3 sentence repair handles it (prompt names the claim).
  - T9: added to F17_trip_fact (sentence-repairable, blocking), so the existing repair/cut wiring applies.
- **T9 word gates** (`quality_gates.py`, right after F2_brand_forbidden, every channel):
  - `gate_platform_truth` → `F2_platform_truth`: blocking, sentence-repairable (T9 never checked these
    words before). Also in `sentence_repair.check_replacement`, so an admin edit cannot add one.
  - `gate_signature_words` → `F2_superlatives`: blocking only when there is more than one stock
    superlative, quotes every one after the first, sentence-repairable on the cheap stage, and
    style-only (`STYLE_ONLY_GATES`: one repair, never a hold — AA-613, a style word is not product truth);
    and `F2_style_warn`: warn-only, one superlative or an undeclared positioning word.
  - Source carve-out as F2: a word in the seed, the CTA or the trip name is never a finding (a tenant
    CTA "Book now …" is published word for word and must not hold every piece).
- **T9 positioning words are a warning, not a block.** T9 never refused curated/refined/luxury before;
  making them blocking for undeclared tenants would add holds with no measurement behind it. The writer
  prompt's WORDS line asks it to avoid them.
- `breathtaking` leaves `_BANNED_PATTERNS_SEED` (it is a layer-2 superlative now, capped, not banned).
  The T9 system prompt still lists it under clichés to avoid (unchanged): the writer is asked to avoid
  it, the gate only blocks the second one.

## Changed

- New `services/acp_shared/signature_vocabulary.py` (layers, declaration, blocked list, superlative
  count, evidence rule, T2 rule 1 and T9 WORDS line builders).
- `brand_pack.pack_from_row` reads `custom_validators` → `signature_words`.
- T2: `forbidden_words.state_forbidden(state, content)` (A1 → `all_forbidden`, unchanged; T2 → layered)
  used by validate_node, the write-time/revalidate strip (`strip_forbidden(..., words=)`), flag_fix's
  revert guard and repair prompt, and the T2 HARD CONSTRAINT block. validate_node fires a soft
  `STOCK_SUPERLATIVE` code (no deduction) for exactly one superlative in a tenant tour.
- T2 prompt: `prompts.build_t2_base_prompt(pack)`; `T2_SYSTEM_PROMPT` = the base for a tenant with no
  signature words. Rule 1 for a tenant: NEVER (undeclared positioning incl. luxury + platform truth),
  superlatives at most one, the signature words allowed with the service-claim caveat.
- State plumbing: `brand_signature_words` (graph state, `_rewrite_tour`), `brand_rules["signature_words"]`
  via the new `t2_rewrite_job.brand_rules_from_pack` (reused by the admin apply check).
- T3: `_t3_structural_issues` validates as a tenant rewrite with the brand fields (it used to run
  validate as A1, so it applied the full AA list); `_t3_grounding_check` adds `unsupported_claims`;
  feedback, the sentence repair (prompt, still-unsupported test, layered forbidden list) and the review
  queue escalation describe the claim. `grounding._repair_prompt` names the claim (A1 never carries it).
- T9: `breathtaking` out of `_BANNED_PATTERNS_SEED`; new F2 gates above; `trip_facts.service_claims` in
  F17; WORDS line in `build_user_prompt` (blog hashes re-captured in the AA-771 guard test, only that line
  changed — verified by diffing the rendered prompts against the base branch).
- Admin T2 drawer (`admin_content_quality.t2_flag` / `t2_check_replacement` / apply): the layered list,
  the claim check; `t2_flag` accepts the pack (a word list still works).
- Tests: new `tests/unit/test_aa800_signature_vocabulary.py` (29 tests); updated expectations in
  aa450 / aa452 (gate ledger +3), aa769 / aa791 (breathtaking → unforgettable as the banned-pattern
  example), aa771 (blog hashes), aa792 (T2 rule 1), aa802 (one superlative no longer flagged).

## Tradeoffs

- Negation detection on brand text is a heuristic; a declaration it misses is fixed by the explicit
  `custom_validators.signature_words` list.
- Density is counted over the writer-authored fields of the whole piece/tour (metadata skipped).
