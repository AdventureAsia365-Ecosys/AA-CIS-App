# AA-1127 — UI fixes, CIS: Studio money and counters, numbers that disagree, spend truth

Source: the S283 UI audit (root `docs/audits/2026-11-17-S283-fe-audit/`, section 6 and `rows.json`). Order set by the
tech lead: S1 (Studio money and counters, CIS API + admin part), C1 (numbers that disagree), C2 (spend truth). The agency
web part of S1 (quote lines and discount on the studio dashboard and billing, the "Live: earlier version" label, the
My Tours quick action wording) belongs to the agency app issue, not here.

## Decisions

- **S1 one rewrite ledger = the quota counter `shared.tenant_rewrite_usage`.** It is the row `GET /v1/quota` reads,
  the only row the hard over-quota mode enforces atomically, and the row the partner report EX-03 reads; it is
  incremented in the transaction that accepts a rewrite (validate first, charge last, AA-741). CIS 448 (migration-only
  PR) makes `shared.v_tenant_monthly_usage.tours_rewritten` read it, so `/v1/billing`, the admin tenant list,
  Tenant 360 and the billed overage show the same number as the quota meter. The alternative (count tenant tour
  versions everywhere) was rejected: it would bill a tenant's own inline edits as rewrites, needs a per-tenant lock to
  enforce the hard mode, and would move the EX-03 report.
- **A tenant edit is not a rewrite.** The dashboard's per-day rewrite line (`/v1/billing` `daily`) counts only versions
  with `edit_source IN ('ai_generated', 're_rewrite')` (`v1_tours.REWRITE_EDIT_SOURCES`).
- **One live post per request and channel.** `REQUEST_LIVE_SQL` in `api/routers/v1_publish.py` is shared by the
  Publish list (`_PENDING_SQL`: such a piece is not offered) and `publish()` (`_PUBLISH_PIECE_SQL` → 409
  `PUBLISH_REQUEST_LIVE`). A post taken down (unpublished / failed) no longer blocks; a live post on another channel
  does not block (a request's channel can change before a re-write).

- **C1 numbers that disagree, one source each.**
  - Overview funnel "In review" counts the aa_internal queue only (`rev_c` gets `rq.tenant_id`), like the Review
    Queue and its nav badge; agency T2 review rows made it 75 against 73.
  - Master Content audit badge: one helper (`frontend/lib/brandAudit.ts`) knows the backend's `fixed` status.
  - Supply content: one `draftBlockers` list drives the blockers box and disables Publish.
  - AI gateway "Need a look" follows the row badge (`statusWordKey`): an idle LLM / guard row ("No recent calls")
    is not counted. The idle window is the new setting `cis.llm.idle_after_hours` (CIS 449, area "ai", default 6 =
    the old `STALE_OK_HOURS`), read by `llm_availability.idle_after_hours()`; `STALE_OK_HOURS` stays only as the
    stand-in while the registry cannot serve the key (it is in the S279 rest baseline).
  - Tenant 360: the Tours tab label reads `pagination.total` and pages on the server (the tenant branch now honours
    page / page_size, LEFT JOIN so every counted version is listed); "Pipeline (latest 20)" from
    `summary.pipeline_runs_shown` (`PIPELINE_RUNS_SHOWN`, a display window).
  - Photos "Tours with photos": base and covered read one served-tours set (`SERVED_TOURS_SQL`, the
    shared/tour_liveness rule of Places), not every active raw row.
  - Reference prices: a "Suggested" filter and tile (the API already counted and filtered it).
  - SEO intelligence: one `_USED_CTE` for the Keywords tab and the demand totals; buyer markets only (`_MARKETS`,
    "US-PAA2" is the PAA top-up storage key); demand carries `linked_volume` / `linked_keywords`; keywords linked first;
    the page opens on linked keywords (a UI filter, default on).
- **C2 spend truth.** `platform_cost.provider_family("anthropic") == "anthropic"`: the Spend forecast gets an
  "Anthropic API" row with its Budgets-tab budget (`FORECAST_PROVIDERS`; optional rows appear with spend or a budget),
  and the FI-02 weekly lines and total gain an Anthropic API line. `cost_explorer.account_key()` names a live Bedrock
  satellite of the registry by its connection key (matched by `resolved_account_id`, the `accounts.account_name` rule)
  instead of "retired".
  - Review fix pass: the Spend forecast shows such a satellite as its own AWS row (`cost_ops._satellite_keys`, only
    with data this month; before, its rows moved off "retired" and fell out of the forecast while the AWS bill tab
    showed them). The Bedrock split orders acc3, the satellites, acc2, retired.
  - The FI-02 weekly report splits Bedrock with the forecast's rule (`cost_ops.ledger_account`, was `_account_of`):
    a live satellite is the line "Bedrock on the serving account (gateway estimate)", counted in the week total (no
    Cost Explorer figure exists for it), and a vendors row; only unknown accounts stay `bedrock_retired`.
  - The AI gateway Providers read returns `totals.llm_month_usd` / `totals.llm_month_by_family` from
    `platform_cost.ai_spend_by_provider` (rolled-up + raw days, `provider_family`), the Overview / Spend / Platform cost
    figure, apart from `totals.month_usd` (which adds DataForSEO, Geoapify and the CRM rows). The Month tile of the
    page shows it as its hint (admin UI PR).

## Changed

- AA-802's integration test `test_older_published_piece_does_not_hide_a_newer_version` asserted the opposite rule (a
  re-write after a publish was publishable). The S251 My Content rule and the audit replace it; the test now asserts
  the refusal and two new cases (taken down → publishable; other channel → publishable).

## Tradeoffs

- The two `ai_generated` versions of 8 Nov the audit saw without a counter row disappear from the billed count. The
  only writer of AI versions (`trigger_rewrite`) increments the counter in the same transaction, so such rows come
  from a seed or a script, not from a real rewrite; billing follows the quota.
- The per-day line still counts versions (the counter has no day): a failed rewrite keeps its version row and its
  counter increment, so the two agree for every real path.

- The daily Cost Explorer check + stale badge (audit C2, about 0.02 USD a run) is not built: it is a paid AWS call that
  needs the tech lead's explicit yes (cost policy).
- The gateway's per-connection spend rows still read the raw ledger (they need today's spend and the newest call per
  connection); only the page's LLM month figure reads the shared rollup-aware total. The two can differ only by raw
  rows of rolled-up days (a tenant erasure merges its rows into the rollup).
- SEO: the generic-term exclusion list proposed in the audit is not built (it needs a Catalogue setting); linked-first
  ordering and the linked-only default answer the finding without a list.
