# AA-879 — CI gate parity (AA-CIS-App part)

Scope here: required-to-be type-check + build for both Next.js apps, a blocking Trivy scan, a coverage
ratchet, and the ECS deploy path filter. Booking and TripPlanner get their own PRs; the U-61 connection
budget check lives in AA-CIS-Infra.

## Decisions

- **Two new jobs, "Frontend Build" and "Portal Build"** (`npm ci`, `tsc --noEmit`, `next build`), not
  steps inside the existing lint jobs. The lint jobs keep a step-level `continue-on-error` for the AA-601
  legacy ESLint errors, so a required check there would not mean "builds". Names follow Booking's
  "Frontend Build". The portal's `tsc` step moved out of "Portal Lint" into "Portal Build" (no double run).
  Both build with no secret and no env var (checked locally on Next 16.4.2: both `next build` pass; the
  admin app's Sentry plugin skips the source-map upload without `SENTRY_AUTH_TOKEN`).
- **Trivy: `exit-code: 1`, `ignore-unfixed: true`, `trivyignores: .trivyignore`.** Reviewed a real report
  first (main run 39633516311, 21/10/2026, job "Docker Build Check"): 145 CRITICAL/HIGH OS findings on the
  debian 13 base, **none with a fixed version**; the Python packages table is clean. So the flip turns no
  current PR red, and `.trivyignore` starts empty. Nothing to fix in this PR.
- **`.trivyignore` expiry uses Trivy's own `exp:YYYY-MM-DD`** (after the date Trivy reports the finding
  again). `check_trivyignore.py` adds what Trivy does not enforce: every entry must have `exp:`, a `# reason`
  comment on the line above, and an expiry at most 90 days ahead (mirrors `.github/pip-audit-ignore.txt`).
- **Coverage ratchet instead of `--cov-fail-under=30`.** The audit's "~30%" was the fail-under value; the
  real total is **85.68%** (same main run, Unit Tests). Floor starts at **85**. The floor may only go up
  (the script compares `.github/coverage-ratchet.json` with `HEAD^1`, the base tip of the PR merge ref).
  The issue's "+5%/month" is a **goal** (`baseline` 85 + 5 per whole month since 22/10/2026, capped at 90)
  that only warns: a date-driven hard fail would turn every unrelated PR red on the 22nd of a month.
- **`frontend/**` removed from `deploy-dev.yml`.** The Dockerfile copies only `api/ shared/ services/
  worker/` and `requirements.txt`, so a frontend change never changed the image; it only restarted api +
  worker (and the job guard could block it). `portal/**` was never in the filter.
- **No new header check for CIS previews**: the admin and portal UI smoke already assert the six security
  headers on every preview (`tests/e2e/smoke/aa876-security-headers.spec.ts`,
  `tests/e2e/smoke-portal/aa885-portal-host.spec.ts`). Booking and TripPlanner get a header step in their
  PRs because they have no UI smoke.

## Changed

- `.github/workflows/ci.yml`: jobs `frontend-build` ("Frontend Build"), `portal-build` ("Portal Build");
  Trivy blocking + ignore-file check step; Unit Tests writes `coverage.xml` and runs "Coverage ratchet";
  "Portal Lint" lost its `tsc` step. Existing job names unchanged.
- `.github/workflows/deploy-dev.yml`: path filter without `frontend/**`.
- New: `.trivyignore`, `.github/scripts/check_trivyignore.py`, `.github/coverage-ratchet.json`,
  `.github/scripts/coverage_ratchet.py`, `tests/unit/test_aa879_ci_gates.py` (9 tests, stdlib only).
- `CONTEXT.md` Deploy & CI.

## Tradeoffs

- `ignore-unfixed` means an OS CVE with no Debian fix never blocks. That is the point (nothing to do), but
  the unfixed CRITICALs (libxml2, openssh-client, linux-libc-dev) stay in the image; a slimmer base image
  (drop gcc/g++/cmake/git after `pip install`, multi-stage) would remove most of them — not in this issue.
- A Debian fix published upstream can turn "Docker Build Check" red on a PR that did not touch the image.
  The fix is a rebuild (the base `python:3.12-slim` is pulled fresh) or a `.trivyignore` entry; this is the
  intended behaviour of a blocking scan.
- Two more Node jobs add ~3–4 min of runner time per PR (public repo: free minutes).
