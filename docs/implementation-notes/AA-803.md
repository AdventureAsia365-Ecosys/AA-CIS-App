# AA-803 — Claude Haiku 5.5 / Sonnet 5.5 in the Model Gateway (S246)

Scope of this slice: catalog rows for the two newest Claude models on Bedrock, a request builder that
does not get a 400 from them, and dropping the LEGACY Sonnet 4.5 acc2 profile from the `sonnet` row.
No stage route changes; moving stages is a separate, measured A/B.

## Decisions

- **Migration, not the admin API.** `PATCH /admin/llm-catalog/{model_key}` only edits price / enabled
  (`catalog._CATALOG_EDITABLE_FIELDS`); new rows and profile ids are a code + migration change (ADR 0005).
  Migration 259.
- **acc3 + acc1 profiles, no acc2.** acc2 refuses every Claude call (channel-program account, AA-843), and
  the Converse path never calls acc2 anyway.
- **`sonnet` acc2 key removed** rather than repointed at Sonnet 4.6: any acc2 Claude profile only adds an
  attempt that always fails (the TripPlanner gateway tries acc2 last).
- **Prices: Anthropic first-party list prices**, recorded as such in `price_source`, with the note that
  Bedrock is partner-priced and the AWS pricing page must confirm before a stage moves (admin PATCH).
  Haiku 5.5's > 100K-token prompt tier is not modelled (single price per row).
- **Forced tool choice → `auto` + instruction** for structured output on models matched by
  `_NO_FORCED_TOOL_CHOICE_MARKERS` (Sonnet 5.5, Opus 5.5, Fable 5.1, Mythos 5.1), matched on the
  Bedrock profile id. **Haiku 5.5 keeps the forced tool**: it accepts `any` / `tool` (the response then
  starts with the tool call, no thinking block), which costs fewer output tokens and gives a reliable
  schema on the 9 high-volume Haiku stages. A first draft listed Haiku 5.5 too; the review against
  Anthropic's Haiku 5.5 migration guide corrected it before the migration PR. Any other model that answers a forced tool choice with a ValidationException is
  switched at runtime, retried once (not billed) and remembered per process.
- **Capability as code, not a new catalog column.** A `supports_forced_tool_choice` column would make the
  catalog SELECT fail on any process that deploys before the migration (catalog unreadable = every
  non-legacy route fails). The marker list lives in `shared/llm_client` only.

## Changed

- `shared/llm_client/client.py`: `_forced_tool_choice_ok`, `_use_auto_tool_choice` (instruction as a second
  system block so the first block — the cache prefix — is unchanged), `_converse_with_param_downgrades`
  (temperature downgrade as before + tool-choice downgrade), `_first_tool_input(allow_text_json=)` accepts a
  JSON object answered as text under `auto`.
- `api/migrations/259_llm_catalog_haiku_sonnet_5_5.sql` (+ Infra byte copy needed in
  `AA-CIS-Infra/db/migrations/cis/`).
- Tests: `tests/unit/test_aa803_claude_5_5_request_shape.py`, `tests/integration/test_aa803_migration_259.py`.

## Tradeoffs

- `auto` tool choice is less strict than forced: a model may answer in text. Covered by the text-JSON
  fallback, then the existing AA-714 schema retry, then the route's next model.
- No `thinking` field is sent: the new models run adaptive thinking at their default effort (Haiku 5.5
  `medium`, Sonnet 5.5 `high`). Thinking tokens count against `maxTokens`; a stage with a tight
  `max_tokens` could see more `max_tokens` stops. The A/B per stage will show it; effort control is a
  later change if needed.

## Should know

- Order: Infra copy of 259 → DB Migrate check/apply → smoke script (one call per model and account,
  stage `adhoc_s246_models`) → merge/deploy the app PR → only then route a structured-output stage to
  either model.
- `opus-5-5` (already in the catalog, eval only) also matched the forced-tool 400; it gets `auto` now too.
- The TripPlanner gateway's Converse call sends no temperature and no tool config, so it needs no change.

## Meal claims, part A: wider ITIN_MEAL_INVENTED detection (S247)

Draft PR #905 (S246) mixed two things: a wider meal-claim detector and a free-text meal rule that clears the
code before Jev. Its adversarial review did not converge (65 confirmed false clears in 3 rounds). S247 splits it.
This part is only the detector; it clears nothing. Part B (the narrowed, structured-evidence rule) is a separate
PR stacked on this one.

### Decisions

- **`ITIN_MEAL_INVENTED` reads plural, future and generic claims.** A meal noun (breakfast, brunch, lunch,
  luncheon, dinner, supper, meal, picnic, feast, banquet, barbecue / BBQ, and the `lunchtime` forms), up to four
  gap words, an optional auxiliary (`is / are / was / were / will be / being / get(s)`), an optional `also`, then a
  provision verb (`included / provided / served / arranged / offered / supplied / prepared / hosted / covered`).
  So `Lunch and dinner are included`, `dinner will be served`, `meals on board the junk are prepared` and
  `Evening meal included` are claims now. Also `includes / including / included` + up to two determiner-type
  words + a meal noun (`The price includes all meals`, `including a picnic lunch`), `full / half board`,
  `all / three / daily / every / each meal(s)`, and code brackets with a placeholder (`(B/-/D)`).
- **Gap words never include a negation or an option.** `not / no / never / optional / cannot / can / could / may /
  might / should / would` and the advice nouns (`recommendations`, `suggestions`, `options`, `tips`, `ideas`,
  `advice`) stop the match, so `Lunch is not included`, `Dinner can be arranged` and `Dinner recommendations are
  provided` are not claims (they were not on main either). `can be` is not an auxiliary: "can be arranged" is
  the traveller's option, not an inclusion (PR #905 counted it and produced a false fire).
- **Every claim sentence is checked, including short ones and day-title lines.** `grounding.sentence_units`
  drops sentences under `MIN_WORDS` (4) and the title lines, so on main `Dinner included.` or
  `Day 3 — Hue (B, L)` was never asked to Jev. When another meal sentence of the same itinerary got a Jev
  accept, the short one passed unchecked. Now a claim sentence Jev is never asked about keeps the code, and Jev is
  not called at all for that itinerary (it could not clear it).
- **The Jev call is unchanged for the askable sentences**: the same unit dicts `sentence_units` builds, the same
  per-unit source (`unit_source`) and so the same subject key (a cache hit on the grounding call).

### Changed

- `brand_audit_node.ITIN_MEAL_INVENTED`: wider, see above.
- `brand_audit_node.itinerary_claim_sentences` (new): every itinerary sentence with its day, the same split and
  day rule as `sentence_units`, without the word floor and keeping title lines.
- `brand_audit_node.meal_time_claims_supported`: claim sentences from the new splitter; the Jev part moved to
  `_jev_clears_meal_claims` (same behaviour, plus the "unaskable claim keeps the code" rule).
- Q0 harness (`tests/unit/quality/chain.py`): a case can set `brand_audit.pre_audit: true`. The stubbed brand
  audit then runs the real `pre_audit_checks` (with Jev as the case stubs it), adds its codes, derives the status
  with `derive_status`, and the codes count as observed. Existing cases do not set it and pass
  unchanged. A harness edit needs the `q0-relabel` PR label (`.github/scripts/q0_red_on_base.py`).
- New Q0 case `a1-meal-plural-claim-unsourced` (`cases/a1_meal_claims.json`, `fire`): Day 3 of the rewrite says
  "Lunch and dinner are included at the hotel in Punakha", the source names no meal. Red on `origin/main`
  (checked locally with the red-on-base script): no code, nothing fixed.

### Tradeoffs

- **More fires, never fewer.** The wider regex and the unaskable-claim rule only add codes. While
  `a1_claim_supported` is on, a wider claim that the source states is usually cleared by Jev (a cache hit on the
  grounding call, so about $0). With Jev off, every one of them keeps the code until part B's rule clears it.
  An extra fire costs one flag_fix itinerary rewrite (~$0.01, J04 unit cost) and never publishes an invented meal.
- **A few narrative sentences now read as claims** ("A lunch stop where noodles are served" with a gap word in
  front of `served`). The gap is capped at four words and stops at negations and modals; the rest is accepted
  (fail-closed, Jev or flag_fix).
- **Kept out of scope**: dotted clock forms (`7 p.m.`) are still not read by `ITIN_CLOCK_TIME` (PR #905 changed
  that too, with a 24-hour canonical form on both sides). It is a separate detector gap; follow-up if wanted.

### Should know

- This PR changes no clearing rule: an itinerary whose every claim is askable goes to Jev exactly as on main
  (same units, same sources, same subject keys; test `test_askable_claims_go_to_jev_with_the_grounding_units_and_sources`).
- The offline replay of S246 (PR #905 notes) counted ~90 more versions in the 30-day window with a meal claim
  under the wider regex. Under Jev on they are Jev questions (cache hits); measure after deploy with
  `scripts/aa803/meal_rule_replay.py` (part B).

## Meal claims, part B: the narrowed structured-evidence rule (S247)

Stacked on part A. Replaces the free-text rule of draft PR #905, whose adversarial review did not converge
(65 confirmed false clears over rounds 3, 4 and 5, about 20 new ones per round). `a1_claim_supported` and
`a1_promise_unsupported` stay ON; this PR only takes from Jev the meal claims the source states in a structured
form, and the replay script measures whether that is enough to revisit OFF (J04/J05).

### Decisions

- **Two clear paths, nothing else** (`services/content_generation/meal_claims.py`, `claim_sourced`):
  1. a pure same-day meal list: `Meals: B, L, D`, `Meals included: Breakfast | Dinner`, a label alone on its line
     with the list on the next (`Meals Included:\n• Breakfast, Lunch`), or a bracket of codes `(B, L)` /
     `(B/-/D)`. Pure = only meal words, B/L/D, separators and placeholders (`-`, `x`, `N/A`, `None`). Anything
     else in the list (`(own expense)`, a count, a venue, `3 meals`) makes the day unreadable, so not cleared.
  2. an unscoped every-day INCLUSIONS item, read as a whole item: `All meals`, `Three meals a day`,
     `All meals (breakfast, lunch and dinner)`, `Full board`, `Half board` (breakfast only), `Daily breakfast`,
     `Breakfast and dinner daily`, `... every day / each morning`. Items split on new lines, bullets, `;` and `|`;
     a comma list is split only when the line has no scope word at all (no digit, day, trek, in, at, on, with,
     except, ...), and never inside brackets. `Hotel with daily breakfast` is NOT read (the prefix may scope it).
- **When the paths are tried at all** (each condition only errs towards "not cleared"):
  - Output sentence: refused on any digit or time word (`noon`, `seven`, `o'clock`), a negation or option
    (`not`, `no`, `own`, `optional`, `or`, `if`, `may`, `can`, `available`, ...), or a reference to another or
    several days (`tomorrow`, `next`, `following`, `every`, `each`, `daily`, `throughout`, `both`, `days`,
    `nights`, `rest of`, `the second day`, `all trek days`). Same-day words (`the day`, `all meals`) are fine.
    Claimed meals: the meal words and codes; a generic noun (meals, feast, picnic, barbecue, banquet, buffet,
    full / half board) claims all three, unless it modifies a meal word (`picnic lunch`, `BBQ dinner`).
  - Days: output days exactly 1..N; source markers exactly one single-day `Day n` for 1..N in order (no range,
    no `Days`, no `Day 2 & 3`, no repeat, no restart, no date header read as a range); the tour duration, when
    exact, is N; no meal text before Day 1.
  - Alignment: the output day and its source day must share at least one specific word (a place or a sight,
    after a stoplist of generic travel words). A day-count match alone is not trusted: a writer can merge one
    day and split another.
  - The source day names no other day or night (`Day 3` inline, `the 2nd evening`, `night 2`, `3 nights`,
    `next morning`, `last night`, `tomorrow`, `alternative`, `version`, `extension`, `post-tour`).
  - Doubt: a strong cue anywhere in the source day (`own expense`, `on your own`, `not included`, `excluded`,
    `payable`, `optional`, `on request`, `supplement`, `upgrade`, `self-arranged`, `for purchase`, a currency, the
    non-English `tự túc` / `libre` / `non inclus`), or a weak cue (`no`, `not`, `or`, `if`, `may`, `can`, `free`,
    `leisure`, `bring`, `tips`, `grab`, `find`, `those`, `deluxe`, `guests`, `responsibility`, `cash`, `only`, ...)
    in a sentence of that day that names a meal (a bare time marker `After breakfast,` does not count as naming
    it). The same sentence test over SUMMARY / DESCRIPTION / PRICE stops both paths for the tour.
  - EXCLUSIONS: a named meal is blocked; any generic meal word there (`meals`, `food`, `full board`, ...) blocks
    all three, including "Meals other than breakfast".
  - INCLUSIONS path only: never the first or last output day; never a day that has its own list (the list
    decides); no day list anywhere that lacks the meal; any exception or scope word anywhere in INCLUSIONS
    (`except`, `not`, `only`, `during`, `while`, `until`, `starting`, `optional`, `extra`, `own`, ...) disables
    the path; an item that continues the matched one (`(on trek days)`, `on safari days`) or any other item
    naming the same meal removes that meal.
- **The day's free text must not talk about the meal** (`narrative_names`): if the source day, outside its pure
  lists, code brackets and bare time markers ("After breakfast,"), names a claimed meal or meals in general
  (meal, food, feast, picnic, eat, dine, full board, ...), the claim goes to Jev, on both paths. This one rule
  replaces the whole class of "a sentence beside the list contradicts it" (own expense, optional, for children,
  organised by participants, n.i., ...) that kept #905 from converging. It halves the day-list clears offline
  (93 -> 42 claims) and is kept on purpose.
- **Codes only in capitals** (`(l)` is not lunch), and a `Meals:` label only where a list can start (line start,
  after a sentence end, a bracket, a pipe, a dash or a bullet): `Group B meals: B, L` makes the day unreadable.
- **INCLUSIONS layout must not hide a scope**: several lines must all be top-level bullets at one indent; a plain
  line may be a heading ("Trek portion" over "All meals"), so a multi-line INCLUSIONS without bullets is not read.
  A colon after the opening "Included:" heading ("Kathmandu: daily breakfast"), a dash inside a line ("Full board –
  trekking portion") and any meal word in SUMMARY / DESCRIPTION / PRICE ("Meals are provided on trek days") also
  turn the INCLUSIONS path off.
- **Hook**: `meal_time_claims_supported` drops the claims `claim_sourced` clears, before the part-A Jev step;
  nothing cleared means exactly the part-A behaviour. Short and title-line claims are cleared by the rule too
  (part A keeps the code on them when the rule does not clear them, since Jev is never asked).
- **No time inference**: the clock check still runs first and unchanged; the rule refuses any sentence with a
  time.

### Changed

- New `services/content_generation/meal_claims.py` (pure, no I/O).
- `brand_audit_node.meal_time_claims_supported`: three lines calling it.
- `CONTEXT.md` (A1 grounding): one paragraph on the meal / clock check.
- New `scripts/aa803/meal_rule_replay.py` (read-only replay, not run by this PR) + its unit test.
- Q0: four `no_fire` cases in `cases/a1_meal_claims.json` (day code list, unscoped "all meals", a short
  sentence on a day list, a title-line code list), each red on `origin/main` and on part A (checked locally with
  the red-on-base script: the code fires, flag_fix makes an unscripted call).

### Tradeoffs

- **Coverage is deliberately small.** Offline on the S246 AA-925 export (published or latest version of 918
  tours; that export has no INCLUSIONS, so path 2 cannot show there): 288 versions with 782 meal claims under the
  new detector; 42 claims cleared by a day list, 3 versions fully cleared. Main not-cleared reasons: the day's
  free text names the meal (336, mostly days with no list at all), refused output sentence (119), source-day doubt
  (88), days not matched (76), another day named in the source day (68). Real coverage, with INCLUSIONS, comes
  from the post-deploy replay. A "plain positive sentence" relaxation ("Dinner at the hotel.") was measured
  offline and would add only 12 claims, so it was not built.
- **Guards still use word lists** (output refusals, source-day doubt), but they gate only two narrow forms of
  evidence, apply to whole sentences or whole days (not word windows), and the narrative rule removes the free
  text that #905 tried to parse. Own probe rounds while building (S247): round 1 found 5 clears (all fixed: by
  participants, n.i., children only, a dash scope, a heading line), round 2 found 3 (qualified `Group B meals:`,
  a lowercase `(l)`, a DESCRIPTION scope; fixed), round 3 found 0 meal false clears in 14 probes.
- **Known residual risks** (each needs the structured evidence present too): a day drift that keeps a shared
  specific word between the swapped days; an INCLUSIONS `Daily breakfast` on a tour where some nights have no
  breakfast and the itinerary does not say so. Both are cases where the operator's own structured statement says
  the meal is included.
- **Not this rule's job**: the venue or detail of a sourced meal ("Dinner is included at a Michelin-starred
  restaurant" against `Meals: B, L, D`). The code is about whether the meal is included; venue facts are
  grounding's (and, while it is on, Jev's) concern.

### Should know

- Every one of the 65 S246 false-clear patterns (plus round 1's B1-B3 and variants, 143 cases) is a regression
  test in `tests/unit/test_aa803_meal_rule_structured.py` section 4, each built WITH the tempting structured
  evidence so the guard that blocks it is what is exercised; a control test checks the same tour without the
  trap does clear. Sections 6 and 7 add 22 probes found while building (responsibility, cash only, post-tour extension, INCLUSIONS
  continuation / only / except / other item / heading / colon / indent / dash, narrative mentions, qualified
  label, lowercase code, DESCRIPTION scope) and the day-drift and description-doubt guards.
- **Measure after deploy** (orchestrator): `scripts/aa803/meal_rule_replay.py` over the J04 set (30 days, master
  tenant, grounding ran, not human-edited). It prints the Jev meal units removed (vs the old code and vs the
  new detector), the waiver share before (S246: 71 / 914 = 7.8 %) and after, and `waiver_bar_met` (after ≤ 5 %).
  Only if the bar is met is OFF for J04/J05 worth revisiting; the Jev meal calls are normally cache hits of the
  grounding call, so the money saving is small and the real gain is that a Jev outage no longer decides them.
- This PR needs an independent adversarial review (it is a clearing rule in front of a fail-closed check).

## Meal claims, part B: review round fixes (S247)

The independent adversarial review of part B (at 126063f1) found two false-clear classes. Both are fixed here.

### Decisions

- **A meal note in another day's block now stops the claim** (`meal_claims.itinerary_doubt`, reason
  `source_itinerary_doubt`). The day-list path read doubt cues only in the matched day's block, so
  "Day 1: ... Note: lunches are at your own expense throughout the trip." or a note after the last day
  ("Important: on private departures lunch is not included.", which falls into the last day's block) did not stop
  a Day 2 lunch claim cleared by Day 2's `Meals: B, L, D`. Main has no such gap: Jev's `unit_source` for a Day 2
  unit holds the Day 1 and Day 3 text. Now every sentence of every OTHER source day is read (outside that day's own
  pure lists and code brackets, which are that day's facts: "Meals: None"). It stops the claim, on both paths,
  when it names a claimed meal and
  - has a strong cue (`_STRONG_CUE_RE`) or a negation-type weak cue (`_NEG_CUE_RE`: no, not, may, can, own, self,
    pay, buy, extra, option, depending, ...), and
  - reaches the claimed day: a tour-wide word or another-day reference (`throughout`, `every`, `all meals`,
    `tour`, `trip`, `departures`, `following days`, `Day 2`, ...) always reaches; otherwise a sentence scoped to
    its own day (`today`, `tonight`, `this evening`) does not; otherwise a strong cue, or a remark marker (`note`,
    `important`, `please`, a plural meal noun "lunches"), reaches.
  `meals` / `food` / `dining` / `full board` name all three meals; a one-off meal word (picnic, feast, banquet,
  barbecue, buffet, eat) names all three only in a tour-wide sentence or a remark.
- **Deviation from the review's literal suggestion** ("run `_meal_sentence_doubt` over the whole itinerary"):
  measured offline on the S246 AA-925 export, that version (any weak cue in any meal sentence of any day) cut the
  day-list clears from 42 to 8, almost all on narrative sentences of other days ("relax, eat, shop, or all three",
  "communal meals with honoured guests", "There are no meals included today", "Meals: None"). The narrower reach
  rule above keeps the review's two probes and 10 own variants refused and keeps 42 / 42 of those clears.
- **A list that belongs to one option, cabin or class is not read** (reasons `source_day_has_variants`,
  `source_list_unreadable`). `_LABEL_START_OK` looked only at the character before `Meals:`, so a qualifier on the
  previous line ("Superior cabin guests:\nMeals: B, L, D") or in the previous sentence ("Option 1 - bike tour.
  Meals: B, L") was never seen. Three guards now:
  1. a variant word anywhere in the matched day (`option(s)`, `optional`, `package`, `premium`, `superior`,
     `deluxe`, `luxury`, `version`, `variant`, `tier`, `category`, `choice`, `choose`) refuses the claim on both
     paths (`claim_sourced`), and makes any list of that day impure (`day_lists`, which the INCLUSIONS path also
     reads on the other days);
  2. a heading line (ending with `:`) anywhere above the list that is not a plain section heading of the
     structured layouts (`Accommodation:`, `Included transportation and activities:`, `Transportation:`, ...)
     makes it impure ("Superior cabin guests:", "Group A:", "For the long route:", "Note:");
  3. an audience or class word (`cabin`, `class`, `standard`, `guests`, `group`, `travellers`, `passengers`,
     `children`, `trekkers`, `those`, ...) in the list's paragraph before it, or on the non-empty line above it,
     makes it impure. Code brackets get guards 2 and 3 too.
- **Deviation**: the review proposed audience words (guests, group, cabin, class) block-wide. Offline, block-wide
  lost 5 of 42 clears, all to narrative in an earlier paragraph ("charms every traveler", "those elusive tigers",
  "check into your cabin"); the paragraph scope loses 1 ("depending on group abilities" in the list's paragraph,
  a fair refusal). Variant words stay block-wide.

### Changed

- `meal_claims.py`: `_VARIANT_RE`, `_AUDIENCE_RE`, `_SECTION_HEADING_RE`, `_list_scoped` (used by `day_lists` for
  labels and code brackets); `_TOURWIDE_RE`, `_REMARK_RE`, `_SAME_DAY_RE`, `_NEG_CUE_RE`, `_sentence_meals`,
  `itinerary_doubt`; two new refusals in `claim_sourced` after `day_doubt`.
- Tests: section 8 of `tests/unit/test_aa803_meal_rule_structured.py`: the review's 5 probes verbatim and 12 own
  variants, each pinned to the guard that must stop it (`REVIEW_REASON`); 6 controls that must still clear (other
  day's "no meals today", "Meals: None", "Lunch can be bought on the train", a picnic with an optional hike, the
  section-heading layout, a cabin in an earlier paragraph); `day_lists` cases; the INCLUSIONS path on a variant day
  and with a tour-wide note on another day.

### Tradeoffs

- Offline (S246 AA-925 export, no INCLUSIONS): day-list clears 42 -> 41 claims, fully cleared versions 3 -> 3.
- Still word lists. Each new guard errs towards "not cleared" and gates only the two structured paths.

### Should know

- Jev's window is day-1..day+1; this rule now reads every day, so it is stricter than Jev on tour-wide notes.

## Meal claims, part B: second review round fixes (S247, at f1ea929c)

The second independent review found three false-clear classes and a CI payload issue. All fixed on the same
branch; each probe of the review is pinned verbatim in section 9 of `tests/unit/test_aa803_meal_rule_structured.py`
with own variants.

### Decisions

- **INCLUSIONS are read on the day-list path too** (`inclusions_doubt`, `inclusions_excluded`; reasons
  `inclusions_doubt`, `excluded`). Jev's `unit_source` carries INCLUSIONS, so a day-list clear that never read them
  was a regression against main. A "Not included:" / "Excluded:" / "n.i." section inside INCLUSIONS (combined
  incl / excl fields in scraped data, a `["Hotels", "EXCLUDED: lunch on cruise days"]` list) is read like
  EXCLUSIONS; any INCLUSIONS sentence (split on `. ! ? ;` and new lines) that names a meal with a strong or weak cue,
  or with an audience / variant word (`cabin`, `guests`, `Superior`, ...), stops the claim on both paths.
- **The days next to the matched one must be silent on the meal** (`adjacent_day_doubt`, reason
  `source_itinerary_doubt`). Jev sees days d-1, d and d+1, and text after the last marker sits in the last day's
  block; the reach gate (tour-wide / other-day / remark) let a singular, own-day sentence through ("Lunch on the
  junk is charged separately.", "For solo travellers lunch is extra."). Now the day before and the day after get
  the same `narrative_names` test as the matched day (a claimed meal or meals in general in the free text, outside
  pure lists, code brackets and bare time markers), plus any meal sentence with `only` / `just` ("Only breakfast is
  provided in the towns" restricts the other meals). Days further away keep the reach gate, as the review allowed;
  `_NEG_CUE_RE` gains `served`, `available`, `replac*`, `cancel*`, `charged`, `a la carte`, `only`, `just`,
  `limited`, `season*`, `closed`, `instead`, and an `only` sentence there names all three meals.
- **The claim sentence must hold nothing but the claim** (`output_extra`, reasons `output_food_noun`,
  `output_second_clause`, `output_word_not_in_source_day`). The review offered two options; both are applied:
  (1) a food or drink noun outside B / L / D (`menu`, `hotpot`, `spread`, `tasting`, `wine`, `pairing`, `chef`,
  `seafood`, `noodle`, `feast`, `picnic`, `buffet`, ...) refuses; (2) a second clause refuses (`,` `;` `:` a
  bracket, a spaced dash, `followed by`, `and a / the / some ...`, `then`, `plus`, `as well as`, `along with`),
  after meal lists ("breakfast, lunch and dinner") are collapsed; (3) every other word, outside function words,
  meal words, provision verbs and the generic venue words `hotel` / `restaurant` / `local` / `today` / time-of-day
  words, must appear in the matched source day (simple plural folding). A day-title claim ("Day 3 — Hue (B, L)")
  is checked only for food nouns: its title words are the writer's day name, not part of the claim.
- The output check runs last on each path, after the list / INCLUSIONS membership, so a meal missing from the list
  still reports `not_in_day_list` (clearer replay stats).

### Changed
