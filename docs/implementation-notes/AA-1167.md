# AA-1167 — AI output and prompt hardening (OWASP LLM05 + LLM01), CIS

Lane l7-aa1167-ai-output, S287. Source: the S286 security gap analysis (package "AI output and prompt hardening",
items LLM05 and LLM01-a; the private report keeps the detail, this public file names the controls only).

## Decisions

- **One output sanitizer, allow-list, no new dependency** (`services/ai_safety/html_sanitizer.py`). Neither bleach nor
  nh3 is in the CIS image; Python's `html.parser` rebuilds the fragment from tokens (never regex patching of HTML).
  Kept: the tags and the exact attribute forms Python-Markdown (`extra` + `nl2br`) writes for a blog piece (tables
  with `text-align`, footnote ids / classes, links). Dropped with their content: script, style, iframe, object, embed,
  svg, math, form, ... Dropped but text kept: every other tag. Links: http, https, mailto, tel or relative only.
  `img` is not allowed: a blog piece has no images, an injected one is a tracking pixel.
- **The allow-lists are security invariants, not settings** (task rule "an admin-editable setting or a documented
  guard"): an administrator must never be able to allow `<script>` or an `on*` handler. They change by reviewed PR
  with a test; the guard test keeps every path on them.
- **Where it runs:** `export.render_markdown_body()` = Markdown render + `sanitize_html`, used by the WordPress post
  body, the HTML fragment and document exports and the subject gate's link check (so it checks the links that are
  really published). `sanitize_plain_text` (tags and comments removed, `javascript:` / `vbscript:` /
  `data:text/html` defused to `blocked:`) on the Facebook message, the plain-text export and the WordPress title and
  meta description (WordPress renders the title as HTML for an account allowed raw HTML).
- **Our own wrapper is added after the sanitizer:** the `<article data-ai-*>` mark, the AA-1168 disclosure paragraph
  and the `<meta name="ai-*">` tags are built by our code from escaped values and stay untouched.
- **Prompt fence behind a setting, default off (= main byte for byte).** S272 rule: a writer-flow behaviour change
  ships behind a switch whose default is main, and the writers' quality was calibrated on today's prompts. The switch
  is the admin setting `cis.llm.prompt_data_fence` (CIS 467, bool, platform, maker-checker, impact high, no env
  override), not an env var. The paid trap run compares off and on before an administrator turns it on.
- **Fence shape:** `<untrusted_data label="...">` ... `</untrusted_data>` around each quoted value; any fence marker
  inside a value (any case, spacing, HTML-escaped or full-width bracket) is removed first, so the value cannot close
  the fence. One system line (`prompt_fence.SYSTEM_RULE`) says what the tags mean. Only the values go inside: our
  headings and code-built lines ("DAYS TO WRITE", "NOT IN THE SOURCE (never state ...)", "FACTS: additional citable
  facts ...", "CALL TO ACTION TO INCLUDE") stay outside, because the rule tells the model to follow nothing inside.
- **What is untrusted (fenced):** S1 v2: every source block of the fact sheet (tour header, days / itinerary,
  overview, included, excluded, optional, figures, conflicts, do-not-use) and, in the meta call, the page draft, the
  figures and the search keywords. T2 (and the legacy A1 v1 prompt, same builder): the TOUR DATA values, the source
  facts block, the Facts Entries and the SEO context (DataForSEO keywords and People Also Ask). T9: the content seed
  (flat or the route moments), the Facts Entries, DESTINATION, TRIP, LEAD WITH and the SEARCH QUESTIONS.
- **What is not fenced, with the reason** (listed in the guard test, so a new input must be classified): the tenant
  brand pack and CTA (the brand fields have their own guard and the CTA is an instruction to include it), our goal /
  channel registries, our angle gate's output, gate feedback, writing-memory lines, the SEO keyword of the blog
  envelope (one phrase from our research cache), the code-built SCOPE line.
- **Mode read once per run:** S1 v2 reads it in `writer_prompts` (writer and meta call of one draft agree; a state
  key `prompt_fence` pins it for the trap run and tests); T2 / A1 v1 in `v1_pipeline.initial_state_for` (state key
  declared on the graph's `ContentState`, else LangGraph drops it, AA-209); T9 in `write_content` /
  `rewrite_with_feedback`. The pure builders take `fence=False` by default.
- **Prompt registry:** the hashed source of `s1_generate` and `t9_write` changed, so the manifest was bumped (s1 v4,
  t9 v9; `_seed_with_facts` joined the t9 symbols because the FACTS instruction moved into it) and CIS 467 registers
  them. Off renders v3 / v8 byte for byte, so the eval is "none: byte-identical default" (the CIS 413 precedent).
  While the switch is on, `quality_settings.prompt_fp()` counts it, so the ledger's prompt_version carries `.s<fp>`.
- **Trap set:** `services/ai_safety/trap_set.py`, 8 invented traps (override, fence break, link, markup, persona)
  over S1 v2 (3), T9 blog (3) and T2 (2), built with the live builders. Offline tests prove each payload is fenced
  data when on and that the scorer fails a reply that obeyed. The paid run `scripts/aa1167/trap_run.py` sends one
  call per trap (8 for fence on, 16 with `--fence both`) on stage `adhoc_aa1167`, role writer, the model of each
  writer's live route, `record_call_sync(**billed_fields(resp))`. `--stop-usd` has no default: the operator states
  the run's budget (no new literal cap).

## Changed (vs the issue)

- The issue asks for the fence "in the S1 v2, T2 and T9 prompts": done, but off by default until the trap run.
- The issue's "preview shows what will be published": the publish paths now send the sanitized render, and the
  HTML export (fragment / document) already is that render. The agency portal's preview lives in AA-Partner and renders
  the piece text as React text (markup shows as literal text, never runs); switching it to the export fragment is a
  follow-up there.
- Judges (F9 / brand-fit) are not fenced in this slice: their prompts are calibrated instruments with their own
  version gates (F9_PROMPT_VERSION); a follow-up.
- T2 DOCX export: text runs written by python-docx (escaped, no markup can run); left as is.

## Tradeoffs

- Allow-list rebuild vs a library: no new dependency or paid service; the cost is our own parser code, covered by
  attack and round-trip tests. Unknown entities pass through verbatim (inert text) to keep normal Markdown output
  byte-identical.
- Fence default off means the injection risk on the writers stays until an administrator switches it on; the output
  sanitizer is on for everyone from deploy, so script / iframe / handler / `javascript:` never reach a site meanwhile.
- `WRITER_PROMPT_VERSION` in the T9 job result is still the sha8 of `SYSTEM_PROMPT` without the fence line; the
  ledger's prompt_version (with `.s<fp>`) is the record that tells fenced calls apart.
