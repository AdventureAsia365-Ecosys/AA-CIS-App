### Slice C — content-validity gate, place fixes, /admin/places
- **One deterministic report, four checks, fixed reason codes** (`services/places/validity.py`): V1 duration
  (`ranged_heading`, `missing_day_numbers`, `duration_text_vs_days`, `extra_days`), V2 same place (`same_destination_names`,
  `near_duplicate`), V3 not a pin (`linear_feature`, `area_feature`), V4 day text (`no_day_text`,
  `day_text_not_naming`). Read as `cis_app` with the AA master tenant named in the SQL (cis_app's policies are
  `USING (true)`), the v_tour liveness rule on the base tables (no catalog read from CIS code).
- **Same-place rule** (V2b): same country, same distinctive name (geomatch tokens minus kind words; also the same
  letters run together, "Kuangsi" = "Kuang Si", "Mount Phousi" = "Phou Si Hill" with the local kind words kept),
  ≤ 2 km, ≤ 5 km when either point is the model's or an area. Clusters are cut at the keeper (no chaining through a
  third place, lesson S239). Keeper: geoapify point, then most live components, then id. Pinned by 22 labelled
  pairs (8 merge / 14 keep), false merges measured first (lesson S245 / AA-779). Extend the pair set from the probe's
  section 4 output and every admin fix.
- **Same kind of place (review S246).** Dropping every kind word made "Long Bien Bridge" = "Long Bien Market",
  "Hoan Kiem Lake" = "Hoan Kiem Night Market", "Ben Thanh Market" = "Ben Thanh Night Market", "Mount Phousi" =
  "Phousi Market" — all within 2 km, so the in-tour dedupe and the admin fix would merge them. `validity.place_kinds`
  reads the kind words a name says (English + local synonyms: tat = falls, phou = mount, tham = cave …; "night
  market", "old town / old quarter", "national park" are kinds of their own). `same_name` now also needs
  `same_kind`: both name the same kinds, or one names none and the other only kinds whose bare name is the feature
  (`BARE_NAME_KINDS`: waterfall, cave, mountain, lake, river, island, village, valley, pass, beach, park, town). A
  bare name never merges with a built place named after it ("Luang Prabang" / "Luang Prabang Night Market", "Long
  Bien" / "Long Bien Bridge"). A kind only ever keeps names apart, so a missing synonym costs a missed merge, never a
  wrong one; local words that often start proper names (ho, ban, phu, khao) are left out. Missed merges accepted:
  "Ben Thanh" / "Ben Thanh Market", "Royal Palace" / "Royal Palace Museum" (an admin merges them by hand).
- **In-tour dedupe stays on** (the pair set passes with the kind rule), with no audit row (the tour's rows are
  rebuilt each run) but a structured log line `place_in_tour_duplicates_merged` with the pairs, so a wrong merge is
  traceable; `counts.in_tour_duplicates_merged` stays in the build row.
- **Flip gate (Done-when 3) = `validity.GATE_REASONS`**: `near_duplicate`, `linear_feature`, `area_feature` — the map
  defects a viewer sees and the fixes clear. `summary.gate` (catalog and per country: items, tours, pass) and
  `stats_counts["gate.items"]`; a "Flip gate" card on `/admin/places`. Informational, never blocking:
  `same_destination_names` (one destination, several spellings = one pin; it is what a near_duplicate becomes once
  the in-tour dedupe or the fix points the spellings at the keeper, e.g. Kuang Si), V1 duration and V4 day text
  (content defects with their own fixes). Test: after the fixes the Kuang Si tour passes the gate.
- **Fix apply checks the dry run's fingerprint** (optional review item, cheap): the dry run returns
  `fingerprint` (sha256 of its planned changes); the UI sends it back on apply, and apply refuses with 409 (nothing
  written, no audit row) when the plan it would write now differs. API callers that send no fingerprint keep the
  old behaviour (re-plan and apply).
- **Linear features hidden, area features drawn as areas** — the proposed answer to Nghiệp's display decision
  (`validity_fix.LINEAR_FEATURES_HIDDEN`, `locate.Located.hidden`): a linear feature is stored `suspect` +
  `review_reason='linear_feature'` + `area`, so no catalog view returns it and TripPlanner draws nothing; the name
  stays in the day text. If Nghiệp prefers a circle, flip the constant (store and fix both read it through
  `Located.hidden` / the constant) — no migration.
- **Pipeline (deploy before the paid run, slice D):** `geomatch.feature_kind` (extends geomatch, no new module) feeds
  `Located.precision` and `hidden` even for a Geoapify-confirmed point; `place_extract` maps in-tour duplicates to
  one keeper per tour (component ids unchanged — they come from the itinerary spelling); the store lookup and
  `upsert_destination` follow `duplicate_of` to a usable keeper, so a merged key never comes back as a new row.
- **Catalog-wide merge only through the admin fix**, dry run by default, same country, scoped by `country` and/or
  `source_id`; apply repoints `geo.tour_place`, `geo.tour_day`, `geo.place_name`, `acp_shared.place_card`,
  `shared.place_photo`, sets `duplicate_of`, writes the audit row LAST (CIS 248 chain lock) with every prior value;
  `undo=<audit id>` restores exactly those rows if they still hold the fixed values (409 otherwise, and on a second
  undo). Booking / TripPlanner rows are counted (or "not readable as the CIS runtime"), never written.
- **No day-parser change** (plan §C.4): ranged headings are listed with `ranged_heading`; fixing
  `itinerary_utils.parse_canonical_itinerary_days` / `catalog._tour_day_text` is a separate catalog-recipe migration
  + content issue, to propose to Nghiệp.
- **Trend:** each `tour_graph_build` stores `validity.stats_counts` in `geo.graph_build.stats['validity']` (a report
  failure is recorded as `{"error": …}`, never fails the build). `GET /admin/places/validity` caches the report 60 s
  per country (the whole catalog is ~1k tours, cheap, but a page flip should not re-run it).

### Linear places drawn as lines (owner decision S246, design only — not implemented on this branch yet)
- **Nghiệp, S246: linear places (rivers, roads, trekking stretches) are drawn correctly, not hidden and not a
  circle.** This supersedes the "Linear features hidden" bullet above. Design: root
  `docs/audits/2026-10-21-S246-aa847/design-linear-places.md`.
- Before this branch merges: drop `LINEAR_FEATURES_HIDDEN` / `Located.hidden` / the `suspect` write in
  `store._write_point` and `_DEST_INSERT_SQL`; a linear name is stored `geo_status='ok'`, `geo_precision='line'` (new
  CHECK value, CIS 255). Word list += stream, creek, waterway, expressway, path, circuit; `range` → area; a
  descriptive phrase that names a feature ("sandbank on the Nam Ou River") links to that feature's destination.
- Shapes in a new internal table `geo.place_shape` (CIS 255: jsonb GeoJSON clipped to the country, three
  simplification levels ≤ 2,000 / 300 / 60 vertices, bbox columns, `osm_type`/`osm_id`, status queue); per tour-day
  stretch `geo.tour_place.segment*` written only by `tour_graph_build` (substring between the previous and this
  day's overnight anchors). No PostGIS (not on the shared RDS; ~340 rows; pure-Python clip / simplify / substring).
- Sources: Geoapify Place Details by the stored `geocoder_place_id` (`details`, + `details.full_geometry` only when
  needed), else Overpass by name + OSM tag near the point; manual GeoJSON on `/admin/places` as the exception.
  New job kind `place_shape` (background, debounced, cap 1) is the single writer of `geo.place_shape`.
- `catalog.v_destination` / `v_tour_place` / `v_tour_component` append shape / segment columns (contracts v1.2);
  a `line` destination is not a graph node. Flip gate: `linear_feature` → `linear_without_shape`.

## Tradeoffs
- Before/after evidence in CI is a fingerprint (row count + md5 of the ordered rows, read as `tripplanner`) of every
  contract view under 253 and under the restored old definitions, on seeded live / trashed / superseded tours,
  suspect and duplicate places, photos, atoms, a current and an old build. Dev evidence is the probe's fingerprint
  section before and after the apply (root audit folder).
- `ANALYZE` in the migration: cheap on these sizes, fixes stale `reltuples`; takes ShareUpdateExclusive until
  COMMIT (does not block reads).

- Linear shapes: jsonb + bbox columns instead of PostGIS (no new extension in the shared DB for ~340 rows; tile
  intersection is a bbox compare on a ~1.5k-row table). Stretch from day anchors instead of drawing the whole river
  (the whole Mekong on a 2-day slow boat is wrong); when anchors do not project onto the line, the country-clipped
  feature is drawn. Missing shape → provisional dashed line between the day's anchors, never a circle or nothing.
  Overpass public instance only for an offline job (fair use ≈ 10k requests/day), never on a request path.
