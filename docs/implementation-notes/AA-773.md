# AA-773 — Offered vs included Status line on every moment + writer rule

Lane A-T9, session S235. Built on main c0e8ce39 (AA-774).

## Decisions
- **One decision function** (`services/acp_shared/offered.py`, new, light — imports only `hygiene`).
  The seed builder writes the Status line with it; `quality_gates._is_offered` (promises_an_option)
  and `trip_facts.optional_activities` (F17) read the Status line back. Lesson S218: a value computed
  in two code paths must use one function. `OFFERED_PHRASES` moved there; `quality_gates._OFFERED_PHRASES`
  is a re-export (same object). `atom_seed` never imports `quality_gates` (test guards it).
- **Sentence level**: the evidence sentence that names the moment decides (label action words first,
  then place words). One-sentence evidence is its own sentence. No overlap, or tied best sentences that
  disagree → status unknown → no Status line (unknown beats a wrong line).
- **Continuation fragment**: a lower-case evidence right after an OFFERED part of the same day and the
  same place (shared merge key, or one of them has no key) is OFFERED; its quote is
  `<previous offered quote> … <fragment>` (the r4 'trekking along shorelines and forest paths').
- **Included line contrast**: rendered when the same day has an offered moment OR the moment shares a
  place (merge key) with one. The second condition was added so the Day-4 'boundary between steppes and
  taiga' moment, which sits in the same merged Khövsgöl block as the Day-5 offered items, is marked
  included (plan Done-when). Single-atom seeds: included line only when another sentence of the same
  evidence is offered.
- **Gate-1 (Nghiệp default approved)**: promises_an_option is Status-aware and the Done-when bullet is kept.
  (a) a block with Status lines is offered only if a Status line says OFFERED; (b) when the block has
  Status lines, only sentences that name one of its offered activities are checked
  (`trip_facts.mentions_activity` on `optional_activities` of that block — the same matcher F17 uses).
  A seed without Status lines keeps the origin rule (every unhedged sentence).
- **F17 Status-aware**: a trip line with a Status line is decided by it (included wins over F17's loose
  marks 'available' / 'can' / 'may'); a line without one keeps the old regex.
- SYSTEM_PROMPT: only the plan §3.1 second bullet (Status rule). The em-dash bullet belongs to the
  separate em-dash issue.

## Tradeoffs
- `moment_fact_count` needed no code change: the Status line is its own line and `_SOURCE_RE` only reads
  "Source itinerary:" lines; a test asserts the count is equal with and without Status lines.
- The mention filter can miss a promise that never names the activity ("you'll glide across the water")
  and inherits F17's matcher false positive ('shoreline' + 'forest' in a steppe/taiga sentence). The gate
  is warn-only, and before this change it warned on 23 sentences in 8/8 r4 blogs, all false positives.
- hygiene (not owned by this lane) still sees Status lines in the seed's own text: replay on the 8 r4
  blogs showed identical `find_issues` / `find_trip_fact_issues` output with and without them.
- Residual divergence: a moment with no Status line whose source uses only F17's loose marks
  ('Kayaks are available') is still optional for F17 and silent in the seed (pre-existing).

## Review round 1 (S235, changes_needed → fixed)
- **B1 (F17 scope of a Status line)**: a Status line covers ONE clause, not the whole Source line.
  `trip_facts.optional_activities` re-runs `offered.decide` (same function that wrote the line) to find
  the moment's clause (`Decision.span`). OFFERED adds that clause's activity (`offered.activity_text`:
  'Horse riding is available at extra cost.' → 'Horse riding'). INCLUDED drops only that clause. The rest
  of the line keeps the legacy mark rule, so 'Drive to the lake. Optional boat rides. Horse riding is
  available at extra cost.' still lists the boat rides, and 'Drive to the lake shore and hike the ridge
  trail. Horse riding at an extra charge.' no longer makes F17 fire on the drive/hike sentence.
- **B2 (cost wording, worst flip)**: Status offered-detection now also matches `at (an) extra …`,
  `extra cost/fee/charge`, `additional fee/charge/cost`, `for a fee`, `surcharge`. A clause with only one
  of F17's loose marks (available / can / may / optional…) and no offered phrase gets NO Status line;
  `trip_facts._OPTIONAL_MARK_RE` is now `offered.LOOSE_MARK_RE` (one definition).
- **B3 (clause level, false offers)**: the decision is per clause: segments split at `; ( )` and
  dashes, clauses at `, :`. The clause that names the moment decides. It is offered through an earlier
  clause only when that clause opens a list (include/including/such as/activities/options, or a colon).
  Before matching, the code strips "<fee|meal|lunch|…> … not included", "single supplement" and "pre-booked".
  'perhaps' and 'for those who' are no longer Status triggers; they stay in the warn-only gate list
  (`OFFERED_PHRASES` is unchanged).
- Follow-ups: `_same_place` requires a shared merge key (a moment without a card never continues a
  list). The continuation chain breaks on a fragment saying 'included' (not 'not included').
  `hygiene.build_scope_lexicon` and `trip_facts._background_places` strip Status lines. Added a test for
  the `_names_offered` empty-acts fallback. The prompt rule now says the OFFERED moment "is kept in the piece".
  SHA guard: cb1e723d… → 3aa6eeba….
- hygiene.py was touched (not in the lane's owned list) only for the lexicon strip, at the
  reviewer's request. It repeats the "Status:" prefix as a constant because offered.py imports
  hygiene (circular import).
- Offline replay after the fixes: unchanged (6 Status lines: 4 OFFERED, 2 included; promises_an_option
  23 sentences in 8/8 → 0/8; F17 0 → 0). hygiene and trip-fact issues are identical on 8/8 r4 blogs,
  and the claim_rules ids are identical.
