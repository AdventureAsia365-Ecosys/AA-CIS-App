## Decisions

- **Migration key 280** (S250 schedule: 279 is reserved for AA-851). Apply after 279 so the readiness check
  (max(version)) never reports 280 while 279 is missing.
- **Same shape as 277** (ADR 0010 decision 10): scope / tenant_id CHECK, RLS ENABLE + FORCE, `writing_rule_cis_app_all`
  and `writing_rule_cis_owner_all` (X1 parity, rule t exempt), `tenant_isolation` TO `aa_app_user` — but **no
  tenant-pool privilege at all**: tenants never see rules (ADR 0010, D7). The policy is there for rls_catalogue rule a
  (a `tenant_id` table needs an `app.tenant_id` policy) and as the floor if a grant ever appears.
- **Token caps in the DB, as an AFTER row trigger** (`shared.writing_rule_token_cap`), not only in code: the plan says
  "enforced at write". An AFTER trigger sees the generated `token_estimate` of the new row (a BEFORE trigger would not)
  and the other rows of the same statement. It takes a transaction advisory lock per (writer, scope, tenant) first, so
  two concurrent approvals cannot both slip under the cap (READ COMMITTED: the sum after the lock sees the other
  commit). Only `approved` + `active` count: candidates are unlimited.
- **Token estimate = ceil(chars / 4)** of `rule_text` + `replacement` (generated column). Deterministic and cheap; no
  tokenizer in Postgres. Close enough for a 400 / 250 budget.
- **Per-row caps as CHECKs**: ≤ 25 words for a rule; a `preference_summary` ≤ 5 sentences and ≤ 125 words (the plan
  says ≤ 5 sentences; 25 words could not hold one) and tenant scope only.
- **Nothing auto-activates at the row level too**: `approved` / `active` need `approved_by` + `approved_at` (CHECK).
- **D9 in the DB**: a platform rule with tenant evidence needs `support_tenants >= 3`; a tenant rule `<= 1`.
- **Gate rename key = `reason_code` + `gate_class`** (the qtax-v1 taxonomy class of the gate,
  `services/quality/registry.gate_classes`). The taxonomy maps old and new gate names to the same class, so a rule
  survives the AA-787 rename. No separate alias table.
- **`match_phrases`** (≤ 5, entity-masked): what the rule targets. The PREDICT check (WM-12) counts held-out edits that
  remove one; the R0 replay (AA-918) counts how often one appears. Added now so 918 needs no migration.
- **One open rule per cluster** (partial unique index on candidate / approved / active): re-mining a cluster is
  idempotent; a rejected rule does not block a new candidate next month.
- **Stage `writing_memory_mine` seeded in 280** with the judge route of 224 (gpt-5.6-luna → gpt-6-luna →
  gpt-6-luna-openai last, no shadow), role `judge`, plus the spend budget `bedrock / job:writing_memory_mine` ($1 a
  run, $2 a day, hard stop). The $25 calendar-month cap (E4) is a code check over the writing-memory stages of
  `llm_call_log`, since `spend_budget` has no monthly axis.

### Decisions

- **Clustering in code, not SQL.** The plan says "SQL clustering ($0)"; the cost point is kept ($0, deterministic,
  before any model call) but the grouping is a pure function (`mining.build_clusters`) over the fetched pass signals,
  so every threshold is unit-tested (tenant A only never yields a platform rule, 3 tenants for platform, 2 reviewers,
  5% of the A1 pieces of 30 days). Dev volumes are thousands of rows.
- **Labels.** reason code, else the gate's first qtax class (an A1 brand-audit code maps through `a1_codes`), else
  the gate; plus, for human edits, every 1-3 word phrase the edit removed (masked). Phrase clusters of one owner with
  the same signal set keep the longest phrase; at most 10 phrase clusters per owner.
- **Tenant system signals are not mined** (D9 counts edits); A1 system signals only through the 5% rule. T9 failed
  attempts are backfilled as evidence for R0 (AA-918).
- **PREDICT is deterministic**: the drafter returns 1-5 `match_phrases`; a held-out edit is explained when a phrase is
  in its masked before text and gone after. Shown = min(8, n - 2), so a cluster needs 3 signals to pass; smaller
  clusters wait and cost no call.
- **Masking**: numbers, prices, times, links, and capitalised names mid-sentence; a sentence-initial word only when it
  recurs capitalised mid-sentence. A single sentence-initial name stays (no dictionary); the 5-gram and brand-name
  lints are the backstop for platform rules.
- **Fact filter**: `new_specifics` (numbers / times) + a promise-word list (`included`, `free`, `private`,
  `transfer`, …) for "lunch" -> "lunch included", which `new_specifics` alone does not catch; added names are grey.
  No Jev call for grey (AA-803 not calibrated): the admin confirms on the page. The verdict reason is not stored (no
  column on the 277 table: adding one would break 277's exact-column re-run guard); the signal detail recomputes it.
- **Lint failures are stored** `rejected` (`rejected_by = 'lint'`), so the admin sees them and the cluster may be
  drafted again next run.
- **Trigger**: automatic = >= 10 new pass signals since the last run, <= 2 automatic runs a month, no open rerun wave;
  manual = the 3rd run of the month (the release-close run). A refused trigger ends the job `succeeded, ran: false`.
  The fact filter queues the automatic run when its trigger holds; the api ops sampler queues the fact filter once a
  UTC day while signals are pending (no Infra schedule needed).
- **Budget**: `shared.cost_guard` per run ($1) and per day ($2, kind scope) from the 280 budget row, plus the month
  cap ($25) over every writing-memory stage in `budget.py` (`spend_budget` has no monthly axis). The mine kind has
  `max_attempts = 1`: a paid run is never retried by the runner.
- **Backfill keeps the original time** (`record_writer_feedback(created_at=…)`, AA-917 addition) and is keyed by
  `locator.backfill`, so a re-run inserts 0 rows and it doubles as a sweep for new T2 edits / T9 attempts / lessons.
  The legacy audit copy of admin sentence text stays (D16).
- **Scope of lessons and T2 edits** follows `scope_for_tenant` like the live capture (master tenant = platform); the
  plan said "A1 -> platform", AA-916 already decided a tenant's own tour stays tenant scope.
- **Admin API is admin only**: reads `tenant.read` (signals and tenant rules hold tenant text), writes `ai.admin`.
  No approve route: approval belongs to releases (AA-919).
- **`REQUIRED_CIS_SCHEMA = 280`**: the jobs and routes need the rule table.

### Tradeoffs

- Phrase clusters can be noisy on whole-piece tenant rewrites; thresholds, the 10-per-owner cap, PREDICT and the
  admin review filter them, and a noisy draft costs ~$0.001.
- The 5-gram corpus (every tenant signal and piece text) is built per run as hashed n-grams; fine at Dev size,
  revisit at thousands of pieces.
