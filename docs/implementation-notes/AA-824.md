# AA-824 — RDS guardrails + connection budget (CIS side: migration 234)

## Decisions
- Migration 234 sets CONNECTION LIMIT on the three app runtime roles and creates `pg_stat_statements`.
  This is the single MIG-6 exception the data standards allow until the Infra role bootstrap (X1) exists.
- `aa_cis_admin` (CIS main pool, worker, DB Migrate runner) is not limited: a limit on the migration
  runner could lock DB Migrate out; it is handled by the role split (X1).

## Changed
- `booking` gets 15, not the 10 in data standards C2.2: Booking's pool is max 5 per task, a rolling deploy
  runs two tasks (10), and one-off scripts need headroom. tripplanner 30 and aa_app_user 15 as specified.

## Tradeoffs
- A role at its limit gets "too many connections for role" instead of starving the other apps; the
  alarm `rds_connections_high` (> 60) and the per-role numbers in `pg_stat_activity` show it.
