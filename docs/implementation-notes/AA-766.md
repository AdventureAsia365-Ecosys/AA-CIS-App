# AA-766 — Tenant 360 panel: Settings editors, Cost, Quality, Markets (S236)

## Inventory before this change (S235 / AA-666 state of /admin/tenants)
Inline 360 panel already had: Tours, Pipeline|Activity, API Usage, Brand (editable, AA-557),
Social Content (skeleton), Usage & Billing, Quality (per-channel gate telemetry, client-filtered),
Audit, Settings (read-only). Missing per AA-766: Settings editors, Cost tab, per-gate Quality +
tenant edit rate, Markets tab.

## Decisions
- Settings editors reuse the existing writes: `PATCH /admin/tenants/{id}` (plan_tier) and
  `PUT /admin/tenants/{id}/config` (markets, channels, posts_per_week). Both already write an
  `acp_shared.audit_log` row with before/after (AA-797) — verified in api/routers/admin.py; no new
  audit code needed for them.
- RPM: the PATCH could only change RPM through a plan change (PLAN_LIMITS default). Added an
  optional `rate_limit_rpm` (1..10000) to the PATCH body: alone it overrides RPM and writes a new
  audit action `tenant.rate_limit_changed`; with `plan_tier` it replaces that plan's default inside
  the existing `tenant.plan_changed` row. The PATCH response now also returns the stored
  `plan_tier` + `rate_limit_rpm` so the editor shows the plan default a plan change applied.
  10000 is a typo guard (10x the largest plan default), not a commercial limit.
- New admin-only read router `api/routers/admin_tenant360.py` (prefix /admin/tenants):
  `/{id}/cost`, `/{id}/quality?days=`, `/{id}/markets`. Separate file because admin.py is ~1.6k
  lines; registered in api/main.py after admin_content_quality.
- Cost = the AA-798 definition (llm_call_log, tenant_id, current calendar month via
  date_trunc('month', now()), shadow rows excluded, Jev included), so Cost totals equal the
  Usage & Billing `llm_cost_usd`.
  - $/piece: calls with `content_piece_id`, channel = COALESCE(piece.channel, request.channel)
    (same as gate-telemetry); kind blog = `blog`, social = facebook/tiktok/instagram/linkedin,
    other = email/landing_page/ads.
  - $/tour: cost of `t2_*` stages / `tours_rewritten` from v_tenant_monthly_usage.
  - Revenue = plan `price_usd_monthly` (full month, not prorated) + `overage_usd`; margin =
    revenue − LLM cost. No plan → revenue/margin null (never invented, AA-798).
- Quality per T10 gate: unnest `content_piece.gate_ledger` over approved+held pieces in a window
  (7/30/90 days, default 30). Entry without `blocking` counts as blocking (same default as
  sentence_repair / _hold_or_ship). "held_pieces" = held pieces where that gate failed.
- Tenant edit rate = distinct tours with a `tenant_edit` version / distinct tours with an
  `ai_generated` version (gold_aa_internal.tenant_tour_versions). There is no tenant edit path for
  T9 content pieces today, so this is the only real edit signal.
- Markets: two market sources exist and both are shown — SEO markets
  (`shared.tenant_seo_config.target_market`, written by Brand Identity, read by T2/T7/research) and
  planning markets (`acp_shared.tenant_config.markets`, the Settings editor). Coverage is computed
  for the SEO markets: places = canonical places of segments built from platform atoms
  (v_active_tour_atoms) of tours the tenant adopted (tenant_tour_versions); for aa_internal, every
  active master. Fresh = researched within 182 days (segment_research.FRESH_FOR).
  The endpoint uses the pure seed_builder helpers, NOT slate._tenant_market_codes, because that one
  records an unmapped_market_requests row as a side effect — a page view must not write.
- Frontend: new tab components in `frontend/app/admin/tenants/_components/` (react-query +
  kit DataTable/Badge/Button/ErrorState/Toast). Tab order: … Usage & Billing · Cost · Quality ·
  Markets · Audit · Settings. The AA-666 per-channel gate table stays under the new Quality view.

## Changed
- PATCH /admin/tenants/{id}: + `rate_limit_rpm`, response + `plan_tier`, `rate_limit_rpm`.
- `AdminTenantAuditAction.RATE_LIMIT_CHANGED = "tenant.rate_limit_changed"`.
- New endpoints: GET /admin/tenants/{id}/cost | quality | markets.
- page.tsx: TenantDetail now takes the tenant row + onChanged (header plan/RPM come from the list
  row, which reloads after a Settings save); read-only SettingsTabContent removed; Billing footnote
  points to the Cost tab.
- CONTEXT.md: RPM override + a Tenant 360 paragraph under Tenant lifecycle.
- No migration (none needed).

## Tradeoffs
- Optimistic UI: plan/RPM switch the "Current" line at once and roll back + error toast on failure;
  planning config writes the react-query cache optimistically and rolls it back, while the form
  keeps the admin's edits so they can retry.
- Market codes in the planning config are validated client-side only (2 letters, upper-cased,
  de-duplicated); the backend still accepts any non-empty strings as before (no behavior change for
  other callers). A warning shows codes outside the 6 SEO-supported markets.
- Coverage scope uses platform atoms of adopted tours; a tenant with no adopted tours shows 0 places
  in scope (explained in the UI) instead of falling back to the platform-wide count.
- Reads stay open to every staff role at the BFF (API_WRITE_RULES only gates writes) — same as the
  existing /admin/billing and gate-telemetry reads; the page itself (/admin/tenants) is admin-only.
