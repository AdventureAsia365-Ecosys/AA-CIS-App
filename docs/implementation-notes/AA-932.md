# AA-932 — CIS part of the partner CRM owner bootstrap (migration 269)

The partner CRM (AA-Partner, root ADR 0010 / 0008a) gets its own schema `crm`, owner role `crm_owner` and migration
key `crm-NNN`. The roles and the schema come from the Infra role bootstrap (`roles/` rl-003, rl-004) and the CRM's
first file `crm-001` lives in AA-Partner; this repo only owns the registry `shared.schema_versions`.

## Decisions

- **Migration 269 grants `crm_owner` exactly what CIS 243 grants `bk_owner` / `tp_owner`**: `USAGE` on `shared`,
  `SELECT, INSERT` on `shared.schema_versions`, and one more branch in the key guard (`crm_owner` inserts `crm-` keys
  only). Without it DB Migrate refuses `crm-001` (exit 8: the owner a file is switched to must be able to register
  itself, Infra `CAN_REGISTER_SQL`).
- The key guard is replaced with `CREATE OR REPLACE` (same name, signature, trigger, comment updated); every 243 rule
  stays. `crm-%` is an exact prefix: `crmx-001` or an upper-case key is refused.
- Guard 1 also checks that no CRM runtime or NOLOGIN role has `USAGE` on `shared` (ADR 0008a decision 1: no
  cross-schema grant in either direction).
- `tests/integration/rls_catalogue_rules.py`: `SCHEMA_OWNERS` gains `crm`, `ROLE_OWNERS` gains `crm_owner`, `crm_app`
  and the four NOLOGIN roles, so rule g flags any CIS grant to a CRM role. Infra keeps a byte copy (Copy Guard).
- `conftest.py` creates `crm_owner` (NOLOGIN) like the other Infra roles, because the replay applies 269.

## Changed

- `api/migrations/269_crm_owner_registry_grant.sql` (new), `tests/integration/test_aa932_migration_269.py` (new),
  `tests/integration/rls_catalogue_rules.py`, `tests/integration/conftest.py`.

## Tradeoffs

- One CIS migration per new owner (the guard lists owner roles by name) instead of a table-driven guard: a lookup
  table would be a second registry next to Infra `owners.yaml`; four owners do not justify it.

## Should know

- Apply order on Dev: Infra rl-003 → **269** → `crm-001`. 269 refuses to run before rl-003 (guard 0).
- Verified before CI on a throwaway PostgreSQL with the real DB Migrate runner (switch to `cis_owner` as on Dev):
  `crm_owner` registers `crm-999`, is refused `bk-999`, and `crm-001` then applies as `crm_owner`. The integration
  test needs the full migration replay, so it runs in CI only.

## Review round (S248, independent agent review)

- **Blocker fixed: rule g.** 269's two grants to `crm_owner` (`shared` USAGE, `shared.schema_versions` SELECT, INSERT)
  were reported by rule g (CIS object granted to the crm owner's role), so `test_rls_catalogue_guard` failed with
  `[g] shared:crm_owner` and `[g] shared.schema_versions:crm_owner`. Both are now allowlisted as contract grants, next to
  the 243 entries for `bk_owner` / `tp_owner`. Infra keeps the byte copy, and its new registry test makes every
  `owners.yaml` owner grant to another owner's role pass the rules.
- **Integration tests now run locally**, on a throwaway PostgreSQL 15.19 cluster with the CI shape (superuser `cistest`,
  role `app_user`, plain `postgres:15` without pgvector): `test_rls_catalogue_guard`, `test_aa852_migration_243`,
  `test_aa860_migration_245`, `test_aa860_migration_246`, `test_aa932_migration_269` together → 117 passed; with
  `test_x1_cis_app_privileges` and `test_s243_admin_consistency` → 44 passed. With the pre-fix rules file:
  `test_catalogue_has_no_unallowlisted_violation` failed on exactly the two crm_owner grants.
