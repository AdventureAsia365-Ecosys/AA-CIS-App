# AA-774 — visiting/practical place-card facts out of the writer seed

## Decisions
- Filter at READ time in `atom_seed.py` (`WRITER_FACT_KINDS = {what_it_is, history, setting, naming}`,
  `writer_facts(card)`); stored cards are untouched, `FACT_KINDS` unchanged, so old cards still validate and
  the admin card view (reads `acp_shared.place_card` directly) keeps every kind. No migration.
- A fact without `kind` counts as `what_it_is`, matching `place_cards._clean_facts`.
- The sibling gate (`RICH_CARD_FACTS`) stays on the UNFILTERED checked-fact count, both in `compose_seed`
  (`pick_siblings(card_fact_count=len(_card_facts(card)))`) and in `atom_seed_parts` (sibling query
  skipped). Synthesis correction: otherwise a LinkedIn card that loses 1-3 practical facts drops below 3
  and brings back the S233 "Other trips" borrowed-places lines.
- `compose_route_moment` picks the richest card by WRITER facts and renders only those; the thin tag
  (`moment_fact_count`) therefore counts writer facts + source sentences.
- Drafter prompt (`_CARD_SYSTEM` facts bullet) = plan 09 §3.5 text (ADR 0012). Checker prompt unchanged.

## Tradeoffs
- Filter after `canonicalize_route_cards`, not before: a numeric conflict between a writer fact and a
  practical fact of another card could drop the writer fact and then the practical one is filtered too.
  Rare (conflicts are about the same measure); keeping canonicalisation on the whole card is simpler.
- `place_cards.render_card` (exported, no caller) is left unfiltered: importing atom_seed there would
  be circular, and nothing renders through it.
- Thin moments: dropping practical bullets can push a moment under `THIN_FACTS`. The offline heuristic
  recount on the 4 distinct r4 seeds shows 0 thin changes (removes 1 / 2 / 4 / 8 bullets); the probe on
  live cards is the authoritative number (Done-when (b)).
