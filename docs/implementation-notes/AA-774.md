# AA-774 — visiting/practical place-card facts out of the writer seed

## Decisions
- Filter at READ time in `atom_seed.py` (`WRITER_FACT_KINDS = {what_it_is, history, setting, naming}`,
  `writer_facts(card)`); stored cards are untouched, `FACT_KINDS` unchanged, so old cards still validate and
  the admin card view (reads `acp_shared.place_card` directly) keeps every kind. No migration.
- A fact without `kind` counts as `what_it_is`, matching `place_cards._clean_facts`.
- The sibling gate (`RICH_CARD_FACTS`) stays on the UNFILTERED checked-fact count, both in `compose_seed`
  (`pick_siblings(card_fact_count=len(_card_facts(card)))`) and in `atom_seed_parts` (sibling query
  skipped). Synthesis correction: otherwise a LinkedIn card that loses 1-3 practical facts drops below 3
  and brings back the S233 "Other trips" borrowed-places lines.
- `compose_route_moment` picks the richest card by WRITER facts and renders only those; the thin tag
  (`moment_fact_count`) therefore counts writer facts + source sentences.
- Drafter prompt (`_CARD_SYSTEM` facts bullet) = plan 09 §3.5 text (ADR 0012). Checker prompt unchanged.

## Changed
- `services/acp_shared/atom_seed.py`: `WRITER_FACT_KINDS`, `_card_fact_dicts`, `writer_facts`; render paths
  use `writer_facts`; gate paths keep `_card_facts`. Module docstring records AA-774.
- `services/acp_shared/place_cards.py`: facts bullet of `_CARD_SYSTEM`; comments on `FACT_KINDS` and
  `PROMPT_SHA`. `PROMPT_SHA` changes automatically: `6b2ef32fe2cb38fa` → `681e1e20ff92d7f3`.
- `tests/unit/test_aa774_card_fact_kinds.py` (13 tests). No existing test needed a change; the T9 writer
  SHA guard lines in `test_aa771_s234_voice_contract.py` are NOT touched (no writer prompt changed).

## Tradeoffs
- Filter after `canonicalize_route_cards`, not before: a numeric conflict between a writer fact and a
  practical fact of another card could drop the writer fact and then the practical one is filtered too.
  Rare (conflicts are about the same measure); keeping canonicalisation on the whole card is simpler.
- `place_cards.render_card` (exported, no caller) is left unfiltered: importing atom_seed there would
  be circular, and nothing renders through it.
- Thin moments: dropping practical bullets can push a moment under `THIN_FACTS`. The offline heuristic
  recount on the 4 distinct r4 seeds shows 0 thin changes (removes 1 / 2 / 4 / 8 bullets); the probe on
  live cards is the authoritative number (Done-when (b)).

## Fact edit endpoint (S235)
Follow-up, option (a) approved by Nghiệp 14/10/2026: admins correct mis-kinded facts (e.g. the Tsaatan
"access requires a multi-hour horse or reindeer ride…" stored as `setting`) so they stop reaching the
T9 writer seed.

### Decisions
- `PATCH /admin/content-quality/place-cards/{card_id}/facts` body
  `{"edits":[{"index","kind"?,"text"?,"drop"?,"expected_text"?}], "reason"}`; `GET .../place-cards/{card_id}`
  returns the card plus `fact_rows` (index, kind, text, `in_writer_seed`) and `fact_kinds`.
- Pure rules in `place_cards.apply_fact_edits` (router only maps errors: FactEditError → 422,
  FactEditConflict → 409). `index` = position in the stored array as loaded; drops apply after all
  edits, so indices never shift mid-request. Each index at most once; drop cannot carry kind/text;
  text whitespace-normalised, 1..600 chars; an all-no-op request is 422.
- `expected_text` (optional; the UI always sends it) guards against a stale form editing the wrong
  fact after a merge / another edit → 409, the UI refetches the card.
- Kept facts keep every other key they had (only `kind` / `text` change) — shape preserved.
- Backend role check `x-admin-role == admin` (same as AA-769 sentence actions / AA-797 tenant writes);
  actor `admin:{x-admin-user-id}`. Audit: `PlatformAuditAction.PLACE_CARD_FACTS_EDITED`
  (`place_card.facts_edited`), tenant_id NULL, details `{reason, display_name, country, facts_before,
  facts_after, changes:[{index, action: edit|drop, before, after}]}`.
- BFF: new `API_WRITE_RULES` entry `content-quality/place-cards` → admin. It also narrows the existing
  verdict / merge / build writes; no real change since the Content Quality page is already admin-only.

### Changed
- Card `status` / `verified_by` are NOT touched by a fact edit (a verified card stays verified; the
  admin edit is itself the human review). No re-check LLM call on edited text.
- No migration (facts is jsonb already).

### Tradeoffs
- Index-based addressing (facts have no ids) + `expected_text` instead of adding fact ids: no data
  backfill, and the conflict window is tiny (admin-only, low write rate).
- Pieces already written keep their stored `writer_input`; only new seeds read the corrected card.
