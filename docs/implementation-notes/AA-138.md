## Decisions

- Declare `brand_rule_version: Optional[int] = None` before the try/except brand fetch block so it's always in scope for the INSERT even if the brand fetch fails.
- Add `version` to both SELECT branches of the brand fetch query (named-filter branch and is_active branch) — they share the same post-fetch extraction logic.
- Refresh button on S1 page also clears `tourStatuses` + `runResults` so stale "Failed" badges from prior in-session runs are wiped. Does NOT clear during an active run (`running` guard).
- Call `loadTours()` after `startRun` loop finishes so `rewrite_count` and `last_rewritten_at` reflect the just-completed rewrites before the progress summary appears.

## Changed

- `api/routers/admin_pipeline.py`: both brand rule SELECT queries now include `version`; `brand_rule_version` extracted from `br_row`; INSERT into `generated_content` adds `brand_rules_version = $16`.
- `frontend/app/admin/s1-rewrite/page.tsx`: `handleRefresh` replaces bare `loadTours` on Refresh button (clears stale state); `startRun` calls `loadTours()` after the rewrite loop.

## Tradeoffs

- Could also pass `brand_rule_version` through the `metadata` JSONB field instead of the dedicated column — chose the column because the schema already has it and it's queryable without JSON extraction.
- Not resetting `tourStatuses` after `startRun`'s `loadTours()` call — intentionally keeping the per-tour done/failed badges visible in the progress summary until the user explicitly refreshes.

## Should know

- `brand_rules_version` is `smallint` in the DB schema. Python `int` passed via asyncpg is fine — no cast needed.
- The UPDATE path for `pipeline_runs` (batch cost tracking) is unchanged; it still silently no-ops when batch_id has no matching row.
