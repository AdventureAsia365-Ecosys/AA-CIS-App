# AA-640 — One source for the plan tour quota; over-quota allowed and billed

## Decisions (Nghiep, 25/09/2026)
- `shared.membership_plans.tours_quota_monthly` is the only tour quota (starter 50 / growth 200 /
  business 500 / enterprise+internal 999999) — the number the portal shows and billing uses.
- Over quota: the rewrite is allowed and billed as overage (`overage_rate_usd_per_tour`, already
  computed by `v_tenant_monthly_usage`). No 429 while the product is in trial.

## Changed
- `_get_tenant_plan_limit`: one query joining tenants → membership_plans (unknown plan falls back to
  the starter row; missing tenant → ("starter", 0)).
- `_check_and_consume_rewrite_quota`: still increments the monthly counter; logs
  `rewrite_over_quota` instead of raising 429.
- `PLAN_LIMITS` (admin.py) keeps RPM only; admin tenant detail reads tours/month from
  membership_plans.
- Tests: test_aa489 rewritten for the new rules; two trigger_rewrite tests re-sequenced (plan
  lookup is a fetchrow now).

## Should know
- The monthly counter (`tenant_rewrite_usage`) counts attempts; billing overage counts versions in
  `v_tenant_monthly_usage`. They can differ slightly (a failed rewrite still counts as an attempt).
  Billing is the one that charges.
