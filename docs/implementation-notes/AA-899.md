# AA-899 — OpenAPI export and breaking-change check (AA-CIS-App part)

Issue scope: CI exports `openapi.json` for CIS and Booking, oasdiff on PRs against `main`, `response_model` for public
routes, publish the spec with the release. Done when: a test PR removing a public field fails unless labelled
breaking. The AA-Booking half is the same design (`AA-Booking/docs/implementation-notes/AA-899.md`).

## Decisions

- **Committed document, two checks.** `docs/api/openapi.json` is committed (reviewable diff in every PR, the API
  reference of the repo). Unit Tests (required) fails when it is stale; a separate small workflow `api-contract.yml`
  diffs the base branch's committed file against the PR's with oasdiff. The breaking job therefore needs no Python
  install (seconds, not minutes) and the stale check reuses the dependencies Unit Tests already installs.
- **Base = `HEAD^1` of the pull_request merge commit** (fetch-depth 2), i.e. the base tip the PR is merged onto; the
  merge commit's file is exactly "main + this PR". No base file (this PR) = first export, pass with a notice.
- **oasdiff 1.33.0, pinned by release URL + SHA-256** (released 01/10/2026; newer 1.34.x were under a week old).
  `--allow-external-refs=false`. Fail level ERR, plus two checks raised to error in
  `.github/oasdiff/severity-levels.txt`: `response-optional-property-removed` (oasdiff calls it info; a client can
  still read the field) and `request-parameter-removed` (warning by default; the brief counts removed params as
  breaking). Tool errors (exit codes other than 0 and 1) always fail, whatever the label.
- **Public vs internal paths.** Public = everything but `/admin/*` (`INTERNAL_PATHS: ^/admin/`). `/admin/*` is called
  only by this repo's admin BFF, changed in the same PR; its breaks become warnings, so the gate does not cry wolf on
  every admin refactor. `/v1/*`, `/auth/*` (Booking calls `/auth/admin-login`, `/auth/booking-token`, the bridge
  JWKS) and `/health*` fail.
- **Escape hatch:** label `api-breaking`, or a conventional breaking title (`type!:`), which release-please also reads.
  The workflow runs on `labeled` / `unlabeled` / `edited`, so adding the label re-runs it without a push (unlike the
  `q0-relabel` label of CI, which needs a push).
- **Deterministic, host-free output:** sorted keys, `servers` dropped, `info.version` = `unreleased` (else every
  release PR, which bumps `api/version.py`, would make the file stale), `info.x-generated-by` marker (handbook rule
  "generated files say do not edit"). Hash-seed independence checked by hand (PYTHONHASHSEED 1 vs 999: same bytes).
- **No secret, no AWS call.** `api.main` calls `init_sentry()` at import, which reads the DSN from Secrets Manager.
  The script forces stub AWS keys, `/dev/null` config files, no profile/session token, endpoint `127.0.0.1:9`, one
  attempt: it fails fast offline, and a laptop with a live MFA session never uses its credential. The unit test
  calls `build_spec()` in the normal unit-test environment (same output, asserted by the stale test itself).
- **Pinned `fastapi==0.161.1` and `pydantic==2.14.1`** in `requirements.txt` (were `>=`). With floating versions the
  stale test would go red on unrelated PRs the day FastAPI or Pydantic changes its schema output. The pins are exactly
  what CI and the image resolved on 23/10/2026 (Unit Tests log of main run 39988043492), so runtime behaviour does not
  change.
- **Response models, ratchet for the rest.** All `/auth/*` and `/health*` operations now have schemas
  (`api/schemas/public_api.py`: `Health`, `Readiness`, `Jwks`, `TenantSession`, plus `Quota` for `/v1/quota`). The 58
  other `/v1/*` operations that return a bare dict are frozen in `tests/unit/snapshots/aa899_untyped_public_routes.json`;
  the test fails if a new public route has no model or a typed route stays listed. Typing all 58 at once would put
  `response_model` validation (and a possible 500 on a wrong type) on every tenant route in one PR with no live test.
- **Release asset:** `release-please.yml` checks out the released SHA and uploads `aa-cis-openapi-vX.Y.Z.json`
  (`info.version` stamped with `jq`) with the CI bot App token it already mints (contents: write). No Python.

## Tradeoffs

- Committing a full spec in a public repo: it is derived only from the public source (route names, models,
  docstrings), carries no host (`servers` dropped) and passes the resource-ID check; AA-577 gated the *live*
  `/openapi.json` against bots scanning the deployed host, which this does not change.
- Gate on the committed file, not on a base spec regenerated in CI: cheaper and simpler, but relies on the stale test
  being required (it is, inside Unit Tests). A PR that skips the regeneration fails Unit Tests, not the API job.
- `contains(title, '!:')` also matches a title that merely contains `!:`; harmless (the PR title check enforces the
  conventional format anyway).
- Documentation-only `responses=` models can drift from the real body; used only where the handler builds its own
  `JSONResponse` (status 503 or a header), and the bodies are tiny.
