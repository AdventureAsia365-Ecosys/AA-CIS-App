# AA-859 PR-J — /admin/atoms is staff only (tenant-JWT branch removed, no flag)

## Decisions
- **No flag.** Nghiệp decided in S240 to delete the AA-431 tenant-JWT branch outright rather than gate it
  behind `ADMIN_ATOMS_STAFF_ONLY_FLAG` (plan D3/PR-J). His evidence: 30 days of WAF logs
  (`docs/audits/2026-10-16-S240-aa859/admin_atoms_waf_results.json`, Q2) show 1,041 `/admin/atoms*` calls,
  all with `X-Admin-Secret` and no `Authorization` header (1,032 GET, 8 PATCH, 1 POST). So no flag constant
  is added to `aa544_tenant_pool.py`, and none was declared there.
- **The new dependency is `_require_atoms_staff`**, attached through `dependencies=[Depends(...)]` on GET
  `/atoms`, GET `/atoms/summary` and PATCH `/atoms/{atom_id}`. The handlers take no auth argument. The two
  routes that were already staff only (`/atoms/unatomized-tours`, POST `/atoms/atomize`) keep their inline
  `verify_admin_secret(x_admin_secret)`, so their signatures and tests do not change.
- **Admin secret is checked first.** A valid `X-Admin-Secret` is staff, whatever else the request carries,
  just like every other admin route (`verify_admin_secret`). If the secret check fails *and* a Bearer token is
  present, the response is 403 `"Staff only: /admin/atoms does not accept a tenant token"`, with one
  `aa859_admin_atoms_tenant_refused` WARNING line (method, path, tenant_id, tenant_token_valid). Without a
  Bearer token, the response is `verify_admin_secret`'s own 403 ("Invalid admin secret"), or 503 when no
  secret is configured, as before.
- **The refusal log decodes the token only to name the tenant** (`_bearer_tenant_id` → `verify_tenant_jwt`,
  every exception swallowed). It is never used for access. A staff JWT or a garbage token logs
  `tenant_id=None, tenant_token_valid=False`.
- The summary SQL is now two module-level constants (`_SUMMARY_TOTALS_SQL`, `_SUMMARY_BY_TOUR_SQL`): with no
  scope clause left, the f-strings had nothing to interpolate.

## Changed
- `api/routers/admin_atoms.py`: `_resolve_atom_owner_scope` was removed and replaced by `_require_atoms_staff`.
  The owner_scope bind filter is gone from list, from both summary queries and from the PATCH `WHERE`
  (`AND owner_scope = $n`). `owner_scope_class` (`platform` / `legacy`) stays: it is the staff filter the
  admin curation page uses. The module header and the comment block now describe the staff-only rule.
- `tests/unit/test_aa300_admin_atoms.py`: removed `TestResolveAtomOwnerScope`, the tenant owner_scope tests
  on list, PATCH (WHERE clause, IDOR 404) and summary, and `owner_scope=None` from every direct handler call.
  The admin no-filter test was renamed to `test_no_owner_scope_bind_filter_staff_see_every_scope`.
- New `tests/unit/test_aa859_admin_atoms_staff_only.py`, which runs through a real FastAPI app:
  - a tenant Bearer gets 403 on all three routes, never reaches the pool, and writes exactly one refusal log
    with the tenant id;
  - a Bearer with a wrong secret also gets 403;
  - a staff JWT or garbage token gets 403, and the log carries no tenant id;
  - the admin secret still gives 200, and no SQL contains `owner_scope = $`;
  - a valid admin secret wins over a Bearer header;
  - no credentials or a wrong secret gives 403 with no refusal log;
  - an unset secret gives 503, while a tenant Bearer still gets 403;
  - a route-inventory check confirms that all 5 routes are staff gated.
- No migration. No tenant-pool code, so there is no reentrancy-stub entry and no
  `test_aa859_reentrancy_j.py` (nothing on this router acquires the tenant pool).

## Tradeoffs
- **Rollback is a revert and redeploy, not a Redis `DEL`.** We accepted this because no caller exists: the WAF
  shows none in 30 days, and the frontend has none. The portal has had no `/admin/atoms` caller since AA-526
  (`(tenant)/portal/layout.tsx:31`). Grep of `frontend/app/api/tenant`, `frontend/app/(tenant)/portal`,
  `frontend/lib` and `frontend/components` finds `admin/atoms` only in `frontend/app/admin/atom-curation/page.tsx`,
  which goes through the admin BFF with X-Admin-Secret. The tenant BFF still forwards *any* path with the
  tenant's Bearer, so a tenant session can reach the route, but it now gets 403 and a log line.
- **Status codes changed for invalid tokens.** The old branch gave an invalid Bearer 401 and a staff JWT 403
  ("Tenant token required"). Both now get 403. The admin page never sends a Bearer, so it is not affected.
- Admin-secret-first means a request carrying both headers is now served as staff. The old code served it as
  the tenant (Bearer first). The WAF window has 0 such requests.
