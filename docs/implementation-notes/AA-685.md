# AA-685 — Unlogged model call sites behind the gateway (Gateway P1b)

Planned with Nghiệp on 28/09 (S201). Two PRs: this repo first (CIS call sites), then
AA-TripPlanner-Web.

## Decisions
- Embeddings get their own role `embed` (not `validate`). Migration 172 widens the `role` CHECK
  on `llm_role_config` and `llm_call_log`, and the `provider` CHECK on `llm_role_config`
  (adds `cohere`).
- TripPlanner uses option (a): a thin client that reads the catalog and route tables and writes
  `llm_call_log` itself. Option (b), an internal CIS endpoint, was rejected because the CIS ECS
  service is often scaled to 0 to save cost, and TripPlanner would go down with it.
- The caller still writes `llm_call_log` (the AA-518 convention: every stage passes a real
  `quality_signal`). The gateway does not log on its own. A guard test fails when a raw model
  call appears outside `shared/llm_client/`.

## Changed (vs. the Linear issue)
- `services/export/handler.py` was listed as calling `invoke_claude()` directly. It does not:
  it only calls `run_t5_atomize()`, which already logs. Dropped from scope.
- Found one more unlogged call: Debate (`services/acp_shared/debate.py`) calls
  `score_brand_fit()` (route `s1_judge`) and never logged it. `judge_node.py` logs the same
  helper. Added.
- `services/acp_shared/h3_rule_extractor.py` has no caller left (the HITL reject endpoint that
  called it lived in the archived ACP app, AA-467). Deleted with its test instead of moved.
- `services/content_generation/s1_batch.py` (Bedrock Batch) writes no cost log either. Not
  changed: Batch is not enabled on acc3 (AA-624), so the path cannot run. Left to AA-621.
- `a0_column_map` now sends a one-line system prompt ("You map spreadsheet columns to database
  fields. Reply with JSON only."). The old raw call had none; `LLMRequest` requires one. Same user
  prompt, same 500-token cap.
- Admin Settings: an `embed` stage only offers catalog models with `api_style='embed'`, and text
  stages never offer them. Three new groups on the page: A0, Embeddings, TripPlanner.

## Tradeoffs
- Logging stays in the caller rather than inside the gateway. Automatic gateway logging would have
  double-logged the ~20 call sites that already log with a real `quality_signal`. The guard test
  closes the gap this leaves: a new raw call fails CI.
- `judge_client.py` keeps its legacy backends (Nova Pro, GPT-5.6 Sol, GPT-4.1 direct) for the
  AA-351 comparison scripts, allow-listed in the guard test. Removing them means rewriting 4 test
  files (`test_aa298_judge`, `test_aa372_gates`, `test_aa351_judge_*`) — not worth it inside this
  issue. Production never reaches that path (all 5 judge call sites pass `stage=`).
- Embedding tokens come from Bedrock's `x-amzn-bedrock-input-token-count` response header. If the
  header is missing, tokens are estimated as chars/4 and the row says
  `quality_signal.tokens_estimated = true`.
- Embedding cost is computed from the resolved catalog row, not `pricing.calc_cost()`: when the
  catalog is unreachable `calc_cost()` falls back to Sonnet rates for an unknown model, which would
  overstate a $0.12/1M embedding ~25x. `embed.py` carries one built-in fallback row for Cohere so a
  DB outage does not stop embeddings.

## Should know
- Rollout: migration 172 is additive → apply BEFORE the deploy. Until it is applied, the new code
  still works: `f10_embed` / `a0_column_map` resolve from `SAFE_DEFAULTS`, but their log rows with
  `role='embed'` would be rejected by the old CHECK (the write is fire-and-forget, so only the log
  row is lost).
- Dry-run of 172 on Dev RDS (28/09, S201, rolled back): only the `role` / `provider` CHECKs are
  replaced; `account_route` and `shadow_sample_pct` CHECKs are untouched; 4 stages inserted.
- Pacing for Cohere (3.5 s between calls, AA-610) stays in `content_embedding.py`, per process.
  TripPlanner's search embeds share the same acc2 quota (20 req/min) and are not paced against it.
- `atom_matching.py` calls `compute_embedding()` directly from async code (no `to_thread`), so the
  3.5 s pacing sleep blocks the event loop. Pre-existing, not changed here.
