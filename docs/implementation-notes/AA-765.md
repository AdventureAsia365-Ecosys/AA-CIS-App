# AA-765 — one judge client, T11 dispatch in services/acp_publish, stage-route docstrings

Source: S229 T-series audit G6 (`docs/architecture/t-series-audit-and-plan.md`). Pure refactor: no prompt, request,
route, response or endpoint behaviour changes.

## Decisions

- **The judge client lives in `shared/llm_client/judge.py`** (the issue: "one judge client in `shared/llm_client`").
  `call_judge()` builds the judge `LLMRequest` (`judge_request()`) and sends it; `invoke_judge()` is the T10
  wrapper that returns the dict quality_gates logs; `strip_json_fence()` / `parse_judge_json[_checked]()` are the
  judge reply parsers. `services/acp_produce/judge_client.py` is deleted (its two importers, quality_gates and
  admin_llm_ops, now import from the shared module), so `grep -rn "def invoke_judge\|judge_client" services` is
  empty and the one implementation is in `shared/`.
- **Only the optional fields a caller gives are set on the request.** The gateway reads
  `LLMRequest.model_fields_set` to decide whether temperature / seed are forwarded (`client.py`), so "same values"
  is not enough: T10 sets `max_tokens` + `temperature`, S1/T2/T7 set `temperature` + `seed` (+ `model_tier` only for
  an adhoc override), exactly as before.
- **brand_fit keeps its own `LLMClient` name and passes `client=LLMClient()`.** About 30 existing tests patch
  `services.content_generation.brand_fit.LLMClient`; keeping that seam means those behavioural tests run unchanged
  against the refactored code, which is the strongest evidence that S1/T2/T7 behave as before. T10 tests patch
  `quality_gates.invoke_judge` (still a module-level name there) and `shared.llm_client.client.LLMClient` (still
  resolved at call time), so they too run unchanged.
- **brand_fit stays strict JSON; T10 keeps json_repair.** The two judges parsed differently before (brand fit:
  `json.loads` only; F9: `json_repair` salvage, AA-777). Both now share `strip_json_fence`, but the salvage is not
  extended to brand fit — that would change which replies count as verdicts.
- **T11 dispatch → `services/acp_publish/dispatch.py`**: `SUPPORTED_CHANNELS`, `INTEGRATION_TYPE`,
  `channel_display_name`, `publish_to_channel` (was `_call_adapter`), `find_remote`, `other_account`,
  `delete_remote`, plus the private adapter builders `_wordpress` / `_facebook` / `_slug` / `_site_host`. The
  router keeps HTTP, auth, the tenant pool, `_get_secret` (Secrets Manager), `_publishable_channel` (raises the
  route's 404/422/409), the SQL constants and the publish_log claim / finish / daily limit. Public names because
  they are now a module API; the router imports them by name, so tests that patched the router's seam now patch
  `pub_mod.publish_to_channel` / `pub_mod.delete_remote` (same seam, new name).
- **Docstrings**: every docstring or comment that said a judge or route *is* a fixed model (GPT-4.1 production
  judge, Nova Pro judge path, "GPT-4.1 fallback", the `model_tier` comment listing "gpt-4.1 → OpenAI direct") now
  names the stage route instead. Historical statements ("AA-757 removed the GPT-4.1 direct path", AA-714 measured
  Luna vs GPT-4.1) and code that handles the legacy keys (`catalog.LEGACY_KEYS`, pricing table, `client.py`'s
  retired-tier refusal) are left as they are. `s1_batch` / `bedrock_batch` really are Haiku-only (Batch); only
  their judge sentence changed.

  test_aa659_stage_routes, test_aa768_s233_completeness, test_aa859_* (unit + integration), test_aa817_fail_closed_routes.

## Tradeoffs

- Out of scope and untouched: `services/writing_memory/eval_judge.py` (the AA-919 R2 eval judge, json_schema,
  its own stage). It is not an S1/T2/T10 judge; moving it would be a behaviour-neutral follow-up but widens the diff.
- Migration SQL comments that still name `judge_client.py` (137, 141) are not edited: changing a migration file
  forces an Infra copy PR (lesson S241, AA-852) for a comment.
- AA-799 follow-ups (Linear comment, S244): checked. Role-scoping the `/admin/review-queue/*/approve|reject` aliases
  is covered by AA-882 (`staff_policy_if_staff` router-wide on admin_pipeline, POLICY `REVIEW_ACT`) and the
  `/v1/pipeline` admin check by AA-816 C9 (`_require_admin` + `principal_verified`). The remaining item —
  deleting the caller-less `POST /v1/pipeline/run` — removes an endpoint (behaviour + auth snapshot change), so it is
  not in this pure-refactor branch; see the lane result for how it is handed over.
