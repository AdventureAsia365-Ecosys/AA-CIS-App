# AA-1048 — two-step claim instrument v6 (lane l4-v6, S282)

This lane follows `AA-1048-two-step.md`. The single gated run of the two-step instrument v5 (pre-registration
`aa1048-two-step-v5`, run `9b0d46f8`) was no_go: stored violations kept 20/21 = 95.2 % (bar 90 %), false positives
dropped 8/25 = 32 % (bar 60 %). The tech lead chose one more pre-registered iteration (v6). The lane makes no paid
call: the orchestrator runs the DRY RUN, the trial and the one gated run.

## Decisions

- **One more step set, not a third step.** v6 keeps the two-step design and changes both texts:
  - `v6c` (classify) orders the work: first set aside everything that is not about what THIS trip gives the
    traveller (background about named places, people, crafts and regions; the writer's reading, comparisons,
    intensifiers, figures of speech, purpose; tone; words that name the reader; text about the text), then list the
    trip specifics left, then look each up with a wider set of one-step readings. The recall guard stays: wording
    about meals, the guide, other travellers, crowds, pace, effort, comfort, safety, suitability or what the
    traveller will see, hear or feel at a stop is never set aside, even when it reads as the writer's judgement.
  - `v6c`'s reply schema adds `set_aside` before `new_specifics` and `kind`, so the model commits to what it sets
    aside before it decides (the schema is part of the prompt tag).
  - `v6j` (judge) first asks whether each listed specific is a trip specific at all (a listed specific that is
    background, a reading or a word naming the reader is supported), then looks the trip specifics up with the same
    one-step readings, then keeps v5j's promise list. Same user prompt and reply schema as v5j.
- **Shaped on the run's false positives only.** v6 is in-sample for the 25 false positives of run `9b0d46f8`, so they
  are held out at claim level: the pre-registration lists their hash prefixes (16 hex) and the runner drops them from
  the pool before the subset is drawn. The pool still holds 41 sampled false positives (paraphrase 20, background 17,
  verbatim 4); the 50-claim subset takes 25 of them, none seen before.
- **The TP side is the same 21 stored violations.** The pool has no other stored violation, and a new pool needs a
  paid R1 fire plus a panel round. v6 was written without reading their text, specifics or reasons, so they stay a
  fair recall check; the pre-registration says so (`held_out.tp_side`).
- **Step sets in code.** `two_step.STEP_SETS` names each registered two-step instrument (`v5`, `v6`): its step
  prompts, its pre-registration file and that file's sha256. `--steps` picks one (default `v6`), so the CLI and the
  `ts.sh` wrapper (`two_step run --pool --fresh --trial/--limit --measured`) are unchanged. A live run refuses a
  registration whose sha256 differs from the pin, so the registration cannot drift after the code ships.
- **v5 is closed in code, not only by the ledger.** A closed set refuses every live run (trial or gated); its DRY RUN
  and the $0 `score` replay still work. The ledger stop rule is unchanged, so v6 gets exactly one gated run: the v5
  gated row is another registration and another step-1 tag, a v6 gated row refuses the next.
- **No new settings, no migration.** The bars, caps and claim limits are the CIS 417 / 423 keys; the hold-out list is
  pre-registration data, not a threshold.
- **Prompt text checks.** Every example is invented (Halvik, Orsa, Drevna, Kettle Ford, Lusk, plus v5's Tasska,
  Ilbern, Quell). A scratch leak check compared every three-word sequence with a content word of both texts with all
  104 claims of the fresh pool: the first draft shared several (an intensifier phrase, a route phrase, a "seen
  earlier" phrase, a "way of life" phrase and generic ones); all were reworded and the final check found none in the examples
  (only generic "and the source" / "the trip is" in the instructions).

## Tradeoffs

- **Same pool, held-out false positives, seen TPs.** A fully fresh pool would cost a paid R1 fire (about 0.4 USD) and
  a panel round, and the tech lead asked for one more iteration on this pool. The FP side of the v6 run is fully out
  of sample (25 of the 41 unread false positives). The TP side is the same 21 stored violations; they were not read,
  but they were measured once. The registration states this before the run.
- **Wider one-step readings raise the recall risk.** "A town the trip stops at or near lies on its road", "a place's
  other well-known name", "a meal on an evening at one hotel is at that hotel" each clear a pattern seen in the
  analysis but could also clear a violation of the same shape. The bars (route TP >= 95 %, judge TP >= 95 %) are the
  guard; H1 is falsifiable on the run.
- **A longer step-1 prompt** (about 5,100 characters of system text against v5c's 2,600) costs more input tokens
  per call; at the S282 measured price this stays far under the cap.
- **Hash prefixes in the repo.** The hold-out list commits 25 claim-hash prefixes (16 hex, as the run reports and the
  manifests carry them); no claim text.
