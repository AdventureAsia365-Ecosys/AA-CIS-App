# AA-129 — Brand Identity v2 + Master Content versions + Tenant fixes

## Decisions

- Brand endpoints added to `admin_pipeline.py` (not `admin.py`) to keep brand logic co-located with existing `/admin/brand-identity` endpoints
- Existing `/admin/brand-identity` GET/POST preserved for backwards compatibility (S1 rewrite page still uses `brand_rules_version` int; S1 page updated to use brand_name list from `/admin/brands`)
- `promote` endpoint: UPDATE published_tours using CTE to pull from generated_content by version_num
- DELETE tenant = soft delete (is_active=false), not hard delete — data retained for audit
- aa_internal tour count fix: list_tenants subquery counts from published_tours directly for plan_tier='internal' since v_tenant_monthly_usage.tours_rewritten tracks billing not catalog size
- Tour versions endpoints: lazy-load per tour on expand (no preload on page load)
- History tab "Make Current" → calls promote endpoint; refreshes detail after success

## Changed

- Migration 043 adds `brand_name TEXT` + index to `shared.tenant_brand_rules`
- brand/page.tsx: rebuilt from scratch — left panel brand list, right panel form with 11 fields, version history accordion
- master-content/page.tsx: rows now expand to show version sub-table (lazy fetch); TourDetailPanelV2 retained for "View" action
- TourDetailPanelV2 history tab: clickable rows load version content read-only; "Make Current" button with confirm
- tenants/page.tsx: delete icon button per row + confirm dialog; aa_internal tour count from published_tours

## Tradeoffs

- brands API uses brand_name as string path param (not UUID). This is intentional — brand names are user-defined strings, not system IDs. Consequence: brand_name must be URL-safe (no slashes), enforced in frontend.
- Kept tour version endpoints schema-qualified to `silver_aa_internal` only (no multi-tenant). Acceptable since admin portal only serves aa_internal catalog.

## Should know

- Route order in admin_pipeline.py: `/tours/{tour_id}/versions/{version_num}/promote` MUST be registered before `/tours/{tour_id}/versions/{version_num}` — FastAPI greedy matching
- `brand_name` will be NULL for all existing 14 rows — frontend handles NULL gracefully (shows "Unnamed" placeholder)
- S1 rewrite page brand dropdown: still sends `brand_rules_version` (int) to run-tour. After this PR, it sends `brand_name` instead. Backend `run-tour` endpoint looks up active version for the brand_name.
