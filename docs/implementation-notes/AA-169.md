# AA-169 — S2 Auto Crash-Recovery + Monitoring Fields + schema_versions fix

## Decisions

- **Recovery query joins acp_stage_runs + acp_runs**: `acp_stage_runs` has no `status` or `tenant_id`; must JOIN `acp_runs` on `run_id` to get both. Task spec's query assumed a flat schema — adjusted.
- **`_do_resume_run` extracted from `_resume()` closure**: Startup hook needs to call resume without an HTTP request context. Extracted as module-level function in router.py taking `(run_id, tenant_id, pool, graph)` args.
- **`apify_cache_hit` added to state**: State only had `dataforseo_cache_hit`. Added `apify_cache_hit: bool` to `S2AgentState` and apify node return so `compute_saved_pct` covers both cached external tools.
- **`total_calls = 2`**: Only dataforseo + apify have TTL caching. The other 5 nodes (google_trends, reddit, gsc, expand_scope, synthesize) always run live or via Bedrock — not counted in cache ratio.
- **`current_iteration` via node wrapper in graph.py**: Cleanest hook point is wrapping each node in `build_s2_graph`. Uses `pool.acquire()` to write to `acp_stage_runs.metadata`. Failures are logged as warnings (not fatal) to avoid breaking the graph run.
- **`recover_stuck_s2_runs` errors are non-fatal**: Wrapped in try-except — startup must complete even if recovery query fails (e.g., migrations not yet applied).

## Changed

- `S2AgentState` gets `apify_cache_hit: bool` field (new)
- `apify.py` returns `apify_cache_hit: True` on cache hit path (new field, was missing)
- `graph.py` wraps each node with `_with_iteration_update()` to write `current_iteration`
- `router.py`: `_do_resume_run(run_id, tenant_id, pool, graph)` extracted; `_background` writes `compute_saved_pct` after ainvoke; `_resume()` closure delegates to `_do_resume_run`
- `main.py`: `recover_stuck_s2_runs(pool, graph)` added and called in lifespan after graph init
- Migration 061 inserted to fix missing schema_versions row for 058

## Tradeoffs

- **Node wrapper vs. graph callback**: LangGraph doesn't expose a clean post-node callback API. Wrapping each node is explicit and easy to test but adds 7 DB calls per run. Acceptable for monitoring — not on the hot path.
- **Sync `asyncio.create_task` in startup**: Recovery tasks are fire-and-forget background tasks, same pattern as `_background()` and `_resume()`. ECS will have the semaphore guard applied per-tenant.
- **compute_saved_pct after ainvoke**: Reading from the dict returned by `ainvoke` is the cleanest approach. No need for `aget_state`.

## Should know

- Migration 058's `INSERT INTO shared.schema_versions` uses `description` column. Check the column name matches live schema before applying 061 (some migration files use `description`, others use `description`).
- `recover_stuck_s2_runs` is called with `create_task` for each row — if ECS restarts during a large backlog, semaphore contention will gate them naturally.
- Grace period is `updated_at < NOW() - INTERVAL '2 minutes'` — protects against racing with a run that just started right as ECS reboots.
