# AA-115 — Forbidden Word Enforcement Audit + Fix

## Decisions
- Multi-field text scanning: check `content`, `content_md`, `seo_title`, `seo_meta`, `title` in order — not just the first non-empty content field. This is the root cause of confirmed slip-throughs (forbidden words in seo_title/seo_meta escaped detection).
- `block` rules use normalized substring match: `_normalize(pattern) in _normalize(field_val)`. `_normalize` = NFKD + strip combining diacritics + lowercase. Handles accented variants.
- `flag` rules use `re.search(re.escape(pattern), text, re.IGNORECASE | re.MULTILINE)`. `re.escape()` is mandatory because patterns like `from $` contain regex special chars — raw `re.search("from $", ...)` would treat `$` as end-of-line anchor and miss "from $299".
- `replace` rule: continues to mutate the primary content field only (not seo fields) — replacing in seo_title would require additional logic and is not currently needed.
- `OutputRuleViolation` gains optional `field_name` + `matched_text` for diagnostics. Backward-compatible (existing callers don't break).
- New tests go in `tests/unit/test_output_rules.py` (not `tests/services/`) — no new pytest module dir needed.

## Changed
- `api/services/acp_post_processor.py`: added `_normalize()`, `_collect_text_fields()`, `_TEXT_FIELDS`, structlog logger, multi-field loop, regex path for `flag` rules, richer violation details.
- `OutputRuleViolation.__init__` gets `field_name` and `matched_text` optional kwargs.
- Added `scripts/audit_output_rules.py` for manual DB count verification.

## Tradeoffs
- Checking all text fields adds ~5 dict lookups per rule per call. With 22 rules and 5 fields = 110 string operations max. Negligible at S4 frequency.
- `re.escape()` means `flag` patterns cannot use real regex syntax. This is intentional — the DB migration explicitly simplified them to substrings. A future `source_type='regex'` flag could opt into raw regex if needed.
- Raising `OutputRuleViolation` on the FIRST matching block rule (not collecting all violations first) keeps the fail-fast semantics and avoids run_count being incremented for subsequent rules that would have also matched.

## Should know
- DB uses `rule_type='block'` and `rule_type='flag'` — NOT `hard_forbidden_output` / `sanitization_reject_patterns` (those are conceptual group names from compiled_writer_rules.json).
- Migration 020 seeds 18 `block` rules + 4 `flag` rules. Migration 037 adds confidence_score column — no data impact.
- The existing tests in `test_acp_post_processor.py` remain valid — they still pass with the new implementation (additive changes only to OutputRuleViolation and review_flags dict fields).
