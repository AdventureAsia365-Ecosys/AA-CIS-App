# AA-857 — Slate subject seeds the wrong place / country

Branch `fix/aa857-subject-seed-country` (AA-CIS-App). Evidence: S239 read-only dump
`.tmp-session/s239/d1_subject_atoms_out.json` (Gyeongju segment `d8aa8991e02d6754`: 37 atoms, 6
countries, `ORDER BY atom_id` took `021bfcdfd62b82c1` Lok Virsa museum, Pakistan; National Library
segment `8cc3b252cddaa88f`: Library + Traditional Arts & Craft School, Bhutan only, took
`00480b6b9d0bfedd` the craft school).

## Decisions
- **Seed rule in its own pure module** `services/acp_shared/subject_seed.py`
  (`choose_representative`), used by both `pick_subject()` (via `_resolve_representative_atom`) and
  `propose_slate()` (via `_segments_with_seed`), so "offered" and "pickable" can never disagree.
- **Place match** = same `place_cards.place_norm` / `name_forms` (accent fold, leading "the" dropped,
  a parenthetical is its own form), or same `core_key` for non-generic names, or same place card
  (`place_card_alias` of the subject place in the member's country, or the member's own
  `atom_place_card`). Never substring: "Gyeongju National Museum" != "Gyeongju". Reused the
  place-card normalisers rather than writing a third normaliser.
- **Tenant tours filter**: the seed must be on one of the tenant's own tours
  (`_tenant_tour_ids`). The Slate scores a Segment only on those tours, so a seed from another
  tour is a place the tenant does not sell (likely the terra-family Gyeongju case).
- **Subject country** is not stored anywhere (`acp_contract.atom_segment` has no country). It is the
  country of the place-matching members; if they span several countries the subject is ambiguous
  and skipped (`subject_place_in_several_countries`) rather than guessed.
- **Tie-break**: exact written form > has `evidence` (richer seed, lessons S232) > atom_id (last,
  deterministic only).
- **Route branch**: stays on the Route's own tour (one country); prefers the place-matching member,
  falls back to any live member of that tour (T9 seeds a Route from every Segment anyway).
- **A3 guard at component level** in `segment_matching._connected(country_of=...)`: two union-find
  components merge only when at most one known country is among them. The AA-695 pair veto was not
  enough: union-find is transitive, so Korea–unknown–Bhutan chains (an unknown-country atom, or a
  pseudo-Segment whose members have no country) glued countries together. Plus
  `assert_one_country()` in `derive_segments` (raises `MixedCountrySegmentError`; a bug guard).
- **Repair keeps the Segment id with the canonical-place country** (keeper), so Subjects / Routes /
  aliases already pointing at the id keep meaning the place they were labelled with; other-country
  member rows are detached and their tours re-run through the existing A3 segment stage.

## Tradeoffs
- The propose-time filter adds one members query + one alias query per Slate proposal (all
  candidate Segments at once). Cheap next to Debate; worth it to never offer a wrong-place subject.
- Stricter offering: subjects whose canonical place sits only on other tenants' tours, or only under
  another wording on the tenant's tour, stop being offered. The dry run counts how many current
  `proposed` subjects this drops (`proposed_subjects_under_new_seed_rule`) before deploy.
- Component guard makes the grouping depend on pair order in principle; pairs are visited in sorted
  atom_id order, so it stays deterministic (test: reversed input, same output).
- Existing mixed Segments are NOT split by the guard: a re-run only adds members. Data needs the
  repair (detach + segment re-run), planned as a DRY RUN first.
