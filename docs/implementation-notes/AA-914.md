# AA-914 — Blogs drop route Segments the trip has no atom in

Branch `fix/blog-drops-segments-the-trip-lacks` (AA-CIS-App), on top of the AA-779 real-question chain.
Root cause (S245 investigation, Linear comment): a stale frozen snapshot plus a historical Segment-label
overwrite (the AA-857 collision class, 08–11/10). Current Routes are clean (0 foreign Segments); six old
`angle_gate_request` rows still carry ids that now hold another tour's Segment or nothing.

## Decisions
- **One shared guard** `services/acp_shared/route_guard.py`, used by every reader of
  `route_segment_ids` / `route.ordered_segment_ids`:
  - `trip_route_segment_ids(conn, trip_id, ids, ...)`: follows a merged id through
    `segment_matching.resolve_segment_aliases` (the AA-857 chain resolver, not a second one), then keeps a
    Segment only when the trip has a live, non-alias member atom in it — the same member test
    `content_writing._ROUTE_SEGMENT_TEXT_QUERY` already used for the atom text (`v_active_tour_atoms`,
    `owner_scope IN ('platform', tenant)`). One query for the whole snapshot.
  - Returns the **live** ids, in snapshot order, without duplicates (two old ids merged into one live
    Segment count once).
  - Drop reasons: `trip_has_no_live_atom` (the foreign / re-labelled case), `unknown_segment` (no
    `atom_segment` row), `duplicate_after_alias`, `no_trip_id`. Each drop is a `route_segment_dropped`
    warning with request id, stored id, live id, reason, trip id and the consumer name; an alias
    resolution is an info line `route_segment_alias_resolved`.
  - Pure core `filter_route_segments` for unit tests.
- **Readers**
  - T8 (`acp_angle_gate.service.set_goal_and_generate`): guards once right after the request read and
    replaces `route_segment_ids` in the in-memory request, so both the Route digest (`_route_moments`)
    and the real-question chain (`_blog_search_demand` → `collect_real_questions(segment_ids=...)`) see
    only the kept Segments.
  - T9 (`acp_content_writing.service.start_write`): guards before `_fetch_route_segments`;
    `route_segment_count` is now the kept count.
  - Slate pick (`slate._resolve_representative_atom`, Route branch): reads the Route through
    `route_guard.current_route` (`superseded_at IS NULL`), guards its Segments against the Route's own tour
    before persisting the snapshot, and anchors on the first **kept** Segment.
  - Admin regenerate (`admin_content_quality.regenerate_angles`): the clone no longer copies
    `route_segment_ids` verbatim. It uses the Subject's Route when that Route is still current, else the
    old snapshot — guarded either way. 409 when no Segment is left.
- **A guard read error is not swallowed**: T8 / T9 run in jobs that retry; writing from an unguarded list
  would be the bug this issue closes.

## Changed
- Scope item 1 asked to drop Segments "the trip has no live member atom in". Implemented as asked; the
  country check of the investigation's fix sketch (Segment-layer / route-detection country guard) is not
  part of this PR — current data has 0 cross-country Routes (Q6/Q8), and the member test catches every
  snapshot Q7 found.
- A Subject on a superseded Route is refused at pick (`SubjectNotEligibleError`, "refresh the Slate and
  pick again") instead of seeding from the old Segment list. The next Slate proposal already deletes such
  proposed Subjects.
- The six old request rows are left as they are (history); the read-time guard makes them harmless.

## Tradeoffs
- Following a superseded Route to the current version of the same identity `(tour_id, first_day,
  last_day)` was considered for the pick. Rejected: the old hub name / score the tenant saw may not match
  the current version (the hub label flipped across countries in the 08–11/10 history), and refusing
  matches the existing "rebuilt away — refresh the Slate" path.
- Regenerate prefers the current Route over the snapshot: the new angles describe what the tour has now.
  When the Route is superseded, the guarded snapshot is used instead of the superseded Route row.
- If the guard drops every Segment, T8 falls back to the single-atom seed (as for an empty list before);
  T9 raises the existing "None of route_segment_ids resolved…" error; regenerate returns 409.
- The tenant `GET` of a request (`fetch_request`) still returns the raw stored ids (ids only, no labels);
  not changed.
