# AA-668 — Writer panel (Social Content): Goal → Angle → auto-write in a right-side drawer

Session S237, lane cis-portal item 3. Scope this session: Social Content only. The tour-rewrite
writer (CatalogDrawer + LiveWriter) moving into the same panel is a follow-up.

Two branches, stacked:

1. `fix/aa-668-brand-default-cta` (small PR, merge first) — the extra CTA step.
2. `feat/aa-668-writer-panel` (stacked on 1) — the drawer.

## Decisions

- **CTA (part 1):** the write-step effect in `AngleGateWizard.tsx` used to ask the tenant for a
  CTA whenever `angle_gate_request.cta` was NULL, which is every real request. The server already
  falls back to the brand's `default_cta` (AA-771, `service.py` `start_write`: `req.cta or
  cta_override or brand default_cta`). The effect now always calls `write`; the inline CTA field
  only shows on the server's 422 `MissingCTAError` (brand has no default CTA). No backend change.
- **Panel (part 2):** the Writer panel is `WriterPanel.tsx`, a kit `Drawer` (720 px on desktop;
  the Drawer's `maxWidth: 100%` makes it a full-screen sheet on a phone). It reuses
  `AngleGateWizard` in `embedded` mode rather than a new state machine: the wizard already owns
  every fetch/poll (request status, `t8_angles` progress, write, piece poll, LiveWriter progress).
  `embedded` now means "inside the panel": the panel owns the context header (Subject title,
  Channel, Segment/Route), the close action and the finished-piece view + actions, so the wizard
  hides `SubjectHeader`, "Start over", the "Content ready" line and `WriteDonePopup`.
- **One click per angle:** each Angle card carries its own "Write with this angle" button, which
  chooses the angle and starts the write at once. This replaces the AA-469 pick-then-confirm pair
  (in both the panel and the standalone T8 page). Goal stays select + "Generate 3 angles", because
  generating angles costs an LLM call and a mis-click there should not spend it.
- **Goal cards:** a 2-column grid (1 column on a phone) so all 8 goals fit the panel without
  scrolling at 1440x900.
- **"Streaming":** no new transport. The panel polls the existing job endpoints the wizard already
  used (`GET /v1/angle-gate/requests/{id}`, `GET /v1/content-writing/pieces/{id}`,
  `GET /v1/progress/piece/{id}` via `LiveWriter`). No LLM call runs inside an HTTP request; T8 and
  T9 stay background jobs (AA-764 / AA-652).
- **Closing keeps the job:** `useWriteWatcher` (in WriterPanel.tsx) takes over a piece the panel
  closed while `ready_state === "in_progress"`, polls it every 4 s (10 min ceiling) and raises a
  kit toast when it is ready or failed. Reopening the same request hands it back to the panel.
- **Reopen:** a Subject picked during this visit gets a "Continue" button. The Slate API does not
  return a picked Subject's `request_id`, so after a reload the shortcut is gone; the piece is in
  My Content either way. No backend change was made for this (scope: no backend change).
- **Result actions:** Export text (+ Export HTML for blog), Open in My Content, Publish (blog and
  facebook only, the channels `v1_publish` supports) behind a `ConfirmModal`; "Change angle" stays
  in the wizard's stepper (it is the "regenerate angle" action — reopens the 3 angles, no new LLM
  call). The AA-819 `AiContentNotice` sits above the actions and inside the publish confirm.
- **Tenant sees content only:** the finished view shows the text and nothing about gates, holds or
  scores. It is copy-locked like My Content's drawer (export is the audited way out, AA-613).

## Changed

- `AngleGateWizard.tsx`: CTA effect (part 1); `onReset` prop removed (its only caller was the
  old inline accordion), `onPieceChange` added; embedded-mode trims listed above; goal grid; angle
  one-click; `LiveWriter compact` inside the panel; the 422 CTA field links to Brand Identity.
- `SlateTab.tsx`: inline accordion replaced by the panel; wrapped in the kit `ToastProvider`.
- `reviewListApi.ts`: `publishPiece` returns the result and treats `success: false` (the endpoint's
  200 for a failed remote post) as an error; `exportPiece` takes only the fields it reads, so the
  panel can export a piece that is not a `ReviewItem`; `PUBLISHABLE_CHANNELS`.
- `_kit/Toast.tsx`: toast z-index 9999 -> 10001, above Drawer/Modal (10000). A toast fired from
  inside an open drawer was painted under the drawer backdrop. Affects every kit toast (only the
  stacking order).
- Tour rewrite (CatalogDrawer + LiveWriter) is NOT moved into the panel this session (lane plan:
  Social Content only). The issue's "same panel for tour rewrite" stays open as a follow-up.
- No Brand Identity change: `default_cta` already exists in Brand settings (AA-771).

## Tradeoffs

- Reusing the wizard inside the panel keeps one state machine (fewer bugs, the standalone T8 page
  keeps working) at the cost of `embedded` branches in the wizard.
- The watcher is client-side only, so a toast needs the Slate page to stay open; if the tenant
  navigates away, the piece still lands in My Content (the job runs server-side).
- The panel is 720 px, wider than the kit default (480), so angle cards and the text read
  comfortably; the Slate behind stays visible on the left at 1440 px.
