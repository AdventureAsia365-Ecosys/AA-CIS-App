# AA-1116 — option B price list and trials on attach (CIS slices S1-S6)

Tech lead 16/11/2026: option B, and every price, threshold, limit and policy value is data an administrator edits in
the CIS admin. Design: the S282 pricing gap audit (10 slices). This repo carries S1-S6; the root PR carries S10.

## Decisions

- **Migrations 435-439 ship as one migration-only PR** (MIG-4; all contract: they ALTER existing tables, replace a
  view or a function, or seed config rows). 434 was taken by another lane (AA-1120). The code PR follows once Infra
  Migration Apply has applied them.
- **S2-S6 ship as one code PR.** They touch the same files (provision, plans service, Tenant 360 Subscription tab, the
  route policy snapshot, openapi.json, these notes); stacked PRs would go DIRTY one after the other. The commits stay
  per slice.
- **Settings reader in SQL is a view, not a function** (`shared.v_setting_billing_effective`, 435). A function runs as
  its caller (booking / tripplanner through a catalog view cannot read the FORCE RLS settings tables) and a SECURITY
  DEFINER routine in `shared` is refused by MIG-6 (CIS 245's guard). The view reads as its owner.
- **AI budget** (437): content plan `ai.budget_usd_monthly` x `cis.billing.trial_ai_budget_pct` while the content
  subscription is trialing, + `ai.budget_addon_usd_monthly` of each live crm / tripplanner plan (x the trial share
  while that subscription trials). Overrides and AA-1016 amounts stay absolute (decision 4). An AA-1016 row with no
  amount follows the plan (decision 5); unlimited only for kind internal.
- **No retail add-ons** (tech lead decision 14, after the TripPlanner review; reviewer fix pass): no `addon` product,
  no `unit` price unit, no `shared.tenant_addon` table, no Tenant 360 Add-ons card or `/addons` routes, no add-on rows
  in `catalog.v_tenant_billing_v1`, `addon.*` out of `cis.billing.founding_eligible_plans`. The custom domain is a
  TripPlanner Pro feature (CRM Pro as before); an AI top-up is a per-tenant override of `ai.budget_usd_monthly`. The
  first lane pass had built the catalogue from decision 1 (since overridden); 435-439 are not applied anywhere yet, so
  the files were rewritten in place instead of adding a contract file that drops the table.
- **Trials on attach** (decision 3): an attach of a NEW crm / tripplanner add-on (saga attach mode, and an approved
  add-on request) starts trialing for `cis.billing.trial_days_default`; a product the tenant held before comes back
  active. A create without `trial_days` stays active (as before; the trial length is the drawer's choice).
- **Agreed price = per billed unit** (reviewer fix): `agreed_price_monthly` replaces the list UNIT price, like the
  price it stands for: per seat on a per-seat plan (line = agreed x max(seats, seats_min), so seats added during a
  12-month lock are billed at the locked seat price), the plan fee on any other plan (seats above `seats_included`
  stay at the extra-seat list price). `lock: true` stores the unit price. The Enterprise floor is compared with the
  line the agreed price gives. Written in the 435 column comment, contract 1.9 and the S7 brief below.
- **Billing details audit without personal values** (reviewer fix): `acp_shared.audit_log` is an append-only hash chain
  the tenant erasure keeps, so `legal_entity_name`, `tax_id`, `billing_email`, `billing_address` (CIS 354 PII tags)
  are audited as `personal: {field: set | changed | cleared}`; currency, country and the founding dates keep their
  before / after. No hash of the value either: a tax id is short enough to brute-force from a hash.
- **`plan_attached` reads `plan_key`** (reviewer fix): since 439 the quotas come from the resolved entitlements, where
  NULL = no quota (decision 11). `_billing.plan_attached` uses the 439 `plan_key` column (falls back to the old quota
  test on a pre-439 row), so Enterprise / internal keep their price, overage and Tenant 360 margin.
- **Seats minimum** (decision 2): provision raises a request below `seats_min` to it (step `<product>_seats_raised_to_N`)
  instead of refusing.
- **Pilot** (decision 8): `pilot_weeks` 0 = until go-live (no end date; 435 relaxes `tenants_pilot_check`); the dated
  bound is `cis.tenant.pilot_max_weeks`.
- **One price source** (S5, 439): `v_tenant_monthly_usage`, `/v1/billing`, the admin tenant usage limits and the rewrite
  quota read `shared.plan` / the resolved entitlements. Enterprise / internal quotas with no number = no quota
  (decision 11; the rewrite path serves int4 max). `shared.membership_plans` stays as history (deprecated comment);
  `admin.py`'s `plan_id` soft link at tenant create still reads it (not a price).
- **Discounts** (decision 6): founding and combo never stack; the larger applies. The quote is one pure function
  (`services/tenant_account/quote.py`) used by Tenant 360 and `/v1/billing`.
- **Price lock**: `lock: true` on the terms route = today's list price in the tenant's currency until today +
  `cis.billing.price_lock_months` - 1 day. No backfill for existing Dev subscriptions (decision 13).

## Changed

- Plans API / drawer: VND prices, seat minimum, contract floor, overage rates (backfilled from membership_plans by
  435), `price_set_at` (set on a list-price change); the AI increment is accepted on crm / tripplanner plans and
  refused on content plans.
- Settings registry: 19 keys (436), maker-checker, guides EN + VI. Code literals removed: `TRIAL_DAYS_MAX`,
  `PILOT_MAX_WEEKS`, `PLAN_ALERT_PCT`, `PLAN_APPROVAL_PCT`, the AA-1016 row defaults 100 / 150 (now the settings,
  80 / 100 / hard stop), the FE prefills.
- `add_domain` refuses a host when the tenant has no `tp.custom_domain` (409 `custom_domain_not_included`).
- New routes (admin; reads `tenant.read` / billing read, writes `tenant.write`, audited): `GET /admin/plans/commercial-terms`,
  `GET|PUT /admin/tenants/{id}/billing-details`, `PUT .../subscriptions/{product}/terms`, `GET .../quote`. `/v1/billing` adds `billing_currency`, per plan `currency`
  and `price_monthly`, and `quote`.
- Hourly tick: unchanged in Python; `tenant_entitlement_sync_due()` (437) also re-syncs trialing tenants, so a changed
  trial share reaches the materialisation within the hour.
- `/admin/billing`, `/v1/billing`, the admin tenant list and Tenant 360 read `plan_key` from the usage view (439).

## Tradeoffs

- `cost_guard._PLAN_FALLBACK` (no resolved key, no AA-1016 row) still reads the content plan only, not the add-on sum:
  it is a fallback for a missing materialisation and errs low (never unlimited).
- `LLM_TENANT_BUDGETS` stays an env switch: moving it to the registry needs an env-override window entry; follow-up.
- The VND drift is shown as a number without a colour: a colour would need its own threshold setting.
- The Plans price PATCH stays single-admin, versioned and audited (decision 12; maker-checker before the first paying
  tenant).
