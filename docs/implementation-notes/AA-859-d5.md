# AA-859 — PR-D5a: T2 version reads on the tenant pool (W5)

Flag: `T2_VERSION_READS_FLAG` (`aa859:t2_version_reads_pool`), declared by PR-S. No migration.

## Decisions
- **Split D5 (D5a here).** The full W5 scope (6 routes) measured ~430 router lines before tests, so per
  the plan's ~600-line rule this PR carries D5a only: `GET /v1/tours/pool`, `GET /v1/tours/my-versions`,
  `GET /v1/tours/versions/{id}`. D5b (`/{id}/full` tenant branch, `/{id}`, `/versions/{id}/export-docx`)
  is a follow-up; the six-route version was built and measured first.
- **Flag off = the pre-AA-859 SQL text.** The `LEFT JOIN shared.job` stays on the admin path; only the
  tenant-pool path drops it. The SQL templates take `{job_col}` / `{job_join}`; a unit test pins the
  flag-off text (whitespace-normalised) to the old inline SQL.
- **Job status on MAIN after the tenant block** (plan D2 "W5 job_status"): the tenant pool returns
  `ttv.job_id` through RLS; `_JOB_STATUS_SQL` (`WHERE id = ANY($1::uuid[])`) runs on the admin pool after
  the tenant connection is released, only when there is at least one job id. Same response keys and key
  order as the joined form (`NULL::text AS job_status` placeholder, then filled in Python;
  my-versions' helper column `_job_id` is dropped).
- **One log event for the three routes**: `aa859_t2_version_read route=pool|my_versions|version
  used_tenant_pool=...`, logged once per request after the block (also on a 404), so one Logs Insights
  query covers W5.
- `browse_pool`: all three queries in the one tenant block (master rows via 239, `already_rewritten`
  via 229 RLS). The stale "Nothing in this function is eligible" comment is replaced.

## Changed
- `api/routers/v1_tours.py`: SQL of the three handlers lifted into module constants (tenant conditions
  as their own constants so tests can mutate them), handlers on `acquire_scoped_conn(...,
  T2_VERSION_READS_FLAG, fail_closed=True)`.
- Plan said "reuses `_ttv_live_standin.py` from PR-D6": D6 is built in parallel, so the integration test
  carries its own live-shape stand-in DDL (inline). Merge it into D6's helper when both have landed.
- Matrix entries live in a new file (`tests/unit/test_aa859_t2_version_reads.py`) instead of
  `test_aa817_fail_closed_routes.py::ROUTES`, to avoid conflicts with the sibling PRs.

## Tradeoffs
- Two queries instead of one join on the tenant path (one extra MAIN round trip per page, only when a
  row has a job). Accepted: shared.job is not readable by aa_app_user (241) and must not get RLS (D2).
- A job status read a few ms after the version rows can differ from a joined read; harmless (the
  portal polls).
- Template SQL with `.format()` is less greppable than inline f-strings; in exchange tests can replace
  the tenant conditions and check flag-off text.

## Should know
- **D5b gets its own flag.** `T2_VERSION_READS_FLAG` covers the three D5a handlers only; a unit test
  (`test_t2_version_reads_flag_is_used_only_by_the_three_d5a_handlers`) fails if another handler uses it.
  D5b adds e.g. `T2_VERSION_DETAIL_READS_FLAG = "aa859:t2_version_detail_reads_pool"` in
  `aa544_tenant_pool.py` plus a FLAGS entry in `aa859_flip_verify.py` (this PR was told not to add flag
  constants). Otherwise a D5b deploy would move three routes to the tenant pool with no flip of its own,
  and reverting D5b would revert D5a too.
- **Known divergence, raw_tours tenant:** on the tenant pool 239 shows raw_tours rows only where
  `tenant_id = AA master`; the admin pool joins any row. A master published tour whose raw_tours row has
  another tenant_id loses `country/duration/price_raw/inclusions/exclusions` (and drops out of the country
  / duration filters and the countries dropdown) with the flag on. Pinned by the integration test
  `test_pool_master_tour_on_a_non_master_raw_row_loses_raw_fields_on_tenant_pool`; the pre-flip probe
  below must be 0 on Dev.
- `v1_tours.py` is shared with W6 (PR-D6): the only overlapping line is the `aa544_tenant_pool` import.
- No `audit_log` or enqueue in these three routes, so no other MAIN exception than job status.
