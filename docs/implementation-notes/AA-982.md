# AA-982 — T9 writer input drops place_paa questions already rejected by Jev A3

## Decisions

- **Where the verdicts come from.** A3 (`services/acp_contract/atom_ranking.py`) asks
  `a3_question_about_here` (+ `a3_question_foreign`, stage `a3_question_scope`) per (Segment country set,
  question) and `a3_landing_belongs` (stage `a3_question_landing`) per (Segment moment, question). The
  verdicts are rows of `shared.decision_log` under the subject keys `paa:<countries>:<q[:300]>` and
  `land:<moment[:200]>:<q[:300]>`. The key builders are now functions (`scope_subject_key`,
  `landing_subject_key`, `country_scope`) used by both A3 and the T9 reader, so they cannot drift.
- **Read-only reuse, no `decide()` call.** `decide()` from a T job would be a no-op (tenant guard, the
  cache is tenant-scoped; S247 jev-reuse audit §2). New `decide.platform_verdicts()` reads the stored
  verdicts the way the decide cache does (current `question_hash`, `NOT cached`, ≤ 180 days, tenant NULL or
  aa_internal) and recomputes the Zone with today's floors and mode. No TypeSafe call, no write, $0. No
  tenant text is involved: the subjects are platform PAA + country names + Segment moments.
- **Drop rule = what A3 itself would act on** (enforce mode, confident):
  - about_here: A3's own `scope_dropped()` (foreign accept OR about_here reject) for the piece's country
    set, or for a Segment's set that contains every piece country (not about anywhere in a larger set ⇒ not
    about the piece; a smaller set's reject proves nothing for a multi-country piece);
  - landing: a reject for **every** moment of the piece (S247 audit rule: one moment of a Route is not
    enough), and never when about_here confidently accepts the question for the piece (the audit's known
    mismatch: practical country questions). about_here has no accept floor today, so this guard is dormant.
  - no verdict → kept (a miss never drops).
- **Filtered inside `merge()`, before the per-tier cap.** A rejected question does not use its tier's room,
  so the next accepted place question takes it (the writer sees more good questions, not fewer). A rejected
  text is also blocked from the later tiers (`serp_topup`, `tour_paa`) so it cannot re-enter under another
  label. `segment_match` is never filtered: those questions passed the same gates for their own Segment.
- **Scope of the change: T9 only.** `collect_real_questions(a3_filter=False)` stays the default, so the T8
  angle chain (tenant-visible list) is unchanged. T8 can switch it on in a later issue (audit C2).
- **Kill switch:** env `T9_A3_PAA_FILTER` (default on; `off`/`0`/`false`/`no` disable). `start_write` runs in
  the api write request, so it is the **api** task that reads it. No Terraform change is needed for the
  default-on behaviour.
- **Count per piece:** log line `t9_place_paa_a3_filter` (api) with `piece_id`, `request_id`, `dropped`,
  `place_paa_kept`, and the stats; the same stats in `writer_input.a3_question_filter` (admin-only), with the
  scope used (`a3_countries`, `a3_segment_ids`) so a check can recompute it exactly.

## Tradeoffs

- **Exact-text lookup only.** A3 keys hold the raw PAA text; `place_paa` reads the same `search_demand`
  strings, so exact match is right for this tier (S247 live: 52/52 place_paa writer questions had an
  about_here verdict). A loose (normalised) match would need a scan of `decision_log` (364 MB).
- **Lookup cap 200 questions per piece** (`A3_LOOKUP_MAX`): keys = questions × (country sets + moments), one
  indexed `subject_key = ANY` query. The tier is ranked; questions past the cap are kept as before.
- **Precision.** The S247 labelled set (200 FAQ questions) put Jev-alone behind the Haiku filter as a FAQ
  selector. This issue does not replace the FAQ filter; it only stops re-feeding questions A3 already
  threw out of the same Segments' landing. The FAQ steps after it (`paa_for_scope`, `t9_faq_filter`) are
  unchanged.
- **A verdict expires after 180 days** (decide cache window). After that the question is kept until the
  next A3 recompute re-asks it.
