# AA-1104 (S280): numbered, collapsible groups on the admin Docs page

The tech lead asked for the Docs page (Platform › Docs, `/admin/docs`) to number its entries and to let a reader fold
and unfold the groups, so the catalogue (about 200 pages) is easier to scan.

## Decisions

- **Numbers come from the whole catalogue, not from the filtered list.** Group n, page n.m, in the order the list
  already used (`groupBySection`: the `docs` folder first, then folders A–Z, pages by path). A search or a type /
  audience filter hides rows but never renumbers the rest, so "3.4" means the same page whatever is typed. Numbers
  are display only; the catalog id (for example GUIDE-15) stays on each row.
- **Open groups live in the viewer's browser.** localStorage `aa_docs_open_groups` (JSON array of folder names),
  every read and write in try/catch with an in-memory fallback, read through `useSyncExternalStore` like the page
  language store. Before the viewer has chosen anything: the group of the page being read is open, else the first
  group, everything else folded.
- **Opening a page opens its group, once.** When the page being read changes (a click, a link inside a page, a shared
  `?path=` URL), its group is added to the remembered set. It runs once per newly opened page, not on every render,
  so the reader can still fold that group afterwards.
- **Search opens matching groups on its own.** While a search query is typed, every group with a match is open and
  shows only the matching pages. Folding a group during a search lasts until the query changes and is not written to
  storage, so clearing the search brings back the reader's own open groups. The type and audience filters narrow the
  rows but do not force groups open (the request named search only); the group header shows "x of y pages match".
- **Expand all / Collapse all** act on the remembered set (every folder / none); during a search they act on the
  search-only fold state instead.
- **Header = kit `Pressable`** (no hand-styled `<button>`, lint rule `no-hand-styled-button`) with `aria-expanded`
  and `aria-controls` pointing at the group's `role="group"` region; native button, so Enter and Space toggle it.
  The kit `NavGroup` was not reused: it is styled for the sidebar (sidebar colour variables, 9.5 px caption).

## Changed

- `frontend/lib/docsGroups.ts` (new): pure helpers (`numberGroups`, `filterGroups`, `sectionOfPath`,
  `defaultOpenGroups`, `parseOpenGroups` / `serializeOpenGroups`, `toggleGroup`, `withOpenGroup`, `openSections`).
  Tests: `frontend/lib/docsGroups.test.mjs`.
- `frontend/app/admin/docs/DocsList.tsx` (new): the list (rows, group headers, open-group store, Expand / Collapse
  all). `DocRow` moved here from `page.tsx` (rows now show their number before the title); the folder caption
  became the group header.
- `frontend/app/admin/docs/page.tsx`: renders `DocsList`; no longer filters or groups itself.
- `frontend/app/admin/docs/messages.ts`: new EN and VI strings.

## Tradeoffs

- Folded groups do not render their rows (the region element stays, `hidden`), so `aria-controls` always resolves
  and 200 rows are not in the DOM when most groups are folded. A browser find (Ctrl+F) no longer sees folded rows;
  the page's own search does.
- The list box on wider screens is 40 px shorter (`calc(100vh - 330px)`) to make room for the Expand / Collapse row.
