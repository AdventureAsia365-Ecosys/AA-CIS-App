# AA-157 — Trash + Restore (source + master)

## Decisions

- **No migration 054**: Migration 052 already includes `deleted_at` + `deleted_by` on both `raw_tours` and `published_tours`. Verified before starting.
- **Endpoints in admin.py** (not a new file): Only 4 new endpoints; creating a separate `admin_trash.py` would fragment simple lifecycle logic. Kept in `admin.py` alongside the existing `PATCH /admin/master/{tour_id}/status`.
- **Source restore → 'active' with conflict guard**: The unique index `uq_raw_tours_active_per_group` blocks restoring a tour to 'active' if another tour in the same group is already active. Catches `asyncpg.UniqueViolationError` → HTTP 409 with a clear message.
- **Master restore → 'inactive'**: Deliberately does NOT auto-activate. Admin must manually set active via the existing `/admin/master/{tour_id}/status` endpoint. Prevents surprise B2B exposure.
- **LIMIT 50 → 200**: Increased the `get_tenant_details` internal query limit so trashed tours aren't silently cut off. Still not paginated — tracked as tech debt.
- **Default filter hides trashed**: When no tab is selected, the frontend hides `master_status='trashed'` rows. "Trashed" tab explicitly shows them.

## Changed

- `services/notifications.py`: Added `SOURCE_TRASHED` and `SOURCE_RESTORED` event types (task specified event slugs `source.trashed` / `source.restored`).
- `get_tenant_details` SQL: Added `pt.master_status::text AS master_status` to internal tenant query. Non-internal tenant query gets hardcoded `'active'::text AS master_status` — B2B trash UI is not in scope.
- `RewrittenTour` TypeScript interface: Added `master_status: string` field.

## Tradeoffs

- **Frontend only covers master trash** (published_tours). Source (raw_tours) trash endpoints exist in the API but have no UI — there's no source listing page in the admin panel. Leaving UI for when a source tours page is built.
- **`window.confirm`** instead of a custom modal: simpler, no new components, acceptable for an admin-only tool.

## Should know

- Migration 052 must be applied before any of these endpoints work. The unique index `uq_raw_tours_active_per_group` is partial (only enforces for `source_status = 'active'`), so trashing and restoring to 'active' is safe as long as no other active exists.
- The notification `shared.notifications` table (migration 053) must also be applied for `emit()` to succeed.
- `AA_INTERNAL_TENANT` constant is already defined in `admin.py` at line 740. Both master endpoints reuse it.
