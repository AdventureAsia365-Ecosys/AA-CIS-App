# AA-835 S6 — CIS supply content consumer, LLM draft job and review API

Slice S6 of AA-835 (root ADR 0004a). Stacked on S5 (`feat/aa-835-cis-278-supply-content`, migration 278; notes in
`AA-835-cis-278.md`). Must not deploy before 278 is applied on Dev.

## Decisions

- **The pull runs in the api's ops sampler** (a new part next to the AA-987 purge sweep), DB only, under
  PART_TIMEOUT_S. Off with `SUPPLY_FEED_PULL=off`; skipped while the draft kind is not registered. Concurrent api tasks
  (rolling deploy) cannot double-pull: the cursor row is locked with `FOR UPDATE SKIP LOCKED`.
- **One transaction per batch** (≤ 200 events): inbox rows, entity / media writes, job enqueue and the cursor advance
  commit together. On error the batch rolls back and `last_error` is written outside it; the next tick retries.
- **Facts are read at pull time** from `v_supply_hotels` / `v_supply_services` (`to_jsonb(row) - id - supply_version`
  = the contract `facts` object). Several events of one entity in one batch: the first applies, the rest are
  `skipped_older`.
- **Every applied version is material** (Booking only bumps `supply_version` on a material change), so published
  content goes `stale` on any applied version, including a photo rights flip. Stale serves no text.
- **content_status after newer facts**: inactive → `unpublished`; ever published → `stale`; otherwise `draft` (any
  older open draft is now outdated: publish refuses it with 409 `outdated`).
- **A missing entity** (gone from the Booking view) is unpublished, not deleted; outcome `missing`.
- **Draft job**: background kind, concurrency 1, 2 attempts. Skips (success, no paid call) on the kill switch, an
  inactive entity or a newer facts version. Two cost limits before the call: a count cap
  (`SUPPLY_CONTENT_MAX_DRAFTS_PER_DAY`, default 20, all entities) and the cost guard row `bedrock /
  job:supply_content_draft` (seeded by 278: $0.10/run, $1.00/day, kind-scoped spend). Either raises `BudgetExceeded`
  → status `stopped_budget`. An unusable reply is `NonRetryable` (its billed row is written first).
- **Writer prompt**: the facts are one `<supply_facts>` JSON block with `<` / `>` escaped (a value can never close
  the block), a system rule to treat it as data, and the source-fidelity rule. Only writer fields are quoted (no ids,
  hashes, destination uuid, media keys). The reply is checked again in code: links / e-mails / phone numbers dropped,
  lists capped, the description cut at the last full sentence within 120 words.
- **Photos**: copied before the LLM call so the draft can reference them. Source bucket and key come from
  `booking.v_supply_media` (never a URL), validated against the bk-023 bucket naming rule (+ optional
  `SUPPLY_MEDIA_BUCKET` pin) and the derived key of that exact media id; the bytes must hash to Booking's sha256.
  Copies go to `photos/supply/<type>/<media_id>-{1600,600}.webp` with `cdn_url` (sha cache-bust). A failed photo is
  reported in the job result and stays uncopied.
- **Review rules** live in `services/supply_content/review.py` so an evidence run can call them through ECS exec
  (reviewer `system:aa835-evidence`). Publish supersedes the previous approved version and every other open draft;
  re-publishing the same approved version after an unpublish is allowed when the facts did not change.
- **RBAC**: edit and regenerate = `content.write`; publish, reject, unpublish = `review.act`; reads open to every
  staff role. Content and reviewer hold the same capabilities today, so a reviewer can publish (it is a review
  action); the viewer and the machine are refused.
- **Router file name** `api/routers/admin_supply_content.py` (repo idiom `admin_*`), not `supply_content.py`.

## Tradeoffs

- Drafts are queued automatically for every applied facts version (paid, ~$0.02 each). Bounded by the count cap and
  the $1/day budget; a Booking edit storm costs at most the cap. The kill switch stops it without a deploy of code
  (env change on the worker task).
- `status` endpoint counts over the whole `booking.v_supply_outbox`; fine on Dev (a handful of rows), an index-backed
  `feed_seq > cursor` count once the feed is large.
- The diff is a plain unified diff of description / highlights / good_to_know / photo ids; enough for a reviewer,
  no word-level highlighting.

## Review round 1 (independent reviewer, S250)

### Decisions

- **Withdrawn photos leave the bucket and the CDN** (should-fix; DM-7 row "supply_media"). The pull, in the same
  transaction as the media change, queues one `supply_media_purge` job per CIS copy whose media lost `usage_rights`,
  was removed from the facts, or whose entity left the facts view (a missing entity now also deactivates its media).
  Key `supply_media_purge:<media_id>:<copied_at in epoch µs>`: the key names the copy, so a photo copied again
  later and withdrawn again gets a new job instead of hitting the finished one. `copied_at` is now
  `clock_timestamp()` so two copies in one transaction (tests) still differ.
- **The purge job** (background, concurrency 1, 3 attempts) re-reads the row and skips when the copy is gone or
  replaced, or the rights came back. Then: `delete_object` on both keys (only under `photos/supply/`), one UPDATE that
  clears every copy column of that same copy (`supply_media_copy_check` allows all-NULL), then a CloudFront
  invalidation of `/supply/<type>/<media_id>-*` (both sizes, every `?v=`) when `PHOTO_CDN_DISTRIBUTION_ID` is set.
  The invalidation is best effort (result + warning line): once the objects and the row are gone a retry could not
  find the copy again. S3 AccessDenied is NonRetryable with a message naming the missing grant.
- **Decode bound** (nit): `photos.check_pixels` reads the image header and refuses more than 50 MP before
  `make_sizes` decodes anything (a small PNG can expand to hundreds of MB, the S207 OOM).
- **CDN off** (nit): with `PHOTO_CDN_BASE=off` the copy step leaves every photo pending (reported as failed) instead
  of marking it copied without a URL, which would never have been retried.
- **Daily cap counts paid calls** (nit): `shared.llm_call_log` rows of stage `supply_content_writer` today, so an
  unusable reply or a draft discarded because the facts moved on counts too. The $1/day kind budget is unchanged.
- **Supersede scope** (nit): `insert_llm_draft` supersedes only older open `llm` drafts; a human draft written
  against older facts stays (publish refuses it with 409 `outdated` anyway). Docstrings now say so.
- The status board gains `photo_purge_jobs_7d` next to `draft_jobs_7d`.

### Should know

- **Infra dependency**: the CIS task role has `s3:GetObject/PutObject` on `*` but no `s3:DeleteObject`, and no
  `cloudfront:CreateInvalidation`. Until the AA-CIS-Infra grant (DeleteObject on `photos/supply/*` of the photo
  bucket, CreateInvalidation on the photos distribution, env `PHOTO_CDN_DISTRIBUTION_ID` on the worker) is applied,
  a purge job fails at once (NonRetryable, visible on the Jobs page and the status board) and the copies stay. The
  read-back view already hides the photo from the moment the pull sees the change, so only URLs Booking rendered
  earlier keep working until then.
- **Stale after a cap stop**: a draft job stopped by the count cap or the budget is not re-queued the next day. The
  entity keeps its status (no text for Booking) until Booking changes it again or a reviewer presses regenerate.
- **Paid default**: `SUPPLY_CONTENT_LLM` defaults to on, so after deploy every applied Booking facts version makes
  one Sonnet call (~$0.02), bounded by 20 calls and $1.00 a day. For the evidence run, trial about 3 entities first
  (paid-runs rule); set `SUPPLY_CONTENT_LLM=off` on the worker if the trial must wait.
- **edit_url**: `catalog.v_supply_content.edit_url` points at `/admin/supply-content/<id>`, which has no page yet
  (admin page cut from this PR). Keep the column (append-only contract). The admin page is a tracked follow-up that
  must ship before Booking's "Edit in CIS" link is relied on; until then the link opens a 404.
