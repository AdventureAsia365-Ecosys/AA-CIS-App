# AA-871 — JSON logs with request ids (CIS api + worker)

Scope 1, CIS part. Mirrors AA-Booking `backend/app/observability/log_config.py` + `request_id.py`.

## Decisions
- One module, `shared/log_config.py`, used by both `api.main` (at import, before routers log anything that
  matters) and `python -m worker` (first thing in `__main__`). `shared/` because the worker must not import `api`.
- structlog is routed through stdlib (`structlog.stdlib.LoggerFactory` + `ProcessorFormatter`) so structlog calls,
  stdlib calls and uvicorn's own lines share one JSON renderer and one root handler on stdout.
- Static fields on every line: `service` (`cis-api` | `cis-worker`, api and worker share `/ecs/aa-cis-dev`),
  `environment` (`ENVIRONMENT`), `git_sha` (`APP_GIT_SHA` via `shared.sentry_init.release()`).
- Request id pattern: 8–64 chars of `[A-Za-z0-9_-]` (a UUID or `uuid4().hex` fits). Anything else is replaced by a
  new `uuid4().hex`, never echoed or logged. Stricter than Booking (`[A-Za-z0-9._:-]{1,128}`).
- Pure ASGI middleware, registered last in `api/main.py` = outermost user middleware, so refusals from
  StaffBearer (401/403/503), the rate limiter (403/429) and route dependencies all carry `X-Request-ID`.
  `app.add_exception_handler(Exception, unhandled_error_handler)` adds it to the unhandled 500 too (Starlette's
  ServerErrorMiddleware answers that one outside every user middleware). Same body as Starlette's default.
- The middleware clears structlog contextvars at the start and end of each request (not only its own key), so no
  binding from one request can reach the next.
- `request_completed` (one per request) replaces uvicorn's access log (`uvicorn.access` disabled): method, path
  (no query string), route template, status, duration_ms. The uvicorn access line also carried the client IP.
- `tenant_id`: bound in the `/v1/*` branch of `rate_limit_middleware`, right after the tenant JWT is verified — the
  one place the API already resolves it for every tenant request. Small (one line + import). Staff paths get no
  tenant_id (staff are not tenants).
- Worker: `Worker._execute` wraps the job in `bound_contextvars(job_id, job_kind)`; the body moved unchanged to
  `_execute_job`. `_execute` runs in its own task and the handler task is created inside it, so the handler (and its
  threads, via the copied context) logs with the ids; the binding ends with the job.
- Sentry: `sentry_sdk.set_tag("request_id", ...)` in the middleware (same per-request scope as the existing
  `sentry_context_middleware` tags).
- Light scrub processor (DM-6.4 safety net): e-mail addresses, `Bearer <token>` and key-like query parameters
  (reuses `shared.sentry_init._redact`, AA-712) are redacted in every value. Booking's full by-key scrubber was not
  ported: CIS logs `name`-like keys for tours/kinds, and by-key redaction would hide them.

## Changed
- `shared/log_config.py` (new), `api/middleware/request_id.py` (new), `api/main.py` (configure at import, exception
  handler, middleware), `worker/__main__.py` (configure), `shared/jobs/worker.py` (job binding),
  `api/middleware/rate_limit.py` (tenant_id binding), `CONTEXT.md` (one bullet under Deploy & CI).
- Tests: `tests/unit/test_aa871_request_id_json_logs.py`.
- No route added, no event name or message changed.

## Tradeoffs
- Configuring is skipped when `ENVIRONMENT=test` (`configure_for_process`): importing `api.main` in the unit suite
  must not swap global logging for 10k tests (one test module configures structlog itself at import). The tests call
  `configure_logging(stream=...)` directly and restore the previous set-up.
- Root level INFO (`LOG_LEVEL` env overrides). structlog `debug` lines (two `*.cache_hit` lines in
  `tenant_config_service`, a few in the Langfuse tracer) were printed before (structlog's default logger does not
  filter) and are now dropped.
- Before this change stdlib `logging` had no root handler: stdlib INFO lines from CIS modules were dropped and
  WARNING+ went to stderr as plain text. They now appear as JSON on stdout, INFO included. Chatty libraries
  (httpx — logs full URLs —, botocore, boto3, urllib3, openai, langfuse, google, asyncio, ...) are pinned to WARNING
  so their volume stays as it was.

## Should know
- **Sentry volume**: structlog `error` / `exception` lines now pass through stdlib, so Sentry's default logging
  integration turns each into a Sentry event (AA-870 assumed this already happened for worker job errors; it did not,
  structlog printed directly). ~84 error/exception call sites. Watch the free-plan quota after deploy.
- API Gateway does not map `context.requestId` into `X-Request-ID` for CIS (no mapping in AA-CIS-Infra), so the id is
  generated by the app unless the caller sends one. Mapping it in Infra would let API GW access logs join on it.
- The Infra metric filters on `/ecs/aa-cis-dev` match quoted substrings (`"llm_call_log_write_failed"`,
  `"too many connections for role" "cis_app"`); they still match inside JSON lines (test
  `test_metric_filter_substrings_still_match`). Do not rename those events.
- Logs Insights discovers JSON fields automatically:
  `fields @timestamp, event, level, status | filter request_id = "<id>" | sort @timestamp`.
- Health checks (ALB, container HEALTHCHECK) produce one `request_completed` line each, as the uvicorn access log did.
