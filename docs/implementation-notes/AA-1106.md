# AA-1106 — Platform › Product map (CIS part)

The catalogue itself (features, integrations, journeys, the guard and the publishing) lives in the root repo:
`docs/catalogue/` and `tools/catalogue/`, notes in the root `docs/implementation-notes/AA-1106.md`.

## Decisions

- **Data source = the docs reader storage.** The root "Docs sync" workflow uploads `catalogue.json` under the docs
  reader prefix, so the CIS task role reads it with the grant it already has (no Terraform, no table, no write path,
  as the issue asks: "a generated JSON bundle published by Docs sync like the docs reader").
- **Route `GET /admin/platform/catalogue`**, POLICY `ops.read` (admin only), the same tier as Platform pages and the
  docs reader. The BFF already forwards `platform` paths for admin only.
- **Cache and size limits reuse the docs reader constants** (`CACHE_TTL_S`, `MIN_REFRESH_S`, `MAX_MANIFEST_BYTES`):
  they are transport limits of the same bucket prefix, not business thresholds, so no new settings registry key.
- **Defence in depth**: only the known sections, only rows with an id, any 12-digit run masked (the root guard
  already refuses account IDs, ARNs and e-mail addresses in the YAML and the bundle).
- **UI**: kit only (PageFrame, PageHeader, KpiTile, Tabs, FilterBar, DataTable, Drawer, Section, Badge, LinkButton);
  the tab and the filters live in the URL; the Graph tab is an inline SVG drawn from the links (one arrow per app
  pair with the link count) plus the same data as a list for screen readers and phones.
- **Language**: page chrome in `messages.ts` (EN / VI); catalogue rows bring `name_vi` (features, apps, journeys,
  steps) and `summary_vi` (apps, journeys); a feature summary stays English.
- **Settings deep link**: Platform › Settings now reads `?app=<app>&area=<area>` to open that tab and area, so a
  setting named in a condition opens next to its row (unknown values fall back to the first tab / area).

## Tradeoffs

- The page shows the bundle as published, so it lags a merged root change by the Docs sync run plus the 5 minute
  cache (Refresh skips the cache, at most every 30 s).
- Contract files have no reader page of their own (JSON / YAML, and the contracts register is not a published docs
  page): the link drawer names each file and its version and says where it lives.
