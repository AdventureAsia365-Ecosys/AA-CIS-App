# AA-700 — T-series Jev (part 2 of AA-696): T7 Debate, T8 angle answers, T9 facts — shadow

Design: `docs/architecture/at-series-v2-design.md` §4.3 (T7-1, T8-1, T9-1). Policy: ADR 0007.

## Decisions
- **Shadow first** (Nghiệp, S206): test tenants hold 5 rewrites / 3 pieces / 3 angle requests and
  `acp_shared.facts` has 2 rows, so no question here can be calibrated now. Migration 193 registers
  3 new Nouls in `shadow`; they collect probabilities during the rerun and are calibrated from
  `decision_log` (no second Jev payment, per design §3).
- **Code is written for enforce**, so turning a question on is an admin/DB change after its
  Calibration Record, not another PR:
  - **T7** `t7_topic_fits_brand` (Debate, cache miss only): enforced accept → pass without Luna;
    enforced reject → cut without Luna (score 6.5, so Luna's clearly bad cuts rank first under the
    `MAX_CUT_FRACTION` rail); anything else → Luna as before. State `{brand, topic{place, action,
    evidence ≤ 8}}`; subject `t7:<brand_version>:<segment|route id>`.
  - **T8** `t8_angle_answers`: per (angle, PAA question the angle claims and the code matched
    verbatim). Enforced reject drops the answer, then `best_index()` (the same sort key as
    `rank_angles`) recomputes the recommendation.
  - **T9** `t9_fact_relevant`: per Facts Entry before `format_facts_block()`. Enforced reject leaves
    the fact out of the prompt (and so out of the grounding text built from it).
- All three pass the tenant id: non-allow-listed tenants get `zone=skipped` (design C2).

## Changed vs the issue
- T7 asks Jev only on a brand-fit **cache miss**: a cache hit already has Luna's score and costs
  nothing. The rerun rebuilds Segments (new ids), so it is all cache misses and the sample is full.

## Tradeoffs
- T7 asks sequentially inside Debate's per-candidate loop (~250 ms next to a ~2–5 s Luna call on
  the same path); T8/T9 ask ≤ 4 at a time. `decide()` opens its own connection per call (no pool).
- T9 in shadow adds one Jev call per fact per write; with 2 facts on Dev that is negligible. If the
  facts table grows large, cache hits (subject = fact id + moment/angle hash) keep rewrites free.
