# AA-572 — Content Trace (AA-568) fix follow-up: 6 issues

Pure UI fix/enhancement on `/admin/tenant-activity` (frontend/app/admin/tenant-activity/page.tsx).
Per the issue's own instruction, STEP0 not required — no backend/schema change.

## Decisions

- **Points 2 (tenant stats) and 3 (sort) are entirely client-side**, computed/applied on the
  already-loaded `rows` (the endpoint caps at 500 rows, already fetched in full for the table) —
  no new query param, no backend change, matching the issue's explicit scope.
- **Stat header is dynamic, not a fixed set of tiles**: "Total pieces" + one tile per channel that
  actually has ≥1 row in the current (already tenant/channel/status/date-filtered) result set,
  sorted by count descending. A fixed 8-channel grid would show a wall of zero-tiles whenever a
  filter narrows the data — a real breakdown of what's actually on screen is more useful and
  matches "breakdown theo channel" literally.
- **Only Gate count/Retry count/Created at got sort** — the issue's own stated minimum. The other
  7 columns are free-text/categorical (Topic/Tenant/Tour/Channel/Angle/Status/Published) where a
  client-side sort wasn't asked for and adds little value; not extending scope beyond what the
  issue's own "có thể mở rộng nếu hợp lý" invites.
- **Point 5 (lineage) resolved via 6 real per-entity lines**: Tour (always) / Atom (if present) /
  Segment (Segment-sourced picks only) / Route + Hub as TWO separate lines (Route-sourced picks
  only — the old single `sourceLabel()` string literally named both "Route/Hub" in one line,
  `"Route/Hub — {hub} (Day X-Y)"`; genuinely split now) / Slate (always — states whether this
  came via the Slate mechanism at all, vs. the pre-Slate direct-atom picker path). `sourceLabel()`
  helper deleted — no longer called anywhere after this split.
- **Point 6 (sticky header) root cause, more precise than the issue's own guess**: the issue
  suggested the fix was "use `minHeight:0` + `height:"100vh"`, learned from AA-566" — both were
  ALREADY correctly present on this page's own outer scroll container (verified before touching
  anything). The real, additional bug: `ContentTraceTable`'s own wrapper `<div>` had
  `overflowX: "auto"` with `overflowY` left at its default (`visible`) — per the CSS overflow
  spec, that combination forces the browser to compute `overflow-y: auto` too, making this INNER,
  never-actually-scrolling div (its height is unconstrained, so it never clips its own content)
  become the nearest non-visible-overflow ancestor — which is what `position: sticky` scopes
  itself to, regardless of whether that ancestor is the one a human would call "the scroll
  region." The `<th>`'s sticky positioning was therefore anchored to a box that never scrolls, so
  it visually behaved as not-sticky at all. Fixed by moving `overflowX: "auto"` up onto the real
  outer scroll container (`flex:1, minHeight:0, overflowY:"auto"`) and leaving the inner table
  wrapper at the CSS default (`overflow: visible`) — now there is exactly ONE real scrolling
  ancestor, and `<th>{ position: sticky, top: 0 }` correctly anchors to it.
