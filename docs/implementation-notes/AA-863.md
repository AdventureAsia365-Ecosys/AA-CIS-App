# AA-863 — Show the Slate seed place and country next to each Subject and T9 piece

Admin only. Content Quality (`/admin/content-quality`, Pieces tab + piece drawer) and the
atom-curation Slate tab (`/admin/atom-curation?section=slate`) show, per row, the seed atom's place
and country, the Segment label, and a warning badge when the seed does not fit the Subject.

## Decisions

- **One rule module, no re-implementation.** `services/acp_shared/seed_audit.py` holds the pure
  check (`seed_check`) and the batched reads. The place check calls
  `subject_seed.match_grade()` with the same alias-card map the Slate uses
  (`subject_seed.load_alias_cards`), so "matches" here means exactly what `choose_representative`
  accepts (any grade 0-4, the loose word-set tier included).
- **Which seed.**
  - T9 piece: `angle_gate_request.atom_id` (the frozen seed the writer was given), read from
    `acp_contract.tour_atoms` (not the active view, so a seed whose tour later left the active set
    still shows its place).
  - Subject (Slate row): the latest `angle_gate_request.atom_id` for that Subject when it was picked
    (`source: "request"`), else the seed a pick would use now (`source: "computed"`), from
    `choose_representative()` over `load_segment_members()` + the tenant's tours — the same inputs
    `_resolve_representative_atom()` uses. No seed → `skip_reason` (the `subject_seed.SKIP_*` code).
  - Route Subject: the Route anchor rule, extracted from `slate._resolve_representative_atom` into
    `subject_seed.choose_route_anchor()` (behaviour unchanged) so admin and pick share it.
- **"The Segment's country"** = the distinct known countries of the Segment's live, non-alias
  members on `owner_scope IN ('platform', <tenant>)` (what the seed rule itself sees). A Route's
  country = its tour's country.
- **Mismatch flags.**
  - `place_mismatch`: Segment Subject, a seed and a Subject place, and `match_grade(...)` is `None`.
  - `country_mismatch`: seed country known, Segment countries known, and the Segment's country set
    is not exactly `{seed country}` — so a still-mixed Segment (several countries) is flagged too,
    because there is no single "Segment country" the seed can agree with.
  - Route Subjects: country check only (the anchor may legitimately be any member of the Route's
    first Segment on that tour; a place check would flag by design).
  - Unknown seed country (tour without country) is not flagged (the seed rule also accepts it for a
    name match); the UI shows "country unknown".
- **Segment ids that merged** resolve to the live id (`resolve_segment_aliases`) before the label /
  country read, same as the Slate and pick do.

## Changed

- New `services/acp_shared/seed_audit.py`: `seed_check()` (pure), `load_piece_seeds()`,
  `load_subject_seeds()`.
- `subject_seed.choose_route_anchor()` — the Route anchor rule moved out of
  `slate._resolve_representative_atom()` (same behaviour; existing AA-857 tests pass unchanged).
- `GET /admin/content-quality/pieces` and `GET /admin/content-quality/pieces/{id}`: every row / the
  detail carries `seed` (object or `null`).
- `GET /admin/dashboard/slate`: every row carries `seed`; the query also reads the Route's tour,
  first Segment id/place and tour country (internal columns, not returned).
- Response shape of `seed`: `atom_id, place, country, source ("request"|"computed"), skip_reason,
  subject_kind ("segment"|"route"|null), segment_id (live), segment_label, subject_place,
  segment_countries[], match (exact|name_form|core_or_card|parenthetical|loose_words|null),
  place_mismatch, country_mismatch, mismatch`.
- Frontend: `app/admin/_components/SeedLine.tsx` (kit `Badge`, kit tokens). Content Quality Pieces
  table: the Title cell gets a second line "Segment: …" + "Seed: place · country" + amber badge
  (header renamed "Title / angle · seed"); the piece drawer gets a "Slate seed" section. Atom-curation
  Slate tab: new "Seed (place · country)" column (sortable: mismatches first; filterable by
  place / country / "mismatch") and one legend line in the explainer.
- Existing tests that mock `conn.fetch` for these endpoints now patch the seed loader (the seed
  reads are their own query set, tested in `tests/unit/test_aa863_seed_audit.py`).

## Tradeoffs

- **Query count.** The issue asked for one batched query. The seed is one set-based query, but the
  check also needs the existing AA-857 helpers (Segment alias chain, place-card aliases, Segment
  members / tenant tours for the Slate). Re-writing those inline would duplicate the seed rule's
  inputs, so the page does a fixed number of set-based reads instead: pieces list = 4
  (seeds, alias chain, Segment facts, place-card aliases), Slate = 4 (request seeds, tenant tours,
  Segment members, place-card aliases). None is per row (no N+1).
- **Fail-soft.** A failure in any seed read logs `seed_audit_pieces_failed` /
  `seed_audit_subjects_failed` and returns rows with `seed: null`; the quality pages keep loading.
- **Mixed Segments are flagged.** A computed seed in a still-mixed Segment is a correct seed by the
  rule (its place matches in one country), yet it is flagged "Mixed Segment" — the Segment has no
  single country. The UI words it differently from "Country ≠ Segment" so admins can tell them apart.
- **No mismatch filter** on the Pieces tab (server-side) — out of scope; the Slate tab can sort /
  filter mismatches client-side on the loaded page.
- **Seed in the Title cell, not a new column**, on the Pieces table: the S239 lesson about the Label
  column being pushed off-screen at 1440 px.

## Should know

- Admin only: `seed_audit` is imported only by `admin_content_quality.py` and `admin_dashboard.py`
  (guarded by a unit test). No tenant route or tenant projection changed. `slate.py` changed only by
  the anchor extraction.
- The frozen seed is read from `acp_contract.tour_atoms` (not `v_active_tour_atoms`) on purpose.
  Segment countries and computed seeds use `v_active_tour_atoms` (what the seed rule reads).
- SQL checked by `prepare()` against the local integration DB: piece seeds, request seeds and the
  Slate query plan; the Segment-facts query plans against `tour_atoms` (the local DB has no
  `v_active_tour_atoms` view; the view's columns are taken from `db-schema-reference.md`, and
  `subject_seed._MEMBERS_SQL` already reads the same columns from it). Not run against Dev data.
- No migration. No frontend unit-test runner exists; the UI was checked with `tsc` + `eslint` only
  (no `next build`, no browser screenshot — the integrate stage builds once).

## S241 UI-verify follow-up (Dev Playwright pass on 748c12c / PR #787)

Evidence: AA-Ecosys `docs/audits/2026-10-17-S241-ui-verify/` (`admin-seed/slate-390-*`,
`slate-sorted-seed-390-*`, `slate-filter-mismatch-390-*`, `admin-jobs/jobs-drawer-succeeded-390-light.png`,

new styles were measured in a static DOM repro in headless Chromium. It was not checked on a
deployed build.

### Decisions

- **Slate tab sideways scroll at 390.** Root cause: below 980 px `.a527-dash-body` stacks
  (`flex-direction: column`) but kept `align-items: flex-start`. Each stacked child therefore got
  its fit-content width, and a table's min-content is not capped by its `overflow-x: auto`
  wrapper: intrinsic sizing ignores overflow for block boxes. The body column grew past the body
  scroller, so the "What is Slate?" card and the stage nav were clipped and the scroller moved
  sideways after a sort or filter.
  Fix, two layers:
  1. `SocialContentSubNav`'s shared media query adds `align-items: stretch` to `.a527-dash-body`.
     This covers all four pages that use the split: atom-curation, Content Trace, Platform Stats
     and Content Quality.
  2. The atom-curation body column gets `width: 100%; max-width: 100%`, the same belt-and-braces
     fix content-quality already had.

  The ~48 px header indent was the header's and body's own 32 px side padding stacked on
  `.aa-admin-main`'s 16 px phone padding. On a phone (`useIsPhone`, < 768 px) both now use 0 side
  padding.
  Repro at 390 with the Slate table:
  | Case | Body scroller scrollWidth / clientWidth | Column width |
  |---|---|---|
  | Before | 670 / 358 | 638 px |
  | After | 358 / 358 | 358 px, only the table wrapper scrolls |

  **Pre-existing, made worse by the Seed column:** the same repro without the Seed column already
  overflowed (444 / 358). The Seed column (`max-width: 280`, one nowrap line) added about 226 px of
  min-content.
- **Kit Drawer header at 390 (Jobs drawer).** In `_kit/Drawer.tsx` the title box is now
  `flex: 1 1 auto; min-width: 0; overflow: hidden`. A string title gets nowrap and an ellipsis, plus
  a tooltip. The close button has `flex-shrink: 0`. A node title is clipped, so the JobDrawer
  header becomes a `display: flex; min-width: 0` row: the kind is one line with an ellipsis and a
  tooltip, and the status badge does not shrink.
  Repro with a long kind at 390: the close X was at x 468–486, off-screen; it is now at x 352–370.
  The other drawer titles (PieceDrawer's 2-line header, TourVersionDrawer, PlaceCardFactsDrawer,
  review, Writer) wrap as before. They now clip at the box edge instead of pushing the X out.
- **Content Quality piece drawer legend pills.** The legend row is `align-items: flex-start`, the
  pills sit in `flex-shrink: 0` wrappers, and the helper text has `min-width: 0`. Repro: pill
  height 24 → 18 px next to the 3-line helper text. On Dev it was about 50 px, with real fonts.
- **"SLATE SEED flush on the header divider" (1440): no code change.** The verify script scrolled
  the section into view with `scrollIntoView({ block: 'start' })` (`uiv/admin.mjs` l.156). That
  puts the section's top edge at the top of the scroller, so the header looks flush in the
  screenshot. `Section` has `margin-top: 18` like its siblings. As the first block in the body it
  also gets the body's 18 px padding, so at scroll 0 it sits 36 px below the divider.
