# AA-663 — Admin information architecture consolidation

## Decisions
- **Sidebar = Overview · Content · Intelligence · Tenants · Operations, then Settings at the bottom.** The groups are data (`NAV_GROUPS` in `AdminSidebar.tsx`) instead of hand-written JSX blocks. There is one Dashboard entry for every role; admins used to see two.
- **Labels:** "S1 Rewrite" → "Rewrite (S1)" (review §5.5). "External Spend" is kept rather than renamed to "Cost Operations": it is the page's own title (AA-622) and the name already used in Jira/Linear.
- **"ADMIN" tag removed.** Visibility is unchanged: an `adminOnly` entry renders for role `admin` only, and that list matches `middleware.ts` PROTECTED_ROUTES, so no role sees a link it cannot open. Every item now uses the brand gold accent, and the active item has `aria-current="page"`.
- **Social Content stays highlighted** on `/admin/tenant-activity` and `/admin/platform-stats` (its sub-nav pages, `also` in the nav entry).
- **Brand Identity → Settings.** The full editor (was `app/admin/brand/page.tsx`) is now `_components/BrandIdentityEditor.tsx` and renders as the Settings "Brand Identity" tab. It replaces the read-only "Brand Rules" tab, which duplicated it. Settings reads `?tab=` (via `useSearchParams` in a Suspense boundary), so `/admin/settings?tab=brand` opens the editor directly.
- **Settings is visible to every staff role.** Before, the sidebar showed it to admins only, although middleware already allowed all three roles. Brand Identity was visible to all roles and now lives there.
- **Legacy `(internal)` route group deleted** (`/upload`, `/review`, `/catalog`, `/brand` and its own sidebar). Nothing outside the group linked to it except the login redirect for non-admin roles, which now goes to `/admin/dashboard`.
- **Redirects** live in `next.config.ts` (`permanent: false`, so they can change later):
  - `/upload` → `/admin/upload`
  - `/review` → `/admin/review`
  - `/catalog` → `/admin/master-content`
  - `/brand` and `/admin/brand` → `/admin/settings?tab=brand`

  Next.js applies redirects before middleware, so the target route's role check still applies. The legacy entries were removed from `PROTECTED_ROUTES` and from `config.matcher`.

## Changed vs issue
- **Not in this PR** (each has its own issue):
  - the single system Overview dashboard (AA-664) — the current Dashboard page is kept as the Overview entry;
  - Tenant 360, and moving tenant activity/quality inside the tenant area, which resolves the Platform Stats / Tenant Activity overlap (AA-666);
  - Settings sub-sections for Integrations, Budgets & limits, Markets, Users & roles — they need backend/UI work. Budgets is currently a tab in External Spend (KAN-90).
- Visibility "follows real permissions" as far as the current role model allows. The content role has no JWT, so admin API calls 401 for it; that is the staff auth issue (AA-656).

## Tradeoffs
- The 400 px check passes (no JS errors), but the admin shell is not responsive: the 236 px sidebar takes most of a phone screen. A collapsible sidebar belongs to the shared UI kit work (AA-662) rather than this IA change.
- The brand editor is embedded with a fixed-height frame (`calc(100vh - 220px)`, min 640 px), so its two panels scroll inside Settings the way they used to scroll inside the full page.
