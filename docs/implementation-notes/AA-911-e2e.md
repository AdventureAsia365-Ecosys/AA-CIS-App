# AA-911 C0: Cognito E2E refusal step on the Booking Preview host

Branch `test/aa-911-e2e-booking-base-url` (test + workflow only; can merge before the bridge is retired). The
bridge removal and the CIS preview sign-in are a separate PR (`AA-911.md` on `refactor/aa-911-retire-booking-bridge`).

## Decisions

- **`e2e-cognito.yml` input `booking_base_url`**, a choice of exactly two hosts: `https://booking.lumiguides.it.com`
  (default) and `https://booking-preview.lumiguides.it.com`. Mailbox trust is unchanged (main + `e2e` environment).
- **Spec env name `E2EBOOKINGORIGIN`** (not `BOOKING_BASE_URL` as the plan said): no underscore, the convention of
  `E2ECOGNITO` in the same workflow. The spec re-checks the value against the same two hosts and throws on
  anything else, so a hand-set env cannot point the run at another site.
- **Vercel protection bypass (only if check V1 shows the Preview host behind Vercel Authentication):** the workflow
  passes the `e2e` environment secret `BOOKING_PREVIEW_BYPASS` as `E2EBOOKINGBYPASS`, and only when the Preview
  host is chosen. The spec adds it as request headers (`x-vercel-protection-bypass` + `x-vercel-set-bypass-cookie`)
  through a Playwright route on the Preview host only, never in a URL (no log line can show it), so Vercel sets a
  host-only cookie that the redirected Cognito callback carries. The plan's query-string variant was dropped for
  that reason. With the secret unset the step behaves as before.
- `bk_cis_session` stays in `BOOKING_SESSION_COOKIES` (clear-only after the bridge goes; it must still hold no
  value).

## Changed

- `tests/e2e/cognito/cognito-login.spec.ts`: `BOOKING_PROD_ORIGIN` → `BOOKING_ORIGIN` from the allowlist.
- `.github/workflows/e2e-cognito.yml`: the input and the two env values.

## Tradeoffs

- The secret name is fixed here so the workflow can reference it; the orchestrator creates it only if V1 needs it.
