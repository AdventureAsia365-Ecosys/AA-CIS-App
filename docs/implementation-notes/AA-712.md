# AA-712 — Place pipeline in CIS (slices 1 + 3: migration 226 + job kinds)

Design: `AA-Ecosys/docs/audits/2026-10-14-S236-design-review/aa712/03-design.md` (approved by Nghiệp with all
recommendations; the ADR is **0007** — 0006 is identity). Inputs: `01-tp-pipeline-map.md`, `02-cis-side-map.md`.
This branch: migration 226 + `services/places/` + three job kinds + triggers + backfill endpoint.
Not here: migration 228 (catalog views; 227 is taken by sonnet5_no_temperature on main), `/admin/places` page, Infra secret/IAM, TP changes, photo
`itinerary_places()` repoint (slice 4).

## Decisions
- **Geocoder = Geoapify for every country (Nghiệp S236, lane cis-geo)** — evidence `aa712/04-geocoder-research.md`
  + `05-geocoder-bakeoff.md`. `GEOCODER_PROVIDER` default `geoapify`; `model_only` kept for tests / emergency;
  `mapbox_permanent` / `amazon_location` kept as names that raise `GeocoderNotSupported` (a stale task-def
  value fails loudly instead of silently running unconfirmed); any other value → `model_only` (logged).
  The first cut's Mapbox Permanent / Amazon Location implementations and `get_mapbox_token()` are removed.
- **Protocol**: `confirm(name, lat, lng, country, *, native_name=None)` returns `Confirmed` (accepted),
  `Unconfirmed(meta)` (checked or deliberately skipped, nothing passed) or `None` (provider does not check).
  `Unconfirmed` exists so the row keeps an audit of what was tried (`geocoder_meta.tried`).
- **Acceptance rule** = the bake-off's (`services/places/geomatch.py`, pure): top 3 scanned; (a) `sim` = 1.0, or
  ≥ 0.5 with ≥ 2 distinctive tokens; (b) not country/state/county/postcode, `city` only for a settlement query
  ("settlement" = no POI feature word such as temple / lake / pass / cave / park); (c) ≤ 25 km of the model's
  point, ≤ 50 km for lake / river / valley / park / trail / road (+ highway / reservoir / tso / national).
  `sim` reuses the bake-off script's STOP set and difflib 0.85 verbatim so the numbers are reproducible;
  other generic-word lists are separate sets. `rank.confidence` is stored in `geocoder_meta`, never a gate.
- **Query = normalised plain name, not the locate label**: altitudes and parentheticals dropped, "X, City" → X,
  "X to Y" → X then Y (≤ 2 queries). A generic name's locality lives in the key, not in the query.
  A phrase with no proper noun (only generic words: ger camp, local market, village center, fishing village,
  living reefs) sends no request (`skipped_generic`) — the model's point for "<name> (<town>)" is the town.
- **Taiwan / South Korea native-script retry**: the locate prompt asks for a 4th element (中文 / 한글) for those
  two countries; `parse_answer` keeps it only when it is in native script and the country is TW/KR; the geocoder
  queries it after the English queries fail, with its own name rule (substring match; type + ≤ 50 km).
- **Unconfirmed → `llm`, `geo_precision='area'`**; hard kinds (bake-off regex: monastery/gompa/dzong/pass/la/
  lake/tso/village/camp/temple/valley/glacier/cave/waterfall/falls/peak/base) also get
  `review_reason='unconfirmed_hard_type'` — the `/admin/places` review list (slice 5) reads it. Precision is a
  property: `point` for geoapify / manual, `area` for llm.
- **New `shared.destinations` columns in 226** (226 is not applied on Dev yet): `geo_precision`
  (point|area|NULL legacy), `geocoder_provider`, `geocoded_at`, `geocoder_meta` jsonb, `review_reason`;
  `located_by` CHECK = mapbox | llm | geoapify | manual (amazon_location dropped). `geocoded_at` = last time an
  external geocoder was consulted (accepted or not) so a re-run on another provider is a job, not a migration.
- **Overwrite rule**: a `geoapify` point replaces `llm` AND legacy TripPlanner `mapbox` rows (stored from Mapbox
  Temporary calls, design §4(b)); `mapbox` is no longer a confirming value.
- **Rate / retry / credits**: ≤ 5 req/s (env `GEOAPIFY_RATE_PER_S` can only lower it); retry 429 / 5xx /
  transport errors up to 3 times, backoff 1 s · 2^n capped 30 s, `Retry-After` honoured; other 4xx fail at once.
  Every attempt counts as a credit. Daily credit guard `GEOAPIFY_DAILY_CREDIT_LIMIT` (default 2,500 of 3,000)
  per UTC day: start value = today's `geo.geocode_call` requests for the provider (`store.geocoder_requests_today`).
  When it trips: the rest of the run is `deferred` (pending, no try counted, no further locate model calls) and
  the job ends `stopped_credit_limit` WITHOUT re-enqueueing itself (a future-`run_after` job would hold the
  deploy gate all day); the next place_extract / backfill picks the names up.
- **Key hygiene**: Geoapify only takes `apiKey` as a query parameter, so the adapter never calls
  `raise_for_status()` (its message holds the URL), maps every transport / HTTP error to `GeocoderError` with the
  status or exception class only, and installs a redacting filter on the `httpx` / `httpcore` loggers (httpx logs
  the full request URL at INFO). `params()` returns the request without the key (safe to log / assert).
- **Cost**: Free plan → `cost_per_request` 0; `GEOCODER_COST_PER_REQUEST_USD` sets it on a paid plan (API 10)
  and then the existing $ budget rows apply. `BudgetedGeocoder` charges per request actually sent.
- **Fixture**: `tests/unit/fixtures/aa712_geoapify_bakeoff.json` = the 71 recorded responses trimmed to the
  fields the adapter reads (no key — checked), with the bake-off hand labels per rank; five candidates below
  rank 0 that the top-3 scan accepts were hand-labelled here (Taktshang path R, Tingtibi–Panbang highway R,
  Phnom Penh Center R, Phi Phi resort R, Bangkok Chinatown N — the report names the last three).
- **Destination key is `(name_norm, lower(btrim(country)), locality_norm)`** (design: `(name_norm, country)` plus the
  §4 homonym rule). `locality_norm` is `''` for distinctive names, the locality for generic names
  (`place_cards.is_generic_name`): the card's locality, else that day's overnight town. A generic name with no
  locality is never resolved (`locality_norm='?'` on its place row, no place_name row).
- **Duplicate cleanup keeps every row and id**: colliding rows get `duplicate_of = keeper` + `geo_status='suspect'`
  (keeper: manual > mapbox > llm > legacy, then has a cover, then oldest). No FK moves (TP tables reference ids;
  CIS may not touch them). Partial unique index `WHERE duplicate_of IS NULL AND name_norm IS NOT NULL`.
- **`geo.name_norm()` (SQL) ≡ `names.name_norm()` (Python)** by construction: same explicit 504-letter accent table
  (not NFKD at call time); unit test compares the literal in the migration with Python, integration test compares
  outputs on real Postgres.
- **Column names**: `geocoder_place_id` (not `mapbox_id`, there are now two providers); `located_by` CHECK extended
  with `amazon_location` and `manual`.
- **Budget provider `geocoder`** (not `mapbox`): covers whichever external geocoder is configured. Rows:
  `geocoder/global` $25/day, `geocoder/job:place_geocode` $50/run (= per-backfill cap; the backfill also refuses
  when its estimate exceeds $50), `bedrock/job:place_extract` $5/run $40/day, `bedrock/job:place_geocode` $3/run.
  Geocoder spend lives in `geo.geocode_call` (day spend) and the job's `cost_usd`.
- **Kind-scoped daily cap** (`load_run_budget(..., day_scope="kind")`): `place_extract`'s $40/day counts only
  place_extract jobs' LLM rows; with the provider-wide figure any busy S1 wave day would stop the pipeline.
  The provider-wide `global` daily cap is still a second axis (`RunBudget.global_day_usd`, checked against
  the provider's spend, `limit="per_day_global"`) — review finding 3: the first cut dropped it.
- **Component identity**: uuid5 of `(source_id, day, name_norm(itinerary place), country_norm(tour country),
  activity)`. The *link* key is separate: the place card's display name + country when a card exists (design §3
  "card identity preferred"), else the itinerary place + tour country.
- **place_extract idempotency key** = `place_extract:<version_id>:<a3_atomize job id>`: one key per version
  would block the admin re-atomize of the same version (keys are unique forever in `shared.job`); a retried atomize
  job still collapses. Set-active / restore / status triggers enqueue without a key but reuse a QUEUED job of the
  same tour.
- **Single writer**: place_extract inserts names only (`ON CONFLICT DO NOTHING`); a name already answered by a known
  destination / card destination is inserted directly as `resolved` (a new row, never an update).
  place_geocode is the only writer of destinations coordinates and of place_name status.
- **Legacy reuse rule** (design §4): a destination is reused by key only when `located_by IS NOT NULL`,
  `geo_status <> 'suspect'` and not a duplicate.
- **Outlier window ±2 days** (design said ±1): with ±1 the correct stop next to a wrong one has only the wrong one
  as neighbour and was flagged too (unit test). A jump is excused when any day of it is a transit day.
- **Graph build excludes suspect / duplicate destinations at build time** (design: "excluded from graph views");
  an admin fix must enqueue a graph build (slice 5). Graph CPU work runs in a thread (S201).
- **temperature 0** for the day and locate calls (TP used the provider default); extraction, determinism wanted.
- **Not-live tour → `skipped_not_live` (job succeeds)**, not NonRetryable-failed: backfill / triggers routinely meet
  trashed tours; a failed job would be noise on the Jobs page.
- **Trial lever measured, not used**: `stay_lever_fills` (nights the rules missed that the day's `stay` atom would
  fill) and `rule_missed_nights` are in every `tour_build.counts` / job result for the trial decision (design §3).
- **Schema `geo` grants**: none (REVOKE PUBLIC). `catalog_owner` gets SELECT in 228 with the 225 dance.

- **Background group cap** (review finding 2): besides the 2-slot reserve, at most `BACKGROUND_MAX_RUNNING = 1`
  background job runs per worker (all place kinds together; `Worker._running_kinds`). The reserve alone let
  3 background jobs claimed before a wave hold their slots, then hand each freed slot to the 6th
  `s1_rewrite`. 8 slots = s1 6 + atomize 1 + background 1.
- **`components_hash` includes the place-card link fields** (card id, display name, country, locality,
  destination) and `place_cards_build` enqueues `place_extract` for its tour when it linked cards (review
  finding 4): cards arrive after atomize, and the "card identity preferred" link needs a rebuild. T8's
  on-demand single-card builds do not enqueue (one card per request; the next extract of the tour sees it).
- **Guard country list = `chk_raw_tours_country`** (18 countries): Indonesia, Malaysia, Kyrgyzstan and
  Uzbekistan added to ISO2/ISO3/BBOX (review finding 5) — TripPlanner's 14 would leave those tours with no
  graph. A unit test compares the list with migration 150.
- **Atoms read through `acp_contract.v_active_tour_atoms`** (steering rule; review finding 7), inside the
  tenant-pinned catalog transaction because the view joins FORCE-RLS `published_tours`.
- **Outlier observations are replaced per evaluated source** and pruned for sources that are no longer
  live (no prune when the live read returns nothing); `replace_source_rows` drops the source's
  observations on a rebuild (review finding 10).

- **Geocoder setup / auth failure = stop the run, not a per-name error** (geocoder review fix 1): a missing
  or empty key, an unreadable secret, or HTTP 401/403 raises `GeocoderUnavailable`; `locate_many` checks the
  key (`ensure_ready`) before the first paid model call and defers the rest of the run on any of them
  (`reason='geocoder_unavailable'`, no try counted), `geocode_pending` reports `stopped_geocoder_unavailable`
  and the job ends with that status without re-enqueueing. Before this, 3 runs (~2 days) would mark every
  pending name `unknown` although the model had a valid point. Names the model itself answered null for in the
  batch already paid keep that answer (it does not depend on the geocoder).
- **Native-script acceptance aligned with the bake-off rule** (fix 2): radius and the settlement-only `city`
  rule come from the English name plus a native feature-suffix list (山莊 / 寺 / 湖 / 潭 / 사 / 호수 / 폭포 …);
  a candidate contained in the query must be ≥ 2 characters and ≥ half the query. "太平山莊" no longer accepts
  the city "太平" (the Taipingshan homonym, bake-off row 58). No bake-off evidence exists for native queries
  (Taiwan / Korea rows were English) — the rule is deliberately no looser than the English one.
- `FEATURE_WORDS` += mount, mt, hill(s), island(s), rock(s), viewpoint ("Mount Fuji" no longer accepts the city
  "Fuji"); an "X to Y" endpoint with no proper noun is dropped ("Road to Mandalay" → ["Mandalay"]). Bake-off
  numbers unchanged (35 correct / 1 wrong / 2 rescued with top-3; 32 / 1 with top-1).
- `GEOAPIFY_RATE_PER_S` is clamped to (0, 5]: 0, negative, NaN or junk → 5 (it used to switch throttling off).
- `geocode_pending` locates only as many names per chunk as today's credits can check (≥ 1 credit per name); the
  rest is deferred unpaid instead of paying a model call the credit guard then wastes.
- Sentry `before_breadcrumb` (api/core/sentry.py) redacts key-like query parameters (`apiKey=` etc.) from
  breadcrumb message / data — hardening in case `place_geocode` ever runs in the API process.

## Changed (vs. the design / the Linear issue)
- Design §4 "Mapbox in CIS" is replaced by Geoapify (S236). Measured on the recorded bake-off: top-3 rule
  accepts 38 of 55 rows with a result — 35 of the 38 rows whose top result is right (report: 34/38 ± 2), 2
  rescued below a wrong #1 (Bangkok Chinatown, Phi Phi), 1 wrong (Hahoe → Andong Folk Village, which the
  normalised query "Hahoe Folk Village" fixes: Hahoe Village at rank 2). The 3 correct rows it rejects
  (Khone Phapheng, Laos Buffalo Dairy, Ritigala) all have a bad legacy `null` reference 100–670 km off.
- **Migration 226 keeps `destinations_lower_name_uidx`** (review finding 1, option b; design §7 now has a
  slice 8 that drops it after TP's writers are removed). TripPlanner's live writers upsert
  `ON CONFLICT (lower(name))` and fail without it. `upsert_destination` therefore: inserts the plain name;
  on a `lower(name)` clash adopts a same-country TP row without `name_norm` (written after 226), else
  retries as `"<name> (<locality>)"`, `"<name> (<country>)"`, `"<name> (<locality>, <country>)"`, each
  attempt in a savepoint. `name` is the plain place name, not the locate label (finding 8).
- New names are inserted inside the persist transaction, after the liveness re-check (finding 9): a
  rolled-back not-live build queues no paid geocode.
- A `BudgetExceeded` from the day call propagates (finding 6): the job ends `stopped_budget`, not a
  rules-only `partial` build.
- Migration 226 sets `SET LOCAL lock_timeout = '10s'` (ACCESS EXCLUSIVE ALTERs must not queue behind a long
  job transaction); `place_outlier` comment says ±2 days.
- No CLI wrapper for the backfill (laptops have no DB route since AA-602); the admin endpoint is the entry point.
- `parse_answer` in locate raises on a non-JSON answer (TP returned all-None): the batch stays pending and is
  retried instead of being counted as "unknown to the model".
- A geocoder error leaves the name pending (design §3 failure rule); TP kept the model point.
- `tour_graph_build` does not enqueue the photo cover match yet: `photos/sync.itinerary_places()` still reads the
  TripPlanner tables until slice 4 repoints it.

## Tradeoffs
- `place_extract` reuses the previous day skeleton when `days_hash` is unchanged and the previous model call did
  not fail — a re-upload with the same itinerary text pays nothing; a `partial` build is always recomputed.
- Re-upload with identical text AND atoms only moves `tour_id` on the existing rows (`rebased`), no rewrite.
- The backfill estimate counts rule anchors only (model-found anchors appear at run time) — a slight underestimate
  of new names; LLM prices are design §8 upper bounds, so the total is conservative.
