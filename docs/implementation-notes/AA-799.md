# AA-799 — /v1/pipeline routes require admin

## Decisions
- New dependency `_require_admin` in `api/routers/v1_pipeline.py`, applied **router-wide**
  (`APIRouter(..., dependencies=[Depends(_require_admin)])`), so `/run` and any route added later are
  covered without remembering a per-route `Depends`. Handlers that use the principal
  (`review-queue`, approve, reject, execution, sources) still declare `tenant=Depends(_require_admin)`;
  FastAPI caches the dependency per request, so it runs once.
- Authorization = the backend admin secret (`X-Admin-Secret`), same check as
  `admin.verify_admin_secret`, but reading `ADMIN_SECRET` per call (testable via monkeypatch) and
  comparing with `hmac.compare_digest`.
- Status codes: no credentials → 401; invalid/expired Bearer → 401 (from `verify_jwt`); a valid JWT
  of any role (tenant or staff) without the secret → 403; wrong secret → 403; secret sent but
  `ADMIN_SECRET` unset on the server → 503 (mirrors `verify_admin_secret`).
- No `x-admin-role` check: the only BFF that targets these routes (`frontend/app/api/pipeline/[...path]`)
  forwards `X-Admin-Secret` only, and the `/admin/review-queue/{id}/approve|reject` aliases (the path
  the admin review page actually uses) check the secret only. A role check here would be
  inconsistent with those aliases; if approve/reject should be limited to `admin`/`reviewer`, do it on
  the `/admin` aliases first (follow-up candidate).
- `/run` kept (admin-only), not deleted — see Should know.

## Changed
- `_get_tenant` (accepted admin secret OR any valid JWT, no role check) removed, replaced by
  `_require_admin`. The unused `_security = _HTTPBearer()` went with it.
- `/sources` now always reads the master tenant's upload history (the admin principal's `sub`);
  before, a tenant JWT read that tenant's own rows. No caller used that tenant path.
- Guard test `tests/unit/test_aa799_pipeline_auth.py` iterates `router.routes`: no-auth 401, tenant
  JWT 403, staff JWT 403, bad JWT 401, wrong secret 403; admin secret accepted (dependency level +
  end-to-end `/review-queue` 200 with a mocked pool, `/run` reaches the handler's own 400 on a
  non-Excel upload, `/sources` pinned to master). 23 of its 37 cases fail on the old code.

## Tradeoffs
- Secret-only (not "secret or staff JWT with role admin"): direct staff-JWT access has no caller and
  would widen the surface; the BFF is the single staff entry point.
- Router-wide dependency vs explicit per-route: router-wide is a stronger guard against future open
  routes; the per-route declarations stay only where the handler needs the return value.

## Should know
- Callers found (AA-CIS-App main @5012da4, AA-TripPlanner-Web, AA-CIS-Infra):
  - No frontend page/component calls `/api/pipeline/*`; `API_RULES.pipeline` in `frontend/lib/rbac.ts`
    and the BFF route exist but are unused.
  - Admin review page (`frontend/app/admin/review/reviewApi.ts`) calls `/api/admin/review-queue*` →
    backend `/admin/review-queue/{id}/approve|reject` (`admin_pipeline.py`), which calls
    `approve_review` / `reject_review` directly with `tenant=None` — bypasses the FastAPI dependency,
    unaffected by this change.
  - `services/content_generation/handler.py` (retired Lambda) calls `/v1/pipeline/run-tour`, which no
    longer exists (moved to `/admin/run-tour`) — dead code, untouched.
  - `tests/load/k6_*.js` reference `/api/v1/pipeline/{upload,status,batch}` — routes that do not exist.
  - TripPlanner, Infra: no callers.
- `/run` has **no caller** — follow-up candidate to delete (Step Functions retired in AA-750).
- Per the AA-230 comment in `admin_pipeline.py`, the API Gateway Lambda authorizer requires a Bearer
  JWT on `/v1/pipeline/*`, so live a no-auth call is likely rejected at the gateway (401) before the
  app; a tenant JWT passes the authorizer and now gets 403 from the app.
