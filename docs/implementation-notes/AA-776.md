# AA-776 — F4-only ledger takes the SEO-fields repair, not a full Sonnet rewrite

Branch `fix/aa-776-f4-only-repair` (from main @ 20a2387). Lane A-T9, S235 (Claude Code).

## Decisions
- **Reversal of an AA-768 decision, on purpose.** `docs/implementation-notes/AA-768.md` (S234
  review, "sentence_repair.plan returns [] …") recorded "F4 alone keeps the old behaviour (None)",
  and `tests/unit/test_aa768_s234_hygiene.py` asserted it ("F4 alone: unchanged (full rewrite)").
  That was a conservative "do not change what you were not asked to" choice, but it contradicts the
  `plan()` comment right above it ("F4_seo_surface … never forces a full rewrite (S233)") and the
  approved issue. The assertion is flipped to `== []` with an AA-776 comment.
- **Slug violations keep `None`.** `_fit_seo_meta` only folds the slug to ASCII (`_ascii_slug`) and
  never writes a new one, so a "no slug" / "slug '…' is not lowercase-kebab" / "slug is N
  characters" violation that survives the fold can only be fixed by a new writer envelope (full
  rewrite). Detected by prefix (`"no slug"`, `"slug "`), the same way title/meta F12 violations are
  detected by `"title "` / `"meta "`. The test builds its slug violations through the real
  `gate_seo_surface`, so a reworded message breaks the test, not production.
- **F4 + a contract gate (F16_faq / F14_first_line) → `[]`.** Before, F4 + F16 returned None
  (full rewrite) while an SEO-field-only F12 + F16 already returned []. The rule is now one rule:
  "no text-repairable failure, at least one SEO-field gate (F4 or title/meta F12), no slug
  violation → []". The contract gate is then handled as it is alone: its own fix step ran, and it
  holds at the end if still failing. A contract gate ALONE still returns None (holds at once,
  AA-768 round 2 decision, `test_aa768_s234_round2.py::test_plan_skips_contract_gates`).

## Changed
- `services/acp_content_writing/sentence_repair.py`: `_SLUG_PREFIXES`, `_slug_violation(g)`;
  the `[]` branch of `plan()` now fires for any non-contract SEO-field gate (F4 included) unless an
  F4 violation names the slug.
- `tests/unit/test_aa768_s234_hygiene.py`: one assertion flipped (`[f4]` → `[]`).
- `tests/unit/test_aa776_f4_only_seo_fields.py` (new): plan() cases + three service-loop tests
  (attempt-1 F4-only → `repair_mode: seo_fields`, no rewrite/repair call; attempt-2 F4-only is not
  `last_try`, attempt 3 runs; slug-only F4 still takes the full rewrite).
- No change in `service.py`: the loop already handles `plan() == []` (S234 review) and `last_try`
  already reads `plan() is None`.

## Tradeoffs
- An F4 the fit cannot fix now costs up to 2 more fit calls (attempts 2 and 3, t9_repair stage,
  ~$0.002 each) and is then held on F4, instead of one Sonnet rewrite (~$0.05) that might also
  have produced an in-band title/meta. In the S234 dump, pieces whose attempt-1 F4 went to a full
  rewrite (ac7698b7, 8a4f0608, 7adcd11e, 12beeee0) still failed F4 at attempt 2, on a new
  title/meta miss (meta length or keyword) — the rewrite is no better at F4 than the fit, and the
  fit is told the exact miss.
- Behaviour change beyond the issue text: SEO-field-only F12 + an F4 slug violation used to
  return [] (the slug violation was ignored) and now returns None (rewrite). Rare (the slug fold
  fixed every S234 slug failure after S233) and the old result could never pass F4.
