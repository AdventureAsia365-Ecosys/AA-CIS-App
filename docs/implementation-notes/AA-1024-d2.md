# AA-1024 D2 — model lifecycle as data (lane l4 of S265)

Plan: root `docs/audits/2026-11-01-S263-gateway-gap-audit/plan.md`, slice D2 (OPS-04). Done-when: a nightly sync fills
`lifecycle_status` and `eol_date`; the digest warns 90 days before the end of life; every routed model has a non-NULL
status. IAM (`bedrock:ListFoundationModels` on the CIS task role and on the acc3 satellite role) is in AA-CIS-Infra,
`docs/implementation-notes/AA-1024-d2.md` there.

## Decisions

- **Columns on `shared.llm_model_catalog`, not on the deployment table** (migration 352, expand): the plan names the
  catalog, and the digest and the routes speak in catalog keys. Per-account facts (acc2 ACTIVE, acc3 refused) go into
  `lifecycle_detail` jsonb, so nothing is lost. Five nullable columns, no CHECK (a constraint on an existing table
  would make the file contract, ADR 0017 d3); the vocabulary is enforced in code.
- **Status vocabulary:** `active` / `legacy` (Bedrock's status, the worst over the answering accounts), `unlisted`
  (an account answered but does not list the id: past end of life or a wrong wire id), `unknown` (no account
  answered and no earlier status), `untracked` (no Bedrock deployment: OpenAI, Anthropic API, Jev, mock). Every
  catalog row gets one, so "every routed model non-NULL" holds after one run even while acc3 refuses.
- **A status Bedrock adds later counts as `legacy`** (it warns rather than hides); the raw value stays in the detail.
- **Fail soft per connection:** a refusal (acc3's account-level hold) or an error is the connection's `access` in the
  result and the detail, with the message masked (`errors.redact_ids`); the run succeeds. A model only that account
  serves keeps its earlier answered status (`kept_from_previous`); a refusal says nothing about the model.
- **No breaker, no ledger:** the list is a free control-plane read, not a model call, so it neither touches the
  connection circuit nor writes `shared.llm_call_log` (nothing is billed; `billed_fields` does not apply).
- **Wire id -> foundation model id:** strip the inference-profile prefix (`global.`, `us.`, `eu.`, `apac.`, `jp.`,
  `au.`, `ca.`, `us-gov.`), take the id from a foundation-model / system inference-profile ARN; an application
  inference profile has no model in its id and counts as unlisted. Match exact, else the single listed id with the
  same base before `:`; never guess between two.
- **Which deployments:** every deployment row on a Bedrock connection, enabled or not (the lifecycle is the model's);
  the catalog `bedrock_profile_ids` only when a bedrock model has no deployment row.
- **Routed** = active `llm_role_config` rows: `model_id`, `fallback_model_ids`, `shadow_model_id`, aliases expanded
  (`shared.llm_model_alias`, in position order) — the same expansion as the invariant.
- **Warning** (bell + digest): routed, and end of life within 90 days or past, or LEGACY, or unlisted. `unknown` is a
  digest line only (no bell: it is an access problem the connection alerts already cover).
- **Bell:** `shared.notifications`, event `llm_model_lifecycle`, entity `llm_model:<key>`, at most one per 7 days per
  model (nightly; a daily repeat is noise), platform tenant id, admin audience, payload with `message`.
- **Schedule:** nightly from 04:00 UTC (after the 02:00 reconcile, before the 05:00 probe); switch
  `LLM_MODEL_LIFECYCLE_SYNC` default ON (the run is free). Background, deploy-gate exempt, max_attempts 2.
- **Manual run:** `POST /admin/job-runner/llm-model-lifecycle/run` (ai.admin), live by default (no cost), `dry_run`
  computes without writing.
- **Before migration 352:** the scheduled run is a no-op with `skipped` (no failed job in the digest between deploy
  and the expand auto-apply); a manual live run is refused; the digest says "not available". No readiness raise.

## Changed (vs. the plan)

- The plan says "fills lifecycle_status and eol_date"; the job also writes `legacy_date`, `lifecycle_checked_at` and
  `lifecycle_detail` (needed for the fail-soft rule and for an admin to see why a status is unknown).
- The admin UI (Settings › LLM Models) does not show the columns yet: the digest section, the bell and the job
  result do. Follow-up for the observability UI rule.

## Tradeoffs

- Worst status over accounts: a model offered on acc2 but not on acc3 reads `unlisted` while an acc3 deployment row
  exists. Correct for routing (that deployment cannot answer), noisy if the row is stale; the detail names the account.
- The list call uses two attempts and a 20 s read timeout: a slow account delays the run by seconds, never fails it.
