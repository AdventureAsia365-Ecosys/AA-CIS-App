# AA-935 (CRM-07) — Content studio -> Partner CRM cross-link

Card: root `docs/audits/2026-10-21-S246-crm-design-v3/design-v3.md` §2.1 (Fix C10) and `final/crm-design-final.md`
§4.4 row "CRM skeleton": "portal sidebar gets a CRM link, CRM sidebar a Content studio link". The CRM web itself is
built in AA-Partner (`web/`, same issue).

## Decisions

- **One link block below the nav groups, not a `NAV_GROUPS` entry.** The CRM is another app on another host: the
  ⌘K palette (`router.push`) and the phone bottom bar must not route to it, and `navActive` has nothing to match.
  A plain `<a>` keeps those three untouched.
- **URL from `NEXT_PUBLIC_CRM_URL`, default the Dev host** `https://partner-dev.lumiguides.it.com` (the portal host is
  already a literal in this repo; host names are not on the DM-6.10 list).
- **No shared session.** The portal still signs in with the tenant API key; the CRM signs in through Cognito (the
  `cis-portal` client until AA-939, then the partner pool). Two sign-ins until AA-979 P2b (design-final §4.4).

## Changed

- `portal/app/portal/_shell/PortalSidebar.tsx`: "Partner CRM -> Open CRM" link (`data-testid="portal-crm-link"`).
- `tests/e2e/smoke-portal/portal-smoke.spec.ts`: one smoke for the link (visible, absolute https URL, another host).

## Tradeoffs

- The link is shown to every portal tenant, also those without a CRM agency yet; the CRM answers them with "Your
  account is not a member of any agency yet". On Dev every agency is synthetic, so nobody real is affected.

## Should know

- Kit files are untouched (no byte-copy drift for the portal or the CRM web vendored copies).
