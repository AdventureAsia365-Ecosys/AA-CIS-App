# AA-791 — per-attempt gate ledger, human Label action, fault-injection set

S237, Claude Code (lane cis-portal item 4). Two branches, D8 migration flow:

1. `feat/aa-791-mig-231` — `api/migrations/231_content_piece_label.sql` + its integration test only.
2. `feat/aa-791-gate-ledger-label` (stacked on 1) — the T9 ledger change, the label routes, the
   drawer / table UI, the 30-piece fault-injection set.

## Decisions

- **Per-attempt ledger lives in `repair_log`, no schema change.** Every failed attempt already appends
  one `repair_log` entry (service.py, after the gates); that entry now also carries
  `gate_ledger`: that attempt's full ledger, trimmed to `gate` / `passed` / `blocking` / `violations`
  (violations capped at 5 per gate, 300 chars each). The passing attempt's ledger is the piece's own
  `gate_ledger` column, so "every attempt" = the `gate_ledger` of each `repair_log` entry that has one
  + `content_piece.gate_ledger`. Passed gates are kept (with empty violations) so a gate's runs, not
  only its failures, are countable per attempt — precision/recall needs the denominator.
- **Trim helper in a new module** `services/acp_content_writing/gate_eval.py` (`ledger_snapshot`), not in
  `quality_gates.py`, so the T9 loop diff is one line and AA-819's T9 guard (same files) rebases cleanly.
- **Label table shape follows the AA-783 criteria pack** (verdict `as_is/light/heavy/reject`, four defect
  classes `fact/voice/format/ai_phrasing` each `none/light/heavy`, minutes to fix, reason) rather than
  the issue's minimal "label + reason", so the labels Nghiệp enters in the UI are directly comparable
  to the spreadsheet pack and the κ analysis of AA-783 needs no second pass.
- **One row per (piece, labeller)**, PK `(piece_id, labelled_by)`. Two people labelling the same piece
  is how agreement is measured; re-labelling overwrites your own row. `labelled_by` is
  `admin:<x-admin-user-id>` (same actor format as the audit log rows).
- **`content_sha256`** of the text at label time: an admin sentence edit after labelling is visible as
  a mismatch (`text_changed_since_label` in the GET response) instead of silently re-scoring a
  different text.
- **No RLS, no tenant column, explicit REVOKE from aa_app_user.** Admin-only data read through the admin
  pool (owner). ENABLE RLS with no policy would add nothing (no tenant dimension) and RLS on Dev has
  surprised us before (lesson S236, aa_cis_admin role behaviour).
- **Missing table tolerated** (D8): `to_regclass('acp_shared.content_piece_label')` is checked per
  request (cheap catalog lookup, no cache so the feature turns on the moment DB Migrate applies 231,
  without a redeploy). Label routes → 503 "Labels are not available yet: migration 231 …"; the piece
  list returns `labels_enabled: false`, no label column data, and ignores the `label` filter; the UI
  hides the column / filter / drawer form and shows a one-line notice.
- **Label filter values**: `as_is`, `light`, `heavy`, `reject`, `labelled` (any), `unlabelled`. The list
  shows the latest label on the piece (any labeller) plus the label count.
- **Fault-injection set = 30 deterministic cases, no LLM** (`tests/unit/aa791_t9_fault_set.py`,
  run by `tests/unit/test_aa791_fault_injection.py`): 10 gates that fired 0 times in S234's 80 pieces
  (report 12 §1.5) × 3 planted faults each, run through `run_quality_gates` with the two judge gates
  (F8/F9) stubbed to pass. Each gate also has a clean twin that must pass that gate (precision guard).
  Gates: F6_cta_present, F0_complete, F4_extreme_length, F11_brand_name,
  F10_cannibalization_cross_tenant, F2_brand_forbidden, F2_banned_patterns, F13_leak, F14_first_line,
  F16_faq.

## Tradeoffs

- Ledger in `repair_log` (no column) vs a new `attempt_ledgers` column: no migration and no change for
  readers, at the cost of readers having to know "failed attempts are in repair_log, the final one in
  gate_ledger". The admin drawer now shows it per attempt so nobody has to read the JSON.
- Trimming violations (5 × 300 chars) keeps each piece's row small (a blog ledger has ~26 gates); the
  final attempt's untrimmed ledger is still the column.
- `to_regclass` per request vs a cached flag: one extra catalog lookup on two admin routes and the
  list, in exchange for no redeploy after the apply.

## S239 — Label form defaults + LABEL column position (Claude Code, branch `fix/aa791-label-form`)

The S239 audit found two UI defects blocking "Label action works on Dev": an unlabelled piece
opened with **As-is pre-selected** (`draftFrom()` defaulted `label` to `"as_is"`), so a stray
Save stored a wrong verdict; and the **LABEL column was the last column**, off-screen behind the
gate-chip columns at 1440 px.

### Decisions
- The form keeps its own draft type, `LabelDraft` (= `PieceLabelBody` with `label: PieceLabelValue
  | null`). `PieceLabelBody` (the POST body) is unchanged: `label` stays required, matching the
  backend. `labelBodyFrom(draft)` returns the body or `null` while no verdict is chosen; Save is
  disabled on `null` and a muted "Pick a verdict to save" hint shows next to it.
- A piece I already labelled still opens with my saved verdict selected and "Update my label".
- The LABEL column moved to right after Status (6th column). It is now on screen at 1440 whatever
  the Blocking fails / Warnings chip lists do. No column was dropped: Att. and Cost are cheap and
  are used by the cost review, and the table already scrolls sideways for the chip columns.

### Changed
- `frontend/app/admin/content-quality/PieceLabel.tsx`, `page.tsx` only. No backend change.
- New mocked UI spec `tests/e2e/aa791-label-form.spec.ts` (every `/api/admin` call answered by
  `page.route`, no Dev data): no verdict pre-selected, Save disabled until one is picked, the POST
  body (verdict, defects, minutes, trimmed reason), the saved-label case, and the LABEL header's
  right edge inside 1440 with no page-level horizontal scroll. 2/2 pass against local `next dev`.

### Tradeoffs
- Moving the column vs narrowing the chip columns: moving is one line and does not depend on how
  many gates fail on a given piece; the chip columns still widen the table (they scroll), but the
  verdict no longer hides behind them.
