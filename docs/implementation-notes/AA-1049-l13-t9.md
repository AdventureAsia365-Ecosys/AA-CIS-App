## Known limits (open review findings, all on opt-in code; to settle with W2 data before any switch goes on)

- **stable_keys, hold class (review round 3, major).** `compare()` weighs a style-only key like a hold-class key:
  prev [F15_voice x2], cur [F1_grounding x1] -> main reverts (truth-clean attempt ships); opt-in keeps cur (held on F1,
  the tenant still receives the text with the fabricated number). Candidate fix: fail closed when `hold_failure(prev)`
  is None and a new key's gate can hold, or count only hold-capable keys.
- **stable_keys, F14 whole-gate key (review round 3, major).** F14_social_shape keys as (F14, `*`), so an attempt-1
  under-floor block and an attempt-2 far-over block look the same; with a same-gate F15 swap the opt-in mode reverts to
  attempt 1 and the AA-780 floor waiver ships the short post approved. Candidate fix: key F14 by violation class
  (under / over / far_over / hashtags), or never revert into a gate that never holds from one that holds.
- **Replay SEO verdict is not independent of the code under review.** `_seo_predicates` uses the checkout's own band
  and predicates; the only main cross-check is that both sides judge the WRITER's values the same. A loosened
  predicate that still fails the writer's value (e.g. a lower meta floor) certifies its own prefix as D-seo-1 (review
  mutation M7). The earlier claim in this file that a predicate change always shows as UNDECLARED was wrong. Candidate
  fix: compute every candidate prefix in the replay script and record main's verdict per candidate in the base row.
- **Replay guard key counts come from stable_keys.** D-guard-1 / D-guard-2 use the branch's own key counts; the gate
  sets are checked against main's view, the counts are not (review mutation M5: a key fold on F13_repeat certifies a
  bad keep). Candidate fix: an independent per-gate findings view recorded on the base checkout.
- **Replay does not run the call site.** The AA-780 floor-only exception and the revert wiring are pinned by
  test_aa450 TestDiscardedAttempts / test_aa780, not by the replay; a floor-only attempt-1 pair in a `--pieces` export
  can differ from what production did.

These limits are written in the replay script's header too. They do not affect a default run (no declared id is
allowed there).

## Step 1 — route_table (zero-diff refactor)

### Decisions
- **One table, two halves joined on `gate`.** The policy half (`repair`: cheap | fix_step | default, `style_only`) stays
  in `services/quality/writing_policy.yaml` route_rows, untouched. The loop mechanics (`action`, `parse`, `section`,
  `cut`, the `slug: rewrite` field override, `truth_cut.cut_not_hold_channels`) live in
  `services/acp_content_writing/route_table.yaml`; `route_table.py` joins both and adds each gate's taxonomy classes
  (`registry.gate_classes`).
- **Why not in writing_policy.yaml:** the first cut put the mechanics into the policy route rows. That moved
  `policy_sha`, and `policy_sha` is hashed into 16 registered prompt versions (prompt_registry `reads_policy`): the
  check then asked for 16 version bumps and a migration (like 389) for a change that alters no prompt and no
  behaviour. A loop-mechanics column is not policy; the policy decisions (stage, style-only, F9 class hold/warn) stay
  where they were. `policy_sha` is unchanged (`739223d6cc24f1e5`).
- **Actions:** a row's `action` is its repair route (`repair_sentence` | `regenerate_section` | `rewrite`); `cut` and
  `hold` are what happens to what is left after the budget (`cut: truth | cut_finding`; hold = not `style_only`, F9
  classes by `f9_class_rows`). That is the ADR's five-way vocabulary without a row having two primary actions.
- **Fail closed at import:** a schema problem in `route_table.yaml` (or a disagreement with the policy rows) raises
  `RouteTableError` when the module loads, so a broken table can never route silently.
- **plan() dispatch by parse:** `sentence_repair.plan` now dispatches on the row's `parse` (quoted / brand_style / f1 /
  f9) instead of gate names; one gate per judge format, pinned by a test.

### Changed (vs the S271 code)
- `sentence_repair._ELIGIBLE_GATES`, `_QUOTED_GATES`, `TRUTH_GATES`, `_seo_fields_only`, `_slug_violation`, the
  judge-quote and heading branches of `plan`; `quality_gates.STYLE_ONLY_GATES`, `CHEAP_REPAIR_GATES`,
  `OWNED_BY_FIX_STEP`; `service.TRUTH_CUT_GATES`, `F17_CUT_GATE`, `F9_CUT_NOT_HOLD_CHANNELS` — all views of
  `route_table`. Names kept (callers and the AA-926 snapshot read them).

### Tradeoffs
- Two files instead of one: accepted to keep `policy_sha` (and 16 prompt versions) stable for a mechanics change. The
  lint forbids restating `repair` / `style_only` in the mechanics file.

### Should know
- Zero-diff proof: `tests/unit/test_aa926_equivalence.py` replays every routing decision (plan, hold_failure,
  never_holds, style-only repair, the routing sets, the truth-cut sets) against its committed fixture, which this
  commit does NOT regenerate. Lint: `tests/unit/quality/test_aa1049_route_table.py` (exactly one row per live T10
  gate id of the taxonomy, a row agrees with its policy half, every S271 set equals its frozen literal).
- `prompt_registry_check.py`: 0 problems (no prompt moved).

## Step 3a — seo_builder (opt-in `T9_SEO_BUILDER=on`; declared diff: fewer SEO-fit calls)

### Decisions
- `services/acp_content_writing/seo_builder.py`: before any SEO-fit call, a failing title / meta becomes the first
  deterministic PREFIX of the writer's own value that passes the SAME `title_ok` / `meta_ok` predicates of
  `_fit_seo_meta` (policy band from the registry, keyword, scope places, unsupported products, date authority,
  rarity, authenticity). Meta: leading whole sentences only (a decimal is not an end; nor is a full stop after a token
  of the explicit list `seo_builder.ABBREVIATIONS` (mt, st, dr, mr, mrs, ms, prof, capt, approx, vs, etc, e.g, i.e,
  incl, est, ca, no, ave, rd, a.m, p.m; case-insensitive), a single-letter initial, or a token with an inner period
  such as "U.S."). Title: the part before " | ", " — ", " – ", ": ".
- **Review fix S272 round 3 (abbreviations, applied although the code is opt-in):** a digit after a full stop no
  longer starts a sentence ("every Sat. 7 am", "Oct. 2026", "5 km. 3 hours"), and the list now has months (jan feb
  mar apr jun jul aug sep sept oct nov dec), weekdays (mon tue tues wed thu thur thurs fri sat sun), company suffixes
  (co ltd inc corp llc pte bhd plc, jr sr) and units (km hr hrs min mins sec secs kg ft mi). A real word on the list
  ("Sun.", "Sat.") only loses a candidate: the field then goes to the fit call, as on main. Pinned by
  `test_no_cut_after_a_month_weekday_company_or_unit` and the end-to-end
  `test_fit_seo_meta_never_ships_a_cut_after_an_abbreviation` (approx. / Sat. 7 am / Oct. 2026, builder on and off).
- **Review fix S272 (abbreviations):** the first cut exempted only capitalised 1-3 letter tokens, so "approx.", "vs.",
  "Prof.", "Capt." and "U.S." ended a sentence: under the real meta band (140-155) and `meta_ok` a mid-sentence prefix
  ("... with a local guide for approx.", 142 chars) passed and shipped with 0 fit calls; F4 could not catch it (same
  predicates). And real words ("Bay.", "Hue.", "Spa.") were dropped as abbreviations. Pinned by
  `test_no_cut_after_an_abbreviation_or_a_dotted_initialism`, `test_a_real_word_at_a_sentence_end_is_an_end` and the
  end-to-end `test_fit_seo_meta_never_ships_a_cut_after_approx` (real `_fit_seo_meta`, real band).
- No model call when both fields then pass. After the one fit call, the fitted value gets the same shortening.
- The second fit call per attempt ("one more try, told how far off") is removed: the next attempt re-runs the fit,
  and F4 reports what is left, as on main.
- Not done (on purpose): a code TEMPLATE for a too-short meta. S272 withdrew the country tail (wrong country on
  cross-border inputs); a short value still goes to the one fit call.
- S273 follow-up (lane l19, `AA-1049-l19-t9-seo-meta.md`): a short meta is now completed by one cited post sentence
  (D-seo-3) or sent to the one fit call with the band stated (D-seo-4); still no template, no country tail.

- D-seo-2: at most 1 fit call per attempt (was 2). Main's tests are unchanged (default off); the opt-in tests are

## Step 2 — stable-key regression guard (opt-in `T9_REGRESSION_GUARD_MODE=stable_keys`); stop rule, truth_cut, verdict cache

### Decisions
- `services/acp_content_writing/stable_keys.py`: a blocking finding's key is (source gate, the folded quoted sentence)
  read through the route table's `parse` (quoted, F1, F9 claim / TEXT_INTEGRITY, brand-style phrase); an F9 CTA miss
  is (F9, `cta_not_reflected`); every other failure is (gate, `*`) because its text carries counts. The judge's
  reason wording is never in a key. Tier-2-only seed-alignment results stay out (as the AA-1000 review rule).
- With the opt-in mode, the AA-528 guard reverts when the rewrite has a key the previous attempt did not AND it is not net-better on
  either measure: as many keys or more AND as many failing gates or more (`stable_keys.compare`). Main's gate-count
  rule stays a condition, so a rewrite that clears a whole gate (e.g. F1 + F9 cleared for three F13_repeat findings)
  is kept exactly as on main: reverting it would bring back a product-truth failure the rewrite cleared. (Review fix
  S272: the first cut counted keys only and reverted that case; pinned by
  `test_a_rewrite_that_clears_whole_gates_is_never_reverted`.)
  The default `T9_REGRESSION_GUARD_MODE=gate_names` is the S271 comparison (the switch is classified in
  `writing_memory.config_fp.MODE_FLAGS`, so the release fingerprint moves with it). The AA-780 floor-only exception
  is unchanged.
- **Stop rule: no code change.** Built and withdrawn: in the default `stop_and_label` mode (D6) attempt 3 is already
  $0, so there is at most one paid repair round; the rule only changed the `legacy` rollback mode, and broke 13 tests
  that pin what the rollback must still do. ADR 0020's "max 2 repair rounds, round 2 only on strict shrink" is met by
  D6; `stable_keys.shrank` is kept (tested) for the W4 instrument-driven loop.
- **Generalised truth_cut: not built.** In the default mode no code cut runs (D6: only classes with a passing
  measurement record may be cut; none exists before W2). Generalising the blog / LinkedIn cuts would change only the
  legacy rollback. Follow-up for W4 (after W2 measurement records).
- **Verdict cache replacing F9PassMemory: not built** (see Should know).

### Declared diffs (opt-in only; two review findings open, see Known limits)
- D-guard-1: a rewrite whose new keys are all in gates the previous attempt already failed, with the gate set
  unchanged and as many keys or more (a same-gate swap), is reverted (S271 kept it: no new gate name).
- D-guard-2: a rewrite with fewer keys than the previous attempt (it clears more findings than it adds, the new ones
  in another gate) is kept (S271 reverted it when the gate count did not drop).
- These are the only two flips: if the gate count dropped, both rules keep; if a new gate appears with the gate count
  not lower, both revert unless the key count dropped (D-guard-2).
- Neither changes a gate verdict or a hold rule: the guard only picks which of two already-gated attempts continues.
  **But the piece STATUS can flip** (review S272), because the attempt that continues is the one the piece ends on
  when the loop stops after it (attempt 2 is the last paid one in `stop_and_label`):
  - held -> approved: prev = [F9_cta_fact 2 claims, F15_voice 1 sentence], cur = [same F15_voice sentence,
    F2_superlatives new sentence]. Main reverts (new gate, 2 >= 2 gates) and the piece ends on prev, held on F9; the
    branch keeps cur (2 keys < 3), and cur passes every hold gate on its own ledger (`hold_failure(cur)` is None), so
    it ships approved.
  - approved -> held: prev style-only, cur with a new F1 number and fewer keys: main reverts to the style-only attempt
    (approved), the branch keeps cur (held on F1).
  Neither is more permissive per text (each side's final ledger is judged by the same gates), so both are the declared
  D-guard-2 / D-guard-1 shape, not a fail-closed violation. The `--pieces` replay counts them
  (`guard_status_flips`, by main's hold view of the attempt each side continues with; exact for the last pair, an
  earlier pair only says which attempt the next round starts from). **Before the live rollout: run the `--pieces`
  replay on a read-only content_piece export and read `guard_status_flips`.**

### Should know
- F9PassMemory (AA-777 sticky pass + AA-865 deletion carry) is the one permissive mechanism in the loop. Replacing it
  with a verdict cache keyed (sentence, cited lines / pack sha, instrument id, policy sha) needs the instrument id per
  verdict (W2/W4, D7) and per-sentence verdict records; a cache without the instrument key would be no stricter than
  today, and dropping the carry rules would re-judge text the judge already passed (cost, noise). Left for the W4
  instrument PR with the same declared-diff replay.

## Step 4 — R0b PieceStore seam + free offline replay (declared-diff report)

### Decisions
- `services/acp_content_writing/piece_store.py`: `production_input(context)` is the production input builder
  (`service._grounding_text` / `_grounding_sheet`, one implementation) with its shas; `DryStore` + `use_store()` (a

- `scripts/quality/replay_aa1049_t9.py`: replays stored pieces (golden fixture and/or a read-only content_piece export
  with repair_log). The stored gate verdicts are the cassette; the F9 judge is never called; an SEO-fit call is a
  cassette miss that is counted, never answered; a piece with no usable F9 verdict is "needs rejudge", never a pass.
  The same script runs against a main checkout (`PYTHONPATH=<main>`) for the base and against the branch for the diff;
  every difference is classified as a declared id (D-seo-1, D-guard-1/2) or UNDECLARED (exit 1).
- **Declared means the declared SHAPE (review fix S272), not the direction.** D-seo-1: the branch makes 0 fit calls
  where main made one, the slug is unchanged, at least one field changed, and every changed field's writer value
  FAILS main's acceptance tests while the new value is a strict prefix of it that PASSES them (and every delivered
  field passes). D-guard-1 / D-guard-2: per attempt pair (one diff entry per pair, so mixed flips never merge into one
  id) with the shapes above; D-guard-1 also needs as many keys or more. Anything else, a flip without evidence, or an
  unknown id, is UNDECLARED.
- **Evidence independent of the branch flow (review round 2, S272).** The first fix still trusted what the judged
  code produced; mutation runs showed it certified itself:
  - SEO verdict: `_seo_predicates` is an independent copy of main's `_fit_seo_meta` acceptance tests (band + keyword,
    scope places, taken title, unsupported products, date authority, rarity, authenticity), built from module-level
    checks both checkouts have and imported from their own modules. It judges the writer's values and the delivered
    values on every checkout; a difference in how the writer's values are judged is UNDECLARED (a predicate change).
    Mutation M1 (skip the fields_ok check) was D-seo-1 x6; now UNDECLARED x7.
  - Production arguments: `_fit_seo_meta` gets the HygieneContext run_write_background builds (after
    `_add_date_spans`: scope, trip name, brand, CTA, channel spec, Facts, trip places) and the taken titles of the same
    tenant's other blog pieces in the replay set (production reads its 50 most recent from the DB; the replay set

    places_named / title_taken from the closures) was 0 diffs; now UNDECLARED.
  - Both-sides fit miss: only the FITTED answer is unknown. The fit request (kwargs: title, meta, forbidden words,
    taken titles, keyword, brand, tenant, body sha) and the fields the soft-fail path ships on a fit outage are
    compared: equal = MISS (not compared); a difference must be the D-seo-1 shape (a code-fixed field, the fit asked

    else UNDECLARED. Mutation M2 (junk fields after the check) was MISS x6; now UNDECLARED x7.
  - Guard: `_guard` records main's gate-name view (`service._regression_failures` of both ledgers) and the hold gate
    of both on every checkout; the classifier requires the branch's stable-key gate sets to equal the BASE row's view

    UNDECLARED. Mutations M3 (drop `len(cur) >= len(prev)`: F13_repeat x3 -> x1 reverted) and M4 (blocking_keys skips

- **SEO-fit cassette miss (review fix S272):** a piece whose replay needs a fit call is a cassette miss (never a hit,

- **Stored sha (review fix S272):** the first cut compared a text's sha with itself (always true) and was reported as
