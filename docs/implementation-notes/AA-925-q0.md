# AA-925 PR 1 — Q0 corpus, real-chain runners, chain order, red on base

## Decisions

- **Cases are JSON** (`tests/unit/quality/cases/*.json`, a list per file), not YAML: PyYAML is not a direct
  dependency and the CI script must stay stdlib-only. Shared synthetic inputs live in `_fixtures.json`; a
  case points at one with `input.base` and overrides fields with `<key>_patch` (deep merge).
- **A case = truth label + checks.** `detector` + `expected` (`fire|no_fire|keep|drop`) is the truth label:
  the case fails when the detector's presence in the observed signals (failure codes, `quality_shadow`
  codes, `degraded` names, failed T9 gates/flags) disagrees with it. `expect` adds checks (publishable,
  status, a field contains / does not contain, counts). Every scripted model answer must be used and an
  unscripted call fails the case (callers such as flag_fix fail open, so the runner records it itself).
- **Runners drive production code** (critique point: a hand-written copy of the order drifts):
  - A1: `graph.build_graph_from_generated().invoke(state)`; the writer JSON is the batch text, so
    `seed_generated_node` runs the exact generate post-processing, then the real nodes. Stubbed: judge
    (pass), brand audit (from the case), Jev (`grounding.judge_units`), `LLMClient.__init__/generate`,
    `call_log.record_call`, lessons write-back.
  - T9: the real `service.run_write_background(..., pool=MagicMock())` with `tenant_id` unset (no DB, no
    embedding), writer / rewrite / sentence repair from the case, F9 stubbed to pass or `invoke_judge`
    raising (`f9: "unavailable"`), `_finalize_piece` captured.
  - gates: the 40 AA-791 cases through their own gate-only `run_case`, labelled by an adapter file
    (`aa791_gates.json` holds labels + the AA-791 case id, not a copy of the data).
- **Import rule.** `chain.py` and the tests import only modules that exist on `main`; AA-925 outputs are read
  with `state.get("degraded", [])` / `state.get("quality_shadow", [])`. So a new case run on the base fails
  on an assertion, and only a junit `<failure>` counts as red.
- **Red on base** (`.github/scripts/q0_red_on_base.py`, stdlib): base = `HEAD^1` of the pull_request merge
  ref (`fetch-depth: 2`), not the fork point. New ids are run by **node id** (`-k` matches substrings:
  `x-dup` would select `x-dup-twin`). The PR's `tests/unit/quality/` and `tests/unit/conftest.py` are copied
  into a `git worktree` of the base, and the script checks `services` imports from that worktree before
  trusting the result. Error / skip / missing = inconclusive = fail.
- **Relabel guard.** Removing a case, changing any label field of an existing case (`expected`, `class_id`,
  `detector`, `severity`, `chain`, `expect`, `input`, `llm_stub`) or changing/removing an existing shared
  fixture needs the `q0-relabel` PR label. Labels are read from the event payload via an env var
  (`PR_LABELS`, never interpolated). A re-run keeps the old payload, so after adding the label push a commit.
- **Exemption.** `red_on_base: false` only for a negative twin (`no_fire|keep`) whose `twin_of` is a new
  positive case in the same PR.
- **No new required check**, no branch-protection change (D1): it is a step inside "Unit Tests".
- `class_id` for gates that are not taxonomy classes yet uses `other.<name>` (design §3.3 rule).

## Chain-order test (`test_chain_order.py`)

- T9: no assignment to `content_text` after the single `_final_integrity(...)` call (an assignment check,
  not a name list: `strip_citation_tags(discarded_attempt[...])` runs after it on the discarded attempt).
- `_cut_truth_items` and `_enforce_authenticity` run after the in-loop `text_integrity.final_pass` and before
  `_final_integrity` — the reason `_final_integrity` is the real last pass.
- A1: `revalidate_node` strips and fits before `validate_node`.
- Edges brand_audit → grounding → flag_fix → revalidate → END in `build_graph()`,
  `build_graph(t2_drafts=True)` and `build_graph_from_generated()`.
- Known post-validate repair: `_apply_grounding_recheck → repair_and_recheck` (PR 3's contract covers it).

## Tradeoffs

- The gate cases keep their gate-only runner: a full chain would run fixers that may legitimately change
  those outcomes, and the AA-791 set measures gate wiring, not the chain.
- Pins that are green on main are only possible in PR 1; afterwards every new case must be red first.
- Running new cases on the base costs a second pytest process in the Unit Tests job (seconds: the corpus
  makes no model or DB call).
