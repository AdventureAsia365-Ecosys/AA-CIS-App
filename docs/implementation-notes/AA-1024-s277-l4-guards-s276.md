# AA-1024 — S277 lane l4: S276 lessons become guards (CIS part)

Two S276 lessons had `Guard: pending AA-1024`. This PR adds the CIS guards; the root PR (same lane) adds the shell
hook rule and the Linear export scan and updates the lesson lines.

## Decisions

- **Pre-push pins check** (`scripts/pre-push.sh`, `check_pins`): compares `fastapi` and `pydantic` of the Python
  the script picked (`AA_PREPUSH_PYTHON`, `$VIRTUAL_ENV`, `.venv`, the main checkout's `.venv`) with the `==` pins in
  `requirements.txt`. One interpreter start reads both versions through `importlib.metadata`.
- It runs only when the plan starts Python tests (`unit` or `integration`, and `--integration`), after `--dry-run`
  exits, and never in `--ci` (CI installs the pins itself). A docs-only push does not pay for it.
- A mismatch **stops at once**, before minutes of tests that would fail falsely, and prints the exact install
  command `"<python>" -m pip install $(grep -E '^(fastapi|pydantic)==' requirements.txt)` plus the uv form for a
  venv without pip. `AA_PREPUSH_SKIP_PINS=1` skips once and shows a WARN line in the summary, like the other skips.
- **Parametrize determinism lint** (`tests/unit/test_s276_parametrize_determinism_lint.py`): AST only, no import.
  It flags a `uuid1/uuid4`, `time.*` clock, `datetime.now/utcnow/today`, `date.today`, `random.*`, `secrets.*`,
  `os.urandom`/`os.getpid` value that reaches `pytest.mark.parametrize` (values and `ids=`), `pytest.param`, or
  `pytest.fixture(params=, ids=)`, directly or through module / class level names (taint follows assignments in
  source order; a later literal assignment clears it). A seeded `random.Random(n)` is deterministic. A lambda body
  is not import time (it runs inside the test), so it is skipped. No allowlist.

## Changed

- Nine existing unit test modules had such values in parametrize inputs. Most were latent (dict / UUID values get
  index ids, so xdist still collected the same ids), but the lint has no allowlist, so each became a fixed literal:
  `uuid.UUID(int=0x…)` constants, a fixed `CANCELLED_AT` in the view-as cases, a fixed past `exp` in the expired
  Cognito token case. The tests that need a value unique per run still build it inside the test.

## Tradeoffs

- Taint is per name, not per dict key: `list(ROUTES)` over a dict whose values hold a random id is flagged although
  only the keys reach the ids. Fixing the value (a fixed id) was cheaper and clearer than teaching the lint which
  reads are key-only.
- Only fastapi and pydantic are compared (the two that broke the openapi snapshot test twice, S274 and S276), not
  the whole requirements file: a full compare would block on every unrelated local drift.
