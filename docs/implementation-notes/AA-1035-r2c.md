# AA-1035 R2 close-out (S269, lane l2-aa1035-r2c) — AA-CIS-App half

Sources: root ADR 0019 d3–d5, root `docs/audits/2026-11-03-S265-ecosystem-restructure/clarifications.md` section 2
and the role matrix of section 3, root ADR 0006a (A10 / A10b), the S267 and S268 Linear comments on AA-1035. AA-Partner
half: AA-Partner `docs/implementation-notes/AA-1035-r2c.md`. The S268 view-as minors (verify-tenant, BFF DELETE owner
check, offboarding / staff sign-out close sessions, E2E admin own sessions) shipped in #1308 (`AA-1035-s268-followups.md`).

## Decisions
- **The CRM scope relay is a CIS read the CRM makes, not a header CIS adds.** The CIS admin relays the staff member's
  own WORKFORCE access token to `/crm/ops/v1`; the staff member holds that token, so any scope sent with it could be
  forged. CIS serves `tenant.membership.v1` 1.3 `GET /tenant/membership/v1/staff-scope?iss=&sub=&desk_role=`
  (M2M `cis.tenant/read`, the membership feed's own client: no new grant) from its own directory:
  `tenant_scope.desk_scope_of_identity` finds the ACTIVE `shared.admin_users` row by `(cognito_iss, cognito_sub)` and
  answers its book (`shared.staff_tenant_assignment`), support also the pool, by the SAME SQL `require_tenant_scope`
  uses. The role comes from the CRM (it read the token's groups), the row only says who the person is; an unknown or
  inactive identity is scope `none`. The key is `desk_role` (the root contract checker refuses a `role` key).
- **CIS still filters too** (defence in depth): `/admin/platform/crm/*` GETs take `tenant.book.read` (desk roles) and
  `{tenant_id}` reads pass `require_tenant_scope`; the agency list is filtered to `tenant_scope_filter`. Usage and
  entitlements are account reads (`tenant.book.account.read`, customer_success only). Writes stay `tenant.write`.
  The Agencies page opens for the book roles (read-only: the CRM answers `can_write` false); the drawer hides usage,
  features and insights when the role has no account read.
- **Tenant QA own book** (matrix "Tenant QA: customer_success R (own)"): a new capability `tenant_content.book.read`
  (customer_success) on the Content quality lists, details and stats only (`any_of(tenant_content.read,
  tenant_content.book.read)`). The routes add `tenant_id = ANY($n::uuid[])` for a scoped caller; a piece or version
  of another tenant is a 404, the same answer as an unknown id (no probing). Labels, place cards, compliance,
  fallback writes and every write stay `tenant_content.read` / `quality.write`; the drawers hide the label section
  for a role without `quality.write`. Only `/admin/tenant-qa/quality` opens for customer_success (rbac PAGE_RULES).
- **Reviewer alias removed** (CIS 375, contract): the A10 E2E row moves to `content`; `admin_users_email_chk` allows
  the E2E address as `content` only; `admin_users_role_not_alias_chk` keeps the enum value unused (an enum value
  cannot be dropped without a type rewrite). Code: `GROUP_ROLES` has no `cis-reviewer`, `canonical_role` /
  `ROLE_ALIASES` / `CIS_ALIAS_ROLES` are gone, `STAFF_ROLES`, `TENANT_SCOPE`, `ROLE_PERMS`, frontend `StaffRole` and
  role labels drop it. A token with only `cis-reviewer` holds no CIS role (403 `no_cis_group`). The group stays in
  `RETIRED_CIS_GROUPS` so Sync removes a leftover membership.
- **Send again to the kept address** (crm.ops.v1 1.12): `POST .../invitation/send` without `email` relays
  `keep_address: true`. support (`tenant.member.resend`) may only do that (403 with an address); customer_success
  and admin may also name a new address. The Dev E2E admin must always name an E2E mailbox address (403
  `e2e_read_only` without one). `members/access` says which (`send_again_to.same_address` / `new_address`).

## Tradeoffs
- One CRM→CIS call per desk identity per 30 s instead of a signed scope assertion: no new key to run, and the scope
  is always CIS's current one (an assignment removed in CIS stops working in the CRM within 30 s).
- The `reviewer` enum value stays (unused, CHECK-forbidden): dropping an enum value means rewriting the type and every
  column using it; the CHECK gives the same guarantee for a contract migration.
- The notification bell keeps `'reviewer'` in its target-role array: rows written before CIS 363 may still carry it.
