# AA-907 — bump langgraph, drop unused langchain packages and chromadb (S245)

Goal: clear the four `.github/pip-audit-ignore.txt` entries (expiring 2026-11-30 and 2026-12-31)
by fixing the dependencies instead of renewing the ignores.

## Decisions

- **Drop, don't bump, the langchain packages.** `git grep` over every tracked `*.py` file finds no
  import of `langchain`, `langchain_core`, `langchain_community`, `langchain_text_splitters` or
  `langgraph.checkpoint`. The only LLM-framework import in runtime code is
  `from langgraph.graph import StateGraph, END` in `services/content_generation/graph.py` (plus
  `tests/unit/test_aa209_judge_score_persist.py`). So `langchain`, `langchain-community` and
  `langgraph-checkpoint-postgres` are removed from `requirements.txt`. That clears PYSEC-2026-2192
  (langchain 1.2.15) completely. `langchain-core` is no longer a direct requirement: it still
  arrives through langgraph (1.6.12 today).
- **langgraph 1.1.8 -> 1.2.16** (the latest on PyPI, 20/10/2026), pinned like before. It resolves
  `langgraph-sdk` 0.4.8 (PYSEC-2026-4240 is fixed in 0.4.4). An explicit `langgraph-sdk>=0.4.4` floor
  is kept so a later langgraph pin cannot quietly bring the vulnerable SDK back.
- **chromadb removed with its only importer.** `chromadb` is imported only by `shared/rag/client.py`.
  `shared.rag` is imported only by `scripts/seed_chromadb.py` and `scripts/seed_chromadb_data.py`
  (offline seeders). No `importlib`/`__import__`/`pkgutil` use reaches `shared.rag`: the only
  `importlib.import_module` call is `tests/unit/test_s218_hard_code_repair.py`, and it loads
  `services.content_generation.*`. Deleted: `shared/rag/`, both seed scripts and the committed
  `chromadb_data/` store (a local Chroma SQLite and HNSW index, about 340 KB, read only by the seeder).
- **Packages that only arrived transitively were added back explicitly.** A pip freeze diff between
  `origin/main` requirements and the new set found 57 distributions that would go away. Each removed
  distribution was mapped to its import names and grepped:
  - `aiohttp` is imported directly by `api/routers/v1_integrations.py`,
    `services/acp_publish/facebook.py` and `services/acp_s4_blog/cms/wordpress.py`. It used to arrive
    only through langchain-community. Added `aiohttp>=3.14.5` (the version the image has today).
    Without it, 61 unit-test modules failed at collection, and the api would have crashed at import.
  - `uvloop` and `httptools` came from chromadb's `uvicorn[standard]`. uvicorn picks them up
    automatically, so the running api uses them today. Changed `uvicorn>=0.29.0` to
    `uvicorn[standard]>=0.29.0` so the server's event loop and HTTP parser stay the same.
  - No tracked code imports any of the other removed modules (grpc, opentelemetry, kubernetes,
    onnxruntime, tokenizers, huggingface_hub, pydantic_settings, psycopg_pool, tqdm, posthog, ...).

## Changed

- `requirements.txt`: removed `langchain`, `langchain-core`, `langchain-community`,
  `langgraph-checkpoint-postgres` and `chromadb`. Changed `langgraph==1.1.8` to `==1.2.16`. Added
  `langgraph-sdk>=0.4.4` and `aiohttp>=3.14.5`. Changed `uvicorn` to `uvicorn[standard]`.
- `.github/pip-audit-ignore.txt`: the four entries are gone and only the header comments are left.
  `pip_audit_gate.sh` skips comment lines, and `test_repo_ignore_list_is_valid_today` passes on the
  comments-only file.
- Deleted `shared/rag/` (3 files), `scripts/seed_chromadb.py`, `scripts/seed_chromadb_data.py` and
  `chromadb_data/` (5 files).
- `Dockerfile`: rewrote only the comment above the apt build tools. It no longer mentions
  chroma-hnswlib. The packages themselves are unchanged.
- `README.md`: the "legacy variables" line no longer lists Chroma.

## Tradeoffs

- The Dockerfile keeps `g++`/`cmake`/`build-essential`. They existed for chroma-hnswlib and are
  probably no longer needed, because every remaining dependency ships a manylinux wheel for
  python 3.12. But this was not proven with a Docker build here (no Docker in this lane), and a
  smaller image is not part of this issue. Trimming them is a separate, low-value follow-up.
- `langgraph` stays pinned exactly (`==`) and is not a floor: a minor langgraph bump changes the
  graph runtime under S1/T2, so it should stay a deliberate change with a regression run.
- `.github/workflows/ci.yml` still has a historic comment that mentions chromadb (in the Trivy step).
  It is left alone so that this PR does not touch a workflow file.

## Should know

- Local evidence (python 3.12.3, fresh venv from the new `requirements.txt`):
  `pip check` clean. `bash .github/scripts/pip_audit_gate.sh requirements.txt` with the empty ignore
  list gives "No known vulnerabilities found" (pip-audit 2.10.1). `pytest tests/unit/` gives 8664
  passed (coverage 85.8%). `pytest tests/acp/` gives 14 passed.
  `tests/integration/test_compiled_graph_state_propagation.py` gives 6 passed: it drives
  `_rewrite_tour` -> compiled graph -> `graph.astream(stream_mode="updates")` on langgraph 1.2.16.
  flake8 (CI flags) and `check_resource_ids.py` are clean.
- `build_graph()`, `build_graph(t2_drafts=True)` and `build_revalidation_graph()` compile on 1.2.16
  with the same node sets as before.
- Version changes the image will see: langgraph 1.1.8 -> 1.2.16, langgraph-prebuilt 1.0.13 -> 1.1.1,
  langgraph-sdk 0.3.15 -> 0.4.8, websockets 17.3 -> 16.1.1 (langgraph-sdk 0.4.x caps it below 17;
  nothing in the repo imports websockets).
- The Done-when still needs the 3-tour S1 regression on Dev after deploy (job status, quality
  score, cost from `shared.llm_call_log` by `job_id`). A normal `s1_rewrite` job logs its pipeline
  stages (for example `s1_generate`), not `adhoc_*`. The job-attributed rows (`llm_call_log.job_id`)
  are the cost evidence.
- Infra follow-up (not in this repo): AA-CIS-Infra still provisions `modules/efs` with a `chromadb`
  access point ("ChromaDB + LangGraph SqliteSaver persistence"). Nothing in CIS uses Chroma or a
  LangGraph checkpointer now, so that EFS is a candidate for removal after checking which task
  definitions still mount it.
