# AA-814 — Facts Entry API + UI (S257)

`acp_shared.facts` (CIS 145, AA-529) had a read path (T9 seed) and no write path: rows were inserted by SQL.
This change adds the write paths, the fields they need, and tenant-over-platform precedence in the writer.

The old AA-529 work was merged (#319, migration 145 + `services/acp_content_writing/facts.py`); there was no unmerged
AA-529 branch to recover. Its read path is kept and extended, not replaced.

## Decisions

- **Migration 302 (separate PR, then the Infra byte copy):** `kind` (NOT NULL DEFAULT `other`, CHECK
  `price | season | visa_entry | transfer_time | booking_terms | other`), `valid_until` (DATE, CHECK not before
  `stated_on`), `updated_by` (TEXT), and `GRANT DELETE ... TO aa_app_user`. Policies unchanged: CIS 229
  `tenant_isolation` (FOR ALL, own scope='tenant' rows) is the only aa_app_user policy that admits a DELETE;
  `facts_platform_read` is FOR SELECT. Guard 2 of 302 checks exactly that before the grant.
- **Field names:** the issue's "subject / value / source" are the existing columns `title / body / provenance`.
  No rename: the T9 read path, the erasure inventory and the gates already use them. The UI labels them Subject /
  Fact / Source.
- **Subject (precedence key):** `(kind, title, country)`, case- and whitespace-insensitive
  (`facts_store.subject_key`). In `facts.pick_facts`, a tenant fact on a subject drops the platform facts on that
  subject; within one scope the latest `stated_on`, then the latest edit, wins. The input order of the kept facts is
  unchanged, so a tenant with no overrides gets the same seed as before.
- **Expiry:** the writer SQL drops facts with `valid_until < current_date`. The tenant list still shows the tenant's
  own expired facts (flag `expired`); the platform list it sees is valid facts only.
- **Seed shows the source:** each entry is now `[Fact id=<id>]` / `<title>: <body>` / `Source: <provenance>; agency
  fact|platform fact`. The head line is unchanged on purpose: `claim_rules._FACT_HEAD_RE`, `hygiene._SEED_LABEL_RE`,
  `sentence_repair` and `service._FACT_BLOCK_RE` parse it. The Source line joins the fact body in claim_rules'
  numbered SOURCE (it can support a claim about where the price comes from; it adds no new claim).
- **Admin API** `/admin/facts` (platform scope only): list, create, get, patch, delete, history. Reads open to every
  staff role (content.read); writes `quality.write` (admin only), same capability as the AA-774 place-card fact
  edits. Audit in the same transaction: `PlatformAuditAction.FACT_*` (`fact.created|updated|deleted`), tenant_id
  NULL, actor `admin:<x-admin-user-id>`, details `after` / `changes {field: [before, after]}` / `before`.
- **Tenant API** `/v1/facts`: list (own + valid platform facts, `overridden_by` on a platform fact the tenant
  replaces), create, patch, delete. Tenant pool (`acquire_scoped_conn`, new flag `aa814:facts_pool`, fail closed),
  and every statement still filters `scope = 'tenant' AND tenant_id = <token sub>`. Body has `extra="forbid"`: a
  `tenant_id` or `scope` in the body is a 422. Another tenant's fact / a platform fact is a 404 on PATCH / DELETE.
  Viewer: read only (api/middleware/tenant_role.py refuses every non-GET under /v1/); editor and owner write.
  Audit `TenantAuditAction.FACT_*` on the main pool after the tenant transaction (AA-859 MAIN exception:
  aa_app_user has no grant on audit_log), best effort, like the integration disconnect.
- **Optimistic concurrency:** PATCH takes `expected_updated_at` (the row's `updated_at` as loaded); a mismatch is 409.
  Same idea as AA-774's `expected_text`.
- **Tenant response models** (`TenantFact`, `TenantFactList`, `TenantFactDeleted`): public `/v1/*` routes must
  declare a response model (test_aa899 untyped-route snapshot); the model also drops `tenant_id` / `updated_by`.
  `docs/api/openapi.json` regenerated with the pinned fastapi 0.161.1 / pydantic 2.14.1 (only the 5 fact paths and
  5 schemas are new).
- **Tenant activity trail:** `fact.created|updated|deleted` are added to `TENANT_VISIBLE_ACTIONS` (category Content,
  "Added / Edited / Deleted a fact"); the audit details carry the fact title at the top level and `detail_text`
  shows it (the tenant's own text). Platform fact rows have tenant_id NULL and never reach a tenant's trail.
- **Limits:** title 200, body 1200, source 500, country 80 characters; at most 200 own facts per tenant.

## Changed

- T2 is not wired to facts in this slice: T2 has no facts input today (no seed block, no grounding source), so adding
  one is a T2 prompt + QA change of its own. The precedence function is shared and ready for it.
- No Excel import (out of scope per the issue).
- Admin page lists platform facts only; tenant facts are tenant data and stay in Content studio.

- Precedence also collapses two platform facts with the same subject (same kind, title, country) to the latest
  stated one. Today every row is kind `other`, so two existing platform facts with an identical title and country
  would show once; none expected on Dev (hand-written rows), say so if the seed loses one.

## Tradeoffs

- Subject = exact (normalised) title, not a fuzzy match: predictable, and the Content studio "Use my own" action
  copies kind, title and country from the platform fact, so overriding needs no typing of the key.
- Country is part of the key: a tenant fact for "any country" does not hide a platform fact scoped to Laos.
- Tenant audit is not in the same transaction as the write (different pools). A lost audit row is logged
  (`tenant_fact_audit_failed`); the fact write stands.
