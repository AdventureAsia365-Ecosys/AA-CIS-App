# AA-814 — Facts Entry API + UI (S257)

`acp_shared.facts` (CIS 145, AA-529) had a read path (T9 seed) and no write path: rows were inserted by SQL.
This change adds the write paths, the fields they need, and tenant-over-platform precedence in the writer.

The old AA-529 work was merged (#319, migration 145 + `services/acp_content_writing/facts.py`); there was no unmerged
AA-529 branch to recover. Its read path is kept and extended, not replaced.

## Decisions

- **Migration 302 (separate PR, then the Infra byte copy):** `kind` (NOT NULL DEFAULT `other`, CHECK
  `price | season | visa_entry | transfer_time | booking_terms | other`), `valid_until` (DATE, CHECK not before
  `stated_on`), `updated_by` (TEXT), and `GRANT DELETE ... TO aa_app_user`. Policies unchanged: CIS 229
  `tenant_isolation` (FOR ALL, own scope='tenant' rows) is the only aa_app_user policy that admits a DELETE;
  `facts_platform_read` is FOR SELECT. Guard 2 of 302 checks exactly that before the grant.
- **Field names:** the issue's "subject / value / source" are the existing columns `title / body / provenance`.
  No rename: the T9 read path, the erasure inventory and the gates already use them. The UI labels them Subject /
  Fact / Source.
- **Subject (precedence key):** `(kind, title, country)`, case- and whitespace-insensitive
  (`facts_store.subject_key`). In `facts.pick_facts`, a tenant fact on a subject drops the platform facts on that
  subject; within one scope the latest `stated_on`, then the latest edit, wins. The input order of the kept facts is
  unchanged, so a tenant with no overrides gets the same seed as before.
- **Expiry:** the writer SQL drops facts with `valid_until < current_date`. The tenant list still shows the tenant's
  own expired facts (flag `expired`); the platform list it sees is valid facts only.
- **Seed shows the source:** each entry is now `[Fact id=<id>]` / `<title>: <body>` / `Source: <provenance>; agency
  fact|platform fact`. The head line is unchanged on purpose: `claim_rules._FACT_HEAD_RE`, `hygiene._SEED_LABEL_RE`,
  `sentence_repair` and `service._FACT_BLOCK_RE` parse it. The Source line joins the fact body in claim_rules'
  numbered SOURCE (it can support a claim about where the price comes from; it adds no new claim).
- **Admin API** `/admin/facts` (platform scope only): list, create, get, patch, delete, history. Reads open to every
  staff role (content.read); writes `quality.write` (admin only), same capability as the AA-774 place-card fact
  edits. Audit in the same transaction: `PlatformAuditAction.FACT_*` (`fact.created|updated|deleted`), tenant_id
  NULL, actor `admin:<x-admin-user-id>`, details `after` / `changes {field: [before, after]}` / `before`.
- **Tenant API** `/v1/facts`: list (own + valid platform facts, `overridden_by` on a platform fact the tenant
  replaces), create, patch, delete. Tenant pool (`acquire_scoped_conn`, new flag `aa814:facts_pool`, fail closed),
  and every statement still filters `scope = 'tenant' AND tenant_id = <token sub>`. Body has `extra="forbid"`: a
  `tenant_id` or `scope` in the body is a 422. Another tenant's fact / a platform fact is a 404 on PATCH / DELETE.
  Viewer: read only (api/middleware/tenant_role.py refuses every non-GET under /v1/); editor and owner write.
  Audit `TenantAuditAction.FACT_*` on the main pool after the tenant transaction (AA-859 MAIN exception:
  aa_app_user has no grant on audit_log), best effort, like the integration disconnect.
- **Optimistic concurrency:** PATCH takes `expected_updated_at` (the row's `updated_at` as loaded); a mismatch is 409.
  Same idea as AA-774's `expected_text`.
- **Tenant response models** (`TenantFact`, `TenantFactList`, `TenantFactDeleted`): public `/v1/*` routes must
  declare a response model (test_aa899 untyped-route snapshot); the model also drops `tenant_id` / `updated_by`.
  `docs/api/openapi.json` regenerated with the pinned fastapi 0.161.1 / pydantic 2.14.1 (only the 5 fact paths and
  5 schemas are new).
- **Tenant activity trail:** `fact.created|updated|deleted` are added to `TENANT_VISIBLE_ACTIONS` (category Content,
  "Added / Edited / Deleted a fact"); the audit details carry the fact title at the top level and `detail_text`
  shows it (the tenant's own text). Platform fact rows have tenant_id NULL and never reach a tenant's trail.
- **Limits:** title 200, body 1200, source 500, country 80 characters; at most 200 own facts per tenant.
- **Seed budget (review finding):** tenants now write rows that reach every T9 prompt, so the facts block is capped
  in `facts.budget_facts` (called by `fetch_facts_for_writing` after `pick_facts`): at most `SEED_MAX_CHARS` 16,000
  characters (about 4k input tokens, separators counted as `format_facts_block` renders them) and `SEED_MAX_FACTS`
  48 entries. Order of preference: a fact scoped to one country (the query already matched it to the piece) before an
  any-country fact, then the tenant's own fact, then the latest stated / edited. A fact too long for the room left is
  skipped and a shorter one may still fit. The kept facts keep their input order, so a seed under the budget is
  byte-identical to before. Unbudgeted, a tenant at the limits (200 facts x ~1.9k characters) added ~380 KB per call.
- **Cost trace:** `resolve_facts` logs `t9_facts_seed` (request_id, tenant_id, facts, tenant_facts, chars) on every
  T9 write; `fetch_facts_for_writing` logs `t9_facts_budget_dropped` (offered / kept / dropped / chars) when the
  budget drops facts. Join on request_id to the T9 rows in `shared.llm_call_log`.

- **Admin page** `/admin/facts` (CIS Content › Assets › Facts): kit DataTable (kind filter, search, show expired),
  create modal, drawer to edit / delete with the audit history, English + Vietnamese (`messages.ts`, nav label).
  Every staff role reads (PAGE_RULES ALL_STAFF, backend reads open); writes are hidden unless `can(role,
  "quality.write")`, refused by the BFF (`API_WRITE_RULES` prefix `facts`, admin only) and by the backend. Saves send
  only the changed fields plus `expected_updated_at`; a 409 tells the admin to reopen. Helpers in `lib/facts.ts`
  (dependency-free, `lib/facts.test.mjs`). The form reuses the AA content editor's `Field` / `fieldStyle`.
- **Smoke:** `/admin/facts` is in the UI smoke page list (every role reads). It calls `/api/admin/facts`, so the
  staff smoke on Production needs the backend of this PR deployed (same PR: ECS deploy + Vercel).

## Changed

- T2 is not wired to facts in this slice: T2 has no facts input today (no seed block, no grounding source), so adding
  one is a T2 prompt + QA change of its own. The precedence function is shared and ready for it.
- No Excel import (out of scope per the issue).
- Admin page lists platform facts only; tenant facts are tenant data and stay in Content studio.

- Precedence also collapses two platform facts with the same subject (same kind, title, country) to the latest
  stated one. Today every row is kind `other`, so two existing platform facts with an identical title and country
  would show once; none expected on Dev (hand-written rows), say so if the seed loses one.

## Tradeoffs

- Subject = exact (normalised) title, not a fuzzy match: predictable, and the Content studio "Use my own" action
  copies kind, title and country from the platform fact, so overriding needs no typing of the key.
- Country is part of the key: a tenant fact for "any country" does not hide a platform fact scoped to Laos.
- Seed budget by characters, not tokens: no tokenizer on the read path; 16,000 characters sits well above what the
  ~60 hand-written platform facts give one country today, so the cap should only bite on tenant floods (watch
  `t9_facts_budget_dropped` in the API/worker logs). A tenant with many any-country facts can crowd out
  any-country platform facts in its own seed (its own facts rank first); country facts are kept first either way.
- Tenant audit is not in the same transaction as the write (different pools). A lost audit row is logged
  (`tenant_fact_audit_failed`); the fact write stands.

## Follow-ups (S258)

Three items left open by the first slice: T2 was not wired to facts, the seed `Source:` line was not in the leak /
label checks, and the admin fact writes were never exercised live.

### Decisions

- **T2 reads facts behind its own switch, `T2_FACTS` (worker env, default off), not `aa814:facts_pool`.** That Redis
  flag routes the `/v1/facts` routes between the tenant pool and the main pool; a missing key means ON, so gating a
  writer prompt on it would turn T2 facts on at deploy with no eval (LLM providers are blocked this session, and a
  writer prompt change needs a panel run: lessons "Pipeline", S246/S252). Same pattern as `T3_BACKGROUND_FACTS` /
  `T9_READER_CHECKLIST_MODE`: off = every T2 prompt byte-identical.
- **One read for both writers.** `t2_facts.with_facts` calls `facts.fetch_facts_for_writing` (platform + the writing
  tenant's own, expiry in SQL, `pick_facts` precedence, `budget_facts`) with the tour's `raw_tours.country`. A tour
  with no country passes `""`, not `None`: the writer query's `$2 IS NULL` branch would offer every country's facts.
- **The facts ride on the T2 source dict (`tour_dict["facts"]`).** That dict is what the writer prompt, the T3
  grounding baseline (`[str(v) for v in tour_dict.values()]`), the AA-795 brand-claim check and the T3 repair rounds
  all read, so one key reaches all of them and a repair round never drops the facts. A price copied from a fact is
  therefore supported in T3, not a novel number.
- **T2 block format: `- <title>: <body>` lines, no `[Fact id=…]` head and no `Source:` line.** T2 has no citations;
  without ids and labels nothing of the seed format can leak into a tour page, and a fact id's hex digits never enter
  the grounding baseline as numbers. Placed with the tour data, before PER-DAY SOURCE LENGTH; T2 user prompt only
  (`build_rewrite_prompt(facts=…)` ignores it for A1).
- **Fail open on the facts read** (`t2_facts_failed` log, `job.result.facts.error`), unlike the brand pack (AA-741):
  facts are optional input; a rewrite without them is the pre-AA-814 behaviour.
- **`Source:` label:** `hygiene.LEAK_RE` (F13 leak, blocking) now matches a sentence that starts with `Source:` and
  the owner tags `agency fact` / `platform fact` anywhere; `_leak_fix` deletes a sentence that is a copied
  `Source:` line (it says nothing to a reader). `_SEED_LABEL_RE` strips `Source:` and the owner tags, so they are
  not seed words. Two more places read the seed's Facts block line by line and now skip the `Source:` line:
  `quality_gates.unused_source_facts` (it offered the line to the FAQ regeneration as "a fact to tell", which is how
  it would leak) and `reader_checklist.fact_entries` (round 10 quoted it word for word to the writer).

### Changed

- New `services/content_generation/t2_facts.py`; `prompts.build_rewrite_prompt(facts=)` + `_render_t2_facts_block`;
  `batch_prompt.build_s1_user_prompt` passes `tour["facts"]` on a T2 rewrite; `t2_rewrite_job.run` calls
  `with_facts` after `_prepare` and records `facts` in `job.result` (`{"mode": "off"}` by default).
- Hygiene / quality_gates / reader_checklist as above. CONTEXT.md (Facts Entry, tenant scope) says which writers
  read facts and how.
- Live admin probe: not code in this repo. The orchestrator runs a script in the api container that calls
  `/admin/facts` on `127.0.0.1:8000` with the container's `ADMIN_SECRET` + `x-admin-role` (the BFF's headers), on an
  expired fact for a fake country, and deletes it (root `.tmp-session/S258/aa814/`, evidence to the root audits).

### Tradeoffs

- Carrying facts in the source dict instead of a new state field: fewer signatures to thread (job, `_rewrite_tour`,
  `initial_state_for`, `run_t3_qa_gate`), and the grounding baseline gets the facts for free. The cost: any future
  code that iterates every source value sees the facts too (today that is exactly the grounding readers).
- `^\W*source:` in LEAK_RE also flags a writer's own sentence-initial "Source: …" attribution. No writer is asked to
  write one; the only `Source:` in any writer input is the Facts label.

### Should know

- `T2_FACTS=on` is an AA-CIS-Infra worker task-definition change; do it after a T2 eval run with facts (golden set
  T2 items, panel on fidelity + voice), not before.
- With the switch on, three readers still rebuild the T2 source without facts: the admin sentence edit / flag check
  on a tenant version (`admin_content_quality`, `source_tour_dict(row)`), the WM-20 release-0 replay
  (`writing_memory/shadow.py`) and the T2 eval writer (`writing_memory/eval_writers.py`). A sentence that quotes a
  fact can be flagged there as unsupported. Wire them (or store the facts used in `generation_meta`) before the
  switch goes on.
- `S1_STRUCTURED_FACTS` (A1 per-day facts, default off) is not excluded on T2 by `generate_node`; its rule "numbers
  only from SOURCE FACTS BY DAY" would contradict the FACTS block if both were on for a T2 run.
- Tests: `tests/unit/test_aa814_followups.py` (switch, read, country, fail-open, line format, prompt placement and
  byte identity for T2 off and A1, T3 grounding with a fact price, LEAK_RE hits and misses, autofix delete,
  find_issues leak, seed words, unused facts, reader checklist entries).
