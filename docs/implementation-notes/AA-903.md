# AA-903: skip the Vercel deploy job on Dependabot runs

## Decisions

- **Job-level `if:` on `github.actor != 'dependabot[bot]'`**, combined with the existing fork-PR guard. GitHub
  withholds Actions secrets exactly when the run was triggered by Dependabot, and `github.actor` stays
  `dependabot[bot]` on a re-run of such a run, so the condition matches "no `VERCEL_TOKEN`" one to one. It covers
  `pull_request`, `push` and a dispatch alike (the workflows have no `pull_request_target` trigger).
- **Not `github.event.pull_request.user.login`** (the PR author): a human who pushes a commit onto a Dependabot
  branch runs with secrets, and that run should still deploy a preview. The author check would skip it for nothing.
- **No Dependabot secret for Vercel** (issue scope): a dependency update never runs with deploy credentials.
- The `Plan` step keeps failing red when `VERCEL_TOKEN` is missing on a normal run (a missing token must stay
  visible); only Dependabot runs are skipped.

## Changed

- `.github/workflows/vercel-deploy.yml` and `.github/workflows/vercel-deploy-portal.yml` (job `deploy`; the `smoke` jobs that call `ui-smoke.yml` / `ui-smoke-portal.yml` `needs: deploy` without `always()`, so they skip with it), `.github/dependabot.yml` comment.

## Tradeoffs

- A Dependabot PR gets no preview. That was already true (the job failed); now the check is neutral instead of red.
  For a frontend dependency bump that needs a look, push the same change from a normal branch.

## Should know

- None of these jobs is a required check (branch protection on `main` requires Lint, Security Audit, Unit Tests, Integration Tests, Docker Build Check; the only ruleset blocks
  force-push and deletion), and the required jobs run on every PR without secrets, so Dependabot PRs stay mergeable.
  A skipped job reports as "skipped", which GitHub treats as passing.
- This PR edits the workflow file, which is in its own path filter, so the PR itself deploys a normal preview:
  that run is the "a normal PR still deploys" evidence.
- The "Dependabot PR shows Vercel deploy as skipped" evidence needs the next Dependabot PR after merge (or
  `@dependabot recreate` on an open one).
- **Review fix (S244):** the skip applies to `pull_request` runs only. The first version also skipped a `push`
  to main whose actor is `dependabot[bot]` (Dependabot merging its own PR), which would turn a production deploy
  that cannot run into a silent green skip, against this workflow's "fail red rather than hide it" rule.
