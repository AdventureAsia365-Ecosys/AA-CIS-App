# AA-690 — A0 ingest Jev gates (part 1: A0-1, A0-3, A0-4)

Design: `docs/architecture/at-series-v2-design.md` §4.0.

## Decisions
- **One call per row.** `services/ingestion/jev_gates.py` asks all three questions about the same state (name, country, duration, summary ≤ 600 chars, itinerary ≤ 2,500 chars), 8 rows at a time. Only rows with itinerary text are asked; empty ones are already dropped by AA-604.
  - `a0_row_kind` (choice): multi_day_tour / day_tour / poi_or_attraction / accommodation / transfer_or_service / other.
  - `a0_itinerary_usable` (noul).
  - `a0_country` (choice over the 21 master countries + other): asked only when the alias resolver found no country.
- **Same function in preview and commit.**
  - The Upload preview (`admin_pipeline` dry_run) uses the app pool.
  - Commit (`process_file`) uses `assess_rows_standalone()` with a small private pool, because that path has no app pool.
- **Effects (enforce + confident only):**
  - a non-tour kind → drop `not_a_tour`;
  - itinerary reject → drop `thin_itinerary`;
  - a confident country pick (not "other") fills an empty country.
- **Design change: `thin_itinerary` drops the row** instead of landing it with a flag. Landing it with an S1 exclusion would need a new `raw_tours` column. A confident Jev "no" plus the preview message is enough; the admin can re-upload a fixed row.
- **Existing tours are never dropped by Jev.** A row that matches an existing tour still goes to `upload_staging` for the human decision (the check order in commit mirrors the preview).
- **Shadow (today):** nothing changes. The preview shows amber notes under a ready row when Jev leans clearly (non-tour kind ≥ 0.6, itinerary p ≤ 0.3, a likely country), and every verdict is logged for calibration.

## Part 2 — A0-2 near-duplicates (S206)

### Measured first (Dev, 761 live raw_tours, same provider + same country)
- Name word-set ≥ 0.8 **and** itinerary word-set ≥ 0.9 → all the same product uploaded twice (case,
  "days"/"DAYS", a stray character slipped past the exact `lower(trim(name))` + provider check).
- Itinerary alike but name different (Golden Triangle 4 vs 5 days), or name alike but itinerary
  different (Classic Laos 6 vs 10 days) → variants: real, separate products.
- Different providers with the same name (Annapurna Base Camp Trek by two operators) → two products.
- The rule below, run over the 756 active rows in ingest order: **20 later copies**, all real
  duplicates (2 of them published: LUXURIOUS LAOS `b0e111a9`, Kang Yatse 2 `0338c948`).

### Decisions (Nghiệp, S206)
- A duplicate is **skipped on Commit** (reason `duplicate_of_existing` in ingest_details and the
  Upload preview). No `upload_staging` row and no manual review step. A variant only adds a note
  to the preview. Different providers are never compared.
- **No Jev**: the deterministic rule separates the cases cleanly on real data (design §4.0 had a
  Jev Noul "same bookable product?"; not needed).
- Rule (`services/ingestion/near_duplicate.py`): same normalised provider + same country + name
  word-set ≥ 0.8 + itinerary word-set ≥ 0.9 + same day count (when both give one).

### Tradeoffs
- One `raw_tours` query per provider per file (cached in `Checker`); rows accepted earlier in the
  same file are remembered, so in-file near-duplicates are caught too.
- The exact match still goes to `upload_staging` as before (unchanged path).

- The Upload page badge also gets labels for `not_a_tour` / `thin_itinerary`, which showed as
  "Missing Fields" before.
