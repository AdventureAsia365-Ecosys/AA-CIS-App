# AA-911 C1: retire the CIS to Booking bridge, staff sign-in on the CIS Preview host

Branch `refactor/aa-911-retire-booking-bridge`. Root ADR 0006a A11 holds the design. Deploy this only AFTER the
AA-Booking bridge removal (B2) is deployed and the real-token replay against Booking was recorded (Done-when line
2, Booking half). The Cognito E2E change is the separate PR C0 (`AA-911-e2e.md`).

## Decisions

- **Removed:** `POST /auth/booking-token`, `GET /auth/.well-known/jwks.json`, `_staff_session_token`,
  `_BOOKING_JWKS_CACHE_CONTROL`, `api/core/booking_jwt.py`, `BookingTokenResponse`, `staff_authz.NO_BOOKING_ROLES`.
- **Kept `_load_active_staff`**: `/auth/verify-admin` still uses it through `_current_staff` (legacy HS256 path),
  and `tests/integration/test_aa816_staff_identity_lookup.py` covers it. Its docstring no longer mentions Booking.
- **Deleted tests** `tests/unit/test_aa680_booking_jwt.py` and `tests/integration/test_aa680_booking_staff_lookup.py`
  (the second only tested `_load_active_staff`, which the aa816 integration test still covers). Trimmed the viewer
  booking-token test, the aa854 docstring and the two public-route allowlist entries.
- **New `tests/unit/test_aa911_bridge_gone.py`**: both paths through the full app (all middleware) answer 404/405,
  never 401, with and without a staff session; the routes and the module are gone.
- **CIS Preview host `aa-cis-preview.lumiguides.it.com`** (`frontend/lib/cognito.ts`): cis-admin origins follow
  `VERCEL_ENV` (production build → production host, preview build → Preview host, `next dev` → all plus
  localhost; unset → production, as before). Break-glass stays production-only.
- **No legacy password login on the Preview host**: `/login` hides the form there and BFF `POST /api/auth/login`
  answers 404 there (`isPreviewSignInHost`). Per-deployment `*.vercel.app` previews keep the flag-driven form for
  the viewer UI smoke (AA-816 S2 decides its replacement).
- **`X-Robots-Tag: noindex, nofollow`** on preview builds (`next.config.ts` `headers()`).
- **Vercel Deploy workflow**: same opt-in alias design as AA-Booking B1: job `preview-alias` (PR label
  `preview-signin`, or a dispatch from `main` with `alias_only_url`; Vercel REST API check: this project, not
  production, READY; global concurrency group). `labeled` is a trigger; a run for another label is skipped and
  has a throw-away concurrency group. The alias job posts its own marker comment (`<!-- preview-signin-alias -->`)
  instead of restructuring the existing preview comment step. UI smoke keeps the per-deployment URL.
- **Audit (before publishing the alias):** every BFF route that attaches `X-Admin-Secret` calls `requireAdmin()`
  first: `app/api/admin/[...path]`, `app/api/pipeline/[...path]`, `app/api/tenant/[...path]`,
  `app/api/tenant/pipeline/brand-identity`, `app/api/tour-full/[id]` (grep 21/10/2026). `app/admin/api-docs/page.tsx`
  only mentions the header in a comment.

## Changed

- Plan item "`_load_active_staff` (if unused elsewhere)": it is used elsewhere, so it stays.
- Migration 249's comment still names `/auth/booking-token` (migrations are immutable).

## Tradeoffs

- A Cognito session on the Preview host carries the user's real role (a verified Bearer), not the C9 viewer cap.
  Recorded in ADR A11; the host is opt-in and points at one preview at a time.
- `BOOKING_JWT_SECRET_NAME` is no longer read; no task definition sets it (grep Infra 21/10/2026).
