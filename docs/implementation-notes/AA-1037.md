# AA-1037 R4 slice 1 (CIS part): Booking's billing read and the billing tick (S269, lane l8)

The Booking side (tables, jobs, pages) is in AA-Booking `docs/implementation-notes/AA-1037.md`. Root ADR 0019 d1 / d9.

## Decisions

- **CIS 377 `catalog.v_tenant_billing_v1`** (contract, catalog recipe like 357): one row per tenant and subscription with
  the plan price columns and the bill-to fields. Column-level grants to `catalog_owner` (never
  `tenant_subscription.billing_ref`); SELECT to `booking` only. Contract `tenant.entitlements.v1` 1.3 (root file first,
  CIS copy byte for byte, SHA pin updated).
- **`tenant_billing_tick`** mirrors `tenant_account_tick` (hourly, sampler part, env switch, not deploy-gate exempt,
  capacity line None). One transaction per tenant, `aa.actor` = the job, so the CIS 354 triggers write the account
  events with the job as actor.
- **Moves** (`billing.decide`, pure): warn -> `past_due` (the existing grace state) + a daily bell; past_due ->
  `suspended` / `billing`; ok -> a billing suspension is lifted (`active` when the content subscription is active, else
  `past_due`), a `past_due` account whose content subscription is active again -> `active`. Compliance, security and
  tenant-request suspensions are never lifted by the tick.
- **paid_through** only moves forward and only on live subscriptions; `ok` + paid through today turns a `past_due`
  subscription `active` (the same column the trial-end rule reads).
- **Dev guard**: on `ENVIRONMENT=dev` only `kind = demo` tenants move (the pilot agency and older real rows are
  `skipped_real`); `internal` never.

## Changed

- New notification event types `tenant.billing.overdue|suspended|restored` (roles tenant, admin, finance). The tenant
  portal shows them through its generic bell row; a dedicated wording is a follow-up in AA-Partner.

## Tradeoffs

- No audit_log row per move: the account event feed (`shared.tenant_account_event`, actor = the job) is the record.
