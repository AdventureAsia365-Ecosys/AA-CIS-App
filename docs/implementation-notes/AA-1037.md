# AA-1037 R4 slice 1 (CIS part): Booking's billing read and the billing tick (S269, lane l8)

The Booking side (tables, jobs, pages) is in AA-Booking `docs/implementation-notes/AA-1037.md`. Root ADR 0019 d1 / d9.

## Decisions

- **CIS 377 `catalog.v_tenant_billing_v1`** (contract, catalog recipe like 357): one row per tenant and subscription with
  the plan price columns and the bill-to fields. Column-level grants to `catalog_owner` (never
  `tenant_subscription.billing_ref`); SELECT to `booking` only. Contract `tenant.entitlements.v1` 1.3 (root file first,
  CIS copy byte for byte, SHA pin updated).
- **`tenant_billing_tick`** mirrors `tenant_account_tick` (hourly, sampler part, env switch, not deploy-gate exempt,
  capacity line None). One transaction per tenant, `aa.actor` = the job, so the CIS 354 triggers write the account
  events with the job as actor.
- **Moves** (`billing.decide`, pure): warn -> `past_due` (the existing grace state) + a daily bell; past_due ->
  `suspended` / `billing`; ok -> a billing suspension is lifted (`active` when the content subscription is active, else
  `past_due`), a `past_due` account whose content subscription is active again -> `active`. Compliance, security and
  tenant-request suspensions are never lifted by the tick.
- **paid_through** only moves forward and only on live subscriptions; `ok` + paid through today turns a `past_due`
  subscription `active` (the same column the trial-end rule reads).
- **Dev guard**: on `ENVIRONMENT=dev` only `kind = demo` tenants move (the pilot agency and older real rows are
  `skipped_real`); `internal` never.

## Changed

- New notification event types `tenant.billing.overdue|suspended|restored` (roles tenant, admin, finance). The tenant
  portal shows them through its generic bell row; a dedicated wording is a follow-up in AA-Partner.

## Tradeoffs

- No audit_log row per move: the account event feed (`shared.tenant_account_event`, actor = the job) is the record.

## Should know

  merged on 05/11 (renamed file and test, RAISE texts, registry row, conftest skip, contract mention, Booking stub).
  Renumber again at merge if main moves (`git grep '377_'`, `git grep "'377'"`, the Booking test stub comment).

- The tick reads Booking's view with the main pool (`cis_app`): it needs bk-042 applied (grant); before that it answers
  `skipped`.

# AA-1037 lane "CIS Tenant 360 billing + Trade nav" (S270)

Root ADR 0019 d9 "Screens now": a Trade group in the AA Admin nav and a read-only Booking billing view in Tenant 360.

## Decisions

- **Route** `GET /admin/tenants/{tenant_id}/booking-billing` (`api/routers/admin_tenant360.py`, read in
  `services/tenant_account/billing.tenant_snapshot`). POLICY is `_TENANT_BILLING_READ`, the rule of the existing
  Billing / Subscription reads (tenant.read | tenant.book.account.read | billing.read) plus `TENANT_SCOPED`: admin and
  finance on every tenant, customer_success on its book only (403 "Tenant outside your scope" otherwise, also for an
  unknown id), never support or the content roles. billing.read alone would leave customer_success out (it does not
  hold it, lib/rbac.ts ROLE_PERMS), while the Billing tab shows to it.
- **Answer**: `available`, `booking` (the view row: status, oldest_overdue_days, overdue_invoices, overdue_amount as
  {ISO code: decimal string}, paid_through, warn/suspend days; null when Booking has no row), `account`
  (account_status, suspend_reason) and `subscriptions` (live ones: product, status, paid_through). No invoice line,
  bill-to, billing_ref or person. The view is read last, so UndefinedTable / InsufficientPrivilege / InvalidSchemaName
  give `available: false` with the CIS side still filled (same fail-soft set as the tick). No CIS migration: `cis_app`
  has SELECT on the view since bk-042.
- **Amounts** keep Booking's scale: the jsonb text is parsed with `parse_float=Decimal` (240.50 stays "240.50"); keys
  that are not 3-letter codes and non-finite amounts are dropped; the screen formats with the kit `Money`, never
  computes.
- **UI: a section, not a tab** (the smaller diff): `Tenant360BookingBilling` sits at the top of the existing Billing
  tab, above the AA-666 meters; the meters stay where they are. Not shown on the AA internal tenant (no agency
  invoices). "Open in Booking" opens Booking admin's `/agency-billing?tab=invoices&tenant=<id>` in a new tab (like the
  other "Open in Booking" links of CIS, so the Tenant 360 page stays open); the URL is built only by
  `lib/apps.ts bookingAgencyInvoicesUrl`.
- **Trade nav**: an eighth group, placed before Platform (the seven d13 groups keep their order). Items `external:
  "booking"` with `href` = the path in Booking admin (`/`, `/agency-billing`, `/pricing/agency-tiers`, `/b2b-desk`);
  `adminNav.tsx` builds the URL with `lib/apps.ts appPageUrl` (it refuses anything that is not an app path), opens it
  in the same tab (`window.location.assign`, the ADR's "app switcher"), and never treats it as the current page
  (sidebar active state, breadcrumb, BottomNav). The ⌘K palette lists them and follows them the same way.
- **Trade visibility** (proposal taken): a capability already in the CIS role, `billing.read` or
  `tenant.book.account.read` (`TRADE_CAPABILITIES`, `lib/rbac.ts canSeeNavItem`) = admin, finance, customer_success.
  The Booking grant (`shared.staff_app_grant`) is not in the CIS session, so it is not used; a person without a Booking
  grant gets Booking's own refusal page.

## Changed

- `lib/apps.ts`: the comment "CIS never reads the booking schema" now names the contract-view exceptions (bk-017,
  bk-023, bk-025, bk-040, bk-042) and still says CIS never reads Booking's tables.
- `lib/adminIa.test.mjs` test 1 expects 8 groups (d13's seven + Trade, d9); tests 3, 5 and 9 skip / filter external
  items through `canSeeNavItem`; new test 13 covers the Trade group and the deep link.

## Tradeoffs

- The `?tenant=` filter of Booking's Agency billing comes from lane aa1037-billing-visual-fixture. Before it ships,
  Booking ignores the key and shows every agency's invoices: the link degrades to the unfiltered list, never an error.
- External items are full page loads (another origin), so the Next router is not used for them.
