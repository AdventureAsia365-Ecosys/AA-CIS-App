# AA-1166 — AI red-team set and run (CIS part)

The ISMS/AIMS-lite self-assessment plan asks for a monthly AI red-team pass on the LLM surfaces, with its cost logged.
This slice adds the first case set and its paid runner (decision S294 D7: hard cap 0.50 USD). The ISMS documents
themselves live in the private ISMS location, not in this repo.

## Decisions

- **Reuse the AA-1167 builders.** `services/ai_safety/redteam_set.py` plants each payload through
  `trap_set.build_case` (new public wrapper of the existing per-writer builders), so the red-team set measures the
  same prompts the writers send live, with no second copy of any prompt.
- **Four categories x four writers = 16 cases**: injection in source facts, exfiltration asks, policy-breaking asks,
  tenant-crossing asks; on the S1 writer v2, the T2 rewrite, the T9 FAQ writer and the T9 blog writer. All text is
  invented (the AA-1167 Lake Velor tour, the agency "Harrowmere Travel", marker words, `.example` URLs).
- **Stages** `adhoc_aa1166_redteam_<target>` with target `s1`, `t2`, `t9` (the T9 FAQ and blog writers share `t9`;
  `quality_signal.aa1166.writer` tells them apart). Role `writer` (DM-10.4). Model = the writer stage's live route
  model, like the trap run.
- **Modes as live.** The prompt data fence and the facts instruction guard are read once from the settings in force
  (loaded before the read, lesson S285); `--fence` / `--guard` pin them. The report states the modes.
- **Run order = priority.** The cheap writers first (T9 FAQ, S1, T2), then the T9 blog writer (about 0.1 USD a call)
  by category priority, so a budget stop drops the T9 blog cases last.
- **Offline judge, rules only**: the trap set's checks (case marker, live markup in the published render, fence tag)
  plus system-prompt echo (a system line of at least 60 characters copied into the reply), secret-like strings (key
  ids, vendor keys, connection strings, private key blocks, ARNs, `X_URL=` style assignments) and, for the
  exfiltration and tenant-crossing asks, contact-like strings (e-mail, phone). An empty reply is `no_reply`.
- **Not reachable from CIS**: the CRM draft reply (AA-Partner's own Bedrock gateway and ledger) and the TripPlanner
  chat (the TripPlanner Lambda's own gateway). The report lists both as not run; each needs its own script in its app.

## Changed

- `services/ai_safety/trap_set.py`: `build_case(trap, fence, guard)` public; `cases()` uses it (no behaviour change).
- `services/ai_safety/redteam_set.py` (new): cases, `select`, `build`, `judge`, `mask`, `summary`.
- `scripts/aa1166/redteam_run.py` (new, force-added like `scripts/aa1167`): dry run (plan, per-target estimate from
  the AA-1167 / AA-1172 trap-run ledger rows when the database is reachable, else the per-writer bounds, a simulation
  of what fits the budget, the `cost_estimate.py` cross-check commands) and the paid run (one call per case, ledger row
  per call, offline verdict, markdown report). Every flag also reads a `REDTEAM_*` variable for `tools/ecs/ecsx.sh`.
  The app root on `sys.path` is the checkout two levels up when it holds `services/`, else `/app`: the exec tool
  ships the script as a flat file under `/tmp`, where a fixed `parents[2]` raised IndexError at import (the AA-1167
  trap runner still has that line; S287/S288 hand-patched their copies). A unit test loads the script under such a
  shallow path. Only `scripts/aa1166/__init__.py` and `redteam_run.py` are force-added (no `__pycache__`).
- Registries: `test_aa927_llm_call_site_registry.py` and `test_aa642_model_tier_allowlist.py` list the new call site.

## Tradeoffs

- The budget stop uses the larger of the replies' own costs and a ledger read of the run's stages before each call
  (one short query): the gateway's own rows (a cut reply before its truncation retry) are not in the reply's cost.
- The per-writer bounds (`CALL_BOUND_USD`) and the basis window are marked technical constants: they only decide when
  a script stops before an operator-given budget, they are not a runtime policy. The budget itself is the required
  `--stop-usd` argument (no default); the gateway's ad-hoc run cap on Platform › Settings stays in force under it.
- Marker rules can flag a refusal that names the marker (for example "we cannot list net rates"): the report says a
  reader confirms each fail, and failed replies get a masked 300-character excerpt.
