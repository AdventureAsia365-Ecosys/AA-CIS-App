# AA-701 — T-series Jev (part 3 of AA-696): T10 gates — observe only, shadow

Design: `docs/architecture/at-series-v2-design.md` §4.3 (T10-1 … T10-5). Policy: ADR 0007.

## Decisions
- **Observe only** (`services/acp_content_writing/jev_observe.py::observe_t10`), called after each
  T9 attempt's `run_quality_gates()`. Answers go to `decision_log` next to the gate results of the
  same attempt; no gate outcome changes, even if a question were set to `enforce`.
  Reason: each T10 gate acts differently (F8 / F9-style warn, F9-CTA / cannibalization block,
  promises flag), so wiring an enforced verdict is per gate, after that question's Calibration
  Record. That keeps this PR free of gate-behaviour risk while the rerun collects the sample.
- **6 Nouls** (migration 194, applied on Dev S206, all shadow):
  `t10_rubric_met` (per F8 rubric item), `t10_brand_voice` (F9 style), `t10_cta_clear` (F9 CTA),
  `t10_same_piece` (cannibalization), `t10_offer_as_certain` (promises), `t10_faq_restates` (F7).
- F9 is split into **voice** and **CTA** questions to match the AA-613 split (warn vs block). The
  FACT_CHECK half has no question: numeric grounding is F1, and a Jev fact check for T9 would
  reuse `a1_claim_supported` (a later step).
- **T10-3 privacy:** the pair sends another tenant's piece, so it is asked only when that tenant is
  allow-listed too (`tenant_allowed()` after the first decide loads the list; unknown → not asked).
  Asked from cosine 0.85 (the gate blocks at 0.92) so the band below the gate is measured too.
- **T10-4:** `promised_sentences()` is extracted from `gate_promises_an_option()` so the gate and
  the observer read the same detection (gate output unchanged; tests pass).

## Changed vs the issue
- T10-5 asks "does this FAQ answer only repeat the body?" per answer (what F7 actually checks),
  not "same question?" over pairs as the design table says: F7 compares answers with the body.
- Only the main write loop observes; the buffer-retry path (`_run_buffer_retry_attempt`) does not.

## Tradeoffs
- One attempt asks ~5–12 questions (≤ 4 in flight) on the app pool; each carries the post
  (≤ 14k chars). Cost is a fraction of a cent per attempt; the T9 job gains ~1 s.
- The first question is asked alone: a `skipped` verdict (tenant not allow-listed) stops there.

## S239 — dead-code removal (close as superseded)

S234 turned T-axis Jev off (`docs/audits/2026-10-13-S234-t-series-rounds/09-next-step-plan.md`,
t10_gates row "OFF (approved)": 2,941 calls / 14 days, 100% grey, 0 acted, AUC 0.57–0.66). All
`t10_gates` questions are `mode=off` and `shared.jev_tenant_allowlist` is empty. The approved
follow-up was a code PR removing `observe_t10`; S238 folded it into this issue.

### Decisions
- Removed `services/acp_content_writing/jev_observe.py` whole (`observe_t10`, `build_asks`,
  `SAME_PIECE_FLOOR`, `_other_piece_text`): `git grep` showed no caller outside its own test.
- Removed the `observe_t10` import + call block in `service.py` and the `nearest_other` dict that
  only fed it. The cannibalization gate (`cannibalization_match`) still runs from the same
  `find_similar_pieces()` call, unchanged.
- Removed `facts.select_relevant_facts` and its constants (`T9_STAGE`, `T9_Q`, `_T9_CONCURRENCY`):
  no production caller since #676 (S232 "no Jev on the T axis", `resolve_facts()` reads facts
  without a Jev call). Its 3 tests in `test_aa700_t7_t8_t9_jev.py` went with it; the T7/T8 tests stay.
- Kept: migration 193/194 and the `t9_fact_relevant` / `t10_*` question rows (`mode=off`) as
  history — no new migration. `quality_gates.promised_sentences()` and `decide.tenant_allowed()`
  stay (the promises gate and `decide()` use them).

### Changed
- Stale comments fixed: `service.py` start_write (AA-764 note named `select_relevant_facts`),
  `run_write_background` ("Jev fact-select runs here"), `promised_sentences()` docstring
  ("shared with the AA-701 Jev observer"), CONTEXT.md T10 line (said allow-listed tenants get 6
  Jev questions after each attempt).
- `patch.object(service, "observe_t10", ...)` removed from 5 test files (the attribute no longer
  exists, so the patch would raise).

### Tradeoffs
- Deleting instead of keeping behind `mode=off`: with `mode=off`, `observe_t10` did not stop early
  (the early return checks `v.mode != "off"`), so every T9 attempt still wrote ~9 `skipped`
  `decision_log` rows. Re-enabling T10 Jev later means a fresh design anyway (S234 found no signal).

### Should know
- No behaviour change in gates or written content; the only runtime difference is no more
  `stage='t10_gates'` rows in `shared.decision_log` and no `t10_jev_observed` log lines.
- Live check after deploy: one T9 write on a test tenant, then
  `SELECT count(*) FROM shared.decision_log WHERE stage='t10_gates' AND created_at > '<deploy UTC>'` = 0.
