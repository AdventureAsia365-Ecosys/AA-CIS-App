# AA-748 — S1 writer gets structured per-day source facts (behind a flag)

S224 (Kiro build; Claude Code owns the A/B measurement — section 4 of the design contract).

## Problem

S218 audit v4: most S1 versions need at least one grounding repair and itineraries are often
compressed, both tracing back to the writer getting raw source text and paraphrasing it freely.
Day tours with short sources are where grounding fails most.

## What this ships (sections 1–3 of the contract — build only, no A/B)

A compact per-day fact table is extracted from the source once and fed to the writer prompt as an
explicit constraint, behind a flag that is **OFF by default**. With the flag off the writer prompt
is byte-identical to today.

### Flag — `S1_STRUCTURED_FACTS`

`source_facts.s1_structured_facts_enabled(tenant_flags)`: same resolve order as AA-747's
`s1_per_day_targets_enabled` — a tenant-config flag (`tenant_flags["S1_STRUCTURED_FACTS"]`) wins
over the `S1_STRUCTURED_FACTS` env var; default off.

### 1. Extract per-day facts — `services/content_generation/source_facts.py`

`extract_day_facts(tour) -> {"days": [{"day", "places", "activities", "transport", "distances",
"durations", "altitudes", "times", "meals", "other_numbers"}], "used_fallback": bool}`.

- The source is split with `prompts.parse_source_day_word_counts(...)["day_text"]` — the one day
  splitter, never a second one. Parser fallback (no day markers) → `used_fallback=True`, no facts,
  prompt stays as today.
- One LLM call per tour through `LLMClient.generate()` on the new stage `s1_source_facts` (role
  `writer`, Haiku), JSON output, cost logged to `shared.llm_call_log` via `record_call_sync` like
  every S1 stage.
- **Honesty guard (deterministic)** reuses `grounding.source_number_parts(tour)` +
  `acp_shared.grounding.find_novel_numeric_claims`: any value in the number-bearing fields
  (distances / durations / altitudes / times / other_numbers) that introduces a number the source
  never states is dropped; a meal is kept only if it is literally present in the raw source
  (itinerary + inclusions/exclusions + summary/description). Any extraction failure → no facts,
  prompt as today (fail open).

### 2. Writer prompt — `build_rewrite_prompt(..., structured_facts=None)`

When facts exist, a `SOURCE FACTS BY DAY` block (compact, one line per non-empty field per day) is
added before `PER-DAY SOURCE LENGTH`, plus a `SOURCE FACTS RULE`: numbers, distances, durations,
altitudes, clock-times and meals may appear in a day's output only if listed in SOURCE FACTS for
that day; each day's places and activities come from that day's facts. The raw itinerary stays in
the prompt (removing it risks more compression) — the facts constrain, the raw text gives prose
detail.

Wiring: `generate_node` (graph.py) resolves the flag and, on the A1 path, extracts the facts once
and stores them on `ContentState.structured_facts` before building the prompt;
`batch_prompt.build_s1_user_prompt` threads `state["structured_facts"]` into `build_rewrite_prompt`.
The Bedrock Batch materializer does no live extraction, so `structured_facts` is absent there and
the batch prompt is byte-identical to today.

### 3. Routing — `shared/llm_client/role_config.py` + migration 210

`s1_source_facts` added to `SAFE_DEFAULTS` (writer / claude / haiku / acc3). Seed migration
`api/migrations/210_s1_source_facts_stage.sql` inserts the matching `shared.llm_role_config` row
(not applied here — Claude Code applies it by hand via ECS exec).

## Tests — `tests/unit/test_aa748_source_facts.py`

`LLMClient` is mocked throughout (no real LLM/AWS). Covers: flag default off / env on / tenant
override; day-splitter reuse; parser fallback → no facts; honesty guard drops a fabricated number
and a fabricated meal while keeping the real ones; extraction fails open on an LLM error; flag-off
prompt byte-identical to baseline; flag-on prompt contains the block + rule before PER-DAY SOURCE
LENGTH with the raw itinerary still present.

## Not in this build (contract section 4, Claude Code)

The A/B on 30 tours from the S223 India wave-2 set, the per-arm metrics, and the adopt decision
(turn the flag on only if grounding repairs drop ≥ 30% at equal or better judge score). No A/B was
run here.
