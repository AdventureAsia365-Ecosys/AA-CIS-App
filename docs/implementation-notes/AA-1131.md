# AA-1131 — Kit accessibility fixes (S283 UI audit batch K1) + role-name check

Source: root `docs/audits/2026-11-17-S283-fe-audit/README.md` section "Proposals", batch K1, and the a11y / kit rows
of `rows.json`. Lane l3 of S284.

## Decisions

- **DataTable page-size select** gets `aria-label={t("rowsPerPage")}` (new kit message, EN "Rows per page", VI "Số
  dòng mỗi trang") and a `data-kit-page-size` hook. This one control was most of the 31 a11y rows (every paginated
  table in all four apps).
- **Keyboard rows** only when the table has `onRowClick`: `tabIndex=0`, `data-kit-row-open`, Enter or Space opens the
  row, but only when the key is pressed on the row itself (`rowKeyOpens(key, target === currentTarget)`), so a key
  on a checkbox, link or row menu inside the row stays that control's. No `role="button"` on the `<tr>`: it would
  hide the table semantics, and a row with controls inside would be a nested interactive element. Same on the phone
  card. The focus ring is a hoisted stylesheet (`DATATABLE_CSS`): an inset 2 px accent-deep outline, like every kit
  focus ring.
- **Drawer** follows the WAI-ARIA dialog pattern: `aria-labelledby` = the title's `useId`; no title → `ariaLabel`
  prop, else the kit word "Dialog". Initial focus: the new `initialFocusRef` prop, else the first focusable element
  (normally the Close button), else the panel (`tabIndex=-1`). Tab / Shift+Tab cycle inside (`trapTarget`, pure, unit
  tested); a `focusin` outside the panel is pulled back unless it lands in another dialog (a ConfirmModal opened from
  the drawer). On close the focus returns to the element that had it when the drawer opened, when it is still in the
  page. The Escape listener reads the latest `onClose` through a ref, so the effect runs once per opening.
- **PageHeader text basis**: the layout rules (CIS `globals.css`, Booking `ui/local/shell.css`, the studio css each had
  a copy) are now the kit's own hoisted stylesheet (`PAGE_HEADER_CSS`). A header with a description AND actions gives
  the text a 420 px basis instead of 240 px, so a long action row wraps under the text instead of squeezing the
  description into a narrow column (Writing memory at 1440). Same selectors as the app copies, so a copy left in an
  app changes nothing; the CIS copy is removed.
- **PageFrame** `<main>` (both variants) is `position: relative`: an `sr-only` (absolute) element inside a page can no
  longer make the document taller than the frame (Booking service page at 390 px had two scroll bars).
- **Sidebar footer pinned**: the shell sidebars are app code, not kit core (the ShellFrame only gives the slot). CIS
  `app/_kit/Sidebar.tsx`: the aside no longer scrolls; the nav and the app links scroll in a wrapper
  (`data-testid="sidebar-scroll"`, `min-height: 0`), the brand and Collapse stay in view. The Booking sidebar (the one
  the audit measured) gets the same change in the Booking PR of this issue.
- **Dark-mode danger badge**: the token is fine (`--aa-red` on `--aa-red-soft` in dark is 5.4:1). The OFFBOARDED chip
  on `/admin/tenants` sat inside a *disabled* kit `Pressable`, and every disabled kit button is drawn at half opacity,
  which made it about 2:1. Fix at the page: offboarded is read-only, so it is a plain Badge with its hint as `title`,
  not a disabled button. No kit token change.
- **Select needs a name**: covered by the role-name check below, not by a type-level requirement on `Select` / `Input`
  (making `aria-label` required would turn tsc red in every consumer at the next sync). Page-level unnamed filters
  are the per-app audit batches' work.
- **Role-name check** (`tests/e2e/helpers/a11yNames.ts`, no axe dependency: the visual job installs Playwright only):
  every visible form control, dialog and button must have an accessible name (aria-labelledby, aria-label, a label,
  a button's text, a field's placeholder, title). In `visual.spec.ts` it is a gate for kit-rendered controls
  (`data-kit-*`) on every page and for every control on the kit gallery; other unnamed controls go to the report
  (`unnamed`) without failing, so the deployed runs do not go red on page work that belongs to other batches.
- **Keyboard check** (`tests/e2e/visual/a11y-keyboard.spec.ts`) drives the new gallery entry "Table and drawer"
  (invented demo rows): Tab to a row, focus ring, Enter opens the named drawer with the focus inside, Tab / Shift+Tab
  stay in, Escape closes and the focus is back on the row; screenshots `a11y-row-focus__*.png` and
  `a11y-drawer-open__*.png`. It runs only in the per-PR gallery build (VISUAL_GALLERY=1).

- Not done here: H1 (the S283 audit scripts as a reusable harness in skill `aa-ui-verify`): the scripts are many

  (lines and complexity may not grow), and the pieces are self-contained.

## Tradeoffs

- Initial focus on the first focusable element (the Close button) rather than the first field: a detail drawer would
  otherwise scroll to a control deep in its body. A form drawer passes `initialFocusRef`.
- The role-name gate is narrow on purpose (kit controls + the gallery). A full gate on every page would be red on day
  one for page filters the audit lists under other batches (C3, C4, P3, B4 …).
- The row focus ring is an outline on a `<tr>`; Chromium draws it. The phone card (a `<div>`) gets the same ring.
