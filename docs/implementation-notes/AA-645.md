## Decisions

- **Not wired into the live graph.** The new writer lives in `services/content_generation/s1_writer_v2.py` and is
  only called by the offline harness `scripts/aa645/s1_screen.py`. `generate_node` / `validate_node` / flag_fix are
  unchanged (apart from the neutral fixer wording below). The plan wires the A/B *winner* in step 4 (S252, shadow or
  review, behind a flag); wiring an arm before the A/B picks it would put an unmeasured writer on the live path and
  would have to be redone for whichever arm wins. "Behind a flag" for step 2 = zero live-path reach.
- **Three arms in one module** (q4-q8 §2.2): `aplus` = today's A1 writer prompt byte for byte
  (`build_s1_system_prompt` / `build_s1_user_prompt`) + a code-built DAYS block (the day-count oracle as an input) +
  a separate meta call; `w` = the new writer (fact sheet + new rules) + separate meta call; `e` = code-built short page
  (At a glance box, `Day N —` blocks with source fact lines, Included / Not included) where the LLM writes only the
  name, subtitle, one hook sentence, 3–5 highlights and one sentence + title per day, + separate meta call.
- **≤ 3 LLM calls per tour per arm** (step-2 bar; today 4.36): writer 1 + meta 1 + at most 1 meta retry. No itinerary
  nudge, no flag_fix, no validate loop in any arm. A+ therefore is "today's writer without the nudge/repair loop";
  the repairs are gates, and code gates are measured, not fixed, in the A/B (q4-q8 §2.1: code-checkable errors are a
  gate that must reach ~0, not part of the win).
- **Place background (step-1 open question D2): allow, figures forbidden** — the current writer policy (memory
  `writer-source-fidelity-policy`) and the step-1 proposal. Config: `background="allow" | "forbid"` on the builders
  and `--background` on the harness; with `forbid`, NAME_NOT_IN_SOURCE becomes a gate in the score.
- **Day plan by code** (`day_plan`): source "Day N" markers (ranges expanded, one block per day) when the source has
  ≥ 2; a sub-day or one-day tour, or a tour with no markers and no usable duration, is exactly one block; a multi-day
  tour with no markers gets one block per stated day, the source given once (thin days allowed to be one sentence).
  A duration vs. markers contradiction follows the markers (the writer cannot invent days) and goes to the
  ask-the-supplier list (fact table `conflicts`).
- **Agency fields** `raw_tours.group_size` and `best_time_to_go` (step-1 handoff point 1: the S1 writer never received
  them) are appended to the source `description` as labelled lines by `with_agency_fields` — for the writer, the
  fact table, the code checks and the panel packet alike, so a group size the page states is not charged as invented
  and the `missing` list drops it.
- **SEO keywords**: only DFS keywords whose content words all occur in the source (`keyword_covered`, the S233 rule)
  and that are not transactional reach the meta call, at most 3; PAA is not used (advisory §5 "stop" list). The meta
  call reads the cached `silver_aa_internal.seo_context.top_keywords`; the harness never calls DataForSEO.
- **Meta**: its own call, target 130–148 characters (lesson S233: aim below the gate band 140–155), code-checked
  (length band, complete sentence, cut signature, list cut, title ≤ 60, budget words, forbidden words, numbers not in
  the source), one retry naming the problems and the measured length, never cut by code.
- **Reference examples** are input data (`--examples <json>`), not code: tour text belongs in the private root repo.
  The screen runs zero-shot; the winning model's pages for the two clean candidates (af0ded16, dfdb4017, advisory
  W2) are exported as example drafts (`--export-examples`) for Nghiệp to edit before A/B run 1.
- **Neutral A1 fixer** (`flag_fix_node.FIX_SYSTEM` and the A1 fix user-prompt head): "Adventure Asia's editorial
  fixer … brand standards" → a white-label catalogue fixer (advisory house-style §4: 9 published S1 tours name
  Adventure Asia as the operator; the fixer framing is the likely cause; same PR as the surgery per the advisory).
  This is the only live-path change of the branch.

## Tradeoffs

- A+ without the nudge and the validate / flag_fix loop is not byte-for-byte today's pipeline. Running the real graph
  offline needs the whole brand / Jev / judge stack and costs ~4.4 calls a tour; the A/B question is "does the new
  writer make fewer meaning errors", which the writer call answers. The live pipeline numbers stay available as the
  stored page (`stored` rows in the harness output, $0).
- The screen model list is a flag. Default `haiku-5-5,gpt-6-luna,sonnet-5-5` (newest Haiku / Luna / Sonnet in the
  catalog, migration 259). `haiku` (Haiku 4.5, today's `s1_generate`) is an optional 4th (~$0.15 more).
- `max_tokens` 16000 for the writer: Claude 5.5 models think adaptively and the thinking counts against `max_tokens`
  (S246 place trial: Haiku 5.5 stopped at 4000). Only produced tokens are billed.

- `s1_checks.check_truncation` accepts a last line that is a list item or a `Label: value` fact line (arm E ends its
  fields that way). Re-run on the 50 golden pages: identical code counts to the step-1 `results.json`.
- Figure coverage (the A/B side metric) counts the source's operational figures (km, hours, metres …) found in the
  page; the trip length (day / night / week) and figures in the name or duration field are left out (written as
  words, structure not content).

## Cost (estimate, list prices from migration 259 / the catalog; the screen logs the real number)

Fact sheets on the golden set: median ~4.7k characters, max ~31k (≈ 1.2k–8k tokens). Per tour, writer + meta:
haiku-5-5 ≈ $0.003, gpt-6-luna ≈ $0.005, sonnet-5-5 ≈ $0.05 (adaptive thinking included, rough). Screen
(12 tours × 3 models, arm W) ≈ $0.7–1.0; trial (3 tours × 3 models) ≈ $0.2. Cap `--max-cost-usd` (in-process, checked
before each unit with a per-model margin). The S246 advisory's "~$2.5" was priced on Haiku 4.5 / Sonnet 4.6.

## Review round 2 (S248, re-review)

Finding → change:

- **MUST — the common tour set was intersected over every row of the arm, ineligible rows included** (a model that
  errored on every unit made it empty → pick None with the wrong reason; a model kept only from the 3-tour trial
  shrank it to 3 tours for everyone) → `score_screen._common_rates` marks each row `eligible` only with zero gate
  pages, zero writer errors and EVERY sample of the arm (the union of the arm's sample ids) completed and
  panel-scored; the common set is computed over eligible rows only, which makes it the arm's full sample set. An
  excluded row carries `excluded_reason` (e.g. `3/12 samples of the arm completed and panel-scored`) in the table and
  in `pick.rows`; it gets a common rate only if it happens to cover the set (information, never competes). No eligible
  row → `pick: None` with "no eligible row …" (the earlier "no panel-scored rows" reason stays for that case).
  Consequence: one tour that failed for every model now leaves no eligible row; the fix is `--retry-errors` on that
  tour, not a smaller comparison set. Decision: no fallback to the old all-rows intersection — it is the bug.
- **TEXT_TRUNCATED on a trailing `+`** ("Group size: 10+", "- Suitable for ages 8+") → `_DANGLING_TAIL_RE` drops `+`.
- **`--retry-errors` overwrote the errored unit** → the new attempt carries `attempt` (2, 3, …) and `prior_attempts`
  (`[{error, n_calls, cost_usd}]`, oldest first; that spend is real); a retry skipped by the cost cap keeps the errored
  unit in `pages.json`. `summary.json` and the scorer add `retried` / `retry_usd` per arm × model; the pick output
  lists every retried row under `warnings` and `pick_retried` for the chosen row. Tradeoff: a retried row stays
  eligible (its final pages are complete and clean) — a warning, not an exclusion, because a transient gateway error
  says little about writing quality; the orchestrator weighs it.
- **`_DAY_REF_RE` was case-insensitive** (prose "over 4 days 60 km" lost 60) → only capitalised `Day N` / `Days N–M`
  at a line start (optional bullet) or followed by a dash / colon that is not a range; a range end glued to a figure
  is not eaten ("Day 2 to 3,000 m" keeps 3,000; "Day 12,000 steps" untouched). Applied per field before joining, so
  each field's first line is a line start.
- **`drop_do_not_use` matched substrings** ("Asia" removed "Asian food", "B" removed "Meals: B, L") →
  `do_not_use_patterns`: whole word (`(?<!\w)…(?!\w)`, so values starting with `+` or ending in `.` work),
  case-insensitive, any whitespace inside a value; values under 3 characters ignored. Inclusion / exclusion items
  (`trim=True`) cut only the item and its pointer words ("from", "by", "operated by", "call", "Tel:", …) when the rest
  stands ("Guide from <operator>" → "Guide", "Pickup (call <phone>)" → "Pickup"); the line is dropped when the item
  sits mid-phrase with no pointer word ("Visit Asia Gallery"), or the rest has no 3-letter word, ends mid-phrase
  (`s1_checks._cut_mid_phrase`) or starts as a fragment ("for visas"). Day fact lines and At a glance lines are still
  dropped whole (a cut "Overnight: …, call" is worse than no line). Also changed beyond the finding: `meta_problems`
  uses the same matcher for its operator-name check (same substring bug class; "Loops" no longer matches "Loop").
- Handoff step 3b: trial cap raised to `--max-cost-usd 0.8` (Sonnet 5.5 reserves ≈ $0.31 a unit; under $0.5 the third
  model's units would wait or be skipped).

Should know (round 2): `pick` now reads `eligible` from the scored table; a hand-built table must carry it.
