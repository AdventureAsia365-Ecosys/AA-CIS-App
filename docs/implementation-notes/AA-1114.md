# AA-1114 — TripPlanner custom-domain follow-up (CIS part)

Source: S282 audit section 6.3 (G18, R29, G4). This repo carries the code items; turning on CodeQL default setup for
AA-Partner is a repository setting outside this PR.

## Decisions

- **Own hosts are an exact match, in their own set.** `AllowedTargets.tenant_tripplanner_hosts` holds the tenant's
  `active` rows of `shared.tenant_tripplanner_domain` (CIS 428). The platform TripPlanner hosts keep their sub-domain
  match; an agency host does not: `evil.trip.agency.example` is not on the TripPlanner agency edge, so it is not the
  planner. The stored host is kept as verified (a leading `www.` is NOT dropped) and compared with the link's host as
  written (`_raw_host`: lower-case, trailing dot removed, `www.` kept). Review fix: an earlier draft dropped `www.`
  from both, so a stored `www.agency.example` allowed the apex `agency.example`, the agency's own shop, which the
  tenant never verified and which is not on the TripPlanner edge.
- **Verified = `active` only.** `pending` / `validating` / `attaching` hosts have no certificate on the edge yet, a
  `failed` host is detached, a `removing` one is on its way out: none of them serves the planner.
- **Same tenant only.** The read is `WHERE tenant_id = $1::uuid`; another tenant's active host is held like any
  off-catalogue booking link. A tenant id that is not a uuid gives an empty set (the gate never raises on it).
- **No read without links.** `load_targets` skips the host read when the piece has no link (most social posts).
- **ReDoS: linear checks, not a tuned regex.** `tripplanner_domain.domain_shape_ok` (alert #62) and
  `tripplanner_site.is_legacy_ipv4_spelling` (alert #60) read the host label by label with set membership; the
  domain check already ran after the 253-character cap and still does. The unit test keeps the former regexes only as
  the reference: both functions agree with them on every string of up to 6 characters over the relevant alphabet and
  on a list of edge cases, and answer 100k-character adversarial strings in well under a second.
- **Entitlement refusal message.** `custom_domain_not_included` (shipped in the AA-1116 pricing PR) now has a sentence
  in `MESSAGES` ("... a TripPlanner Pro feature. Change the plan first.") instead of the bare code.

## Tradeoffs

- One extra indexed read per gate run with links (`tenant_tripplanner_domain_tenant_idx`); no cache, so a host that
  becomes active or is removed counts at the next check.
- Exact host means the `www.` twin and the apex of a verified host are both refused (`www.trip.agency.example` when
  `trip.agency.example` is verified, `agency.example` when `www.agency.example` is). A writer that adds or drops
  `www.` gets the piece held; the safe side for a sales link, and a link to the verified host itself passes.
