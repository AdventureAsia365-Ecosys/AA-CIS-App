# AA-795 — T2: persist the judge breakdown per version + brand-claim fidelity check

Report 12 (S234 T-series rounds) §2.3 fixes F-f and F-g, proposal #11.

## Decisions

- **Own column, not `generation_meta`.** CIS 297 (AA-920) documents `generation_meta` as "how the version was
  written: ids and hashes only". A judge verdict is how it was *scored* and carries the judge's feedback text, so it
  gets its own nullable `jsonb` column: `gold_aa_internal.tenant_tour_versions.judge_breakdown` (CIS **300**).
- **Number 300.** `db/run_migration.py` has no version-order rule (any unregistered version is applied; the copy
  guard only checks numbers are unique per owner), so a reserved number below the highest applied one would be
  accepted. 297 and 298 are already taken (AA-920 WM-25 and the `catalog.v_tour_place_name` view lane), so the next
  free number, 300, is used. 300 > 299 (the highest applied), so `readiness.REQUIRED_CIS_SCHEMA = 300` is enough and
  nothing goes into `OUT_OF_ORDER_CIS`.
- **The judge's own numbers are recorded where they are computed.** `judge_node` (T2 only) adds one state key,
  `judge_t2_axes` = {gate, validate_score, judge_score_raw, mission_cap, mission_source, binding}. It is declared in
  `ContentState` (LangGraph drops undeclared keys, AA-209), added to `t2_repair.DRAFT_KEYS` (a restored best draft
  restores its own verdict) and re-listed in `_rewrite_tour`'s result.
- **Binding axis** = which number set the stored score: `brand_fit`, `cross_brand` (gate `combined` only),
  `mission` (the mission-absent cap), `tiebreak` (the Jev tie-break moved the judge score), `validate` (validate's
  structural score is strictly below the judge score) or `unjudged` (the judge did not run on the kept draft).
  On a tie the earlier axis in that order wins (a cap equal to brand fit changed nothing).
- **Brand-claim check is deterministic and report-only.** Backlog L1 says no new gates for 4 weeks, so a flagged
  claim never changes the status, the score, the text or the T3 loop: it is recorded in
  `judge_breakdown.brand_claims` and shown in the admin drawer. Kill switch: `T2_BRAND_CLAIM_CHECK=off`.
- **No LLM call.** The two report examples ("children aged seven to sixteen", "consent-based community visit") are
  caught by patterns, so no LLM pass was added (and so no `T2_BRAND_CLAIM_LLM` flag, no new stage key, no
  `llm_role_config` seed). If a later rerun shows open-ended brand claims the patterns miss, the LLM pass goes
  through `LLMClient` with role `judge`, behind a default-off flag, as a follow-up.

## Tradeoffs

- A claim lexicon misses claims it does not list, and the age / group-size patterns only read numbers next to a
  person noun. False negatives were preferred to noise: the result is an admin signal, read next to the judge's
  scores, not a gate.
- Review fix (independent review, S256): numbers are read as whole tokens only (`_NUM`), so "aged 300 years" is no
  longer an age claim of 30 and "anyone under 12" no longer needs the source to state a 1. The source side is
  lenient: besides the claim patterns, every number in a source clause that names an age (or a group) counts as
  stated, so label-style A1 text ("Minimum age: 7", "Maximum group size: 12", "Children 8+") supports the matching
  claim. The cost is a claim whose numbers happen to sit in such a clause for another reason is missed; that is the
  preferred direction for a report-only signal. `judge_axis` treats `mission_present` falsy (not only `False`) as
  absent, the same rule as `judge_node.t2_judge_score`.

## Should know

- **Ship order (D8):** Infra copy PR → DB Migrate `check` → `apply` 300 → merge this PR → Deploy Dev. Without 300 every
  T2 save fails (the UPDATE names the column) and `/health/ready` reports `schema_behind` (required 300).
- Report-only by design: the status / score / text / T3 loop of a version are byte-identical with the check on or
  off (`test_flagged_claims_change_nothing_else_in_the_save`). The only new writes are the column and `job.result.judge`.
- The breakdown describes the **kept** draft. With `T2_BEST_DRAFT` on, a restored draft restores its own axes
  (DRAFT_KEYS). A T3 sentence repair edits the saved text after the judge, so the judge numbers describe the draft
  before that repair; the brand-claim check reads the final saved text.
- If the judge fails on a retry draft, the graph keeps the previous draft's judge_* values in state (pre-existing
  behaviour); the breakdown then shows that earlier verdict. `degraded` in job.result says the judge was unavailable.
- Old versions have NULL (the drawer says so). Feedback text cannot be rebuilt for them (llm_call_log keeps numbers
  only), so there is no backfill. A $0 read-only scan (`.tmp-session/S256/aa795/aa795_brand_claims_scan.py`, root
  workspace) runs the claim check over the existing versions after deploy.
- No LLM call was added, so `llm_call_log` and cost are unchanged.
