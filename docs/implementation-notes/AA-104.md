# AA-104 — S1 State Bridge Guard (Write-before-Trigger)

## Decisions

- **`s1_tour_ids` skipped**: `S1StagePayload` only has `s1_keywords_used`; adding `s1_tour_ids`
  would require a schema migration. Deferred.
- **`seo_keywords_used` source**: Keywords collected from `gold_aa_internal.published_tours.seo_keywords_used`
  per batch. Elements may be plain strings or dicts with "keyword" key — both handled.
- **S2 guard entry point**: `run_s2()` background task (`_background()` in `services/acp/s2/router.py`).
  Added optional `s1_run_id` field to `RunS2Request` so EventBridge consumer can pass S1's run_id.
- **Missing `acp_run_context` row**: If no row exists for `run_id`, `write_run_context_stage` does an
  UPDATE 0 rows silently. Transaction still commits, event still publishes. A missing S0 row is a
  different bug; not blocked here.
- **`S1ContextNotReadyError` location**: `services/acp_shared/errors.py` (new file). Shared module,
  importable by both service layers.

## Changed

- `services/export/handler.py`: S1 completion block now fetches `seo_keywords_used` from batch,
  wraps both `shared.acp_runs` INSERT and `write_run_context_stage("s1")` in a single asyncpg
  transaction, publishes event ONLY after commit.
- `services/acp/s2/router.py`: `RunS2Request` gains `s1_run_id: Optional[str]`. Background task
  checks `acp_run_context.s1_keywords_used` for that run_id before starting the graph.
- `services/acp_shared/errors.py`: New file — `S1ContextNotReadyError`.

## Tradeoffs

- **Transaction wraps both writes**: `shared.acp_runs` and `acp_run_context` write are in the same
  asyncpg transaction so both commit atomically, or neither does. Slightly more locking but correct.
- **Guard is optional**: If no `s1_run_id` passed to S2, guard is skipped. Preserves backward
  compatibility for manual S2 triggers that don't have an S1 context.

## Should know

- asyncpg connections are autocommit by default; `async with conn.transaction():` is the explicit
  begin/commit wrapper.
- `write_run_context_stage` receives the same `conn` object and participates in the outer transaction.
- `S1ContextNotReadyError` bubbles up from `_background()`, sets `acp_runs.status='failed'`
  with the error message — observable in DB.
