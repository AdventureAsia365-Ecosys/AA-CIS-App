## Incident during rollout (28/09, S200)
- After migration 171, an end-to-end run showed `brand_audit` returning `pass` with no codes and
  cost 0, while the GPT-4.1 shadow said `flagged`.
- Root cause (from `llm_shadow_log.primary_output`): GPT-5.6 Luna's forced-tool output omitted
  the required key `status`. A Bedrock forced tool does not enforce the schema the way OpenAI
  strict mode does. The node's `result["status"]` raised a KeyError, and its existing graceful
  path returned `pass`.
- Mitigation: `s1_brand_audit` was rolled back to GPT-4.1 on Dev (`updated_by =
  rollback-s200-brand-audit`). The other three judges stayed on Luna.
- Fix: `shared/llm_client/schema_check.py`. Every structured output is checked against its
  schema in the gateway, and nested objects returned as JSON text are decoded. A mismatch raises,
  so the route tries the next model; the caller never receives it.
