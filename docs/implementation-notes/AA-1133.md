## Decisions

- **Search index built at publish time, opened in memory here.** The root Docs sync writes `search/index.sqlite`
  (SQLite FTS5, about 6 MB for 207 pages / 2,048 sections) next to the pages; the manifest names its sha256.
  `api/services/docs_search.py` reads it under the existing read-only docs-reader prefix grant, refuses it when the
  hash differs (503 while a sync is half done), opens it with `sqlite3.Connection.deserialize` (no file on the task
  disk) and `PRAGMA query_only`, and keeps one connection per manifest hash. No table, no new AWS permission.
- **Query safety.** The typed text is reduced to word characters; each word becomes a quoted prefix term, all required.
  Nothing the caller types reaches FTS5 syntax (tests: `NEAR(`, `OR`, quotes, `*`).
- **Vietnamese without marks.** `unicode61 remove_diacritics 2` folds every Vietnamese mark except the stroke of
  "đ", so the index carries a fourth column `folded` (the section text with đ → d) only for sections that have one;
  "den long", "đèn lồng" and "cho" all find "Chợ đêm … Đèn lồng".
- **Role filtering twice.** Owner-tier sections are dropped in SQL unless the caller may read owner pages, and every
  hit must also be a page the manifest lists for that caller (fail closed: a page gone from the manifest never shows).
- **Snippets as segments.** The API returns `[{text, hit}]`, never markup; the page renders `<mark>` itself. 12-digit
  runs are masked like a page body.
- **Heading ids match the index.** The reader takes the body's H1 out (the header shows the title) but seeds the
  slugger with it (`outline(body, [h1])`), so the ids are the ones the builder computed on the whole page and a search
  hit lands on its heading (`#doc-<slug>`).
- **Sidebar from `nav`.** The builder emits `nav` (front-matter, else derived from the folder) and `nav_order`; the list
  groups by it in the fixed order start, guides, operations, architecture, reference, legal-security, with readable
  labels (EN / VI). An older bundle without `nav` still groups by folder.
- **Feedback.** One row per (repo, path, actor) in `acp_shared.docs_feedback` (CIS 454, expand): a new answer replaces
  the old one. The page posts the original page's path and the language read. Every staff role but the read-only
  viewer answers (READ_ONLY_ROLES refuses the POST; the widget is hidden for it); the admin view (`GET
  /admin/docs/feedback`, ops.read, the Feedback button on /admin/docs) lists pages with the most "No" first and their
  latest notes, and counts (never names) pages the admin may not open. `acp_shared`, not `shared`: DM-1.5.
- **Open to every staff role (B7).** New capability `docs.read` held by every role; POLICY manifest / page / asset /
  search / POST feedback = docs.read, GET feedback = ops.read. BFF and page rules: `EVERY_STAFF`. The AI gateway Guide
  tab now links to the reader for finance and ai_ops too (they can open it). The tech lead's condition ("after the
  wrong staff pages are fixed or carry a banner") is met by the root PR: the three staff runbooks and their `.vi.md`
  copies carry `known_issue`, shown as a banner until the fixing PR removes it.
- **GitHub links.** Source = the file at the published commit; History and Edit = the branch. Only while the bundle
  names a public repo (`source.github`, set by Docs sync from the repository visibility); Edit only for the admin role.
- **Code blocks.** Language label from the fence class and a kit `Button` "Copy" (clipboard API; nothing happens on an
  insecure context). No syntax highlighting in this slice (Shiki would add ~1 MB of grammars; later slice).

## Tradeoffs

- **Index in the bundle vs built in the API.** Building at publish time keeps the API cold start cheap (one 6 MB read,
  no 200 page reads) and makes the index the same for every task; the cost is a second artifact whose hash must match
  the manifest (handled: 503 for a moment during a sync).
- **One answer per person and page** instead of an append-only log: the admin view needs "how many people find this
  page unhelpful now", not a history; a person who changes their mind replaces their answer.
- **No admin-menu collapse on /admin/docs.** The advisory's "menu collapses on this page only" would be a one-page
  variant (ADR 0016, consistent-not-one-off); the three columns fit at ≥ 1280 px with the menu open. A kit-wide
  "wide content" mode is a separate kit change.
