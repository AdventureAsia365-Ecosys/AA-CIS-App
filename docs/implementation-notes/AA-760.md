# AA-760 — Portal page-by-page audit + state fixes ("Writing…" bug)

Split from AA-670 (S229). Built S247 (22/10/2026) by a Claude Code subagent, stacked on the AA-759
PortalShell branch. UI only: no API change, no migration.

## Decisions

- **One status model** (`portal/app/portal/_components/workStatus.tsx`) for work a tenant can see:
  `queued / writing / checking / done / failed`, plus `WorkStatusBadge` (kit `StatusBadge`).
  - Tour versions use `status` + `edit_source` + the `job_status` the API joins from `shared.job`
    (`tourWorkStatus`, built on the existing `catalogApi.isAiWriting / isRewriteFailed`).
  - Pieces use the tenant-safe `ready_state` the API derives from the job (`pieceWorkStatus`).
  - The live view uses the progress snapshot: an active `check` / `revise` step reads as
    `checking` (`liveWorkStatus`). Today that is the only place `checking` can appear: the list
    endpoints expose no separate check state.
  - The activity feed (`/v1/billing` activity has no job) is joined to the same version in the
    `["my-versions"]` query (`activityState`). Until that query answers, a row shows no badge
    instead of a guessed "Writing".
- **Browse Tours "Writing…" fix.** The row status now comes from the tour's latest version in the
  shared `["my-versions"]` query, so a failed job reads "Writing failed" (with "Retry in My Tours").
  That query polls every 5 s while anything is queued or writing and stops on terminal states. A
  tour the server marks `already_rewritten` that is not in the loaded page reads "In My Tours"
  (done). Only finished versions can fall off page 1: the endpoint is newest first, so an active
  rewrite is always on page 1.
- **AngleGateWizard**: both polls (angles `t8_angles`, piece `t9_write`) are react-query
  `refetchInterval`s:
  - only one request in flight at a time, paused in a hidden tab;
  - they stop on a terminal state;
  - the 180 s hard stop is gone (every write is a job that always ends, and a job that ends without
    success marks the piece/request failed). After 3 min the poll slows to 15 s and a "taking longer
    than usual" note shows.
  - The poll tick (the async `queryFn`) settles the wizard state, as the old interval callback
    did; nothing runs in an effect.
- **Stale sidebar count**: the shell's observer of `["my-versions"]` polls (10 s) while a version
  is active, so the My Tours count moves when a background rewrite finishes on any page.
- **Shell data reuse**: the dashboard reads billing / pool total / activity from the shell queries
  (same keys, one request) instead of fetching them a second time in an effect.
- **SlateTab, Marketplace, Browse Tours** moved to react-query. The Slate's background-refresh
  poll is a `refetchInterval` while `refresh.refreshing`, and Social Posts and Articles share the
  one cached answer.

## Changed

- New `workStatus.tsx`. Callers moved onto it: PoolTab, CatalogTab, ReviewList, TourRewritePanel,
  WriterPanel (the watcher), LiveWriter (a status badge in its header), Dashboard, the Activity
  page and the bell.
- AngleGateWizard: no `setInterval` left; the write-done popup is on the kit `Modal`.
- Audit fixes found on the page pass:
  - one date format everywhere ("9 Oct 2026"; My Content / Publish lists showed "10/20/2026");
  - "My Catalog Tours" → "My Tours" in every tenant-facing string;
  - "Social Content" → "Social Posts" in the wizard and drawer copy;
  - the Settings title matches the nav ("Team & Settings");
  - the Marketplace copy no longer points at "Atom Curation" (a page tenants do not have);
  - the Browse Tours filter bar wraps on a phone (the search box was ~70 px wide at 390);
  - error state + Retry on Browse Tours, Marketplace and Dashboard.
- Lint (portal): 9 errors at the start of S247, 7 after AA-759, **1** now. The one left is
  `BrandTab.tsx` fetch-in-effect: a form initialiser, see below.
- Kit ESLint rule: `error` for every portal file now, except the 3 legacy files in
  `KIT_LEGACY_FILES` (`portal/eslint.config.mjs`).

## Tradeoffs

- `my-versions` is still `page_size=50` (the API caps at 100, no `published_tour_id` filter).
  The status is correct for every active rewrite (newest first). A tenant with more than 50
  versions still sees My Tours truncated. Server-side paging needs an API change (follow-up; it is
  the AA-718 pattern on `/v1/tours/my-versions`).
- Two observers poll `["my-versions"]` while on My Tours (page 5 s, shell 10 s). react-query
  dedups requests in flight; it costs at most one extra read per 10 s, and only while a rewrite runs.
