# AA-816 — C7: staff directory reconcile job

S242 plan step C7 (`docs/audits/2026-10-18-S242-cognito-phase1/plan.md` in the root repo). Separate file from
`AA-816.md` on purpose: the C6 and C7 PRs run in parallel and both used to edit the one notes file.

## Decisions

- **Kind name `staff_directory_reconcile`** on `shared.job` (CIS kinds keep unprefixed names, ADR 0003a §3).
  `concurrency=1`, `max_attempts=2`, `expected_seconds=120`, `background=True` (never takes a pipeline slot).
  Not `deploy_gate_exempt`: AA-751 keeps that flag unused (a test asserts no kind sets it), and the job runs
  in seconds, so the gate waits at most one short run.
- **Daily trigger = the existing ops-probe Lambda**, not a new scheduler. Scheduled CIS work is driven by
  the Infra Lambda `dfs_balance_check` (EventBridge Scheduler, 06:15 UTC default path set, plus
  `retention_daily` at 20:30 UTC), which POSTs admin paths with the admin secret. C7 adds the machine route
  `POST /admin/job-runner/staff-reconcile/schedule` (idempotent per UTC day:
  `staff_directory_reconcile:schedule:<day>`), listed in `MACHINE_ROUTES`. The Lambda needs a one-line Infra
  change to call it (add the path to `_PATHS` in `accounts/aa365/lambda_src/dfs_balance_check/handler.py`);
  that is a separate Infra PR, out of this lane. Until then the on-demand button is the only trigger.
  No in-process scheduler was added to the api sampler: it would widen `ops_metrics_sampler.py`'s job and its
  docstring promises it enqueues nothing.
- **On-demand** `POST /admin/platform/staff-directory/reconcile` and read
  `GET /admin/platform/staff-directory/health`, both `staff.read` (admin role). Enqueuing a read-only report
  is not a directory write, so it does not need `staff.write` / owner. A queued or running reconcile is
  returned instead of enqueuing a second one.
- **Path `/admin/platform/staff-directory/...`, not `/admin/platform/staff/...`**: `GET /staff/{staff_id}`
  would swallow `GET /staff/health` (FastAPI matches in order, and the new route goes at the END of the
  router to stay clear of C6's edits). A separate segment cannot collide with any C6 `/staff/{id}/…` route.
- **Cognito calls: only `ListUsers` and `ListUsersInGroup`** (the I3 task-role grant). Pool id and region
  come from the WORKFORCE issuer (`api.core.identity_config.workforce_issuer()`, code constant with env
  override), so no new task-definition variable. Break-glass address: code constant `admin@adventure.asia`
  (D1 outcome, the `admin` row) with env override `COGNITO_BREAKGLASS_EMAIL`.
- **CIS role from groups reuses `api.core.staff_identity.role_from_groups`** (the C3 rule: highest `cis-*`
  group), so the reconcile and the sign-in path can never disagree on what "role drift" means.

- **Report categories beyond the brief** (all report only): (a) also flags a Cognito user whose email
  matches an active row already bound to a DIFFERENT sub (`row_bound_to_other_sub`, a user re-created in
  Cognito: C3 links by email only while `cognito_sub IS NULL`, so that person would be locked out); an
  inactive row whose Cognito user is still enabled (`row_inactive`); an inactive row + disabled Cognito user
  is consistent and not reported. (b) also flags a row bound to another pool's issuer (`other_issuer`).
  (c) also flags two `cis-*` groups at once and an active row whose Cognito user is disabled
  (`cognito_disabled`). A missing staff group (ListUsersInGroup ResourceNotFound) is a finding, not a failure.
- **Break-glass** is excluded from (a)/(c)/(d) and gets its own block: present, CONFIRMED, disabled at
  rest, in cis-admin + booking-admin (ADR 0006). Each deviation counts in `drift_total`.
- **`drift_total`** = (a) + (b) + (c) + (d) + break-glass issues + missing groups. Readiness (e) is NOT
  drift: legacy rows not yet created in Cognito are expected before cutover, so the plan's "a run reports
  0 drift" holds on today's Dev while readiness still says "not ready".

## Tradeoffs

- **Daily trigger needs one Infra line** vs an in-process timer in the api: the Lambda path keeps one
  scheduling mechanism (EventBridge Scheduler -> ops-probe Lambda -> machine route -> idempotent job),
  visible in Infra, with retries and a per-day key. Cost: until the Infra PR lands, only the button runs it.
- **The health read returns emails/usernames** (admin-only, staff.read) — needed to act on a finding. The
  log line `staff_reconcile_summary` carries counts only, so CloudWatch never holds the staff list.
- **Staleness**: the report is at most a day old unless someone presses "Check now". Cheap enough to run
  more often later (two list calls + seven group calls, no MAU impact: ListUsers is not a sign-in).
- **Group mapping duplicated?** No: the CIS map is imported from `api.core.staff_identity` (C3); the Booking
  map is a local constant checked by a test against the 247 CHECK values.

## Should know

- **Infra follow-up (not in this PR)**: add `"/admin/job-runner/staff-reconcile/schedule"` to `_PATHS` in
  `AA-CIS-Infra/accounts/aa365/lambda_src/dfs_balance_check/handler.py` (06:15 UTC default run; `_ALLOWED_PATHS`
  is built from `_PATHS`, so one line). The handler's own tests may list the paths.
- **IAM**: the job runs on the WORKER service. Checked read-only on Infra origin/main: both task definitions use
  `aws_iam_role.ecs_task` (`modules/ecs/main.tf:373` api, `:574` worker) and `accounts/aa365/identity_iam.tf`
  grants ListUsers / ListUsersInGroup on WORKFORCE to it. A denial would fail the job NonRetryable with
  `AccessDeniedException`, shown in the job error and on the panel ("Last check failed").
- **No AdminGetUser**: ListUsers can not tell whether a user has a password, so (d) is status based
  (FORCE_CHANGE_PASSWORD, RESET_REQUIRED, ...). Noted in the report's `notes`.
- **Break-glass address** defaults to `admin@adventure.asia` (D1). If D1 changes, set `COGNITO_BREAKGLASS_EMAIL`
  or change the constant; ⚠️ it is an underscore env var — edit manually in VSCode / Terraform, do not paste.
- **Local unit test runs** must neutralise AWS config (the app's Sentry DSN lookup tries Secrets Manager at
  import and prompts for MFA): `AWS_CONFIG_FILE=/dev/null AWS_SHARED_CREDENTIALS_FILE=/dev/null` plus dummy keys.

## Review round 1 (C7 review of 52048f5d)

- **M1 fixed — report readable through the job-runner API.** `GET /admin/job-runner/jobs[/{id}]` are open
  to every staff role (the S1 page polls them) and the machine, and they returned the full `shared.job.result`
  (staff emails, groups, status, break-glass state). Not fixed with a POLICY entry on those GETs (would break
  the S1 page). Instead `admin_job_runner._restricted_results()` maps a kind to (capability, redact function);
  `staff_directory_reconcile` -> (`staff.read`, `staff_reconcile_job.redact_job`). Callers without the
  capability (reviewer, content, machine) get counts + `drift_total` + `ready` + `redacted: true`, and no
  `payload.requested_by`. Admins still see the full job. The role is read from `x-admin-role`, the header
  `staff_policy` decides on (set by the BFF, or by `staff_bearer` from Cognito groups). Chosen over storing
  only counts in `shared.job.result`: the health route reads the report from the job row, and a second store
  would need a migration.
- **L1 fixed — status findings.** (d) now runs only for an enabled Cognito user matched to an active row, so
  an offboarded user (disabled + inactive row) never counts and a user already in (a) is not counted twice.
  `FORCE_CHANGE_PASSWORD` goes to a new list `pending_first_sign_in` (count `pending_first_sign_in`), NOT
  counted in `drift_total`: invitees from C6 sit there until they sign in, and an email-code sign-in may leave
  the status as it is. `RESET_REQUIRED`, `UNCONFIRMED` and other statuses stay drift. The panel shows the
  pending list as a muted readiness line.
- **L2 fixed — email drift.** For a row matched by `(iss, sub)`, a different normalised email (lower-case,
  trimmed) on the two sides is a `group_drift` entry `kind: "email"`.
- **N1 fixed — double click.** `enqueue_manual` checks for an active run and inserts in one transaction
  under `pg_advisory_xact_lock(hashtext('staff_directory_reconcile:manual'))`; `queue.enqueue` takes the
  connection (it only calls `fetchrow` / `fetchval`).
- **N2 not changed.** A re-created Cognito user shows as `row_bound_to_other_sub` in (a) and the row's old sub
  as `unknown_sub` in (b): two facts about two objects, both need the same fix (relink the row). Left as is.
- **Open, check live:** Nghiệp's own `UserStatus` after his email-code sign-in. If it is still
  `FORCE_CHANGE_PASSWORD`, the pending line will list every staff member who signs in that way; that is
  expected and not drift.
