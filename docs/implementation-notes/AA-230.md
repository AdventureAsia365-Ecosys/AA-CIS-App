# AA-230 — Fix Review Queue CORS via same-origin BFF proxy

## Decisions
- Approach Z: route `/admin/review` page calls through a same-origin Next.js BFF
  proxy (`frontend/app/api/pipeline/[...path]/route.ts`) instead of calling the
  ECS API host directly from the browser. Eliminates the cross-origin request, so
  no CORS preflight/headers needed.
- Proxy mirrors the existing admin proxy (`app/api/admin/[...path]/route.ts`);
  only the upstream path prefix differs (`/admin/` → `/v1/pipeline/`).
- Auth: proxy injects server-side `X-Admin-Secret` (ADMIN_SECRET env). Verified
  backend `_get_tenant` (api/routers/v1_pipeline.py:289-303) accepts X-Admin-Secret
  OR Bearer JWT, so the browser no longer needs to send the cookie token.

## Changed
- NEW: `frontend/app/api/pipeline/[...path]/route.ts` — BFF proxy → `${API_URL}/v1/pipeline/...`.
- `frontend/app/admin/review/page.tsx`:
  - 3 fetches retargeted to same-origin `/api/pipeline/review-queue[...]`.
  - Dropped `Authorization: Bearer` headers (proxy authenticates server-side).
  - Removed now-unused `getToken()` calls in onApprove/onReject (kept the one
    in useEffect gate that decides whether the user is logged in).
  - Removed orphaned `const API_URL = process.env.NEXT_PUBLIC_API_URL` (no longer referenced).

## Tradeoffs
- BFF proxy adds one network hop (browser→Vercel→ECS) vs direct call, but removes
  the CORS class of failures entirely and keeps the admin secret server-side.
- Kept the useEffect `getToken()` login gate: with the secret server-side the page
  could load for anyone, but preserving the gate keeps existing UX (no behavior change).

## Should know
- Frontend-only change → ships via **Vercel**, not ECS. Verify on the Vercel
  **Preview** URL `/admin/review` that the queue renders; no ECS digest involved.
- Proxy requires `ADMIN_SECRET` + `API_URL` env vars set in Vercel (same as the
  existing admin proxy — already configured, since /admin pages work).
