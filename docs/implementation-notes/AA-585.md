# AA-585 — GET /tours + GET /tours/{tour_id} unauthenticated legacy routes deleted

## Decisions

- Deleted both routes outright (`api/main.py`), not "add auth" — grep of both Admin and Tenant
  frontends confirmed zero legitimate consumers anywhere, so there was no real usage to gate,
  only legacy pre-`/v1/tours/*` code left over.
- Removed the now-orphaned `get_repo()` dependency (`api/main.py`) and the `RawTourRepository`
  import in `api/main.py` — confirmed via repo-wide grep these were used by nothing else in this
  file. `RawTourRepository` the class itself is untouched (still used by
  `services/ingestion/handler.py`) — only the dead import/dependency wiring in `main.py` went.
  Also removed the now-unused `uuid` import from `main.py` (`uuid.UUID(tour_id)` validation was
  only in the deleted `get_tour()`).
- Updated `tests/load/k6_api_smoke_test.js` (not CI-wired — verified no `.github/workflows/*`
  references it — but a real leftover reference that would have silently 404'd every run) to drop
  its `/tours` and `/tours/{tour_id}` groups/thresholds/metrics, keeping only the `/health` check.
  Left a comment explaining why (routes deleted, `/v1/tours/*` needs a real tenant JWT so isn't a
  drop-in unauthenticated replacement) rather than silently deleting the file's stated purpose.

## Changed

- `api/main.py` — removed `GET /tours` (`list_tours()`) and `GET /tours/{tour_id}` (`get_tour()`),
  the `get_repo()` dependency, the `RawTourRepository` import, and the `uuid` import.
- `tests/load/k6_api_smoke_test.js` — removed `tours_list`/`tour_detail` groups, their `Trend`
  metrics, `API_KEY`/`headers()` (no longer used by anything), and their threshold entries.

## Tradeoffs

- Considered fixing the JOIN instead of deleting (mirroring AA-582's approach for `.../full`) —
  rejected: unlike AA-582's admin branch of `.../full` (which has a real, live caller), these 2
  routes have **zero** consumers in either frontend. Fixing a JOIN bug for a route nobody calls
  would be speculative work; deleting matches AA-579's precedent for genuinely dead routes.
- Did not touch `shared/repository/raw_tour_repository.py` (`RawTourRepository` class) — it has a
  real caller (`services/ingestion/handler.py`), out of scope for this issue.

## Should know

- **Live-verify evidence (see Linear comment on AA-585 for full detail)**: before this fix, the
  routes were reachable unauthenticated via the internet-facing ALB
  (the `aa-cis-dev-alb` DNS name, plain HTTP, no TLS) — confirmed via
  direct curl returning full `raw_tours` rows (`links`/source-scrape URLs, `price_raw`, `provider`)
  with zero headers. Same bypass class as AA-577's Swagger leak. Post-deploy verify should re-curl
  both routes via that same ALB hostname and confirm 404, not just check the primary domain (which
  per AA-583 was already unreachable there before this fix, for an unrelated reason — API Gateway
  never had a resource for these paths at all).
- CloudWatch (`/ecs/aa-cis-dev`, 14-day retention) showed 12 hits/14 days, all 200 OK, but ALB
  access-log-to-S3 only started 2026-09-11 (today) — the 8 pre-existing hits' real source (bot vs.
  human) is unrecoverable. Treat "delete, don't just gate" as the right call regardless, since the
  frontend grep (not traffic) is what actually established zero legitimate need.
