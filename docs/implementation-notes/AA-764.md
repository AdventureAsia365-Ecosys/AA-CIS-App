# AA-764 — T7 slate + T8 angles + T9 fact-select on the worker (G5)

## Decisions
- **No migration.** Two new job kinds (`t7_slate`, `t8_angles`); `shared.job.kind` has no CHECK.
- **T8 "generating" marker** = `status='pending_goal' AND goal IS NOT NULL`. A pending_goal request
  otherwise always has goal NULL (only set_goal_and_generate() writes goal, together with
  'pending_choice'). `start_goal_generation()` claims the request with a conditional UPDATE
  (`... AND goal IS NULL`) and enqueues in the same transaction: a double click gets 409, and a
  crash cannot leave a request "generating" without a job. The job's `on_terminal` clears goal.
- **No idempotency key** on either kind: `shared.job` keys are reused forever, but both actions
  repeat (re-propose, retry a failed generation). Concurrency is guarded instead by the
  conditional UPDATE (T8) and a per-tenant `pg_advisory_xact_lock` + in-flight check (T7).
- **GET /v1/slate is read-only.** It enqueues a proposal only when the tenant has never had a
  successful one or the last is older than 24 h (`SLATE_STALE_AFTER_HOURS`); `POST /v1/slate/refresh`
  enqueues on demand. `unmatched_markets` now comes from the latest successful job's result.
- **Portal status** comes from the domain endpoints, not a new tenant job endpoint:
  `GET /v1/angle-gate/requests/{id}` gains `generating` / `generation_failed`; `GET /v1/slate`
  gains `refresh {status, refreshing, finished_at}`.
- **T9 fact-select** (Jev per fact) moved from `start_write()` (HTTP) into `resolve_facts()`, run
  first in `run_write_background()` (the t9_write job). Old contexts without `facts_pending` are
  untouched, so jobs enqueued before the deploy still work.

## Changed
- `services/jobs/t7_slate_job.py`, `services/jobs/t8_angles_job.py` (new), registered in
  `services/jobs/__init__.py`.
- `services/acp_shared/slate.py`: `latest_slate_job`, `last_proposal`, `request_slate_proposal`.
- `services/acp_angle_gate/service.py`: `start_goal_generation`, `clear_failed_generation`,
  `fetch_request` flags.
- `api/routers/v1_planning.py`: read-only GET, new `POST /v1/slate/refresh`.
- `api/routers/v1_angle_gate.py`: POST goal → 202 via `start_goal_generation`; the 502 path is
  gone (an angle-generation failure is now a job failure → `generation_failed`).
- `services/acp_content_writing/service.py`: `resolve_facts`.
- Frontend: `AngleGateWizard.tsx` polls the request after 202 (and on resume);
  `SlateTab.tsx` shows "last updated / updating…", an "Update topics" button, and re-reads
  quietly every 15 s while a proposal runs.

## Tradeoffs
- After a pick, the Slate no longer re-proposes on reload (it used to, on every load). Topics
  refresh daily or on "Update topics" — the price of not paying Debate on every page view.
- A proposal job holds the deploy guard for its ~3–4 min run. Accepted: it only runs on a stale
  or explicit refresh, not per load.
- Angle generation now has 2 attempts (job retry) instead of one HTTP try.

## Should know
- First load for a tenant with no proposal shows the Slate empty with "updating…" for a few
  minutes, then fills in by polling.
- Integration test `tests/integration/test_aa764_t7_t8_jobs.py` covers the new SQL on real Postgres.
