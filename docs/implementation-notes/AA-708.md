# AA-708 — Sync AA marketing photos from Google Drive (Jira CON PHOTOS) to S3

## Decisions
- **Drive access by API key.** The CON PHOTOS folders are shared "anyone with the link" (checked
  01/10/2026: KOREA, BHUTAN, SRI-LANKA open without sign-in), so a Google API key with the Drive API
  enabled is enough — nothing to share with a service account. The client also accepts a
  service-account key JSON (RS256 assertion via PyJWT[crypto]) for folders that are not public.
  Secret: `aa-cis/dev/gdrive-photo-reader` (`{"api_key": "..."}` or the SA JSON); env
  `GDRIVE_API_KEY` for local runs.
- **No CloudFront yet.** Images are served by `GET /content/photos/{id}?size=large|small`, a 302 to a
  1 h presigned S3 URL (API Gateway `/content/*` has no auth). `cover_image_url` stores that stable
  URL, so CloudFront can come later (Infra) without rewriting rows.
- **S3**: the bronze bucket (`PHOTO_BUCKET` or `BRONZE_BUCKET`), `photos/<country>/<file id>-{1600,600}.webp`,
  EXIF rotation applied, WebP q82. The ECS task role already writes this bucket.
- **Destination matching is opt-in** (`match_destinations`, default off). On 01/10/2026
  `shared.destinations` (1,251 rows, created 11/09 and 29/09) still held places extracted from the
  tours published before the S207 reset (Nghiệp: destinations must come from the rewritten,
  atomized tours). Plan: sync + tour matching now; per country, once its rerun wave is rewritten,
  atomized and re-extracted by the TripPlanner, run the sync for that country with
  `match_destinations: true` — unchanged files are not downloaded again, only re-matched, and
  `fill_destination_covers` sets covers.
- Tour match = folder name ↔ active `raw_tours.src_name` in the same country (exact after
  normalising, else one clear fuzzy best ≥ 0.85). Destination match = file label ↔ destination name
  (exact, else the single longest name contained as whole words). Ambiguous → unmatched → manual.
- A manual assignment or a rejection is never overwritten by a later sync.
- Covers: only empty covers or covers this job set earlier are written.

## Changed (vs. the design in the issue)
- Service account → API key (public folders); CloudFront → public redirect route for now.
- Destination matching deferred (see above). The admin page assigns tours only for now.
- Laos (CON-31) has no folder link on the board — not in `CON_FOLDERS`.

## Tradeoffs
- Redirect route vs. CloudFront: one extra API hop per image, fine for Dev/TripPlanner traffic; no
  Infra change or MFA apply needed to ship.
- No vision model: matching by names only; the unmatched queue covers the rest.
