# AA-769 — Admin Content Quality page

## Decisions
- **New route `/admin/content-quality`** ("08 · Content Quality" in the Social Content sub-nav), not a 6th tab inside
  the 1,408-line atom-curation page (Nghiệp S233: new page, phase out 06 later). UI kit + react-query + URL state.
- **Tabs**: Pieces (T9, every tenant), Tour versions (T2, every tenant), Gate stats (30 days), Place cards (AA-772).
- **API** `api/routers/admin_content_quality.py` (X-Admin-Secret, admin pool): `GET /pieces` (limit/offset/total,
  sort whitelist, filters tenant/channel/status/gate/q), `GET /pieces/{id}`, `GET /stats`, `GET /tour-versions`,
  `GET /tour-versions/{id}`, `GET /place-cards`, `PATCH /place-cards/{id}`, `POST /place-cards/build` (job
  `place_cards_build`, one tour, ≤60 atoms).
- **Counts and filters read `gate_ledger` (+ `flags`)**, never `held_reason` (S232 lesson: it names only the first
  blocking gate).
- **Highlights computed on read** from the violation strings (same parsers as sentence_repair) + `locate_sentence`
  on the final text — works for old rows, no DDL for offsets.
- **Writer input snapshot** (`content_piece.writer_input`, migration 220) written at finalize: seed, route moments,
  facts, scope, brand pack, rubric, angle, goal, keyword, CTA, trip.
- Cost per piece = `llm_call_log` by `content_piece.job_id` (1:1 since the buffer retry is gone).

## Tradeoffs
- Not in the Playwright UI smoke yet: the PR preview talks to the Dev API, which has no `/admin/content-quality`
  until this ships. Add the route to `tests/e2e/smoke/ui-smoke.spec.ts` (readySelector
  `[data-testid="content-quality-ready"]`) in the next PR.
- Pieces written before this PR have no writer input ("Not recorded").

# AA-769 part 2 (S234 PR4) — cut / rewrite a flagged sentence from the drawer

## Decisions
- **Two steps, suggest then apply.** `POST /pieces/{id}/sentences/suggest` makes the one LLM call and writes
  nothing; `POST /pieces/{id}/sentences/apply` is deterministic and is the only write. Cut = apply with an empty
  replacement. A manual edit = apply with the admin's own text (no LLM).
- **Stage `t9_repair`** (decision C2 of the S234 plan): writer, Claude Haiku, Sonnet fallback. Its DB row comes from
  PR1's migration 221; this PR adds no migration and registers the stage in `SAFE_DEFAULTS` with a guarded
  `setdefault` so it merges cleanly with PR1 (which adds the same key to the dict literal).
- **`repair_sentences` generalised, defaults byte-identical** (`stage`, `mode`, `attempt`, `content_piece_id`,
  `max_tokens`). The pipeline call is unchanged (t9_write / attempt 2 / sentence_repair, guarded by a test). The admin
  suggest calls `repair_sentences_detailed` (same body, also returns the model) with stage `t9_repair`, mode
  `admin_suggest`, attempt `None`, `max_tokens=400`, `content_piece_id=<piece>`.
- **Grounding has one implementation**: `service.grounding_text_from(...)`; `_grounding_text(context)` (pipeline) and
  `grounding_from_writer_input(wi)` (admin) both call it; a test feeds one context through both paths.
- **Edit-ready highlights**: each highlight keeps its display span and adds `text`, `sentence_start/end`, `sentence`,
  `key` (sha1 of the sentence, 12 hex). `expand_to_sentence` widens an F9_brand_style phrase to its sentence and never
  crosses a newline. A separate `flagged_sentences` list merges highlights on the same sentence (one row, all gates).
- **Optimistic concurrency without a version column**: the client sends the span text it saw; the server accepts it at
  the given offsets, else at its single occurrence, else 409. A stale or emoji-shifted offset can never cut the wrong
  words.
- **Checks on a replacement** (`sentence_repair.check_replacement`): F1 grounding, F2 banned patterns, brand-forbidden
  words, F11 brand name — run on the replacement only, against the stored source. 422 lists the violations. Suggest
  runs the same checks and returns them so the drawer can warn before Apply.
- **Pieces with no `writer_input`** (written before migration 220): suggest returns 409 (no source to rewrite from);
  cut works; a manual edit is checked against the rest of the piece (a number already in the piece is not new).
- **Cut length guard**: refuse a cut that empties the piece, or that takes it from ≥ the channel minimum
  (`_length_bounds_for_channel`) to under it. A piece already under the minimum can still be trimmed.
- **Admin role**: BFF `canWriteAdminPath` (lib/rbac.ts `API_WRITE_RULES`) returns 403 for a non-GET on
  `content-quality/pieces/*` unless the verified JWT role is `admin`, and forwards `x-admin-role`. The backend also
  requires `x-admin-role: admin` on both new endpoints (a curl with only the secret gets 403 — send the header).
- **Audit**: `acp_shared.audit_log`, actions `content_piece.admin_sentence_cut|_rewritten|_edited`
  (`AdminAuditAction`), actor `admin:<x-admin-user-id>`, details `{start, end, before, after, mode, gate, problem,
  suggestion, suggestion_model, suggestion_cost_usd, length_before, length_after, published}`. Same transaction as the
  UPDATE. The drawer lists the last 50 as "Admin edits".
- **Cost by stage** in the drawer reads `job_id = $1 OR content_piece_id = $2`, so suggestions show as a `t9_repair`
  row. The list/header `cost_usd` stays the write-job cost.

## Changed (vs. the design file)
- Stage `t9_repair` instead of the design's `t9_sentence_edit` (plan decision C2). No migration here (C1).
- `flagged_sentences` is a separate list next to `highlights` instead of merging inside `highlights`, so the inline
  marks stay one per gate (existing tests unchanged) and the action list is one per sentence.
- No optimistic local splice in the UI: Apply returns the full piece detail, which replaces the cached query
  (`setQueryData`), then the list query is invalidated. Simpler, and the server is the only splice implementation.
- Highlight offsets are mapped from code points to UTF-16 in the drawer (`codePointIndex`), fixing the latent emoji
  shift for display.
- `POST /requests/{id}/regenerate-angles` was first left out (not in the PR4 bullet list); added in the review
  round, because the plan's re-measure step names PR4 as its owner (see below).

## Tradeoffs
- `gate_ledger` / `flags` are not recomputed after an edit: they record what the writer produced and keep the gate
  stats measuring the writer. The highlights are re-located on read, so a cut sentence simply stops being highlighted.
- `content_summary` / `content_embedding` are not recomputed (the tenant hand-edit does not either).
- A published piece can be edited (with a warning in the drawer and `published: true` in the audit row); WordPress is
  not re-synced.
- ConfirmModal sits inside the Drawer; Escape closes both (both listen on window). Nothing is lost — no edit was made.

## Should know
- Cost: one suggestion ≈ $0.0013 (social seed, ~0.9k tokens in) to ≈ $0.006 (route blog seed, ~5.2k tokens in) on
  Haiku. Cut and manual edit cost $0. Until migration 221 seeds the `t9_repair` row, the stage runs from
  `SAFE_DEFAULTS` (a "stage missing" warning per call) — same model.
- Merge order with PR2: PR2 also plans `expand_to_sentence` / `tidy_after_cut` in `sentence_repair.py`; whichever
  lands second keeps this PR's versions (they are tested here) and drops its own.
- Merge with PR1: PR1 adds `t9_repair` to the `SAFE_DEFAULTS` literal; the `setdefault` here then does nothing and
  can be deleted in a later cleanup.
- Manual Dev check after deploy (aa-ui-verify): on a held piece, Cut one sentence → text changes, an audit_log row,
  the "Admin edits" section; Rewrite one → an `llm_call_log` row with stage t9_repair, model haiku,
  content_piece_id set. Desktop + mobile, light + dark.

## Review round (S234) — decisions
- **Sentence boundaries** (must-fix): `sentence_repair.is_sentence_end` is now the one rule for "this mark ends a
  sentence": the mark run + closers must be followed by whitespace, a citation tag or the end of the text (so
  `12.5`, `1.5`, `U.S.` never end one), and a period after a short abbreviation list (`Mt. St. Ft. Dr. Mr. Mrs. Ms.
  Prof. Jr. Sr. No. vs. approx. ca. e.g. i.e.`) does not either. `sentence_tail_end` replaces `_SENTENCE_TAIL_RE` in
  both `locate_sentence` (pipeline AA-768 repair too — it had the same half-sentence bug) and `expand_to_sentence`
  (backward and forward walk). The abbreviation list is deliberately short; "We love the U.S. It is big." is read as
  one sentence (an admin would see a longer span, never a fragment).
- **Replacement clean-up** (should-fix): `sentence_repair.sanitize_replacement(text, channel)` — `strip_citation_tags`,
  drop echoed `[Moment id=…]`/`[Fact id=…]` labels, `strip_markdown` on `PLAIN_TEXT_CHANNELS`, collapse whitespace.
  Applied to the suggestion before it is returned and to every apply before the checks, so what is checked, saved and
  audited is the same string. A replacement that cleans to "" is a 422 (use Cut).
- (SUPERSEDED by "Review round 3" below) **Regenerate angles** (must-fix, plan section 3 option A): `POST /admin/content-quality/requests/{id}/regenerate-angles`
  (202, admin role, BFF rule `content-quality/requests/`). One transaction: `FOR UPDATE` on the request; 409 unless
  status is pending_choice/approved/reusable with a goal; 409 while a `t8_angles` job is queued/running or a piece is
  `processing` for it; every option `chosen=false`; status back to `pending_goal` with the goal kept (the tenant
  flow's own "generating" state); enqueue `t8_angles` (same payload as the tenant flow, `created_by=admin:<id>`);
  audit `angle_gate_request.admin_angles_regenerated` with the old angles. No migration.
- (SUPERSEDED by "Review round 3" below) **Option rows are overwritten in place**: `set_goal_and_generate` now upserts (`ON CONFLICT (request_id, idx) DO
  UPDATE … chosen = false`). Deleting them is impossible without a migration (`content_piece.angle_gate_option_id` FK,
  `UNIQUE (request_id, idx)`, `idx` 0-2). On the tenant path the rows never exist yet, so nothing changes there.
- **PR2 overlap** (should-fix): `repair_sentences_detailed` now also accepts the optional `"context"` item field PR2
  adds, so PR4's signature is the superset (`stage`, `mode`, `attempt`, `content_piece_id`, `max_tokens`, context).
  The `t9_repair` `SAFE_DEFAULTS.setdefault` block is now byte-identical to PR2's, so that hunk merges cleanly.

## Stacked on PR2 (feat/aa768-hygiene-scope-seed, S234) — decisions
- **Base**: rebased onto `feat/aa768-hygiene-scope-seed` (which sits on PR1 `feat/aa772-place-card-cost`). Backup

- **`repair_sentences`**: ONE signature — `stage`, `mode`, `attempt`, `content_piece_id`, `max_tokens`, optional
  `"context"` per item — with `repair_sentences_detailed` (returns the model too) as the implementation. The quality
  signal keeps PR2's `source_chars` and PR4's `attempt` (None for the admin suggest).
- **One set of sentence primitives, in `hygiene.py`** (lowest layer; sentence_repair imports hygiene, never the
  reverse): `is_sentence_end` + `sentence_tail_end` (PR4's decimal/abbreviation rule, moved here), PR4's
  character-walk `expand_to_sentence` (passes PR2's test too) and PR2's structural `tidy_after_cut`. `sentence_repair`
  re-exports them (`sr.X is h.X` guard test). `hygiene.sentence_spans` now uses `is_sentence_end` as well, so the
  T9 autofix, the F12/F13 quotes, `locate_sentence` and the admin span all split "Mt. Fuji" / "No. 5" the same way.
- **"No." is an abbreviation only before a number** ("Room No. 5"); "Is it hard? No." ends a sentence. The PR4 list
  had "no" unconditionally, which would have merged a FAQ "No." into the next sentence once sentence_spans used it.
- **`expand_to_sentence` keeps line markers**: a FAQ answer's "A: " and a bullet's "- " / "* " stay out of the span
  (same as `sentence_spans`), so a Rewrite keeps the marker, and a Cut leaves an empty "A:" / "-" that
  `tidy_after_cut` removes (with the FAQ question). Before, a rewrite of an F13-flagged FAQ answer replaced "A: …"
  and broke the FAQ.
- **Hashtag highlights (F13 misspelt hashtag)**: on a hashtag-only line the span is the hashtag token itself, never
  the whole line — Cut drops that one tag, a manual edit replaces it.
- **`tidy_after_cut` merged**: PR2's (empty answers/bullets/sections, trailing-newline kept when the input had one)
  plus PR4's "single stray space at a line start" rule. `apply_edit` keeps the piece's own trailing-newline state.
- **Silent cut fixed**: PR2's `splice` turns a replacement that restates a neighbour into a delete. On the admin path
  that would have saved a Cut when the admin asked for a Rewrite. `splice(guard_repeats=False)` from `apply_edit`;
  `check_replacement(text=, span=)` reports the repeat as an `F13_hygiene` failure instead (suggest shows it, apply
  returns 422).
- **Replacement checks for the new gates**: with the stored `writer_input`, `check_replacement` also runs
  `hygiene.find_issues` on the replacement — `F12_scope` (out-of-scope place) and `F13_hygiene` (source-notes leak,
  social proof). Pieces without `writer_input` keep the AA-769 four gates only.
- **Suggest passes neighbours as CONTEXT** (`sentence_repair.neighbours`), the same way the T9 sentence repair does.
- **highlights()**: the F12/F13 parser (PR2) also takes `F15_voice` (same "<problem>: '<sentence>'" shape, plan C4)
  so PR3 lands without touching the router; F14_social_shape is not sentence-quoted and stays out.
- **SAFE_DEFAULTS**: PR1 has `t9_repair` in the dict; the guarded `setdefault` duplicate is removed.
- **Grounding**: one `grounding_text_from`; PR2's AUDIENCE relabel ("not a fact about this trip") is kept in it, so
  `_grounding_text` and `grounding_from_writer_input` both carry it.

## Review round 3 (stacked review, S234) — decisions
- **Regenerate angles clones the request** (finding: the in-place upsert kept `option_id`, so every old piece's
  joined angle name/style — tenant wizard resume (`_LATEST_PIECE_FOR_OPTION_QUERY`), My Content, the admin
  list/drawer — switched to the NEW angle, and resume could land on an r1 piece). Now: lock the old request, insert
  a new `angle_gate_request` copying tenant/atom/trip/channel/CTA/subject/route_segment_ids/goal with status
  `pending_goal` (goal set = "generating"), enqueue `t8_angles` for the new id with `regenerated_from` in the
  payload, audit on the old id with `new_request_id`. The old request, its option rows and its pieces are never
  written. `set_goal_and_generate` is back to a plain INSERT (no ON CONFLICT). Busy check (409): a `t8_angles` job
  queued/running with `payload->>'regenerated_from'` = this request (double click). The pieces-processing check is
  gone — nothing on the old request changes now. Response: `{request_id: <new>, regenerated_from, job_id, status,
  goal}`.
- **One boundary rule, really**: `_SENTENCE_END_CHARS` = `.!?…`, `_CLOSERS` adds `*` (matches `_SENT_END_RE`), and
  `sentence_spans` calls `is_sentence_end` for every mark (no ellipsis bypass). `expand_to_sentence` walks back over
  a whole closer run (`.**`, `?”)`) before testing the mark. "**Day one.** We drive" is now two sentences in the
  T9 autofix, F12/F13 quotes, `repeats_neighbour` and the admin span alike.
- **Ordinals / units**: the abbreviation word must be a whole word (`(?<![A-Za-z0-9])`), so "1st." / "21st." end a
  sentence again (attempt-2 `locate_sentence` no longer swallows the next sentence). `ft` (and km/mi/hr/hrs/min/mins)
  moved to `_UNIT_ABBREVIATIONS`: an abbreviation only when the text runs on in lower case or a digit ("4,000 ft.
  above the valley"); "4,000 ft. The trail" ends. `m` left out on purpose (would catch "I'm.").
- **FAQ question lines**: `expand_to_sentence` on a `**Q: …**` line returns the question text inside the markup.
  `apply_edit`: a Cut of a question removes the whole Q line plus its "A:" answer block (up to a blank line, the
  next question or a heading; `tidy_after_cut` then drops an emptied FAQ heading); a Rewrite replaces only the
  question text and strips any `**Q:` / `**` the admin typed, so the markup stays exactly once.
- **Blocking vs warning on the admin path** (plan section 4 PR4 lists F1/F2/F2_brand_forbidden/F11 only; PR2 keeps
  F12 warn-only until the replay shows 0 FPs): `check_replacement` returns `[{gate, violations, blocking}]`.
  Blocking: F1, F2, brand-forbidden, F11, and a **near-verbatim** neighbour (`hygiene.near_verbatim`, the pipeline's
  auto-delete rule). Warning: F12_scope, F13 leak/social proof, and a looser `restates` neighbour hit. `/apply`
  422s on blocking only, otherwise saves and returns `warnings` (also stored in the audit details); the drawer
  shows blocking checks in red ("would be refused") and warnings in amber ("Apply still saves"), and toasts the
  warnings after Apply.

## Review round 3 — tradeoffs / should know
