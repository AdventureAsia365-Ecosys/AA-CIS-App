# AA-213 — Observability metadata (fallback_used + score_overall + batch_id)

## Decisions
- Persist three previously log-only/unused signals into `generated_content.metadata`:
  `score_overall` (was unused/null), `fallback_used` (silent Sonnet→Haiku fallback, was log-only),
  `batch_id` (traceability back to pipeline_runs).
- `fallback_used` captured in generate_node SUCCESS return only (resp exists there). Error branches
  left untouched — referencing resp there would NameError.
- `_build_generated_metadata` gains a `batch_id=None` kwarg rather than reaching for `req` (it never
  received req); call site passes `getattr(req, "batch_id", None)`.

## Changed
- graph.py: ContentState +1 key (fallback_used); generate_node success return +1 key.
- admin_pipeline.py: _build_generated_metadata signature +batch_id kwarg; base metadata dict +3 keys;
  call site passes batch_id.

## Tradeoffs
- score_overall duplicates quality_scores.score_overall (separate table) but lands inline in the
  metadata JSON so a single generated_content read carries it without a join.

## Should know
- fallback_used flows graph state → _rewrite_tour result dict → _build_generated_metadata, same path
  as the AA-209 judge_* fields (which had a prod no-op bug from missing propagation). _rewrite_tour
  must carry "fallback_used" out of graph result for this to be non-null — verify propagation.
