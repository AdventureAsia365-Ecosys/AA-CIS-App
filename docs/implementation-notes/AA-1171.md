# AA-1171 — Alerts catalogue P0 (CIS part)

Lane l12 of S287. Tech lead decisions D1–D11 (S287 alerting decision page; root
`docs/audits/2026-11-21-S287-alerting-inventory/README.md` section 8). Infra, Booking, Partner and root parts have
their own notes in their repos.

## Decisions

- **One source (D1)**: `api/services/alerts_catalogue.py` builds one document; `GET /admin/platform/alerts/catalogue`
  returns it, `GET /admin/platform/alerts/summary` returns its counts and firing rows for the Ecosystem status card
  (no second list). Both `ops.read`.
- **Row = alert condition**: a CloudWatch alarm, an EventBridge rule whose targets include an SNS topic, a budget or a
  cost anomaly subscription, an in-app check (CIS fixed checks one row each; per-stage families and digests one row
  each, named `<prefix><stage>`).
- **App / severity from tags**, not names: `tag:GetResources` (one paged call), `ListTagsForResource` per ARN when it
  is refused. Overview › Apps health uses the same rule (App tag, name prefix as fallback) and adds `alarm_totals`.
- **CloudWatch thresholds stay Terraform-owned (D2)**: `editable_via = terraform` with a GitHub code search link of the
  name without its interpolated prefix (the Terraform file holds the literal suffix). No PutMetricAlarm anywhere.
- **In-app thresholds are settings (D3)**: CIS 469 adds `cis.ops.*` (15 keys, maker-checker, today's values as
  defaults: the 8 state / spend / default bell keys, plus, after review, the quality funnel floor / drift share /
  new-model share, the reply cut share shared by `route_cut` and `qf_cut`, and three family bell windows); `shared/ops_thresholds.py` is the only reader (ships in the migration PR for the settings-lint reader
  check); `shared/ops_checks.py`, `shared/jobs/backlog.py`, `services/reports/reliability.py`,
  `services/recompute/lifecycle.py`, `services/acp_contract/research_coverage.py`,
  `shared/llm_client/route_watch.py` and `services/quality/funnel.py` read it on every evaluation.
- **Bell windows per family (review fix)**: `Check.bell_key` names the window setting (default 6 h; route 1 h for
  `route_fb` / `route_last`; daily 24 h for stage coverage, `route_cost`, `route_cut`; nightly 20 h, bounded 12-23 h,
  for the research checks, `route_digest` and `qf_*`). `Check.bell_every` is now a property that reads it.
  `route_back` keeps a fixed 1-minute window marked `# technical-constant:` (route_watch raises it once per
  recovery; the window only folds two raises of one tick).
- **Peers without cross-schema reads**: Booking `GET /booking/ops/checks` and CRM `crm.ops.v1 GET /ops-checks`, each the
  app's own registry with the values in force, called with the staff member's Cognito token (the CRM console relay;
  `crm_console.ALLOWED` gains `GET /ops-checks`). A peer that does not answer drops its rows and says why in
  `freshness`.
- **Budgets (D7)**: acc2 from the Platform › Infra read (the Terraform docs output), acc1 / acc3 / management static
  (`EXTERNAL_BUDGETS`), account IDs at run time only (`accounts.account_id`, env `AWS_MGMT_ACCOUNT_ID`).
- **Recipients on two topics (D5)**: `shared.alert_recipient.topic` (CIS 469); "All alerts" (alerts topic) or "Page
  alerts only" (page topic, `PAGE_TOPIC_ARN`). Reconcile per topic; the bootstrap lives on the alerts topic and is
  refused on both; the CIS ops e-mails (spend, settings) go to the `alerts` rows only (they are ticket-level).
- **Coverage gap column**: per row (no Severity tag, no action, insufficient data, actions disabled, in-app check
  silent while its API is down, static budget without live state) plus a list of
  known gaps (no synthetic check, Sentry / CI / vendor mail not listed, a single alerts recipient, no page recipient).
- **UI**: Platform › Alerts has two tabs (Catalogue default, Recipients); one PageFrame in `page.tsx` (adminFrame test);
  nav label "Alerts". KPI tiles, breakdown by type and app, sources with freshness, URL filters (app, type, severity,
  state, changed in, gaps), DataTable with CSV, the known gaps. English by default; no issue ids in UI text.

## Changed

- `STALE_SHARE_LIMIT`, `LAG_LIMIT_S`, `ROLE_CONNECTIONS_PCT`, `XID_AGE_LIMIT`, `JOBS_STARVED_AFTER_S`,
  `SPEND_NEAR_RATIO`, `BELL_EVERY` and both `OVERDUE_FACTOR` constants are gone; the settings-lint baseline shrank by
  four entries. Check texts no longer state numbers; the finding carries the threshold in force.
- Review fix: funnel `MIN_REQUESTS`, `DRIFT_ALERT_PCT`, `DRIFT_NEW_MODEL_PCT`, `THRESHOLDS` (now `thresholds()`, the
  values in force stored in each CIS-08 snapshot), route_watch `CUT_ALERT_PCT` and every `bell_every=timedelta(...)`
  literal of `shared/ops_checks.py` are gone; the governed baseline lost three entries and the rest baseline one. The
  catalogue no longer reports "Threshold is a code constant" for the `qf_` rows; each CIS check row names its bell
  window key in `threshold_source`.
- Readiness requires 469 (`REQUIRED_CIS_ABOVE_GAP`): the recipients reads name the new column.
- The `platform-alerts` UI smoke entry opens `?tab=recipients`; a new entry checks the Catalogue tab.

## Tradeoffs

- Peer registries over HTTP rather than a vendored JSON: the thresholds shown are the live values (they are settings
  now), at the price of a token-bound read (a legacy password session sees the two peer sources as unavailable).
- The CIS check rows show `ALARM` while the last bell is inside the check's bell window: a good-enough live state
  without a new table (D11 keeps ack / history for the pilot).
- Budgets are not read live (no Budgets grant): the spend against them is on Spend › AWS bill.

## S287 live-check follow-up (fix/aa1171-catalogue-text)

- **Changed:** catalogue descriptions of CloudWatch alarms and EventBridge rules drop tracker references
  (`strip_issue_refs`): the live check found 31 rows showing 14 issue IDs copied from the Terraform descriptions. Only
  `AA-<n>` is removed; runbook ids (CIS-08) and event codes stay. The Terraform descriptions keep their references.
- **Changed:** the CRM `/ops-checks` relay uses the 5 s list timeout (a cold CRM task answered in 3.8 s, over the 2 s
  read timeout, and the catalogue lost the 19 CRM rows); the peer section is cached 30 s instead of 300 s, so one slow
  peer call no longer hides its rows for five minutes.
- **Changed:** Overview › Apps health says "CloudWatch alarms" (it counts alarms only; in-app checks are on the
  Catalogue), so it no longer reads "none firing" while a CIS in-app check fires.
