# AA-1027 E4 + E5 — CIS side (lane l3-e4e5-tp, S265): migrations 350 and 351

Root plan: `docs/audits/2026-11-01-S263-gateway-gap-audit/plan.md` rows E4 (gap TP-5) and E5 (gap TP-1). The
TripPlanner side (view-only reads, fail closed, stage x model params applied to the request body) is
AA-TripPlanner-Web `docs/implementation-notes/AA-1027-l3-e4e5-tp.md`.

## Decisions

- **350 appends two columns** to `catalog.v_llm_gateway_config_v1`: `supports_temperature` (catalog) and
  `stage_params` (one jsonb object per stage x model: max_tokens, min_output_tokens, temperature, effort,
  reasoning_mode; NULL when no row). One object rather than five typed columns, like `deployments` /
  `deployment_routing`: a later field of `stage_model_params` goes inside the object, not into a new view column.
  `notes`, `created_at`, `updated_at`, `updated_by` are not exposed (catalog_owner has no SELECT on them; the guard
  checks it).
- **The 341 body is repeated byte for byte**; the only additions are the two columns and one LEFT JOIN on the table's
  primary key (stage, model_key). The integration test compares the column list and the per-stage join (another
  stage's row of the same model never shows).
- **351 = REVOKE ALL** on the two tables from `tripplanner` (table-level REVOKE ALL also removes column grants), with
  the 270-style guards: nothing left on either table (a grant by another grantor fails the apply and names it), only
  `llm_call_log` left on schema `shared`, the ledger INSERT and both contract views still readable.
- **Both files are contract** (ACL changes on existing tables, a replaced view): no `-- migrate:` directive, no
  readiness raise (MIG-4). Preflight locally: lint ok, class contract, refused only on the number (see below).
