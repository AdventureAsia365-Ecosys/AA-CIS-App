# AA-763 — T-series stage keys (G4)

## Decisions
- Route keys only. New keys: `t2_judge`, `t2_brand_audit`, `t2_flag_fix`, `t2_itinerary_nudge`
  (T2 run of the shared S1 graph) and `t7_debate_judge` (T7 Debate brand fit). Jev stage labels
  (`s1_grounding` on the T2 meal-time check, `t2_judge_tiebreak`, `t3_grounding`, `t7_debate`) are
  not route keys and are left as they are.
- One helper, `services/content_generation/stages.py::stage_for(state, a1_stage)`, derives the T2
  twin from `state["is_tenant_rewrite"]` — no new graph-state field (LangGraph would strip an
  undeclared one), same branch judge_node's tie-break already uses. Call sites without `state`
  (`nudge_itinerary_day`, `_process_itineraries`, `_rerepair_meta`, `brand_fit._judge`) take a
  `stage=` keyword defaulting to the old `s1_*` value, so A1 is byte-identical.
- **Reverses AA-620's "flag_fix / itinerary_nudge stay shared"** — the issue scope lists
  `t2_flag_fix`; the cost/routing split is the point of G4. Models are unchanged.
- Migration 219 copies each A1 twin's **whole row** (model, fallbacks, account, shadow model and
  %), so routing and the 10 % judge shadow (AA-714 A/B) behave exactly as before; a DO block fails
  the migration if a twin row is missing. SAFE_DEFAULTS mirrors the twins.
- `grounding.py`'s `s1_flag_fix` repair is A1-only (the node returns early for T2) — untouched.

## Changed
- `services/content_generation/{stages.py (new), brand_fit.py, judge_node.py, brand_audit_node.py,
  flag_fix_node.py, itinerary_utils.py, graph.py}`, `services/acp_shared/debate.py`.
- `shared/llm_client/role_config.py` SAFE_DEFAULTS; `services/acp_shared/writing_progress.py`
  TOUR_STAGE_STEPS (or the T2 progress bar stops advancing).
- `api/migrations/219_t_series_stage_keys.sql` (+ identical Infra copy).
- Admin `frontend/app/admin/settings/llmShared.ts`: T2 group lists the new keys, new T7 group
  (the Models tab only shows stages listed there).

## Tradeoffs
- `stage_for` maps by `is_tenant_rewrite`, not a per-node state field: one rule, but a future
  third flavour of the graph would need a real field.
- Historical `llm_call_log` rows keep `s1_*` for T2 work before this deploy (tenant_id set since
  G1, so they can still be split by tenant).
