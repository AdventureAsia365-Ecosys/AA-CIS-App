# AA-1144 — CIS part: agency facts and the T2 fact lock (S285 decisions D7, D8)

The CRM part of AA-1144 (closed list of agency lines, crm-080) shipped in AA-Partner. Facts Entries and the agency T2
copy live in CIS, so the cross-app permission review (root `docs/audits/2026-11-19-S285-session/
advisory-r3-permissions-cross-app.md`, gaps P4 and P5) added this CIS slice. D9 (AA item names in CRM quotes) is in
AA-Partner.

## Decisions

- D7: the agency kinds are `("booking_terms",)` (`facts_store.AGENCY_FACT_KINDS`). The advisory says markup is a CRM
  price rule, not a fact, so `price` is not an agency kind (the Partner studio form offered price + booking terms
  after the CRM PR; the Partner PR of this lane narrows it).
- The rule sits in `facts_store` (scope `tenant`), not only in the router, so every tenant write path gets it. Staff
  platform facts keep every kind.
- An older own fact of a locked kind: listed with `read_only: true`, deletable, never edited (a PATCH of it, even a
  kind change to booking terms, is 422: re-typing a price into "booking terms" would keep the number alive).
- "No longer override AA facts" is done by leaving such facts out of every writer read: the SQL (`kind = ANY($3)` on
  the tenant half) and `pick_facts` (for other callers such as the AA-1047 measure script). T9 and T2 (`T2_FACTS`)
  read the same function; TripPlanner and CRM quotes never read `acp_shared.facts`.
- D8: "fact fields" are the facts the FactSheet tour builder already extracts (`services/quality/s1_facts.py`): day
  markers, figures with their unit, place names, "not included" item groups. The T2 content has no separate fact
  columns (it is `name`, `subtitle`, `summary`, `highlights`, `itineraries`, `seo_*`), so the lock compares facts
  inside the text, plus any key outside those wording fields (duration, price, inclusions ...).
- Base = the version being edited + the Master (`aa_*`) + the raw source (`src_*`, duration, price_raw, inclusions,
  exclusions). Facts already in the AA-written copy (e.g. from platform facts) never block a wording edit.
- Places are checked in `highlights` and `itineraries` only: the name, summary and SEO lines carry the agency's own
  brand words, which would read as new names.
- A figure with a unit must match the same unit ("3 nights" never clears "3 days"); a bare figure matches the number.
  A label figure ("USD 390": the reader takes a capitalised word before a number for a label) counts as a fact.
- The edit is laid over the version (fields not sent are kept). Before, the stored version was exactly the sent dict;
  the Content studio sends no itinerary, so an edit used to drop the T2 itinerary (the display fell back to the
  Master's). Keeping it is the safe reading of "wording stays editable".
- `edited_by_user` = `tenant:<tenant>:<membership>` from the token; `body.edited_by` is ignored (kept in the model so
  old clients do not 422).
- Audit: `tenant_tour_version.edited` (membership, new version id, per changed field the old / new sha256) and
  `tenant_tour_version.edit_refused` (the locked list), on MAIN after the tenant transaction, best effort like the
  Facts Entries audit. `actor` is `tenant:<id>` (the column is 64 characters; the member is in `details`). Both are
  tenant-visible in Account › Activity (the allowlist test requires every TenantAuditAction there).

## Changed

- No migration: the CHECK of CIS 302 keeps every kind for the older rows.
- `GET /v1/facts`: `kinds` is now the agency kinds only; own facts carry `read_only`; `overridden_by` comes from the
  agency kinds only. openapi.json regenerated (the `read_only` field).
- `PATCH /v1/tours/versions/{id}` (edit): 422 `fact_locked` with `{code, message, locked}`; merged content; editor
  from the token; audit rows.

- Review pass (three reviewer findings, all confirmed by a probe on an invented tour and fixed):
  - Spelled-out durations: `_word_figures` reads "two"..."twenty" (and thirty / forty / fifty) before day / night /
    hour / week as a figure, in the base and in the edit, so "A two-day walk" on a 3-day tour is `figure`. "one" is
    left out ("one day you will ..." is an idiom).
  - Inclusions: a new "included" claim (include / cover / provided / comes with, a clause not "not included" and not
    optional, cut before "except") is locked (`fact: included`) when the source excludes the group (raw exclusions
    lines that are not conditional, any "not included" clause of the base; "meals" when any meal is excluded) or no
    base text names the group outside a "not included" clause. A claim the version already makes is kept. The raw
    exclusions list is never a base for a claim (its lines carry no "not included" word).
  - Place base: highlights / itinerary of the parent + Master / raw texts, never the parent's name / summary / SEO
    lines, so a place first put in the summary (free) does not clear it for the itinerary in a second edit. Each
    saved edit was checked against the same rule, so the chain of tenant edits cannot widen the place base.
  - "not included" groups are read per clause ("Lodges are included, but flights are not included" excludes flights
    only); before, the whole sentence counted and "accommodation" read as excluded.

## Tradeoffs

- The text checks can refuse a harmless edit (a new capitalised word in the itinerary whose words the base never
  uses). The 422 names the field and the value, so the agency rewords it; a false refusal is safer than a changed
  fact reaching TripPlanner. Spelled-out durations ("a two-day walk", "three nights") are read since the
  review pass (see Changed); other spelled-out numbers are not (the FactSheet reader does not read them either).
- Dropping a figure or a place passes: less detail is not a different tour. Dropping a "not included" item does not
  pass (the advisory's example: removing "flights not included").
- The lock lives in CIS; the Partner studio only shows the refusal. A second client would get the same 422.

- An inclusion verb used loosely ("Highlights include the boat transfer") reads as a claim; it is refused only when
  the base never names that group outside a "not included" line, so a false refusal names the group and the agency
  rewords it.

## S285 follow-up: gaps found by the live check (lane l23)

The live check after the CIS fact-lock PR (root audit folder `docs/audits/2026-11-19-S285-session/aa1144/`) refused
"23-day", "eleven-day" and "$4,999" but let two fact changes through with 200, and found two side defects.

### Decisions

- Root cause 1 ("This seven-day trek" -> "This ten-day trek" saved): the figure base held every raw source text, and a
  raw "10 days" (another departure, a visa rule) cleared the new length. Reproduced on an invented tour with the old
  module. A day / night / week figure is now checked against `master_length` (the Master's day count: the last
  "Day N" of the Master itinerary, else of the version, else the raw duration; nights from the raw duration when it
  gives the same day count, else one fewer; weeks when the days are whole weeks) plus the day / night / week figures
  AA wrote (the version and the Master texts). Raw texts no longer clear a length. Digits and spelled-out numbers
  ("ten-day", "10-day", "ten days") alike, in every wording field.
- Root cause 2 ("International flights included." saved): the claim passed when any base text named the item group
  outside a "not included" line, so "a scenic flight ..." in a raw text cleared "flights included". A new claim now
  needs the Master to state it: the version or the Master text says the item is included, or the raw inclusions list
  names it. Claims carry a scope ("international" / "domestic", from the word right before the item): a scoped claim
  is cleared by the same scope or by the whole group; an unscoped claim needs the whole group, and any scoped
  exclusion of the group locks it.
- The raw inclusions list counts as the Master's statement: `published_tours` has no inclusions column, and the
  studio shows `raw_tours.inclusions` as the tour's inclusions (GET /v1/tours/versions/{id}).
- `check_edit` takes `master_texts`, `source_inclusions` and `duration` as keyword arguments; `check_against_base`
  passes them from the same base row (`MASTER_KEYS` = the `aa_*` columns). No SQL change.
- GET /v1/tours/mine answered 500: no `/mine` route exists, so "mine" reached `/{tour_id}` and the `$1::uuid` cast
  failed in Postgres. Every path id of the tenant tours router (`/{tour_id}`, `/{tour_id}/full` after its auth,
  `/pool/{id}/rewrite`, `/versions/{id}` GET / PATCH / export / retry) is now a 404 when it is not a UUID, before any
  database work (`_require_uuid`, the value passes through unchanged). A literal `/mine` route was not added: nothing
  calls it; the studio's list is `/my-versions`.

### Changed

- `services/content_generation/t2_fact_lock.py`: `LENGTH_UNITS`, `master_length`, scoped inclusion claims
  (`_scoped_groups`, `_claims`, `_listed`, `_excluded`, `_covers`); `_mentioned_groups` / `_claimed_included` /
  `_excluded_groups` removed.
- `api/routers/v1_tours.py`: `_require_uuid` on every path id.
- Tests: `tests/unit/test_aa1144_s285_fact_lock_gaps.py` (the two live cases and their negatives),
  `tests/unit/test_aa1144_s285_tour_path_ids.py`; `test_aa1144_t2_fact_lock.py` passes the raw inclusions list;
  `test_aa741_preaudit_hardening.py` uses a UUID tour id.
- The studio save (AA-Partner web) sends only the fields the agency edited; the CRM builder logs its refusal codes
  (both in the Partner PR of this lane).

### Tradeoffs

- A day / night figure that AA wrote anywhere in the version or the Master clears that figure everywhere ("two days at
  the summit camp" lets an agency write "two days" in another sentence). The rule refuses lengths that no AA text
  states, which is what the live check found; telling a sub-trip length from the tour length would need sentence
  parsing the FactSheet reader does not do.
- An inclusion claim the raw source text makes but the Master does not is refused (the Master is what AA operates).
- "Flights included" is refused when the Master only includes domestic flights: the broader claim is a different
  fact. The agency keeps the scope word.
