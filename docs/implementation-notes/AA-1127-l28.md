# AA-1127 lane l28 (S285) — daily Cost Explorer check (C2) and the Dev test-data clean-up (D1)

Tech lead decision S285 evening: E2 = a daily Cost Explorer check (~0.02 USD per run, ~0.6 USD a month), on/off and
frequency as settings; E3 = rename or retire the Dev test tenants and staff named with issue ids, never delete, keep
every E2E identity in use.

## Decisions

- **Scheduler: the existing daily-job pattern, no new mechanism.** Job kind `cost_explorer_refresh`
  (`services/jobs/cost_explorer_refresh_job.py`) on the CIS job runner, queued by the api's ops metrics sampler once per
  UTC day with an idempotency key `cost_explorer_refresh:<day>`, exactly like `llm_cost_reconcile`,
  `llm_model_lifecycle_sync` and `llm_connection_probe`. The difference: the switch and the hour are settings
  (`cis.spend.ce_daily_refresh_enabled`, `cis.spend.ce_daily_refresh_hour_utc`, CIS 461), not an env var and a literal.
  No Infra change: the worker uses the same task role as the api (`ce:GetCostAndUsage` and the acc3 AssumeRole are on
  it since AA-623).
- **One run = the same two reads as `POST /admin/cost-explorer/check`**: per account and service (acc2 + acc3) and acc2
  by App tag, so the forecast's AWS rows, the AWS bill tab, By app and the nightly LLM cost reconciliation all read
  current data. The window is the month to date, started `FINAL_AFTER + CE_LAG` (5 days) back so every day gets one
  fetch after Cost Explorer stopped revising it; a unit test simulates a month of daily runs and checks the By app lazy
  refresh then finds nothing stale (so the lazy path no longer pays on its own).
- **Default hour 01:00 UTC**: before the 02:00 UTC `llm_cost_reconcile`, which reads the stored CE snapshot for Bedrock.
- **Cost line**: the CE client counts requests (`fetch_all_accounts_cost(..., stats=)`, pages included, failed accounts
  too); the run reports `requests x 0.01 USD` as the job's own cost (`shared.job.cost_usd`) and in its result. The lazy
  path only logs its estimate; there is no other ledger for AWS API calls. The real charge appears as the "AWS Cost
  Explorer" service line of acc2 in the snapshot.
- **Stale badge from the newest fetch of each snapshot**: `freshness()` takes the older of the two `max(fetched_at)`
  (both indexed), stale when older than `cis.spend.ce_stale_after_hours` (default 36 h = one daily run + slack) or when a
  table is empty. Display only. Added in the two routers (`GET /admin/platform/cost`, `GET /admin/cost-ops/forecast`)
  rather than inside `cost_by_app` / `cost_forecast`, so the Overview card and the money report keep their shapes and
  their mocked-pool tests; it never raises.
- **Registered everywhere a kind must be**: `services/jobs/__init__.py`, the background kinds list of
  `tests/unit/test_aa737_worker_throughput.py`, and `capacity.KIND_LINES` (`None`: no LLM call). The sampler part lives
  in the job module (`sampler_part`) and runs under `_guarded_part`, so `sample_once` keeps its complexity and the
  sampler file stays under the 800-line limit (code_health ratchet).
- **max_attempts 1**: a failed paid read is not retried; the next day's run, the lazy refresh or the button cover it.
  Not deploy-gate exempt (a run released by a deploy pays again).
- **E3 is a script, not code in the repo**: `.tmp-session/S285/aa1127/aa1127_dev_hygiene.py` in the root workspace,
  run by the orchestrator with `tools/ecs/ecsx.sh` (cis_app can UPDATE `shared.tenants` and `shared.admin_users` and
  INSERT `acp_shared.audit_log`; no master needed).

## Changed

- Requested ~0.02 USD a run; a run is 3 requests (2 accounts by service + 1 App tag), so ~0.03 USD a run, ~0.9 USD a
  month. The App-tag read keeps By app current too (otherwise By app pays the same request lazily on the first view).
- `shared/aws_client/cost_explorer.py`: an optional `stats` keyword on `fetch_all_accounts_cost` /
  `_fetch_one_account_cost`; callers without it are unchanged.

## Tradeoffs

- A setting change of the hour applies from the next UTC day once today's run exists (idempotency key per day).
- The stale rule uses the newest fetch of the whole table, not of the viewed month: the badge answers "is the daily
  check working", the month's own coverage stays in the existing "covers … last fetched" line.
