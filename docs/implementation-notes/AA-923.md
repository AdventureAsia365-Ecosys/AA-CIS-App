# AA-923 — Writing memory: labels for T2/A1, offboarding deletion, retire the old lesson paths

Covers WM-32 (labels on T2 versions and A1 content), WM-33 (offboarding deletion of learned tenant data) and WM-34
(retirement of `shared.pipeline_lessons`, `acp_shared.acp_output_rules`, `/v1/rules` and the dead rule adapter code).
Spec: root `docs/audits/2026-10-20-S245-writing-learning-loop/issues/README.md` Group 9.

## Decisions

- **WM-34 is two PRs, code first.** The code PR removes every reader and writer (the `/v1/rules` router, the
  AA-132 lessons loader and write-back, `api/services/acp_post_processor.py`, `services/acp_produce/rule_adapter.py`
  and their tests). A separate migration-only contract PR then quarantines both tables in `retired` (DM-3.9: candidate
  → quarantine → drop after >= 14 days), so the deployed code never reads a table that is gone. The drop itself is
  a later migration (after the 14 days and a second DRY RUN), not part of this issue's code.
- **Quarantine, not DROP, in this issue.** The spec says "drop tables"; the data standards (DM-3.9) and the
  AA-850 precedent (CIS 294 → 296) require the reversible quarantine step first. "Schema reference PR shows the
  tables gone" is met for their source schemas the night after the quarantine apply.
- **`api/core/staff_secret.py` stays.** Its only router was `/v1/rules`, but it is a staff/machine auth guard, not
  a lesson path, and AA-923 does not name it. Deleting an auth module is a separate, reviewed auth change. The S241
  route-auth tests keep exercising it on a probe router with the old `/v1/rules` shape.
- **The `/v1/rules` prefix stays in `STAFF_PATH_PREFIXES`** (and in the BFF mirror `STAFF_API_PREFIXES`), like
  `/v1/social` after AA-850: the prefix is fail-closed staff-only, so a route added there by mistake later still
  goes through the staff middleware and POLICY. Only the POLICY entry of the removed PATCH route goes. After deploy
  `/v1/rules` answers 404 (no route); a unit test checks the real app.
- **`flag_fix_node._write_lessons_safe` stays as a logging no-op** (the AA-729 harness and unit tests patch it by
  name); `write_lessons_log` and the frozen flag are gone.
- **`scripts/aa729/select_samples.py` keeps its `lessons_text` parameter** fixed to `""` so the frozen golden-set
  samples stay byte-reproducible.

## Changed

- Removed: `api/routers/v1_rules.py`, `api/services/acp_post_processor.py`, `services/acp_produce/rule_adapter.py`,
  `services/content_generation/pipeline_lessons.py`, their tests (`test_aa363_rule_adapter.py`,
  `test_acp_post_processor.py`, `test_output_rules.py`, `test_aa915_pipeline_lessons_frozen.py`).
- `api/main.py`: the `/v1/rules` router is no longer included. `api/core/staff_authz.py`: the PATCH POLICY entry
  removed; prefix comment updated. Route-policy snapshot regenerated (two `/v1/rules` rows gone).
- The three S1 prompt builders (`admin_pipeline._execute_run_tour`, `s1_batch._load_prompt_state`, the AA-645
  shadow script) no longer call the lessons loader (it returned "" since AA-915: prompts are unchanged).
- New guard `tests/unit/test_aa923_retired_lesson_paths.py`: no runtime file queries either table, the four modules
  stay gone, the lessons hook sends no SQL.
- `CONTEXT.md`: the "frozen predecessor" paragraph is now "retired predecessor".

## Tradeoffs

- Keeping `staff_secret.py` leaves a guard with no router; the alternative (delete it now) widens a lesson-retirement
  PR into an auth change. Follow-up noted for the orchestrator.
