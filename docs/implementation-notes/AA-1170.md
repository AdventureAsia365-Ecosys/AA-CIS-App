# AA-1170 — Compliance readiness page (phase 1)

Lane l10 of session S287. Decisions Q1–Q17 of the S287 decision page (Linear issue AA-1170); advisory: root
`docs/audits/2026-11-21-S287-compliance-tracking/README.md` sections 4 C.1–C.7, 5 (phase 1) and 8.

## Decisions

- **Two CIS PRs (MIG-4).** The migration-only PR carries CIS 466 (schema `compliance`, the requirement catalogue seed,
  the seven `cis.compliance.*` settings, `compiled_defaults.json`, `api/services/compliance_settings.py` naming the keys).
  The code PR carries an identical copy of `compliance_settings.py` (the module the code imports) and raises readiness
  to 466; it is branched from `main`, not stacked.
- **Evidence path, phase 1 (Q7).** The root workflow `compliance-evidence.yml` publishes ONE file,
  `docs-reader/compliance/evidence.json` (plus a per-day copy), with the existing Docs sync role, like the Delivery page.
  CIS reads it under the docs-reader grant (nothing new in Terraform, no Infra change for the evidence path).
- **Ingest on read.** The overview reads the published file (cached 5 minutes per process) and inserts its rows; the
  unique `(source, check_id, collected_at)` makes it idempotent. The Refresh button (`compliance.write`) skips the cache
  (at most every 30 s). No worker job in phase 1 (the DB collector job is phase 2).
- **Stale is computed at read time** from the CURRENT validity setting of the source (`valid_until` stored at ingest is
  also honoured, whichever ends first). That is what makes "set a short validity window in Settings and the score drops"
  work live (Done-when).
- **Facts graded in CIS, not in the collector.** For drill age, access review age and overdue docs the collector
  publishes the fact (a date or a count) and `pass` when it read it; CIS grades the fact against the settings. The
  thresholds therefore live only in the admin settings (tech lead S279), never in the public collector.
- **Score definitions.** Check -> control (all required checks pass = met, some = partial, none and one stale = stale,
  else gap; no automatic check = no evidence, counted as gap) -> requirement (a full-coverage control met = met; any
  partial = partial; unmapped requirements count in the denominator). Strict = met / n, weighted = (met + w x partial) /
  n. EU AI Act is scored the same way but the card says it is a legal checklist for counsel (Q14 keeps PDPL / GDPR out).
- **Capabilities.** `compliance.read` (every GET) and `compliance.write` (Refresh), administrator only (Q10). They are not
  `.approve` capabilities, so a custom role may be given them (CIS 462 CHECK).
- **Register loader.** `scripts/compliance/load_register.py`: stdlib + asyncpg, runs as one downloaded file over the
  S3-mediated ECS exec as `cis_app`, DRY RUN by default; upserts controls, deactivates controls missing from the file
  (never deletes: evidence history), replaces the whole mapping table (the file is the complete register). Refuses ids, frameworks, refs or text
  the tables would refuse, and text with an account ID, an ARN, an S3 URI or an e-mail address.

## Changed

- The advisory proposed `cis.compliance.validity_days.{daily,...}` per frequency; the migration (already committed
  before this resume) has one key per evidence source (`cis.compliance.validity_hours.root_daily`), because phase 1 has
  one collector and staleness belongs to the source. A new source adds its own key.
- The advisory's evidence statuses `manual_pending` / `manual_accepted` became one `manual` (not met in phase 1);
  manual evidence upload is phase 3.
- No Infra Terraform change. The Infra PR only registers the new schema (owners.yaml, isolation probe, RLS catalogue,
  run_migration, retention check), which the Copy Guard and the nightly probe need for any new CIS schema.

## Tradeoffs

- Writing evidence and today's snapshot during a GET keeps phase 1 free of a new job kind; the cost is a few inserts on
  a page view, idempotent. A daily snapshot exists only for days someone opened the page (the trend says so).
- The collector's GitHub reads use the run's token on public repos; Dependabot, secret-scanning and code-scanning alert
  counts need the read-only GitHub App (phase 2, Q5).
- Readiness tracking, not immutable evidence: the Docs sync role can overwrite the file. Phase 2 moves it to an Object
  Lock bucket and its own role (Q6, Q8).

## Should know

- The register (controls + mappings) is private and never committed; tests use `register.example.json` (EX- ids). The
  unit guard refuses the private id prefix, account IDs, ARNs and S3 URIs in the compliance files.
- `tests/integration/test_aa1170_compliance_service.py` needs CIS 466: in this PR's CI it runs after `main` carries the
  migration PR.
- Until the register is loaded every framework shows 0 % (every requirement unmapped); that is correct, not a bug.
