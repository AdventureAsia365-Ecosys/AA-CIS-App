# AA-197 [AA-193·F2] DataForSEO rebuild — implementation notes

## Decisions
- New `services/seo_intelligence/seed_builder.py` owns ALL seed/market logic (pure functions,
  no I/O) so it is unit-testable without DB/HTTP and reusable by handler + admin_pipeline.
- Seed is built ONCE by the caller (admin_pipeline) and passed through; the DFS client no longer
  appends "tours"/"tour" — kills the `{country} tours tours` double-tours bug at the root.
- Buyer market resolved from `tenant_seo_config.target_market.countries` (array, no `.primary`)
  via MARKET_RANK (US>UK>AU priority). Empty/unknown → US default (2840) — preserves old behavior.
- `keyword_ideas` fallback when `top_keywords` empty: reuse `related_keywords` (already fetched
  from the same SERP call) else `[seed]`. No extra API call (cost-neutral) — Ms. Thu #4 "widen to ideas".

## Changed vs. original requirement
- `process_seo()` signature gains `seed` and `tenant_id` (both optional/keyword) — backward compatible;
  when `seed` empty it falls back to `destination` so existing callers/SF path don't break.
- Redis cache key now `make_key(seed, location_code)` (was destination+activity) — same tour for a
  different buyer market is a distinct cache entry.
- `fetch_all` return adds `related_keywords` + `keyword_ideas` (additive). Existing keys
  `keywords.top_keywords` + `people_also_ask` kept byte-for-byte so prompts.py L61-62 unaffected.

## Tradeoffs
- `first_activity` only takes the FIRST token of the (dirty, 25%-coverage) `activities` blob —
  good enough as a seed qualifier; richer extraction (src_highlights prose) deferred.
- COUNTRY_NORMALIZE is a small explicit map (SRI-LANDKA, OKINAWA) + title-case fallback rather than
  a full geocoder — covers observed dirt, easy to extend.
- PAA + related reuse ONE SERP advanced call (no second HTTP) to hold DFS cost flat.
