# AA-198 [AA-193·F1] Brand differentiation resolver — implementation notes

## Decisions
- New helper `_resolve_brand_rule(conn, tenant_uuid, brand_identity_id, brand_name)` centralizes
  brand-rule selection. Priority: explicit `id` → named brand (active) → explicit `'default'` brand.
- No migration / no dedupe: master tenant already has 1 active version per brand (verified STEP 0).
  The bug is pure selection logic, fixed in code only.
- `else` branch now selects `brand_name = 'default'` explicitly instead of cross-brand
  `is_active = true ORDER BY version DESC LIMIT 1` (which let Terra Family v2 win every time).

## Changed vs. original requirement
- Only the live S1 path (`POST /admin/run-tour` → `_execute_run_tour`) is touched. The dead
  `/acp/s1/run` Step Functions path (uses `brand_identity_id` in run_config) is left untouched.
- `TourRunRequest` gains `brand_identity_id: Optional[str]` alongside existing `brand_name`.
- New `GET /admin/brand-rules` returns id/brand_name/version/is_active only — no prompt content.
- graph.py: forbidden_words now also injected as an explicit system instruction (defense added),
  post-hoc validate_node check (L212-225) kept (defense in depth).

## Tradeoffs
- Resolver returns the raw asyncpg Record (or None); caller keeps existing mapping/except logic so
  the diff stays minimal and behavior on fetch failure is unchanged.
- `'default'` brand row currently has an empty system_prompt → no-brand runs produce unbranded
  generation (is_branded=False), which is the intended explicit default, not Terra passthrough.
