# S248 — S1-first step 1: fact table + code checks (Refs AA-645)

M2a "S1-first" plan (S246 content-quality advisory, private root repo `docs/audits/2026-10-21-S246-content-quality-advisory/`
§5 step 1 and q4-q8 §2.2 step 0). No Linear issue of its own; AA-645 is the parent of the chain (step 2 = prompt surgery +
3-model screen). Offline, $0, no LLM, no DB. Results (tour text) live in the private root audit
`docs/audits/2026-10-23-S248-s1-step01/`; this repo holds the code only.

## Decisions
- **Code-built fact table, not Haiku extraction.** The advisory allowed "$0–1, Haiku extraction"; the lane brief says $0 /
  no LLM. Everything is regex + the existing parsers (`day_parse`, `hygiene.proper_nouns`). Two value kinds (q4-q8 §5):
  `verbatim` entries (value and quote are substrings of the source field) and `derived` entries (duration kind, conflicts)
  that carry their source quotes. `verify_pointers()` proves the "100% verbatim" bar on every run.
- **Measurement, not gates.** `services/quality/s1_checks.run_checks` is called only by `scripts/s1_step01/fixture_report.py`.
  Nothing is wired into `graph.py`; S1-first freezes new gates for four weeks (advisory Q2).
- **Reuse the pipeline's own functions** for each question (day oracle, `meta_cut_signature`, `find_novel_numeric_claims`
  over `source_number_parts`, `find_novel_word_numbers`), so offline and online answers agree.
- **NUMBER_NOUN_MISMATCH compares units only** (a figure with a unit vs the same number in the source with a unit of
  another kind or a different noun). A bare count ("281 residents" vs "281 people") is wording: the panel's call.
- **NAME_NOT_IN_SOURCE is a review list.** On the old writer most hits are place background, which the writer policy
  allows; it is only a pass/fail signal if step 2 forbids names outside the fact table.

## Changed (vs the plan)
- Two small fixes in live modules, found by running the checks on the golden set:
  - `day_parse.source_day_markers`: "Day 05 & 06" / "Day 11, 12 & 13" are ranges (they read as one day, so the AA-925
    oracle charged a faithful day 6/12/13 as `DAY_OUTPUT_EXTRA`). Only the oracle reads the range end; the word-count
    split (`parse_source_day_word_counts`) keys blocks by their first day as before.
  - `seo_meta_utils.meta_complete_sentence` / `meta_cut_signature`: a meta ending in a two-word capitalised place name
    ("…and Hoi An.") is not a weak ending "an". Before, `META_INCOMPLETE_SENTENCE` (an A1 hard code) fired on it.
- Added `DAY_PLACE_MISMATCH` (day title names a stop the source puts on other days only) and `meta_list_cut` (closing
  list without "and") to catch the day-drift and cut-meta cases the existing functions missed.

## Tradeoffs
- The checks were developed and measured on the same 50 golden S1 pages (no held-out set). TPR on the golden set is
  optimistic; the first held-out read is the step-3 A/B arms (new pages), where `fixture_report --pages` runs as is.
- The place list in the fact table is heuristic (capitalised runs minus sentence-start words); a title-case source
  ("Sleeping Tents") leaks generic words. Good enough for checks; a writer input may want an LLM-extracted list later.

  --ground-truth <audit>/ground-truth.json --out <audit>/results.json` (needs the app venv; no DB, no network).

- `services/quality` purity: `s1_checks` imports utility modules only (`content_generation.grounding`, `day_parse`,
  `seo_meta_utils`, `prompts` via the oracle, `acp_content_writing.hygiene` / `claim_rules`); checked at import time
  that no graph / flag_fix / service module is pulled in.
- Fact-table conflicts are deliberately narrow: an item both included and excluded is reported only for specific
  items (breakfast, lunch, dinner, drinks, tips, visa) and never for a conditional exclusion ("meals not mentioned
  in the itinerary"); generic groups are usually qualified on one side ("international flights").
- Missing-field probes read the source text fields + duration + price. `raw_tours.group_size` / `best_time_to_go`
  are separate columns the S1 writer does not receive today; step 2 can add them to the writer input.
