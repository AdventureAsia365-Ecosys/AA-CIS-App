# AA-772 — Place cards + seed scope (S233, with AA-768 seed items)

## Decisions
- **One card per real place**, not per atom: `place_key = norm(display_name)|norm(locality or region)|norm(country)`
  ("City Palace" Jaipur ≠ Udaipur). `atom_place_card` links an atom to its card (resolved once per atom).
- **Built in jobs, never in HTTP**: T8 (`t8_angles` job, before the seed is read) and T9 (`resolve_facts`, first
  step of the `t9_write` job; the seed is re-read when a new card was built). Soft-fail: no card → old seed.
- **Two models**: `a3_place_card` drafts identity + 6–10 facts (no prices/hours/superlatives/trip claims);
  `a3_place_card_check` (judge route, other vendor) confirms identity and each fact — only "supported" facts are
  kept; identity rejected → no card (tried again next time). Status starts `auto_checked`; admin can set
  verified/rejected (PR 5). Cost on the card row + `llm_call_log` (stages seeded by migration 220).
- **Seed** (`atom_seed.py`): reads `v_active_tour_atoms`; Location from the card (display name, locality, region,
  country + "the itinerary calls it …"), `Naming:` note, `Day N of the trip`, `Place background` facts; siblings
  only same country, no alias, not the same tour, shortest first, labelled "other trips — never promise";
  whole-day-body evidence trimmed to the sentences naming the place (≤500 chars).
- **Scope line** (`SCOPE:`) for every T9 piece: route = days X–Y + places in order, "must not promise anything
  outside these moments, even if the TRIP name does"; single moment = "one moment (day N)".
- **Facts**: filtered by `facts.country` (migration 220) = the trip's country; the per-fact Jev relevance call is
  dropped from T9 (S232: no Jev on the T axis).
- T8/T9 atom reads moved to `v_active_tour_atoms` (CLAUDE.md rule).

## Tradeoffs
- First write for an atom pays ~2 short calls (~$0.01–0.03) and a few seconds; a route blog with 10 new moments
  builds them 4 at a time.
- The checker is an LLM, not a human: cards are "auto_checked" until an admin verifies. Writers may cite them;
  the F9 judge sees them as source.

## Should know
- Needs migration 220 (tables + stage keys) before deploy.

# S234 — PR1: place-card cost cut + migration 221

Plan: `.tmp-session/s234/plan.md` §4 PR1, decisions C1, C2 (rows only), C8, C9.

## Decisions
- **Order of work per call** (`ensure_place_cards`): free rule skip → group by
  (`place_norm(place)`, `fold(tour country)`) → existing card by alias, then by core name → stored
  miss (skip unless `force`) → at most ONE draft per group, every atom of the group linked.
- **Rule skip = C9** (`card_skip_reason`): `names_somewhere` (the same function ranking's
  `classify_exclusion` uses for `unnamed_place`), a leading `your/our`, or a logistics head noun on
  the folded place (hotel, resort, guest house, lodge, airport, station, terminal, pier, jetty,
  camp — except "base camp" —, homestay, restaurant, cafe, border gate/crossing/post, checkpoint,
  information centre). Called with the PLACE only; a transit ACTION is not skipped (a card is about
  the place, and grouping makes the transit atom reuse it). I import `names_somewhere` rather than
  calling `classify_exclusion(place, "")`: same single rule, without a fake action.
- **Rule skips are not cached in `place_card_miss`** — they are free to recompute, so a rule change
  (bump `RULE_VERSION`) takes effect at once. They are written to `atom_place_card` (card_id NULL,
  `miss_reason`) for the admin view only.
- **Negative cache** `place_card_miss(place_norm, country_norm)`: no_name 30 d, identity_rejected
  14 d, error 1 d. A miss blocks a draft only while `retry_after > now()` AND `rule_version` and
  `prompt_sha` (sha of both system prompts + MAX_FACTS) match the code. `model` is stored for
  information only (a route change alone does not invalidate misses).
- **Keys**: `fold()` = NFKD + a small map for letters NFKD keeps (đ, ø, ł, ß, æ, œ); `place_norm()`
  = fold minus leading the/a/an/your/our/local/standard; `core_key()` = place_norm without a
  parenthetical and without neutral kind words (lake, nuur, town, city, sand dunes, els, volcano,
  uul — NOT dzong/monastery/museum/river/valley). New `place_key = core_key(display_name)|fold(country)`.
- **Legacy keys**: S233 cards keep their 3-part key until the data step. The core-name lookup reads
  new keys by equality plus every legacy-format key (`LIKE '%|%|%'`, 74 rows today) and compares
  in Python, so reuse works before the backfill.
- **Aliases**: itinerary spelling (under the tour country), display name, parenthetical and the
  draft's `aliases` field (under the card country AND the tour country — fixes the Vietnamese
  place on a "Laos" tour being drafted again). `source`: itinerary | display | draft_alias | merge.
- **Prompts**: 4-6 facts (`MAX_FACTS=6`), `max_tokens` 900, `aliases` in the JSON, "one country"
  instruction; draft says "country the tour is sold as (the route may cross into a neighbouring
  country)"; check gets the tour name and "the place may be in a neighbouring country", and its
  system prompt says not to reject on a neighbouring country alone.
- **Key conflict**: the stored card wins, `cost_usd` is incremented by the new spend.
- **T9 read-only (C8)**: `resolve_facts` no longer imports `ensure_place_cards`; it always re-reads
  the seed (cheap DB reads) so a card built by T8/the job since `start_write` is used.
- **Job**: reads up to 400 atoms of the tour, caps PAID drafts at `MAX_PLACES=40` groups,
  `force` from the payload, returns the counters (atoms, already_linked, skipped_by_rule, places,
  linked_existing, skipped_cached, over_cap, drafted, linked_new, missed, errors, built).
- **Admin**: `force` on POST /place-cards/build; GET /place-cards/duplicates (pure
  `duplicate_clusters`: same core name, whole-word containment, alias — candidates only);
  POST /place-cards/{keep_id}/merge {from_ids} (one transaction: re-link atoms, move + add
  aliases, add facts up to MAX_FACTS without dropping any, sum cost, delete merged cards, audit
  row `place_card.merge`); PATCH status now writes `place_card.status` in the same transaction.
  `write_audit_log` accepts `tenant_id=None` (platform data → NULL); constants in
  `PlatformAuditAction`.
- **Migration 221** (C1) also seeds `t9_repair` (writer, haiku → sonnet) and `t10_claims`
  (validate, gpt-6-luna → gpt-5.6-luna, shadow 0) with explicit VALUES (not twin copies), plus
  SAFE_DEFAULTS and the Settings > LLM stage group/labels. No caller uses them in this PR.

## Changed (vs. the plan)
- `a3_place_card` route unchanged (Sonnet) — the A/B decides (needs a paid run).
- No batched draft/check (design e2): not in the PR1 list; per-place grouping already removes most
  calls.
- No job scoping by Segment `excluded_reason` (design priority 3) — the rule skip covers the
  unnamed part; transit-only scoping left out on purpose (a card is about the place).
- Token-logging bug (PR0 c) fixed here, see "Should know".

## Tradeoffs
- Lowercase itinerary places are always skipped, even when a card exists for that place under a
  capitalised spelling ("lake khovsgol"). Measured S233: 40/40 lowercase samples were generic.
  A lookup-before-skip would recover these at $0, at the risk of linking generic text by alias.
- Capping additions at MAX_FACTS on merge, never truncating the kept card's own facts.
- `force` ignores the miss cache only, not the rule skip: an attraction named "X Camp" still needs
  a code/rule change (or an alias) to get a card.
- No advisory lock: with T9 read-only the only concurrent builders are T8 jobs on different
  request atoms; a rare double draft is bounded by the UNIQUE key + cost accumulation.

# S234 — PR1 review fixes

## Decisions
- **Generic names** (`is_generic_name`: every word of the name, outside a parenthetical, is a kind
  noun / qualifier / when word — ranking's `PLACE_KINDS` plus common landmark nouns such as palace,
  fort, monastery, square, bazaar): "City Palace", "Lake Palace", "Night Market", "National Museum",
  "Old Town". For these:
  - `place_key` = `core | fold(locality or region) | country` (City Palace Jaipur ≠ Udaipur — the
    migration-220 invariant is back for the names it was about). A generic draft with no locality and
    no region is a `no_name` miss, never a country-wide card.
  - grouping is per atom (`atom_group_key` → `"<place_norm> @<atom_id>"`), so one call never drafts
    one Udaipur card for a Jaipur atom, and a miss blocks that atom only (not the whole country).
  - no alias rows (itinerary, display, draft alias, merge) and no alias / core-name lookup.
  - free reuse only through `pick_local_card`: an existing non-rejected card with the same name and
    country whose `locality` appears as whole words in the atom's itinerary sentence — exactly one
    such card, else draft. The tour name is not used (a Rajasthan tour name lists both cities).
- **`core_key`** strips neutral kind words (lake, nuur, town, city, els, volcano, uul, sand dunes)
  only at the edges and only when the words left start and end with a distinctive word:
  'Lake Khövsgöl' == 'Khövsgöl Nuur' == 'khovsgol'; 'City Palace' stays 'city palace'; 'Hoi An Old
  Town' keeps 'town'; 'Forbidden City' → 'forbidden' (a distinctive word remains; accepted).
- **Rejected card on a key conflict** (`_store_card`, `SELECT … FOR UPDATE` then insert/update):
  same identity (folded display/locality/region/country) as the rejected card → nothing linked,
  `identity_rejected` miss stored (14 d), cost still added to the card; a different identity →
  the rejected card is replaced (fields, facts, status `auto_checked`, verified_by/at cleared) and
  the atoms are linked. A non-rejected card still wins and gets the cost. `already_linked` now
  counts only links to non-rejected cards, so atoms stuck on a rejected card are resolved again.
- **Logistics skip** applies only when the atom's `activity_type` is stay/transit/food or NULL
  (`_ATOM_PLACE_QUERY` selects it). 'Hua Hin Railway Station' (culture), 'Everest View Hotel'
  (trek), 'Hua Hin Elephant Camp' (other) keep their card — ranking keeps them rankable.
- **Duplicates / merge**: `duplicate_clusters` leaves out rejected cards and pairs two generic-name
  cards only when their locality matches. `merge_cards` refuses a rejected keep card, takes no
  facts from rejected cards, and adds no facts to a verified keep card (its reviewed facts stay as
  reviewed; atoms, aliases and cost still move).

## Changed
- `test_key_conflict_keeps_the_card_but_adds_the_cost` used a rejected card and asserted the link to
  it (locked in the bug); it now uses an auto_checked card, plus 3 tests for the rejected cases.

## Tradeoffs
- Generic names pay one draft per atom the first time a city is seen (bounded by `MAX_PLACES` per
  job); after that, sentences naming the city link for free. An itinerary sentence that never names
  the town always drafts (once — then the atom is linked or its miss is cached).
- The generic word list is hand-made; a name it misses ("Royal Palace" is covered, a new landmark
  noun may not be) behaves as before (country-wide key). Add the noun when one shows up.
- Repeating a rejected identity is cached 14 days, not forever: a prompt change or expiry tries again.

## Should know
- The post-deploy key backfill must use `place_key(display_name, country, locality or region)`
  (generic names keep 3 parts), not `core_key|country` for every card.
- Generic-name cards have 3-part keys, like S233 legacy keys; the core-name lookup still reads every
  3-part key but skips generic names in Python.

## S234 round 2 — seed hygiene + keyword grounding (panel §5 fixes 3 and 5)

Branch `feat/aa772-seed-canonical-keyword`. Evidence: `.tmp-session/s234/panel/02-commercial-panel-s234.md`
§2 classes 2 and 7, the 20 stored pieces in `.tmp-session/s234/pieces.json`.

### Decisions
- **Root cause of "Bhutan meditation retreat" (6/6 Punakha LinkedIn):** `choose_keyword` read the
  country from after the LAST comma of the `Location:` line. Since S234 that line ends with
  "(do not place it in any other town, region or country)", so the "country" was `{region, country}`
  and `bhutan` stayed a place word — the keyword matched on the country alone. Fixed by removing
  parentheticals first. Second gap: nothing checked the keyword's non-place words.
- **Product vocabulary, not "every non-place word".** A keyword is lower-case, so place words
  cannot be told from other words; a strict "every word must be in the seed" rule would reject
  'khovsgol and gobi tour' style keywords on 'gobi' (scope owns places). `seo_grounding.PRODUCT_STEMS`
  lists bookable products/services (retreat, meditat-, yoga, spa, cruise, boat, trek/hike, safari,
  cooking, homestay, diving, horse/riding, luxury, festival …); a stem must appear in the seed
  (prefix match: trek ~ trekking; hike/hiking ≡ trek; bike/biking ≡ cycling). 'climb' is only
  'rock climb' (a "trail climb" on a hike is not a product).
- **Fallback:** next grounded candidate; if none, the first place-matching candidate with its
  ungrounded product words removed when ≥2 words remain ('punakha dzong meditation retreat' →
  'punakha dzong'); else None (writer titles naturally).
- **Meta check** (`meta_unsupported_products`): product nouns + "guides you / guided tour /
  private guide" in the meta must appear in the seed or the body. Wired in two places: the SEO
  fit's `meta_ok` (an ungrounded meta triggers the fit, the words go to `forbidden_words`, and an
  ungrounded fitted meta is never kept) and F4 `gate_seo_surface(seed=…, body=…)` (blog only, a
  violation line; F4 is already blocking + repairable). quality_gates change is 1 optional kw-arg
  + 4 lines, isolated from PR A's gate logic.
- **Canonical facts** (`seed_canon.canonical_facts`): a conflict = same unit, same "of" word when
  both have one ('70 percent of MONGOLIA's' vs '0.4 percent of the WORLD's' are two measures),
  ≥3 shared context words in a 4-before/6-after window, non-overlapping values (ranges overlap
  → consistent: 20,000–24,000 vs 24,000). Spelled numbers two..hundred count ("two percent");
  "one" does not ("one of the deepest"). Facts are compared only when they share a subject place:
  the card's own place (cards with one core name + country are one place) or another seed card
  the fact names. Winner order: verified card → the fact on the place's OWN card over a mention
  on another card → place with more moments in the seed → earlier card. (The task's order was
  verified → more atoms → first; "own card" was added because on the S233 seed every Khövsgöl
  card had 1 atom and the first card was Sod Camp, so the outlier '2%' would have won over three
  '0.4%' lines.)
- **Soft contradictions kept:** "ancient" vs "geologically recent" has no number; a word-level
  contradiction rule would drop true facts on synonyms. Both lines stay (documented in the module).
- **Day order cause (Sod Camp vs Mörön):** two causes, both seed-side. (1) Within a day the walk
  followed Segment order, so 'Sod Camp — overnight' (Day 3) came before the Day 3 volcano.
  Now: day → overnight moments last → `created_at` (A3 inserts one atom per autocommit statement
  in the model's itinerary order; there is no ordinal column) → Segment order. (2) Card locality:
  the Sod Camp card put a Day 3 camp on the Khövsgöl lakeshore, while Day 4 says "stop for lunch
  near Moron … before continuing to the lakeshore camp". Rule `overnight_card_off_route`: an
  overnight moment whose card region matches no other carded moment of the same day loses its
  card (Location falls back to itinerary place + country; its facts go with it). The writer was
  not the cause — it followed the seed.
- **Card merge:** `place_cards.merged_facts` no longer adds a donor fact that conflicts with a
  kept fact (the kept card's value is canonical).
