# AA-738 — Deterministic forbidden-word strip + tighter writer prompt

## Decisions

- **Root cause measured before designing (S218).** The 9 Nepal tours in review with
  `retried with sonnet, still FORBIDDEN_WORD` contain **zero** words from the AA core list
  (`VALIDATE_FORBIDDEN`). Every hit is from the AA brand's own `tenant_brand_rules.forbidden_words`
  (43 words, `default` v2): `explore` ×10, `package` ×2, `nestled` ×2, `vibrant` ×1. These are
  ordinary verbs/nouns that Haiku and Sonnet both write naturally, which is why the Sonnet retry
  never cleared them. A word-level substitution clears all 15 hits.
- **Strip runs at write time, not after flag_fix.** It is applied in `generate_node` and
  `seed_generated_node` right after `_process_itineraries` (so the per-day nudge output is covered
  too), before `validate_node` scores anything. FORBIDDEN_WORD then never fires for a strippable
  word, so no flag_fix LLM call, no re-judge and no Sonnet retry is spent on it. flag_fix already
  reverts any forbidden word its own repair introduces (AA-641), so the content stays clean
  through the rest of the graph.
- **Two strip levels, in order:** (1) word substitution from a fixed neutral map (e.g.
  explore→visit/wander, nestled→set, package→trip, vibrant→lively), keeping capitalisation,
  plural `s` and fixing `a`/`an`; (2) for prose fields only (summary, description, itineraries),
  drop the whole sentence when no substitute exists (CTAs like "book now", "act fast"), but only
  if the paragraph keeps at least one sentence and the line is not a `Day N` header. Highlights:
  drop the item only if ≥3 remain. Short fields (name, subtitle, seo_title, mobile_card_text,
  seo_meta) are substitution-only; seo_meta also has to stay in band. Anything else stays as is
  and FORBIDDEN_WORD still blocks it (AA-736 safety net).
- **A substitute is never used if it is itself forbidden** for the active brand — falls through
  to sentence drop / leave.
- **C: dropped FORBIDDEN_WORD from the AA-736 Sonnet-upgrade trigger** (option i). The data
  shows Sonnet does not fix these words, and T2 rewrites with Sonnet anyway. Kept for
  BRAND_SEO_META_VIOLATION / MISSING_FIELD. A surviving FORBIDDEN_WORD goes straight to review
  with "forbidden word not auto-removable in <field>".

## Changed

- New `services/content_generation/forbidden_strip.py`.
- `graph.py`: `_apply_forbidden_strip` wired into both write entry nodes.
- `batch_prompt.py`: forbidden list is now a hard constraint with plain alternatives.
- `admin_pipeline.py`: `_REWRITE_CLASS_HARD_CODES` minus FORBIDDEN_WORD; failure summary names
  the field when a forbidden word survives without a Sonnet retry.
- `_derive_field_failures` gained `extra_forbidden` and now scans aa_description / aa_highlights /
  aa_itineraries too. Found while wiring the summary: it scanned only the AA core list and only
  5 short fields, which is why the S217 reasons said "still FORBIDDEN_WORD" with no field. The
  run path passes the brand's words (`result["_brand_forbidden_words"]`); the Review Queue
  endpoint still calls it without them — that UI side belongs to AA-739.
- Tests: new `tests/unit/test_aa738_forbidden_strip.py` (16, fixtures = the real Nepal
  sentences); AA-736 upgrade tests switched to MISSING_FIELD + 1 test that FORBIDDEN_WORD no
  longer triggers Sonnet + 1 summary test; AA-606 prompt test follows the new header. Full unit
  suite 2405 passed.

## Tradeoffs

- A substitution can read slightly flatter ("visit the city" vs "explore the city"). Accepted:
  S1 is a neutral platform draft (AA-724), the tenant voice is applied at T2.
- The strip scans raw field text, which is stricter than validate's JSON-dump scan (validate
  misses a word right after `\n` or an escaped unicode char). Stricter is harmless.
- The system prompt changes, so `prompt_version` changes and the Bedrock prompt cache misses
  once.

## Should know

- The strip also runs on the T2 path (same `generate_node`, `t2_generate` stage) with the
  tenant's own list. That is intended: FORBIDDEN_WORD blocks T2 the same way.
- `validate_node` scans `json.dumps(generated)`, which includes `seo_keywords_used` (DFS
  keywords). A keyword containing a brand word (e.g. "trek package") would fire FORBIDDEN_WORD
  with no copy field to fix. None of the 9 Nepal cases were this; not changed here.

## Follow-up after the S218 Sri Lanka wave (126 tours)

- FORBIDDEN_WORD on the latest version fell to 11/126 (9%), vs 50–73% on the pre-AA-738 waves
  (Korea 22/30, China 64/121, Bhutan 24/32). 0 Sonnet upgrades.
- But 8 tours with score ≥ 7 were still blocked by FORBIDDEN_WORD, nearly all in `seo_meta`:
  flag_fix / the seo_meta re-repair loop rewrote it back to "Explore …" **after** the write-time
  strip. Fix: `_apply_forbidden_strip` also runs at the start of `revalidate_node` (after every LLM
  edit, before the last validate). Also fixed the strip log (`tour` name; the state has no
  `tour_id`).
- Not AA-738: 11 tours blocked only by seo_meta/seo_title length (rate same as earlier waves —
  Bhutan 16%, Thailand 14% — but AA-736 now makes length codes block Master and flag_fix
  (AA-608) gives up without a deterministic fallback), and 21 low judge scores (family/honeymoon
  persona kept from the source, itinerary inconsistencies).
- **False positive fixed:** validate scanned `json.dumps(generated)`, which includes
  `seo_keywords_used` (DFS keywords). S218: "Family Adventure (Summer)" had the keyword "cheap
  summer getaways", and "Explore Amazing Five In The Wild" had its own source title as a keyword,
  so FORBIDDEN_WORD fired with no copy field to repair and Master stayed blocked. 13/538 latest
  versions (12 days) carry a forbidden word in that field. validate now skips
  `forbidden_strip.SKIP_FIELDS` when scanning. Every copy field is still scanned, so this removes
  a false positive and does not loosen the gate.
- **Validate blind spot fixed:** the word scan ran on `json.dumps(...)`, whose escapes glue a
  letter onto the word (`\n` → "n", `—` → "\u2014" → "4"), so the whole-word lookbehind missed
  "—explore" / "\nExplore". S218: Nepal master "Khopra Danda" went live after AA-736 with
  "…as you wish—explore the city". `forbidden_words.copy_text()` flattens fields to plain text;
  `validate_node` and `forbidden_in` (flag_fix revert, grounding) now scan that.
