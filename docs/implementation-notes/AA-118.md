# AA-118 — LLM Cost Tracking End-to-End

## Decisions

1. **acp_stage_runs is new** — no existing table; migration creates it with UNIQUE(run_id, stage)
2. **UPSERT not UPDATE** — `record_stage_cost` uses `INSERT ... ON CONFLICT DO UPDATE` so rows auto-create; spec said UPDATE but that silently no-ops if row absent
3. **psycopg2 sync for cost_utils** — Lambda compatibility; async callers wrap via `asyncio.to_thread`
4. **S1 (content_generation) skipped** — ContentState has no ACP run_id; S1 tracks cost via `shared.pipeline_runs.cost_usd` (different pipeline); not wired into acp_stage_runs
5. **S4 evaluate Lambda skipped** — Lambda receives no run_id in event payload; no way to record stage cost without API change
6. **Social llm_client token capture** — added optional `_token_log: list` param to bedrock client factory; callers that care pass a list and read it after; backward-compatible
7. **finalize_run_cost placement** — S2: in synthesize.py after status='completed'; S3: in handler.py after conn.commit(); S4 blog: in save_node; S4 social: no single completion point → lazy-compute at GET /admin/acp/runs/{run_id}

## Changed vs. Original Requirement

- `record_stage_cost` uses UPSERT (spec had UPDATE-only)
- Added `conn` param variant for S3 Lambda (avoids opening new connection mid-transaction)
- S4 social token capture via closure list rather than separate DB client per call

## Tradeoffs

- Psycopg2 sync inside asyncpg services → `asyncio.to_thread` overhead per Bedrock call; acceptable since it's non-critical path
- FK on `acp_stage_runs(run_id)` → records only for valid ACP runs; graceful fallback logs warning on FK violation

## Should Know

- **acp_stage_runs FK**: `run_id` must exist in `acp_shared.acp_runs` before any stage cost is recorded
- **S3 Lambda**: `record_stage_cost` inlined locally (can't import from services.acp_shared in Lambda zip)
- Migration 055 must be applied before any stage runs for cost data to appear
- `finalize_run_cost` sums ALL stage costs; calling it multiple times is safe (idempotent sum)
