## Decisions

- **Router name `api/routers/admin_platform.py`** (not `admin_staff.py` as §5.4 sketched): the task
  names it, and §6.2 already plans `admin_platform.py` for the Apps health routes, so the whole
  `/admin/platform/*` prefix lives in one module.
- **Staff GETs go under `POLICY` (capability `staff.read`, admin only).** GĐ1 left every GET open to
  any secret holder; the staff directory is the first read narrowed server-side. A new
  `POLICY_READ_PREFIX = "/admin/platform/"` makes the GĐ1 test "reads stay open" precise: a GET may
  only be under POLICY when it is under `/admin/platform/`, so `GET /admin/llm-config` (S1 page)
  can never be narrowed by accident. The machine principal (secret, no role) is refused: no CI or
  Lambda caller needs the directory.
- **Explicit column list, never `*`.** `password_hash` is not selected at all; the test checks the
  SQL text as well as the response.
- **Malformed id → 404, not 422.** `staff_id` is a `str` parsed with `uuid.UUID`; FastAPI's own UUID
  validation would also work, but a 404 says the same thing whether the id is malformed or unknown.
- **Sections in the nav model, not a new AppSwitcher** (§4): `NavGroup.section` = `platform` | `cis`.
  The two collapsible section headers render only when the role sees both sections, so
  reviewer/content see the same flat CIS list as before.
- **Settings stays the standalone footer entry** for now: it still mixes platform tabs (LLM Models,
  Jev Credit, UI Kit) with content tabs, and splitting it changes URLs (GĐ6). Moving it into either
  section today would be wrong for half its tabs.
- **No Apps placeholder**: there is no `/admin/platform/apps` page yet (GĐ7), so no nav item.
- **Cross-app links come from a typed registry `frontend/lib/apps.ts`** (§6.1): Dev constants
  (`https://aa-booking-admin.vercel.app`, `https://aa-tripplanner.vercel.app`) with optional
  `NEXT_PUBLIC_*` overrides, same pattern as Booking `lib/config.ts` `DEV_CIS_ADMIN_URL`. No env var is
  needed on Dev. Deep links are built only from the registry (no free return URL, no token).
- **Section-header collapsed state** is a small localStorage store read with `useSyncExternalStore`
  (same pattern as `sidebarStore.ts`), React-Compiler safe, no setState in effects.

## Tradeoffs

- The staff page is **not** added to the Playwright UI smoke matrix in this PR: the smoke runs the
  Vercel preview against the live Dev API, which has no `/admin/platform/staff` until this backend is
  deployed, so the page would fail the "no failing /api/ response" check. Add it right after the
  deploy (one line in `ui-smoke.spec.ts` `ADMIN_PAGES`).
- The page says "Open in Booking" for every account even though Booking may not have a profile for
  that CIS user yet (Booking creates one on first login). Booking's own page handles the miss.

## Should know

- Header trust is unchanged: until GĐ4 (staff JWT Bearer) anyone holding `ADMIN_SECRET` can claim
  `x-admin-role: admin`. The directory is read-only, so the exposure is the list of usernames + roles.
- The BFF rule `{prefix: "platform"}` matches `platform` and `platform/...` only (`canReadAdminPath`
  compares `prefix` or `prefix + "/"`), so `/admin/platform-stats` is not caught.
- The staff smoke row and the Booking staff-page "Managed in CIS" deep link
  (`/admin/platform/staff/{cisUserId}`) are follow-ups (§6.3 puts the latter in GĐ5).
