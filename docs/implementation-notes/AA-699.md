# AA-699 — T-series Jev (part 1 of AA-696): T3 grounding, T2 judge tie-break, T0 brief

Design: `docs/architecture/at-series-v2-design.md` §4.3 (T0-1, T2-1, T3-1). Policy: ADR 0007.

## Measured first (S206, Dev)
- The two allow-listed test tenants (WanderLux `a1b2c3d4…`, test-1 `1bae2159…`) hold 5 tenant rewrites
  (`tenant_tour_versions`), 3 content pieces, 3 angle requests; 0 tenant rows in `decision_log`.
  ~200 items per question cannot be sampled from tenant data now.

## Decisions
- **Nghiệp (S206): shadow first, calibrate from the rerun.** Wire T-series through `decide()`; a question
  may enforce only when it is the *same* question on the *same* state shape as one already calibrated.
- **T3-1 reuses `a1_claim_supported`** (enforce, accept_floor 0.90, no reject floor). A1 asks
  "is every fact in this sentence in the source?" with state `{source, sentence}`; T3 asks the same
  with source = the master content T2 rewrote from. Only the sentences the numeric regex flagged are
  asked; an enforced accept clears that hit, so a unit conversion no longer costs a full Sonnet rewrite.
  Logged under stage `t3_grounding`; the cache key is per (source, sentence) and per tenant.
- **T2-1:** the A1 tie-break (`a1_brand_fit`, shadow) now also runs for tenant rewrites, on the
  combined judge score (what gates T2), stage `t2_judge_tiebreak`, with the tenant's id.
- **T0-1 deferred.** The Lambda path (`POST /admin/tenants/{id}/brand-brief`) uploads to
  `acp-bronze-867490540162`, which returns 404 (acc1 infra destroyed in AA-271), so it cannot run. The
  in-API parser (`POST /admin/brands/parse-docx`) has no tenant id, so the C2 allow-list guard cannot
  apply and a brand brief is tenant content. Its output is pre-filled fields an admin reviews before
  saving, so a Jev Choice there has little to gain.

## Changed vs the issue
- T3 non-numeric sentences are **not** asked. `a1_claim_supported` has no reject floor (below 95% on
  non-numeric sentences), so asking would change nothing, and the rerun's A1 pass already collects the
  low-p non-numeric data the reject floor needs.

## Tradeoffs
- The first flagged sentence is asked alone: if its verdict is `skipped` (tenant not allow-listed,
  or mode off) the rest are not asked, so non-allow-listed tenants pay one DB round-trip, not N.
- `decide()` without a pool opens one connection per call (≤ 4 in flight). T3 hits are few per
  attempt (0–20), so no pool is created for them.

## Should know

- `run_t3_qa_gate()` result gains `jev_cleared` (count across attempts); log event `t3_jev_cleared`.
