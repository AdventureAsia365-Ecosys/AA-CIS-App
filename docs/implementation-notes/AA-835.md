# AA-835 — supply content (hybrid supply content, root ADR 0004a)

Per-slice notes: `AA-835-cis-278.md` (storage, CIS 278), `AA-835-s6.md` (consumer, draft job, review API),
`AA-835-admin-page.md` (admin UI), `AA-835-smoke-s251.md` (staff smoke). This file holds findings that cut across them.

## S251 live run finding

The first Dev runs of `supply_content_draft` failed twice with `draft unusable: reply is not JSON: Expecting value`
(`services/supply_content/writer.py` `parse_output`). `shared.llm_call_log`: model `sonnet-4-6` on the acc3 satellite,
~150 output tokens. Root cause: CIS 278 seeded stage `supply_content_writer` with `model_id 'sonnet'`, a LEGACY key
(`shared/llm_client/catalog.py` `LEGACY_KEYS`). `LLMClient._call_key` sends legacy keys down `_legacy_chain` →
`_call_bedrock_satellite` → `invoke_claude` (Anthropic Messages API), which never received `request.json_schema`: no
tool, no instruction, so the model answered in free text and the strict `json.loads` refused it. Catalog keys go
through `_call_bedrock_converse`, which asks for the schema as a tool and conforms the reply (`_checked_json`).

### Decisions

- **Gateway: a schema is never lost silently.** For a request with `json_schema` on a legacy Claude key (`haiku`,
  `sonnet`), `LLMClient._legacy_structured` appends to the system prompt an instruction to answer with exactly one JSON
  object matching the named schema, with the schema JSON (`sort_keys`, stable text), after the caller's own system
  prompt (the caller's text stays first). The reply's object is taken with `_json_object_in_text` (a ``` fence around
  the whole reply is tolerated; prose before or after is not), conformed with `_checked_json`, and the response
  content becomes the canonical JSON text — the same contract as the Converse path. Anything else raises
  `BilledUnusableReply` with `call_log.billed_record(resp)` as its billed usage, so `_call_key_logged` writes the
  gateway's billed_unusable `llm_call_log` row (`gateway_attempt: true`, no ok-rate key) and a route moves to its next
  model. `gpt-4.1` is excluded: `_call_openai` already sends a strict `response_format` (and the key is retired).
- **Warn once per stage per process** (`llm_legacy_key_structured_output`, with stage, model, schema name and the
  action "route this stage to a catalog (Converse) key"), so a structured stage left on a legacy key shows in the logs
  without flooding them.
- **Route: `sonnet-5-5` → `sonnet`** (CIS 282). `sonnet-5-5` is the Sonnet catalog key with Converse + acc3 (and acc1)
  profiles (259) and the key the A1 writer `s1_generate` runs on since S250, so supply copy is written by the same
  model as the catalogue. The legacy `sonnet` stays as the LAST fallback: same vendor (writers are Anthropic), now
  schema-checked by the gateway, and it keeps the stage working when the catalog is unreadable (lesson S222 #617:
  SAFE_DEFAULTS must run with the DB down). SAFE_DEFAULTS mirrors the row.
- **282 only moves 278's seed** (`model_id = 'sonnet'` with no fallback). A row an admin already changed in Settings is
  left alone and reported in a NOTICE. A guard refuses the file if `sonnet-5-5` is missing, disabled, not Converse or
  has no acc3 profile (the route would fail every call).
- **Writer `parse_output` accepts a fenced reply** (defence in depth for a reply that did not pass the gateway's
  check, e.g. a test stub or a future path); prose around the JSON is still `DraftUnusable`.
- **Writer `max_tokens` 1200 → 2048.** Sonnet 5.5 runs adaptive thinking by default (AA-803: no thinking field is
  sent) and its thinking counts against `maxTokens`; the reply itself is < 400 tokens. One Sonnet 5.5 request is
  ≈ $0.026 (3k in, 2048 out); the worst job attempt is two Converse requests (schema retry) plus the legacy Sonnet 4.6
  fallback ≈ $0.09, so the job's `CALL_ESTIMATE_USD` is now $0.10 (was $0.05; still fits the $0.10 per-run cap: one
  call per run). The $1.00 day cap and the 20 calls/day cap count the gateway's billed rows, so they bound it too.
- **Review fixes (S251, after two independent reviews).**
  - Typed bad replies: `UnusableReply` base; `BilledUnusableReply` (one key) now subclasses it; new
    `RouteUnusableReply` when every model `_call_route` tried answered unusably (any outage / skip-only keeps the plain
    `RuntimeError`, so a retry still happens on outages). Its usage is on `logged_usage`, not `billed_usage`, so
    `_billed_usage_of` never logs it twice. `unusable_reply_cost(e)` gives the billed USD.
  - Supply writer: `UnusableReply` from `generate()` → `DraftUnusable` (job: `NonRetryable`), no second log row. Before
    this, a gateway-refused reply was a plain error and the job paid for its second attempt.
  - Place dedupe: an unusable `a3_place_dedupe_check` reply is charged to the run budget and `models.cost_usd`, not
    re-logged, and becomes `unsure` for that pair only (as `parse_verdict` did before S251) instead of stopping the
    rest of the run's model band. An unusable PRIMARY reply is charged and still stops the band (unchanged; Converse).
  - No live text for a structured request on the legacy Bedrock / satellite / OpenAI paths (Converse already did this).
  - An empty legacy reply with zero tokens is a plain failure, no $0 billed row (same rule as Converse).
- **Guard test** (`tests/unit/test_s251_legacy_structured_output.py`): every stage whose caller sends `json_schema=`
  (the S251 inventory) must have a catalog primary in SAFE_DEFAULTS, except an explicit allow list holding the one known
  legacy primary, `a3_place_dedupe_check`.

### Tradeoffs

- **Prompt-only schema on legacy keys vs. tool use on the Messages API.** `invoke_claude` could send Anthropic `tools`
  + `tool_choice`, which would enforce the shape better, but it is shared with Mechanism-B callers, has its own
  streaming path, and the legacy keys are on their way out. An instruction plus the same conform check, failing as
  billed-unusable, is small, keeps every non-schema request byte-identical, and turns a silent failure into a logged
  one. The real fix for a structured stage is a catalog key (282 for this one).
- **Strict extraction (fence only) vs. a lenient one (first `{…}` anywhere, `json_repair`).** Lenient extraction would
  accept prose like "Here is the JSON: {...}", but it is also how wrong objects get through (an example object in the
  prose). The Converse path accepts only a whole-reply object too (`_first_tool_input` with `auto`), so both paths now
  mean the same thing by "usable".
- **Legacy fallback on the supply route.** Without it a sonnet-5-5 outage (e.g. the S246 Marketplace subscription
  episode) stops every draft; with it the fallback is the model that failed live — but now with the schema asked and
  checked, and its failures are billed_unusable rows, not silent.

### Should know

- **Apply order:** 282 needs no app deploy first (the gateway reads the row per call, 20 s cache) — with the OLD image
  the primary `sonnet-5-5` already enforces the schema; the legacy fallback is schema-safe only with the new image,
  and the old image still sends `max_tokens` 1200 (a long think can end before the tool call), so deploy the app soon
  after. Apply in version order: Dev has CIS 280; 281 (destructive, needs its snapshot) is merged but not applied —
  apply 281 before 282, or `max(version)` = 282 would hide a missing 281 from the readiness check.
  Copy 282 byte-identical to `AA-CIS-Infra/db/migrations/cis/` (Copy Guard), then DB Migrate `check` → `apply` with
  `shared.job` / `booking.job` idle. The PR carries a migration: not auto-merged.
- **Behaviour change for `a3_place_dedupe_check` (still `haiku`, CIS 257).** Before, its replies came back as free text
  and `services/places/dedupe.py` `parse_verdict` regex-salvaged verdict / confidence or fell back to `unsure`. Now the
  schema is asked for (better replies expected), but a reply that is not one conforming JSON object (e.g. prose, a
  verdict outside the enum such as `Same`) raises `BilledUnusableReply`; `place_dedupe_job.check` turns it into
  `unsure` for that pair (review fix; the call is charged to the run budget), so the rest of the band is still asked.
  Not moved in 282: moving it to `haiku-5-5` changes the verdict cache key
  (`stage_models`: every cached pair would be asked again, paid) and haiku-5-5 has not been smoke-tested on this
  schema. Proposed follow-up: smoke `haiku-5-5` on the verdict schema (adhoc stage), then a migration
  `a3_place_dedupe_check` → `haiku-5-5` with `haiku` as fallback.
- **`s1_source_facts`** has a legacy `haiku` FALLBACK only (primary `gpt-6-luna`, catalog); its parser strips fences and
  repairs JSON, and the call fails open. The S248 decision memo proposes dropping the route; left as is.
- `s1_brand_audit`, `t2_brand_audit`, `writing_memory_mine`, `a3_place_dedupe` are on catalog keys (Luna) and are not
  affected; an admin moving one of them to `haiku` / `sonnet` now gets schema-checked replies instead of silent free
  text.
- No paid call or AWS call was made for this change; the live proof is the next `supply_content_draft` run on Dev
  after 282 is applied (expect `llm_call_log` model `sonnet-5-5`, `output_parsed: true`).
