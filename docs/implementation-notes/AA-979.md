# AA-979: CRM-P2a, the tenant portal leaves this repo (freeze of the CIS copy)

Linear AA-979 (card CRM-P2, root ADR 0010 §6). Stage P2a moves `portal/` into
`AdventureAsia365-Ecosys/AA-Partner/portal` with its history, on the same Vercel project (`aa-cis-portal`) and the
same tenant API-key sign-in. This file covers the AA-CIS-App side (P2a-3); the move itself, the Partner deploy
workflows and the ported guards are described in AA-Partner `docs/implementation-notes/AA-979.md`. Session S250,
agent Claude Code.

## Decisions

- **Cut** = `d1e0eb43` (main after #980). `portal/` tree at the cut: `ba736844f356f5d13aa40e4fc378c460e5efbfb7`,
  118 files. AA-Partner's imported `portal/` has the identical tree id.
- **Freeze guard, not deletion.** `portal/` stays here, unchanged and undeployed, until P2b + 7 days (ADR 0010 §6), so
  a rollback to the CIS-built deployment stays possible. `tests/unit/test_aa885_portal_split.py`
  `test_portal_copy_is_frozen` pins the tree id: any commit that changes a byte under `portal/` fails Unit Tests,
  with a message that says to make the change in AA-Partner.
- **No CIS workflow deploys the portal any more**: `vercel-deploy-portal.yml` and `ui-smoke-portal.yml` are deleted,
  and the test that checked them is inverted ("no CIS workflow deploys the portal or calls its smoke").
- **Portal smoke moved**: `tests/e2e/smoke-portal/` and the Playwright projects `smoke-portal-setup` / `smoke-portal`
  are removed (the specs live in AA-Partner `e2e/smoke-portal/`).
- **Dependabot**: the `/portal` npm entry is removed (a security PR against a frozen copy would fail the freeze guard).
- **Byte-copy tests of the vendored kit dropped** from `test_aa885_portal_split.py`: the frozen copy cannot follow a
  kit change here (the freeze guard would fail), and AA-Partner's "Vendored CIS copies" check now compares its
  `portal/` kit with `frontend/` on CIS main. A kit change here is copied into AA-Partner `portal/` afterwards.
- **`test_aa760_muted_contrast.py`** checks `frontend` only, and the "admin and portal share the muted palette" test
  is gone: an admin palette edit must not force an edit of the frozen copy. AA-Partner checks the portal tokens.
- **Kept**: "Portal Build" (the frozen copy still builds; it is a required check, removed with `portal/` in the
  deletion step by the admin login), "Portal Lint" (non-required), the admin-side tests (308 to the portal host, gate
  and rbac staff-only, tenant proxy staff-only) and the other tests that read portal files (aa820, aa886, aa911,
  aa760 metering, login cross-links): they read frozen files, so they stay green and still describe what is live
  until the Partner deploy replaces it.

## Changed

- Plan P2a-3 said "keep the admin-side tests"; `test_context_lists_the_vendored_files` was also removed (the list in
  CONTEXT.md now points to AA-Partner).

## Tradeoffs

- Keeping the portal-reading tests (aa820, aa886, aa911) costs nothing while frozen and documents the live portal
  until P2b; they go with `portal/` in the deletion PR.

## Should know

- **Merge only after the AA-Partner production deploy of the portal is verified live** (AA-Partner P2a-2), so the
  portal is never without a deployer, and never with two.
- **After the merge**, the orchestrator deletes from AA-CIS-App the repo variable `VERCEL_PORTAL_PROJECT_ID` and the
  secrets `VERCEL_PORTAL_BYPASS_SECRET` and `E2E_TENANT_API_KEY` (old branches can still run the old workflows with
  repo-level values; lesson S241). `VERCEL_TOKEN` stays: the admin workflow uses it.
- No ECS deploy: `deploy-dev.yml` does not watch any changed path.
- To change the portal now: AA-Partner `portal/`. If an emergency fix must ship from here before P2b, re-pin the tree
  id in the freeze guard in the same PR and say why in this file.
