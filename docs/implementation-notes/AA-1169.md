# AA-1169 — T9 blog first-pass yield under the W5 measure

Goal (tech lead, S286): first-pass yield >= 0.30 on the W5 T9 sample (12 GATE items of golden aa729, the `w5-t9`
proof), errors per blog still non-inferior, median requests <= 5, 0 contract violations, 0 unsupported trip promises.
S285 measured 0.083 (1 of 12) with 3.5 flagged claims per blog on arm B (A 4.67, non_inferior, upper bound 1.00 < 4.0).

## S292 lane e-t9-yield ($0 part, 25/11/2026)

### What "first pass" means under W5 (read from code, no assumption)

- Arm B's first pass is the writer's first draft only: R2 regenerate calls `eval_writers._t9` ->
  `generate.write_content` (no repair, no deterministic fix step, citation tags still in the text).
- An item fails when the pinned claim instrument (AA-1048 two-step v7, advisory) flags ANY sentence of >= 3 words in
  any reader field (title, meta, slug, body, FAQ). `first_pass_yield = 1 - item_fail_rate` (decision.computed_metrics).
- The instrument names no policy class (`failure_codes` empty, class `claim.unsupported`), so "which gate fires first"
  has no stored answer: this lane adds a deterministic classifier of the flagged sentences.
- The production T10 gate stack plays no part in the W5 verdict.

### Decisions

- **A $0 diagnosis command, not a guess.** `python -m services.writer_proof.runner first-pass --prereg w5-t9
  [--fixed <classes>]` (READ ONLY, no model call) reads the counted B run's rows (output, details.judge_claims, the
  item input) and prints, per arm: items, passes, flags per item, and per claim class the items whose FIRST flag it
  is, the items with the class, the items it fails ALONE, flags per field (seo / body / faq). `--fixed` projects the
  yield and the pre-registered verdict if a fix removed every flag of those classes (an upper bound). It also re-runs
  the deterministic T10 gates on each stored draft (`f9_results=[]`: the F9 judge is never called).
- **Classes = the writing policy topics** (writing_policy.yaml `claims`): number (D1), rarity (D13), suitability
  (D14), route_timing (D4/D15 timing, F17 direction), scene (D15), operator (D2), reflection (D3), other. First match
  in that order wins. Regex on the sentence itself; the instrument's `why` is not read (it is free text).
- **Counts only in the output**, no claim text (the runner prints ids and counts; public repo, tenant text).
- **The stored B rows are only on Dev.** This lane may not ECS exec, so the exact counts are a live step for the
  orchestrator; the local evidence below is a proxy.

### Should know

- The projection is an upper bound: a prompt rarely removes a whole class, and a rewritten sentence can be flagged
  for something else. It turns an arm-B fail into a pass only when the fail came from claims alone: a hard stop (QA
  artefacts, an isolation leak, injection), a fail with no flagged claim or a fail with a failure code no flagged
  claim carries stays a fail, and a pass stays a pass (review fix: before it, a hard-stop fail with no claims became a
  pass; the row query now reads `hard_stop` and `failure_codes`). S285 had 0 hard stops, so its numbers do not move. Under the instrument's precision the 0.30 target needs about two thirds fewer flags per blog
  (Poisson: yield 0.30 at about 1.2 flags per blog; 3.5 today).

### Decisions (writer fix)

- **A blog-only CLAIM CHECK block behind a switch, default off.** `prompts._BLOG_CLAIM_RULE` follows the length block
  of a blog prompt (first draft and rewrite) while the setting `cis.t9.blog_claim_rule` is on (CIS 490, bool,
  platform, maker-checker; `claim_rule.enabled()`, any read problem = off). Off renders v9 byte for byte (the AA-1167
  parity hashes, re-checked in `tests/unit/test_aa1169_blog_claim_rule.py`). S272 rule: a writer prompt change ships
  behind a switch whose default is main; the paid re-measure decides.
- **What it targets** (the proxy's top classes, all existing policy topics): route and time narration (D4 / D15, F17
  direction; the repair prompt already forbade an added time of day, the first draft did not), ranking and rarity
  (D13), the reader's day (pace, ease, who it suits, what the reader sees or feels: D14 / D15; how the brand plans
  the trip: D2), plus "restate a seed fact in the seed's own words" for the paraphrase false positives. It keeps
  SOURCE FIDELITY's place background and adds no length number.
- **Not in writing_policy.yaml.** A policy edit changes `policy_sha`, which every prompt that reads the policy and the
  eval judge's source layout hash: a cascade of version bumps for a switch that is off by default. The block lives in
  prompts.py (hashed, t9_write v10) and names the policy topics it narrows.
- **Not a gate threshold change.** The W5 item verdict has no threshold (any flagged claim fails the item); counting a
  blog as a first pass with k flagged claims would change the pre-registered measure, which is the tech lead's call,
  not this lane's.
- **Re-measure = a new pre-registration** `w5-t9-r2` (DRAFT): w5-t9's sample, judge, metrics and decision on the
  active golden version 1.7.0 (null carry from 1.5.0), cap 5 USD. Registration (status, lock sha) is a reviewed PR
  after the tech lead's yes.

### Tradeoffs

- A prompt block cannot be proved at $0: the projection (`--fixed`) is an upper bound and the proxy is 4 blogs. The
  switch keeps production unchanged until the paid re-measure shows the effect.
- Plainer prose: "restate in the seed's own words" may read flatter; F15_voice and the brand panels still apply.
- Length: fewer commentary sentences can leave a thin seed under the F4 floor more often; the block says to reach the
  length with seed facts and place background, and the re-measure reports words per blog through the gate replay
  (F4_extreme_length counts).
