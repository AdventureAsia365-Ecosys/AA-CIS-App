# AA-1169 — T9 blog first-pass yield under the W5 measure

Goal (tech lead, S286): first-pass yield >= 0.30 on the W5 T9 sample (12 GATE items of golden aa729, the `w5-t9`
proof), errors per blog still non-inferior, median requests <= 5, 0 contract violations, 0 unsupported trip promises.
S285 measured 0.083 (1 of 12) with 3.5 flagged claims per blog on arm B (A 4.67, non_inferior, upper bound 1.00 < 4.0).

## S292 lane e-t9-yield ($0 part, 25/11/2026)

### What "first pass" means under W5 (read from code, no assumption)

- Arm B's first pass is the writer's first draft only: R2 regenerate calls `eval_writers._t9` ->
  `generate.write_content` (no repair, no deterministic fix step, citation tags still in the text).
- An item fails when the pinned claim instrument (AA-1048 two-step v7, advisory) flags ANY sentence of >= 3 words in
  any reader field (title, meta, slug, body, FAQ). `first_pass_yield = 1 - item_fail_rate` (decision.computed_metrics).
- The instrument names no policy class (`failure_codes` empty, class `claim.unsupported`), so "which gate fires first"
  has no stored answer: this lane adds a deterministic classifier of the flagged sentences.
- The production T10 gate stack plays no part in the W5 verdict.

### Decisions

- **A $0 diagnosis command, not a guess.** `python -m services.writer_proof.runner first-pass --prereg w5-t9
  [--fixed <classes>]` (READ ONLY, no model call) reads the counted B run's rows (output, details.judge_claims, the
  item input) and prints, per arm: items, passes, flags per item, and per claim class the items whose FIRST flag it
  is, the items with the class, the items it fails ALONE, flags per field (seo / body / faq). `--fixed` projects the
  yield and the pre-registered verdict if a fix removed every flag of those classes (an upper bound). It also re-runs
  the deterministic T10 gates on each stored draft (`f9_results=[]`: the F9 judge is never called).
- **Classes = the writing policy topics** (writing_policy.yaml `claims`): number (D1), rarity (D13), suitability
  (D14), route_timing (D4/D15 timing, F17 direction), scene (D15), operator (D2), reflection (D3), other. First match
  in that order wins. Regex on the sentence itself; the instrument's `why` is not read (it is free text).
- **Counts only in the output**, no claim text (the runner prints ids and counts; public repo, tenant text).
- **The stored B rows are only on Dev.** This lane may not ECS exec, so the exact counts are a live step for the
  orchestrator; the local evidence below is a proxy.

### Local $0 evidence (proxy, private files under the root .tmp-session, not committed)

1. Claim instrument on T9 blogs (AA-1048 v7 pool, 62 fired t9_blog claims of 4 blogs, human-labelled): 6 true
   violations, 56 false positives. v7 kept 88 % of true violations and 46 % of paraphrase / 18 % of background false
   positives (gated run 46d645c4). At the t9_blog base rate about 3 of 4 flags on a blog are false positives
   (precision about 0.23, against 0.73 on the balanced gated subset).
2. Expected flagged share per class on that pool (the classifier, weighted by v7 survival per label group): rarity
   0.28, other 0.24, route_timing 0.23, number 0.12, suitability 0.06, scene 0.05, reflection 0.03.
3. Human labels of the 12 GATE controls: 8 pass (light) and 4 fail, while the instrument passed 1 of 12. The light
   fixes the panel names are mostly an order or time the source does not give ("Day 7 begins with", "the evening's
   first stop") and loose route framing; the 4 fails are a wrong / invented fact or a significance claim.
4. Deterministic T10 gates re-run on the 12 GATE stored texts (production finals, not first drafts): 1 passes; first
   failure F15_voice 5, F4_extreme_length 4, F2_banned_patterns 1, F13_leak 1. On all 34 t9_blog golden texts: 4 pass.

### Should know

- The projection is an upper bound: a prompt rarely removes a whole class, and a rewritten sentence can be flagged
  for something else. Under the instrument's precision the 0.30 target needs about two thirds fewer flags per blog
  (Poisson: yield 0.30 at about 1.2 flags per blog; 3.5 today).
