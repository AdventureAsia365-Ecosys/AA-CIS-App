# AA-838 — capacity review decisions (CIS part: D9 application_name)

Session S256 (28/10/2026), Claude Code lane. Branch `feat/aa-838-application-name`. Source: root
`docs/audits/2026-10-28-S255-aa838-capacity/README.md` §4 D9 (approved by the tech lead in S256) and data
standards C1.1a ("every pool MUST set `application_name`").

## Decisions

- **One place, not forty call sites.** `shared/secrets.get_database_url()` now returns the DSN with
  `application_name=cis-direct` appended (`with_application_name`, pure). asyncpg turns unknown DSN query
  parameters into `server_settings`, and an explicit `server_settings` argument wins over the DSN
  (`connect_utils._parse_connect_dsn_and_args`: `{**query, **server_settings}`), so the named pools keep their
  names (`cis-api`, `cis-tenant`, `cis-worker`, `cis-job`, `cis-job-a3-lock`) and every other connection built
  from `get_database_url()` stops showing as "(empty)" in `pg_stat_activity` / Performance Insights.
- **The eight direct `os.environ["DATABASE_URL"]` connects** (`api/routers/admin_pipeline.py` ×4,
  `api/routers/jobs_repo.py` ×2, `services/content_generation/s1_batch.py`, `services/eval/regression.py`) now
  call `get_database_url()`. Same value in ECS (no `SECRET_DB_ARN` in the task definitions), plus the name.
- **Name `cis-direct`**, overridable with env `CIS_DB_APPLICATION_NAME`. The containers carry no variable that
  tells api from worker, and the role (`cis_app`) plus the `cis-` prefix already attribute the load to CIS;
  a per-process name can come later through that env var in Terraform if PI ever needs the split.
- **Only the query is touched.** The function appends `&application_name=…` / `?application_name=…` to the
  stripped string and never re-encodes the user/password/host part; a DSN that already names one, or that is not
  a `postgres(ql)://` URL, is returned as is.

## Changed

- `shared/secrets.py`: `DEFAULT_DB_APPLICATION_NAME`, `with_application_name()`, `get_database_url()` uses it.
- The four modules above: direct DSN → `get_database_url()`; `s1_batch.py` drops its now-unused `import os`.
- `tests/unit/test_aa838_db_application_name.py` (10 tests, incl. asyncpg's own DSN parser: default applied,
  explicit `server_settings` wins, credentials untouched).

## Tradeoffs

- Ad hoc S3-mediated ECS-exec scripts (`python3 /tmp/s.py`) do not import `shared.secrets`; they read
  `DATABASE_URL` themselves. asyncpg ignores `PGAPPNAME`, so they are covered by the runbook template instead
  (root `docs/ops/runbooks/ecs-exec-s3-mediated.md`: `server_settings={"application_name": "cis-exec"}`).
- Not touched: the Lambda `services/acp_produce/sweeper_lambda.py` (own DSN, not in the ECS services) and
  `scripts/` one-offs that build pools from parsed host/user/password (they get the name only if they pass the DSN).

## Should know

- Behaviour change is the session name only; no query, pool size or timeout changes. Visible after deploy as
  `application_name = 'cis-direct'` in `pg_stat_activity` for `cis_app` sessions that used to be empty.
- Targeted tests: every unit test file that imports the touched modules or `shared.secrets` (4,804 passed).
