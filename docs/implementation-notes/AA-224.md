# AA-224 — Bedrock streaming + read timeout fix

## Context
Sonnet branded prompts were silently falling back to Haiku. Root cause: non-stream
`invoke_model` held the HTTP connection open for the full generation; with the default
~60s read_timeout, long Sonnet generations hit the socket timeout, raised, and triggered
the quality-fallback path to Haiku.

## Decisions
- **Step 2/4 — patch `_call_bedrock` in `shared/llm_client/client.py`** (this step).
- Switch `invoke_model` → `invoke_model_with_response_stream` so chunks arrive
  incrementally and the socket never idles past `read_timeout`.
- Add `botocore.config.Config` on the `bedrock-runtime` client:
  `read_timeout=300`, `connect_timeout=10`, `retries={max_attempts:2, mode:standard}`.

## Changed
- Streaming usage accounting now spans events:
  - `input_tokens` + cache read/write counts from `message_start`.
  - `output_tokens` (cumulative) from `message_delta`.
  - text accumulated from `content_block_delta` (`text_delta`).
- Replaces the previous single-read `result["content"][0]["text"]` + `usage` block.

## Tradeoffs
- Streaming adds per-event JSON parsing overhead vs. one final read — negligible vs.
  the timeout failure it prevents.
- `output_tokens` from `message_delta` is cumulative; we take the last value rather than
  summing deltas.
