## Decisions

- BUG 1 backend: disambiguate brand JOIN using `gc.metadata->>'brand_name'` — since multiple brands can share the same `version` integer (Atlas&Hearth v1, Trail Pulse v1), joining only on `version + tenant_id` would return wrong rows. The `metadata` JSONB already stores `brand_name` from `_execute_run_tour`; using it makes the JOIN unambiguous without adding a new column.
- BUG 1 frontend: update `HistoryRow` interface to carry `brand_name: string | null`; render as `${brand_name} · v${brand_rules_version}` with null-safe fallback.
- BUG 2: clear `tourStatuses` AFTER `loadTours()` completes inside `startRun`; update the progress bar guard from `Object.keys(tourStatuses).length > 0` to `Object.keys(tourStatuses).length > 0 || runComplete` so the "View in Master Content" button still appears after tourStatuses is wiped.
- BUG 3: clear `runResults + tourStatuses + runComplete` when the "Run Rewrite" button is FIRST CLICKED (before the confirm dialog), not only inside `startRun`. This prevents stale "1 failed" from the previous run appearing while the confirm dialog is open.

## Changed

- `api/routers/admin_pipeline.py` `get_tour_history`: adds `gc.tenant_id`, LEFT JOIN `tenant_brand_rules` ON `version + tenant_id + metadata brand_name`, returns `brand_name` in response.
- `frontend/app/admin/_components/TourDetailPanelV2.tsx`: `HistoryRow.brand_name` field; Brand V cell shows `${brand_name} · v{n}`.
- `frontend/app/admin/s1-rewrite/page.tsx`: three changes — (1) `startRun` clears tourStatuses after loadTours, (2) progress bar guard adds `|| runComplete`, (3) "Run Rewrite" button click pre-clears stale state.

## Tradeoffs

- The metadata JOIN is a LEFT JOIN: rows without `brand_rules_version` (older versions) or without metadata `brand_name` key return NULL for `brand_name`, displayed as "—" in the UI. Acceptable for backward compatibility.
- Not adding a dedicated `brand_name` column to `generated_content` — that would require a migration; reading from metadata JSONB is sufficient and avoids schema churn.

## Should know

- `gc.tenant_id` was not previously in the `get_tour_history` SELECT; it's now added to support the JOIN condition. It's not exposed in the response (no need to expose tenant_id on history rows).
- Progress bar will show "Rewrite Progress + View in Master Content" (no counts) when runComplete=true but tourStatuses is empty — that's the intended post-clear state.
