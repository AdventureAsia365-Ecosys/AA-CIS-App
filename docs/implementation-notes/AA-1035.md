# AA-1035 — R2 staff roles and tenant scope (slice 1: backend and data)

Sources: root `docs/adr/0019-b2b-only-ecosystem-model.md` d3 / d4 (d5 for context), the role table and permission
matrix in root `docs/audits/2026-11-03-S265-ecosystem-restructure/clarifications.md` section 3, Linear AA-1035.
Other halves: AA-CIS-Infra (WORKFORCE groups), AA-Booking (bk-038 + the finance role), root (DM-7.1 rows).

## Decisions
- **Migrations (batch cis 362-364).** 362 only adds the six enum values (a value added in a transaction can not be
  used in it). 363 (contract) merges `reviewer` rows into `content`, sets the column default to `content`, replaces
  `admin_users_email_chk` (the A10 E2E address may be `reviewer` or `content`) and adds `'finance'` to
  `staff_app_grant_role_chk`. 364 (contract since the S267 review, see below) creates `shared.staff_tenant_assignment` (PK staff + tenant, kind
  owner / backup / support, partial unique index: one owner per tenant) and `shared.staff_view_as_session` (schema
  only: reason 3-500 chars, expiry at most 60 minutes after start, end reason; FK RESTRICT to the staff row so the log
  outlives a disabled account). No RLS, like `staff_app_grant` / `staff_crm_grant` (both on the X2 RLS catalogue rule a
  allowlist); grants to `cis_app` after REVOKE ALL (no UPDATE on the assignment table: a kind change is delete +
  insert). The view-as log is append-only by a guard trigger (UPDATE only ends an open session, DELETE only for an
  offboarded or deleted tenant, no TRUNCATE); `cis_app` holds DELETE on it for the AA-839 erasure only.
- **The A10 E2E reviewer row is not merged.** The WORKFORCE pre token trigger issues its tokens only with exactly
  `cis-reviewer`; moving the row (and the trigger) to content is part of removing the alias. Its sign-in resolves to
  `content` (the alias) and the drift checks compare the alias as content.
- **`reviewer` stays a role for one release**: in `ROLE_PERMS` (same set as content), accepted by the directory
  validator (not offered on the Staff page), `cis-reviewer` maps to `content` in `GROUP_ROLES`. The reconcile job
  reports a merged person whose group is still `cis-reviewer` (row `content`) as drift, so "Sync" moves them to
  `cis-content`.
- **Capabilities.** `tenant.read` keeps "every tenant" (only admin); the split adds `tenant_content.read`,
  `catalog.read`, `tenant.book.read`, `tenant.member.write`, `tenant.assign`, `billing.read`, `billing.write`,
  `wave.run`, `lab.read`. A POLICY entry may be `any_of(...)` (a tuple). Every role is one explicit set.
- **Deny by default for unlisted GETs**: they need `content.read`. Every role that had it before R2 still has it, so
  nothing changes for admin / content / reviewer / viewer; customer_success, support and finance reach only listed
  routes. The machine (secret, no role) keeps the unlisted GETs (CI smoke).
- **`require_tenant_scope`** is a route dependency (`dependencies=TENANT_SCOPED`) on all 50 staff routes with
  `{tenant_id}` (47 existing + 3 assignment routes); a unit test walks the app and fails on a missing one, and also
  pins the two tenant-token routes outside the staff prefixes. Scope kinds: all (admin, finance, ai_ops,
  content_lead, tenant_qa), book (customer_success), book + pool (support), internal (content, reviewer, viewer).
  Pool = agency / demo tenants without an owner assignment or in the `tech_touch` segment.
- **Staff identity for the scope**: the verified Cognito identity; with the MAIN admin secret (machine / CI /
  operator), `x-admin-user-id`. The main secret already lets its holder claim admin, so this grants nothing new and
  makes the live isolation check runnable without a Cognito session. Preview credential: viewer, internal only.
- **Directory** `GET /admin/tenants` filters its rows in Python by the scope set (tens of tenants).
- **PATCH `/admin/tenants/{id}`** is field-level: `tenant.write` any field; `billing.write` (finance) only
  `plan_tier` and `is_active` (plan change, suspend for debt).
- **Content-quality writes** check `quality.write` instead of `x-admin-role == "admin"` so content_lead and tenant_qa
  can do Tenant QA (admin unchanged; reviewer / content still refused).
- **Booking bridge**: every R2 role is in `NO_BOOKING_ROLES` (no bridge token); Booking reads finance from the group.
- **Infra groups**: the six `cis-<role>` groups were added too (not only `booking-finance`), because the role comes
  from the group; without them no one can hold a new role.

## Changed (vs. the slice brief)
- Added assignment API routes (GET / PUT / DELETE `/admin/tenants/{tenant_id}/assignments[/{admin_user_id}]`) in
  this slice: the Assignments page (slice 2) is UI only, and the live isolation check needs a way to assign.
- `frontend/lib/rbac.ts` (role union, capability mirror, labels, page / BFF rules) and the Staff page role lists
  changed: the backend <-> frontend parity tests require it, and the BFF must let the tenant desk roles through.
  The new nav entries per role follow the matrix; no new page.

## Tradeoffs
- `GET /admin/tenants/{tenant_id}/details` now has a POLICY entry (content.read | tenant.read | tenant.book.read), so
  the machine gets 403 there (it never called it; the route already refused the machine for any tenant but aa_internal).
- customer_success sees Tenant 360 tabs of its book incl. cost and quality (matrix: "AI & spend R (own tenants)",
  "Tenant QA R (own)" is slice 2 for the tenant text list pages).
- Unlisted GETs that are not content (notifications, search, job list) are refused for the tenant desk roles; the
  bell in their topbar will need its own capability when their UI lands (slice 2).
- ai_ops gets AI writes in the Writing Lab but no tenant-text read yet (the logged Lab read is slice 2); release
  reads (ids, statuses, numbers) are `lab.read`.

## Should know
- **Order:** root DM-7.1 PR → CIS migration PR (batch 362-364, all contract; Migration Apply is parked at the
  unapplied 336, so a person applies 362, 363, 364 with DB Migrate apply when every job table is idle) → Infra RLS
  rules copy PR + Infra groups PR → this code PR (readiness requires 362-364 above the 336 gap) → Booking bk-038
  PR → Booking code PR. Do not assign an R2 role on the Staff page before the Infra apply (AdminAddUserToGroup fails,
  "saved, Cognito pending").
- After deploy, every merged reviewer shows as drift in the Staff directory health until "Sync" (adds cis-content,
  removes cis-reviewer). Until then they sign in as content (alias) — no access change.
- `tests/unit/snapshots/aa1035_role_route_matrix.json` pins every role x route decision; regenerate it with
  `python -m tests.unit.test_aa1035_role_matrix` after a deliberate change and review the diff.
- Follow-ups (slice 2): view-as endpoint + banner + log writer, Assignments page, ai_ops logged Lab read
  (`tenant_content.read` in Lab only), `crm.ops.v1` relay of the staff scope, a staff-common capability for the
  bell, Tenant QA list filtering for customer_success, removing the reviewer alias (row, trigger, CHECK, group).

## S267 fix pass 1 (independent review findings)
- **support vs the owner seat.** support held `tenant.member.write` on its book and the pool, and the invite / PATCH
  accepted `content_studio_role: owner`; the send-again re-seals an invitation to the address typed in the body. So
  support (and customer_success) could make any address the Content studio owner of an unowned agency. Fix: new
  `tenant.member.resend` (support: the send-again route only); customer_success keeps `tenant.member.write`; every owner
  write (invite as owner, change to / from owner, remove an owner, send an owner invitation again) needs `tenant.write`
  in the route (`admin_tenant360._require_owner_tier`; the role change and removal check the LOCKED row in
  `services/tenant_membership/writer.py`, `allow_owner=False`). `GET .../members/access` leaves `owner` out of
  `invite_roles` and adds `owner_writes`; the Members tab hides change role / remove on an owner row and the owner
  choice in the role dialog (`frontend/lib/tenantMembers.ts roleChoices`, `memberRowActions`).
- **Rejected part: "send again to its stored address".** Neither system can read the first address back: CIS never
  stores it (root ADR 0010a; `shared.tenant_members` has no address column) and the CRM seals it under the token,
  whose hash is all it keeps (`AA-Partner api/app/members/studio.py seal_email`, re-sealed on every issue). A stored
  address would need a new CIS column (PII, ADR 0010a change) or a CRM resend-by-id endpoint (Partner, out of this
  lane). Narrowest safe alternative taken: support may re-send only editor / viewer invitations (an owner invitation
  needs `tenant.write`); a support member can still re-address an editor / viewer invitation (audited by the CRM relay
  log, scoped to its book and the pool). Follow-up for Partner: a resend that keeps the sealed address.
- **"Reset MFA" has no CIS route**: tenant member MFA and owner recovery live in the CRM (`/admin/platform/crm/...
  owner-recovery`, `tenant.write`); nothing to grant support here.
- **finance opens Tenant 360.** `GET /admin/tenants/{id}/details` now takes `billing.read` too and answers a caller
  without `tenant.read` / `tenant.book.read` / `content.read` the header only (plan, usage, cost): no tours, pipeline
  runs or brand rules (those queries do not run). The panel shows only Billing and Subscription to such a role.
- **Tenant picker for the content side.** New `GET /admin/tenant-names` (id, name, slug, derived status; filtered by
  `tenant_scope_filter`) under `any_of(tenant.read, tenant_content.read, tenant.book.read, billing.read, lab.read,
  spend.read)`: lab.read and spend.read added to the brief's list because ai_ops holds neither of the others and is
  one of the roles the finding names. content / reviewer / viewer stay out (they see no tenant but aa_internal).
  `frontend/lib/tenants.ts TENANTS_API` points at it (same cache key; DataErasure reads the same fields).
- **ai_ops on the Writing Lab pages**: `PAGE_RULES /admin/lab` = admin, content_lead, tenant_qa, ai_ops. The
  tenant-text panels of Writing memory (signals, candidates, exemplars) still answer ai_ops 403 until the logged Lab
  read (slice 2); releases, the stage pages and every ai.admin write work.
- **customer_success writes its book.** New `tenant.book.write`: `PUT .../config`, `PUT .../brand-identity` and
  PATCH `/admin/tenants/{id}` for every field but `plan_tier` / `is_active` (RPM, publish limit; the S267 review's
  "billing" split). Plan, suspend, generate-key, offboard / restore, entitlement overrides and the add-on saga stay
  `tenant.write` / `billing.write`.
- **schema-gate and the preflight see REQUIRED_CIS_ABOVE_GAP.** `.github/scripts/schema_gate.py readiness_keys` adds
  the literal tuple's keys; `required_keys` takes the strict-prefix file range up to `REQUIRED_CIS_SCHEMA` only
  (`strict_top`), so 336 (the gap) is never required and 362-364 are. `migration_preflight.py` reads keys through it,
  so rule 3 / 4 see the above-gap raise without a change of its own. The file must stay identical in CIS, Booking and
  Partner (convention, no CI guard): the same bytes are committed on the Booking code branch of this lane; the
  Partner copy (and its test) is a follow-up (no Partner worktree in this lane). The change is a no-op for booking /
  crm (their branch reads `REQUIRED_SCHEMA_VERSIONS` only).
- Tests: `tests/unit/test_aa1035_s267_fix_pass.py` (every finding through the real app with a fake connection),
  `tests/integration/test_aa1035_s267_fix_pass_pg.py` (owner seat, picker, finance header, CSM PATCH on real

## S267 fix pass 2 (deploy order vs. the Infra groups)
- **A missing group no longer blocks Sync or an existing-user create.** `CIS_GROUPS` / `BOOKING_GROUPS` now hold the
  R2 groups, and Sync plus the create-over-an-existing-user path remove every staff group the row does not hold.
  Cognito answers `ResourceNotFoundException` for a group the pool does not have, so if this code rolled before the
  AA-CIS-Infra groups apply (`terraform-apply.yml` runs on dispatch only, merging the Infra PR creates nothing),
  every Sync and every re-create would end "saved, Cognito pending" for all staff, including the post-deploy Sync
  that moves merged reviewers to `cis-content`. Fix: `CognitoDirectory.remove_from_group` treats
  `ResourceNotFoundException` as done (a missing group holds nobody) and logs `staff_directory_remove_missing_group`
  with the group. Adding to a missing group still fails, so assigning an R2 role before the Infra apply still ends
  "saved, Cognito pending" (the warning in "Should know" stands).
- Tradeoff: a wrong pool id answers the same code; the create, add, enable and disable steps still fail on it, so
  only a remove-only role change (dropping a Booking grant) could pass silently, and the warning log names it.
- Order, said plainly: run the AA-CIS-Infra `terraform-apply` (WORKFORCE groups) before anyone assigns an R2 role;
  the CIS code deploy itself no longer depends on it.
- Tests: `tests/unit/test_aa816_staff_directory_writes.py::test_missing_group_is_fine_for_removal_only` (wrapper under
  Stubber) and `::test_sync_and_existing_user_create_succeed_before_the_r2_groups_exist` (Sync of a merged reviewer
  and create over an existing Cognito user, every R2 group answering `ResourceNotFoundException`); both fail without
  the fix.
