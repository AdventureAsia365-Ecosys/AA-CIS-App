# AA-1035 — R2 staff roles and tenant scope (slice 1: backend and data)

Sources: root `docs/adr/0019-b2b-only-ecosystem-model.md` d3 / d4 (d5 for context), the role table and permission
matrix in root `docs/audits/2026-11-03-S265-ecosystem-restructure/clarifications.md` section 3, Linear AA-1035.
Other halves: AA-CIS-Infra (WORKFORCE groups), AA-Booking (bk-038 + the finance role), root (DM-7.1 rows).

## Decisions
- **Migrations (batch cis 362-364).** 362 only adds the six enum values (a value added in a transaction can not be
  used in it). 363 (contract) merges `reviewer` rows into `content`, sets the column default to `content`, replaces
  `admin_users_email_chk` (the A10 E2E address may be `reviewer` or `content`) and adds `'finance'` to
  `staff_app_grant_role_chk`. 364 (expand) creates `shared.staff_tenant_assignment` (PK staff + tenant, kind
  owner / backup / support, partial unique index: one owner per tenant) and `shared.staff_view_as_session` (schema
  only: reason 3-500 chars, expiry at most 60 minutes after start, end reason; FK RESTRICT to the staff row so the log
  outlives a disabled account). No RLS, like `staff_app_grant` / `staff_crm_grant`; grants to `cis_app` (no UPDATE on
  the assignment table: a kind change is delete + insert; no DELETE on the view-as log).
- **The A10 E2E reviewer row is not merged.** The WORKFORCE pre token trigger issues its tokens only with exactly
  `cis-reviewer`; moving the row (and the trigger) to content is part of removing the alias. Its sign-in resolves to
  `content` (the alias) and the drift checks compare the alias as content.
- **`reviewer` stays a role for one release**: in `ROLE_PERMS` (same set as content), accepted by the directory
  validator (not offered on the Staff page), `cis-reviewer` maps to `content` in `GROUP_ROLES`. The reconcile job
  reports a merged person whose group is still `cis-reviewer` (row `content`) as drift, so "Sync" moves them to
  `cis-content`.
- **Capabilities.** `tenant.read` keeps "every tenant" (only admin); the split adds `tenant_content.read`,
  `catalog.read`, `tenant.book.read`, `tenant.member.write`, `tenant.assign`, `billing.read`, `billing.write`,
  `wave.run`, `lab.read`. A POLICY entry may be `any_of(...)` (a tuple). Every role is one explicit set.
- **Deny by default for unlisted GETs**: they need `content.read`. Every role that had it before R2 still has it, so
  nothing changes for admin / content / reviewer / viewer; customer_success, support and finance reach only listed
  routes. The machine (secret, no role) keeps the unlisted GETs (CI smoke).
- **`require_tenant_scope`** is a route dependency (`dependencies=TENANT_SCOPED`) on all 50 staff routes with
  `{tenant_id}` (47 existing + 3 assignment routes); a unit test walks the app and fails on a missing one, and also
  pins the two tenant-token routes outside the staff prefixes. Scope kinds: all (admin, finance, ai_ops,
  content_lead, tenant_qa), book (customer_success), book + pool (support), internal (content, reviewer, viewer).
  Pool = agency / demo tenants without an owner assignment or in the `tech_touch` segment.
- **Staff identity for the scope**: the verified Cognito identity; with the MAIN admin secret (machine / CI /
  operator), `x-admin-user-id`. The main secret already lets its holder claim admin, so this grants nothing new and
  makes the live isolation check runnable without a Cognito session. Preview credential: viewer, internal only.
- **Directory** `GET /admin/tenants` filters its rows in Python by the scope set (tens of tenants).
- **PATCH `/admin/tenants/{id}`** is field-level: `tenant.write` any field; `billing.write` (finance) only
  `plan_tier` and `is_active` (plan change, suspend for debt).
- **Content-quality writes** check `quality.write` instead of `x-admin-role == "admin"` so content_lead and tenant_qa
  can do Tenant QA (admin unchanged; reviewer / content still refused).
- **Booking bridge**: every R2 role is in `NO_BOOKING_ROLES` (no bridge token); Booking reads finance from the group.
- **Infra groups**: the six `cis-<role>` groups were added too (not only `booking-finance`), because the role comes
  from the group; without them no one can hold a new role.

## Changed (vs. the slice brief)
- Added assignment API routes (GET / PUT / DELETE `/admin/tenants/{tenant_id}/assignments[/{admin_user_id}]`) in
  this slice: the Assignments page (slice 2) is UI only, and the live isolation check needs a way to assign.
- `frontend/lib/rbac.ts` (role union, capability mirror, labels, page / BFF rules) and the Staff page role lists
  changed: the backend <-> frontend parity tests require it, and the BFF must let the tenant desk roles through.
  The new nav entries per role follow the matrix; no new page.

## Tradeoffs
- `GET /admin/tenants/{tenant_id}/details` now has a POLICY entry (content.read | tenant.read | tenant.book.read), so
  the machine gets 403 there (it never called it; the route already refused the machine for any tenant but aa_internal).
- customer_success sees Tenant 360 tabs of its book incl. cost and quality (matrix: "AI & spend R (own tenants)",
  "Tenant QA R (own)" is slice 2 for the tenant text list pages).
- Unlisted GETs that are not content (notifications, search, job list) are refused for the tenant desk roles; the
  bell in their topbar will need its own capability when their UI lands (slice 2).
- ai_ops gets AI writes in the Writing Lab but no tenant-text read yet (the logged Lab read is slice 2); release
  reads (ids, statuses, numbers) are `lab.read`.
