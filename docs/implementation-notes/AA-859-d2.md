# AA-859 PR-D2 — PATCH /v1/content-writing/pieces/{id} on the tenant pool (W2)

Flag: `PIECE_EDIT_FLAG` = Redis key `aa859:piece_edit_pool` (declared in PR-S, wired here). No migration;
does not depend on 241 (content_piece has RLS + `INSERT, SELECT, UPDATE` for aa_app_user since 115/147/229).

## Decisions
- The SQL constant was renamed `_UPDATE_CONTENT_TEXT_QUERY` → `_PIECE_EDIT_SQL` (plan name). No other
  reference existed (grep of api/, services/, tests/).
- `update_piece_content_text` gained `request: Optional[Request] = None`, same convention as `fetch_piece` /
  `fetch_latest_piece_for_request`: the router passes it; a direct caller with only `pool` keeps the old path.
- Flag off keeps the **exact** old shape, including the audit row written on the same admin connection right
  after the autocommit UPDATE, and an audit failure still propagating (500). Only the flag-on path makes the
  audit best-effort, because there the audit is a separate MAIN write after the tenant transaction committed.
- One `aa859_piece_edit` log line per request (inside the block, after the UPDATE) with `used_tenant_pool`,
  `updated` (row matched or not), `tenant_id`, `piece_id`. Audit failure: `aa859_piece_edit_audit_failed`
  (warning), response still 200.
- No tenant connection is held across the audit insert: the audit runs after `acquire_scoped_conn` exits
  (commit + release), asserted by an ordering unit test.

## Changed
- `services/acp_content_writing/service.py`: `_PIECE_EDIT_SQL`, `_piece_edit_not_found`,
  `_write_piece_edit_audit`, `update_piece_content_text(..., request=None)`.
- `api/routers/v1_content_writing.py::update_piece`: passes `request=request`.
- Tests, new files only (to avoid conflicts with the sibling AA-859 PRs):
  - `tests/unit/test_aa859_piece_edit_pool.py` — fail-closed matrix for this route (helpers imported from
    `test_aa817_fail_closed_routes.py`), flag-off old shape, audit-after-commit ordering, audit failure on the
    flag-on path is a 200, not-found writes no audit, router → tenant pool.
  - `tests/unit/test_aa859_reentrancy_d2.py` — reentrancy stub entry (1 acquire, no nesting).
  - `tests/integration/test_aa859_piece_edit_pool.py` — real Postgres: precondition (RLS on, UPDATE grant,
    no audit_log grant), owner edits approved + held on the tenant pool with one audit row, both pools give
    the same answer, foreign tenant cannot edit (both pools), processing piece not editable, forgotten-WHERE
    (B cannot edit A's piece on the tenant pool; the admin pool does — sanity).
- Plan deviation: the plan lists `tests/integration/test_aa817_tenant_pool_content.py` and "flags module" as
  files; the flag already exists (PR-S) and the integration test is a new file instead of an edit, to keep
  the parallel PRs conflict-free.

## Tradeoffs
- Kept two audit shapes (same-conn on flag off, MAIN-after-commit on flag on) instead of one, to honour
  "flag OFF = exact old behaviour". When the flag has been on long enough to delete the off path, the
  same-conn branch goes with it.
- Best-effort audit on the flag-on path means an audit row can be lost (logged). Accepted per plan D2: the
  edit is already committed, and audit_log is never granted to aa_app_user.
