# AA-801 — Stabilise the T2 brand_fit / mission verdict

## Decisions
- Option (a) median-of-3 is implemented behind env `T2_JUDGE_REPEAT` (worker task def), values
  `single` (default, prod behaviour unchanged) or `median3`. Same env-flag pattern as
  `T2_JUDGE_GATE` (AA-792). Default stays OFF until the measurement (5 runs x 10 versions) shows the
  spread drop; Nghiệp flips it.
- Median3 runs the 3 judge calls in parallel (thread pool, one `contextvars` copy per call so the
  live-progress sink keeps working). It replaces the AA-714 near-threshold repeat for T2 (no double
  repeat: 3 calls, never 5). The AA-692/699 Jev tie-break (layer 3) is unchanged.
- Aggregation (`brand_fit.aggregate_runs`): median of brand_fit and of cross_brand_distinct
  (statistical median: odd count = middle value, even count = mean of the two middle values);
  mission = strict majority, a tie (only possible when a call failed and 2 remain) counts as
  absent (conservative, same `> n/2` rule AA-714 used). Feedback comes from the run whose brand_fit
  is closest to the median (first such run on a tie). Cost and tokens are summed over every call.
- Partial failure: when 1 or 2 of the 3 calls fail, the verdict is aggregated from the successes and
  `failed` is logged; when all 3 fail the error is re-raised, so judge_node's existing non-blocking
  except keeps validate's score (same as a single failed call today).
- Review fix: a call that is billed but unusable (JSON parse failure in `_judge`) now carries its cost
  on the exception (`billed_cost_usd`, read with `brand_fit.billed_cost`). `_judge_parallel` sums it
  into the aggregated `cost_usd` and records `{"failed": n, "failed_cost_usd": x}` in `runs` /
  `judge_runs`. When all calls fail the re-raised error carries the summed cost; judge_node still logs
  nothing in that case (unchanged behaviour of a failed single call — a separate concern).
- Shadow: not restricted to the first of the n calls. Restricting it needs a new LLMRequest flag in
  the gateway, out of scope; documented instead (CONTEXT.md T2 judge + Should know below).
- Storage: T2 judge results are only stored in `shared.llm_call_log.quality_signal` (the T2 job
  persists no `metadata.judge` — `tenant_tour_versions` has no judge column). Median3 adds
  `quality_signal.judge_runs = {mode, n, brand_fits, distincts, missions, chosen_brand_fit,
  chosen_distinct, chosen_mission, brand_fit_spread, failed}`. No migration.

## Changed
- `services/content_generation/brand_fit.py`: `BrandFitResult.runs` (new optional field, default
  `()`), `aggregate_runs()`, `score_brand_fit(..., repeat=1)`; the AA-714 near-band median now goes
  through `aggregate_runs` (same numbers for 3 runs; it already took the middle value).
- `services/content_generation/judge_node.py`: `t2_judge_repeat()` reads `T2_JUDGE_REPEAT`; T2 passes
  `repeat=3` when `median3`; `judge_runs` added to quality_signal only in that mode.
- Measurement script (not in the repo, never run by the lane):
  `AA-Ecosys/.tmp-session/s236/aa801_measure.py`.

- Review fixes (measure script): tenants are matched by slug (`trail-pulse`, `atlas-hearth`,
  `wildkind-travel`, `terra-family`, S229 audit table) with a name fallback — the old `%a&h%` pattern
  never matched "Atlas & Hearth". A tenant with 0 rows prints a WARNING and is listed in
  `summary.tenants_missing`. Drafts with no summary and no itineraries are skipped as
  `empty_content` (judge_node skips empty drafts too). A judgement that raises is charged to the $1
  guard: max(known billed cost, costliest judgement so far or `--call-estimate` x calls); the
  estimated part is reported as `estimated_failed_cost_usd`.

## Tradeoffs
- Cost: median3 = 3 judge calls per judge attempt (prod today: 1, or 3 when the first lands in
  6–8). S235 T2 cost was $0.269/version with up to 10 judge calls per job; median3 should cut the
  retries noise drives, but the measurement must show cost ≤ $0.30/version (Done-when).
- Parallel vs sequential: parallel keeps T2 latency ~one judge call; costs the same.
- Options (b) rubric anchors and (c) a different judge model are not implemented here — the script
  measures (a) vs current first.

## Should know
- With the flag OFF, `score_brand_fit` and judge_node behave and log byte-identically to before
  (pinned by tests).
- The measure script re-judges stored versions against the tenant's CURRENT brand pack (the pack may
  have changed since S235); both modes use the same pack, so the comparison is fair.
- Shadow spend: with `median3` ON and a shadow configured on the `t2_judge` route, each of the 3
  calls samples its own shadow, so shadow spend per judgement can triple. Check the route's
  `shadow_sample_pct` before flipping the flag.
- Per-call raw scores of the measurement live only in the S3 JSON; the `adhoc_aa801` llm_call_log
  rows carry the aggregated score plus `n_calls`.
- Unit tests: 24 in `tests/unit/test_aa801_t2_judge_median3.py` (incl. failed-call cost and
  contextvars visible inside the pool threads).
- The script disables the stage-route shadow (`LLMClient._start_shadow`) so the spend it logs under
  `adhoc_aa801` is the whole spend and the $1 guard is exact.
