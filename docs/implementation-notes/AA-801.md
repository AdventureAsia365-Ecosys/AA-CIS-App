# AA-801 — Stabilise the T2 brand_fit / mission verdict

## Decisions
- Option (a) median-of-3 is implemented behind env `T2_JUDGE_REPEAT` (worker task def), values
  `single` (default, prod behaviour unchanged) or `median3`. Same env-flag pattern as
  `T2_JUDGE_GATE` (AA-792). Default stays OFF until the measurement (5 runs x 10 versions) shows the
  spread drop; Nghiệp flips it.
- Median3 runs the 3 judge calls in parallel (thread pool, one `contextvars` copy per call so the
  live-progress sink keeps working). It replaces the AA-714 near-threshold repeat for T2 (no double
  repeat: 3 calls, never 5). The AA-692/699 Jev tie-break (layer 3) is unchanged.
- Aggregation (`brand_fit.aggregate_runs`): median of brand_fit and of cross_brand_distinct
  (statistical median: odd count = middle value, even count = mean of the two middle values);
  mission = strict majority, a tie (only possible when a call failed and 2 remain) counts as
  absent (conservative, same `> n/2` rule AA-714 used). Feedback comes from the run whose brand_fit
  is closest to the median (first such run on a tie). Cost and tokens are summed over every call.
- Partial failure: when 1 or 2 of the 3 calls fail, the verdict is aggregated from the successes and
  `failed` is logged; when all 3 fail the error is re-raised, so judge_node's existing non-blocking
  except keeps validate's score (same as a single failed call today).
- Review fix: a call that is billed but unusable (JSON parse failure in `_judge`) now carries its cost
  on the exception (`billed_cost_usd`, read with `brand_fit.billed_cost`). `_judge_parallel` sums it
  into the aggregated `cost_usd` and records `{"failed": n, "failed_cost_usd": x}` in `runs` /
  `judge_runs`. When all calls fail the re-raised error carries the summed cost; judge_node still logs
  nothing in that case (unchanged behaviour of a failed single call — a separate concern).
- Shadow: not restricted to the first of the n calls. Restricting it needs a new LLMRequest flag in
  the gateway, out of scope; documented instead (CONTEXT.md T2 judge + Should know below).
- Storage: T2 judge results are only stored in `shared.llm_call_log.quality_signal` (the T2 job
  persists no `metadata.judge` — `tenant_tour_versions` has no judge column). Median3 adds
  `quality_signal.judge_runs = {mode, n, brand_fits, distincts, missions, chosen_brand_fit,
  chosen_distinct, chosen_mission, brand_fit_spread, failed}`. No migration.

### Round 2 (S236) — options (b) rubric anchors and (c) a different judge model
- Measurement round 1 (9 S235 T2 versions x 5): current 6/9 versions with verdict spread <= 1, max 2.0,
  mission stable 3/9; median3 5/9, max 2.0, mission stable 5/9. Sampling more does not help, so the
  noise is in the rubric. Nghiệp chose to compare (a) median3, (b) anchors, (c) another judge model,
  and (b)+(c).
- (b) is behind env `T2_JUDGE_ANCHORS` (`on`/`1`/`true`/`yes`, default off), same pattern as
  `T2_JUDGE_REPEAT`; it combines with median3. `brand_fit.build_rubric_anchors()` builds the anchors
  deterministically (no LLM) from the graph state's brand_* fields = the tenant's T0 brand pack: name,
  core idea, audience + mindset, voice words (max 6), on-brand example (clipped to 400 chars at a word
  boundary), forbidden words (max 15, "caps brand_fit at 6"). Unfilled fields are left out of the
  anchors, never shown as "(none)". Anchors for both brand_fit and cross_brand_distinct (4/6/8/10;
  odd values only between two anchors).
- Mission test with anchors: "does the copy express the tenant core idea: <core_idea>?" answered
  true only with one VERBATIM itinerary sentence in a new optional reply key `mission_evidence`. The
  code enforces it: `require_evidence` turns an unquoted true into false. The quote is not
  substring-checked against the copy (models normalise punctuation; a strict check would flip true to
  false on whitespace) — it is logged (`quality_signal.mission_evidence`, 300 chars) for audit.
  Without a core idea the anchors still apply but the mission axis and reply shape stay as before.
- Reply schema: a superset (`mission_evidence` only when anchors + mission). Old parsers ignore it.
- (c) needs no gateway change: `LLMRequest.model_tier` is already the gateway's per-request override
  (one model, no route fallback, no shadow, catalog price). `score_brand_fit(model_override=...)`
  passes it through, and refuses it (ValueError) on any stage that is not `adhoc_*`, so app code can
  never pin a judge model past `shared.llm_role_config`; production changes go through the route.
- Alternative judge model for the measurement: `sonnet-5` (Claude Sonnet 5, Bedrock acc3 via Converse,
  catalog $2.00 in / $10.00 out per MTok, enabled). The t2_judge route is all OpenAI-vendor
  (gpt-5.6-luna -> gpt-6-luna -> gpt-6-luna-openai); the catalog's only other chat vendor is
  Anthropic. Sonnet 5 over `haiku` ($1/$5): a stronger reader of brand nuance, and haiku already
  writes T2 flag-fix/nudge edits. Over `opus-5-5` ($4/$20): 2x cheaper. It is a different model
  generation from the T2 writer (`sonnet` = 4.5/4.6) but the SAME vendor, so adopting it on the
  t2_judge route would break the writer != judge vendor rule (ADR 0006 §5 / ADR 0008; the admin route
  save enforces it). Measurement only; adoption needs Nghiệp + an ADR amendment.
- Cost accounting (round 1 question "why is median3 cost_per_judgement equal to current?"): the v1
  numbers are correct. "current" is not one call: luna takes no seed, so the AA-714 near-band layer
  re-scores twice whenever the first brand_fit lands in 6..8 — nearly every S235 draft — and sums the
  three costs. Both modes therefore billed ~3 calls per judgement (~$0.0005 each). v1 just could not
  show it (`calls` = null in current mode). v2 counts every billed reply with a ledger around
  `LLMClient.generate` and reports `billed_calls` / `calls_per_judgement`.

- Round 2 review fixes (S236): (1) the mission quote is checked in code — `evidence_in_source()`
  folds case, whitespace, typographic quotes/dashes and markdown emphasis, strips surrounding quotes,
  trailing punctuation and a trailing ellipsis, needs >= 4 words, and must be a substring of
  `itinerary_digest(generated["itineraries"])` (exactly the shortened text the judge saw). A yes
  without such a quote is overruled to mission_present=false and recorded as
  `BrandFitResult.evidence_verified=False` (True = verified yes, None = not checked / plain no);
  logged as `quality_signal.evidence_verified` when the flag is on. (2) An explicit 7 anchor for
  brand_fit and cross_brand_distinct ("angle clear in the overview and at least half of the days"),
  "5 or 9" are the in-between scores. Reason: MIN_QUALITY = 7.0; with only 6/8 anchored a judge
  wavering between neighbouring anchors flips pass/fail with a spread of 2. Kept 4/6/8/10 rather than
  moving to 5/7/9 so the 6 = mission-cap and 8 = clear-pass meanings stay.

### Round 3 (S236) — fix after the live round-2 measurement
- Live result (9 S235 T2 versions x 5, Dev): `anchors` met the brand_fit target (spread <= 1 on 9/9)
  but mission=false on 45/45 judgements with no quote (evidence "", evidence_verified null, 0
  overruled), so every verdict was capped at 6; `current` had mission_true_share 0.73. Both sonnet-5
  modes: 45/45 `ValidationException ... temperature is deprecated for this model`, $0 billed.
- Mission root cause = the prompt, not the parser or the schema: the reply shape did ask for
  `mission_evidence` and `_judge` read that key; replies parsed (no errors), so the judge answered
  `false`. The round-2 wording asked for "one sentence VERBATIM ... that expresses" the core idea, and
  only then "true". A core idea is an abstract multi-clause line ("Private cultural journeys with
  depth, beauty, and meaning for discerning travellers"); no single itinerary sentence "expresses" it,
  and the digest cuts days mid-sentence, so a strict reasoning judge never found one to copy. It also
  dropped the AA-792 bar (overview + most days, not quoted) that gave 0.73.
- Fix keeps the design (a yes counts only with a code-verified >= 4-word quote from the itinerary
  digest): `mission_evidence` is asked FIRST (before mission_present, in the axis list and in the JSON
  shape): a passage of >= 6 consecutive words from the day whose emphasis best reflects the core idea,
  copied word for word, without the "…" cut marker; it does not have to name or restate the idea.
  `mission_present` = true when the quote is non-empty AND the AA-792 bar holds.
- Parser hardening found on the way: `bool(result.get("mission_present"))` read the strings "false" /
  "no" as True (the old yes/no wording invites a string answer). `_coerce_bool` reads true/yes/y/1 as
  yes and anything else (incl. null) as no; a missing key keeps the old default (True). A quote
  returned as a list takes its first non-empty item (`_coerce_text`).
- Sonnet 5: the gateway already omits temperature for a catalog row with `supports_temperature =
  false` (`_call_bedrock_converse`, `_call_openai`); the row was seeded true by migration 169.
  Migration 227 sets it false. Added a gateway guard: a Converse/ConverseStream call rejected with a
  ValidationException about temperature is retried once without it (not billed; warning
  `converse_temperature_rejected`), so a stale flag on another row degrades instead of failing.
- Consequence of 227: `brand_fit._seeded_model("satellite-sonnet-5")` is now False, so a sonnet-5
  judge gets the AA-714 near-band repeat like Luna (sonnet on Converse never received a seed anyway).
  The measure script pins one call per judgement for model-override modes (`_seeded_model` -> True
  while the mode runs; `--prod-repeat-for-models` to keep prod behaviour) so the comparison stays
  1 call/judgement and fits the budget.

### Round 3 review fixes (S236)
- Mission bar vs the 7 anchor: the round-3 text asked for "overview and most itinerary days", but the
  brand_fit 7 anchor is "overview and at least half of the days". In round 2, 29/45 anchored verdicts
  were 7; a consistent judge would answer mission=false for a 7, the cap drops it to 6, and it fails
  MIN_QUALITY 7 — an anchored pass would in effect need an 8. The anchored mission bar is now
  "overview and at least half of the itinerary days" (same threshold as the 7 anchor). The un-anchored
  AA-792 test keeps "most days": it has no 7 anchor and its prompt must stay byte-identical with the
  flag off. Also: "shows only in the summary or overview" is false.
- Migration 227 also sets `opus-5-5` `supports_temperature = false` (the only other Converse Claude 5
  row still flagged true; not observed failing, but leaving temperature out never fails a call).

## Tradeoffs
- Cost: median3 = 3 judge calls per judge attempt (prod today: 1, or 3 when the first lands in
  6–8). S235 T2 cost was $0.269/version with up to 10 judge calls per job; median3 should cut the
  retries noise drives, but the measurement must show cost ≤ $0.30/version (Done-when).
- Parallel vs sequential: parallel keeps T2 latency ~one judge call; costs the same.
- Options (b) rubric anchors and (c) a different judge model are not implemented here — the script
  measures (a) vs current first.

- Anchors lengthen the judge prompt by ~600-800 tokens (~+30% input on luna, still < $0.001/call).
- Quoted-mission rule is stricter than the AA-792 "overview AND most days" wording in one way (needs a
  quote) and looser in another (one itinerary sentence is enough). Chosen because it is checkable and
  binary; the measurement shows whether mission_true_share collapses (a stable but useless "always
  false" must not count as a win — v2 reports `mission_true_share` and `mean_brand_fit` per mode).
- Model comparison confound: (round 2 assumed sonnet-5 honours temperature — it does not, see round 3.)
  After migration 227 a sonnet-5 judge is unseeded; the measure script still runs it at 1 call per
  judgement, while luna `anchors` runs the prod AA-714 repeat (~3 calls). Compare spreads with that in
  mind; `--prod-repeat-for-models` measures sonnet-5 the prod way at ~3x cost.
- Round 3 mission wording: looser than round 2 (a passage that shows the idea, not one sentence that
  states it), still checkable. Risk: a judge quotes a generic passage and says yes; the quote is logged
  so an audit can read it, and the overview + half-of-days bar is still part of the yes.
- What `evidence_verified` means: `evidence_in_source` only proves the >= 4-word passage exists in the
  digest the judge saw. It does not check that the passage reflects the core idea (the prompt says it
  need not name it). A yes backed by a logistics line ("Your private guide meets you at the airport")
  verifies True (pinned by a test). So an anchored, verified yes = the judge's own mission verdict +
  "the quote is not invented"; read `mission_evidence` samples when auditing, not the flag alone.
- Mission bar (anchored) "at least half of the days" vs the un-anchored "most days": the anchored test
  is deliberately aligned with the 7 anchor; mission_true_share between `current` and `anchors` is
  therefore not a like-for-like bar.

## Should know
- With the flag OFF, `score_brand_fit` and judge_node behave and log byte-identically to before
  (pinned by tests).
- The measure script re-judges stored versions against the tenant's CURRENT brand pack (the pack may
  have changed since S235); both modes use the same pack, so the comparison is fair.
- Shadow spend: with `median3` ON and a shadow configured on the `t2_judge` route, each of the 3
  calls samples its own shadow, so shadow spend per judgement can triple. Check the route's
  `shadow_sample_pct` before flipping the flag.
- Per-call raw scores of the measurement live only in the S3 JSON; the `adhoc_aa801` llm_call_log
  rows carry the aggregated score plus `n_calls`.
- Unit tests: 24 in `tests/unit/test_aa801_t2_judge_median3.py` (incl. failed-call cost and
  contextvars visible inside the pool threads).
- The script disables the stage-route shadow (`LLMClient._start_shadow`) so the spend it logs under
  `adhoc_aa801` is the whole spend and the $1 guard is exact.
- Round 2: with `T2_JUDGE_ANCHORS` off (default) the T2 prompt, the `score_brand_fit` call and the
  logged quality_signal are unchanged (pinned by tests; prompt byte-identical checked against main).
- Estimated v2 spend: current/median3/anchors ~ $0.08-0.10 each; model:sonnet-5 ~ $0.28;
  anchors+model:sonnet-5 ~ $0.34 (estimate from ~2.3k input tokens per judge prompt). All five modes
  fit the $1.20 total guard; each model mode fits $0.40.
- Evidence check is strict on purpose (substring after normalisation): a judge that fixes a typo or
  merges two sentences is overruled. If `evidence_overruled` is large in the measurement, read the
  samples before deciding — it may be the judge paraphrasing (fix the prompt) rather than missing
  mission. The >= 4-word minimum stops a one-word "quote" passing.
- No 1-3 anchor band: a broken or off-brand draft lands at or below 4, enough for a pass/fail gate.
- Migration 227 must be applied (DB Migrate workflow) before the re-measure; the image must carry
  this PR (preflight checks both). It changes sonnet-5 and opus-5-5 (temperature off). 226 is left to
  the open AA-712 branch; DB Migrate applies one named file and does not check for gaps.
- Process: `AA-CIS-Infra/db/migrations/cis/` currently ends at 224, so 225 and 227 need the infra copy
  PR merged before DB Migrate can apply 227 — a step before the re-measure.
- Catalog cache TTL is 300 s: a running task keeps the old sonnet-5 flag for up to 5 minutes after
  227; the gateway temperature retry covers that window.
- Gateway retry scope: only Converse/ConverseStream rows with `supports_temperature` true reach it
  (after 227 none of the Claude 5 rows). The match needs ValidationException + "temperature" +
  deprecated / not supported / unsupported / not allowed; "temperature and top_p cannot both be
  specified" and maxTokens errors re-raise. `kwargs` is changed in place, so the AA-714 schema retry
  also runs without temperature. Before this PR a temperature error made `generate()` fall through to
  the next route model; now sonnet-5 succeeds directly. Live `shared.llm_role_config` writer routes on
  sonnet-5 were not checked.
- Parser change applies to every caller, flag on or off: `_coerce_bool` / `_coerce_text` also parse
  A1 s1_judge, T2 without anchors and Debate replies. JSON bools and a missing key (default True)
  behave as before; a string "false"/"no" is now no (fix), and any other non-yes string (e.g.
  "partially") is now no where `bool()` used to read it as yes. The flag-off PROMPT is unchanged.
- Round 3 was verified offline only (rendered prompt + canned replies); whether luna now says yes
  is what the re-measure answers — read `raw_mission_yes_share` and `raw_mission_samples` first.
- sonnet-5 in the measurement is an `adhoc_` override only; adopting it for t2_judge would be the
  same vendor as the T2 writer (ADR 0006 §5 / ADR 0008) and needs an ADR change + Nghiệp's call.
