# AA-757 — move `t5_atomize` onto the LLM gateway (no model change)

## What changed

`t5_atomize` was the last call site that bypassed the gateway: both atomize paths in
`services/acp_produce/tenant_pipeline.py` called
`shared.llm_client.bedrock_satellite.invoke_claude` directly, so the stage had no route, no
fallback, no shadow and could only run Claude models (lesson: *"đã lên gateway" phải kiểm theo
đường gọi, không theo việc có ghi cost* — AA-685 left this site because it already wrote
`llm_call_log`). This change moves both call sites onto `LLMClient.generate()` so the admin stage
route (fallback + shadow) applies and a non-Claude model can be selected. **This task is the move
only — the model switch to GPT-6 Luna and the A/B are Claude's, done separately.**

Both call sites now call:

```python
await asyncio.to_thread(
    LLMClient().generate,
    LLMRequest(system_prompt=_SYSTEM_PROMPT, user_prompt=prompt,
               stage="t5_atomize", max_tokens=4096),
)
```

- Stage `t5_atomize`, `SYSTEM_PROMPT` as the system prompt, `max_tokens=4096`.
- **No `model_tier`** → the admin stage route decides the model (fallback + shadow come for free).
- The call is still synchronous, wrapped in `asyncio.to_thread(...)` as before.
- JSON parse unchanged: `json.loads(_strip_json_fence(resp.content))["atoms"]` (was
  `llm_result.text`).

## Behaviour unchanged on today's config (haiku)

- Same prompt (`_build_user_prompt` / `_build_day_user_prompt` + `_SYSTEM_PROMPT`).
- Same per-day failure handling (a day whose call or parse fails keeps no fingerprint row and is
  retried next run; other days stay committed).
- Same day fingerprint: still keyed on `_t5_cfg.model_id` (the stage config is still read once up
  front for the fingerprint key and the `record_call` role). On haiku config the route is a single
  model, so `LLMClient` runs exactly that model — identical to the old direct Haiku call.

## Cost logging

`LLMClient.generate()` does not write `llm_call_log` itself, so exactly one
`record_call_with_pool` per call is kept, now reading the response instead of recomputing cost:

| field | before | after |
|-------|--------|-------|
| `model` | `llm_result.model_used` | `llm_result.model_used` |
| `tokens_in/out` | `llm_result.usage.get(...)` | `llm_result.input_tokens` / `.output_tokens` |
| `cost_usd` | `calc_cost(_t5_cfg.model_id, ...)` | `llm_result.cost_usd` |
| `role` | hardcoded `"writer"` | `_t5_cfg.role` (from the stage config) |
| `account` | `_t5_cfg.account_route or "acc3"` | `llm_result.satellite_account` |
| `fallback_used` | hardcoded `False` | `llm_result.fallback_used` |
| `provider` | hardcoded `"bedrock-satellite"` | `llm_result.provider` |

`calc_cost` and the `invoke_claude` import are removed from the module.
