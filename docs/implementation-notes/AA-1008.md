# AA-1008 — kit ShellFrame, visual job, suppression close-out (CIS part)

Lane l3 of S269 (Claude Code). CIS is the canonical kit repo: the ShellFrame and the Tabs roles are built here and
reach AA-Partner / AA-Booking through the Kit Sync bot. The consumer adoption, their visual jobs and their
suppression close-out are in AA-Partner `docs/implementation-notes/AA-1008.md` and AA-Booking
`docs/implementation-notes/AA-1008.md`. H3 (required checks in branch protection) is not in this lane: it needs the
tech lead's GitHub sign-in.

## Decisions

- **Slots, not data props.** ADR 0016 decision 1 says "a slot-based ShellFrame whose nav, identity, logout and brand
  label are props". The three shells differ a lot (CIS collapsible rail + RBAC nav + palette, CRM folded groups with
  the agency card and a sticky document-scroll layout, the studio's counts and search), and a data-driven nav in core
  would need router, RBAC and session imports that core must not have. So ShellFrame owns the frame and behaviour and
  takes `sidebar`, `topbar`, `bottomNav`, `palette`, `footer`, `banner` slots, each either a node or a function of
  the shell controls (open / close drawer and palette, `sidebarId` for `aria-controls`). `useShell()` gives the same
  controls to a component deeper in a slot.
- **What moved into core:** the layout, the drawer state and its CSS (off-canvas below the breakpoint, hidden from the
  tab order while closed, backdrop, Esc), the ⌘K / Ctrl K palette state, the two scroll models ("main": a one-screen
  column whose main scrolls; "document": the CRM's sticky sidebar over a scrolling document), and whether the shell
  or the page renders `<main>`. Breakpoints are 768 (CIS, Booking) and 900 (agency app), the two values the apps had.
- **CSS through a hoisted style element** (`ShellStyles`, `<style href precedence>` like `ButtonStyles`), keyed on
  `data-kit-shell` attributes with child selectors only, so a shell nested in a page (the gallery demo) never styles
  the outer one. No class names (kit lint), no `--aa-*` definitions.
- **Tabs roles (S6f "track Tabs roles"):** the track variant is now an ARIA tab list like the underline one
  (`role="tablist"` + `aria-label`, `role="tab"`, `aria-selected`, one tab stop, arrow keys, `disabled` + `title`).
  Sweep of the four repos' E2E / unit tests for `getByRole("button", { name })` on a track tab label: none found in
  CIS, AA-Partner, AA-Booking or TripPlanner (TripPlanner has no Tabs); the Partner messaging unit test selects the
  tabs as `<button>` elements, which they still are.
- **Visual run per PR = `next start`, not a Vercel preview** (Linear re-scope, ADR 0019 d23: the frontends leave
  Vercel). The gated `/kit-gallery` route (404 unless `KIT_GALLERY=1`) gives every PR a public page with every core
  component, the ShellFrame demo included. Signed-in pages are captured after the production deploy only (the
  Cognito callbacks are the production and fixed Preview hosts).
- **Two overflow assertions.** The admin document never scrolls (the PageFrame is the scroll region), so
  `document.scrollWidth == viewport` alone can never catch a wide page (lesson S254). The probe also checks every
  `[data-kit-frame]` / `[data-kit-shell="main"]` (`scrollWidth <= clientWidth + 1`). The self-test plants one wide
  strip in the document and one in the frame; each must be caught.
- **"Every changed page"** = `tests/e2e/visual/changed-pages.mjs` over the PR diff (or `before...sha` after a push):
  a page folder touches its pages, a private folder (`_components`) its parent's subtree, a kit / layout / `lib/`
  change every page.

- **The kit sync consumer table drops `portal`** (S6f close-out). AA-Partner `portal/` was deleted by AA-1036
  (Partner #212) but `.github/scripts/kit-sync.sh` still listed it, so the next Kit Sync bot run (this PR's own core
  change) would have re-created `portal/app/_kit/core` + `portal/kit.lock.json` in AA-Partner, and the Kit Consumers
  `portal` leg would fail on a missing app. Three consumers now: crm-web, booking, tripplanner.

- **Two kit additions for the S6f close-out of AA-Partner** (consumer code could not reach `{}` honestly without them):
  - `Modal` `pinFooter` (+ `moreLabel`, `initialFocus`, `bodyTestId`): AA-Partner's stage-engine dialog frame (S262:
    title and footer in view, only the body scrolls, the whole box under 480 px of height, a "more below" cue) moved
    into the kit. Its layout needs a fallback declaration and a media query, so it is CSS (`MODAL_CSS`, hoisted like
    `ShellStyles`), scoped to `[data-kit-modal="box"][data-pin-footer]`; a plain Modal renders as before.
  - `DataTable` `rowTestId`: a row's own `data-testid` (AA-Partner's ledger `line-<id>`, which its unit tests and E2E
    scenarios read); every row also gets `data-kit-row`. Without the prop the rows stay `kit-datatable-row`.
  Tests: `lib/kitModal.test.mjs`, `lib/kitDataTableRows.test.mjs` (Frontend Build, "Kit button render tests").
- **Overflow probe fix (all three repos).** The probe compared the document with `window.innerWidth`; under the 390 px
  mobile emulation a page that overflows widens its layout viewport, so innerWidth grew with the overflow and the page
  passed. It now compares with the configured viewport width. The AA-Partner run found a real 12 px overflow that way
  (`/signed-out`, fixed there). A redirect answer (3xx, e.g. "/") is no longer a "failed request".
- Review fix (S269): the drawer wrapper is fixed at `100dvh`, and the kit drawer CSS now also sizes the slot inside it
  (`[data-kit-shell="sidebar"] > * { height: 100% !important }` below the breakpoint). The CIS and Booking sidebars
  set `height: 100vh` inline; on a phone browser 100vh is the large viewport, so without this the account / sign-out
  rows sat under the browser toolbar (the old `.aa-admin-sidebar { height: 100% !important }` rule did this before).
  Playwright mobile emulation has no dynamic toolbar, so the unit test on `SHELL_CSS` is the guard.

## Changed (vs the issue)

- The issue named "CIS admin, the portal and CRM web"; after AA-1036 the portal is part of AA-Partner `web/`, so the
  shell and the visual job target CIS admin, the one agency app and Booking admin (Linear comment of S265).
- The visual job is report-only; making it a required check is H3.
- The four dynamic admin routes (`/admin/lab/[stage]`, `/admin/platform/staff/[id]`, `/admin/supply-content/[id]`,
  `/admin/tenants/[id]`) are excluded with reasons: their list pages open them by router push, so there is no link to
  read a real id from.

## Tradeoffs

- Slots keep each app's look and markup (its CSS hooks, test ids); the price is that the sidebar and topbar are not
  shared code. Sharing them would mean moving RBAC and session concepts into core.
- The deployed run reuses the smoke setup (one Cognito sign-in per run, `e2e-cognito` concurrency group), so it waits
  behind the production smoke instead of signing in a second user.
- The offenders list (elements whose right edge passes the viewport) is reported, not asserted: closed drawers and
  off-canvas panels sit outside the viewport on purpose.
