# AA-1150 — Lean staff roles step 1 (CIS part)

Session S286 (lane l1-roles-step1). The Booking part (finance reads, the make / approve split) is a separate PR in
AA-Booking with its own notes file.

## Decisions

- **Three people-role presets** lead the Staff page's account panel: "Administrator", "Business owner", "Content +
  Product & operations". "Administrator" reuses the existing `platform_owner` preset (CIS admin + Booking admin + CRM
  Agency admin, other CRM roles kept), so no second code path does the same thing.
- **Business owner** (`preset="business_owner"`) = CIS admin + Booking admin; CRM roles are left as they are. The lean
  matrix says "CRM read only", but no read-only CRM staff role exists yet, so the preset neither adds nor removes one.
- **Content + Product & operations** (`preset="content_ops"`) = CIS `content_lead`, no Booking grant, no CRM role
  (tech lead decision Q1: no interim Booking `contracting` until custom roles). It replaces roles (unlike the additive
  presets), so it goes through the normal self-demote and last-owner guards, and the UI does not offer it on one's own
  row.
- **No preset sets the owner flag** (`is_owner`), like the two older presets; the business-owner marker is part of the
  custom-roles issue.
- **Every other role** (the CIS / Booking / CRM fields, Save roles, the Pricing team preset) is behind a "Show all
  roles" toggle (collapsed by default). Add staff offers the same presets in a "Role" select (default "Content +
  Product & operations", the least access of the three), with "Custom (show all roles)" for the fields; the create
  API has no preset field, so the page fills the role fields from the preset (`lib/staffPresets.ts`).
- **Retired Booking role `content_creator`**: removed from `BOOKING_ROLES` (service 400 `booking_role`, route 422);
  `RETIRED_BOOKING_ROLES` keeps its group in `BOOKING_GROUPS` so Sync and create-over-an-existing-user remove it. Sync
  also deletes a retired grant row in the same transaction with a `staff.roles_changed` audit row
  (`details.retired_booking_role`), so the directory and the pool agree and the C7 reconcile reports no drift. The
  Pricing team preset treats a retired grant as an empty slot. The CIS 363 CHECK still allows the value; dropping it is
  a later contract migration once no grant holds it.
- **Label**: Booking `contracting` is shown as "Product & operations" (EN) / "Sản phẩm & điều hành" (VI) on the Staff
  page and in the invitation e-mail; the role code is unchanged.

## Tradeoffs

- The preset definitions live twice (backend `change_roles`, frontend `PEOPLE_PRESET_ROLES` for the create and the
  "Current" mark); `staffPresets.test.mjs` reads the backend file to keep the role lists and preset names equal.
- Deleting a retired grant on Sync (rather than leaving the row and only dropping the group) keeps one source of truth;
  it is a role revocation the owner triggers, audited, not a data deletion.
