# AA-1127 — 390 px defects from the S285 live evidence run (lane l21)

Source: the S285 live evidence run (latest AA-1127 comment): read-only E2E CIS admin, about 45 page loads, 0 document
overflow, but five spots at 390 px that ran past the phone frame or said the wrong thing. Separate file from
`AA-1127.md` (C3) and `AA-1127-c4.md` (C4) so the PRs never touch the same notes.

## Decisions

- **Reproduced before fixing, with a local harness, not guessed.** `next dev --webpack` with the API unreachable (the
  dev gate lets a legacy token through on `cis_role`, proxy.ts) and every `/api/**` answered by Playwright with invented
  fixtures (made-up tenants, stage names, check ids); headless Chromium with scrollbars on (lesson S239). Before: main
  frame +276 px on `/admin/decisions` (the exact live number), +85 px on the TripPlanner settings search (live +58 with
  other labels), review-log check badges cut inside the phone cards. After: frame overflow 0 on the four pages in light
  and dark; only the kit tab tracks scroll sideways, by design.
- **Platform › Settings: the Area column goes after the Setting column while searching.** The kit table's phone card
  uses the first column as its title; with Area first, the whole setting cell (label, what, key, badges, Explain) sat
  in a right-aligned label/value row with a 240 px minimum and was cut. Setting-first fixes the phone card and keeps
  the desktop table readable (Setting, Area, Value…). The cell's minimum is now `min(240px, 100%)` and the label and
  the key (one long dotted token) wrap anywhere, so a narrow column can never cut them either. The same change fixes
  the +9 px of the CIS spend search.
- **Jev Decisions: the colour legend wraps.** It was one flex row of five zone pills and three mode pills (nowrap
  each) at the bottom of every tab: 276 px wider than a phone.
- **Tenant QA review log: badges holding one long token break anywhere** (`tokenBadge`: `maxWidth: 100%`,
  `overflowWrap: anywhere`, passed through the kit Badge's `style`); the 160 / 150 px gate labels wrap too. Page-level,
  not a kit change: the kit Badge is right for short labels, and a kit core edit would need a sync PR in Partner and
  Booking for no other page's benefit.
- **TenantSelect placeholder: "Name, slug or id" / "Tên, slug hoặc id".** The inline search box is 200 px; the old
  text was cut ("Search by name, slug or"). The box keeps its aria-label ("Search tenant"), so the shorter text loses
  nothing for a screen reader. Fixes Content Trace and every other inline TenantSelect (review log, quality…).
- **App profiles "Takes effect" per app** (`lib/appProfileApplies.appliesKey`, its own file: `lib/aiGateway.ts` sits at its code-health size baseline): CIS "Within 20 s, in the CIS gateway" (the
  20 s per-process cache of `shared/llm_client/app_profile.py`), TripPlanner "Within 20 s, in TripPlanner's own
  gateway" (its own 20 s cache of the catalog view), CRM "At once: the CRM reads it on every AI call" (the edit is
  relayed to the CRM first and its gateway reads its row on every call), any other enforced app the generic "Now, in
  the app's own gateway", and an app the gateway does not act on (Booking today, `ENFORCED_APPS`) "Not used". The
  live run saw the TripPlanner wording on every row because the one generic string named TripPlanner.

## Tradeoffs

- Source guards, not a rendered test in CI: the per-PR visual run has no session and no backend, and the staff run
  happens after the production deploy. The harness used here is a scratch tool (fixtures only); turning it into a
  per-PR "staff pages with fixtures" job would be its own slice.
- The setting cell in a desktop search now has Area as the second column (it was first). Minor; the search chips above
  the table already say which areas matched.
