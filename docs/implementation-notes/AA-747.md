# AA-747 — Trim S1 LLM calls per tour

Code written by Kiro (aa-worker, 66 credits), gated by Claude Code + kiro-reviewer (PASS-with-nits; 3 nits fixed by Claude).

## Decisions
- Item 1: a seo_meta/seo_title code leaves the LLM fix request only when the deterministic fit (AA-740) makes it stop firing; content codes (robotic opener, DFS verbatim, forbidden word that survives) stay with the LLM. No field left → no flag_fix LLM call.
- Item 2: `MAX_NUDGES_PER_TOUR = 3`, shared across generate_node and flag_fix via `state.itinerary_nudges_used`, worst day (largest distance from the clamp band) first; skipped days recorded `skipped_reason: "nudge_cap"`. A day generate_node already nudged is never re-marked as skipped (reviewer nit).
- Per-day target lengths in the main prompt exist behind `S1_PER_DAY_TARGETS` — **default OFF**; A/B on 10 tours before enabling.
- Item 3: FE awaits only the prefetch job creation, then starts rewrites; prefetch commits `seo_context` in the given order, 5 tours per batch, and re-checks freshness per batch; the rewrite SEO step waits (10 s poll, 5 min cap) for its own tour's row when a covering prefetch job is queued/running, then falls back to a per-tour fetch.

## Changed
- Item 4 (shadow 10–20%) was done by config on 09/10 (AA-686 API), not code.

## Tradeoffs
- The nudge budget resets per generate attempt (a regenerate gets a fresh 3) — kept: a regenerate is a new version.
- Fallback after the 5-min cap can still buy for a tour the prefetch has not reached yet; the per-batch freshness re-check prevents the prefetch from buying it again.

## Should know
- "Done when" (flag_fix ≤ 15% of versions, ≤ 3 nudges/tour, first S1 < 2 min, pass rate/score ≥ S218 India 86% / 7.69) is measured on a real wave next session: 3-tour trial, then ~50 India tours (Nghiệp approved S222).

## S223 (10/10/2026) — measured on Dev

**50-tour India wave (flags as shipped in #620, per-day targets OFF):** 50/50 jobs ok; 40 new Masters, 7 kept the old Master (new version failed gates → review row `dismissed` by design), 3 pending review (Rajasthan `FACT_CHECK_MANUAL_CHECK`). Mean judge score 7.58 (= this set's baseline 7.58), 49/50 ≥ 7. First S1 started 4 s after enqueue (the India `seo_context` was still fresh, so the prefetch-wait path was not exercised). flag_fix from flag codes on 12% of tours (no seo_meta/seo_title call); `grounding_repair` on 86% of tours — now the main flag_fix source (→ AA-748). Cost $1.51 / 50 tours.

**Nudge cap — kept per version (Nghiệp's question, S223).** The wave showed up to 9 nudges on one tour = 3 generate attempts × 3. The cap stays per generate attempt (Tradeoffs above): a retry is a new text that can compress again, a nudge costs ~$0.0013 vs ~$0.015 for a full regenerate, and 3/7 gate failures were `ITINERARY_STILL_COMPRESSED`. Done-when reads "≤ 3 nudges per version".

**Many compressed days per tour.** 18/50 tours had > 3 days outside the clamp band; with the cap, 70 days were left un-nudged and 14 of those tours still went to Master (validate only re-checks nudged days).

**Per-day targets A/B → default ON.** 10 tours with > 3 compressed days, rerun with `S1_PER_DAY_TARGETS=true` (one api-container process, same code path as the job): days outside the band 70/102 (69%) → 17/102 (17%), nudges 27 → 11, mean judge score 7.44 → 7.89, 9/9 published. One outlier (Delhi to Kathmandu, 15 days, 23k-char source) stayed 12/15 — not truncation (`stop_reason=end_turn`, 3.7k output tokens). This PR flips the default to ON; `S1_PER_DAY_TARGETS=false` turns it off. The `tenant_flags` override path is wired in the prompt builder but nothing populates `state["tenant_flags"]` yet.
