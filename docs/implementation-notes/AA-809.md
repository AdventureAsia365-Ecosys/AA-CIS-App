# AA-809 — Post-draft dedup for place cards

## Decisions
- New resolver `find_card_for_draft()` in `services/acp_shared/place_cards.py`, called inside the
  store transaction of `build_card_for_group()` after the identity check, before `_store_card()`.
- Candidates are the non-rejected cards of the DRAFT's country (fold), fetched once
  (`place_key LIKE '%|<country>' OR lower(country) = <country>` — covers new 2-part keys, S233 legacy
  3-part keys and generic 3-part keys), then matched in Python.
- Match order, first method with a hit wins: `place_key` (exact key) → `alias` (alias table on the
  display-name forms) → `core_key` (display-name core vs card name cores, legacy keys included) →
  `feature_synonym` (core + small synonym table) → `draft_alias` (alias table + core on the draft's
  own aliases).
- A method that hits more than one card returns no match (`place_card_post_draft_ambiguous` log) —
  the old insert path runs; we never guess between two cards.
- Synonym fold lives in `match_key()` (comparison only, never in `place_key`, so no stored key
  changes and no migration): waterfall/waterfalls -> falls; trailing tso / tsho / co dropped while a
  distinctive word remains (lake / nuur were already neutral edge words in `core_key`).
- Generic names (`is_generic_name`) skip alias/core/synonym entirely: only a generic card with the
  same core name AND the same locality (locality, else region) matches (`generic_locality`).
- A draft alias that is the display name or part of it as whole words ("Punakha" for "Punakha
  Dzong") is never used for matching.
- On a match: atoms linked, `_alias_rows` written (itinerary forms + drafted display name + draft
  aliases, ON CONFLICT DO NOTHING), cost added to the existing card, group miss deleted. The
  existing card's identity, facts and status are not touched.

## Changed
- `build_card_for_group` returns outcome `linked_after_draft` on a match; `ensure_place_cards`
  counts it in the new counter `linked_after_draft` (groups) instead of `linked_new`; `built` still
  counts the atoms linked by a draft. The exact-key case (previously handled inside `_store_card` and
  counted as `linked_new`) now also reports `linked_after_draft` with method `place_key`.
- `find_existing_cards` (pre-draft, itinerary name) is unchanged: its SQL fetches by key, and
  adding the synonym fold there would need a country-wide fetch too — kept the change small.

## Tradeoffs
- Candidates = all non-rejected cards of one country (~110 cards total on Dev today), matched in
  Python; one extra query per draft (drafts are already ≤1 per place group and paid).
- Ambiguity → insert as before (a duplicate the admin merge can fix) rather than a wrong link.
- The draft still costs a call; this only stops the duplicate insert. Pre-draft synonym matching
  would save the call — follow-up if the trial shows many `feature_synonym` hits.
