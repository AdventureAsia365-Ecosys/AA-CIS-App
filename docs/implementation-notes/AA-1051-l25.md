Golden aa729@1.7.0 is imported on Dev (S285): 1.5.0 plus 22 S1 samples (`s1-051..072`, built as 1.6.0, never
imported) and 48 T2 samples (`t2-021..068`); 218 items, 1.5.0 superseded, split rows written by the importer. Non-trap

no migration; `w5-t9` and the null run stay on 1.5.0 unchanged.

## Decisions

- **The sample is every non-trap GATE item of the writer, listed, not a seeded draw.** `runner draft` picks
  `min_items` ids by a seeded hash; with 26 a1 GATE items it would drop one id chosen by hash, not `s1-027`. The S285
  l7 drafts already listed "every non-trap GATE item less the unjudgeable ones", so this lane keeps that rule and
  writes the list by hand from the fixture's ids and the split rule (`splits.split_of`), then checks it against the
  fixture: S1 25 = 26 less `s1-027` (stored output over the judge's 16,000-char evidence cap); T2 20 = all.
- **Only `golden_set.version`, `sample_ids` and `note` change.** The loader checks no golden hash (a draft names name
  and version; the plan compares them with the active set). Judge pin, metrics, margins (4.0), alpha, writer_sd
  (S1 4.9, T2 4.6), claims_per_item, min_power and caps (S1 8, T2 5) are unchanged; the loader accepts both files.
- **Notes say how the GATE items were chosen and labelled**: positions declared before any label (the side is a hash
  of the renumbered id), the strata of the new items, the panel + verifier protocol, the orchestrator's dispute rule
  (pending tech lead review), the GATE label balance, and the golden carry rule that opens the proof.
- **Power** (same formula as the l7 drafts, power = Phi(margin / se - z_alpha)): S1 about 0.96 at n 25 (0.85 at
  n 15), T2 about 0.95 at n 20. The plan's own power check still needs the R1 and two-step reports.

## Tradeoffs

- **S1 and T2 meet the minimum exactly** (25 / 20): one more unjudgeable item in a later version would push either
  below it. Accepted: the minimum is a setting, and a later version needs a new draft anyway.
- **The 4 elephant T2 items are one Master tour on 4 tenants** (same stored control output, different tenant inputs),
  also the 4 known-failure items. They satisfy "elephant >= 2" in count but are not 4 independent tours; their per-item
  differences are correlated. Kept: the S271 design asks for the stratum, and the T2 writer's brand work differs per
  tenant. Said in the note.
