# AA-759 — PortalShell on the kit (grouped nav, real ⌘K, phone bottom bar, theme, route renames)

Split from AA-670 (S229). Built S247 (22/10/2026), Claude Code subagent. UI only: no API, no
migration, no env var.

## Decisions

- **Route map (no T-number slugs).** Every old slug answers **308** to its new path
  (`portal/next.config.ts`, `permanent: true`; the query string is passed through, so
  `?piece=`, `?tour_id=` and `?resume_request_id=` deep links keep working):

  | Old | New | Nav |
  |---|---|---|
  | `/portal/t1-rewrite` | `/portal/tours` | Tours › Browse |
  | `/portal/t4-pool` | `/portal/tours/mine` | Tours › My Tours |
  | `/portal/marketplace` | `/portal/tours/marketplace` | Tours › Marketplace |
  | `/portal/t0-brand` | `/portal/brand` | Brand |
  | `/portal/t7-planning` | `/portal/create/social` | Create › Social |
  | — (new) | `/portal/create/article` | Create › Articles |
  | `/portal/t8-angle-gate` | `/portal/create/write` | deep link only (as before) |
  | `/portal/t10-review` | `/portal/content` | Content › My Content |
  | `/portal/t11-publish` | `/portal/content/publish` | action on My Content |
  | `/portal/t11-publish/connection` | `/portal/account/integrations` | Account › Integrations |
  | `/portal/activity` | `/portal/account/activity` | Account › Activity |
  | `/portal/billing` | `/portal/account/billing` | Account › Billing |
  | `/portal/settings` | `/portal/account/settings` | Account › Team & Settings |
  | `/portal/api` | `/portal/account/api` | Account › API |

  `/portal/dashboard` and `/portal/help/facebook` keep their paths (no T-number). `/portal/create`
  and `/portal/account` are index pages that redirect to their first child.
- **Social vs Articles.** Both pages are the same Slate (`PlanningTab` → `SlateTab`) filtered to a
  set of Channels: Articles = `blog`; Social = every other Channel (LinkedIn, Facebook, Instagram,
  TikTok, and the on-demand Email / Landing Page / Ads). One data source (`GET /v1/slate`), no new
  API. The trip-reallocation card stays on Social only (it is about the weekly social rhythm).
- **Marketplace** is not in the AA-759 target list; it is a read-only rollup over the tenant's
  tours (ADR-2026-038 §0.3), so it moved under Tours instead of being dropped.
- **Publish is an action of My Content**, not a nav item (issue target): the My Content header has
  a "Publish" button; `/portal/content/publish` highlights My Content in the nav. Channel
  connections (WordPress, Facebook Page) moved to Account › Integrations.
- **Shell styling without className.** The kit rule (no `className` in page code) now applies to
  the whole shell. Responsive behaviour (off-canvas drawer < 900 px, bottom bar < 768 px, collapsed
  rail) is CSS in `portal/app/globals.css` keyed on `data-pshell="…"` attributes and the
  `html[data-sidebar]` / `html[data-theme]` attributes, so the server HTML is already right on a
  phone (no hydration flash, no JS media query in the shell).
- **Theme.** The portal is no longer pinned light. The admin theme store and the sidebar store are
  vendored as byte copies (`theme.ts`, `useTheme.ts`, `sidebarStore.ts`, `useSidebar.ts`,
  `useHydrated.ts`) and the root layout runs the same two restore scripts before paint. On the
  portal origin the keys (`cis_theme`, `cis_sidebar`) are separate from the admin's (different
  host = different localStorage). The portal `T` token object now returns the `--aa-*` CSS
  variables (same move AA-601 part B made for the admin `A`), so one `data-theme` switch recolours
  every legacy portal component too.
- **⌘K** is built on the kit `Modal` (the kit rule forbids a hand-rolled `role="dialog"`). Groups:
  Pages (client match over the nav), Tours (`GET /v1/tours/pool?search=`), My tours and My content
  (client match over the cached `my-versions` / `content-reviews` queries, the same query keys the
  pages use, so no extra request when the page was already opened).
- **Shell data via react-query**: `/api/tenant/me`, pool total, `my-versions` (key shared with My
  Tours, so the badge and the page count the same rows) and `/v1/billing`. No raw fetch on mount.
- **Dates**: `fmtDate` / `fmtDateTime` in `ui.tsx` now call the kit `formatDate` /
  `formatDateTime` (one formatter with the admin: "9 Oct 2026", not "09 Oct").
- **Toast**: the shell's hand-rolled toast is replaced by the kit `ToastProvider` (`role=status`);
  `showToast(msg)` keeps its signature.

## Changed

- New `portal/app/portal/_shell/` (PortalShell, sidebar, topbar, bottom bar, palette, nav model,
  shell data hooks). `portal/app/portal/layout.tsx` only mounts it.
- Old `Sidebar.tsx` / `CommandPalette.tsx` deleted (replaced by `_shell/`).
- Route folders moved with `git mv` (history kept); every internal link points at the new paths.
- ESLint: the kit rule is `error` for `app/portal/_shell/**` and every `app/portal/**/page.tsx`
  (was 2 files); the rest of the portal stays `warn` until migrated (AA-760).
- Smoke: `tests/e2e/smoke-portal/portal-smoke.spec.ts` uses the new paths; a new unauthenticated
  check asserts each old slug answers 308 to its new path; screenshots now also in dark.
- Unit: `tests/unit/test_aa885_portal_split.py` guards the 5 new vendored files; a new test checks
  the 308 map in `portal/next.config.ts`.

## Tradeoffs

- Two redirect hops for an old admin-host link (`aa-cis…/portal/t4-pool` → portal host same path →
  `/portal/tours/mine`). Cheap, and the admin redirect stays a generic `/portal/:path*`.
- The phone breakpoints differ on purpose: drawer < 900 px (AA-605 behaviour kept), bottom bar
  < 768 px (the kit phone cut).
- Dark mode recolours everything that reads `T` / `K`; a few hard-coded light literals in legacy
  components may still look off in dark — that per-page pass is AA-760's checklist.

## Should know

- The kit toast sits bottom-right; on a phone it can cover the bottom bar for its 4 s (same as the
  admin).
- `help/facebook` keeps its path; it links to `/portal/account/integrations` now.
