> adventure.asia mail host forwards its mail to `e2e@e2e-mail.lumiguides.it.com`, and the helper matches the
> forwarded To header. See `AA-816-a10-removal.md`.

Lane AA-816, builder `cis-e2e`. Separate notes file so it does not collide with `AA-816.md` (other lanes).

## Decisions

- **Workflow name `e2e-cognito.yml`** (task text), not `cognito-e2e.yml` (plan). The Infra role description
  mentions `cognito-e2e.yml`; it is only a description, the trust does not depend on the file name.
- **Read-only mailbox.** The reader role `aa-cis-dev-e2e-mail-reader` (Infra I5, `e2e_mailbox.tf`) has
  `s3:ListBucket` (prefix `inbound/`) + `s3:GetObject` only — no delete (S243 decision, overrides the plan's
  "delete after use"). Cleanup is the bucket's 1-day lifecycle. The helper never tries to delete.
- **Which message.** The helper lists `inbound/` once BEFORE the code is requested (baseline keys), then polls
  every 3 s for a key that (a) was not in the baseline, (b) has `LastModified` >= test start − 60 s (clock
  skew), (c) is addressed to `e2e-cognito@adventure.asia` (To / Cc / Delivered-To / X-Original-To /
  X-Forwarded-To / Envelope-To — the forwarder may rewrite the envelope but keeps the To header), and (d)
  yields a code. Newest first. The baseline excludes the SES setup notification, the invite email and any
  code of an earlier run, so a stale code is never typed.
- **Code extraction.** Minimal MIME walker in `tests/e2e/helpers/mailbox.ts` (no new npm dependency):
  multipart recursion, quoted-printable and base64 decoding, HTML stripped (style/script blocks dropped,
  entities decoded). First a 6–8 digit number within 80 non-digit characters after the word "code"; else
  the only distinct standalone 6–8 digit number in the body (a `#` before it is ignored — CSS colours).
  Plain-text parts before HTML parts. Headers are never searched (the subject could carry a date).
- **AWS CLI through `execFile`** (no shell, fixed argv), `--region us-west-1`, no `--profile`: CI gets the
  role from `configure-aws-credentials` (env), a local run uses whatever the caller exported. Each CLI call
  has its own 20 s cap; the whole wait has a hard 90 s cap (lesson: every Playwright wait has its own cap).
  The downloaded `.eml` goes to a `mkdtemp` dir and is removed right after reading.
- **"Excluded from default runs".** Playwright has no default-project switch: without `--project`, every
  project runs. So: the `chromium` project ignores `cognito/`; the `cognito` project is the only one that
  matches it; and the sign-in test skips unless `E2ECOGNITO=1` (set only by the workflow). The env name has no
  underscore on purpose (CLAUDE.md env rule). The MIME unit test in the same project needs no env and no AWS.
- **Fixed base URL** `https://aa-cis.lumiguides.it.com` for the `cognito` project (ignores `BASE_URL`): only the
  production host is a registered callback of the cis-admin client; a preview answers `/login?error=cognito_host`.
- **No code in artifacts.** Project `screenshot: 'off'`, `trace: 'off'`, `retries: 0`. The spec takes its own
  screenshots at safe points (login page, managed login with the email, empty code page, admin landing, after
  sign-out). On failure it screenshots only when the page is NOT on the managed-login host (the code field
  may hold a live code); otherwise it attaches the URL + heading text. The code is never logged.
  The workflow uploads the screenshots ONLY — not the HTML/JSON reports, whose step titles carry action
  values (`fill` names the typed text = the code). No `::add-mask::` either: if a reporter prefixed the
  line, the command would not be recognised and the code would be printed in clear.
- **Managed login steps.** Email address → Next → "Check your email" (S242 screenshots 01–03, 8-digit code).
  If Cognito shows a sign-in method choice first (user with a password), the spec picks the email option.
- **Logout + no silent re-login.** Account menu → Sign out → Cognito `/logout` → back on `/login`; then
  `/admin/dashboard` must bounce to `/login`, and "Sign in with company email" must show the managed-login
  email form again (the managed-login session cookie is gone) — no code is requested a second time.
- **Workflow guard.** The role trust pins `environment:e2e` + `ref refs/heads/main`, so the job runs only on
  `main` (an explicit `if:`; a branch dispatch would fail at AssumeRole otherwise).
  `timeout-minutes: 10` (plan said 5; `playwright install --with-deps` alone takes 1–2 min on a cold runner).

## Changed (vs. plan E1)

- No delete after read (reader role is read-only, task text).
- Workflow file name `e2e-cognito.yml`, timeout 10 min.
- Spec path `tests/e2e/cognito/cognito-login.spec.ts` + unit spec `tests/e2e/cognito/mailbox-parse.spec.ts`
  (fixtures `tests/e2e/cognito/fixtures/*.eml`, fake codes).

## Tradeoffs

- Env gate vs. a config-level hack (reading `process.argv` in the config breaks worker project matching).
- Header check is lenient (any of six headers). A stricter "To only" check could miss a forwarder that
  rewrites To; the baseline + time window already pin the message to this run.
