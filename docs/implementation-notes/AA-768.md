# AA-768 — T9 writer source fidelity

## Decisions
- Read the 9 held pilot pieces (S231, `acp_shared.content_piece`) before changing anything. Two
  separate causes, not one:
  1. **F1_grounding** — the writer adds numbers the seed lacks (900 m, 3,120 m, 1970s, e-visa
     fee). Some "invented" numbers were not invented: terra-family's "children aged 7–16" is the
     tenant's own `customer_segment`, which the writer is shown but the gate never was.
  2. **F9_cta_fact = FACT_CHECK_MANUAL_CHECK** — the F9 judge saw only the piece, CTA and rubric,
     and was told "when uncertain about a factual claim: manual_check". With no source to check
     against it flagged every fact-bearing piece, and the repair feedback was a bare code, so no
     rewrite could fix it (4 of 5 final pieces held on this).
- Writer prompt: A/B policy from S223 (#629) plus an explicit numbers rule — a number only if it
  appears in the seed, Facts, trip name or audience line. Stricter than S1 on numbers on purpose:
  T10 F1 is a deterministic number check, so "allowed background" must be written without numbers.
- Gate source text (`service._grounding_text`) = atom/route text + Facts + AUDIENCE + TRIP +
  DESTINATION — exactly what the writer is given as fact.
- F9 judge gets that same source and a narrowed rule: FACT_CHECK only for a claim about this trip
  the source does not support, quoted in `flagged_phrases`; place background is not flagged.
- Rewrite feedback = every failed blocking gate's violations, prefixed with the gate name. Before,
  only `first_failure` went to the writer, so the atlas-hearth blog (F1 + F4 SEO + F3 + F9) fixed
  F1 and held on the rest.

## Changed

- `quality_gates.py`: `gate_brand_voice(..., source_text=None)`; `run_quality_gates` passes its

  `repair_log[]` entries gain a `feedback` list, used for `revision_feedback` and the buffer retry.

- F9 judge prompt grows by the source text (route blogs: ~7–12 moments). Small extra judge cost;

## S233 — PR: SEO title/meta regenerated, per-channel ceiling, F0_complete

### Decisions
- **SEO fit = one short LLM call, never a string cut.** `generate.fit_seo_fields()` runs only when the
  writer's title or meta is outside the band (title 45–60, meta 120–158, full sentence, keyword kept).
  A new value is kept only if it lands in the band; otherwise the writer's own value stays and F4

- **Writer ceiling per channel:** blog 8000, other channels 3000 (was 2048 for all). A

  with a stray backslash. It reads the text, not `stop_reason`, because `json_repair` makes a cut
  blog envelope look complete. Hashtag lines, list items, headings and links are exempt endings.

### Tradeoffs
- SEO fit adds ~1 short call per blog when out of band (~$0.003). Cheaper than a held piece or a stub.
- F0 checks the last prose line only; a cut inside a list item is not caught (rare; ceiling raise and

## S234 — PR2 review fixes

### Decisions
- **Trip-name gazetteer entries are place runs, not whole capitalised phrases.** `trip_name_places`
  takes every capitalised word of the trip name (also right after ':'), drops `COMMON_CAPS`, a new
  marketing list `TRIP_NAME_WORDS` (Cultural, Discovery, Adventure, Highlights, Classic, Best,
  Thunder, Dragon, …), numbers and <3-letter words, and breaks runs at punctuation / lower-case
  words. `build_scope_lexicon` then splits each run at every allowed word ('Mongolia Gobi' on a
  Mongolia piece → 'gobi'). 'Bhutan Cultural Discovery - 8 Days' on a Bhutan seed now adds nothing,
  so the trip-name replace, the SEO-fit band and F12 no longer fire on the trip's own name.
- **Trip-name entries count only when capitalised** (`ScopeLexicon.cap_only`): they come from a
  marketing name, so a lower-case common word must not match ('the gobi-style dunes'). Sibling
  phrase entries stay case-insensitive (calibrated on r1).
- **Place matching is token-based** (`_name_tokens` + `_has_place`): the text is reduced with the
  same filter as the keys (`phrase_tokens`), so "Tiger's Nest", "Tiger’s Nest" and 'Erdene-Zuu'
  match 'tiger nest' / 'erdene zuu'. `_CAPWORD_RE` treats 'Erdene-Zuu' as one word. `choose_keyword`
  uses `hygiene.names_place` for the same normalisation.
- **Allowed side keeps sentence-initial words** (`proper_nouns(keep_initial=True)` for own lines and
  SCOPE): over-including the allowed side only means fewer flags ('Location: Khovsgol, …').
- **FAQ topics ask about the topic itself.** age = age-suitability wording (what age, age range,
  how old, too young, suitable/safe for (young) children, child-friendly…), never bare kids /
  children; price = price/cost/fees/inclusions or 'what is included in the price/tour/trip', never
  bare 'include'; fitness drops bare 'fit' (keeps 'how fit', 'fit enough', 'challenging');
  best_time = best time/season/time of year/weather, never 'when should'.
- **C10 merge = card id OR core name** (`merge_keys` + `group_route_moments`, union-find): the
  name key is the sorted set of `phrase_tokens(display_name)` + country, so 'Lake Khövsgöl' and
  'Khövsgöl Lake' on different cards merge, 'Sod Camp, Khövsgöl Lake area' does not.
- **`sentence_repair.plan` returns [] when the only blocking failures are SEO-field ones** (an F12
  with only title/meta violations, optionally with F4). The loop then re-runs the SEO fit + gates
  on the same text (`repair_mode: "seo_fields"`, $0 text cost) instead of a full Sonnet rewrite,
  and `last_try` no longer treats it as "needs a rewrite". F4 alone keeps the old behaviour (None).

### Changed
- `hygiene.py`: `TRIP_NAME_WORDS`, `trip_name_places`, `ScopeLexicon.cap_only`, `names_place`,
  token-based `places_named`, `proper_nouns(keep_initial=)`, hyphen-joined `_CAPWORD_RE`.
- `service.py`: `choose_keyword` uses `hygiene.names_place`; the loop handles `plan() == []`.
- `quality_gates.py`: narrower `_FAQ_TOPICS` question patterns.
- `atom_seed.py`: `merge_key` → `merge_keys` + `group_route_moments`.
- `sentence_repair.py`: `_seo_fields_only`, `plan` returns [] for SEO-only F12.

### Tradeoffs
- `TRIP_NAME_WORDS` is a finite list: a marketing word not on it, in a trip name, becomes a
  (capitalised-only) gazetteer entry. Cheaper than a dictionary and visible in F12 warns.
- A seed with no Location line (no country) does not allow the trip's country, so a trip-name
  country can be flagged on such a piece. Rare (atoms carry `raw_tours.country`).
- The core-name merge key can join two different places with the same core name in one country
  (two 'Tourist Camp's → {tourist}). Accepted: same name + same country on one route is almost
  always the same place, and a wrong merge only joins two blocks.
- Kept 'challenging' / 'difficult' as fitness questions ('Is the climb challenging?'): the seed
  rarely states effort and S233 answers to these were invented; the FAQ is optional.
